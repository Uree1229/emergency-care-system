## 범위와 한계

- 병원·환자·자원·회신·자원 확인·위치·이동·처치시간은 합성 설정이다. 실제 병원이나 카카오 API를 호출하지 않는다.
- 완전정보는 손실을 비교하기 위한 기준이다. 관측 분기는 전달된 병원 capacity/used만 알고 서버의 현재 확정 예약·도착 대기는 즉시 안다.
- 병원 자원 수량의 누락·전달 지연만 바꾼다. 수용 판단·이송 중 변경 알림·서버 확정 검증까지 모두 지연시킨 실험이 아니다.
- 현재 서버의 수용 회신은 자원 수량 갱신이 아니다. 이 실험의 별도 자원 확인 요청·응답은 새 합성 실험 계약이다.
- 자원 수량을 모르는 상태에서 유효 수용 응답으로 사람이 수동 확정하는 기존 운영 경로는 별도다. 여기의 미배정은 관측 수량 기반 자동 배정 미확보이며 실제 수용 거절을 뜻하지 않는다.
- 등록된 대기 수요는 외부 유입을 포함해 즉시 알려진 원장으로 가정한다. 등록되지 않은 외부 대기열이나 대기 정보 자체의 누락은 검증하지 않는다.
- source 관측시각과 수신시각을 분리한다. 10분 초과만 stale이고 정확히 10분은 fresh다. 현재 운영 API에 이 전달층을 구현한 것은 아니다.
- fresh 부족은 일시 유보하고 1분 후 재평가한다. 실제 서버 문의 workflow 수명주기를 그대로 재현한 것이 아니다.
- 관측 모델의 제안과 실제 확정 결과를 분리한다. H1/C1 목적·증명은 제안 모델에만 적용하고 gate 이후 결과의 최적성은 주장하지 않는다.
- 최종 확정 gate는 환경의 실제 수량을 즉시 검사할 수 있다고 가정한다. 운영 서버가 병원 내부 실제 수량을 자동 감지한다는 뜻이 아니며 gate 자체의 지연·실패는 이번 비교에서 제외한다.
- 같은 잠재 환경과 정보 전달 규칙을 주지만 분기별 선택으로 이후 점유·회신·확인 요청과 관측 수량은 달라질 수 있다.
- 없는 정보는 0이나 가용량으로 대체하지 않는다. 끝까지 확인 응답이 없으면 미배정/확인 필요 상태가 남을 수 있다.
- H1 50ms는 기준안 이후 추가 탐색, C1 50ms는 모델 작성과 두 단계 탐색이다. 총 호출시간의 강제 상한이나 임상 안전시간이 아니다.
- 계산시간은 분 단위 모의 시계에 더하지 않는다. 같은 유형의 새 seed 검증이며 실제 현장 일반화를 입증하지 않는다.
- 기회 보호는 H1/C1의 현재 배정 대상을 잠시 동기화하는 규칙이다. 기존 R1·H1·C1 소스와 기존 결과는 변경하지 않는다.
- 구조적으로 한 병원만 가능한 환자와 대안 병원이 있는 동등·낮은 우선순위 환자 사이의 알려진 fresh 병상 경합만 보호한다.
- 구조적 대안은 진료 역량 일치로만 센다. 해당 병원의 현재 수용 보장이나 이후 회신을 예측한 것이 아니다.
- 유보는 첫 확인 대기와 해당 환자의 첫 유보부터 각각 최대 3분이며 재문의·새 수용 응답으로 초기화하지 않는다.
- 유보 환자의 마지막 유효 수용 회신이나 확인 대기 환자의 회신이 다음 tick에 만료된다면 유보하지 않는다. 3분은 전체 확정·도착 지연의 상한이 아니다.
- 현재 수용·자원 보고가 끝까지 없으면 자동 배정 미확보가 남는다. 보호 후 도착이나 모든 환자의 비악화는 보장하지 않는다.
- 16개 합성 유형의 새 seed 검증이며 유형 자체가 보지 못한 실상황이라는 뜻은 아니다. 기존 검증 seed는 재사용하지 않는다.
- 개선 분기는 병원 수용 문의와 자원 수량 재확인을 병행한다. 미래 회신 지연이나 실제 미보고 수량은 정책에 제공하지 않는다.
- 빠른 확인은 보존하지만 초기 정보가 같으면 빠른 회신·긴 회신·무응답을 미리 구별할 수 없다. 모든 환자의 비악화는 보장하지 않는다.
- early/responsive도 3분 시계를 첫 실제 자원 확인 대기부터 센다. 초기 문의와 병행해 수용 회신 시점보다 먼저 시작한다. 3분 이내 회신의 기존 이점을 보존하도록 예산 자체는 줄이지 않는다.
- 확인 응답에도 필수 수량이 unknown이면 early/responsive 보호를 중단한다. 무응답과 실제 부족은 다른 사건이다.
- 추적은 희소 병원의 현재 SEARCH 수요가 있는 동안만 수행한다. 새 자원 요청이 늘 수 있으며 수용 문의 감소와 별도 집계한다.
- 만료된 수용 회신을 자원 보고로 되살리지 않는다. 최신 가용 보고를 받아도 새 문의와 새 수용 응답을 거쳐야 한다.
- 22개 합성 유형의 새 시드 비교이며 현장 임상적 안전성·최적성이나 운영 서버의 자동 감지를 검증한 것이 아니다.
- 동률 안정화는 기존 C1의 현재 미배정 우선순위 합·가중 이동시간 두 목적값을 모두 유지하는 기준안만 선택한다.
- 기준안보다 좋은 C1 해는 유지한다. 기준안이 더 나쁜 경우 다른 동률 해들의 전역 정규화를 보장하지 않는다.
- 높은 우선순위·빠른 요청 시각·환자 ID 기준은 실험의 재현 가능한 선택 순서이며 임상적 우열을 추가 판정하지 않는다.
- 실제로 병상이 부족하면 누군가는 기다린다. 환자별 추가 지연·대기 환자 변경·전체 꼬리 시간을 함께 해석한다.
- 최대 37분이라는 이전 결과는 이전 검증 시드 기준이다. 새 전후 비교는 같은 새 검증 시드의 동결 C1과 개선 C1을 사용한다.
- 동률 후처리는 별도 솔버를 추가하지 않는다. 계산 오버헤드는 전체 호출시간에 포함하고 별도 계측한다.
- 26개 합성 유형의 새 시드 검증이다. 실제 운영 서버·임상적 안전성·전체 이송 최적성을 입증하지 않는다.
- 자원 변화 보고는 새 합성 입력 계약이다. 보고 개선 효과와 같은 정보를 받은 재검토 알고리즘 효과를 분리한다.
- 현재 발생한 변화만 전달한다. 미래 퇴실 시각을 예측하거나 병상·환자·처치시간을 바꾸지 않는다.
- 전체 대기는 모든 환자의 탐색·병원 내 대기·전원 대기 합이다. 이동시간은 별도이며 요청→처치 도달도 함께 평가한다.
- 미처치 환자는 관찰 종료까지 포함한다. 처치 완료 사례만의 평균으로 개선을 주장하지 않는다.
- 병상이 실제 점유된 동안의 물리적 대기는 남는다. 모든 환자의 도착 개선이나 전체 이송 최적성을 보장하지 않는다.
- 31개 합성 유형의 새 검증 시드이며 운영 서버·팀원 UI에는 적용하지 않는다.
