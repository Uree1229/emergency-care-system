배정 알고리즘 구체화

작성일: 2026년 9월 30일. 구현 기준: 기존 solver_improved.py와 112개 기능 롱리스트. 이 문서는 다음 구현을 위한 설계안이며, 새 알고리즘 구현·실험 완료 보고서가 아니다.

1. 문제 정의와 방식 선택

‘주어진 환자 요구, 병원 응답, 관측된 자원 일정 아래에서 환자별 목적 병원과 예상 치료 시작시각을 함께 결정하는 문제’로 정의한다. 목표는 단순 최단거리보다 적합한 치료의 시작까지 걸리는 시간을 줄이는 것이다.

추천 구성: 후보 필터링 + 이동시간 행렬 + OR-Tools CP-SAT 자원 일정 배정 + 사건 발생 시 재계산. 일대일 정적 비용표에 맞는 헝가리안 알고리즘만으로는 병원별 복수 용량, 시간대 점유, 여러 자원, 이동 중 목적지 고정을 함께 표현하기 어렵다. 일반적인 제약이 추가된 배정에는 CP-SAT를 사용하는 선택이 적합하다. [1][2]

Dijkstra는 도로 그래프를 직접 구축할 때의 경로 계산 선택지다. 초기 구현은 지도 API 또는 고정된 합성 이동시간 행렬을 사용하여 배정 알고리즘 검증에 집중한다. 지도 API의 summary.distance와 summary.duration은 이동 비용 입력 후보다. [3]

2. 초기 범위

- 필요한 진료과·우선순위는 입력값으로 제공한다. 증상으로 진단·중증도를 추론하지 않는다.
- 환자는 치료 자리 1개, 필요시 전문팀 1개를 일정 시간 점유하는 단일 치료 단계로 단순화한다.
- 여러 진료과의 치료 가능 조건은 교집합으로 필터링한다. 실제 여러 팀의 동시 배정까지 지원하려면 자원 종류별 요구량 모델로 확장해야 한다.
- 수술→ICU 등의 연속 단계는 초기에 구현됐다고 주장하지 않는다. 향후 단계별 시작·종료·자원 점유와 선후관계로 확장한다.
- 첫 실험: 1분 단위, 계획 구간 120분, 병원 10곳·환자 20명 이하. 이는 계산 실험 설정이며 임상 기준이 아니다. 계획 구간 끝까지 점유가 이어지는지 검증한다.

3. 추천과 확정 분리

1. 요구 진료·자원 조건으로 문의 후보 생성. 불명확한 정보는 추가 확인 대상으로 분리한다.
2. 예상 이동시간 기준 상위 K=3곳에 병렬 문의하는 시연 정책을 둔다. K는 설정값이며 후보 제한 때문에 최적성을 잃을 수 있으므로 결과에 표시한다.
3. 응답 하나가 도착하면 즉시 현재 응답 집합으로 재평가한다. 모든 병원의 응답을 기다린 뒤 계산하지 않는다. 추가 후보 확대도 사용자/운영 정책으로 처리한다.
4. 추천 단계에서는 미확인 후보를 볼 수 있지만, 확정 단계의 후보는 해당 환자에 대해 유효한 ACCEPTED 응답이 있는 병원뿐이다.
5. 솔버는 배정 제안을 반환한다. 서버는 환자 조건·응답 만료·자원 버전을 트랜잭션 안에서 재확인한 뒤 환자당 목적지 1곳만 확정한다.
6. 여러 병원의 긍정 응답 자체는 복수 병상 점유로 세지 않는다. 목적지 확정 시 한 곳의 예정 수요만 기록하고 나머지 문의를 종료한다. 별도 임시 자원 홀드를 도입한다면 만료·해제를 명시하고 별도 점유로 모델링한다.

응답 지연을 단순 가산점으로 계산해 수용 거절 병원을 선택하지 않는다. 응답은 확정 가능 여부를 제한하고, 문의에 실제 소요된 시간은 시간축과 전체 지연에 반영한다.

4. 입력과 출력

입력: now, snapshot_version, 환자 상태·최초 요청시각·우선순위·필요 조건·허용 시작시각·점유시간, 병원별 자원 캘린더, 환자별 유효 수용 응답, 현재 위치 기준 이동시간, 기존 확정 이송과 치료 중 점유.

환자 상태를 분리한다.
- WAITING: 목적지와 치료 시작시각을 계산할 수 있음.
- CONFIRMED_NOT_DEPARTED: 기존 확정을 우선 유지하고, 변경 시 이전 확정 해제와 새 수용 확인이 필요함.
- IN_TRANSIT: 목적지는 고정, 예상 치료 시작시각은 가변. 예정 도착시각은 현재 위치의 잔여 이동시간으로 갱신.
- TREATING: 실제 병원·실제 시작시각을 고정하고 남은 자원 점유를 반영.
- COMPLETED/CANCELLED: 해당 시점 이후 예정 점유 해제.

출력: snapshot_version, patient_id, proposed_hospital_id, eta_at, estimated_start_at, status, unassigned_reason, affected_patients, solver_status, objective_values, elapsed_seconds. 배정안의 ‘실행 가능’과 ‘최적성 증명 완료’를 구분한다.

미배정 이유는 NO_COMPATIBLE_HOSPITAL / NO_VALID_ACCEPTANCE / DEADLINE_OR_CAPACITY / DATA_UNCONFIRMED 등을 구분하되, 제약 조합의 정확한 원인을 분석하지 못했으면 복합 원인으로 표시한다.

5. 수학 모델

환자 i, 병원 h, 자원 r, 정수 분 t에 대해:
- x[i,h]: 병원 h에 환자 i를 배정하면 1.
- u[i]: 계산상 실행 가능한 배정이 없으면 1. 실제 환자를 취소한다는 뜻이 아님.
- s[i]: 예상 치료 시작시각. 미배정이면 0으로 두고 목적함수에서는 제외.
- a[i,h]: 현재 시점과 잔여 이동시간으로 계산한 도착 가능시각.
- e[i,h]: 적합성·유효한 수용 응답을 만족하면 1.
- d[i], q[i,r]: 점유시간과 자원 요구량. 초기 가상 입력.
- C[h,r,t], B[h,r,t]: 운영 용량과 이미 치료 중인 환자 등 확정 점유.
- r[i]: 최초 요청시각, L[i]: 허용 치료 시작시각. 재계산 때 r[i]와 L[i]를 초기화하지 않음.

제약:
1. sum_h x[i,h] + u[i] = 1.
2. x[i,h] <= e[i,h]. 미응답·만료 응답으로 확정하지 않음.
3. x[i,h]=1이면 s[i] >= a[i,h] 및 s[i] <= L[i].
4. 배정된 환자는 [s[i], s[i]+d[i]) 동안 q[i,r]만큼 자원을 점유.
5. 모든 h,r,t에 대해 B[h,r,t] + 새로 계획한 점유 합 <= C[h,r,t]. 치료 중 환자를 B와 새 점유에 중복 포함하지 않음.
6. IN_TRANSIT는 기존 병원 이외 x=0. 계산 불가 시 u=1을 ‘조정 필요’로 반환하되 실제 목적지·기존 기록은 자동 삭제하지 않음.
7. TREATING은 병원과 실제 시작시각을 고정. 실측 점유가 용량을 넘는 경우 잘못된 배정으로 숨기지 않고 입력 충돌·운영 검토 상태로 반환.
8. 허용 구간 전체에서 자원 사용을 확인한다. 계획 끝 전에 시작해도 종료가 계획 끝을 넘으면 캘린더를 연장하거나 그 배정을 제외하는 정책을 명시한다.

CP-SAT 구현은 선택적 interval과 누적 자원 제약을 사용한다. 시간대별 용량 변화는 최대 용량에서 차감되는 비가용 구간을 추가하는 방법을 사용할 수 있다. 기존 코드의 2자원 모델부터 유지하고 일반 자원 사전으로 확장한다.

6. 목적함수

초기 기본 실험 정책은 기존 코드의 severity_first를 유지한다. 우선순위 g를 높음·중간·낮음으로 두고, U_g는 미배정 수, W_g는 배정된 환자의 sum(s[i]-r[i])다.

사전식 최소화: (U_높음, U_중간, U_낮음, W_높음, W_중간, W_낮음).

이는 모든 우선순위군의 배정 수를 먼저 정한 뒤 군별 시간을 줄이는 정책이다. 임상적으로 확정된 규칙이 아니며, 낮은 군 배정 증가가 높은 군 지연을 늘리는 사례도 별도 평가한다. 비교 정책 total_first는 맨 앞에 전체 미배정 수를 추가한다.

각 단계가 OPTIMAL로 증명된 경우에만 값을 고정하고 다음 단계로 이동한다. FEASIBLE에서 중단되면 유효한 최선 해를 반환하되 전체 사전식 최적이라고 표시하지 않는다. 허용 지연시간은 실험 설정이며 임상 기준이라고 부르지 않는다.

7. 이동 중 B 유입에 따른 처리

1. 병원 H1이 B의 도착과 자원 점유를 등록한다. 알고리즘은 observed_at 이후에만 이 사건을 알 수 있다.
2. 기존 치료 중 점유는 유지하고, A의 목적지 H1을 고정한 채 치료 시작시각을 재계산한다.
3. 동일 자원을 쓰지 않으면 A에게 영향 없음. 영향을 받으면 변경된 추정 시작시각과 조정 필요 여부를 표시한다.
4. 허용 구간 안에서 치료가 가능하고 병원이 수용을 유지하면 목적지를 유지한다.
5. 수용 유지가 어렵다면 A를 조정 필요로 표시하고 현재 위치에서 대체 병원에 문의한다. 기존 2순위에 자동 배정하지 않는다.
6. 새 수용 응답과 추가 이동시간을 반영한 대안을 담당자가 확인한 뒤 목적지를 변경한다. 새 확정·옛 점유 해제·이력 기록은 한 트랜잭션으로 처리한다.
7. 대체 병원이 없으면 조정 필요와 연락 수단을 반환한다. 해가 없다는 이유로 이동 중 환자를 화면에서 제거하지 않는다.

손으로 확인 가능한 예시(전부 가상, 분 단위): A가 t=0에 H1로 출발, ETA=10, 치료시간=20, 허용 시작시각=30. t=5에 B가 H1의 같은 자원을 점유해 t=25까지 사용한다. 재평가 결과 A는 H1에서 t=25 시작 가능하다. 이 경우 목적지 변경은 필수가 아니다. B 점유가 t=45까지라면 A는 조정 필요다. t=6에 H2가 수용을 확인하고 현재 위치에서 12분 거리이며 자원이 비어 있다면 H2의 예상 시작은 t=18이다. 이 값은 새 응답과 현재 위치를 사용한 대안이지 확정 전 자동 지시가 아니다.

8. 계산 지연과 서버 적용

초기 솔버 예산은 3초 실험값으로 둔다. 최신 입력으로 검증한 순차 배정안을 먼저 만든다. 솔버가 FEASIBLE을 찾으면 유효성을 검증해 반환하고, 못 찾으면 유효한 순차 배정안을 사용한다. 고정 점유 자체가 충돌하면 대체안도 만들 수 없으므로 NEEDS_REVIEW를 반환한다.

현재 구현의 탐욕 초기해·모델 구성 시간은 별도 제어가 없어 프로세스 전체 3초를 엄격히 보장하지 않는다. 운영 요청 제한이 필요하면 작업 프로세스 타임아웃과 응답 상태를 추가한다. 화면의 2~3초 조회와 솔버 실행을 묶지 않는다. 버전이 바뀐 사건을 모아 재계산하고 중복 작업은 합친다.

서버 적용은 snapshot_version·patient_version·응답 유효성의 원자적 비교 후 처리한다. 오래된 결과는 적용하지 않고 최신 버전으로 재계산한다. 기존 commit_allowed는 로컬 검사라 DB 트랜잭션을 대체하지 못한다.

10. 평가 계획

비교군을 3개로 둔다.
- B0: 순차 문의 + 최근접 수용 병원. 현실 전체를 대표한다고 하지 않고 정의된 비교 정책으로 표시.
- B1: 병렬 문의·상황 변경 알림 + 탐욕 배정.
- B2: B1과 동일한 문의·관측 조건 + CP-SAT 배정.

B0↔B1은 문의/알림 방식의 효과, B1↔B2는 알고리즘 효과를 구분한다. 가능하면 문의 방식×배정 방식의 2×2 비교로 보완한다.

동일 난수 seed의 환자 발생, 외부 유입, 실제 치료시간, 이동시간 오차를 모든 군에 재사용한다. 알고리즘에는 실제 사건의 미래나 실제 종료시각을 미리 주지 않고, 관측된 사건과 추정 종료시간만 전달한다. 예측 오차로 계획이 실제로 지켜지지 않는 경우도 결과에 포함한다.

상황: 정상, 미응답, 동시 자원 경합, 미등록 B 유입, 오래된 병원 정보, 적합 병원 없음, 대체 병원 없음. 정보 지연·응답률·외부 유입률·치료시간 오차를 변화시키며 민감도를 본다.

핵심 지표: 최초 요청부터 실제 치료 시작까지의 시간, 군별 미배정·기한 초과, 목적지 변경 횟수·추가 이동, 후보 밖 배정·중복 점유·허위 수용 확정 건수, 계산시간과 대체안 비율. 배정된 환자만의 평균으로 결론 내리지 않고 관찰 종료까지 치료 못 받은 환자를 별도 보고한다. 최소 30개 seed의 짝지은 차이·분포를 제시한다. 임상적 효과가 입증됐다고 주장하지 않는다.

11. 구현 순서와 완료 조건

1. 데이터 계약·API 매핑: 실제 응답을 확보하고 결측·단위·식별자 매칭 확인.
2. A26: 이동 중 병원 고정/시작시각 가변을 분리. B 유입 후 A가 지연될 수 있고 목적지는 자동 변경되지 않는 테스트.
3. 응답 어댑터·확정 처리: 만료 응답 배정 금지, 동시에 두 환자가 마지막 자원에 확정되지 않는 테스트.
4. 이벤트 연결: 미등록 B 등록→영향 환자 표시→재평가→수용 재확인의 시연.
5. B0/B1/B2 공통 시뮬레이터: 같은 사건과 관측 지연을 사용해 검증.

롱리스트 연결: 데이터 A01~A05·S02·S16·T01, 확정 H21~H24·S05·S07, 재계산 A24~A27·H33~H36·P37~P38, 평가 T05·T08~T13. 파일 내 항목 개수를 이번 설계만으로 추가·변경하지 않았다.
