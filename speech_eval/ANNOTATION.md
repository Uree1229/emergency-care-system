# 음성 입력 개발 정답 주석 기준

`corpus_dev.json`은 사람이 작성한 한국어 합성 발화 120개와 정답이다. 15개 `family`에 각각 8개가 있으며 단일 항목 발화와 여러 항목을 함께 말하는 발화를 포함한다. **이 파일에는 실제 녹음, 실제 음성 인식 결과, 환자 기록이 없다.** 오인식처럼 읽힐 수 있는 문구도 작성한 텍스트일 뿐 관찰된 ASR 오류가 아니다.

용도는 `development_synthetic`이다. 제한된 개발 예산에서 작성자가 지원 항목과 보수적 입력 계약을 참고해 선정한 예시이므로 작성자 편향과 반복된 문장 틀이 있다. 신규 독립 검증 표본, 임상 검증 자료, 현장 정확도 추정치로 부르지 않는다. 이 데이터로 규칙을 수정했다면 같은 데이터의 점수는 개발 재현 점수로 보고한다.

## 정답의 출처와 고정 원칙

정답은 각 `reference_text`에 직접 명시된 내용을 사람이 읽어 작성했다. production 추출기나 명령 parser를 실행해 정답을 생성하거나 현재 출력에 맞춰 수정하지 않았다. 지원 필드와 형식 제한, 명령 계약은 `server/voice_terms.py`와 `config/paramedic_voice_terms.json`을 읽어 참고했다. 현재 parser가 처리하지 못하는 명백한 발화도 정답은 발화 의미를 유지한다. 예를 들어 `BP 90/60`은 수축기 90·이완기 60, `HR 130 bpm`은 맥박 130, `호흡수 이십`은 20, `맥박 아흔둘`은 92이다. 이 사례를 parser 출력을 따라 빈 정답으로 바꾸면 안 된다.

이 corpus는 **16개 초안 항목을 발화에서 얼마나 충실하게 옮기는지**를 측정한다. 환자의 실제 상태, 수치의 의학적 정상 여부, 진단, 중증도, KTAS, 적절한 진료과·치료·이송 여부에 대한 의학적 정답을 제공하지 않는다.

## 구조

- `observed_at = 1793332800`은 상대 발생 시각 계산에 쓰는 고정 유닉스 초다. 평가 시 실행 시각으로 바꾸지 않는다.
- `id`는 사례 식별자이며 유일하다. `reference_text`는 1~4000자다.
- `family`는 오류 유형별 집계 단위다. `template_group`은 수치·표면 표현만 달라진 유사 문장 틀을 묶는다. 향후 분할 실험에서는 동일 group을 양쪽에 나누지 않는다. 현재 파일 자체에는 독립 시험 세트가 없다.
- `mode`는 발화 내용으로 추측하는 대상이 아니라 평가 호출에서 제공하는 입력 모드다. 명령 의미는 `command` 모드에서만 평가한다.
- `expected.action`은 `dictation`, `review`, `undo`, `confirm`, `submit`, `edit`, `add`, `unknown` 중 하나다.
- `expected.fields`에는 발화가 확정해 주는 지원 항목만 넣는다. 빠진 key는 미언급·제외를 뜻하며 `null`, 0, 빈 목록, `unknown`으로 채우지 않는다. 숫자 0이 직접 발화된 경우에는 별개의 실제 값으로 보존한다.
- `expected.review_field`는 조회 명령의 대상이다. 전체 조회는 `null`이다. `blood_pressure`는 조회 시 혈압 두 항목을 함께 읽기 위한 별칭이며 `fields`에 저장하는 17번째 항목이 아니다.

## 지원 항목과 값

|항목|정답 형식과 의미|
|---|---|
|`age`|직접 말한 정수 나이, 0~130|
|`age_group`|직접 말한 십 년 단위 문자열 `0대`~`120대`|
|`sex`|`male`, `female`, `unknown`|
|`symptoms`|명시한 현재 증상의 canonical 문자열 목록|
|`denied_symptoms`|명시적으로 없다고 한 현재 증상의 canonical 목록|
|`uncertain_symptoms`|현재 여부가 미확인·불확실한 증상의 canonical 목록|
|`consciousness`|`alert`, `impaired`, `unresponsive`, `unknown`|
|`breathing`|`normal`, `abnormal`, `absent`, `unknown`|
|`systolic_bp`|정수 1~350 mmHg|
|`diastolic_bp`|정수 1~250 mmHg|
|`pulse`|정수 0~350 회/분|
|`spo2`|수치 0~100 %|
|`temperature`|수치 20~45 °C|
|`respiratory_rate`|정수 0~100 회/분|
|`glucose`|수치 0~1500 mg/dL|
|`onset_at`|현재 증상 발생과 명시적으로 연결된 유닉스 초 정수|

수치 범위는 production 입력 형식 제한이다. 임상적 정상·이상 판정이 아니다. 지원 단위가 아닌 화씨나 mmol/L은 이 계약에서 자동 변환하지 않는다. 범위를 벗어난 값, 정수가 필요한 항목의 소수, 수축기 ≤ 이완기인 혈압을 임의로 수정·반올림·뒤집지 않는다.

증상 canonical 어휘는 `흉통`, `호흡곤란`, `복통`, `두통`, `어지럼`, `구토`, `오심`, `발열`, `기침`, `객혈`, `출혈`, `경련`, `실신`, `마비`, `의식저하`, `설사`, `요통`, `발진`, `외상`, `부종`, `심계항진`이다. 예를 들어 `가슴 통증` → `흉통`, `현기증` → `어지럼`만 정규화한다. 증상 목록의 순서는 임상적 의미가 없으므로 평가 시 집합으로 비교할 수 있다. 동일 증상을 있음·없음·미확인에 동시에 넣지 않는다.

## 발화 해석

1. **직접 명시한 값만 기록한다.** `55세`에서 `50대`를 추가하지 않고 `70대`에서 정확한 나이를 만들지 않는다. 성별·의식·호흡 상태를 말투, 나이, 다른 수치로 추정하지 않는다. `의식 있음`은 `alert`의 근거가 아니다. `호흡곤란`만으로 `breathing=abnormal`을 만들지 않는다. 명시적인 `의식 저하`는 증상 canonical `의식저하`와 상태 `impaired`를 둘 다 표현한다.
2. **부정과 불확실성을 구분한다.** `흉통 없음`은 `denied_symptoms`, `흉통 의심`은 `uncertain_symptoms`다. 이중 부정 `흉통이 없는 것은 아님`은 확정된 현재 흉통으로 단정하지 않는다. `의식 미확인`처럼 상태 자체가 미확인이라고 명시된 경우에는 enum `unknown`을 기록한다. 미언급 상태를 `unknown`으로 생성하지 않는다.
3. **모호한 수치는 추측하지 않는다.** 대략·범위·소수 일부 누락·여러 후보·`일이공`처럼 해석이 불확실한 연속 한글 숫자는 빈 정답으로 둔다. 명백한 한자어 수사와 고유어 수사는 실제 수치로 적는다. `아흔둘`을 90으로 잘라 읽거나 `이십`을 2로 읽는 것은 오류다.
4. **현재 환자와 다른 주체·시점을 분리한다.** 가족, 과거력, 지난주 측정, 끝난 과거 사건은 현재 관찰에 넣지 않는다. 별도 문장의 현재 환자 관찰은 유지한다. 다만 `1일 전부터 복통이 시작됨`은 현재 증상의 발생 시각을 명시하므로 단순 과거력 배제와 다르다.
5. **질문은 관찰이 아니다.** dictation의 `혈압 120에 80입니까?`는 값이 없다. 같은 발화의 별도 문장이 현재 증상을 확정하면 그 문장만 기록한다. command의 `맥박 얼마야?`는 조회이며 새 측정값을 만들지 않는다.
6. **상충된 관찰에서 마지막 값을 선택하지 않는다.** 서로 다른 혈압, 맞지 않는 나이와 연령대, 동일 증상의 있음/없음 충돌은 해당 항목을 제외한다.
7. **dictation 정정 발화에는 보수적 제외 계약을 적용한다.** `A 아니고 B`, 정정·수정·취소가 섞인 dictation은 전체 `fields={}`다. 이 사례에는 `reference_policy_exclusion` 태그를 붙였다. 이는 B를 사람이 이해할 수 없다는 의미가 아니라 별도 수정 명령이나 직접 확인을 요구하는 입력 정책이다. 반면 명시적인 command `혈압 110에 70으로 수정해`는 `action=edit`와 혈압 110/70을 정답으로 갖는다.
8. **명령 모드를 존중한다.** dictation은 `action=dictation`이며 발화에서 명령을 자동 승격하지 않는다. V058/V100의 `확인 완료`, V060/V101의 `환자 정보로 전송`은 같은 문구에 다른 모드를 제공하는 경계 사례다. command의 조회·취소·확인·전송은 새 관찰 `fields={}`다. 수정·추가는 해당 내용만 추출한다. `확인하고 전송해줘` 같은 복합 명령은 `unknown`이며, `전송하지 마`도 `submit`으로 해석하지 않는다. `confirm`과 `submit`은 별도 동작이다.

상대 발생 시각 정답은 다음과 같이 직접 계산했다.

|사례|발화 간격|직접 계산|
|---|---|---|
|V113|10분|1793332800 − 600 = 1793332200|
|V114|2시간|1793332800 − 7200 = 1793325600|
|V115|1일|1793332800 − 86400 = 1793246400|
|V117|5분|1793332800 − 300 = 1793332500|

`오늘 오전 9시` 같은 절대 시각은 이 초안 계약에서 날짜·시간을 사람이 확인하는 대상으로 두며 자동 생성하지 않는다. `observed_at`은 실제 녹음 일시나 환자 관찰이 수행됐다는 증거가 아니다.

## 무엇을 측정하고 어떻게 보고할 것인가

텍스트 정답만 사용하는 실행은 **reference transcript → 구조화/명령 평가**다. 실제 음성을 확보한 뒤에만 음성 인식 오류와 후속 구조화 오류를 함께 측정할 수 있다. 녹음 없이 WER/CER을 0으로 적거나 음성 정확도를 보고하지 않는다. 녹음이 일부 사례만 있으면 녹음된 사례 수, 인식 성공 수, 누락·실패 수를 분리해 표기한다. 누락 사례를 성공으로 계산하지 않는다.

측정할 오류는 명령 action 또는 조회 대상의 혼동, 필요한 key 누락, 언급하지 않은 key 추가, 숫자·enum·증상 값의 오기, 증상 부정/불확실성의 뒤바뀜, 질문·가족·과거 정보를 현재 사실로 입력한 오류, 모호한 수치의 임의 선택이다. 특히 정답 `{}`에서 값이 생긴 경우도 오류로 센다. 사례 전체 일치율 외에 action, 필드 누락·추가·값 오류, `family`별 건수와 결과를 함께 보아 긴 발화와 짧은 발화의 차이를 확인한다.

실제 녹음을 연결할 때도 원문과 이 정답을 인식 결과에 맞춰 고치지 않는다. 녹음자가 reference와 다른 말을 했다면 녹음 불일치로 분류하고 별도 전사·검토를 거친다. 수집된 녹음은 합성 문장을 읽은 음성일 수 있으므로 실제 환자 대화·독립 현장 검증 자료와 구분해 보고한다. 정답 오류를 발견하면 근거 발화, 변경 이유, 영향을 받는 사례 ID와 데이터 버전을 남기고 수정한다.
