# 구급대원 음성 입력 평가

현재 서버의 `server.voice_input._extract`와 `voice_terms.parse_command`를 직접 평가한다. `_extract`는 기본 추출기와 R1 확장을 합친 실제 경로다. 기존 `voice_lab/`는 별도 R1 추출기의 연구 기록이므로 수정하지 않는다. 두 도구의 입력 필드와 정답 정책이 달라 결과 수치를 직접 비교하지 않는다.

## 준비한 데이터

[`corpus_dev.json`](corpus_dev.json)은 **15개 유형 × 8문장 = 합성 개발 문장 120개**다. 나이·성별·의식·호흡·증상·활력징후 등 관찰 정보 **16개 항목**을 다룬다. 서버의 R1 확장 항목은 실행 결과에 보존하지만 정답이 없어 채점하지 않는다. 지원 29개 항목 전체의 정확도로 해석하면 안 된다. 숫자·한글 수·약어·긍정/부정/불확실·미언급·질문·과거/가족·정정·추가·조회·되돌리기·확인·전송 명령을 포함한다.

정답은 사람이 읽을 수 있는 발화의 뜻과 명시한 보수적 처리 정책에 따라 작성했다. 추출기를 실행해 정답을 생성하지 않았다. [정답 작성 기준](ANNOTATION.md)을 함께 확인한다. 작성자와 표현의 편향이 있는 **개발용 자료**이며 독립 검증·의학적 정답·실제 발화 정확도 자료가 아니다. `template_group`이 같은 표현 변형을 독립 시나리오처럼 세지 않는다.

이 정답은 '직접 언급한 관찰만 입력'하는 기준이다. R1 확장이 증상으로부터 기존 관찰 항목을 보충하면(예: 호흡곤란에서 `breathing` 추가) 불필요한 자동입력으로 표시한다. 이는 명시한 정답 정책과의 차이이며 임상적으로 틀렸다는 판정이 아니다. 수치·부정 오류와 정책 차이를 원문에서 따로 검토해야 한다. 빈 초안에서의 추출만 평가하며, 이전 초안과의 재조정·필수 항목 검사·환자정보 제출은 별도 API 검증 범위다.

## 먼저 현재 기준선 실행

프로젝트 루트에서:

```powershell
python -m speech_eval evaluate --output outputs/speech_eval/my_reference_run
```

출력 폴더가 이미 있으면 실행을 거부한다. 소스·사전·정답 파일 해시를 실행 전에 잠그고, 실행 후 달라졌으면 결과를 게시하지 않는다. 실행에 사용한 추출기·평가 코드·정답도 `sources/`에 보존한다. 이 스냅샷은 전체 서버를 대신하는 독립 배포 패키지는 아니다.

| 산출물 | 내용 |
|---|---|
| `report.html` | 브라우저에서 원문·정답·추출 결과 비교. 오류 문장만 표시 가능 |
| `report.md` | 전체·유형별 요약과 실패 문장 |
| `report.json` | 항목별 오류·증상 극성·명령·출처·짝지은 비교의 원자료 |
| `reference_cases.csv` | 합성 대본을 그대로 넣었을 때의 결과 |
| `recordings.csv` | 가져온 STT 출력별 결과. 실제 음성 없으면 헤더만 있음 |
| `recording_template.json` | 실제 결과를 추가할 빈 양식 |
| `source-lock.json`, `sources/` | 소스와 입력의 해시·스냅샷 |

## 실제 음성 결과 수집

새 앱의 [음성 입력 시험 화면](http://127.0.0.1:18032/paramedic/evaluate.html)을 사용한다. 다른 포트에서는 공통 서버의 `/paramedic/evaluate.html`이다.

1. 가상 대본과 익명 화자 ID, 조용한 환경·배경 소음·마스크 등 조건을 선택한다.
2. `읽기 시작`을 누르고 대본을 그대로 읽는다. 다른 말로 읽었으면 다시 시도한다.
3. 최종 인식 결과는 수정하지 않는다. 대본과 동일하게 읽었는지 확인하고 `결과 기록`을 누른다. 인식 실패도 별도로 기록할 수 있다.
4. 여러 화자·조건의 결과를 모아 `JSON 내려받기`를 누른다. 파일은 내려받기 전까지 메모리에만 있다.
5. 내려받은 파일로 평가한다:

```powershell
python -m speech_eval evaluate --recordings "C:/path/speech-recordings.json" --output outputs/speech_eval/my_recorded_run
```

녹음 파일 자체는 수집 화면에서 저장하지 않는다. 브라우저 STT가 반환한 원문과 인식 상태·조건·화자 ID를 보존한다. 익명 ID는 실명이나 연락처를 넣지 않는다. 임의의 실제 환자 대화를 사용하지 말고 준비된 가상 대본만 읽는다. 실제로 읽은 문장이 대본과 다르면 정답 항목도 다시 검토해야 한다.

다른 엔진의 STT 결과는 같은 JSON 양식이나 JSONL로 가져올 수 있다. 각 항목은 `recording_id`, `case_id`, `source`, `engine`, `condition`, `status`, `hypothesis`가 필요하다. `source: human_voice`에는 익명 `speaker_id`와 `reference_verified: true`도 필요하다. JSON 패키지에는 최상위 `dataset_id`·`corpus_sha256`가, JSONL에는 각 행에 두 값이 필요하다. 성공 `status: ok`의 빈 문장은 거부하며, 미인식은 `no_match`, 엔진 오류는 `error`로 기록한다. 실패 결과의 평가용 `hypothesis`는 빈 문자열이다. 오류 전에 수신한 최종 조각은 `raw_hypothesis`·`collection.received_final_fragments`로 별도 보존한다.

수집기의 `corpus_sha256`는 사용한 대본 버전을 연결한다. 다른 정답 파일의 해시가 오면 가져오기를 거부한다. 화자 ID·환경별 자료를 나누어 보되 같은 화자가 여러 번 읽은 문장을 독립 화자처럼 세지 않는다.

## 합성 오인식으로 도구만 시험

```powershell
python -m speech_eval evaluate --recordings speech_eval/recordings_synthetic_example.json --output outputs/speech_eval/my_simulated_run
```

예시는 수치 바뀜·부정어 소실·명령어 소실·미인식을 손으로 만든 네 건이다. 실제 음성이 아니므로 `synthetic_corruption`으로 별도 집계하며 실제 음성 성능이나 소음 영향으로 해석하지 않는다. 수집 화면의 `합성 결과 넣기`도 같은 출처로 표시한다.

## 평가 방식

- **원문 → 추출기:** STT를 거치지 않은 합성 대본 기준선.
- **STT 출력 → 같은 추출기:** 실제 인식문 또는 출처를 명시한 합성/수동 문장.
- **짝지은 분해:** 원문에서는 맞았는데 STT 출력에서 틀린 경우, 원문에서도 틀린 경우를 구분한다. 두 단계의 오류를 하나의 정확도로 섞지 않는다.
- **항목:** 맞은 값·다른 값·누락·불필요한 자동입력, 정밀도·재현율. 다른 값은 거짓 양성과 거짓 음성에 각각 한 번 기여한다.
- **증상:** 있음·없음·불확실을 별도로 비교한다. 미언급을 없음으로 채우지 않는다.
- **숫자:** 혈압·산소포화도 등의 틀린 값과 누락을 구분한다. 단위가 다른 숫자 오차를 하나의 평균으로 합치지 않는다.
- **명령:** 앱과 똑같이 받아쓰기/명령 모드를 고정한다. 조회 대상은 조회 명령에서만 비교한다. 정정 명령의 대상 안내 메타데이터를 오류로 세지 않는다.
- **문자 오류:** Unicode NFKC·대소문자 정규화 후 CER/WER를 계산한다. CER은 공백을 무시하고, 소수점·부호·슬래시는 보존한다. 한글 수를 숫자로 바꾸는 표기 차이도 문자 오류가 될 수 있어 항목 정확도와 함께 본다.
- **실패:** 인식 실패를 성공한 결과의 평균에서 조용히 빼지 않는다. 시도 수·실패 수·구조화 성능의 분모에 남기며 문자 오류율은 실제 출력이 있는 경우의 분모를 따로 표시한다.
- **시간:** 기록이 없는 시간·수정 횟수는 0이 아닌 미측정이다. `parser_runtime_ms`는 서버 계산시간이며 구급대원의 작업시간이 아니다.

`timing`에 같은 단조 시계의 `input_start_ms`, `speech_start_ms`, `speech_end_ms`, `stt_final_ms`, `review_done_ms`, `submit_done_ms`, `correction_count`를 제공하면 해당 값이 있는 구간만 집계한다. 순서가 모순이면 시간값을 제외하고 경고를 남긴다. 브라우저 수집 화면은 마지막 STT 콜백 시각만 기록하며 실제 발화 종료를 알 수 없어 `speech_end_ms`나 전체 입력시간을 만들어 넣지 않는다. `collection.capture_*`는 캡처 상태 시각이며 실제 발화 시각이 아니다.

## 다음에 필요한 실제 실험

같은 과업을 수동 입력과 음성 입력으로 수행하고, 발화·대기·수정·확인·전송까지의 총시간, 오입력, 조작 수를 비교해야 한다. 참가자와 과업 순서를 교차 배치해 학습 효과를 줄인다. 동료 시험을 실제 구급대원 사용성 검증으로 부르지 않는다. 개발 자료로 발견한 문제를 고친 후에는 새 화자·새 문장·새 녹음으로 별도 검증한다.

새 대본 JSON 생성(기존 파일은 덮어쓰지 않음):

```powershell
python -m speech_eval prompts --output paramedic-ui/new-evaluation-cases.json
```

검증:

```powershell
python -m unittest test_speech_eval_metrics test_speech_eval_runner
```
