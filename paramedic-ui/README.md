# 이송 노트 — 별도 구급대원 웹 앱

최신 메인 연결: [음성·이송·치료조건 검토·추천·알림 연결](../docs/MAIN_UI_INTEGRATION_20261030.md). 메인 확인 질문·보류·미측정·변경 전후, 같은 환자 진행 링크와 WAITING 명시 치료조건 적용을 추가했다. 확정·이송 중에는 같은 환자의 별도 병원 검토 화면으로 연결한다. 아래 최초 작성 기록과 최신 상태를 구분한다.

2026-10-30. 팀원 앱과 별개로 새로 작성한 웹 앱이다. 기존 `patient-ui`, `emergency-app`, `hospital-ui`를 수정하거나 가져오지 않았다. 공통 서버의 음성 초안 API와 환자·병원 후보 API를 사용한다.

메인 이송 노트: **http://127.0.0.1:8000/paramedic/**

간편 음성 시험은 **http://127.0.0.1:8000/paramedic/quick-test.html** 에서 진행한다(음성 V2, 2026-10-30). 토글·음성 종료는 이 화면에서 사용한다. 메인 화면(`/paramedic/`, `index.html`)에는 별도로 로컬 WAV 녹음과 PCM 소음 설정 비교를 추가했다. [시험 방법·실험 결과·한계](../docs/VOICE_NOISE_TESTING_20261030.md).

- **화면(시안 B 대화형, 10-30 사용자 선택):** 위에 환자 요약 칩(확인 질문 12항목: 변화 ▼·질문 중·보류·미측정·빈칸 구분), 가운데에 대화(앱 질문과 말한 문장 말풍선, 그 아래 처리 결과 태그), 아래에 질문 카드와 큰 원형 마이크가 있다. 질문이 있으면 큰 마이크는 그 질문에 답하고 왼쪽 `다른 내용` 버튼이 일반 입력이다. 의식·호흡처럼 보기가 정해진 질문은 보기 버튼을 탭해도 된다. 상세 값·근거·경고는 `전체 보기`, 말하기 방식·예시·안내는 설정에 있다. 시스템 설정에 따라 다크 모드로 바뀐다.
- **토글 방식(기본):** 버튼을 한 번 눌러 시작하고 다시 눌러 종료한다. 손을 떼어도 계속 듣는다. 확정 인식 조각을 합쳐 종료 후 서버에 한 번 보낸다. Space·Enter도 한 번 눌러 시작·종료하며 키 자동 반복은 무시한다. 앱의 상한은 180초이고, 브라우저 음성 서비스가 먼저 종료할 수도 있다.
- **중간 명령:** 두 마이크 조작 방식 모두 확정 인식문의 “그만”·“중단”·“종료”·“녹음 종료”를 문장 중간에서도 처리한다. 첫 유효 명령 앞의 본문을 기존 입력 방식·질문 문맥으로 저장한 뒤 마친다. 임시 인식문과 임상·인용·부정 표현은 제외하며, 명령만 있으면 빈 초안이나 발화를 만들지 않는다.
- **병원 추천 명령:** “병원 추천해줘”·“병원 추천해 주세요”는 앞 본문의 저장 응답을 확인한 뒤 `병원 추천 준비`를 연다. 응답 유실은 같은 요청 재시도로 확인하고, 충돌·실패 중에는 진행하지 않는다. 계속 버튼을 누르면 동일 초안을 GET으로 복원해 정보 확인·위치·동의·명시적 환자 등록을 거쳐 기존 후보 조회로 이어진다. 초안 확인·환자 등록·병원 문의를 음성 명령만으로 실행하지 않는다. [동작 계약과 검증](../docs/VOICE_MID_TRIGGER_20261030.md).
- **무전기 방식(선택):** 설정에서 `누르는 동안 말하기`를 고르면 누르는 동안 듣고 손을 떼어 종료한다. 0.4초보다 짧은 누름은 버리고 최대 30초다. 중간 명령도 적용한다.
- **원문과 늦은 인식:** `인식 원문 · API 전송 본문`에서 확정 원문, 명령 앞 전송 본문, 종료 사유·시각을 구분한다. 명령 뒤의 같은 문장과 늦은 확정 인식은 `명령 뒤 추가 인식 (미반영)`에 남긴다. 다음 녹음에도 유지하고, 직접 입력으로 가져와 검토·반영하거나 추천 준비 화면으로 수동 검토용으로 이어갈 수 있다. 버튼·시간 상한으로 종료할 때는 늦은 확정 결과까지 모은다.
- **직접 입력 시험:** 설정의 `직접 입력 시험`에서 1~4000자 본문을 검토해 초안에 반영할 수 있다. 직접 입력에는 음성 종료어 규칙을 적용하지 않는다. 같은 본문을 성공 직후 다시 보내지 않으며, 녹음·요청 처리 중에는 입력 방식을 바꾸거나 수동 본문을 반영할 수 없다. 음성 본문이 4000자를 넘으면 원문을 화면에 남기고 전송하지 않는다.
- **자동 판단(기본):** `mode: "auto"`로 보낸다. 상태 설명과 “혈압이 100에 70으로 떨어졌어” 같은 변화는 초안에 반영하고, “방금 거 취소”·“정리해줘” 같은 말은 명령으로 처리한다. 음성 “확인”·“전송”은 실행하지 않는다. `환자 상태만`·`수정·확인 명령`으로 바꿀 수 있다.
- **방금 바뀐 내용:** `session.latest_changes`로 `이전 값 → 현재 값`과 수치 방향(▲▼)을 보여 준다. 값 없이 “맥박이 떨어졌어”처럼 말해 서버가 재확인 표시를 하면, 이전 값을 **이전 관찰값**으로 표시하고 현재 값은 미확인으로 둔다.
- **확인 질문:** `session.followup.next_question`을 카드로 보여 주고, 마이크가 닫힌 뒤 한 번 읽어 준다. 카드의 답하기 버튼도 선택한 토글·무전기 방식을 따르며, `followup/answers`로 그 질문의 답만 보낸다. `미측정 · 모름`은 `unavailable: true`로 보내며 값을 채우지 않는다.
- **널널한 답변 처리:** 구급대원이 검토·전송 때 고친다는 전제로, 답을 깐깐하게 다시 묻지 않는다.
  - ‘비 측정’·‘및 측정’·‘미측’·‘측정 안 했어요’·‘모르겠어요’ 같은 답은 미측정으로 보낸다(들린 문장 그대로 + `unavailable: true`).
  - 답변 녹음 때는 인식 후보 5개 중 질문에 맞는 것을 고르고, 그 질문의 보기 단어를 힌트로 준다(특정 숫자는 넣지 않음).
  - 서버가 답을 받지 않으면 같은 질문을 반복하지 않고 **보류**한 뒤 다음 질문으로 넘어간다. 보류한 질문은 들린 말과 함께 검토 목록에 남긴다.
  - 값 판정 자체(‘분당 20회’, ‘혈압 120 80’ 등)는 서버 담당이며, 완화안을 [작업 기록](../docs/VOICE_UI_CLAUDE_HANDOFF.md) 5.5절에 넘겼다.
- **서버 확인:** 시작할 때 `voice_revision`이 `voice-v2-20261030`인지 확인하고, 다르면 화면 아래에 경고한다. 서버가 `auto`를 지원하지 않으면 `환자 상태만`으로 바꾼다.
- **저장 확인:** 서버 응답으로 확인한 저장 발화 수를 표시한다. `저장된 기록 확인`에서 서버 주소·전체 기록 ID·버전을 볼 수 있다. 원문이 저장돼도 환자 항목이 추출되지 않을 수 있어 두 상태를 구분한다. 응답이 불확실하면 이번 입력은 확인 중으로 표시한다. [실행 중인 서버의 DB 점검 방법](../docs/VOICE_STORAGE_CHECK.md).
- **중간 저장·복구:** 같은 브라우저·서버 주소에서 마지막 임시 저장 후 12시간 이내에 다시 열면 같은 작성자·초안을 GET으로 복원한다. 아직 전송하지 않은 확정 인식문과 직접 입력은 미반영 검토용으로, 저장 여부가 불확실한 요청은 원래 요청 번호·본문·버전을 유지한 재시도 대상으로 복원한다. 마이크·음성 명령·환자 등록·병원 문의는 복원만으로 실행하지 않는다. [저장 범위와 검증](../docs/VOICE_DRAFT_RECOVERY_20261030.md).
- **환자별 기록 전환:** 현재 환자 번호를 상단에 표시하고 목록 선택·새 환자·직전 환자 전환을 지원한다. 음성 “새 환자 시작”·“이전 환자로 돌아가”는 앞 내용을 현재 환자에 저장한 뒤 전환한다. 명령 뒤 문장은 원환자에 미반영으로 남긴다. 환자별 작성자·초안·미반영 내용·수정안을 분리하며 전환 시 복창 확인은 다시 시작한다. 저장 확인 대기 중에는 전환을 막는다. [분리·이전 복구본 이관·정리](../docs/VOICE_PATIENT_SWITCH_20261030.md).
- **병원 인계용 요약:** `병원 인계용 요약`을 열어 저장된 관찰·마지막 변경·미확인 항목을 입력 기반 초안으로 만든다. `인계 요약해줘`는 앞 본문 저장 후 같은 미리보기를 연다. 미반영 원문·알고리즘 제안은 사실에 넣지 않으며, 복사·읽어주기 직전 최신 초안과 비교해 바뀌었으면 재생성을 요구한다. 환자 전환 시 미리보기를 비운다. 복사·읽기는 별도 버튼으로 실행하며 병원에 자동 전송하지 않는다. [구성·제약·검증](../docs/VOICE_HOSPITAL_HANDOFF_20261030.md).
- **상태 관찰·수정 이력:** 저장된 여러 버전의 이전 값·이후 값과 재확인 상태를 최신순으로 비교한다. 기록 입력·관찰 변화 입력·입력 수정·되돌림·질문 답변을 구분한다. 조회 전후 저장본을 대조하고 변경·환자 전환·조회 실패 시 오래된 카드를 비운다. 전체 건수와 최근 최대 20건을 표시하며 미반영 원문은 넣지 않는다. [조회 계약·검증](../docs/VOICE_OBSERVATION_HISTORY_20261030.md).
- **통신 장애 안내:** `연결·저장 상태`에서 브라우저 온라인 표시·API 응답·음성 인식·브라우저 임시 보관·서버 저장 확인을 구분한다. `서버 연결 확인`은 최대 6초의 읽기 전용 점검이며, 대기 요청 재전송·새 초안 생성·자동 반영을 하지 않는다. 직접 입력은 기존 검토칸을 유지해 열며 저장 확인 대기는 기존 재시도로 먼저 처리한다. [오류 구분·복구·검증](../docs/VOICE_CONNECTION_GUIDANCE_20261031.md).
- **음성 명령 연습·데이터 수집:** `/paramedic/command-practice.html`에서 합성 대본 96개(긴 대본 40개)·자유 발화·반복·섞기·실패 재시험과 소음/말하기/장비 조건을 기록한다. 시도 자동 보관, 원문과 독립된 정답 검토, JSON 합치기·CSV/TXT 내보내기와 파일 확인 후 새 묶음을 지원한다. 마이크 경로와 수동 모의를 분리하며 환자·병원 API를 호출하지 않는다. [사용법·자료 형식·검증](../docs/VOICE_COMMAND_PRACTICE_20261031.md).
- **중요 항목 복창 확인:** 저장된 혈압·맥박·산소포화도·체온·호흡수·혈당·의식·호흡·증상 분류를 먼저 읽는다. 없음·미확인·누락·이전 관찰값을 구분한다. 항목의 맞아요 또는 말로 확인 버튼으로 현재 표시 내용을 확인하며, 최신 초안 GET 뒤 같은 버전·값일 때만 이 화면의 확인 상태를 바꾼다. 잘못된 항목은 그 항목의 수정칸에서만 PATCH로 고치고 다시 확인한다. 추천 준비의 계속 버튼은 복창 확인이 끝난 뒤 사용할 수 있다. [확인·수정·재시도 계약](../docs/VOICE_CRITICAL_REVIEW_20261030.md).
- **문맥 힌트:** 서버 힌트 중 항목 이름·증상 용어만 브라우저 `SpeechRecognitionPhrase`에 넘긴다. ‘의식 명료’·‘구토 없음’·숫자처럼 값이 든 표현은 정상 소견 쪽으로 인식을 끌 수 있어 넘기지 않는다. 브라우저가 거부하면 한 번만 일반 인식으로 다시 시작한다. 힌트를 넘긴 것과 정확도 개선은 별개이며 측정하지 않았다.

저장 응답을 잃어 결과가 불확실하면 새 입력을 막고 `재시도`를 제공한다. 재시도는 원래 요청 ID·본문·버전을 유지한다. 409에서는 최신 초안과 질문을 다시 불러오며 이전 본문을 자동 덮어쓰지 않는다.

`새 환자 시작`은 현재 기록을 보관한 뒤 새 작성자·환자 번호를 준비하며 이전 기록을 지우지 않는다. `현재 환자 복구본 제거`는 해당 환자의 브라우저 임시본만 지우고 서버 원기록·다른 환자는 보존한다. 환자 본문을 처음 전송할 때 서버 초안을 만든다. 전환 자체는 실제 환자 등록·병원 문의·전송 API를 호출하지 않는다. 작업 기록: [Claude 구급대원 화면 인계](../docs/VOICE_UI_CLAUDE_HANDOFF.md).

이 화면은 **자유 발화 기능 확인**이며 정답 일치율이나 실제 음성 정확도를 계산하지 않는다. 관찰 항목과 R1에서 파생한 추가 제안을 구분해 표시한다. 서버에는 성공적으로 전송한 본문과 결과가 남는다. 같은 브라우저의 localStorage에는 환자별 초안 참조, 미반영 확정문·직접 입력, 원본 재시도 요청의 최소 데이터를 보관하며 원본 음성·임시 인식·전체 서버 임상 스냅샷은 넣지 않는다. 12시간은 자동 복원 유효기간이다. 공용 기기에서는 작업 후 환자별 복구본 제거로 정리한다. 브라우저 저장 공간 삭제·비공개 모드 종료·다른 브라우저나 서버 주소로의 이동은 복구 범위에서 제외된다.

정답을 고정한 문장별 STT 결과 수집은 **http://127.0.0.1:8000/paramedic/evaluate.html** 에서 별도로 진행한다. [정답셋·평가 실행·현재 기준선](../docs/SPEECH_EVALUATION.md).

## 기능

- 한국어 브라우저 실시간 음성 인식: 부분 문장은 임시 표시하고 최종 문장만 서버 초안에 반영한다.
- Azure 짧은 녹음 인식: 마이크 PCM을 16kHz·모노·16비트 WAV로 변환해 서버에 보낸다. 최대 60초다. 서버 Speech 키가 설정되지 않으면 이 옵션을 비활성화한다.
- 로컬 오디오 시험: 키 없이 최대 60초 WAV와 익명 설정 JSON을 직접 내려받는다. 원본 오디오를 STT·서버로 보내지 않는다. 다음 녹음 전에 내려받아야 하며 메모리의 파일은 새 녹음·새 기록·페이지 종료 때 정리한다. 페이지 연결 과정의 빈 초안 생성과 오디오 전송은 구분한다.
- PCM 입력 비교: 기본 `legacy` 설정을 유지하고 `raw`·`noise_suppressed` 요청 프로필을 선택할 수 있다. 요청·지원·기기가 보고한 실제 값을 구분하고 미확인은 그대로 남긴다. 브라우저 STT에 이 설정이 적용됐다고 표시하지 않는다.
- 음성 명령·수동 항목 정정·새 관찰·되돌리기, 전체·항목별 읽어주기.
- 명령 모드에서는 최종 문장을 받으면 마이크를 닫은 뒤 결과를 읽어준다. 앱의 안내 음성이 재입력되지 않도록 한다.
- 현재 버전 확인 → 동의·GPS 또는 직접 위치 → 환자 등록 → 병원 후보 확인. 조건과 위치는 음성에서 추정하지 않는다.
- 기존 환자 ID를 불러와 목적지 확정 전 정보를 수정할 수 있다. 수정은 기존 환자정보 변경 계약을 따른다.
- 응답을 잃은 쓰기는 원래 요청 ID·본문·버전으로 재시도한다. 409 뒤 자동 덮어쓰기는 하지 않는다.

마이크는 버튼을 눌렀을 때만 켠다. 화면을 나가거나 입력을 종료하면 마이크·오디오 자원을 정리한다. 서버 파일 인식은 종료 후 결과가 나오는 방식이며 실시간 인식으로 표시하지 않는다. 브라우저 음성 서비스·마이크 권한·네트워크에 따라 실제 인식 가능 여부가 달라진다. 읽어주기는 장치의 한국어 TTS를 사용한다. 마이크를 쓸 수 없어도 문장 입력으로 같은 서버 흐름을 확인할 수 있다.

## 실행

새로운 가상 시연 DB를 처음 만들 때 한 번만 실행한다. **`--seed`는 지정한 DB를 초기화하므로 기존 공공·팀 개발 DB에는 사용하지 않는다.**

```powershell
python -m server.app --db data/paramedic-voice-demo.db --seed --port 8000 --no-planner --no-inquiry-worker
```

다음 실행은 `--seed`를 빼고 데이터 유지:

```powershell
python -m server.app --db data/paramedic-voice-demo.db --port 8000 --no-planner --no-inquiry-worker
```

http://127.0.0.1:8000/paramedic/ 를 연다. 같은 서버의 API를 기본으로 사용하며 화면 왼쪽에서 다른 공통 서버 주소를 지정할 수 있다. 모바일 마이크·위치는 HTTPS 또는 localhost와 브라우저 권한이 필요하다. LAN의 일반 HTTP 접속에서는 마이크·위치가 제한될 수 있다.

## 시험 순서

1. `예시 문장 넣기` → `문장을 검토 항목에 반영`. 예시는 음성을 인식한 결과가 아닌 가상 입력이다.
2. `명령 직접 입력`에 `혈압 120에 80으로 수정해` → 실행. 실제 마이크 시험은 입력 모드를 `음성 명령`으로 바꾸고 같은 말을 한다.
3. 항목을 직접 수정해 저장하거나 이전 변경을 취소한다. 비어 있는 추가 항목은 `추가 항목 입력`을 펼친다.
4. `읽어주기` → `기록 확인 완료`. 이후 내용을 수정하면 다시 확인해야 한다.
5. GPS 또는 직접 좌표를 입력한다. `광주 시연 위치`는 가상 시험 좌표이며 실제 위치가 아니다.
6. 필요한 진료 분야와 동의를 직접 확인 → `환자 등록`. 후보 병원과 확인 필요 항목을 조회한다.

자동 문의·병원의 수용 응답·목적지 확정은 이 앱에서 자동 수행하지 않는다. 후보는 수용 확답이나 솔버의 확정 배정이 아니다. 현재 로컬 시연 DB는 가상 병원 10곳을 사용한다. 기존 공공 자료가 적재된 서버로 연결하면 그 서버의 병원 목록을 사용한다.

메인 화면은 작업자 ID·서버 주소·세션 ID를 `sessionStorage`에 남기고, 대화 화면에서 이어온 미반영 문장은 별도 10분 handoff로 전달한다. 대화형 quick 화면의 중간 저장은 초안 참조·미반영 원문·원래 재시도 요청을 `localStorage`에 보관하며 12시간 이내에 자동 복원한다. 원본 오디오는 브라우저 저장소에 넣지 않는다. 작업자 ID는 시연용 구분이며 실제 사용자 인증을 대신하지 않는다.
