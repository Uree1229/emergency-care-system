# 미래 대기열의 확률적 잔여시간과 후속 작업 경계 보정

상태: 별도 후보 `eat_cohort_envelope_l15_f`의 훈련 360환경 실행·공식 의미 감사·독립 집계 대조를 완료했다. 기존 성공은 보존했지만 대기를 줄이지 못해 채택하지 않는다. 소스·보호 조건·판정 기준은 실행 전 고정한 그대로다.

## 배경과 단일 변경

Fullmenu는 문의 후보 3개 제한을 풀어 Stoploss 대비 기존 827명의 선정 대기를 1,604초, 추가 415명은 1,230초 줄였지만 기존 성공 환자 2명을 잃었다. 환자별 예측 확률 보호를 더한 Pareto는 두 환자를 복구했으나 대기가 기존 자료에서 동일하고 추가 자료에서 12초 늘었다. 보호 안에서 대기를 먼저 비교한 Waitpareto도 실제 선택 변경 0건으로 같은 결과였다. 이 세 후보의 소스·원문·실패 판정을 보존한다.

이번에는 허용 오차나 성공 보존 기준을 완화하지 않고, 가상 미래 문의의 대기열 점수식 하나를 보정한다. 기존 Stoploss는 불확실한 기존 대기열과 앞선 가상 미래 작업의 평균 종료시간을 각각 평균낸 뒤 큰 값을 택한다. 이는 아래 선언된 모형에서 두 경계를 함께 고려한 기댓값을 작게 볼 수 있다.

기존 대기열의 종료시각을 나타내는 비음수 확률변수를 `C0`, 현재 원점에서 계획 문의까지의 시간을 `s`, 앞선 가상 미래 작업의 평균 종료시각을 상수 `T`로 둔다. 기존 모형의 안정적인 잔여시간 함수는 `J(t)=E[(C0−t)+]`다.

| 비교 | 현재 시점의 예측 대기 |
|---|---|
| 기존 | `max(J(s), (T−s)+)` |
| 보정 | `(T−s)+ + J(max(s,T))` |

보정식은 **확률적 C0와 상수 T라는 선언된 모형 안에서** `E[(max(C0,T)−s)+]`와 같다. `T≤s`면 기존과 같고, 같은 T에서 기존 식 이상·두 잔여시간의 합 이하다. 예를 들어 C0가 0초·200초일 확률이 각각 1/2이고 s=0, T=100초이면 기존 식은 100초, 보정식은 150초다. 이 예시는 산술 확인용이며 실험 자료에 맞춘 분포나 설정이 아니다.

실제 앞선 작업의 종료시각은 C0와 의존하며 T도 기댓값 근사다. 따라서 이 식을 실제 병원 전체 대기열의 정확한 예측이라고 주장하지 않는다. 보정된 시작시각이 기존 취소 확률·예상 작업량·다음 T를 바꾸므로, 모든 후속 작업의 대기나 최종 성공 확률이 기존보다 단조적으로 늘거나 줄어든다는 보장도 없다.

## 유지하는 구조와 증거

- 기존의 평균 보존 shifted/thinned C0 법칙과 현재 무응답 조건·안정적인 `J` 계산을 그대로 사용한다. 미래 시점의 무응답을 새로 조건화하지 않는다.
- 현재 문의·전체 후보·가상 후속 문의 계획의 병원/시각/순서, 초기 CDF, 잔여 문의 환자의 점수, 고정 F0 취소 근거를 유지한다. 새 계획을 탐색하거나 실제 자원을 분수로 해제하지 않는다.
- 수정된 대기에서 기존 검사시각·예상 취소 작업량·평균 종료시각·최종 CDF를 같은 순서로 재계산한다. 같은 T의 기존 식과 새 식을 기록하고, 기존 수치 연산 허용 범위 안에서 관계를 검사한다. 새 맞춤 허용 오차나 클램프를 도입하지 않는다.
- 기존 Fullmenu·Pareto·Waitpareto 제안을 보존한다. 모든 허용 행과 원래 Stoploss가 실제 선택한 기준 행을 **동일한 새 모형으로** 다시 점수화한다. 원래 3개 행의 저장된 계획, 확장 행의 저장된 Dynamic 투영과 고정 Recourse/Followplan 복원으로 같은 계획을 확인한다.
- 새 점수를 입력으로 환자별 예측 수용 확률 비감소 조건 `1e−12`와 대기 우선 선택 `1e−9`를 그대로 적용한다. 기준 행의 식별자는 바꾸지 않는다. 입력 점수 모형이 달라지므로 이전 수치와 완전히 같은 후보 집합을 뜻하지 않으며, 원래 실제 성공 환자의 보존은 별도로 판정한다.
- 현재 두 환자의 문의만 실제 적용한다. 공개 정보·A/H 경계·동시 문의 4건·총 문의 10곳·FIFO·원자적 적용·기존 대기 문의·기본 후속 H 동작을 유지한다. 성공 결과·미래 환자·실제 작업자 상태·정답은 정책에 입력하지 않는다.

## 실행 전 고정하는 판정 기준

성공 보존 기준은 원래 Stoploss의 **성공 환자 식별자**다. 성공 수가 같더라도 기존 성공을 다른 성공으로 교환하면 통과하지 못한다. 기존·추가 두 자료에서 성공 손실과 대기 증가를 합쳐 가리지 않는다.

| 이미 관측한 훈련 자료 | Stoploss 성공 / 선정 대기 | 이번 후보의 통과 조건 |
|---|---:|---|
| 기존 827명 | 692 / 113,429초 | 성공 692 이상·대기 113,296초 이하·Stoploss 성공 손실 0명·Stoploss보다 대기 엄격 감소 |
| 추가 415명 | 363 / 54,627초 | 성공 364 이상·대기 53,498초 미만·Stoploss 성공 손실 0명·Stoploss보다 대기 엄격 감소 |

두 자료 존재를 포함한 훈련 조건 9개를 실행 전에 고정한다. 실패 선정 대기는 300초, 실패 도착 비용은 1,800초다. 성공 식별자·선정 대기·도착·개인 최대 지연·혼합/스트레스 구간·Fullmenu 대비를 각각 보고한다.

훈련 통과 뒤에만 새 개발 120환경을 실행한다. Stoploss·CS·Hedge 각각 실패 비증가와 대기 엄격 감소, Stoploss 성공 손실 0명으로 7개 조건을 적용한다. 새 개발 통과 뒤에만 별도 검증 368환경을 실행한다. 동일한 점 조건에 세 비교군 각각 실패 차이 95% 상한 0 이하·대기 차이 95% 상한 0 미만을 더해 13개 조건을 요구한다. 시나리오 단위 짝 부트스트랩 10,000회이며, 지표별 주변 구간으로 전체 조건의 공동 95% 보장은 아니다.

## 보존과 검사

부모 Waitpareto 봉인은 `527f8cfb84cf802e06f9100c272bf972004199d6cca780b986e77a61311a9178`다. 부모 소스 570개·엄격 참조 3,290개·압축 원문 4,560개를 보존하고 새 소스 16개를 더한 586개를 고정한다. 이전 문서 해시 변경의 역사적 이력을 승계하며 새 재결속은 하지 않는다.

전체 검사·고정 예제에서 비교군 21개의 전체 원문 동등성과 새 후보의 독립 감사를 확인한다. 합성 검사로 잔여시간 항등식·같은 T의 국소 관계·비선형 꼬리·퇴화 사례·큰 T·고정 F0 및 계획 불변·행 전부와 기준 행 재계산·현재 행동을 확인한다. 예제 검사는 성능 자료가 아니다.

소스 고정 뒤 새 이름 공간의 입력 명세 848개를 생성한다. 훈련 360환경에서 새 후보를 각각 한 번 실행하고 비교군 21개·7,560분기는 봉인된 결과를 재사용한다. 모든 원문을 저장한 뒤 네 프로세스에서 각 원문을 한 번 의미 감사한다. 이후 검사는 정확히 결속된 증명을 재사용하고 부모 원문 감사는 다시 실행하지 않는다. 별도 표준 라이브러리 회계기가 모형·정책·시뮬레이터 없이 결과를 재계산한다.

훈련·새 개발을 모두 통과할 때만 새 개발·검증의 22개 정책을 실행한다. 최대 새 실행은 11,096분기다. 단계 실패 뒤 후속 단계를 차단하며 성능 재실행·결과 제외·사후 설정 변경을 하지 않는다.

과거 `docs/README.md` 참조 오류 10건은 실패·추적·원래/현재 해시를 보존한다. 정확히 동일한 검사 ID·오류·해시이고 다른 오류·건너뛰기·소스 변경이 없을 때만 새 고정 자격을 허용하며 전체 검사 통과로 표시하지 않는다. 읽기·해시·단언을 바꾸지 않는다.

모든 성능 환자의 우선순위는 미확인·기본값 4다. 임상 응급도별 효과나 현장 우월성을 주장하지 않는다. 전체 실행·감사·수집 소요시간은 정책 계산시간이 아니다. 운영 서버와 기본 `fixed_3`는 유지한다.

## 결과

전체 검사는 96개 모듈·1,740건 중 1,730건이 성공했다. 나머지 10건은 부모에서 보존한 정확히 동일한 역사적 `docs/README.md` 참조 오류이며 실패와 추적을 보존했다. 실행 오류·건너뛰기는 없고 새 검사 131건은 모두 성공했다. 실제 전체 소스 586개는 검사 전후 동일했다. 전체 검사 통과로 표현하지 않는다.

독립 표준 라이브러리 회계기의 기존 수치·9/7/13개 조건은 부모와 동일하다. 호출 이름 충돌 검사와 실제 main의 합성 사전 경로 검사, 23개 변조 거부 검사를 통과했다. 이 합성 검사 시점의 새 모델·정책·감사 검사 파일 3개에는 명시적으로 합성 해시를 사용했으므로 실제 소스 고정의 증거로 쓰지 않는다. 이후 위 전체 검사에서 실제 586개 소스의 동일성을 별도로 확인했다. 별도 집계기의 합성 산술·성공 식별자·최대 지연·전체 조건·불완전 인덱스 거부 검사도 통과했다.

고정 예제에서는 비교군 21개의 전체 원문이 부모와 같았고 새 후보 2개 모두 독립 감사를 통과했다. 자연 확장 예제는 225행·미래 작업 2,518개를 검사했고, 25개 작업에서 기존 수치 연산 허용 범위를 넘는 양의 국소 보정이 확인됐다. 이 예제에서 실제 선택 변경은 0개였다. 이는 새 계산 분기와 원문 동등성을 확인한 기능 예제이며 성능 개선의 증거가 아니다.

독립 집계기에는 엄격 참조 파일 수를 이전 차수인 2,885개로 남긴 메타데이터 오류가 있었다. 원문 읽기·시작 마커 생성 전에 멈춰 실제 원문 집계나 성능 재실행은 없었다. 고정된 원본은 보존하고 별도 `independent_repair_accounting_v2.py`에서 개수 3,290과 충돌하지 않는 저장 경로만 수정했다. 본문 전체·AST 대조와 독립 합성 재검사에서 산술·판정·인덱스 함수 9개가 원본과 같음을 확인했다. 소스 586개·판정 조건·공식 실험은 바꾸지 않았다. 실패 추적·수정 경위·독립 검토·두 버전의 해시는 `diagnosis/`에 보존한다.

### 확정 결과 — 공식 감사·독립 집계 일치

새 후보 360분기를 각각 한 번 실행해 모든 원문을 저장했다. 비교군 21개·7,560분기는 봉인된 결과를 재사용했다. 독립 검토를 통과한 수정 집계기는 새 원문 360개를 각각 한 번 읽었고 부모 원문·모형·정책·감사·성능 실행은 하지 않았다. 원본 집계기의 실패 시도는 원문 읽기 0회였다. 두 자료는 모두 이미 관측한 훈련 자료이며 새 개발·별도 검증이 아니다.

|---|---:|---:|---:|---:|---:|

Fullmenu의 대기 단축 1,604초·1,230초는 회복하지 못했다. Envelope는 Fullmenu보다 각각 1,604초·1,242초 길었다. 선언된 대기열 모형 안의 보정식 검사 통과를 실제 대기 단축이나 예측 정확도 향상의 증거로 대신하지 않는다. 두 구간의 기존 성공 보존은 통과했지만 엄격한 대기 감소는 모두 실패했다. 원래 기존 대기 목표와 추가 성공·대기 목표도 미달해 9개 훈련 조건 전체 판정은 실패다.

실패 도착 비용 1,800초를 포함한 J는 기존 840.874초, 추가 821.807초다. Stoploss 대비 기존은 동일하고 추가는 약 0.822초 낮았다. 총 도착 비용 341초 감소가 선정 대기 감소 조건을 대신하지 않는다. Stoploss 대비 개인 선정 대기 최대 증가는 기존 0초·추가 42초, 두 정책에서 모두 성공한 환자의 최대 도착 지연은 기존 0초·추가 91초였다.

최종 판정은 훈련 기준 미달이다. 실제 기존 성공 보존은 두 구간 모두 통과했지만 선정 대기 감소를 달성하지 못했고, Fullmenu의 단축 효과도 회복하지 못했다. 새 개발·별도 검증으로 넘어가지 않으며 운영 서버와 기본 `fixed_3`는 유지한다.

저장 결과 감사도 360사례에서 성공했고 정확히 결속된 기존 의미 증명을 재사용했다. 실제 `execute('development')` 차단 검사에서는 실패한 훈련의 `verify_prior` 조건에서 멈췄다. 작업 목록·실행 풀·시뮬레이터 호출은 모두 0회였으며 새 개발·별도 검증 산출물은 생성되지 않았다. 고정 소스 586개의 해시는 전후 동일했다.

증거는 `.codex-build/eat-cohort-envelope-20261025/`에 보존한다. 공식 `repair.json`, 저장 결과 감사 `repair-audit.json`, 의미 증명 인덱스 `repair-semantic-audit.json`과 사례별 증명, `diagnosis/independent-repair-accounting-v2.json`, 대조 `independent-official-agreement-v2.json`, 회계기 복구 경위·독립 검토·단계 차단 기록을 함께 남긴다. 최종 회계 검증 `verification.json`은 이 문서·소스·원문·검사·감사·실패 판정과 원본/수정본 증거를 해시로 결속한다.

### 추가로 확인한 적용 범위의 병목 — 미구현·미검증

별도 소스 연구에서는 상위 공동 평가의 활성화가 JOINT의 즉시 대기 개선, TAIL의 기회 보호 거부, Budget의 뒤쪽 두 환자 문의 수 비교를 통한 거부 취소에 연쇄적으로 묶여 있음을 확인했다. 그 결과 첫 문의 대상이 정확히 2명 또는 3명인 그룹은 상위 공동 평가가 활성화되지 않는다. 현재 미평가 150그룹의 구체적인 인원별 분포는 추가 원문 통계를 계산하지 않아 확인하지 않았다.

다음 좁은 검토 대상은 첫 문의 대상이 정확히 2명인 비활성 그룹의 후보 평가다. 이는 전체 대기 환자가 2명이라는 의미가 아니며, 이미 문의 중이거나 비활성인 모든 잔여 환자를 점수와 보호에 포함해야 한다. 원래 조합표·동시 기준 행의 타당성·공개 원점의 잔여 환자 고정 정보를 독립 감사할 준비 경로가 필요하다. 현재 후보나 판정 기준을 바꾸지 않았으며 이 제안은 구현·성능 검증하지 않았다. 소스 결속과 제한 사항은 `diagnosis/next-scope-research-v2.json`에 보존했다. 원본 연구 기록의 세 줄 위치 표기 오류는 원본을 남긴 v2에서 정정했으며 알고리즘 주장은 같았다.
