# dev2 음성인식 적용 기능 인계

2026-11-03. dev2가 음성 입력과 검토 기능을 이어받을 때 참고할 현재 적용 범위다. 아래의 **시연 적용 상태는 멘토용 실행본 기준**이며, Git 코드와의 차이는 별도 표로 구분한다. 개선 과정과 검증 결과는 [개선 노력과 남은 작업](VOICE_IMPROVEMENT_EFFORTS_DEV2_20261103.md)에 정리했다.

## 실행본과 Git 기준

| 기준 | 식별과 범위 |
|---|---|
| 멘토 시연 소스 | 로컬 `team-common-20261103-v1.12-flow-console-candidate`, 실행본 ID `team-20261031-4bb1a5205415b9f7`. 시연 서버는 이 후보와 같은 최종 기능 소스를 사용한다. |
| Git 비교 기준 | 이 문서 추가 전 [d019495](https://github.com/Uree1229/emergency-care-system/commit/d019495abbd867ceda2cb2377282cbf20fd53159), 브랜치 `codex/flow-console-20261103`. 이후 main 변경까지 비교한 표는 아니다. |
| 서버 설정 확인 | 시연 서버의 `GET /api/voice/capabilities` 조회에서 Azure `speech.configured=false`를 확인했다. 다른 PC에서는 해당 API로 다시 확인한다. |

로컬 시연 후보의 모든 음성 변경이 이 Git 브랜치에 합쳐진 상태는 아니다. 이번 인계는 문서 추가이며, 해당 후보 소스와 ZIP은 이 문서 커밋에 포함하지 않는다. dev2는 작업을 시작할 소스 버전을 먼저 맞춰야 한다.

## 적용된 처리 흐름

한국어 음성 → 브라우저 STT의 확정 인식문 → 사전과 규칙으로 항목 추출 → 확인 질문과 TTS 복창 → 사용자의 검토와 최종 등록 순서다. 중간 인식문은 미리보기로 사용한다.

| 기능 | 멘토 시연본 동작 | 주로 확인할 코드 경로 |
|---|---|---|
| 한국어 STT | `SpeechRecognition` 또는 `webkitSpeechRecognition`을 `ko-KR`로 사용한다. | `paramedic-ui/speech.mjs`, `quick-test.js` |
| 의료 용어와 동의어 | 항목명과 증상 표현을 사전으로 연결한다. 브라우저가 지원하면 용어 힌트도 전달하며 미지원·거부 시 일반 인식으로 복귀한다. | `server/voice_lexicon.py`, `voice_terms.py`; `paramedic-ui/speech.mjs` |
| 질문별 인식 후보 | 일반 보고는 기본 첫 후보를 사용한다. 확인 질문은 최대 5개 후보를 요청하고, 실제 반환된 짧은 답변 후보를 질문 형식과 비교한다. | `paramedic-ui/answer-match.mjs`, `quick-test.js` |
| 수치 추출 | 나이·혈압·맥박·산소포화도·체온 등의 지원 표현을 항목으로 나눈다. 혈압 구분자와 질문 답변 문맥을 처리한다. | `server/voice_terms.py`, `voice_r1.py`, `voice_input.py` |
| 부정과 불확실성 | 증상 있음·없음·의심을 분리하고, 지원하는 조건·지시 표현이 현재 관찰값으로 들어가지 않게 처리한다. | `server/voice_terms.py`, `voice_r1.py` |
| 누락과 충돌 | 서로 다른 수치가 충돌하면 임의 선택하지 않는다. 확인 질문의 `모름`과 `나머지는 다 모름`을 지원한다. | `server/voice_input.py`, `voice_followup.py` |
| 음성 제어 | 녹음 종료·수정·읽어주기 등의 지원 명령을 처리한다. 환자 등록과 병원 문의는 각 단계의 명시 절차를 따른다. | `paramedic-ui/recording-control.mjs`; `server/voice_terms.py` |
| TTS 순차 확인 | 간편입력에서 중요 항목을 읽고 `맞아요`, `아니요`, `다시 읽어줘`, `중지`로 답한다. 확인 뒤 다음 단계 이동을 지원한다. | 시연본의 `paramedic-ui/critical-conversation.mjs`, `critical-conversation-audio.mjs` |
| 미입력 항목 처리 | 간편입력의 내용 확인 진입 시 빈 항목을 모름·미측정으로 남긴다. 입력한 값까지 지우거나 정상값으로 채우지 않는다. | 시연본의 `quick-test.js`, `critical-review.mjs` |
| 근거와 복구 | 원문·항목 근거·변경 이력과 미반영 입력을 보존한다. 결과 미확인 요청은 원래 요청 ID와 내용으로 확인·재시도한다. | `server/voice_input.py`; `paramedic-ui/voice-client.mjs`, 복구 모듈 |

코드 경로는 역할을 찾기 위한 안내다. 같은 파일명이라도 위 두 기준의 바이트와 기능이 다를 수 있다.

## 해석 예시

아래는 가상 텍스트의 처리 예이며 새 마이크 시험 결과가 아니다.

| 인식문 | 기대되는 처리 |
|---|---|
| `혈압 120에 80` 또는 `혈압 120-80` | 수축기 120, 이완기 80으로 분리한다. |
| `흉통은 있지만 호흡곤란은 없습니다` | 흉통 있음과 호흡곤란 없음을 분리한다. 호흡 정상은 자동 생성하지 않는다. |
| `흉통 의심` | 미확인·의심 증상으로 남긴다. 관련 메뉴 분류는 확진을 뜻하지 않는다. |
| `맥박 90 맥박 110` | 둘 중 하나를 골라 확정하지 않고 상충 경고와 재확인을 남긴다. |
| 현재 확인 질문에 `모름` | 해당 항목을 미측정·확인 불가로 남긴다. 일반 받아쓰기의 모든 모름 표현에 동일 적용되는 것은 아니다. |

## Git 코드와 시연본의 차이

| 기능 | Git 기준 d019495 | 멘토 시연 소스 |
|---|---|---|
| TTS 순차 대화 확인과 미입력 모름 처리 | 기존 중요 항목 검토는 있으나 새 순차 대화 모듈과 일괄 기본 처리는 미연결 | 적용 |
| 800ms 명령 확정 게이트 | `command-commit.mjs`와 Quick 연결이 존재함 | 해당 모듈과 연결 없음. 확정 인식문에서 명령을 찾으면 종료 처리 |
| RNNoise | 별도 수동 A/B 비교 도구가 있음. 브라우저 STT 입력의 자동 전처리는 아님 | 관련 비교 도구와 모듈 없음 |
| 복수 후보의 서버 문맥 검토 | `voice_recognition_context.py`와 후보 전송·충돌 검토가 연결됨 | 해당 모듈 없음. 질문별 후보 선택과 기존 조건·지시 규칙은 별도로 존재함 |

800ms는 후속 인식 조각을 기다리는 실험 설정이며 무음 감지가 아니다. RNNoise와 후보 검토가 Git에 존재한다는 사실만으로 현재 시연 화면에 적용됐다고 설명하지 않는다.

자체 STT 모델 재학습이나 LLM 자동교정 경로는 현재 시연본에 없다. Azure는 연결 코드가 있으나 조회 당시 미설정이었다. 상세 화면의 PCM 소음·반향·자동 음량 설정은 Azure 녹음과 로컬 WAV 경로용이며, 간편입력의 브라우저 STT에 처리 음원을 주입하는 기능이 아니다.

## dev2 작업 시작

1. 작업 브랜치와 시연 후보 중 어느 소스를 기준으로 할지 기록하고, 위 네 가지 기능 차이를 먼저 확인한다.
2. `speech.mjs` → `quick-test.js` → `server/voice_input.py` → `voice_terms.py`와 `voice_r1.py` 순서로 입력 경로를 읽는다. 기존 API 계약은 [음성 API](VOICE_INPUT_API.md)를 따른다.
3. 음성 기능 변경은 별도 가상 DB와 `voice-only` 모드에서 확인한다. 기존 멘토 시연 서버와 DB는 보존한다. 환경 준비는 [팀원 음성 시험 안내](TEAM_VOICE_TEST_GUIDE_20261031.md)를 참고한다.
4. 원문과 확인된 숫자를 보존하고, 미확인을 0·정상·수용 가능으로 바꾸지 않는다. 최종 등록·병원 문의·목적지 확정을 한 번의 인식 결과로 자동 연결하지 않는다.
5. 새 발화의 원음·대본·수정 전 인식문을 확보해 STT 결과와 항목 추출 결과를 따로 비교한다. 자세한 측정 항목과 남은 작업은 [개선 노력 문서](VOICE_IMPROVEMENT_EFFORTS_DEV2_20261103.md)를 따른다.

Git에 있는 추가 기능의 설명은 [명령 확정 게이트](VOICE_COMMAND_GATE_20261031.md), [RNNoise 비교](VOICE_RNNOISE_COMPARISON_20261031.md), [복수 인식 후보 검토](VOICE_RECOGNITION_CONTEXT_20261103.md)에 있다. 이 문서 추가로 해당 기능의 실행 연결을 변경하지 않았다.
