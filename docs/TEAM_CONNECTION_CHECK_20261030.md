# 팀원 화면 연결 전 서버 재전송·경합·복구 검증

2026-10-30. 기존 서버 API의 연결 계약을 실제 공통 실행기와 HTTP로 검증하는 실행기를 추가했다. 이미 진행 중인 지도 재생·도로 결합과 겹치지 않도록 그 파일은 수정하지 않았다. Claude의 음성 화면·해석 코드, 팀원 화면, 원래 시연 서버와 업무 DB도 수정하지 않았다.

## 1. 추가한 도구와 범위

```powershell
python -m server.team_connection_check --output .codex-build/team-connection-new
```

새 출력 폴더를 지정해야 한다. 기존 폴더는 덮어쓰지 않는다. 실행 전 공통 서버 프로필을 검사하고, 고정된 두 통합 시험 모듈을 실행한다. 시험마다 새 합성 DB와 포트 0의 로컬 서버, 실제 문의·배정 백그라운드 워커를 사용한다. `run_once`를 수동 호출하거나 가짜 추천 결과를 넣지 않는다.

이 도구는 기존 API 규칙과 상태 일관성을 확인한다. 운영 API·배정 목적함수·자동 확정 규칙을 새로 바꾸는 작업은 아니다. 실제 브라우저의 오프라인 모드·탭 새로고침·사용자 인지·마이크·실제 병원 전송은 시험하지 않는다.

## 2. 고정된 8개 통합 사례

| 사례 | 실제로 확인하는 결과 |
|---|---|
| 마지막 자리의 동시 확정 | 같은 병원의 마지막 자리 1개에 두 환자가 각각 수용 응답을 받더라도, 동시 확정은 1건만 성공. 다른 요청은 `RESOURCE_CONFLICT` 409, 도착 예정 수요는 1 |
| 환자정보 변경 뒤 오래된 병원 화면 | 재사용된 문의에 옛 버전으로 답하면 409. 최신 정보로 재문의·수용한 뒤 추천 가능하며 추천 자체로 목적지는 확정되지 않음 |
| 같은 자원 버전의 동시 수정 | 두 작업자가 같은 `expected_version`으로 자원을 갱신하면 한 요청만 반영되고 다른 요청은 충돌 |
| 환자 수정과 기존 목적지 확정의 경합 | 두 요청이 동시에 들어와도 둘 다 커밋되지 않음. 승리한 처리와 환자·문의·수정 이력이 일관됨 |
| 제출 응답 유실을 가정한 재시도 | 첫 응답을 사용하지 않고 동일 요청 ID·본문으로 다시 제출해도 환자와 반영 사건은 1개. 새 GET으로 제출 세션·최신 환자·연결 초안 복원 |
| 중요 사건의 커서·미확인 복구 | 페이지 중복 없음. GET은 delivered/ack를 만들지 않음. 표시 전 ack는 거절, 작업자별 확인 독립, 미확인 조회와 전진 커서 분리 |
| 실제 공통 서버 재시작 | 같은 DB로 두 워커를 다시 실행해도 환자·음성·문의 식별자, 자원, 확인 기록 보존. 계획 결과·lease·heartbeat는 업무 이력과 분리 |
| 음성 정정의 중복 적용 | 미제출 초안은 현재 환자를 바꾸지 않음. 확인한 정정을 동일 요청으로 재전송해도 환자 수정은 한 번만 반영. 새 연결 초안은 최신 값 사용 |

마지막 자리·수정 경합은 동시 시작 장벽과 독립 HTTP 요청을 사용한다. 어떤 요청이 먼저 성공할지는 고정하지 않고, 한 번만 반영되는 불변조건을 검증한다. 응답 유실 사례는 실제 통신 장애를 유발한 시험이 아니라, 서버가 이미 처리한 응답을 클라이언트가 받지 못했다고 가정한 동일 요청 재시도다.

## 3. 화면 담당자가 연결할 규칙

| 상황 | 화면에서 할 일 | 하면 안 되는 처리 |
|---|---|---|
| 제출 결과를 모름 | 원래 `actor_id`, 요청 ID, operation, 전체 본문으로 재시도한 뒤 현재 세션·환자를 GET | 새 요청 ID로 새 환자 생성, 원래 요청의 본문 변경 |
| 중복 성공 응답 | 당시 처리 영수증으로 해석하고 현재 상태 재조회 | 캐시 응답을 현재 최신 환자 상태로 단정 |
| 환자·문의 409 충돌 | 최신 환자와 문의를 다시 읽고 담당자가 새 정보로 판단 | `expected_version`만 최신 값으로 바꿔 수용 응답 자동 재전송 |
| 마지막 자리 `RESOURCE_CONFLICT` | 환자는 미확정으로 두고 자원·후보·수용 응답 재조회 | 화면의 낡은 추천을 강제 확정 |
| 새 알림 수신 | 화면에 실제 그린 후 delivered, 사용자가 확인한 뒤 acknowledge | GET 성공 즉시 두 상태를 자동 완료 |
| 탭 복귀·재연결 | 기존 ID·작업자 문맥으로 현재 상태와 `unacknowledged_only=true` 별도 조회 | 전진 스트림 커서 뒤의 새 사건만 읽고 과거 미확인 사건 누락 |
| 추천이 오래됨 | GET으로 최신 상태를 확인하고 과거 확정 조작 제거 | 폴링할 때마다 POST replan 호출 |
| 공통 서버 재기동 | 같은 전용 DB와 원래 이송 ID 사용 | DB 삭제·seed로 재연결 문제를 숨김 |

중요 사건의 `actor_id`는 시연용 작업자 식별자다. 확인 분리 검증을 운영 로그인 인증이나 병원별 권한 검증으로 표현하지 않는다. 알림 확인은 의료적 수용 유지·조정 판단과 별도다.

세부 API는 [음성 API](VOICE_INPUT_API.md), [환자정보 변경](PATIENT_AMENDMENTS_API.md), [업무 계측·중요 사건](BACKEND_MEASUREMENT_API.md), [팀원별 API 연결](TEAM_FEEDBACK_API_HANDOFF_20261029.md), [공통 실행본](TEAM_COMMON_RUNTIME_20261030.md)을 따른다. 이번 실행의 `connection-contract.json`에도 주요 오류와 후속 동작을 저장한다.

## 4. 증거와 실패 처리

출력에는 다음 자료가 있다.

- `protocol.json`: 실행 전 시험 목록·실행 프로필·선택 소스 해시·범위.
- `report.json`: 시험 결과, 요청 method/path/status, 확인 항목, 실제 워커 상태·종료, 무결성 검사.
- `report.md`·`tests.log`: 결과표와 실패·오류 상세.
- `connection-contract.json`: 화면 복구 동작 계약.
- `sources/`: 사용한 서버·설정·시험 소스 사본.

시험이 PASS여도 시험별 HTTP 요청·확인 항목·실제 두 워커의 RUNNING 상태·종료 증거가 없으면 전체 검증을 실패 처리한다. 소스 변경·읽기 실패·기준 프로필 변경·생략된 시험·예상 실패도 전체 통과로 인정하지 않는다. 클래스 초기화 오류처럼 `startTest` 이전 오류가 발생해도 결과를 보존한다.

보고서 도구 자체의 검증은 `test_team_connection_check.py`다. 이 파일의 가짜 시험·증거는 보고서 보호 로직의 단위시험용이며 실제 HTTP 통합 성공 표본에 포함하지 않는다.

```powershell
python -m unittest test_team_connection_check -v
python -m unittest test_team_connection_races test_team_connection_recovery -v
```

최종 실제 실행 자료는 `.codex-build/team-connection-check-20261030/final-run-03`에 보존한다. 초기 실행·도구 보완 전 결과도 덮어쓰지 않았다. 검증 시간은 테스트 프로그램의 실행시간이며 환자 병원 선정시간·이동시간·현장 업무 부담의 지표로 쓰지 않는다.

## 5. 이후 팀원에게 넘길 완료 기준

Claude와 김민석은 실제 화면에서 음성 등록·검토·재시도·새로고침 뒤 동일 이송 복원을 연결하고, 김준성은 오래된 문의 응답 거절 후 재조회와 취소 인지·불필요 검토 종료를 연결한다. 양쪽은 중요 사건 표시·확인·복구를 연결한다. 정진은 이 실행기의 실패 로그와 재현 사례로 서버 계약을 지원한다.

서버 계약 통과는 화면 연결 완료가 아니다. 다음 실제 리허설에서는 두 기기에서 입력·수용·확정·조건 변경과 탭 복귀·연결 단절을 직접 수행해야 한다.

## 6. 최종 결과

최종 실제 연결 검사 **8개 시나리오·28개 확인·HTTP 206회**가 통과했다. 테스트별 HTTP·워커 증거 누락 0건, 소스 사본과 실행 전후 해시 일치, 생략·예상 실패 0건이다. HTTP 횟수는 이번 폴링 실행의 기록이며 고정 업무량 지표가 아니다.

보고 도구 보호 단위시험은 **10개**다. 증거가 없는 PASS, 워커 미가동, 클래스 준비 오류, 시험 실패·생략, 소스 변경·최종 해시 읽기 오류, 기존 출력 덮어쓰기 등을 검사한다.

별도 서버 릴리즈 작업본에서 기존 음성·문의·배정·대화·이송 검사와 함께 실행한 관련 회귀는 **614개 모두 통과**했다. 이 수에는 이번 8개 통합·10개 보고기 검사가 포함되며 이를 별도 고유 환자나 현장 표본 수로 합산하지 않는다.

기준 알고리즘·기존 업무 API·UI를 변경하지 않았다. 새 검증기와 시험·문서만 `codex/common-runtime-20261030` 서버 전용 로컬 브랜치에 추가한다. 원래 작업 폴더와 지도·최종평가 작업 파일은 보존했다.
