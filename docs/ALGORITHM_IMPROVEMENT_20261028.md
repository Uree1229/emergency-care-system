## 같은 결과를 더 적은 계산으로 얻는 시제품

기존 Recourse 한 번의 평가 안에서 병원·시점이 같은 확률 배열을 재사용하는 시제품의 입력 범위를 28개에서 134개로 넓혔다. 모든 입력에서 전체 반환값의 타입·사전과 목록 순서·`float.hex`와 입력 불변성이 원함수와 일치했다. 항상 Memo를 사용하는 별도 계측에서는 확률 배열 요청 2,134회 중 실제 계산이 570회, 재사용이 1,564회였다. 이 수치는 아래 조건부 선택기의 전체 계산 감소율을 뜻하지 않는다.

처음 시간 측정에서 짧은 입력·가득 찬 자기 문의·후보 없는 입력은 캐시 오버헤드가 확인됐다. 그래서 후보·잔여 예산이 각각 2 이상, 자기 고정 문의가 4건 미만, 문의 가능한 구간이 45초 이상인 등 보수적인 조건에서만 Memo를 쓰고 나머지는 원함수를 직접 호출하는 별도 선택기를 만들었다. 선택 조건도 개발 입력을 본 뒤 정한 설정이다.

첫 Adaptive 버전은 고의적인 사전 키 해시 충돌에서 추가 동등성 호출이 생길 수 있었다. 원본과 해당 증빙은 보존하고, 새로운 Keyguard 버전에서 읽는 다섯 사전의 키가 정확한 문자열인지 조회 전에 확인하도록 보완했다. 추가 비교 호출·호출 순서·원래 예외를 확인하는 회귀 검사를 포함한 18개 검사가 통과했다. 같은 134개 입력의 경로는 원함수 109개·Memo 25개였으며 모두 출력이 일치했다. 임의의 중첩 커스텀 객체가 계산 도중 입력을 바꾸거나 동시에 입력이 바뀌는 상황까지 보장하지 않는다.

Keyguard와 원함수의 같은 여섯 대표 입력을 직접 비교했다. 워밍업 후 AB/BA 순서를 네 번씩 균형 있게 배치한 8개 블록, 블록당 각 함수 5회 호출이며 결과 검사는 측정 밖에서 했다.

| 후보 2개 | 1.483ms | 1.299ms | 12.4% |
