# 환자별 예측 확률 보호 안에서 선정 대기 우선 최소화

상태: 별도 실험 후보 `eat_cohort_waitpareto_l15_f`의 훈련 360환경 실행·공식 의미 감사·독립 집계 대조를 완료했다. 기존 성공은 보존했지만 대기 단축을 회복하지 못해 채택하지 않는다. 소스·보호 조건·판정 기준은 실행 전 고정한 그대로다.

## 문제와 단일 변경

Fullmenu는 평가 후보 3개 제한을 풀어 기존 827명의 선정 대기를 Stoploss보다 1,604초, 추가 415명은 1,230초 줄였지만 기존 성공 환자 2명을 잃었다. Pareto는 모든 현재 점수 대상 환자의 예측 수용 확률이 Stoploss 기준보다 낮아지는 행을 제외해 두 환자를 복구했다. 그러나 선정 대기는 기존 자료에서 동일하고 추가 자료에서 12초 늘었다. 두 후보의 원문·소스·실패 판정은 봉인해 보존했다.

Pareto는 보호를 통과한 행에서도 우선순위별 확률 합을 먼저 최대화하고 대기를 마지막에 비교했다. 이번 후보는 **동일한 보호를 통과한 행에서 전체 예측 선정 대기를 먼저 최소화**한다. 환자별 예측 확률 보호·점수·전체 후보·모형·활성화 조건·허용 오차를 바꾸지 않고, 선택 순서 하나만 변경한다.

1. 기존 Fullmenu와 Pareto의 전체 제안 및 모든 행의 점수·환자별 보호 증거를 그대로 계산하고 보존한다. 현재 H가 남은 대기 상태의 점수 대상 환자 모두가 대상이며 이미 문의한 환자도 포함한다.
2. Pareto가 허용한 행만 비교한다. 원래 Stoploss의 실제 선택 행은 항상 포함돼야 한다. 각 환자의 최종 예측 수용 확률은 Stoploss 기준보다 기존 허용 오차 `1e−12`를 넘어 낮아질 수 없다.
3. 전체 예측 선정 대기 합의 최솟값을 구하고 기존 허용 오차 `1e−9` 이내의 행만 남긴다. 그 안에서 기존 우선순위 4·2·1의 확률 합을 차례대로 비교한다. 마지막 동률은 Stoploss 기준 행, 이후 원래 행 순서로 해소한다.
4. 기준 행이 허용되므로 선택한 행의 예측 대기는 Stoploss 기준 대기보다 `1e−9`를 넘어 길 수 없다. 별도의 대기 상한·가중치·임계값을 추가하지 않는다. 실제로 적용하는 행동은 현재 두 환자의 문의뿐이다.

이 보호는 현재 공개 정보에 대한 모형의 예측 조건이다. 실제 성공이나 이후 경로의 보장을 의미하지 않는다. 기존 성공 환자의 실제 보존은 실행 결과에서 별도로 판정하며, 과거 성공 식별자·미래 환자·실제 작업자 상태·미래 사건·정답은 정책에 입력하지 않는다. 이전 자료에서 허용 행이 적었다는 사실만으로 새 경로의 개선 폭이나 상한을 단정하지 않는다.

## 변경하지 않는 검증 기준

성공 보존 기준은 Pareto나 Fullmenu가 아니라 원래 Stoploss다. 성공 수가 같더라도 기존 성공 환자를 다른 환자로 교환하면 통과하지 못한다. 기존·추가 자료를 합쳐 성공 손실이나 대기 증가를 가리지 않는다.

|---|---:|---|
| 기존 827명 | 692 / 113,429초 | 성공 692 이상·선정 대기 113,296초 이하·Stoploss 성공 손실 0명·Stoploss보다 대기 엄격 감소 |
| 추가 415명 | 363 / 54,627초 | 성공 364 이상·선정 대기 53,498초 미만·Stoploss 성공 손실 0명·Stoploss보다 대기 엄격 감소 |

두 자료 존재를 포함한 훈련 조건 9개를 실행 전에 고정한다. 실패 선정 대기는 300초, 실패 도착 비용은 1,800초다. 선정 대기와 도착 지표, 성공 식별자, 개인 최대 지연, 혼합·스트레스 구간을 각각 보고한다. Fullmenu 대비 대기 감소 효과의 회복 여부도 별도로 표시한다.

훈련 통과 뒤에만 새 개발 120환경을 실행한다. Stoploss·CS·Hedge 각각 실패 비증가와 대기 엄격 감소, Stoploss 성공 손실 0명으로 7개 조건을 요구한다. 새 개발 통과 뒤에만 별도 검증 368환경을 실행한다. 동일한 점 조건에 세 비교군 각각 실패 차이 95% 상한 0 이하·대기 차이 95% 상한 0 미만을 더해 13개 조건을 적용한다. 시나리오 단위 짝 부트스트랩 10,000회이며 지표별 주변 구간으로, 전체 조건의 공동 95% 보장은 아니다.

## 보존과 실행 절차

부모 Pareto 봉인은 `a3cf76b7f58081875d5313606f9eb4ef5d19d4f7afb7181ec92714773a8f7f5b`다. 부모 소스 554개·엄격 참조 2,885개·압축 원문 4,200개를 보존하고 새 소스 16개를 더한 570개를 고정한다. 역사적 문서 해시 변경은 기존 이력을 승계하며 다시 결속하지 않는다.

- 합성 단위 검사, 전체 검사, 고정 예제에서 비교군 20개의 전체 원문 동등성과 새 후보의 감사·보호·대기 우선 분기를 확인한다. 고정 예제는 성능 자료가 아니다.
- 소스 고정 후 새 이름 공간의 입력 명세 848개를 생성한다. 훈련 360환경에서 새 후보를 각각 한 번 실행하고, 비교군 20개·7,200분기는 봉인된 기록을 재사용한다.
- 모든 원문을 저장한 뒤 네 프로세스에서 각 새 원문을 한 번 의미 감사한다. 공개 정보·부모 증명·변경 없는 보호·독립 대기 선택·동률·현재 출력·FIFO·원자적 적용·동시 문의 4건 및 총 문의 10곳 제한을 확인한다.
- 정책·모형·시뮬레이터 없이 성공·대기·도착·개인 손실·판정 조건을 별도로 집계한다. 부모 원문 감사는 다시 실행하지 않는다.
- 모든 단계가 통과할 때만 새 개발·검증의 21개 정책을 실행한다. 최대 새 실행은 10,608분기다. 단계 실패 뒤 후속 단계를 차단하며 성능 재실행·결과 제외·사후 설정 변경을 하지 않는다.

과거 `docs/README.md`의 역사적 참조 오류 10건은 실패·추적·원래/현재 해시를 그대로 보존한다. 정확히 동일한 검사 ID·오류·해시이고 다른 오류나 건너뛰기·소스 변경이 없을 때만 새 고정 자격을 허용하며 전체 검사 통과로 표시하지 않는다. 읽기·해시·단언을 바꾸지 않는다.

모든 성능 환자의 우선순위는 미확인·기본값 4다. 임상 응급도별 효과나 실제 현장 우월성을 주장하지 않는다. 실행·감사·수집 전체 벽시계 시간은 정책 계산시간이 아니다. 운영 서버와 기본 `fixed_3`는 유지한다.

## 결과

전체 검사는 90개 모듈·1,609건 중 1,599건이 성공했다. 나머지 10건은 부모에서 보존한 정확히 동일한 역사적 `docs/README.md` 참조 오류이며, 실패와 추적을 보존했다. 실행 오류·건너뛰기는 없고 새 검사 131건은 모두 성공했다. 실제 전체 소스 570개는 검사 전후 동일했으며, 전체 검사 통과로 표현하지 않는다.

고정 예제에서는 비교군 20개의 전체 원문이 부모와 같았고 새 후보 2개 모두 독립 감사를 통과했다. 자연 확장 예제는 225행을 평가하고 기존 보호로 224행을 제외했다. 새 대기 선택 분기와 기준 대기 이하 조건도 감사했으나, 이 예제는 기준 행 하나만 허용돼 실제 개선 선택의 증거가 아니다. 대기 우선 선택이 기존 확률 우선 선택과 달라지는 분기는 별도 합성 검사로 확인했다.

독립 표준 라이브러리 회계기는 기존과 동일한 수치·9/7/13개 조건·식별자 보존을 유지한다. 실제 main의 합성 사전 경로 검사와 호출 이름 충돌 검사가 성공했다. 이 합성 검사 당시 아직 없던 새 감사 검사 파일 한 개에는 명시적으로 합성 해시를 사용했으므로 실제 소스 고정의 증거로 쓰지 않는다. 이후 위 전체 검사와 고정 예제에서 실제 570개 소스의 동일성을 별도로 확인했다. 별도 집계기의 합성 산술·성공 식별자·최대 지연·전체 조건·불완전 인덱스 거부 검사도 통과했다.

### 도착과 해석

실패 도착 비용 1,800초를 포함한 J는 기존 840.874초, 추가 821.807초다. Stoploss 대비 기존은 동일하고 추가는 약 0.822초 낮았다. 총 도착 비용 341초 감소가 선정 대기 감소 조건을 대신하지 않는다. Stoploss 대비 개인 선정 대기 최대 증가는 기존 0초·추가 42초, 두 정책에서 모두 성공한 환자의 최대 도착 지연은 기존 0초·추가 91초였다.

모형의 현재 시점에서 선택 행의 예측 대기가 기준 이하라는 성질은 실제 전체 경로의 선정 대기 비증가 보장이 아니다. 이번 결과에서도 추가 자료의 12초 증가가 남았다. 공개 모형·가상 후속 계획·실제 후속 행동의 차이를 구분하며, 현재 결과만으로 그 차이의 인과적 원인을 확정하지 않는다.

최종 판정은 훈련 기준 미달이다. 기존 성공 보존은 두 구간 모두 통과했지만 선정 대기 감소를 달성하지 못했고, Fullmenu의 단축 효과도 회복하지 못했다. 새 개발·별도 검증으로 넘어가지 않으며 운영 서버와 기본 `fixed_3`는 유지한다.

저장 결과 감사도 360사례에서 성공했고 정확히 결속된 기존 의미 증명을 재사용했다. 실제 `execute('development')` 차단 검사에서는 실패한 훈련의 `verify_prior` 조건에서 멈췄다. 작업 목록·실행 풀·시뮬레이터 호출은 모두 0회였으며 새 개발·별도 검증 산출물은 생성되지 않았다. 고정 소스 570개의 해시는 전후 동일했다.

증거는 `.codex-build/eat-cohort-waitpareto-20261024/`에 보존한다. 공식 `repair.json`, 저장 결과 감사 `repair-audit.json`, 의미 증명 인덱스 `repair-semantic-audit.json` 및 사례별 증명, 독립 집계·대조·증명 검토·단계 차단 기록은 각각 본 폴더와 `diagnosis/`에 있다. 최종 회계 검증 `verification.json`은 이 문서·소스·원문·검사·감사·실패 판정을 해시로 결속한다.
