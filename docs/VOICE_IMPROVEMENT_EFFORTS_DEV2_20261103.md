# dev2 음성 입력과 검토 개선 노력 및 검증 한계

2026-11-03. dev2 인계 대상은 구급대 음성 입력, 항목 추출, 확인·수정과 인계 준비다.
현재 기능 설명은 [현재 적용 기능](VOICE_CURRENT_FEATURES_DEV2_20261103.md)과 함께 읽는다.
이 문서는 개선 과정의 요약이며, 새 성능 측정 결과나 최종발표 자료가 아니다.

## 버전과 근거의 구분

- 혈압·부정·조건 지시 처리와 순차 음성 확인의 아래 결과는 각각의 **로컬 개발·시연 후보** 기록이다.
- 이 문서 작성 기준 Git 커밋 `d019495`와 멘토 시연 소스는 동일한 버전이 아니다.
- 로컬 후보에서 확인한 성과를 현재 Git 체크아웃의 동일 동작·정확도 보장으로 옮기지 않는다.
- 이번 인계는 음성 개선에 관한 것이며, 해당 로컬 개선은 고정 배정 코어 21개를 보존했다.
- 실제 인식문 재처리, 합성 문장 검사, 브라우저 모의 검사, 실제 마이크 측정은 서로 구분한다.

## 1. 기존 인식문에서 혈압 형식·부정 범위를 수정

새 녹음 대신 기존 13건의 인식문과 정답을 보존하고 같은 텍스트를 수정 전후 파서에 넣었다.
`혈압 120-80`의 양의 두 수치를 지원하고, `경련 실신 없음`의 명백한 끝 부정을 목록 범위에 적용했다.
쉼표·다른 측정 항목·긍정 서술·역접을 넘어 부정이나 의심을 퍼뜨리지 않도록 범위를 제한했다.
질문에 대한 `120-80` 답변은 현재 혈압 질문이 항목명을 제공하며, 임의의 숫자를 혈압으로 추정하지 않는다.

| 같은 13건 재처리 지표 | 수정 전 | 수정 후 |
|---|---:|---:|
| 추출 항목·행동 전체 일치 | 6/13 | 8/13 |
| 기대 필드 중 값 일치 | 13/30 | 16/30 |
| 증상 극성 뒤집힘 | 2 | 1 |
| CER / WER | 48.22% / 83.75% | 동일 |

**이는 파서 개발 검사다. STT 인식문·CER·WER는 바뀌지 않았으므로 음성인식률 향상이 아니다.**
전체 일치에는 값을 보류하는 것이 정답인 2건도 포함된다.
화자는 S01 한 명이며, 배경 소음·마스크 조건은 실제 조건을 바꾼 것이 아니라 화면 표시만 바꾼 자료다.
V009·V046은 전체 일치로 개선됐지만 V002·V031·V048·V104·V117의 전체 실패는 유지했다.
V048은 일부 항목을 회수했어도 전체 정답과 달라 실패로 남겼다. 원문·정답·분모를 고치지 않았다.

초기 수정에서는 V117의 뒤쪽 불확실성이 앞 증상에 퍼지는 악화와 혈압 전환의 한쪽 값 입력을 발견했다.
경계 처리를 보완하고 실패 기록을 보존했다. `경련 실신 의심/미확인`의 남은 경계도 후속 후보에서 보완했다.
같은 개발 문장을 다시 통과한 결과를 독립 평가나 새 사람의 발화로 세지 않는다.

## 2. 논문 원리를 제한적으로 적용

[ConText 원논문](https://pmc.ncbi.nlm.nih.gov/articles/PMC2757457/)의 단서·예외·범위 종료 원리를 참고했다.
영어 사전, 과거성의 14일 기준, 논문의 성능 수치는 한국어 음성 입력에 이식하지 않았다.
지원하는 조건 표현과 명시적인 지시가 함께 있을 때만 해당 구간을 현재 관찰에서 제외한다.

- `호흡곤란이 생기면 알려주세요`를 현재 호흡곤란으로 자동 입력하지 않는다.
- `현재 혈압 120/80, 수축기 혈압 80으로 떨어지면 연락하세요`에서 현재 120/80을 보존한다.
- `구토하면 흉통이 심해집니다`처럼 실제 관찰을 보고하는 문장을 지시문으로 일괄 삭제하지 않는다.
- 원문 구간과 근거를 보존하며 과거 저장 기록을 새 규칙으로 자동 재해석하지 않는다.

사전 기대값을 둔 합성 32문장의 개발 검사에서 기본·통합 추출이 각각 10/32에서 32/32가 됐다.
알려진 문제와 실패를 보고 규칙을 보완한 결과이므로 독립 평가셋이나 실제 음성 정확도가 아니다.
이전 13건 8/13과 합성 기준문 117/120은 유지했다. 새로운 실제 마이크·실소음 측정은 없었다.
지원 목록 밖 생략·인용·다중 화자·복합절 전체를 해석한다고 보장하지 않는다.

## 3. 숫자·부정 오류를 검토로 연결

확실한 수치 형식을 늘리는 작업과 함께, 모호한 값을 자동 채우지 않는 보호 장치를 유지했다.
서로 다른 맥박 값, 역순 혈압, 다수 수치, 지원하지 않는 단위와 불확실 표현은 재확인 대상으로 둔다.
증상을 있음·없음·미확인으로 나누고, `호흡곤란 없음`을 `호흡 정상`으로 확대하지 않는다.
검토를 통과시키기 위해 누락을 0이나 정상값으로 바꾸지 않는다. 실제 구조는 [음성 API](VOICE_INPUT_API.md)를 참고한다.

Git의 후속 [복수 인식 후보 문맥 검토](VOICE_RECOGNITION_CONTEXT_20261103.md)는 별도 버전의 기능 기록이다.
후보 간 수치·부정 충돌을 검출하는 구현 검사와, 같은 음성을 더 잘 인식했다는 성능 검증은 다르다.
특정 정상값이나 기존 측정값에 가깝다는 이유로 후보를 정답으로 고르는 개선은 하지 않는다.

## 4. 반복 확인의 부담을 줄이는 사용성 작업

로컬 시연 후보에서는 사용자가 시작한 뒤 TTS로 중요 항목을 순서대로 읽고 확정 음성 답변을 받도록 연결했다.
`맞아요`는 현재 항목 하나만 확인하고, `아니요/수정할게요`는 수정 화면으로 보내며 불명확한 답변은 멈춘다.
모든 항목을 확인한 뒤에도 `다음 단계`라는 별도 응답이 필요하며, 마지막 `네/맞아요`만으로 상세 검토로 이동하지 않는다.
TTS 종료 뒤 응답을 듣고, 환자·세션·버전 변경이나 늦은 응답이 이전 항목을 확인하지 못하도록 보호했다.
빈 항목은 모름·미측정으로 남겨 확인 부담을 줄이되, 이미 기록한 값을 덮거나 정상으로 바꾸지 않는다.
최종 등록·위치·동의·병원 문의·목적지 확정은 각각 명시적인 기존 절차로 남긴다.
당시 브라우저 검사는 TTS·음성 결과를 모의 어댑터로 대체했다. 실제 TTS·마이크 성공률이나 터치 감소 실측은 아니다.

## 5. RNNoise는 악화도 확인하고 기본 STT에 연결하지 않음

[원본·RNNoise 짝 비교](VOICE_RNNOISE_COMPARISON_20261031.md)는 같은 합성 음원을 원본·처리본으로 비교한 실험이다.
12개 한국어 합성 발화×4조건과 잡음뿐인 3개, 총 51쌍을 같은 로컬 faster-whisper base로 102회 인식했다.
조건별 12발화 중 진짜 명령은 6건이고 나머지 6건은 비명령이다. 아래 성공 수의 분모 6은 진짜 명령만을 뜻한다.

| 조건 | 원본 명령 성공 | RNNoise 명령 성공 |
|---|---:|---:|
| 조용함 | 6/6 | 6/6 |
| 엔진 소음 | 6/6 | 6/6 |
| 사이렌 | 5/6 | 4/6 |
| 혼합 소음 | 3/6 | 0/6 |

원본 성공을 잃은 4쌍, 반대로 복구한 0쌍을 모두 남겼다. 혼합 소음 CER도 21.02%에서 123.79%로 악화했다.
파형 지표 개선을 인식 정확도 개선으로 바꾸지 않았다. 실제 사람 102명이나 브라우저 STT의 결과도 아니다.
RNNoise는 원본을 보존하는 선택형 파일 A/B 비교 도구이며 **현재 기본 마이크·STT 전처리로 채택하지 않았다.**

## 남은 검증과 다음 작업

1. 버전·원음·정답·원문을 고정하고 새 문장과 실제 발화를 수집한다. 기존 13건은 개발 자료로 유지한다.
2. 실제 소음·마스크·거리·마이크 조건을 기록하고, 같은 입력의 수치 완전 일치·극성 반전·누락을 비교한다.
3. 같은 사람이 수동/음성을 번갈아 수행해 수정·검토·완료시간·터치 수를 측정한다. 실패·중단도 보존한다.
4. 실제 TTS 종료·마이크 권한·확인 답변·중단·재개와 다른 기기의 전체 흐름을 확인한다.
5. 수정 후보의 코드·구성·검사 결과를 함께 확인한 뒤 Git 버전과 시연 버전을 일치시킨다.
