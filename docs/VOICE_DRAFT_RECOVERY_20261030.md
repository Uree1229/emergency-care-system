# 대화형 음성 초안 중간 저장과 복구

대상은 `/paramedic/quick-test.html`이다. 팀 환자용·병원용 화면과 서버의 임상 처리 규칙은 변경하지 않는다.

## 사용 흐름

1. 확정 인식문과 직접 입력을 이 브라우저의 localStorage에 동기 임시 저장한다. 임시 인식과 원본 음성은 저장하지 않는다.
2. 새로고침·브라우저 재접속 후 마지막 임시 저장부터 12시간 이내인 복구본을 읽는다.
3. 이미 초안 ID가 있으면 같은 작성자로 서버 GET을 수행하고 ID·작성자·DRAFT 상태·최소 버전을 확인한다. 다른 환자에 연결된 초안은 받지 않는다. 실패하면 빈 초안으로 대체하지 않는다.
4. 서버 저장이 확인된 내용은 서버 원문과 환자 요약에서 보여 준다. 아직 보내지 않은 문장은 미반영 검토칸에 놓는다. 자동 반영하지 않는다.
5. 저장 여부가 불확실한 요청은 기존 요청 ID·본문·버전·발화 ID와 작업 단계를 복원한다. 사용자가 같은 요청 재시도를 눌러야 서버에 보낸다.

초안 생성 응답을 잃었으면 session ID가 없어도 원래 생성 요청을 재시도한다. 생성 결과를 확인한 뒤 원래 발화 ID의 문장을 저장한다. 초안 저장 응답 유실은 원래 요청을 재시도하여 서버의 idempotency 캐시로 중복 저장을 막는다. duplicate 뒤 최신 GET까지 실패해도 pending 요청을 유지한다.

## 쓰기 전 보관

`VoiceClient.beforeWrite`는 네트워크 호출 전에 동기 실행한다. 저장 공간 오류·용량 초과·다른 탭 변경 등으로 체크포인트를 쓰지 못하면 HTTP 쓰기를 보내지 않는다. 현재 문장과 pending 작업을 메모리에 유지하고 오류를 표시한다. 저장을 확인하기 전 새 요청으로 바꾸지 않는다.

`QuickSession.exportRecovery()`와 `restoreRecovery()`는 create/write/answer의 작은 JSON 계약만 허용한다. actor·초안·작업 단계·본문·질문·요청 ID를 교차 검증한다. 복원은 메모리 작업이며 자동 POST·환자 등록·병원 문의·음성 명령 실행·마이크 시작을 수행하지 않는다.

## 저장 범위와 정리

- checkpoint 형식은 기존 `paramedic.voice.quick-recovery.v1` 계약을 유지한다. 현재 물리 보관은 `paramedic.voice.patient-records.v1` 목록의 환자별 checkpoint이며, 기존 단일 키는 안전하게 이관한다. [환자별 전환](VOICE_PATIENT_SWITCH_20261030.md).
- 본문: 초안 참조·미반영 텍스트·수동 검토 문장·최소 pending 요청과 작업 문맥. 전체 서버 환자 스냅샷과 오디오는 제외한다.
- 한 복구본은 UTF-8 JSON 128KiB, 미반영/직접 입력은 각각 16,000자 이내다. 실제 API 입력은 기존 4,000자 이하다. 초과 원문을 잘라 저장하지 않고 실패를 표시한다.
- 12시간은 자동 복원 유효기간이며 브라우저가 닫힌 동안 파일을 삭제하는 타이머가 아니다. 만료·형식 오류·다른 원점의 복구본은 자동 재생하지 않고 명시적인 새 기록 시작을 기다린다.
- 새 환자 시작은 이전 환자의 복구본을 보존한다. 현재 환자 복구본 제거는 선택한 환자의 브라우저 임시본만 지우고 다른 환자·서버 원기록은 유지한다. 공용 기기에서는 작업 후 환자별로 복구본을 정리한다.
- 다른 탭에서 값이 바뀌면 오래된 탭의 후속 쓰기·삭제를 차단한다. 비교 후 localStorage 쓰기는 원자적 CAS가 아니므로 완전히 동시인 다중 탭 저장을 보장하지 않는다. 서버의 버전 검사와 idempotency 검증도 함께 적용한다.

같은 브라우저와 서버 원점에서만 복원한다. 저장 공간 삭제, 비공개 모드 종료, 다른 장치·브라우저·포트로의 이동, 확정 인식 전에 사라진 음성은 복구하지 못한다. 복구본은 암호화된 저장소로 표현하지 않는다.

## 검증

모듈 시험은 스키마·12시간 경계·용량·원문 보존·오디오 차단·이전 값 보존을 검증한다. 실제 quick 페이지를 실행하는 모의 DOM 시험은 새 실행 환경과 공유 저장소로 새로고침을 재현하고 GET 복원, create/transcript/answer 응답 유실, 정확한 재시도, 저장 공간 실패, 다른 탭 변경과 실패 시 빈 초안 방지를 확인한다.

별도 HTTP 시험은 실제 production handler와 새 합성 SQLite를 사용한다. 실제 마이크·STT 서비스·사용자 녹음 DB·실제 환자 등록·병원 전송은 사용하지 않는다. 자동 테스트는 음성 인식 정확도 측정과 구분한다.
