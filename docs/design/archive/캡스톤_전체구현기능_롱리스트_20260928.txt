응급환자 병원 연결 서비스구현 기능 롱리스트
병원용 웹 · 환자 및 보호자용 웹 · 배정 알고리즘  |  2026년 9월 28일
캡스톤 기간 안에 구현·검증할 범위를 기능 ID별로 정리한 팀 작업 관리 문서이다. 기존 158개 항목에서 통합·제외를 거쳐 총 11개 영역, 112개 항목으로 확정했다. 담당자와 상태 칸은 팀에서 작성한다.
로그인과 계정 관리 기능은 구현 범위에서 제외한다. 기존 기능 ID는 참조를 위해 유지하며, 통합된 기능은 대표 ID에 괄호로 표기하고 삭제·통합한 ID는 재사용하지 않는다.
분류와 사용 방법
핵심은 주요 서비스 흐름과 알고리즘 검증에 필요한 기능, 선택은 핵심 완료 후 일정에 따라 추가할 기능이다. 핵심 100개 전체가 첫 시연 대상은 아니며, 상태 칸에 첫 시연 / 이후 구현과 계획 / 진행 / 검증 / 완료를 함께 기록한다. 범위에서 뺀 기능은 문서 끝의 제외 항목에 모아 최종 보고서의 한계 및 향후 과제로 기술한다.
담당자·상태 공란은 미구현을 의미하지 않는다. 기존 솔버와 응답 화면에 구현된 항목도 포함되어 있으므로 확인 후 계획 / 진행 / 검증 / 완료로 기록한다. 완료 판단은 화면 유무뿐 아니라 서버 연결과 해당 예외 조건의 검증을 포함한다.
구분별 항목 수  |  핵심 100개 · 선택 12개
구현 방식 기준
환자용 화면은 네이티브 앱 대신 모바일 웹으로 구현한다. 앱 설치 없이 이용하며, 위치 권한 거절 시 직접 입력을 제공한다. 전화·길찾기 연결은 단순화하여, 전화는 tel 링크, 길찾기는 외부 지도 앱 링크로 연결한다.
실시간 갱신은 2~3초 주기의 조회로 처리한다. 웹소켓과 푸시 알림은 사용하지 않는다.
가상 데이터 시연에서는 로그인 없이 병원별 고유 URL로 접속한다. URL 구분은 접근 통제를 대신하지 않으며, 실제 운영용 인증·권한 체계는 별도 과제로 둔다.
병원 기본정보는 공공데이터를 1회 적재하고, 환자·자원 변화는 가상 데이터로 구성한다. 이동시간은 지도 API 또는 실험용 추정값을 사용하며 추정 방식과 한계를 명시한다. 초기에는 필요한 진료과와 중증도가 입력된 것으로 가정한다.
첫 통합 시연의 흐름
환자 정보 입력 → 후보 병원·배정안 계산 → 수용 문의·응답 → 목적지 확정·이동 → 미등록 환자 유입 → 예상 치료 시작시각·수용 가능 여부 재평가 → 변경 알림 → 도착 확인
먼저 이 흐름을 연결한 후 수용 불가·미응답·취소·동시 응답을 추가한다. 이후 이동 중 돌발 환자 유입과 재계산(A24~A27, H33~H35, T05)을 검증한다. A26·H33~H35·T05와 변경 알림(P37·H36)은 핵심 시나리오이므로 유지한다. P09의 누락 처리와 T12의 목적지 변경·추가 이동시간 평가도 핵심으로 유지한다.
일정이 부족하면 중복 정보 표시와 중간 상태를 단순화하고, 추가 시나리오 및 사용성 실험 규모를 조정한다. 동시 수용 충돌 방지와 자원 제약 검증은 유지한다. 핵심을 선택으로 변경해도 전체 항목 수는 줄지 않으므로 분류 변경 시 개수를 다시 집계한다.
설계 기준
일반인의 입력은 관찰 정보로 취급한다. 위험 신호 문항은 전문가 검토 대상이며, 미확인 정보를 경증으로 처리하거나 설문으로 자가용 이동 가능을 확정하지 않는다.
알고리즘은 배정안을 제안하고 병원은 환자별 수용 여부를 확인한다. 수용 응답을 즉시 치료나 특정 병상의 보장으로 표시하지 않는다.
이동 중 목적지는 우선 유지한다. 자원 변화가 발생하면 예상 치료 시작시각과 기존 수용 가능 여부를 다시 평가하고, 목적지 변경은 새 병원 확인과 담당자 판단을 거친다.
현재 구현된 고정 환자 처리와 달리 A26은 치료 시작시각 재평가를 요구하는 추가 과제이다. 우선순위와 허용 지연은 실험 설정과 임상적으로 검토한 기준을 구분한다.
