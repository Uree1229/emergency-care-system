응급환자 병원 배정 지원 시스템 구현 기능 롱리스트
개정일: 2026-10-14
대상: 구급대원 모바일 웹 · 병원 웹 · 공통 서버/DB · 문의 정책 · 공동 배정 · 지도 시뮬레이션 · 검증

1. 이번 개정의 기준

- 현재 프로젝트 범위와 실제 코드·연결 문서를 기준으로 다시 구성했다. 기존 9월 28일본은 archive에 보존했다.
- 일반인·보호자 직접 이용, 자가 진단·자가 이동 판단, 로그인·계정 관리는 현재 핵심 구현에서 제외한다.
- 코드 폴더 patient-ui/emergency-app, DB의 patient 같은 내부 식별자는 유지해도 된다. 사용자 역할과 요구사항은 구급대원 기준이다.
- 문의 정책 V3, 공동 배정 H1, 비교 솔버 C1(CP-SAT), 현재 운영 솔버 추천을 각각 구분한다.
- 공개 병원·도로 자료와 가상 환자·응답·운영 자원은 분리한다. 실제 의료기관으로 문의·메시지를 보내지 않는다.
- 기존 P/H/A/S/O/T ID는 과거 보고서 참조용으로 보존하고 새 ID 대응표를 제공한다. 기존 코드 주석·보고서 생성기는 이 작업에서 변경하지 않았다.

2. 상태와 완료 기준의 읽는 법

연결완료: 해당 범위의 화면과 서버 또는 지도 흐름을 로컬 가상 환경에서 연결 확인했다.
구현완료: 해당 서버·수집·검증 도구를 구현했다. 사용자 화면이나 장기 운영의 완료를 자동으로 뜻하지 않는다.
API완료: 서버 계약·검증은 있으나 필요한 사용자 화면·조작 연결이 남아 있다.
실험완료: 명시한 합성 실험을 끝냈다. 운영 서버·전체 이송 연결이나 현실 효과를 뜻하지 않는다.
부분: 기능 일부가 있으나 항목에 적힌 보완·추가 연결·검증이 남아 있다.
미구현: 이번 범위에 필요하지만 아직 구현 또는 별도 정책 비교를 하지 않았다.
미검증: 실제 참여자·기기·환경 평가를 아직 수행하지 않았다.

핵심: 최종 시연·연구의 완료 기준에 포함할 항목. 모든 핵심이 당장 새로 개발할 일이라는 뜻은 아니다.
선택: 핵심 연결과 검증 후 필요성과 일정에 따라 추가한다.
완료 기준은 최종 판정 기준이다. 현재 상태가 부분/API완료인 항목에 적힌 모든 조건이 이미 통과했다는 뜻은 아니다.
담당은 역할 단위이며 팀원 이름·기한은 팀이 확정한다. 구급대원/병원 UI 변경은 각 팀원이 맡고 현재 사용자는 서버·DB·알고리즘·시뮬레이션과 연결 계약을 담당한다.

3. 핵심 서비스 흐름

구급대원 상태·위치 입력 → 공통 이송 ID 저장 → 조건별 후보 탐색 → 서버 문의 정책 → 병원 질문·수용 회신 → 구급대원 목적지 확정 → 출발·3자 대화 → 등록된 조건 변경의 환자별 재확인 → 병원 유지/조정 판단 → 새 수용 확인 → 구급대원 목적지 변경 → 병원 도착·퇴실.

서버 사건 메시지는 진행 기록이다. 채팅으로 수용·출발·임상 입력·목적지 변경을 대신하지 않는다.
신규 환자를 받을 여유 0과 이미 수용한 환자의 조건 유지 불가는 다르다. 자원 변화만으로 자동 재배정하지 않는다.
현재 기본 화면 흐름은 연결됐지만 추천 패널·외부 유입 목록/퇴실/정산 UI와 H1 통합은 남아 있다.

1) 공식 구급대원 진입 흐름과 입력 항목 정리: G01~G05, G13, G18.

2) 양쪽 추천 표시와 배정 워커 가동 시연: G11, HW16, SV05.
   가동/비활성·만료·입력 부족을 먼저 표시하고 유효 회신의 수동 확정 경로를 유지한다.
3) 병원 자원 후속 화면 연결: HW11, HW13~HW15.
   외부 유입 중복 방지→목록·개별 퇴실→정산 충돌의 명시적 처리 순으로 연결한다.
4) H1 전체 이송 연결과 계산/품질 비교: AL04~AL06, VT04~VT06.
   기존 실험 결과를 보존한 새 분기에서 진행하고 더 긴 CP 예산·공통 환자 이동 악화·정보 지연을 함께 비교한다.

   빠른 거절과 수용 결과를 구분하고 유효 수용 이후 추가 대기·확정의 절충을 별도 실험으로 정의한다.

7. 검증은 네 묶음으로 관리

문의 정책: 고정 1/3/5, V2, V3 및 새 문의/확정 정책의 문의 수·실패·선정/대기 절충.
정적 공동 배정: 같은 현재 수용 후보·자원·목적·예산의 H1과 CP-SAT 품질·계산시간·미배정·공통 환자 이동.
전체 이송: 같은 외부 환경에서 문의·회신·확정·도착·변경·전원을 진행한 정책 결과. 앞선 선택으로 이후 자원·회신이 달라질 수 있다.
현장 사용성: 구급대원·병원 담당자의 입력·회신·갱신·재확인 총 업무시간과 누락/오응답. 실제 의료인 미참여는 역할 테스트로 표시한다.

현재 실제 도로 3사례는 설명용이며 독립 검증 성과에 합치지 않는다. 공식 상황실 평균시간과 합성 지표의 차이를 현행 체계 대비 개선율로 계산하지 않는다.

8. 선택/향후 또는 현재 범위 밖

선택 기능은 G19, G20, HW18, CM06이다.
다음은 현재 핵심 개발 약속에서 제외한다: 일반인·보호자 전용 서비스, 로그인·계정·운영 권한 체계, 실제 119/상황실/EMR 연계, 실제 자원 예약, 운영형 푸시·웹소켓, 병원 처치 종료·미래 수용확률 정밀 예측, 실제 임상 예후/사망률 우월성 검증, 운영 DB와 지도의 실시간 자동 동기화, 자원 여유 비율 정책.
로그인 제외는 실제 운영 보안 완료를 뜻하지 않는다. 기관별 URL·담당자명도 접근 통제를 대신하지 않는다.
