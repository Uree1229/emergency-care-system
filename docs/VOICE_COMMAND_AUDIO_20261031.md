# 명령 연습 원본 녹음과 음성 포함 ZIP

`/paramedic/command-practice.html`에서 원본 녹음·확정 인식문·독립 정답·시험 조건을 함께 수집한다. 명령은 판정 결과만 보여 주며 환자 등록·전환·병원 문의를 실행하지 않는다. 이 페이지는 녹음을 앱 서버에 업로드하지 않는다. 브라우저 음성 인식 서비스 자체는 네트워크를 사용할 수 있다.

여기서 **원본 녹음**은 브라우저 `MediaRecorder`가 만든 WebM·Ogg·MP4 바이트를 재인코딩하지 않고 보관한 파일이다. 장비의 가공 전 PCM이나 음성 인식 서비스 내부에서 처리한 것과 동일한 음원을 뜻하지 않는다.

## 사용 순서

1. [명령 연습 안내](VOICE_COMMAND_PRACTICE_20261031.md)에 따라 합성 대본과 익명 화자·장비·소음·말하기 조건을 정한다. `원본 녹음도 함께 보관`은 기본 선택이다. 끄면 기존 인식문 수집만 실행한다. 수동 모의 입력에는 음성 파일을 만들지 않는다.
2. `말하기 시작`을 누르고 마이크 권한을 허용한다. 녹음 준비 후 브라우저 음성 인식을 시작한다. 같은 버튼으로 마치거나, 선택한 명령 자동 종료를 이용한다. 늦게 도착한 확정 인식문까지 최종 판정에 반영한다.
3. 시도 종료 후 녹음 상태를 확인하고 재생한다. `선택한 녹음 파일 내려받기`로 한 파일을 따로 보관할 수도 있다. `불완전 녹음 경고`가 있으면 전체 발화가 들어 있는지 직접 확인한다.
4. 인식문·대본·의도한 명령을 확인하고 정답·메모를 저장한다. 주석 수정은 녹음·확정 인식문·당시 명령 판정을 바꾸지 않는다.
5. `음성 포함 전체 ZIP 내려받기`를 누른다. 포함 음성 수와 누락·오류 수를 확인하고 실제 내려받은 파일을 열어 본다. JSON·CSV·TXT만으로는 녹음이 보관되지 않는다.

HTTPS 또는 `localhost`처럼 마이크와 SHA-256을 사용할 수 있는 실행 환경이 필요하다. 공통 앱 서버에서는 `http://127.0.0.1:8000/paramedic/command-practice.html`을 연다. 호스트·포트·브라우저·프로필이 다르면 브라우저 보관함도 달라질 수 있다.

## 녹음과 인식의 구분

녹음은 별도의 `getUserMedia`·`MediaRecorder` 경로이며 브라우저 음성 인식은 `VoiceCapture` 경로다. 녹음 요청에는 `echoCancellation:false`, `noiseSuppression:false`, `autoGainControl:false`를 전달한다. 이는 장비·브라우저에 대한 요청이며 실제 전처리 해제를 보증하지 않는다. 소음 억제의 정확도 개선이나 STT와 동일한 오디오 입력을 입증한 설정도 아니다.

인식 결과의 `ok`, `error`, `no_match`, `aborted`와 녹음 파일의 상태는 별개다. 인식이 실패해도 녹음이 있을 수 있고, 인식문이 있어도 녹음 권한·코덱·저장 실패로 파일이 없을 수 있다. 임시 인식문은 확정 원문에 섞지 않는다. 실제 환자정보 대신 합성 대본을 사용한다.

## 브라우저 보관과 복구

텍스트·정답·조건은 기존 localStorage 키 `paramedic.voice.command-practice.v1`에 둔다. 녹음은 IndexedDB `paramedic-command-practice-audio-v1`의 `recordings` 보관함에 시도 ID별로 둔다. 한 행에 Blob·SHA-256/MIME/크기/시각/오류 코드와 녹음 당시의 원래 시도 snapshot을 함께 커밋한다. 같은 ID에 다른 파일·원문을 덮어쓰지 않으며 저장 후 다시 읽어 확인한다.

이 IndexedDB 행의 원자성과 localStorage 목록 저장은 구분한다. 두 저장소 전체를 하나의 원자적 트랜잭션으로 묶지는 않는다.

- **IndexedDB 실패:** 최종 Blob을 얻었다면 현재 화면 메모리에 유지하고 `memory_only`로 표시한다. 새 음성 녹음을 막고 ZIP 내보내기 또는 `브라우저 보관 다시 시도`를 안내한다. 이 상태에서 새로고침하면 메모리 파일을 잃을 수 있다.
- **음성 저장 후 텍스트 목록 실패:** 음성과 원래 시도 snapshot이 보관함에 남아 있을 수 있다. 목록 저장을 재시도하거나, 다음 실행에서 `녹음 보관함의 누락 시도 복구`를 누른다. 기존 ID의 정답 주석은 덮어쓰지 않는다.
- **목록에 녹음 정보만 있고 파일이 없음:** 복원·JSON 합치기 후 현재 보관함을 따로 검증해 `missing`으로 표시한다. 기대 해시·크기는 남겨 대조할 수 있게 한다. 파일을 임의의 무음으로 대체하지 않는다.
- **녹음 중 페이지 이탈:** 이미 알려진 확정 인식문은 `aborted`/`page_exit`, 음성은 `interrupted`로 보관하려고 시도한다. 진행 중 녹음 조각은 취소하며 페이지 종료·충돌·전원 차단 뒤 원음 복구를 보장하지 않는다. 이미 커밋된 보관함 행만 누락 시도 복구의 대상이다.

녹음 오류가 나더라도 최종 Blob을 확보했다면 부분 파일을 보존한다. `captureErrorCode`를 보관함에 남기고 시도 `audio.errorCode`와 ZIP manifest 경고로 전달한다. `stored`/`actualAudioSaved:true`는 브라우저 지속 보관을 확인했다는 뜻이며 완전한 녹음·정확한 인식·좋은 음질을 뜻하지 않는다.

## v1·v2 메타데이터

음성 없는 기존 v1 자료는 그대로 지원한다. `audio`를 연결한 자료는 `schema:2`를 사용하며 v1과 같은 텍스트·출처·정답 필드를 유지한다. `purpose:synthetic_command_practice`는 합성 연습 용도 표시이지 파일이 합성 음성임을 인증하는 값이 아니다.

시도별 `audio`에는 `status`, `contentType`, `extension`, `byteLength`, `sha256`, `startedAt`, `endedAt`, `errorCode`가 있다.

| 상태 | 의미 |
|---|---|
| `stored` | IndexedDB에 쓰고 다시 확인한 파일 |
| `memory_only` | 현재 화면 메모리에서만 확보한 파일 |
| `missing` | 기대 파일 정보는 있으나 현재 파일을 확인하지 못함 |
| `failed`·`unavailable`·`empty` | 녹음 실패·지원 불가·최종 음성 없음 |
| `interrupted` | 페이지 이탈 등으로 녹음을 확정하지 못함 |
| `not_recorded` | 녹음하지 않은 시도 |

시도 `actualAudioSaved`는 `stored`일 때만 true이고 묶음 값은 해당 시도가 하나라도 있으면 true다. JSON 가져오기는 원래 기록의 메타데이터와 출처를 보존한다. 이 플래그만으로 가져온 JSON에 음성이 들어 있다고 판단하지 않는다. UI가 현재 보관함의 실제 파일·원문 연결을 다시 확인한다. ZIP에 실제로 포함된 파일 여부는 manifest의 `included`를 기준으로 확인한다.

## ZIP 내용과 무결성

외부 CDN·라이브러리 다운로드 없이 브라우저에서 저장 방식 ZIP을 만든다. ZIP 헤더·목록·CRC32 구조는 [PKWARE ZIP 명세](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)를 따른다. 파일 구성은 다음과 같다.

| 경로 | 내용 |
|---|---|
| `manifest.json` | 시도 ID별 포함 여부·가용 상태·음성 경로·MIME·크기·SHA-256·오류 경고, 파일별 해시 목록 |
| `dataset-original.json` | 내보내기 전 데이터셋의 정규 JSON |
| `dataset.json` | 현재 확인한 파일 상태를 반영한 데이터셋 복사본 |
| `attempts.csv` | 복사본의 인식문·정답·조건·음성 메타데이터를 표로 검토하는 자료 |
| `audio/0001-시도ID.webm` 등 | 실제 확보한 원본 바이트. WebM·Ogg·MP4 형식 유지 |
| `README.txt` | 저장 플래그·누락·부분 녹음·가져오기 한계 안내 |

원래 데이터셋은 변경하지 않는다. ZIP의 `dataset.json`에서는 현재 파일이 없으면 저장 성공 주장을 `missing`으로 바꾸고 기대 해시·크기는 유지한다. 메모리 파일도 포함할 수 있으며 `memory_only`와 `included:true`를 함께 표시한다. 누락·오류·미녹음 시도도 manifest에 남긴다.

포함 전 실제 바이트로 SHA-256을 계산하고 보관된 해시·크기·MIME 및 원래 시도와 대조한다. 원문·출처·시험 조건이 다른 같은 ID의 파일은 연결하지 않는다. ZIP 자체에는 CRC32도 기록한다. 경로는 고정된 `audio/` 아래에 순번과 인코딩된 ID를 사용한다. 부분 파일의 바이트를 보정하거나 재인코딩하지 않는다.

**JSON 합치기는 메타데이터만 합친다. ZIP·음성 파일 가져오기는 이번 기능에 없다.** 별도 평가기의 `speech_eval --recordings` 입력을 자동 생성하는 기능도 아니다. STT 성능을 계산하려면 실제 발화·독립 정답·녹음 조건을 별도로 검토해야 한다.

## 용량과 새 묶음

시도당 최대 180초·음성 20MiB, 현재 수집 묶음의 음성 예산은 128MiB, 브라우저 전체 녹음 보관함은 150MiB다. 시작 시 다음 시도의 최대 20MiB를 확보할 수 있는지 보수적으로 확인하므로 128MiB에 도달하기 전 새 녹음을 막을 수 있다. 텍스트는 기존 500건·JSON 4MiB 상한을 유지한다. ZIP 생성에는 256MiB 상한이 있다. 실제 브라우저 할당량이 더 작으면 먼저 실패할 수 있다.

음성 기록이 있는 묶음은 현재 ZIP을 내려받고 실제 파일을 확인했다는 체크를 해야 새 묶음을 시작할 수 있다. 인식문만 있는 묶음은 JSON 확인을 사용할 수 있다. 정답·기록이 바뀌면 이전 내보내기 확인은 무효가 된다. 브라우저는 내보내기 요청만으로 OS 파일 저장 성공을 확인할 수 없다.

새 묶음은 기본적으로 목록만 비우고 이전 녹음은 IndexedDB에 남긴다. `이번 ZIP에 포함한 녹음을 브라우저에서도 정리`를 선택하면 확인한 ZIP에 포함된 ID·해시의 파일만 정리한다. 누락·불일치 파일을 일괄 삭제하지 않는다. 정리하지 않은 이전 묶음도 누락 시도 복구로 다시 나타날 수 있다. 복구 전에 현재 자료를 별도 ZIP으로 보관하면 묶음을 구분하기 쉽다.

## 현재 검증 범위

대상 회귀 **291개(기존 core 119 + 페이지 12 + 오디오 메타데이터 44 + 캡처/보관함 84 + ZIP 32)**, 배포 후보의 전체 Node 회귀 **1,706/1,706**가 통과했다. 최종 통합은 **17개 시나리오·80개 UI 확인**을 통과했고, 내려받은 **ZIP 19개를 Python 표준 `zipfile`로 열어 360개 확인**(CRC·실제 바이트·파일 목록·해시·원문·정답·조건·누락·부분 녹음 경고)을 수행했다. 정적 의존 파일 10개의 바이트·MIME을 확인했으며 앱 API 요청은 0건이다. 권한 대기 취소·늦은 콜백·저장 실패 후 메모리 내보내기·새로고침 누락 표시·시도 복구·같은 ID의 다른 원문 연결 거절도 확인했다.

통합 시험은 가짜 브라우저·인식기·MediaRecorder·IndexedDB를 사용하므로 실제 마이크 또는 실제 STT 정확도 증거가 아니다. 실제 브라우저에서는 기존 수동 모의 1건을 ZIP으로 내려받아 CRC 및 음성 0개 표시를 별도로 확인했다. 실제 마이크 녹음·재생 음질·STT와 동시 마이크 사용·여러 브라우저의 권한/코덱 호환성은 아직 확인하지 않았다. 가짜 IndexedDB 시험은 실제 브라우저의 동시 트랜잭션·디스크 내구성이나 실제 BFCache 동작을 보증하지 않는다.

```text
node --test test_paramedic_command_practice_data.mjs test_paramedic_command_practice_page.mjs test_paramedic_command_practice_audio_metadata.mjs test_paramedic_practice_audio.mjs test_paramedic_practice_audio_bundle.mjs
```
