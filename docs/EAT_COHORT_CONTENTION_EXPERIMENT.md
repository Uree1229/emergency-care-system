# 후속 문의 계획 사이의 예상 대기 경합 보정

상태: 별도 후보 `eat_cohort_contention_l15_f`의 훈련 360환경·1,242명 검증을 마쳤다. 목표를 충족하지 못해 채택하지 않는다. 새 개발·별도 검증은 실행하지 않는다. 이전 두 후보의 소스·원문·감사·실패 조건을 보존한다.

## 목표와 기준

기존 827명의 CS 대비 성공 순증 3명과 D 대비 선정 대기 78초 단축을 유지하고, 추가 415명의 CS 대비 성공 부족·대기 증가를 개선한다. 두 자료는 모두 이미 관측한 훈련 자료이며 각각 통과해야 한다.

| 훈련 구간 | CS 성공 / 선정 대기 | Hedge 성공 / 선정 대기 | Recourse 성공 / 선정 대기 | 직전 Followplan 성공 / 선정 대기 | 이번 조건 |
|---|---:|---:|---:|---:|---|
| 기존 240환경·827명 | 689 / 111,858초 | 692 / 113,296초 | 691 / 111,495초 | 693 / 113,163초 | 성공 692 이상·대기 113,296초 이하 |
| 추가 120환경·415명 | 364 / 53,498초 | 363 / 54,759초 | 364 / 53,666초 | 364 / 54,712초 | 성공 364 이상·대기 53,498초 미만 |

실패한 환자의 선정 대기는 300초로 계산한다. 환자 우선순위·성공 수를 먼저, 대기를 그다음에 줄이는 원칙을 유지한다. 개별 성공 교환은 별도로 보고하며 모든 과거 성공 환자의 개별 성공을 보장한다는 추가 조건은 두지 않는다. 도착시간은 선정 대기와 구분하고, 실패 환자의 도착 비용은 1,800초로 계산한다.

## 관측한 한계

직전 Followplan은 기존 구간에서 성공 목표를 넘겼지만, 추가 구간은 CS보다 대기가 1,214초 길었다. 특히 기존·추가 스트레스 구간에서 각각 1,721초·694초의 초과 대기가 다시 생겼다. 저장한 계획을 확인하니 여러 환자가 같은 병원으로 15초에 재문의할 계획인데도 각 환자의 미래 대기를 따로 평가하고 있었다.

다음 한 재평가 시점만 허용하는 제한도 검토했으나, 문제 경로의 주요 문의가 이미 15초에 있고 기존 추가 성공에는 45초 계획도 포함돼 있어 적용하지 않았다. 이번에는 계획한 병원·시점 자체를 고정한 채 후속 계획끼리의 예상 작업량만 반영한다.

## 바꾸는 계산 한 가지

부모 Followplan의 최대 세 가지 문의안·초기 회신 분포·후속 문의 계획·잔여 환자 점수를 그대로 보존한다. 각 문의안에서 처음 문의하는 환자들의 가상 후속 문의를 한 줄로 모은다.

1. 가상 송신 시점, 첫 집단의 환자 순서, 후보 순서로 후속 문의를 정렬한다.
2. 부모 모형의 초기 회신 분포와 각 후속 문의의 보정 전 회신 분포 F0를 고정한다.
3. 후속 문의의 원래 예상 대기에 앞서 계획한 같은 병원 후속 문의들의 예상 작업량을 더해 q1을 구한다.
4. 해당 문의의 예상 시작 시점 `min(송신 오프셋 + q1, 환자 H)`까지 다른 병원에서 수용되지 않았을 확률 S를 고정 분포로 계산한다. 자기 병원은 제외한다. 예상 작업량은 원래 평균 작업량을 작업자 수로 나눈 값에 S를 곱한다.
5. 초기 회신 분포는 그대로 두고 후속 문의의 q1 회신 분포만 다시 계산한다. 초기·후속 회신을 합쳐 예상 성공·선정 대기를 구한다. 수용 가능성에 S를 다시 곱하지 않는다.

보정한 F1을 작업량 계산으로 되돌리지 않는다. 후속 송신 시점이 15초라면 q1이 0이어도 그 시점 전 수용으로 송신하지 않을 가능성을 작업량에 반영한다. 미래 문의 비용의 생존확률은 보정한 분포로 다시 계산하고 초기 문의 비용은 고정한다.

이 계산은 정적 대기열 근사다. 앞선 작업량을 시간이 흐른 만큼 줄이지 않으므로, 서로 다른 시점의 작업량을 보수적으로 과대 계산할 수 있다. 계획의 병원·시점을 재최적화하지 않고, 실제 미래 회신이나 실제 다음 정책 행동을 보장하지 않는다.

예상 작업량을 확률로 줄이는 것은 실제 동시 문의 자리를 나누는 동작이 아니다. 실제 동시 문의 4건·총 문의 10곳·A/H·원자적 묶음 적용·FIFO·단독 및 후기 H 경로는 그대로다. 실제 송신은 현재 두 환자에게만 적용하며 가상 미래 문의를 실제 예약으로 만들지 않는다.

## 사전 검증 절차

부모 474개 소스·참조 859개·압축 원문 2,400개를 보존하고 새 소스 16개를 더한 총 490개를 검사·동결한 뒤 실행한다. 부모 단계에서 기록한 문서 목록의 역사적 해시 변경은 그대로 승계하며 이번에 새 참조를 재결속하지 않는다. 현재 문서·기존 소스·과거 원문을 복원하거나 수정하지 않는다.

- 훈련 360환경: 새 후보 분기만 한 번씩 실행하고 봉인된 비교군 15개·5,400분기를 재사용한다. 모든 원문 저장 후 두 훈련 구간의 조건을 따로 검사한다.
- 새 개발 120환경: 훈련 조건을 모두 통과할 때만 16개 정책을 비교한다. CS·Hedge 각각의 실패 비증가와 선정 대기 엄격 감소를 모두 요구한다.
- 별도 검증 368환경: 새 개발도 통과할 때만 실행한다. 같은 점 조건과 함께 CS·Hedge 각각의 실패 차이 95% 상한이 0 이하, 대기 차이 95% 상한이 0 미만이어야 한다. 시나리오 단위 짝 부트스트랩 10,000회이며 지표별 주변 95% 구간이다. 네 조건의 공동 95% 보장은 아니다.

새 입력은 소스 동결 뒤 생성하고 과거에 생성만 해 둔 미실행 입력의 난수도 재사용하지 않는다. 결과 제외·성능 재실행·같은 후보의 사후 설정 변경은 하지 않는다. 단계 실패 뒤의 성능 실행은 차단한다. 최대 새 실행은 8,168분기다. 운영 서버와 기본 `fixed_3`는 바꾸지 않는다.

독립 감사는 부모 Followplan 전체 증명, 고정 계획·초기 CDF·정렬·고정 F0·작업량·새 후속 CDF·비용·최종 선택과 실제 모든 환자의 FIFO를 별도로 확인한다. 의미 감사는 모든 원문 저장 후 네 프로세스에서 진행하고, 원문·전체 소스·원문 인덱스 해시에 결속한 사례별 증명을 저장한다. 유효한 증명이 있으면 저장 감사를 다시 실행하지 않고 재사용한다. 이는 검증 작업의 병렬화이며 성능 정책을 바꾸지 않는다. 전체 실험 벽시계 시간은 감사·수집을 포함하므로 정책 계산 속도로 해석하지 않는다.

전체 검사는 현재 파일로 실행한다. 과거 문서 목록 해시를 확인하는 검사 10개의 실패는 부모와 같이 실패로 보존하고, 정확한 검사 ID·문서 오류·기존/현재 해시만 일치할 때 새 동결 자격을 허용한다. 해시·파일 읽기·원래 검사 문구를 대체하지 않으며 전체 검사 통과로 표시하지 않는다. 나머지 검사·보존 명세·원문 동등성·새 독립 감사는 유효해야 한다.

최종 표준 라이브러리 회계기는 정책·시뮬레이터를 호출하지 않고 성공·선정 대기·도착·개별 성공 교환·단계 조건을 재계산하고, 사례별 의미 증명의 출처와 해시를 다시 대조한다. 합성 입력의 우선순위는 미확인·기본값 4이며 다양한 실제 임상 응급도에 대한 우월성 주장은 하지 않는다.

## 결과

사전 검사 60개 모듈·965건 중 955건이 성공했다. 나머지 10건은 부모에서 이미 기록한 `docs/README.md`의 역사적 참조 해시 오류이며 실패·추적 기록을 그대로 보존했다. 실행 오류와 건너뛴 검사는 없다. 새 검사 113건은 모두 성공했다. 원본 읽기·해시·검사 단언을 바꾸지 않았으며 전체 검사 통과로 표시하지 않는다.

고정 예제에서는 비교군 15개의 전체 원문이 부모와 같고 새 후보 2개의 독립 의미 감사가 성공했다. 동시 발생 예제는 실제 공동 처리 4개와 새 미래 작업량 32개를 검사했다. 이는 연결·계산의 사전 검사이며 새 성능 표본이 아니다. 부모 소스·참조, 인과적 입력, 확률·비용의 중복 계산 여부와 표준 라이브러리 회계기의 변조 거부를 별도로 검토했다.

### 공식 결과와 독립 집계

새 후보 360분기를 각각 한 번 실행하고 모든 원문을 저장한 뒤, 독립 의미 감사 360개와 환자별 별도 집계를 마쳤다. 비교군 15개·5,400분기는 봉인된 기록을 재사용했다. 별도 집계와 공식 결과는 두 구간·세 범위·16정책의 지표 96묶음, 다섯 비교군의 짝 비교 30묶음, 개별 성공 교환·도착·9개 회귀 식별군에서 모두 일치했다. 과거 2,400개 원문의 정책 감사를 재실행하지 않았다.

전체 실행·의미 감사·수집 벽시계 시간은 약 531.26초였다. 정책 계산시간이나 현장 처리 지연을 측정한 값이 아니다. 원문 제외·성능 재실행·사후 설정 변경은 없다. 운영 서버와 기본 `fixed_3`는 그대로다.

### 판정과 다음 가설

기존 성공 목표만 통과했고 기존 대기·추가 성공·추가 대기 목표는 실패했다. 후속 단계는 차단한다. 소스 490개·검사·고정 예제·모든 새 원문·사례별 감사 증명·별도 집계·최종 문서를 해시에 결속해 남긴다.

다음 연구 가설은 후속 문의 시점 사이에 처리된 작업량을 대기열에서 차감하는 시간 진행 모형이다. 현재는 15초·195초처럼 떨어진 문의에도 앞선 작업량을 줄이지 않는다. 다만 평균 작업량에서 경과시간을 단순 차감하면 확률적인 잔여 작업을 과소 평가할 수 있다. 실제 미래 회신이나 실제 문의 자리 해제를 관측한 것처럼 처리해서는 안 된다. 병원·문의 시점·초기 회신 분포를 고정하고, 작업자·FIFO·잔여 분포 가정을 별도 후보에서 검증해야 한다. 이 가설은 구현하거나 성능을 실행하지 않았으며 성공 복구나 대기 감소를 보장하지 않는다.
