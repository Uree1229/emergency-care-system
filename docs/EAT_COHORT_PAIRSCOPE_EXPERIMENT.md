# 첫 문의 대상 두 명인 구간의 공동 평가 확장

상태: 별도 후보 `eat_cohort_pairscope_l15_f`의 훈련 360환경·독립 의미 감사·회계 대조를 마쳤다. 기존 자료에서 성공 1명 손실과 선정 대기 63초 증가로 직접 목표와 전체 승격 조건 모두 실패했다. 소스·보호·판정 기준은 실행 전에 고정한 그대로이며 채택하지 않는다.

## 변경 범위

기존 상위 공동 평가는 특정 TAIL 거부를 Budget이 뒤쪽 두 환자 비교로 취소한 경우에만 활성화됐다. 첫 문의 대상이 정확히 두 명이면 이 뒤쪽 비교 자체가 없어 상위 평가가 실행되지 않았다. 이전 Envelope는 기존 827명의 선정 대기가 Stoploss와 같고 추가 415명은 12초 길었으며, 실제 선택 변경 0건이었다. 소스·결과·실패 판정을 봉인해 보존했다.

이번 후보는 **활성화 범위 하나만** 확장한다. 부모가 이미 평가한 그룹은 부모 Envelope의 점수·보호·선택·동작을 그대로 유지한다. 부모가 평가하지 않은 그룹 중 현재 두 명 외에 남은 첫 문의 대상이 없는 경우(`tail_members == []`)에만 새 공동 평가를 수행한다. 첫 문의 대상이 세 명인 구간과 단독 환자의 후속 H 처리는 그대로다.

첫 문의 대상 두 명이라는 것은 전체 대기 환자가 두 명이라는 의미가 아니다. 이미 문의했거나 자동 문의가 꺼졌거나 작업 정보가 없는 환자도 현재 대기 상태이고 H가 남아 있으면 점수와 보호 대상에 포함한다. 실제로 적용하는 문의는 현재 두 명의 문의뿐이다.

## 새로 평가하는 구간

1. 공개 원점의 첫 문의 대상·작업 버전·문의 목록·이벤트 경계를 검증한다. 원래 JOINT 조합표와 Stoploss가 실제 선택한 기준 인덱스를 보존한다. 기준 행이 원래 타당한 조합 목록에 속하는지 단언하며 예외로 면제하지 않는다.
2. 기준 행을 먼저 놓고 원래 조합표의 나머지 타당한 행을 순서대로 모두 평가한다. 기존 H 문의 수·후보 제한·동시 문의 4건·총 문의 10곳·원래 조합 타당성을 유지한다.
3. 현재 두 환자의 같은 시점 Dynamic 투영을 만든다. 뒤쪽 환자가 없으므로 뒤쪽 단계는 빈 목록이고 단독 뒤쪽 처리는 없다.
4. 같은 공개 원점에서 모든 잔여 환자의 기존 문의 CDF를 고정한다. 비활성 부모 제안의 빈 `owner_origins`를 재사용하거나 환자를 누락하지 않는다. 기존 고정 법칙으로 원점을 새로 구성하고 환자·시간·우선순위·문의·작업의 대응을 독립 감사한다.
5. 기존 Recourse 초기 작업·잔여 환자 점수, Followplan 후속 계획, Envelope 대기열 점수 법칙을 동일하게 적용한다. 모든 타당한 행과 기준 행을 같은 법칙으로 계산한다.
6. 모든 현재 점수 대상 환자의 예측 수용 확률이 기준 행보다 기존 허용 오차 `1e−12`를 넘어 낮아지는 행은 제외한다. 허용 행에서는 예측 선정 대기 합의 최솟값 `1e−9` 범위를 먼저 고르고, 기존 우선순위 확률·Stoploss 기준 행·원래 행 순서로 동률을 해소한다.

공개 입력·A/H 경계·FIFO·원자적 적용·전체 환자 변경 감지·실제 자원 검증을 유지한다. 미래 사건·새 환자·실제 작업자 상태·과거 성공 결과나 식별자를 정책에 입력하지 않는다. 예측 확률 보호는 실제 성공 보장이 아니며, 기존 성공 보존은 실행 결과에서 별도로 판정한다.

## 실행 전에 고정하는 조건

성공 보존 기준은 원래 Stoploss의 성공 환자 식별자다. 성공 수가 같더라도 기존 성공을 다른 성공으로 교환하면 통과하지 못한다. 기존·추가 두 자료에서 손실이나 대기 증가를 합쳐 가리지 않는다.

|---|---:|---|
| 기존 827명 | 692 / 113,429초 | 성공 692 이상·대기 113,296초 이하·Stoploss 성공 손실 0명·Stoploss보다 대기 엄격 감소 |
| 추가 415명 | 363 / 54,627초 | 성공 364 이상·대기 53,498초 미만·Stoploss 성공 손실 0명·Stoploss보다 대기 엄격 감소 |

두 자료 존재를 포함한 훈련 조건 9개를 실행 전에 고정한다. 실패 선정 대기는 300초, 실패 도착 비용은 1,800초다. 성공 식별자·선정 대기·도착·개인 최대 지연·혼합/스트레스 구간·후보 확장판 Fullmenu 및 부모 Envelope 대비를 각각 보고한다.

훈련 통과 뒤에만 새 개발 120환경을 실행한다. Stoploss·CS·Hedge 각각 실패 비증가와 대기 엄격 감소, Stoploss 성공 손실 0명으로 7개 조건을 적용한다. 새 개발 통과 뒤에만 별도 검증 368환경을 실행한다. 동일한 점 조건에 세 비교군 각각 실패 차이 95% 상한 0 이하·대기 차이 95% 상한 0 미만을 더해 13개 조건을 요구한다. 시나리오 단위 짝 부트스트랩 10,000회이며 지표별 주변 구간으로 전체 조건의 공동 95% 보장은 아니다.

## 보존과 검증

부모 Envelope 봉인은 `bd5baa58efcd8e40973ab39c47cd23fbddf6e2753d1e8b4d12453a1d489712b6`다. 부모 소스 586개·엄격 참조 3,704개·압축 원문 4,920개를 보존하고 새 소스 16개를 더한 602개를 고정한다. 이전 문서 해시 변경·별도 집계기 복구·연구 기록 정정은 봉인된 이력을 승계하며 원본을 변경하지 않는다.

전체 검사와 고정 예제로 비교군 22개의 전체 원문 동등성을 확인한다. 새 단위 검사는 두 첫 문의 환자와 잔여 환자가 함께 있는 구간, 비활성/작업 없는 잔여 환자, 원점 누락·버전 변경·기준 행 오류 거부, 전체 행 평가·보호·기존 활성 경로·세 명 구간 제외·단독 처리·실제 현재 문의·FIFO를 확인한다. 고정 자연 예제에서 기존 평가와 새 두 명 구간 평가가 모두 실행되고, 잔여 환자가 실제 보호에 포함되는지 감사한다. 이는 기능 검사이며 성능 자료가 아니다.

소스 고정 뒤 새 이름 공간의 입력 명세 848개를 생성한다. 훈련 360환경에서 새 후보를 각각 한 번 실행하고 비교군 22개·7,920분기는 봉인된 결과를 재사용한다. 모든 원문을 저장한 뒤 네 프로세스에서 각 새 원문을 한 번 의미 감사한다. 이후 검사는 원문·소스에 결속된 증명을 재사용하며 부모 원문 감사는 다시 실행하지 않는다. 별도 표준 라이브러리 회계기가 모형·정책·시뮬레이터 없이 결과를 재계산한다. 집계기의 실제 보존 메타데이터 검사도 성능 실행 전에 확인한다.

각 선행 단계를 통과할 때만 해당 새 개발·검증의 23개 정책을 실행한다. 최대 새 실행은 11,584분기다. 단계 실패 뒤 후속 단계를 차단하며 성능 재실행·결과 제외·사후 설정 변경을 하지 않는다. 새 평가·기존 평가·여전히 비활성인 그룹과 실제 선택 변경을 구분해 보고한다. 이전 미평가 150그룹 전체가 새로 활성화된다고 가정하지 않는다.

과거 `docs/README.md` 참조 오류 10건은 실패·추적·원래/현재 해시를 보존한다. 정확히 동일한 검사 ID·오류·해시이고 다른 오류·건너뛰기·소스 변경이 없을 때만 새 고정 자격을 허용하며 전체 검사 통과로 표시하지 않는다. 읽기·해시·단언을 바꾸지 않는다.

모든 성능 환자의 우선순위는 미확인·기본값 4다. 임상 응급도별 효과나 현장 우월성을 주장하지 않는다. 전체 실행·감사·수집 소요시간은 정책 계산시간이 아니다. 운영 서버와 기본 `fixed_3`는 유지한다.

후보 병원이 완전히 없는 두 환자 구간에서는 새 생산 코드의 빈 조합·원점·0건 문의 처리를 별도 합성 검사했다. 다만 봉인된 기존 JOINT 감사기의 `0`과 `0.0` 엄격 타입 비교 때문에 이 경우의 전체 부모 원문 감사는 거부된다. 단언 완화·정규화·건너뛰기를 하지 않았고 전체 감사 통과로 표시하지 않는다. 이번 합성 성능 입력은 병원 수가 양수이고 맞는 진료 분야·병상 10,000개로 시작하므로 첫 문의 후보가 비어 있지 않은 범위다. 이 감사 경계와 정확한 거부 추적은 `diagnosis/legacy-empty-offer-audit-boundary.json`에 보존한다.

## 결과

전체 검사는 102개 모듈·1,869건 중 1,859건이 성공했다. 나머지 10건은 부모에서 보존한 정확히 동일한 역사적 `docs/README.md` 참조 오류이며 실패와 추적을 남겼다. 실행 오류·건너뛰기는 없고 새 검사 129건은 모두 성공했다. 실제 전체 소스 602개는 검사 전후 동일했다. 전체 검사 통과로 표현하지 않는다.

고정 예제에서는 비교군 22개의 전체 원문이 부모와 같았고 새 후보 2개 모두 독립 감사를 통과했다. 자연 예제는 기존 평가 1그룹·새 평가 1그룹·여전히 비활성 2그룹이었다. 새 평가에서 기준 행 1개·잔여 환자 원점 6개·미래 작업 4개를 검사했다. 이 예제의 원래 타당한 조합은 기준 행 하나뿐이라 실제 선택 변경은 없었다. 새 범위와 전체 잔여 환자 보호의 기능 증거이며 성능 개선의 증거가 아니다. 복수 타당 행·선택 변경·환자별 손실 거부는 별도 합성 검사로 확인했다.

독립 표준 라이브러리 회계기의 수치·9/7/13개 조건은 부모와 동일하다. 실제 main의 합성 사전 경로·호출 이름 충돌·23개 변조 거부 검사를 통과했다. 이 사전 검사 시점의 새 모델·정책·감사 검사 파일 3개에는 명시적인 합성 해시를 사용해 실제 소스 고정 증거로 쓰지 않는다. 이후 전체 검사와 고정 예제에서 실제 602개 소스의 동일성을 별도로 확인했다.

별도 집계기는 산술 합성 검사뿐 아니라 **실제 `run` 초기 경로**도 미리 실행해 보존 메타데이터를 확인했다. 실제 보존 파일·참조 수 3,704·현재 602개 소스·실제 비교군 기록과 부모 보고서를 읽었으며, 아직 만들지 않은 동결 기록·360개 인덱스·명세·디렉터리 목록만 합성 자료로 제공했다. 시작 마커 생성 직전에 차단해 원문 읽기·해제·모형·성능 실행은 0회였다. 실제 원문 헤더나 아직 만들지 않은 동결 기록까지 검증했다고 주장하지 않는다. 증거는 `diagnosis/independent-accounting-metadata-prefreeze-review.json`에 보존한다.

### 제한적 후속 진단

실패 결과를 바꾸지 않고 이미 관측한 네 사례만 추가 조사했다. 새 성능 실행·정책 재평가·더 넓은 행 탐색 없이 저장된 점수를 읽었다. 초기 성공 확률이나 CDF 전체를 보호하는 방식은 유익했던 두 사례까지 막지만, 성공 손실 사례는 초기 확률이 오히려 아주 조금 증가해 막지 못했다. 임의의 확률 임계값은 추가하지 않는다.

성공 손실 사례에서는 평균 대기로 초기 확률이 0으로 계산된 기준 병원을 다른 병원으로 교체했다. 다른 지연 사례에서는 같은 경계의 병원을 새로 추가했다. 평균 대기가 남은 H를 넘는다는 모형상의 0은 실제 불가능을 뜻하지 않는다. 별도 후보 Pairshield에서 이 경계의 초기 병원 소속 변경만 제한하는 법칙을 검증한다. 이는 훈련 자료에 근거한 새 가설이며, 해당 선택만 취소하면 결과가 복구된다는 반사실적 성능 주장은 하지 않는다. 이 실험의 소스·결과·실패 판정은 변경하지 않는다. 원문 연구 기록은 `diagnosis/bounded-initial-support-research.json`에 보존한다.
