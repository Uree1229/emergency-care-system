# 팀원용 연결본 실행·테스트 가이드

환자 입력 → 병원 문의 → 추가 질문·답변 → 수용·목적지 확정 → 채팅·출발 → 도착·퇴실을 각자 PC에서 테스트합니다. 병원 역할도 팀원이 직접 조작합니다.

**실제 병원에는 문의·환자 정보·채팅을 전송하지 않습니다.** 실제 서울 병원 20곳의 공개 정보를 로컬에 불러오고, 가상 환자와 업무 기록은 본인 PC의 SQLite DB에 저장합니다.

## 1. 코드 준비

Python **3.11 이상**과 Git을 준비합니다. 처음 받는 경우:

```powershell
git clone --branch codex/team-integration-20261013 https://github.com/Uree1229/emergency-care-system.git
cd emergency-care-system
```

이미 저장소를 사용 중이고 수정 중인 파일이 있다면 별도 폴더로 위 명령을 실행하세요. 아래 명령은 모두 **저장소 최상위 폴더**에서 실행합니다.

## 2. 가장 빠른 실행: 준비된 환자로 테스트

```powershell
python -m server.team_demo --db data/team-demo.db --port 18027 --scenario normal
```

실행 후 브라우저에서 <http://127.0.0.1:18027/public-flow-demo.html>을 엽니다. 시작 페이지에 있는 이송자·병원 화면 링크를 각각 다른 탭으로 여세요. 서버는 이 터미널에서 계속 실행되며 `Ctrl+C`로 종료합니다.

| 항목 | 기본 설정 |
|---|---|
| 가상 환자 | `CAU-E2E-001`, 중앙대학교 서울캠퍼스 발생 |
| 상태·필요 조건 | 22세, 손목 통증·부종, 의식 명료·정상 호흡, 정형외과·응급병상 1자리 |
| 초기 문의 | 중앙대학교병원 `NMC-A1100003`, 문의 대기 |
| 병원 목록 | 서울 5개 구의 실제 기관 20곳 |
| 공공 API 인증키 | 불필요: 저장소의 공개 정보 스냅샷 사용 |
| 추가 Python 패키지 | 이 실행에는 불필요: 표준 라이브러리 서버 사용 |

이송자 화면은 `/patient/?pid=CAU-E2E-001`, 병원 화면은 `/hospital/?hid=NMC-A1100003&pid=CAU-E2E-001`입니다. 병원 담당자 이름에 `가상 담당자`처럼 테스트용 이름을 입력하세요. 로그인 기능은 없습니다.

## 3. 기본 이송 테스트 순서

| 순서 | 조작할 화면 | 조작·확인할 내용 |
|---|---|---|
| 1 | 병원 | 수용 문의에서 `CAU-E2E-001` 선택 → **확인 중** 응답 |
| 2 | 병원 | 추가 질문에 `손가락 움직임을 확인했나요?` 입력 → 전송 |
| 3 | 이송자 | 질문이 표시되는지 확인 → `가상 시연: 움직임 확인됨` 답변 |
| 4 | 병원 | 답변을 확인하고 **수용 가능** 응답 |
| 5 | 이송자 | 수용 응답의 유효기간 안에 **목적지 확정** |
| 6 | 양쪽 | 병원은 **도착 예정 · 이송 대화** 탭에서 환자 선택. 서로 메시지를 보내고 같은 대화방에 표시되는지 확인 |
| 7 | 이송자 | **현재 위치에서 출발 확정** → 이송 중 상태 확인 |
| 8 | 병원 | **환자 도착 확인** → 이송자 상태가 도착으로 바뀌고 채팅이 읽기 전용으로 전환되는지 확인 |
| 9 | 병원 | **퇴실 확인 · 점유 해제** → 퇴실 상태 확인 |

추가 질문·답변은 수용 판단 전의 정형화된 문의 기능입니다. 자유채팅은 목적지가 확정된 병원이 참여한 뒤 사용합니다. 채팅에 “수용합니다”라고 써도 수용 상태는 바뀌지 않으며, 해당 버튼으로 처리해야 합니다.

## 4. 원본 환자 입력 앱부터 시작하기

2번 공통 서버를 실행한 상태에서 **새 터미널**을 열고 같은 저장소 폴더에서 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r emergency-app/requirements.txt
$env:COMMON_API_URL = 'http://127.0.0.1:18027'
$env:EMERGENCY_PROFILE_DB = Join-Path (Get-Location) 'data/team-profiles.db'
.\.venv\Scripts\python.exe -m uvicorn main:app --app-dir emergency-app --host 127.0.0.1 --port 18028
```

1. <http://127.0.0.1:18028/>에서 가상 프로필을 등록하거나 미등록으로 진행합니다.
2. 의식·호흡·증상을 입력합니다. 시연 위치는 위도 `37.5051`, 경도 `126.9573`을 직접 입력할 수 있습니다. 이 값은 중앙대의 **가상 발생 지점**이며 실제 GPS 관측이 아닙니다.
3. 확인된 필요 진료 분야가 선택지에 있으면 직접 선택합니다. 목록이나 필요한 정보가 없으면 미확인으로 전달하고, 임의 진단하지 않습니다. 동의 후 **정보 전송 및 병원 탐색 시작**을 누릅니다.
4. 새 이송 건이 생성되고 공통 서버의 임시 이송자 화면으로 이동합니다. 화면의 환자 ID는 준비된 `CAU-E2E-001`과 별개입니다.
5. 병원 화면에서 그 새 환자의 문의를 선택해 3번의 나머지 과정을 진행합니다.

원본 환자 앱 안의 채팅·이송 진행 UI는 팀원이 통합할 부분입니다. 현재 연결본은 입력 완료 후 임시 `/patient/` 화면으로 이동합니다. 프로필 DB와 공통 이송 DB도 별도로 저장됩니다.

## 5. 조건 변경·목적지 변경 테스트

기본 서버를 종료하고 새 DB로 두 사례를 준비합니다.

```powershell
python -m server.team_demo --db data/team-change-demo.db --port 18027 --scenario both
```

시작 페이지에서 `CAU-CHANGE-001`의 두 화면을 엽니다. 이 사례는 여의도성모병원 `NMC-A1100011`으로 **가상 이송 중**이며, 로컬 정형외과 제한 때문에 재확인이 필요한 상태로 시작합니다. 실제 병원의 수용 응답이나 제한이 아닙니다.

1. 이송자 화면에서 현재 위치를 갱신합니다. 이송 중 대체 문의에는 최근 위치가 필요합니다.
2. 기존 병원 화면에서 영향 사유를 확인하고 판단 메모 입력 후 **조정 필요**를 누릅니다.
3. 시작 페이지·이송자 화면에서 서버가 보낸 대체 문의를 확인합니다. 문의받은 새 병원의 역할 화면을 엽니다.
4. 새 병원에서 **수용 가능**으로 응답합니다.
5. 이송자 화면에서 새 응답을 확인하고 **목적지 변경**을 결정합니다. 기존 목적지가 자동으로 바뀌지 않는지도 확인합니다.
6. 새 병원과 대화 후 도착·퇴실까지 진행합니다. 이전 병원은 새 대화에 참여하지 않아야 합니다.

## 6. 반복 실행·오류 해결

- **기존 환자는 재시작해도 초기화되지 않습니다.** 기본 이송을 반복하려면 새 DB 경로를 사용하거나 `--case-suffix RUN2`를 붙여 `CAU-E2E-001-RUN2`처럼 새 사례를 추가하세요. 조건 변경 사례는 기존 가상 제한과 충돌할 수 있으므로 새 DB 경로를 사용합니다.
- `--scenario empty`는 사례를 새로 만들지 않는 옵션이며 기존 데이터를 삭제하지 않습니다. 완전히 빈 업무 기록으로 시작하려면 사용하지 않은 DB 경로와 함께 실행하세요.
- **포트 사용 중:** 기존 서버를 종료하거나 `--port 18029`로 실행하고 출력된 새 주소를 사용하세요. 원본 입력 앱의 `COMMON_API_URL`도 같은 주소로 맞춥니다.
- **가상 병원만 표시됨:** 이전 광주 시연 서버를 열었을 수 있습니다. 시작 페이지·이송자·병원·입력 앱이 모두 이번 공통 서버 주소를 사용하는지 확인하세요.
- **환자 없음:** DB와 환자 ID가 맞는지 확인합니다. 시작 페이지에 표시된 사례 링크를 사용하세요. `--scenario normal`은 변경 사례를 만들지 않습니다.
- **수용 만료:** 이송자 화면의 후보 병원에서 새 문의를 보내고, 병원이 다시 수용 응답한 뒤 목적지를 확정합니다.
- **대체 문의가 위치를 기다림:** 이송자 위치를 다시 갱신합니다. 목적지는 병원의 조정 판단과 새 수용 확인 후 사람이 변경합니다.
- **원본 입력 앱이 서버 연결에 실패함:** 공통 서버 실행 여부와 `COMMON_API_URL`을 확인합니다. 입력 앱에서 보고 화면을 열기만 해서는 환자나 문의가 생성되지 않습니다.

## 7. 각자 PC와 한 PC 공유의 차이

각자 실행하면 `localhost`가 각자의 PC이므로 DB와 대화방도 별개입니다. 같은 기록을 두 사람이 테스트하려면 같은 네트워크에서 한 명이 공통 서버를 실행합니다.

```powershell
python -m server.team_demo --db data/team-lan-demo.db --host 0.0.0.0 --port 18027 --scenario normal --base-url http://192.168.0.10:18027
```

예시 IP를 서버 PC의 실제 내부 IP로 바꿉니다. 참여자는 그 주소의 `/public-flow-demo.html`을 열고, 원본 입력 앱도 같은 `COMMON_API_URL`을 사용합니다. 방화벽에서 접속이 막힐 수 있습니다. 휴대전화의 일반 HTTP 주소에서는 GPS 권한이 제한될 수 있으므로 시연 좌표를 직접 입력할 수 있습니다. 인터넷 공개 운영용 인증·접근통제 구성은 포함하지 않습니다.

## 8. 검증 기록과 데이터 해석

테스트 후 브랜치·커밋, 실행 명령, 환자 ID, 마지막 상태와 화면 캡처를 남기세요. 기본 흐름·질문/답변·양방향 채팅·목적지 변경·새로고침 복구 중 실패한 단계와 오류 문구도 적습니다.

자동 검사:

```powershell
python -m unittest test_team_demo test_server test_conversations test_transport_review test_transport_reassignment test_patient_commit_bridge -q
```
