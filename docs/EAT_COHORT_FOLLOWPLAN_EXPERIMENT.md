# 첫 문의 환자의 후속 문의 기회를 반영하는 공동 배분

상태: 2026년 10월 22일 훈련 조건 미달로 종료했다. 기존 827명의 목표는 통과했지만 추가 415명의 선정 대기가 CS보다 길었다. 원문 의미·저장 감사와 독립 집계는 통과했다. 새 개발·별도 검증은 실행하지 않았고 운영에 적용하지 않았다. 전체 검사 852개 중 842개 통과·과거 문서 참조 실패 10개 보존의 한계는 아래에 명시한다.

## 목표와 이전 결과

기존 827명에서 CS 대비 성공 순증 3명과 D 대비 대기 78초 단축을 유지하고, 추가 415명에서 CS보다 성공 수가 줄거나 선정 대기가 늘어나는 문제를 개선한다. 이미 관측한 두 자료는 모두 훈련 자료이며 합산해서 한쪽의 실패를 다른 쪽 개선으로 상쇄하지 않는다.

| 훈련 구간 | CS 성공 / 총 선정 대기 | Hedge 성공 / 총 선정 대기 | 직전 Recourse 성공 / 총 선정 대기 | 이번 통과 조건 |
|---|---:|---:|---:|---|
| 기존 240환경·827명 | 689 / 111,858초 | 692 / 113,296초 | 691 / 111,495초 | 성공 692 이상, 대기 113,296초 이하 |
| 추가 120환경·415명 | 364 / 53,498초 | 363 / 54,759초 | 364 / 53,666초 | 성공 364 이상, 대기 53,498초 미만 |

실패한 환자의 선정 대기는 300초로 반영한다. 우선순위·성공 수를 먼저, 대기를 그다음에 줄인다는 기존 원칙을 유지한다. 모든 과거 성공 환자의 개별 성공을 동시에 보존하는 추가 조건은 두지 않으며, 성공 교환은 별도로 보고한다. 도착시간은 선정 대기와 구분하고 실패 환자의 도착 비용은 1,800초로 계산한다.

## 한 가지 계산 변경

직전 계산은 이미 문의 중인 환자에게는 후속 H 문의 계획을 평가했지만, 첫 문의 집단의 환자는 최초 회신 분포 위주로 평가했다. 이 차이를 줄이기 위해 이번 `eat_cohort_followplan_l15_f`는 첫 문의 환자에게도 별도의 가상 후속 계획을 평가한다.

- 원래 최대 세 가지 문의안과 초기 가상 문의의 고정 F0·예상 취소 작업량·q1 계산을 유지한다.
- 초기 문의의 회신 분포를 q1에서 그대로 가져오고, 실제로 캡처한 환자·후보·마감·잔여 문의 한도를 바탕으로 가상의 후속 계획을 만든다. 실제 문의 ID나 DB 버전을 만들어 넣지 않는다.
- 초기 문의를 보낸 병원은 후속 후보에서 제외한다. 원래 공개 후보 전체에서 남은 후보를 다시 정렬하며, 초기 문의 건수만큼 총 문의 예산을 차감한다.
- 최초 재평가 장벽은 현재 문의안 또는 참조 후속 제안의 `next_review_at`에서 가져온다. 추가 문의는 A·H 이전에만 계획하고, 매 문의 시점마다 초기 문의와 앞선 계획을 합쳐 정수 동시 문의 한도 4건을 검사한다.
- 초기 문의와 후속 문의의 회신 분포를 한 번만 합친다. 초기 회신이 없다는 조건을 다시 곱하는 중복 조건부 계산은 하지 않는다. 다른 환자의 후속 가상 문의는 실제 대기열에 예약하지 않는다.

이미 문의한 나머지 환자의 점수는 직전 Recourse와 동일하게 유지한다. 우선순위별 예상 성공 수, 총 선정 대기 순서로 문의안을 고르고 동률이면 원래 Recourse 선택을 유지한다. 실제 문의 송신은 현재 두 환자에 대해서만 실행한다. 실제 동시 문의 한도·총 문의 10곳·A/H·원자적 적용·FIFO·단독 및 후기 H 경로는 바꾸지 않는다.

후속 계획은 공개 정보로 만든 정적 근사다. 실제 미래 회신이나 취소를 미리 아는 계산이 아니며, 후속 계획과 실제 다음 행동이 일치한다는 보장도 없다. 미회신을 가정한 자리 계산은 실제 거절로 자리가 일찍 비는 상황을 보수적으로 평가할 수 있다.

## 사전 검증 계획

이전 소스 458개·참조 812개·압축 원문 2,040개를 고정한다. 새 소스 16개를 더한 총 474개를 검사·동결한 뒤에만 정식 성능을 실행한다. 운영 서버와 기본 정책 `fixed_3`는 변경하지 않는다.

재개 시 다른 작업에서 변경된 문서 목록 `docs/README.md` 한 개를 확인했다. 기존 458개 소스와 나머지 참조 811개는 같았다. 해당 목록은 실행·설정·입력·결과 의존성이 없는 문서이므로 현재 내용을 유지하고, 이전 해시·현재 해시·이유를 새 보존 명세에 명시했다. 최초 보존 명세 원문도 별도로 남겼다. 이전 실험의 소스·결과·감사 기록을 수정하거나 이 문서를 이전 내용으로 복구하지 않았다.

전체 초기 검사 848개 중 838개가 통과했고, 과거 명세에 고정된 문서 해시를 확인하는 기존 검사 10개는 이 변경 때문에 실패했다. 원래 문서의 정확한 사본을 확보하지 못했으므로 해시나 파일 읽기를 대체해 통과시키지 않는다. 모든 검사를 현재 파일로 그대로 실행하고, 이 열 개의 실패와 전체 추적을 실패로 남긴다. 정확히 사전 명시한 검사 ID·문서 경로·오류·구/신 해시에 해당하고 다른 오류·실패·건너뛰기가 없으며, 새 소스·현재 보존 명세·원문 동등성·독립 감사가 모두 유효한 경우에 한해 새 후보 동결 자격을 부여한다. ‘전체 검사 통과’로 표시하지 않으며 최종 회계에도 이 한계를 명시한다. 알고리즘·성능 조건을 바꾼 예외가 아니다.

이 구분을 검사하는 합성 경계 검사 4개를 더한 최종 전체 실행은 852개 중 842개 통과·같은 10개 실패·오류 0개·건너뛰기 0개다. 새 후보의 검사 107개는 모두 통과했다. 최초 실패 기록도 별도로 남겼다. 과거 문서를 대신 읽게 하는 패치나 기대 해시 치환은 최종 검사 코드에 없으며, 전체 검사는 현재 파일로 실행했다.

고정 입력 어댑터 확인에서는 비교군 14개의 원문이 이전 실행기와 같았다. 새 후보의 두 원문 감사도 통과했다. 동시 발생 입력에서는 실제 원자적 처리 4묶음 중 계산한 문의안 3개·첫 환자 후속 계획 18개·미래 동시 점유 검사 20개를 확인했다. 이는 기능 경로 검사이며 새 성능 자료나 튜닝 결과가 아니다.

1. 훈련 360환경에서 이번 후보 분기 360개를 한 번씩 실행하고 봉인된 비교군 14개·5,040분기를 재사용한다. 모든 원문을 저장·감사한 후 위의 두 구간별 조건을 모두 검사한다.
2. 통과할 경우에만 새 개발 120환경에서 15개 정책을 비교한다. CS와 Hedge 각각에 대해 실패 비증가와 총 선정 대기 감소를 모두 요구한다. Recourse는 별도 비교 대상으로 보고한다.
3. 새 개발도 통과하면 별도 검증 368환경을 실행한다. 동일 점 조건과 함께 CS·Hedge 각각에 대한 실패 차이의 95% 상한이 0 이하, 대기 차이의 95% 상한이 0 미만이어야 한다. 시나리오 단위 짝 부트스트랩 10,000회, 지표별 주변 95% 구간이며 네 조건의 공동 95% 보장은 아니다.

새 개발·검증의 역할 난수는 소스 동결 후 생성한다. 과거 실행 자료뿐 아니라 생성만 했던 미실행 명세의 난수도 재사용하지 않는다. 단계 실패 이후 성능 실행은 차단한다. 결과 제외·성능 재실행·새 자료를 본 뒤 같은 후보의 설정이나 조건을 바꾸는 작업은 하지 않는다.

독립 감사는 보존한 Recourse의 공개 입력·가상 대기열·회신 분포 증명을 먼저 검사하고, 가상 후속 계획의 출처·재평가 장벽·예산·매 시점 동시 문의·최종 선택을 별도로 계산한다. 실제 모든 환자의 FIFO 결과도 검사한다. 이후 저장 감사는 정확한 원문·소스 해시에 결속한 의미 증명을 재사용한다. 최종 표준 라이브러리 회계기는 정책·시뮬레이터를 호출하지 않고 성공·대기·도착·개별 성공 교환과 단계 조건을 재계산한다.

합성 입력의 환자 우선순위는 모두 미확인·기본값 4다. 임상 응급도가 다양한 실제 상황에 대한 우월성 주장은 하지 않는다.

## 결과

동결 후 훈련 환경 360개에서 새 후보 분기 360개를 한 번씩 실행했다. 모든 원문 저장 후 의미 감사를 마쳤고, 저장 감사에서는 같은 원문·소스 해시에 결속한 의미 증명을 재사용했다. 결과 제외·성능 재실행은 없었다. 별도 표준 라이브러리 집계는 새 원문 360개를 한 번씩 해제해 검사했으며 공식 보고서의 모든 구간·성공·대기·도착 지표와 네 비교군의 개별 성공 교환까지 일치했다.

|---|---:|---:|---:|---:|
| 기존 827명 | 689 / 111,858초 | 692 / 113,296초 | 691 / 111,495초 | **693 / 113,163초** |
| 추가 415명 | 364 / 53,498초 | 363 / 54,759초 | 364 / 53,666초 | **364 / 54,712초** |

기존 구간은 CS 대비 성공 순증 4명으로 3명 유지 목표를 넘겼다. D의 691명·113,374초와 비교하면 성공 2명 증가·대기 211초 단축이며, 요청한 78초 단축도 유지했다. Hedge보다 성공 1명 증가·대기 133초 감소했다. 다만 직전 Recourse보다 성공이 2명 늘면서 총 대기도 1,668초 늘었다. 기존 두 통과 조건은 모두 충족했다.

추가 구간은 CS와 성공 수가 같지만 대기가 1,214초 길다. 직전 Recourse보다 1,046초 증가했고, Hedge보다 47초 짧은 수준이다. 성공 조건은 통과했으나 대기 감소 조건은 실패했다. 두 구간을 합산해 이 실패를 상쇄하지 않는다.

### 변화가 생긴 위치

기존 혼합 695명은 성공 567명·대기 100,821초로, CS보다 성공 4명 증가·대기 416초 단축이었다. 하지만 스트레스 132명은 12,342초로 CS·Recourse보다 1,721초 길어져 Hedge 수준의 초과 대기가 재발했다.

추가 혼합 349명은 성공 301명·대기 48,582초로 CS와 성공 수가 같고 대기가 520초 길었다. 스트레스 66명은 6,130초로 CS보다 694초 길었다. 새로 대기가 늘어난 혼합 환경 244·269의 차이는 각각 221초·238초이며, 환경 307에서는 107초가 줄었다. 환경 291의 +218초와 297의 −50초는 직전과 같다. 번호는 이번 원장의 0부터 시작하는 인덱스다.

이후 읽기 전용 진단에서 장기 계획을 다음 한 시점으로만 자르는 방안을 검토했으나, 스트레스 악화 경로의 주요 재문의는 이미 15초에 계획돼 있었고 기존 추가 성공에는 45초 계획도 있어 채택하지 않았다. 더 직접적인 한계는 여러 환자의 후속 계획이 같은 병원에 몰려도 서로의 가상 작업량을 반영하지 않는다는 점이다. 이 후보의 소스·계획·조건은 수정하지 않으며 이를 반영하는 작업은 별도 후보로 진행한다.

### 개별 성공 교환과 도착시간

- 기존 구간은 CS 성공 손실 없이 4명을 추가 성공시켰다. 직전 Recourse의 기존 성공도 모두 보존하면서 환경 185의 P01·P06을 각각 254초·101초에 추가 성공시켰다. Hedge와 비교하면 기존 성공 2명 손실·추가 성공 3명의 교환이 있다.
- 추가 구간은 CS 기존 성공 3명 손실·추가 성공 3명이다. 환경 291의 P06·P07과 환경 307의 P02를 잃었고, 환경 297의 P03·P07과 환경 307의 P03을 추가 성공시켰다. 성공 수가 같다는 말은 기존 CS 성공 환자 전원을 보존했다는 뜻이 아니다.
- 기존 환자당 도착 비용은 839.933초로 CS보다 4.930초 짧다. 추가 구간은 824.773초로 CS보다 5.369초 길다. 두 정책 모두 선정한 환자 중 CS 대비 최대 도착 지연 증가는 기존 307초, 추가 607초다. 선정 대기와 도착 개선을 혼동하지 않는다.

실제 `execute('development')` 호출 차단 검사에서도 훈련 조건에 의해 `verify_prior`에서 중단됐다. 작업 생성·실행기·시뮬레이터 호출은 모두 0회다. 새 개발·검증 원문이나 결과는 없으며 이번 후보는 채택하지 않았다. 감사의 무결성 통과와 후보 성능 통과는 별개다.
