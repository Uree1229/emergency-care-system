# 음성 앱–서버 연결 검증

후속 작업 완료: [환자정보 적용 보완·356개 회귀·가상 병원11단계](VOICE_PATIENT_LINK_VERIFICATION_20261030.md). 아래는 최초 초안 연결 검증 기록이며, 후속 작업은 별도 검증 폴더에 보관했다.

2026-10-30. Codex 담당은 서버와 서버 검증이다. Claude 담당인 `paramedic-ui/`는 읽기 전용으로 확인했고 수정하지 않았다. 실제 환자정보·마이크·외부 STT·병원 문의는 사용하지 않는다. 기존 시연 DB의 실제 음성 시험 기록도 이 검증에 덮어쓰지 않는다.

## 검증한 범위

앱의 실제 `VoiceClient` 모듈을 읽기 전용으로 불러와 별도 임시 DB·로컬 HTTP 서버에서 아래 12단계를 실행했다. UI 버튼을 조작한 시험과 구분한다.

1. 음성 초안 생성.
2. 긴 최종 인식문 한 건 전송 → 누락 질문 5개 생성.
3. 의식·호흡·혈압·맥박·호흡수에 짧게 답변 → 질문 해소.
4. “혈압이 지금 100에 80까지 떨어졌어” → 새 관찰과 이전 값 보존.
5. “혈압 110에 70으로 수정해” → 정정 이력과 혈압 읽어주기.
6. 음성 확인 안내 → 별도 화면 확인 API.
7. 수치 없는 변화 보고 → 이전 값 보존·재확인 질문·기존 확인 해제.
8. 미측정 답변 취소 → 재확인 상태 복원.
9. 미측정 후 새 측정값 취소 → 이전 미측정 답변 상태 복원.
10. 저장 성공 뒤 응답을 잃는 상황 → 같은 요청 재시도·중복 반영 없음.
11. 다른 클라이언트가 수정한 뒤 오래된 버전 쓰기 → 409·덮어쓰기 없음.
12. 최종 확인 뒤 재조회 → 값·확인 상태 보존, 환자 등록·병원 문의 0건.

결과: `.codex-build/voice-connection-20261030/client-flow-v1/report.json`, `client-report.json`. 12단계 통과, 실행 전후 관련 소스 해시 일치. 실제 음성 정확도·현장 입력시간을 측정한 결과가 아니다.

최종 서버·음성·평가 도구 회귀 **174개 통과**, 실행 전후 소스 해시 일치. 추가된 HTTP 통합 6개와 상태·취소 경계 8개도 포함한다. 기존 시연 서버18032에 수정 코드를 반영했고, 재시작 전 SQLite 백업을 보관했다. 환자·문의·음성 세션·발화·이력·요청·미측정 상태 테이블 전체를 백업과 비교해 기존 데이터가 같음을 확인했다. 상세는 `.codex-build/voice-connection-20261030/live-health.json`이다.

## 발견해 수정한 서버 문제

| 문제 | 원인 | 수정 |
|---|---|---|
| 미측정 답변을 취소하면 이전 변화 보고까지 잘못 취소 | 수치가 없는 답변은 undo 대상에서 제외됨 | 질문 상태가 바뀐 답변도 취소 이력에 포함 |
| 측정값 취소 후 이전 미측정 상태가 사라짐 | 값·메타데이터와 미측정 상태 테이블이 별도로 관리됨 | 미측정 상태를 revision 메타데이터에도 보관하고 DB 상태를 원자적으로 동기화. 기존 기록도 읽을 때 호환 |
| 올바른 증상 답변 뒤에도 계속 재질문 | 증상 있음/없음 대안 필드에 오래된 질문 표시가 남음 | 해당 질문에서 생성한 대안 필드 표시만 해소. 다른 실제 미확인 증상은 계속 질문 |

추가로 혈압 한쪽만 입력하면 나머지 값을 계속 묻고, 다른 질문의 미측정 상태를 유지하며, 응답 생성 도중 실패하면 값·질문 상태·이력 모두 롤백되는 것을 확인했다.

현재 연결 수정 버전은 `/api/voice/capabilities`의 `connection_revision: "voice-connection-20261030-v1"`로 확인한다. 기본 `voice_revision`과 기존 API 요청 형식은 유지한다.

## Claude에게 남겨둘 화면 연결 항목

아래는 읽기 전용 감사 시점의 상태다. 이후 Claude 작업으로 달라질 수 있다. 이 문서가 프론트 수정을 대신하지 않는다.

| 연결 항목 | 확인 위치·현재 상태 | Claude 작업 |
|---|---|---|
| 긴 문장 묶음 | quick 화면은 final 조각을 모으지만 본 앱 `app.js`는 조각별 전송 | 본 앱의 긴 발화 종료 처리 연결 |
| 자동모드 | `quick-session.mjs`가 auto를 허용하지 않고 기존 UI는 dictation/command만 선택 | 무전기 입력과 `mode:auto` 연결 |
| 누락 질문 | `/followup`, `/followup/answers` 호출이 아직 없음 | 질문 ID·제시 버전 저장, 질문 표시·TTS·짧은 답변 전송 |
| 재확인 중인 이전 값 | `needs_clarification` 표시 코드가 없음 | 현재 값으로 확정된 것처럼 보이지 않도록 이전 관찰·재확인 상태 표시 |
| 새 관찰·질문 피드백 | 본 앱의 commandFeedback가 observe/missing을 제외 | 새 응답 종류와 `latest_changes` 표시 |
| 화면 확인 | 본 앱은 confirm 호출, quick 화면에는 확인 버튼 없음 | 자동모드 `confirmation_requires_tap` 흐름 연결 |
| R1 선택 필드 | AVPU·주증상 등 새 enum을 숫자 input으로 만드는 경로가 있음 | 적절한 선택 입력으로 표시하고 의도하지 않은 unset 방지 |

서버 시험 통과를 현재 프론트의 전체 연결 완료라고 표현하지 않는다. 앱에 연결한 뒤 실제 마이크와 화면으로 별도 확인해야 한다. 재시도는 요청 ID·발화 ID·본문·버전을 그대로 유지하고, 409는 최신 세션·질문을 읽어 다시 검토한다.

## 다시 실행

Node가 PATH에 있으면:

```powershell
python -m server.voice_connection_check
```

없으면 Node 실행 파일 경로를 지정한다. 결과 디렉터리는 기존 결과를 덮어쓰지 않는 새 경로여야 한다.

```powershell
python -m server.voice_connection_check --node "C:/path/to/node.exe" --output "outputs/voice_connection/new_run"
```

서버 회귀 검사는 `test_voice_connection_http.py`, `test_voice_connection_edges.py`를 포함한다. 테스트용 SQLite 임시 디렉터리와 loopback 소켓 접근이 가능한 환경에서 실행한다. 상세 실행 기록은 `.codex-build/voice-connection-20261030/server-verification.json`, `server-verification.log`에 보관한다.
