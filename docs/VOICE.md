# 음성 입력과 자료 수집

2026-11-05 기준. 저장소 기능과 별도 로컬 음성 작업의 적용 범위를 표시한다. 실제 실행본의 주소와 버전은 기동 결과에서 확인한다.

## 화면과 처리 경로

| 경로 | 용도 |
|---|---|
| `/paramedic/` | 상세 입력·검토, 위치·필요 치료조건 확인, 환자 등록과 병원 연결 |
| `/paramedic/quick-test.html` | 대화형 상태 기록, 확인 질문, 토글·음성 명령, 환자별 임시 기록과 인계 요약 |
| `/paramedic/command-practice.html` | 대본 낭독·명령 판정 연습, 인식문·정답·시험 조건·선택적 원음 수집 |
| `/paramedic/evaluate.html` | 고정 개발 대본을 사용하는 인식 결과 수집 |
| `/paramedic/noise-compare.html` | 별도 로컬 음성 작업에 있는 원본/RNNoise 비교 화면 |

기본 경로는 브라우저 `SpeechRecognition`/`webkitSpeechRecognition`의 한국어 인식문을 `server/voice_terms.py`, `server/voice_r1.py`, `server/voice_input.py`의 규칙과 검토된 용어사전으로 구조화한다. 상세 화면에는 Azure 변환 경로와 로컬 시험용 WAV 녹음도 있다. Azure 사용 여부는 서버 capabilities의 설정 상태를 확인한다. 로컬 WAV 모드는 파일을 보관해 별도로 평가할 때 사용한다.

참고 진단·상병 용어 검색과 실행용 증상 동의어는 분리돼 있다. 사전에 명칭이 있다는 이유만으로 진단·응급도·치료조건을 채우지 않는다. 원문과 항목 근거, 명시적 관찰, 규칙에서 파생한 제안을 구분해 검토한다.

발표용 4단계 통합 구급대 화면과 병원 어댑터 오류 대조는 로컬 `.codex-build/hospital-full-demo-20261105/`의 고정 소스 실행본에 있다. Git 기본 화면과 이 실행본의 배포 범위를 혼동하지 않도록 실행본 manifest를 기록한다.

## 기록·명령·확인

간편 화면은 한 번 눌러 시작하고 다시 눌러 마치는 토글과 누르는 동안 말하기를 제공한다. 현재 상한은 토글 180초, 누르는 동안 말하기 30초다. 직접 입력도 보내기 버튼을 눌러 같은 초안에 반영한다.

| 명령 예 | 처리 |
|---|---|
| `중단`, `녹음 종료`, `그만` | 앞의 확정 본문을 저장하고 녹음을 마침 |
| `병원 추천해줘` | 앞 내용을 저장한 뒤 검토·추천 준비로 연결 |
| `새 환자 시작`, `이전 환자로 돌아가` | 지원하는 명령을 확인한 뒤 환자 기록 전환 |
| `병원 인계 요약해줘` | 저장된 구조화 내용의 인계 초안 미리보기 |
| `혈압 읽어줘`, `맥박 92로 수정해줘`, `방금 입력 취소` | 선택한 입력 모드와 지원 문법에 따라 조회·정정·되돌림 |

명령을 포함한 발화에서는 첫 유효 명령 앞 내용을 먼저 저장한다. 명령 뒤 문장과 늦게 확정된 발화는 원래 환자의 미반영 항목으로 보존한다. 저장 결과가 불확실하면 원래 요청 ID·본문·버전으로 결과를 확인한 뒤 후속 동작을 진행한다.

`종료 시각`, `종료하지 마`, 인용·간접 보고와 처치 설명은 명령과 구별한다. 명령 연습 화면의 기본 후속 문맥 대기 800ms는 실험 설정이다. 간편 입력 화면의 같은 게이트 연결은 별도 로컬 음성 작업에 있다. 새 확정문이 들어오면 후보를 다시 판단하고 임시 인식이 남으면 실행을 보류한다. VAD·EOT 모델과 LocalAgreement 방식 연속 재인식의 도입은 추가 과제다. 지원 문법과 경계 조건은 `paramedic-ui/recording-control.mjs`, `command-commit.mjs`와 해당 테스트를 기준으로 확인한다.

중요 수치와 증상 극성은 복창·검토 대상으로 표시한다. 없음, 미확인, 미측정, 미기록, 이전 관찰값을 구분한다. 알아듣지 못한 답변은 원문을 보류하고 정상값이나 0으로 채우지 않는다. 혈압·증상 부정 처리 수정은 기존 인식문을 다시 해석하는 기능이며 실제 STT가 전달한 원문은 유지한다. 환자 등록·병원 문의·목적지 확정에는 화면의 명시 동작이 필요하다.

## 환자별 저장과 복구

간편 화면은 환자별 초안 참조, 확정 인식문·직접 입력의 미반영 부분, 결과 확인 대기 요청을 브라우저에 임시 보관한다. 자동 복원 유효기간은 마지막 저장부터 12시간이다. 서버의 작성자·초안·상태·버전을 GET으로 확인한 뒤 이어가며, 미반영 문장은 다시 검토한다. 새 환자를 시작해도 이전 환자의 복구본은 목록에 남는다.

연결·저장 안내는 브라우저 임시 보관과 서버 저장 확인, API 오류와 음성 인식 오류를 구분한다. 다른 환자나 서버로 전환하는 동안 늦게 도착한 응답을 새 환자에게 적용하지 않는다. 원래 요청의 결과가 불확실하면 새 요청을 만들기 전에 동일 요청을 재확인한다. 브라우저 저장 공간·다른 원점·탭 동시 변경의 한계도 화면 안내를 따른다. 간편 화면의 저장 계약은 `draft-recovery.mjs`, `patient-records.mjs`에 있다. 상세 화면의 `main-recovery.mjs` 보완은 별도 로컬 작업이므로 해당 변경을 포함한 실행본에서 확인한다.

간편 초안 복구는 원본 음성을 보관하지 않는다. 원음은 아래 연습 수집에서 별도로 선택해 저장한다. 공용 브라우저에서는 작업 후 선택한 환자의 임시 복구본을 정리한다.

## 병원 인계

인계 요약은 저장된 구조화 관찰을 고정 템플릿으로 정리한다. 부정·불확실·이전 관찰과 미반영 내용의 존재 여부를 표시한다. 원문 자유 메모를 확인된 관찰로 바꾸지 않으며, 새 관찰·입력 정정·되돌림을 구분한다.

생성·복사·읽기 전에 같은 환자와 버전인지 확인한다. 요약 생성 후 원천 기록이 바뀌면 다시 생성한다. 별도 통합 실행본의 인계 교환 화면은 같은 환자의 저장본·질문·답변·병원 재진술을 연결한다. 공유된 버전과 작성자를 함께 확인하고 미리보기 검토 뒤 별도 공유 동작을 수행한다. Git 기본 화면의 로컬 요약과 배포된 인계 교환 기능은 실행본의 링크와 API capabilities로 확인한다.

## 연습 자료 수집

1. 합성 대본 또는 자유 발화를 선택하고 가명 화자·장비·소음·마스크·거리·짝 비교 ID를 기록한다. 측정하지 않은 조건은 비워 둔다.
2. 말하기 시작과 마치기로 한 시도를 수집한다. 원본 녹음 보관을 선택하면 같은 시도의 인식문·정답·조건과 연결해 저장한다. 무인식·오류·중단도 남긴다.
3. 실제로 말한 내용과 대본이 같은지 확인하고 독립 정답을 검토한다. 자동 판정에 맞춰 정답을 바꾸지 않는다. 수동 모의 입력은 실제 마이크 시도와 구분한다.
4. 음성 포함 ZIP을 내려받아 `dataset.json`, `manifest.json`, 음성 파일의 포함·누락·해시를 확인한다. JSON/CSV만으로 원음이 복구되지는 않는다.

기본 제공 자료에는 긴 복합 문장을 포함한 합성 대본 96개가 있다. 명령 없는 문장, 수치·부정·인용·시간 표현, 진짜 명령을 함께 시험한다. 원음은 IndexedDB와 실제 확보한 파일을 대조하며 부분 녹음·메모리 보관·저장 실패·누락을 표시한다. 브라우저 저장은 장기 백업을 대신하지 않으므로 ZIP의 실제 파일을 확인한다.

## 소음 비교와 평가 범위

상세 녹음 화면은 소음 억제·반향 제거·자동 이득의 요청값과 기기가 보고한 적용값을 구분한다. 브라우저 STT의 내부 오디오 전처리는 브라우저가 제어하는 부분이 있다.

별도 로컬 RNNoise 비교 화면은 한 원음을 공통 48kHz 모노 PCM으로 변환한 뒤 A와 처리본 B를 만든다. 동일 STT 엔진·설정으로 얻은 두 인식문을 독립 정답과 비교한다. 원본·A/B WAV·메타데이터 ZIP을 보관한다. 이 화면의 처리본을 기본 브라우저 STT에 자동 연결하는 흐름은 별도 적용 상태를 확인해야 한다.

기존 실제 인식문 13건 재처리의 전체 일치 6→8건은 로컬 파서 수정의 과거 개발 결과다. 해당 파서 변경은 문서 정리와 별도 작업으로 관리한다. 같은 인식문을 재사용했으므로 새 사람·새 발화의 인식 정확도 향상으로 계산하지 않는다. 합성 TTS·혼합 잡음의 RNNoise 비교도 실제 한국어 현장 소음 시험과 분리한다.

새 발화는 원음을 확보하고 같은 화자·대본·장비에서 조건 하나씩 바꿔 수집한다. CER/WER 외에 중요 수치·부정 극성·명령 오탐과 수정·확인까지의 시간을 평가한다. 검증 명령과 실제 환경의 남은 측정은 [테스트 안내](TESTING.md)에 정리했다.
