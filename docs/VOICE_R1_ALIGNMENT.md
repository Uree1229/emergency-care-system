# 서버 음성 입력 API의 R1 맞춤 목록

작성일: 2026년 10월 30일 · 상태: **반영 완료(10-30 오후, 0절)**. 처음 작성할 때는 제안이었다 · 대상: [`server/voice_terms.py`](../server/voice_terms.py), [`server/voice_input.py`](../server/voice_input.py), [`config/paramedic_voice_terms.json`](../config/paramedic_voice_terms.json) · 근거: [R1 최소 입력 항목](R1_MINIMUM_INPUT.md), [음성 초안 시제품](VOICE_INPUT_PROTOTYPE.md)

Codex가 만든 서버 음성 API는 세션·확인·전송 흐름, 원문 근거, 변경 이력을 갖춘 운영 경로다. 이 문서는 그 API를 R1 입력 항목에 맞추기 위해 바꿀 것을 정리한다. 같은 문장으로 두 추출기를 비교한 결과를 근거로 들었다.

## 0 반영 결과(2026-10-30 오후)

**구현한 것.** `voice_terms.extract`의 결과는 바꾸지 않았다. 세션에 반영하는 단계에서 R1 칸을 더하는 방식이다.

- **새 모듈 [`server/voice_r1.py`](../server/voice_r1.py):** R1 칸 13개를 추출·검사·읽어 주기·제출 변환한다.
  - 질문·과거력·정정 문장은 서버와 같은 기준으로 건너뛴다.
  - 같은 칸에 서로 다른 값이 나오면 채우지 않고 경고한다. 의식 표현이 서로 다르면 기존 의식 상태도 비운다.
  - 불확실 표현에서는 AVPU·호흡·등급·2차 고려사항을 넣지 않는다. 주증상만 약한 후보로 쓴다.
- **`voice_terms.py`:** A1 할머니·할아버지 오인 수정('할아버지' 안의 '아버지' 포함), A3 '이십'·'아흔둘' 수 읽기, A4 BP 약어, A5 명령 변형과 '빠진 칸' 명령, R1 칸 검사·읽어 주기
- **`voice_input.py`:** 세션 반영·미리보기·수정 명령에 R1 칸 추가, AVPU↔의식 상태와 나이↔연령 구분 맞춤
- **빠진 칸 명령:** 빠진 R1 필수 칸만 읽어 준다.
- **제출 변환(4절):** 우선순위, `extra`의 R1 키, 새 환자의 진료 프로필. 앱이 진료 요구를 명시하면 자동 프로필을 쓰지 않고, 기존 환자의 진료 요구는 바꾸지 않는다.
- **첫 문의 차단:** `start_inquiry`일 때 필수 5칸이 비면 409 `R1_FIELDS_REQUIRED`
- **카탈로그:** v1.1.0. R1 칸, HR·RR·BST·새츄 별칭 추가
- **Codex 테스트 수정:** 첫 문의를 시작하는 2개만 받아쓰기 문장에 R1 필수 칸을 넣었다.

**검사.**
- 음성 테스트 92개 통과: 새 `test_voice_r1` 12개, Codex 음성 테스트 67개, `test_voice_lab` 13개
- 관련 서버 테스트 30개 모듈 759개 통과
- 솔버(OR-Tools)가 필요한 4개 모듈은 이 PC에서 실행 불가

**정확도(잠금 후 1회).** [보고서](../simulation_results/voice_server_r1_validation_20261030.md), 처음 쓰는 검증 문장 v2 40개.

|---|---:|---:|
| 칸 재현율 | 86.7% | 88.9% |
| 칸 정밀도 | 99.2% (틀림 1) | 97.6% |
| 필수 5칸 재현율 | **92.9%** | 88.1% |

**남은 문제(다음 개선 후보).** 이 검증 문장은 이제 공개됐으므로, 고친 뒤에는 새 검증 문장으로 다시 잰다.
1. **[반영 완료, 10-30] 문장 단위 불확실·대략값 판단:** 서버는 쉼표로 이어진 문장 전체를 한 단위로 봤다. 그래서 '발음 이상'의 '이상'을 대략값으로, '임신 가능성'을 불확실로 보고 같은 문장의 나이·혈압·발생 시각·의식까지 버렸다(v01·v36·v37).
   - **고친 것:**
     - 불확실·대략값 판단을 그 표현이 있는 쉼표 구간에만 적용한다.
     - '이상·이하·미만·에서'는 수에 붙을 때만 대략값으로 본다.
     - 과거력·질문도 해당 구간만 뺀다. 가족이 주어이면 '환자·본인·이번·현재·지금'이 나올 때까지 뒤 구간도 뺀다(Codex 테스트의 '어머니는 70세 흉통, 기침' 유지).
   - **효과:** 수정 전에 고정한 새 검증 문장 v3 40개로, 수정 전·후를 각각 잠금 후 1회 쟀다([전](../simulation_results/voice_server_scope_before_20261030.md), [후](../simulation_results/voice_server_scope_after_20261030.md)).

     | v3 40개 | 수정 전 | 수정 후 | voice_lab v1(참고) |
     |---|---:|---:|---:|
     | 칸 재현율 | 63.2% | **92.4%** | 94.1% |
     | 칸 정밀도 | 97.5% | **98.3%** | 92.6% |
     | 문장 완전 일치 | 16/40 | **31/40** | 25/40 |
     | 필수 5칸 재현율 | 78.9% | 91.7% | 92.7% |
     | 활력징후 재현율 | 33.3% | 96.5% | 100% |

   - **검사:** 음성·서버 테스트 36개 모듈 853개 통과
   - **v3에서 남은 실패:** '추정'이 붙은 구간 안의 나이('8세 여아 … 기도 폐쇄 추정'), '60세 이상으로 보이는'·'30대 추정'에서 연령 구분을 못 정함, 임신 중 복통·질 출혈을 복통으로 고름, 약한 후보끼리면 '기타'보다 구체 묶음을 우선하지 않음('고열, 경련 의심'), '마지막 정상 1시간 전'을 발생 시각으로 쓰지 않음, '벌 쏘임' 어휘, 가족 주어 문장('어머니가 가슴이 아프다고…')
1-2. **[반영 완료, 10-30] v3에서 남은 실패 수정**
   - **서버 추출기(`voice_terms`):**
     - 불확실·대략값 판단 범위를 쉼표 구간에서 **값 주변**으로 좁혔다. 뒤에 붙는 표현은 값 끝에서 10자 안, '대략·약'은 값 앞 10자 안만 본다. 쉼표가 빠진 인식문 대비다.
     - 쉼표 뒤의 '의심·없음'이 앞 증상을 꾸미지 않게 했다('흉통, ST 상승 의심').
     - '마지막 정상 ○시간 전'과 R1 주증상 + '부터'를 발생 시각으로 쓴다.
     - BT·PR·열·혈당 체크 별칭을 추가했다.
   - **R1 모듈(`voice_r1`):**
     - 같은 값 주변 범위 규칙을 쓴다.
     - 주증상은 불확실 표현이 붙어도 후보로 둔다. 약한 후보끼리면 '기타'보다 구체 묶음을 고른다.
     - 임신 중 복통에 출혈이 함께 있으면 산과로 고른다.
     - 대략값 나이라도 15세에서 먼 경우(20세 이상, 10세 이하, 20대 이상)는 연령 구분을 정한다.
     - 'STEMI 의심'은 '예'로 넣는다(다른 불확실 표현은 제외). 쉼표 너머 '경련 … 멈춤'도 인식한다.
     - '비응급·준응급'을 단독으로 말해도 등급으로 읽는다. 어휘(미끄러짐·찰과상·벌 쏘임·숨쉬기 힘듦)를 보강했다.
   - **효과:** 수정 전에 고정한 새 검증 문장 v4 40개(쉼표 없는 문장 포함)로, 수정 전·후를 각각 잠금 후 1회 쟀다([전](../simulation_results/voice_server_round3_before_20261030.md), [후](../simulation_results/voice_server_round3_after_20261030.md)).

     | v4 40개 | 수정 전 | 수정 후 | voice_lab v1(참고) |
     |---|---:|---:|---:|
     | 칸 재현율 | 83.2% | **98.8%** | 93.8% |
     | 칸 정밀도 | 98.5% | **100%** (틀림 0) | 98.1% |
     | 문장 완전 일치 | 24/40 | **37/40** | 30/40 |
     | 필수 5칸 재현율 | 87.2% | 98.9% | 92.6% |

   - **v4에서 발견해 바로 고친 것(새 문장으로는 아직 검증 전):** 이 3건은 위 수치에 들어 있지 않다.
     - '넘어짐'의 '넘어'를 대략값('100 넘어')으로 보고 같은 구간의 나이를 지우던 문제. '넘어·넘음'도 수에 붙을 때만 대략값으로 본다.
     - 명령 '입력 내용 읽어줘'·'이제 보내 줘'
   - **검사:** 음성·서버 테스트 36개 모듈 855개 통과
   - **이 수치의 한계:** 문장 작성자가 추출기 작성자와 같다. 실제 구급대원 발화와 음성 인식 오류로 다시 재야 한다.
2. **'STEMI 의심'을 ST 상승 미확인으로 버림(v33):** 칸 이름 자체가 '의심'이므로 예외로 둔다.
3. **어휘 보강:** '열 39도'(체온), PR·BT 약어, '미끄러져'(외상), '힘듦'(호흡곤란), '비응급'(등급), '혈당 체크 결과 38'
4. **명령의 자유로운 표현:** 앱이 명령 모드를 고르면 영향이 작다. 자동 판단을 쓰려면 voice_lab처럼 부분 일치로 넓힌다.
5. **R1 13절 3번(행정 정보 보완 시 수용 유지):** 아직 반영하지 않았다. 환자 버전이 오르면 기존 수용이 `usable: false`가 되므로, 버전 규칙까지 함께 설계해야 한다.

[비교 보고서](../simulation_results/voice_compare_server_20261030.md) · 잠금 `voice_compare_server_20261030_lock.json`. 두 추출기 모두 수정하지 않고 한 번 실행했다.

| 검증 문장 40개, 공통 칸 100개 | 서버 추출기 | voice_lab |
|---|---:|---:|
| 재현율 | 50.0% | 78.0% |
| 정밀도 | 87.7% (틀림 7) | 97.5% (틀림 2) |
| 명령 문장(되돌리기·다시 읽기·빠진 칸·전송) | 0/4 | 4/4 |
| R1 전용 칸(37개, 전체 기대 칸의 27%) | 미지원 | 37/37 |

서버 추출기에는 개발 문장 43개도 처음 보는 문장이다. 거기서도 재현율 56.0%, 정밀도 93.3%였다.

**이 비교는 voice_lab에 유리하다.** 개발·검증 문장을 voice_lab 작성자가 써서 말투가 voice_lab 사전에 가깝다. 수치 차이보다 아래 2절의 **원인이 분명한 문제**를 근거로 삼는다.

## 2 서버 쪽에서 원인이 분명한 문제

| 번호 | 문제 | 예(문장 ID) | 제안 |
|---|---|---|---|
| A1 | '할머니·할아버지'를 가족 정보로 보고 문장 전체를 버림 | "할아버지가 갑자기 왼쪽 팔다리에 힘이 없고…"(h02) | 가족어 단독이면 환자 지칭으로 본다. '과거·병력·예전'과 함께일 때만 과거력으로 처리 |
| A2 | 받아쓰기 문장에 '수정'이 섞이면 전체를 비움 | "환자 정보 수정할게요 혈압은 110에 70"(h09) | 받아쓰기에서도 정정어 뒤의 값을 수정 제안으로 처리하거나 자동으로 수정 명령으로 넘김 |
| A3 | 한국어 수 읽기 오류 | "호흡수 이십" → 10(h08), "산소 포화도 아흔둘" → 90(h15) | 한자어·고유어 수 변환 보완 |
| A4 | 영문 약어 미인식 | "BP 90/50 HR 130"(h07) | BP·HR·RR·SpO2·GCS·BST 별칭 추가 |
| A5 | 명령을 고정 문장으로만 인식 | "아까 말한 거 되돌려", "다시 불러줘", "보내 주세요" | 정규식 기반 명령 인식, '빠진 칸 알려 줘' 추가 |
| A6 | 구급 현장 어휘 부족 | 교통사고·추락·골절·부딪힘(외상), 편마비·구음장애·안면마비(뇌졸중), 농약·약물 과다(중독), 진통·양수(분만), 심정지·CPR | voice_lab 사전([`voice_lab/terms.py`](../voice_lab/terms.py))의 표현을 카탈로그에 합침 |

반대로 서버가 더 나은 점은 유지한다.
- 질문, 과거력, 대략값, 불확실 표현은 관찰 사실로 넣지 않는다.
- 증상을 있음·없음·불확실 목록으로 나눈다.
- 원문 인용과 변경 이력을 남긴다.
- 확인 뒤에만 전송하고, 녹음 원본은 저장하지 않는다.

## 3 R1에 맞추기 위해 추가할 칸

| 번호 | 추가·변경 | 값 | 이유 |
|---|---|---|---|
| B1 | `avpu` | `A`·`V`·`P`·`U`·`unknown` | R1 필수. 지금 `consciousness`는 V·P를 구분하지 못한다. 제출할 때 `consciousness`로 함께 변환 |
| B2 | `chief_complaint` | R1 10묶음 | R1 필수. 증상 목록을 묶음으로 바꾸는 표가 필요하다. '주증상은 ~'처럼 직접 말하면 그 값을 우선한다. 임신 중 하혈은 산과로 고른다 |
| B3 | 연령대 이원화 | 지금 `age_group`(10년 단위)은 `age_decade`로 바꾸고, `age_group`은 R1 값(`adult`·`child`·`neonate`·`pregnant`)으로 쓴다 | R1 필수. 소아·임신 구분이 병원 선택을 바꾼다 |
| B4 | `pre_ktas` | 1~5·`unclassified` | R1 필수. 말한 경우에만 채운다. 시스템이 추론하지 않는다 |
| B5 | 2차 고려사항 | `stemi_suspected`, `injury_region`, `labor`, `pregnancy_weeks`, `seizure_ongoing`, `bleeding_risk`, `high_risk_mechanism` | R1 6절 |
| B6 | 측정값 추가 | `nrs`(0~10), `gcs`(3~15) | R1 5절 |

## 4 제출 변환

지금 `_patient_patch`는 나이·의식·호흡·발생 시각·증상 문장만 환자 칸으로 옮기고, 나머지는 `extra.voice_observations`에 둔다. R1 기준 변환을 추가한다.

- `priority`: Pre-KTAS 1·2 → 4, 3 → 2, 4·5 → 1. `priority_source: "expert"`. 미분류는 `null`
- `extra`: `avpu`, `chief_complaint`, `treatment_profile_id`, `age_group`, `pre_ktas_level`, `vitals`, 2차 고려사항 키
- 진료 프로필 선택: R1 4절 규칙. 시제품의 `voice_lab.extract.profile_for`와 같은 규칙이다.
- 필수 5칸이 비어 있으면 전송을 거부하고 빠진 칸을 알려 준다(`to_server_payload`와 같은 동작).

시제품의 `to_server_payload`가 만든 본문은 서버 입력 검사(`_clean_patient`)를 통과한다(`test_voice_lab`).

## 5 그 밖에 정할 것

- **음성 인식 경로:** 지금 서버 녹음 인식은 Azure, 즉 Microsoft 클라우드를 쓴다. 가상 대본 시연에는 문제없지만, 실제 환자 음성은 외부 전송이 된다. 시연 전용으로 둘지, 서버 PC에서 도는 Whisper로 바꿀지 정한다.
- **문의 뒤 음성 수정:** 수정 API를 거치므로 R1 13절 3번(행정 필드는 수용 유지)과 함께 바꿔야 한다.
- **역할:** 서버 음성 파일은 Codex가 작업 중이다. 같은 파일을 동시에 고치지 않도록, 반영할 사람을 정한 뒤 진행한다.
