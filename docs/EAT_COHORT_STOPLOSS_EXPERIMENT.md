# 후속 문의의 잔여 작업 꼬리 반영

상태: 별도 후보 `eat_cohort_stoploss_l15_f`의 훈련 360환경·1,242명 검증을 마쳤다. 환자별 정규화 결과가 직전 Advance와 모두 같았고 목표를 충족하지 못해 채택하지 않는다. 새 개발·별도 검증은 실행하지 않는다. 이전 소스·증거는 보존했다.

## 개선할 계산

Advance는 미래의 기준 대기를 `max(q0−s,0)`로 계산했다. q0는 현재 예상 작업량, s는 미래 송신 오프셋이다. 실제 처리시간에 분산이 있으면 평균에서 시간을 차감한 값이 남은 작업의 기댓값을 과소 평가할 수 있다. 직전 후보의 추가 대기는 51초 감소했지만 개인 도착 지연이 최대 277초 늘었고, 성공·대기 목표도 미달했다. 이번 변경이 그 결과의 원인이나 해법이라고 미리 단정하지 않는다.

이번 후보는 현재 공개 입력으로 추정한 선두 작업의 로그정규 잔여 꼬리를 기준 대기에 반영한다. 원래 Followplan의 최대 세 가지 문의안, 문의 병원·시점·환자 목록, 초기 회신 분포, 잔여 환자 점수, 문의 비용·우선순위·동률 처리 원칙은 고정한다. 미래 문의끼리의 완료시각 갱신은 Advance의 평균 근사를 유지한다.

### 현재 증거에 고정한 잔여 함수

서비스 시간 S의 분포를 기존 로그정규 모형으로 두고, `J(t)=E[(S−t)+]`, 현재 추정 경과를 a, 회신 확률을 r, 서비스 누적분포를 F라고 하자. 현재 무회신 증거의 확률은 `D(a)=1−rF(a)`다.

현재 증거만 가지고 u초 뒤를 예측하는 선두 잔여 평균은 `J(a+u)/D(a)`다. 분모 a를 현재 시점에 고정한다. 미래에도 계속 무회신이었다는 관측은 입력에 없다. 수치 계산은 기존 로그 꼬리·차감 안정화 방식에 맞춰 처리하고, 분모를 미래 시점으로 바꾸는 오류를 독립 검사한다.

### 현재 평균을 보존하는 기준 대기 근사

부모 기록의 현재 기준 대기를 q0, 선두 잔여 평균을 m이라고 하자. 선두 잔여 확률변수 R과 독립인 베르누이 변수 B를 이용해 `C0=f+B·R`이라는 기준 완료 작업량 근사를 선언한다.

- q0가 m 이상이면 `f=q0−m`, `p=P(B=1)=1`이다.
- q0가 m보다 작으면 `f=0`, `p=q0/m`이다.
- m이 0인 퇴화 경우는 `f=q0`, `p=0`이고, q0가 0이면 전체 작업량이 0이다.

이 구성의 현재 평균은 q0다. 가상 작업량 차감으로 q0가 선두 평균보다 작아진 경우도 확률질량을 줄여 같은 평균으로 맞춘다. 이를 실제 선두의 취소를 관측한 것으로 해석하지 않는다.

현재 선두 평균은 봉인된 원래 계산과 대조하고, 부동소수점 오차는 원시값·보정량·허용량과 함께 남긴다. 기본 32 ULP와 로그 차감 연산의 민감도에서 전파한 허용량 안에서만 경계를 보정한다. 큰 오류·유한하지 않은 허용량·양의 꼬리를 수치적으로 구분하지 못한 경우는 실패한다. 이 허용량은 정한 피연산자 오차 가정 아래의 공학적 검사이며 초월함수 전체의 인증된 오차 구간은 아니다.

송신 오프셋 s에서의 기준 잔여 기댓값은 s가 f보다 작으면 `f−s+p·m`, 나머지 경우는 `p·J(a+s−f)/D(a)`다. 0시점 평균 보존·유한성·비음수·단조 감소·평균 차감 하한 이상의 값을 검사한다. 뒤 작업을 결정적 평균으로 두고 선두의 처리 시작을 추정한다는 가정이 남는다. 실제 숨은 대기열 전체의 정확한 분포를 복원했다는 주장은 하지 않는다.

각 미래 문의의 고정 F0는 위 기준 잔여로 한 번 구성한다. 보정 대기는 기준 잔여와 같은 병원의 앞선 미래 작업 잔여의 최댓값이다. 예상 시작까지 다른 병원에서 수용되지 않았을 확률 S와 평균 서비스 시간으로 미래 작업량을 갱신한다. 보정 F1을 작업량 계산으로 되먹이지 않고, S를 자기 병원 수용 확률에 중복 곱하지 않는다.

이 모형은 실제 회신·작업자 상태를 추가로 안다고 가정하지 않는다. 실제 동시 문의 4건·총 문의 10곳·A/H·종료 장벽·원자적 공동 적용·FIFO·단독 및 후기 H 경로는 유지한다. 가상 미래 문의를 예약하지 않고 현재 두 환자의 행동만 적용한다. 미래 사건·결과·아직 등록되지 않은 환자·시나리오 ID를 정책에 넣지 않는다.

## 보존과 검증 절차

부모 Advance 봉인은 `f7290b0e4e1dc395bec771bdb3b4cc49fbaeeb3c6ae030efdf28c1bf5259d789`다. 부모 소스 506개·참조 1,666개·과거 압축 원문 3,120개를 보존하고 새 소스 16개를 더한 522개를 검사·고정한다. 문서 목록의 역사적 해시 변경은 기존 이력을 승계하며 새 재결속은 하지 않는다.

- 훈련 360환경: 새 후보만 각각 한 번 실행한다. 비교군 17개·6,120분기는 봉인된 기록을 재사용한다. 모든 원문 저장 후 두 훈련 구간을 따로 판정한다.
- 새 개발 120환경: 훈련 조건을 모두 통과할 때만 18개 정책을 실행한다. CS·Hedge 각각의 실패 비증가와 선정 대기 엄격 감소를 모두 요구한다.
- 별도 검증 368환경: 새 개발도 통과할 때만 실행한다. 같은 점 조건에 더해 CS·Hedge 각각의 실패 차이 95% 상한이 0 이하, 대기 차이 95% 상한이 0 미만이어야 한다. 시나리오 단위 짝 부트스트랩 10,000회다. 지표별 주변 95% 구간으로 네 조건의 공동 95% 보장은 아니다.

새 입력은 소스 고정 후 생성하고 과거에 생성만 해 둔 미실행 입력의 난수도 재사용하지 않는다. 입력 명세는 848개이며 최대 새 실행은 9,144분기다. 결과 제외·성능 재실행·사후 설정 변경은 하지 않는다. 실패 뒤 후속 단계는 차단한다. 운영 서버와 기본 `fixed_3`는 바꾸지 않는다.

독립 감사는 고정 부모 증명·평균 보존·현재 증거의 조건화·수치 안정성·미래 CDF·비용·선택·전 환자 FIFO를 확인한다. 모든 원문 저장 후 네 프로세스에서 의미 감사를 하고 원문·전체 소스·원문 인덱스에 결속한 사례별 증명을 남긴다. 유효한 증명은 재실행하지 않는다. 표준 라이브러리 회계기는 정책·시뮬레이터를 호출하지 않고 성공·대기·도착·성공 교환·조건을 별도로 집계한다.

전체 검사는 현재 파일로 수행한다. 과거 `docs/README.md` 검사 10개가 같은 역사적 참조 해시 오류로 실패하면 실패와 추적을 그대로 남긴다. 정확한 검사 ID·오류·원래/현재 해시만 일치할 때 새 동결 자격을 허용하며 전체 검사 통과로 표시하지 않는다. 읽기·해시·단언을 바꾸거나 검사를 건너뛰지 않는다.

합성 성능 자료의 우선순위는 미확인·기본값 4다. 임상 응급도별 효과나 실제 현장 성능의 우월성을 주장하지 않는다. 전체 벽시계 시간은 감사·수집을 포함하므로 정책 계산시간으로 해석하지 않는다.

## 결과

### 자연 활성화 검사

성능 원문을 재실행하지 않고 저장된 근거에서 새 분기가 쓰인 범위를 따로 집계했다. 360원문에 공동 처리 그룹 180개가 있었고 그중 30개가 메뉴를 평가했다. 80개 행의 미래 문의는 총 849개다.

현재 기준 대기와 선두 평균이 양수인 것은 2개 사례·2개 그룹·3개 행의 5개 작업뿐이었다. 다섯 작업 모두 `before_shift` 분기로, 송신 시점에 결정적 후속 작업 구간이 아직 남아 있었다. 새 `head_tail` 분기의 자연 활성화는 **0건**이었다. 수치 허용량을 넘는 기준 대기 증가와 같은 기록의 앞선 완료시점 대비 q1 증가도 0건이었다. 평균 차감식과 비교한 최대 차이는 약 `2.84×10⁻¹⁴`초로 기록된 수치 허용량 이내였다.

이 자료는 새 꼬리 분기의 성능 효과를 검증할 조건을 제공하지 않았다. 수학·합성 검사에서 확인한 동작과 이번 시스템 성능 결과의 적용 범위를 구분한다. 결과가 같다는 이유로 꼬리 모형 일반의 효과가 없다고 결론 내리지 않는다. 내장 Followplan 참조 대비 선택 개입은 8개 그룹에서 확인했으며, 이를 Advance와의 직접 행동 비교로 해석하지 않는다. 집계와 원문 해시 결속은 `diagnosis/activation-accounting.json`에 남겼다.

### 판정과 다음 가설

기존 성공 목표만 통과했고 기존 대기·추가 성공·추가 대기 목표는 실패했다. 새 개발·별도 검증으로 넘어가지 않으며 후보를 채택하지 않는다. 운영 서버와 기본 `fixed_3`는 유지한다. 소스·검사·원문·의미 증명·별도 집계·활성화 진단·문서를 해시에 결속해 남긴다.

다음 구조적 연구 대상으로 평가 메뉴의 범위를 확인했다. Dynamic이 남긴 최대 세 가지 행을 후속 후보들이 계속 재평가한다. 6개 병원 중 환자마다 2곳을 문의하는 설정에서 원래 공동 문의 표는 최대 225개 조합이며, 일반적인 코드 상한은 400개다. 실제 자원 제약을 만족하는 행 수와 추가 평가의 효과는 별도 확인이 필요하다.

실현 가능한 다른 행을 평가하려면 공개 입력만으로 Dynamic의 후속 투영, 초기 예상 작업, 잔여 환자 점수, 행별 미래 문의 계획을 새로 구성해야 한다. 메뉴 번호만 늘리는 방식으로 구현할 수는 없다. 계산량도 현재 세 행 평가보다 크게 늘 수 있다. 이는 아직 구현·성능 검증하지 않은 가설이며, 이번 결과가 같은 원인이라고 단정하지 않는다.

후속 실험에는 새 분기를 실제로 사용하는 공개 입력의 기능 검증 범위를 먼저 선언할 필요도 있다. 이런 사례를 추가할 경우 기존 827명·415명 보존 목표와 별도 범위로 기록해야 한다. 이번 훈련 실패 뒤의 새 개발·별도 검증은 실행하지 않았다.
