# 재확인이 오래 걸릴 때의 지연 개선

2026-10-15 · 합성 시뮬레이션 배정·재확인 단계 개선 · 운영 서버 미적용

## 결과와 남은 한계

병원 수용 응답 뒤에 자원 수량을 확인하던 순서를 **병행 확인**으로 바꿨다. 수용 회신이 만료되어도 현재 희소 환자가 검색 중이면 **독립 자원 추적**을 계속한다. 확인 응답에도 필수 수량이 빠져 있으면 다른 환자를 계속 유보하지 않는다.

개발 66사례 × 14분기 후 소스·설정·런타임을 잠그고, 미사용 검증 시드로 **132사례 × 14분기 = 1,848회**를 비교했다. 각 규칙의 환자 실행은 402개, 기존 보호와 개선 분기에서 모두 도착한 실행은 372개다. 모든 입력은 합성이다.

| 조건 | 기존 보호 대비 개선의 평균 도착 변화 | 분모 | 추가 설명 |
|---|---:|---:|---|
| 1분 재확인·전문팀 정보 누락 | −0.667분 | 18 | P02·P03 각각 1분 단축 |
| 2분 재확인 | −0.667분 | 18 | P02·P03 각각 1분 단축 |
| 3분 재확인 | −0.667분 | 18 | 기존 보호로 얻은 희소 환자 기회 유지 |
| 5분 재확인 | **−1.556분** | 18 | P03 평균 −3.667분, P02 −1분 |
| 8분 재확인 | **−1.444분** | 18 | P03 평균 −3.333분, P02 −1분 |
| 수용 회신 만료 후 8분 재확인 | −1.778분 | 18 | P03 평균 −5.333분 |
| 빠른 재확인 응답에도 전문팀 수량 누락 | −1.500분 | 12 | P02의 불필요한 추가 대기 3분 → 0분, P03 미배정은 유지 |
| 장기 재확인 응답에도 전문팀 수량 누락 | −0.500분 | 12 | P02 추가 대기 3분 → 2분, P03 미배정은 유지 |

이 표의 H1·C1 집계 평균은 같다. **개인별 결과까지 같다는 뜻은 아니다.** 모든 차이는 같은 새 검증 시드에서 개선−기존 보호로 계산했다. 이전 실험의 다른 시드 평균을 이번 전후 비교에 섞지 않는다.

5분 재확인 유형의 무보호 대비 평균은 기존 보호 +0.778분에서 개선 −0.778분으로 바뀌었다. 8분 유형은 +1.000분에서 −0.444분으로 바뀌었다. 그래도 두 유형 모두 각 6개의 P03 실행 중 1개는 기존 보호보다 1분 늦었다.

## 바꾼 처리 방식

### 1. 수용 문의와 수량 확인을 병행

현재 문의 후보의 자원 보고가 unknown/stale이면 수용 응답을 기다리지 않고 별도 수량 확인을 시작한다. 현재 보고로 fresh 부족이면 이 병행 조건에는 들어가지 않는다. 자원 확인이 먼저 끝나도 환자별 수용 응답 없이 확정하지 않는다.

기존 3분 확인 기회는 유지한다. 단, 개선 분기는 수용 응답 뒤가 아니라 **첫 자원 확인 대기 시점**부터 시계를 센다. 대표 사례는 요청 0분 → 수용 회신 1분 → 보호 종료 3분이므로 실제 경쟁 환자 유보가 3분에서 2분으로 줄어든다. 재문의·새 응답으로 시계를 재시작하지 않는다.

3분 미만으로 창을 단순 축소하면 3분에 도착하는 재확인을 놓쳐 희소 환자가 크게 늦어지는 회귀가 생긴다. 이 문제를 단위 테스트에 포함했고, 3분 응답을 받을 기회는 보존했다.

### 2. 불완전한 재확인 응답 이후에는 유보 중단

첫 확인 대기 이후 실제로 받은 `confirmation` 보고에도 필요한 수량이 unknown이면 해당 수용 후보로 다른 환자를 유보하지 않는다. 미래의 회신 속도·내용을 예측한 것이 아니라 이미 받은 불완전 응답을 근거로 한다. 확인되지 않은 환자를 배정 모델에 넣지는 않는다.

### 3. 자원 추적을 수용 회신 수명과 분리

매 tick 끝에 이미 자원 확인을 요청한 병원을 대상으로, 현재 발생했고 SEARCH 상태이며 구조적으로 해당 병원 한 곳만 가능한 환자의 수요를 확인한다. 자원이 unknown/stale/부족이면 수용 회신이 없거나 만료됐더라도 수량 재확인을 진행할 수 있다.

병원별 진행 중 요청은 하나만 허용하고, 응답·타임아웃 뒤에는 기존 `retry_minutes` 간격을 지킨다. 미래 환자, 알려지지 않은 실제 자원량, 복구 예정 시각, 응답 예정 시각은 추적 판단에 사용하지 않는다.

### 4. 최신 보고에 따른 재문의

같은 tick에 받은 최신 적용 보고가 fresh이고 필요한 자원이 충분하며, 환자에게 진행 중 문의·유효 수용 회신이 없으면 새 문의를 시작할 수 있다. 만료된 수용 회신을 복원하지 않고 **새 문의 → 새 수용 응답 → 확정 검사**를 거친다.

단위 사례에서 보고 5분 → 새 문의 5분 → 새 수용 응답·확정 6분을 검증했다. 다만 이번 1,848회 벤치마크의 `report_driven_wake`는 **0회**였다. 벤치마크의 개선을 이 이벤트의 실측 효과로 설명하지 않는다. 이 동작의 검증 범위는 단위 사례다.

## 전체 결과와 개인별 비용

| 기존 보호 대비 | H1 | C1 |
|---|---:|---:|
| 공통 도착 실행 | 372 | 372 |
| 평균 도착 변화 | −1.180분 | −1.180분 |
| 빨라짐 / 동일 / 늦어짐 | 159 / 201 / 12 | 159 / 195 / 18 |
| 개인별 최대 추가 지연 | **6분** | **37분** |
| 한쪽에서만 도착 | 양쪽 모두 0 | 양쪽 모두 0 |
| 미배정·미도착 | 30 → 30 | 30 → 30 |

미배정 30개는 전체 정보가 계속 없는 유형 18개, 전문팀 정보만 계속 없는 두 유형에서 각 6개다. 이는 수량 기반 자동 배정 미확보이며 실제 병원 수용 거절이나 임상적 실패를 의미하지 않는다.

**C1의 최대 37분 지연은 남은 중요한 약점이다.** 대안 병원이 없는 조건에서 선행 확인으로 P03이 초기 배정에 참여하면서, 같은 목적값의 배정 중 P01 대신 P03이 먼저 배정됐다. 6사례에서 P01은 기존보다 29~37분 늦어졌고 P03은 빨라졌다. 유형 평균은 단축됐지만 평균만 보면 대기 환자의 신원이 바뀐 비용이 숨겨진다. H1은 해당 조건에서 P01/P02의 초기 배정을 유지했다.

H1에서도 낮은 우선순위의 대기 환자가 처음부터 배정에 참여하면 유연한 P02가 대안 병원으로 가며 5~6분 늦어지는 사례가 있다. 이는 높은 우선순위 환자를 보호 규칙으로 유보한 것이 아니라 현재 공동 배정 목적함수의 결과다. 자원 중단·복구, 늦게 발생한 환자, 긴 재확인에서도 일부 1~2분 지연이 남는다. 모든 환자의 비악화는 주장하지 않는다.

## 요청량과 구성 요소 비교

H1·C1 각각 동일한 집계다.

| 요청 종류 | 기존 보호 | 개선 | 변화 |
|---|---:|---:|---:|
| 환자 수용 문의 | 1,127 | 868 | −23.0% |
| 별도 자원 수량 확인 | 310 | 499 | **+61.0%** |

두 요청은 작업 내용이 다르므로 동일한 부담으로 합산하지 않는다. 이 합성 환경에서는 요청 증가에 따른 자원 확인 처리시간의 추가 악화를 모델링하지 않았다. 실제 운영 부담이 감소했다는 증거로 해석하지 않는다.

14분기는 완전정보·관측정보 R1/H1/C1 6개, 기존 보호 H1/C1 2개, `early` H1/C1 2개, `watch` H1/C1 2개, 두 개선을 합친 `responsive` H1/C1 2개다. `early`에는 선행 확인·더 이른 시계·불완전 응답 후 보호 중단이 함께 들어가며 하나의 미세 요소만 바꾼 비교는 아니다.

선행 확인만 한 분기는 8분 재확인 유형에서 기존 보호보다 평균 1.111분 악화됐다. 독립 추적과 합친 분기는 평균 1.444분 단축됐다. 따라서 이번 개선을 선행 요청만의 효과로 설명하지 않는다.

## 검증 범위와 증거

개발 시드 21101–21103, 검증 시드 22101–22106을 사용했다. 이전 개발·검증 시드는 재사용하지 않았다. 기존 22개 합성 유형의 새 시드이며 실제 현장 일반화를 입증하지 않는다.

**관련 테스트 394개 통과.** 독립 감사기는 시뮬레이터·정책·관측 저장소·솔버를 실행하지 않고 저장된 원시 사건으로 관측, 수용, 보호, 병행 확인, 추적 대상, 중복·재요청 간격, 모델·실제 확정, 결과·비교 분모를 다시 검사한다. 보고 기반 재문의도 최신 정보와 새 문의·수용 흐름을 검증한다.

저장한 검증 파일을 별도 감사 명령으로 재검증했고, 3,654개 배정 결정과 1,452개 CP-SAT 모델 증명의 독립 완전탐색 재확인을 통과했다. 현재 모델 증명은 전체 이송·보호·추적의 최적성을 증명하지 않는다. 최종 실제 확정 검사는 즉시 권위 있는 실제 자원 수량을 검사할 수 있다는 기존 합성 환경 가정을 유지한다. 운영 서버가 미보고 병원 상태를 자동 감지한다는 뜻이 아니다.

운영 서버·팀원 UI·이전 실험 소스와 결과는 변경하지 않았다. C1의 동률 배정 안정성 문제와 자원 확인 부하를 해결하기 전에는 이 결과를 운영 적용 완료로 취급하지 않는다.
