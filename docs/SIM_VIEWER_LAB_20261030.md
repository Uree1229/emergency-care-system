# 시뮬레이션 지도 재생 새 화면 (lab.html)

2026-10-30. Claude Design 시안 3개(A 관제실형, B 비교 분석형, C 발표·스토리형)를 실제 뷰어에 탭 3개로 옮겼다. 기존 화면(`index.html`)과 재생 엔진(`app.js`)은 바꾸지 않고 **별도 페이지**로 두었다.

## 1. 상태

| 구분 | 내용 |
|---|---|
| 구현 완료 | `simulation/viewer/lab.html` · `lab.css` · `lab.js` 세 파일. 탭: **지도 재생**(A) · **결과 비교**(B) · **발표**(C) |
| 가상 검증 | 저장된 58개 사례 전부에서 비교·발표 탭 자동 생성, 오류·NaN 없음. 1440×900 · 1024×768 · 375×812 화면 확인. 기존 `test_viewer_server`(2)·`test_viewer_basemap.cjs`(6) 통과 |
| 향후 계획 | 기존 `index.html`을 새 화면으로 바꿀지는 사용자 결정 후 진행. 바꿀 때 팀 실행본도 다시 묶어야 함(2절) |

## 2. 별도 페이지로 둔 이유와 20:17 반영 사고

- 20:17에 `index.html`을 3탭 구조로 먼저 바꾼 뒤 사용 한도로 작업이 멈췄다. CSS·JS는 아직 없어서 기존 화면 배치가 깨진 상태였다.
- 그동안 Codex가 작업 트리의 뷰어로 시연 서버(18045)를 띄우고, 23:21에 팀 실행본 `team-common-20261030-v1`을 묶었다. 실행본의 `source/simulation/viewer/index.html`은 **미완성 3탭 구조**다(SHA-256 `6f26e052…4284b3`). 이 파일을 `app.js`·`styles.css`와 함께 열면 지도가 오른쪽 좁은 칸으로 밀린다(23:23 화면 확인).
- 23:23:55에 작업 트리의 `index.html`을 커밋 HEAD 내용으로 되돌렸다(`d920f45e…bdc8fbd8`, `git status` 변경 없음). 18045 시연 화면은 바로 원래 배치로 돌아왔다.
- **팀 실행본은 수정하지 않았다.** 실행본 파일 명세가 바이트 단위로 고정돼 있으므로 Codex가 복구된 `index.html`로 다시 묶어야 한다.
- 새 화면 파일(`lab.*`)은 어디에서도 링크하지 않는다. 다음 실행본에 함께 들어가도 기존 `index.html`·`demo.html` 동작에는 영향이 없다.

## 3. 여는 방법

```powershell
python -m simulation.viewer_server --reuse-data
```

`http://127.0.0.1:18005/lab.html`을 연다. 다른 포트로 띄운 서버도 경로 뒤에 `/lab.html`만 붙인다. 주소로 상태를 지정할 수 있다.

- `lab.html?scenario=road-online-simultaneous` — 시나리오 지정. 상단 선택을 바꾸면 주소도 갱신된다.
- `#compare`, `#story` — 결과 비교·발표 탭으로 바로 연다.
- 바닥글의 **기존 화면** 링크로 `index.html`에 돌아간다.

## 4. 탭별 화면

**지도 재생 (A 관제실형)**
- 어두운 3단 배치: 정책 카드 | 지도 | 사건 기록·실험 조건. 1279px 이하에서는 오른쪽 열이 아래로, 999px 이하에서는 지도·카드·기록 순서의 1단으로 바뀐다.
- 지도 배경 타일은 CSS 필터로 어둡게 바꾸고, 지도 위에 경과 시간 표시를 얹었다. 재생·문의·이동 표시와 단축키는 기존 `app.js` 그대로다.

**결과 비교 (B 비교 분석형)**
- 정책별 최종 배정 미니 지도: 환자 발생지→관측 종료 시 목적지 직선. 환자 6명 이하는 환자 번호, 그보다 많으면 병원별 인원수로 표시한다. 미배정은 빨간 X로 표시한다.
- 핵심 지표 막대: 수용 확정, 문의 건수, 관측 종료 시 미배정, 최종병원 도착 평균(도착 인원 병기). 기록이 있으면 재문의·이송 이동시간 합계·4군 치료 미시작도 보여 준다. 막대는 같은 지표 안의 상대 길이다.
- **왜 달라졌나**와 환자별 최종 배정 표, 기존 전체 지표 표(항상 관측 종료 값)도 함께 둔다.

**발표 (C 발표·스토리형)**
- 기준·비교 정책 두 개를 고르고 단계별로 넘긴다. 기본 쌍은 확정 인원이 가장 적은 정책과 가장 많은 정책이다. 같으면 결과가 가장 많이 갈린 쌍이다.
- 키보드: ←/→, PageUp/PageDown(발표용 리모컨), Home/End.
- 비교·발표 탭에서는 Space·←/→가 숨은 지도 재생을 움직이지 않는다. 탭을 떠날 때 재생도 멈춘다.

## 5. 자동 생성 규칙

사례가 58개라 문장은 손으로 쓰지 않았다. 저장된 사건(`commit`·`redirect`·`transfer_depart`·`ask`)과 `patient_outcomes`에서만 뽑는다. 원인 추정 문장은 만들지 않는다.

| 항목 | 규칙 |
|---|---|
| 최종 목적지 | `patient_outcomes.destination_hospital_id`. 없으면 마지막 배정 사건 병원 |
| 처음 갈린 시각 | 환자별 배정 병원 순서(연속 중복 제거)를 정책 쌍끼리 비교해 처음 달라진 시각. 같은 시각이면 어딘가에서 미배정된 환자 → 가능 병원이 1곳뿐인 환자 → 실험 우선순위가 높은 환자 순으로 대표를 고른다 |
| 희소 역량 문장 | 환자의 필요 역량을 모두 갖춘 병원이 1곳뿐일 때만. 그 병원을 받지 못한 정책에서 다른 환자가 먼저 확정된 시각을 함께 적는다 |
| 문의·도착 비교 | 값이 가장 작은 정책 묶음과 가장 큰 묶음만 보여 준다. 도착 평균에는 "도착한 환자만 평균" 주의를 붙인다 |
| 발표 단계 | 발생 → 119 현장 도착(서버 기록 제외) → 문의 시작 → 처음 갈린 순간(갈림이 없으면 첫 확정) → 결과. 정책 1개 기록에 사람이 확정한 목적지 변경이 있으면 그 단계를 추가한다 |

## 6. 한계

- 미니 지도와 발표 지도의 선은 직선 요약이다. 실제 도로 경로·이동 중 위치는 지도 재생 탭에서만 본다.
- 음성 연결 기록(`voice_*`)은 시간이 사건 순서(#번호)라 시간 지표 행을 뺐다. 환자 0명 기록은 안내 문구만 보여 준다.
- 정책이 하나뿐인 서버 기록은 비교 대상이 없어 **기록 요약**으로 바뀐다.
- 발표 문장은 기록 사실의 나열이다. 임상 효과나 현장 개선율을 뜻하지 않는다.

## 7. 파일

| 파일 | 역할 |
|---|---|
| `simulation/viewer/lab.html` | 3탭 구조. 기존 `index.html`과 같은 DOM ID를 써서 `app.js`를 그대로 불러온다 |
| `simulation/viewer/lab.css` | `styles.css` 위에 덮는 테마·배치. 재생 탭은 어두운 테마, 비교·발표는 밝은 테마 |
| `simulation/viewer/lab.js` | 탭 전환, 비교·발표 자동 생성, `app.js`의 `render`·`renderResults`·`selectScenario`·`renderGeography` 감싸기. `window.replayDebug`에 `setView`·`view`·`story` 추가 |

`index.html`·`app.js`·`styles.css`·`basemap.js`와 재생 JSON은 수정하지 않았다.
