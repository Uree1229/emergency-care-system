# 통신 장애 안내와 저장 상태 구분

대상은 `/paramedic/quick-test.html`의 `연결·저장 상태`다. 서버 응답이 없을 때 무엇이 확인됐고 무엇이 아직 확인되지 않았는지 보여준다. 서버 저장 여부를 브라우저의 온라인 표시나 임시 보관 성공만으로 판단하지 않는다.

## 안내와 동작

- 브라우저의 online/offline은 연결 힌트로만 표시한다. 오프라인으로 표시돼도 로컬 API에 접속할 수 있으며, 온라인으로 바뀌었다고 요청을 자동 재전송하지 않는다.
- API 요청의 응답 수신·연결 실패·5xx 서버 오류·JSON/기능 응답 형식 오류를 구분한다. 401·403·404·409 등 4xx는 서버 응답이 있는 요청 오류이며 인터넷 단절로 표시하지 않는다. 서버 음성 기능 버전 불일치도 별도로 안내한다.
- 브라우저 복구본 저장을 확인한 경우와 임시 저장 실패·미확인을 구분한다. 저장 실패 때에는 현재 화면과 원문을 유지하고 별도로 보관하도록 안내한다. 임시 보관 성공을 서버 반영 성공으로 바꾸지 않는다.
- 음성 인식 오류는 마이크·브라우저 음성 서비스를 확인하도록 안내한다. API가 정상이어도 음성 입력은 실패할 수 있다. 새 말하기가 실제 듣기 상태로 진입하면 이 화면의 이전 음성 오류 표시를 해제한다.
- 결과 확인이 필요한 요청은 원래 요청 ID·본문·버전의 재시도 대상으로 유지한다. 임시 저장 단계에서 HTTP 전송이 차단된 경우도 포함하므로 이미 서버로 전송됐다고 단정하지 않는다.

`서버 연결 확인`은 별도 클라이언트의 capabilities GET 한 번으로 점검한다. 최대 6초 뒤 점검 대기를 끝내며 가능한 브라우저에서는 해당 읽기 요청을 중단한다. 기존 쓰기 요청의 타임아웃·큐·중복 방지 동작은 바꾸지 않는다. 점검 성공은 서버 응답·기능 버전 확인일 뿐, 불확실한 쓰기 결과를 확정하거나 재시도하지 않는다.

`직접 입력 열기`는 기존 검토칸을 열고 내용을 보존한다. 원문이나 대기 요청을 새 입력으로 자동 복사하지 않는다. 버튼 자체는 초안 생성·전송·반영을 하지 않는다. 결과 확인 대기 중에는 기존 검토칸의 읽기만 허용하고, 동일 요청의 결과를 먼저 확인한 뒤 작성·반영하도록 안내한다. 직접 입력도 서버에 반영하려면 연결이 필요하다.

## 오래된 응답과 보관 범위

수동 점검은 시작 당시 클라이언트·환자 세대·로컬 환자 번호·보관본을 대조한다. 환자 전환·다른 탭의 보관본 변경·온라인/오프라인 변화·페이지 종료 때 점검을 취소한다. 취소·시간 초과 이후 늦게 온 응답으로 상태를 덮어쓰지 않는다. 자동 초기 기능 조회도 이전 클라이언트의 결과를 다른 환자 화면에 적용하지 않는다.

연결 상태는 마지막 확인 시점의 메모리 상태이며 상시 통신 감시나 음성 인식 정확도 판정이 아니다. 새 임상 내용·원문·오디오·오류 원문을 별도 진단 기록으로 저장하지 않는다. VoiceClient의 선택적 observer에는 method/status/kind만 전달하고 URL·본문·환자/작성자/초안 ID를 넘기지 않는다. observer가 실패해도 실제 API 결과나 재시도 계약은 바뀌지 않는다.

## 검증

독립 안내 모델·API observer·실제 페이지의 모의 DOM 시험과, 새 SQLite를 사용하는 실제 HTTP 통합을 수행한다. 서버 커밋 뒤 응답 유실, 동일 요청 재시도, 읽기 점검 중 대기 요청 보존, 4xx/5xx/잘못된 응답, 임시 저장 실패, 음성 오류, 브라우저 상태 변화, 점검 시간 초과·늦은 응답·환자 전환·다른 탭 변경을 확인한다.

최종 배포 후보의 전체 Node 회귀 **1,415/1,415**, 실제 HTTP 통합 **13개 시나리오·83개 확인**을 통과했다. 느린 초안 복원이 끝난 뒤 해당 클라이언트의 기능 버전을 확인하는 시험도 포함한다. 기존 요청을 유지한 상태의 점검·응답 유실 후 정확한 재시도·중복 발화 방지·실제 6초 시간 초과·오래된 응답 무시를 확인했다. 시험 DB는 DRAFT 초안만 사용했으며 환자·병원·문의 생성과 임상 확정·전송은 0건이었다.

5xx·응답 형식 오류는 실제 서버 커밋 뒤 클라이언트 응답 경계에 주입했다. 409는 실제 버전 충돌 응답을 사용했고, 401·403 등 전용 안내 문구는 독립 모델·페이지 회귀에서 확인했다. 실제 브라우저에서는 저장된 합성 초안 복원·연결 상태 펼침·읽기 전용 서버 점검과 본문 표시를 확인했고, 변경된 정적 파일 5개가 최종 소스와 일치함을 확인했다.

합성 환자와 모의 인식기만 사용하며 운영 DB·실제 마이크·클라우드 STT·OS 클립보드는 사용하지 않는다. 실제 브라우저 화면 확인과 모의 장애 검증은 실제 현장 통신 품질이나 음성 정확도 측정과 구분한다.
