# 현재 병상 부족 보고의 제한적 수용 재확인

2026-10-17 · 합성 이송 실험 · 부분 개선 확인 · 전체 후보 채택 보류

현재 만석으로 보고된 가까운 병원에도 최대 한 번 수용 여부를 재확인하는 후보를 구현했다. 과거 다중 문의 사례의 처치 시작은 **7.5→5.25분**, 다른 환자는 **3.5분 유지**로 개선됐다. 지난번 해결한 지연 6건과 기존 개선 6건도 보존했다.

새 검증에서는 직전 안전 회신 후보 대비 H1에서 **42명 단축·936명 동일·12명 악화**였다. 환경별 전체 대기 증가가 **6개** 발생해 엄격한 채택 조건을 통과하지 못했다. 개선과 회귀를 모두 보존하고 실제 서버의 기본 고정3 및 기존 선택값은 유지했다.

## 구현한 문의 규칙

원래 문의 선택기는 현재 보고의 자원 부족을 확인하면 해당 병원을 문의 후보에서 제외한다. 새 후보는 아래 조건을 모두 충족할 때 다른 목적의 실제 재확인 문의 한 건을 허용한다.

- 아직 탐색 중이고 목적지를 한 번도 확정하지 않은 최초 문의 에피소드다.
- 최초 실제 문의와 가장 최근 실제 문의 모두에서 30초 이상 지났다.
- 기존 문의가 진행 중이지만 현재 신선한 수량으로 사용할 수 있는 수용 제안은 없다.
- 구조적으로 치료 조건을 충족하며, 아직 문의하지 않았고 진행 중 문의나 기존 수용 제안이 없는 병원이다.
- 모든 필수 자원 보고가 신선하다. 응급 병상만 환자 수요보다 부족하며 보고된 총 병상 수는 충분하다. 다른 필수 자원은 수요 이상이다.
- 현재 등록된 다른 탐색 환자의 같은 병원 문의나 유효 수용 제안이 없다.
- 이동시간은 현재 진행 중인 문의 중 가장 가까운 병원의 이동시간에 2분을 더한 값 이하다.
- 기존 동시 문의 3곳·에피소드 접촉 10건 안에서, 환자당 한 번만 가장 가까운 적격 병원에 보낸다.

이 문의는 원시 기록에서 `shortage_probe` 목적과 전용 사유로 구분한다. 부족 보고의 값을 가용으로 바꾸거나 일반 문의의 수량 적격 검사를 통과한 것처럼 표시하지 않는다. 실제 병원 심사·회신 이후 기존의 신선한 충분 자원 검사와 실제 물리 자원 확정 게이트를 모두 통과해야 배정된다.

일반 문의가 모두 끝나고 선택적 재확인 문의만 남았을 때는, 이미 받은 신선한 수용 제안을 기존 공동 배정 절차에 올릴 수 있도록 했다. 실제 진행 중 문의를 지우거나 취소하지 않고 별도 원장과 준비 사건을 남긴다. 기존 희소 기회 보호·우선순위·배정 제약·수용 만료·실제 확정 검사도 거친다. **이 예외는 선택적 문의만 기다려 자기 환자가 늦는 일을 줄이는 규칙이며, 전체 환자의 무악화 보장은 아니다.**

기존 제출 문의와 병원 FIFO 심사 작업은 실제로 유지한다. 새 문의 자체가 작업 순서를 차지하며, 환자가 다른 병원으로 출발한 뒤에도 이미 제출된 작업 때문에 다른 문의가 영향을 받을 수 있다. 병상·인력·이동시간·처치시간·문의 기한을 유리하게 바꾸지 않았다. 추가 자원 변화 보고 채널은 전 분기에서 0건이고, 기존 자원 재확인 채널의 요청 수는 따로 집계한다.

## 보존한 과거 사례

19개 저장 입력을 바꾸지 않고 새 8분기로 실행했다. 기존 보호 V4·직전 안전 회신·고정3의 H1/C1 6분기에서 환자 결과와 문의 기록 114개 비교가 정확히 일치했다.

| 저장 입력 | 직전 후보 P01 | 새 후보 P01 | P02 또는 관련 환자 |
|---|---:|---:|---|
| 기존 개선 6건, 32101~32106 | 각 5.5분 | 각 5.5분 | P02 각 3.5분 유지 |
| 지난번 해결 6건, 34101~34106 | 각 8.25분 | 각 8.25분 | P02 각 3.5분 유지 |
| 다중 문의 경계, 시드 7 | 7.5분 | 5.25분 | P02 3.5분 유지 |
| 후발 단일 후보 환자 P03 경계, 38101~38106 | 기존 값 | 기존 값 | P01/P02/P03 결과 모두 유지 |

기존 보호 V4 대비 최대 17분의 P01 지연이 있던 P03 경계는 이번 변경으로 해결되지 않았다. 해당 입력은 P02와 P03이 각각 병상을 사용해 P01이 기다리는 물리적 경합이다. 다른 환자의 처치 시각까지 동시에 유지하는 일반적 해결을 주장하지 않는다.

## 새 개발·검증

기존 73개 환경을 완전 보존하고 10개를 추가했다. 실제 회신 전에 해소되는 부족, 계속 만석, 무응답, 후발 환자 FIFO 경쟁, 원 기한 뒤 회신, 짧은 수용 기한, 다른 필수 자원 부족·누락, 오래된 보고, 타 환자 문의 보호를 포함한다.

개발 39101~39103, 별도 검증 40101~40106은 이전 보존 자료의 스칼라 및 배열 시드 기록과 겹치지 않는다. 소스 122개·설정·채택 기준을 고정한 뒤 개발을 실행하고 선택을 잠갔다. 검증으로 다시 선택하거나 코드를 튜닝하지 않았다.

8분기는 기존 보호 V4·직전 안전 회신·제한적 재확인을 H1/C1 각각에 적용한 6개와 고정3 참고 2개다. 같은 환경에서 실행 순서를 회전했다.

| 직전 안전 회신 → 재확인 후보 | 개발 | 별도 검증 |
|---|---:|---:|
| 환경 | 249 | 498 |
| 전체 실행 | 1,992 | 3,984 |
| 분기당 환자 | 495 | 990 |
| 처치 단축 / 동일 / 악화 | 21 / 468 / 6 | 42 / 936 / 12 |
| 해당 표본 최대 처치 악화 | 2분 | 2분 |
| 전체 대기 합 변화(환자·분) | -27.75 | -55.5 |
| 대기 증가 환경 | 3 | 6 |
| 요청→처치 제한 합 변화 | -21.75 | -43.5 |
| 문의 수 변화 | 6 | 12 |
| 처치 상실 | 0 | 0 |

아래 집계는 H1 기준이다. H1/C1 환자 결과는 이 모집단에서 같았다. 이를 두 알고리즘의 일반적인 성능 동등성으로 해석하지 않는다. 두 배정 알고리즘의 반복 결과를 합쳐 환자 수를 두 배로 세지 않는다.

| 방식 | 환자 | 미처치 | 전체 대기 합(환자·분) | 요청→처치 제한 합(분) | 문의 | 기존 자원 재확인 |
|---|---:|---:|---:|---:|---:|---:|
| 기존 보호 V4 | 990 | 60 | 9133 | 13041.5 | 2666 | 1050 |
| 직전 안전 회신 후보 | 990 | 60 | 9114.5 | 12993 | 2672 | 1038 |
| 제한적 재확인 후보 | 990 | 60 | 9059 | 12949.5 | 2684 | 1044 |
| 고정3 참고 | 990 | 54 | 8515 | 12692.5 | 2425 | 981 |

기존 보호 V4 대비 검증은 66명 단축·18명 악화이며 대기 증가 환경이 7개다. 고정3 참고 대비도 처치 상실 18명과 처치 악화 263명이 있다. 어느 기준에서나 우수한 정책이라는 결론은 내리지 않는다.

## 실제 회귀 원인

검증 시드 40101의 후발 환자 FIFO 환경에서 P01은 **8.75→7.5분**으로 빨라졌지만 P02는 **4.25→6.25분**으로 늦어졌다. 추가 심사가 진행 중일 때 나중에 실제 접수된 P02의 문의가 뒤에서 기다린 결과다. 두 환자의 대기 합 변화는 **0.75환자·분**이다. 나중에 발생할 환자는 정책 입력에 넣지 않았다.

검증 시드 40101의 기한 뒤 회신 환경에서 P01은 **6.75→7.5분**으로 늦어졌다. 문의를 앞당기면 원래 3분 문의 기한도 앞당겨지고, 병원 내부 작업 뒤 도착한 회신을 놓칠 수 있다. 현재 정보만으로 그 비공개 작업 종료를 알았다고 가정하지 않았다.

무응답 환경은 일반 문의가 끝났을 때 선택적 재확인을 기다리지 않는 처리로 **9→7.5분**이었다. 실제 회신 전 부족 해소 환경은 **4.75→4.25분**이었다. 이 이득으로 다른 환자의 악화를 상쇄해 채택하지 않는다.

현재 정보에는 앞으로 발생할 환자, 병원 내부 심사 종료 예정, 병상 해소 예정이 없다. 보고가 부족하다는 이유만으로 재문의가 언제나 이롭다고 볼 수 없고, 새 문의가 실제 작업과 병상 경쟁을 만든다. 이번 결과는 그 비용을 드러낸다.

개발 시드 39101에서 부족 해소·계속 만석·늦은 회신의 세 환경은 첫 `shortage_probe` 순수 결정 함수에 전달된 **원시 입력 전체가 정확히 같았다.** 원본 gzip의 해시를 확인한 뒤 저장 입력끼리 비교했으며 모델을 재실행하거나 입력 필드를 숨기지 않았다. 같은 결정이 이후 다른 결과를 만든 것은 이번 함수의 공개 입력 범위 밖의 환경 차이다. 이것을 보고 곧 병상이 빈다고 예측하는 기능을 구현했다고 설명할 수는 없다.

## 채택 기준과 검증 범위

직전 안전 후보 대비 개인 처치·최종 도착 악화 및 처치 상실 0, 환경별 전체 대기·요청→처치 제한 합 비증가, 전체 문의 1.10배 이내, 전체 대기 엄격 감소를 요구했다. 기존 보호 V4에도 처치 상실과 환경별 대기·요청→처치 제한 합 증가를 금지하는 추가 조건을 유지했다. **직전 안전 후보 대비 평균이 좋아져도 한 환경의 대기가 늘거나 환자가 더 늦어지면 통과시키지 않았다.** 두 배정 알고리즘 모두 개발의 기존 보호 V4 유지 선택을 검증에서도 그대로 사용했다. 실제 운영 기본 고정3도 바꾸지 않았다.

전체 대기는 이동을 제외한 탐색·병원 대기·전원 준비 합이다. 요청→처치는 미처치를 동일 관찰 종료로 제한한다. 이번 모형의 병원 내 대기 합은 0이며 실제 응급실 대기 감소를 증명하지 않는다. 우선순위는 공급된 합성 값으로 자동 임상 응급도 판정이 아니다.

운영 서버의 순수 문의 선택기를 공유 시뮬레이션에 연결한 실험이다. 운영 HTTP·DB 전체 흐름이나 전역 300초 기한, 별도 네트워크 수신 지연, 실제 임상 성과, 향후 병상 가용 예측은 검증하지 않는다. 기존 감사기의 도착 후 요구 역량 추가 처리 한계도 유지한다.

## 증거와 파일

신규 121개를 포함한 **1,701개 테스트**가 통과했다. 기존 선택적 로컬 HTTP 바인딩 시험 6개 제외 목록은 유지했다. 작은 구조 시드 7/8의 332회 통합 실행·감사도 통과했다. 이 통과는 원장·제약의 정합성을 뜻하며 성능 채택 통과와 구분한다.

저장된 개발 1,992회·검증 3,984회·과거 회귀 152회, 합계 **6,128회**의 원시 증거를 엔진·솔버 import 없이 별도 프로세스에서 다시 감사했다. 원 문의·보충·재확인의 실제 출처, 원 기한과 FIFO 심사, 기존 정보·수용·비차단 준비 사건·배정 모형·실제 자원 게이트·이동·대기를 재구성하고 환자별 비교와 전체 집계 및 개발 선택을 독립 계산했다.

원 입력·압축·복원 원문·잠긴 소스 122개의 SHA-256을 확인했다. 이전 3,113개 파일의 변경은 0개다. 시드 최초 스캔의 비표준 vendor JSON 3개 제외 내역도 남겼고, 고정 보존 자료의 실제 실험 JSON/GZIP 스칼라·배열 시드를 별도로 확인했다. 모든 결과는 새 경로에 저장했다.
