# 문의 정책과 H1·C1 공동 배정 개선

2026-10-16 · 합성 전체 이송 실험 · 운영 기본 정책 유지

문의 정책도 개선 대상으로 포함했다. V3 기반의 **저부하 관측 보완 후보 V4**를 추가하고, 기존 C1 실험의 백업 문의 보존·돌발 병상 중단 회복을 H1에도 적용했다. 문의와 공동 배정 사이에서 새로 드러난 희소 병상 경쟁에는 **진행 중인 원 문의를 근거로 한 최대 1분 기회 보호**를 추가했다.

운영 서버의 정책 등록·기본값·DB·팀원 화면은 바꾸지 않았다. `server/inquiry_v4.py`는 독립 순수 계산 후보이며, 새 결합 엔진에서 검증했다.

## 문의 정책 변경

V4는 기존 V3의 실제 계산 함수를 먼저 호출한다. V3가 문의를 제안하면 그 결과를 그대로 유지한다. V3가 기다리기로 했을 때 다음 조건을 모두 만족하면 기존 비용 순위의 첫 후보 한 곳에 보완 문의한다.

- 최근 전송 이후 30초 이상 경과.
- 현재 대기 문의 1~2곳, 동시 문의·현재 에피소드 접촉 예산이 남음.
- 다른 환자의 미해결 문의가 없고, 추가 후보 병원에도 미해결 문의가 없음.
- 후보와 대기 병원의 최근 유효 회신 표본이 각각 2건 미만.
- 후보의 예상 이동시간이 현재 가장 가까운 대기 병원보다 120초 이내로 길음.

최근 15분 회신 범위, 15초 재평가와 기존 45초 추가 문의 방어 규칙을 유지했다. 병원 수용 확률이나 복구 예정 시각을 예측하지 않는다. 실제 수신한 이력, 이미 전송한 문의, 현재 이동시간 추정만 사용한다.

## 배정과 문의 사이의 희소 기회 보호

한 곳씩 문의하면 같은 시각의 두 환자가 서로 다른 시각에 수용 회신을 받는다. 선택지가 많은 환자가 먼저 배정되면, 해당 병원만 가능한 환자는 다음 공동 배정에 참여하기도 전에 병상을 잃을 수 있었다.

새 규칙은 이미 발생·등록된 탐색 환자가 구조적으로 한 병원만 가능하고, 그 병원으로 실제 진행 중인 문의가 있을 때만 적용한다. 현재 받은 병상 보고가 신선하고 충분하며 다른 필수 자원의 명백한 부족도 없어야 한다. 현재 수용된 유연한 환자 중 우선순위가 같거나 낮고 문의할 수 있는 다른 구조적 후보가 있는 환자만 잠시 유보한다.

유보는 원 문의 제출 후 1분, 원래 시간 초과, 유보된 환자의 최초 유보 후 1분 중 가장 이른 상한을 지킨다. 수용이 곧 만료되거나 더 높은 우선순위·대안 없는 환자에게는 적용하지 않는다. 유보된 환자의 대안 문의도 기존 후보 검사와 실제 V3/V4 선택 계산을 통과해야 한다. 아직 수용을 받지 않은 환자를 자원 배정 모형에 넣지 않는다.

설명용 구조 시험 시드 7에서는 단일 병원 환자의 처치 시작이 **24.25→3.5분**, 유연한 환자는 **3.25→5.75분**이었다. 두 환자의 합계는 18.25분 줄었지만 개인 간 절충이 남는다. **유보 상한 1분이 최종 처치 지연의 상한 1분이라는 뜻은 아니다.** 같은 입력의 고정3 결과 `[6, 3.5]`에 비하면 새 V3 결과 `[5.75, 3.5]`는 두 환자 모두 같거나 빠르다.

## H1의 돌발 중단 회복

기존 6건의 입력을 그대로 재실행했다. H1과 C1 각각 백업 보존 전후 4분기씩, 총 24분기를 원시 기록으로 감사했다.

| 원본 시드 | H1 보존 전→후 | C1 보존 전→후 |
|---|---:|---:|
| 28101 | 18→13분 | 18→13분 |
| 28102~28106 | 각각 19→14분 | 각각 19→14분 |

각 사례의 문의는 3→2건, 추가 자원 변화 보고는 0건이다. 원래 3분 전원 준비·이동·문의 기한·수용 만료를 유지했다. 이 사례는 과거 회귀이며 아래 새 검증 시드와 구분한다. H1 자체의 탐색 목적·50ms·최대 2,048회 설정은 유지하고, 문의·관측·회복 절차를 연결한 변경이다.

## 비교 설계

기존 48개 환경의 입력 전체를 그대로 보존하고, 희소 선택지·가까운 무응답·동시 FIFO 혼잡·늦은 회신·최근 이력 반전·표본과 창 경계·선정/도착 절충·확정 직후 병상 중단의 8개 환경을 추가했다.

10개 분기는 다음과 같다.

- 고정3 × H1/C1, 백업 회복 전후: 4개.
- V3/V4 × H1/C1, 같은 전체 회복·진행 문의 보호 적용: 4개.
- V3 × H1/C1, 진행 문의 보호를 끈 비교군: 2개.

모두 같은 15초 판단 격자를 사용한다. 시각은 실제 분이며 이동은 기존 분 단위 경로 반올림을 유지한다. 원본 분 단위 시계를 별도 교정 실행했을 때 기존 48개 환경의 환자 결과·자원 스냅샷이 정확히 같았다. 15초 판단 자체의 효과를 V4나 H1의 효과와 혼합하지 않는다.

실제 서버의 **순수 문의 선택 계산**을 공통 이송 루프에 연결했다. 서버 전체 워크플로를 재현한 것은 아니다. 공통 수용 후 대기 2분·재문의·전원 절차를 유지하며, 접촉 10건은 탐색 에피소드별 한도다. 운영 워크플로의 전체 300초 자동 문의 종료를 전체 이송에 적용하지 않았다. 만료 수용을 갱신하거나 미확인 수량을 가용으로 채우지 않는다.

개발 시드 31101~31103의 168사례·1,680분기를 실행했다. 소스 90개·설정·런타임과 개발 선택을 잠근 뒤 검증 시드 32101~32106을 실행했다. V4 선택 조건은 V3 대비 처치 상실 0, 개인 처치 악화 0, 문의 총량 1.10배 이내, 전체 제한 처치 도달 합의 엄격한 개선이며 H1/C1 각각 평가한다. 검증에서는 개발의 선택을 바꾸지 않는다.

## 새 검증 결과

**56환경 × 6개 새 시드 × 10분기 = 3,360회**, 분기당 환자 실행 708건을 비교했다. H1/C1은 이번 입력에서 각 환자의 선정·도착·처치 시각과 아래 집계가 같았다. 동일한 최적성이나 일반적인 동등 성능을 뜻하지 않는다.

| 공통 조건의 문의·회복 분기 | 미처치 | 전체 대기 합(환자·분) | 요청→처치 제한 합(분) | 환자 문의 | 수량 재확인 |
|---|---:|---:|---:|---:|---:|
| 고정3 · 백업 미보존 | 43 | 6,949.75 | 10,015.75 | 1,738 | 839 |
| 고정3 · 전체 회복 | 36 | **6,199.25** | **9,225.75** | **1,612** | **839** |
| V3 · 전체 회복·진행 문의 보호 | 36 | 6,403.25 | 9,350.75 | 1,620 | 849 |
| V4 후보 · 같은 회복·보호 | 36 | 6,400.25 | 9,347.75 | 1,620 | 849 |

**V4는 V3 대비 12건을 각각 15초 단축하고, 696건은 같으며 악화·처치 상실·추가 문의는 0건이었다.** 전체 제한 처치 도달 합의 감소는 3분이다. 개선 폭은 작다. 개발에서 고정한 선택 조건을 새 검증에서도 충족했지만, 이 조건의 비교 대상은 V3이며 고정3보다 우수하다는 승격 기준이 아니다.

V4의 개선 12건은 신규 `silent_first_options`·`late_reply_deadline`에서 각각 6건이다. 기존 48개 환경의 612건은 V3와 같았다. 신규 환경 전체 96건에서는 V3 대비 12건 단축·84건 동일이었다. 생성한 스트레스 환경의 이득을 일반적인 개선율로 확대하지 않는다.

**이번 전체 이송 입력에서는 고정3이 V3·V4보다 유리했다.** V3는 고정3 대비 43건 단축·240건 악화·425건 동일, 개인별 최대 추가 지연 8분이었다. V4의 전체 제한 처치 도달 합도 고정3보다 122분 많고 환자 문의가 8건 많았다. 유형 균등 제한 처치 평균도 고정3 12.4531분, V3 12.6387분, V4 12.6298분이었다. 따라서 운영 기본값 `fixed_3`를 유지한다. 기존 서버 문의 실험의 V3 장점이 이번 자원·이송 환경에 그대로 일반화된다고 주장하지 않는다.

기존 48개 환경에서는 고정3 대비 V3의 제한 처치 합이 169분 증가했고, 새 8개에서는 44분 감소했다. 새 8개에서 V4는 고정3보다 47분 감소했으나, 전체로는 기존 환경에서의 비용이 더 컸다. 기존 환경에는 문의 검토 부담을 FIFO로 모형화하지 않는 유형도 많다. 환경 구성과 문의·자원 관측 계약을 함께 읽어야 한다.

### 회복과 진행 문의 보호의 효과를 분리

같은 고정3에서 백업 회복을 켠 H1은 **60건 단축·0건 악화·648건 동일**, 관찰 종료까지 미처치는 **43→36건**이었다. 전체 대기 합은 750.5분, 제한 처치 도달 합은 790분 줄고 문의는 126건 줄었다. C1도 같은 집계였다. 기존 48개 환경의 54건과 신규 8개 환경의 6건이 단축됐다. 새로 처치한 7건이 포함되므로 공통 처치 환자의 평균 개선으로 해석하지 않는다.

V3에서 진행 문의 보호만 켠 비교는 **6건 단축·6건 악화·696건 동일**, 최대 악화 2.5분이었다. 전체 대기 합은 **105.5 환자·분**, 제한 처치 도달 합은 **93.5분** 감소했다. 환자 문의는 6건 줄었고 기존 수량 재확인은 6건 늘었다. 이 효과는 신규 희소 선택지 유형에서만 발생했으며, 기존 48개 환경의 612건 결과는 같았다. 단순히 대기를 다른 환자에게 옮긴 것인지 판단하도록 두 전체 합계와 개인별 절충을 같이 공개한다.

모든 분기의 추가 자원 변화 보고는 **0건**이다. 다만 기존 수량 재확인 횟수와 회신 내용은 배정 이후 점유·문의 시각에 따라 달라질 수 있다. 새 보고 채널을 추가하지 않았다는 뜻이며 모든 분기의 수신 보고가 완전히 같다는 뜻은 아니다.

## 검증과 보존

저장한 gzip 원시 사례를 별도 프로세스가 다시 읽어 SHA-256과 문의 원장·실제 수신 자원·현재 모형·최종 충돌 검사·물리 이동·전원 준비·전체 환자 지표를 확인한다. 감사기는 엔진이나 배정 솔버를 실행하지 않는다. 문의 선택 함수 재호출은 원시 입력을 독립 재구성한 뒤의 결정 재현 검사이며, 선택 정책의 최적성 증명으로 해석하지 않는다.

첫 개발 실행은 병원 FIFO 시작 로그 누락 때문에 106사례 뒤 중단됐다. 같은 시각의 마지막 재검토 단계에서 생성한 문의의 시작 로그가 기록 배출 이후에 남는 오류였다. 새 엔진의 기록만 수정했고, 개발 사례 31102의 10분기에서 환자 결과·배정·문의·실제 FIFO 작업시간은 수정 전과 완전히 같았다. 누락된 시작 로그 4개만 추가했으며 감사 조건은 완화하지 않았다. 중단된 기록을 보존하고 개발 전체를 `r2` 출력으로 다시 실행했다. 검증 시드는 이 수정 뒤에 처음 사용했다.

최종 저장 검증 336사례·3,360분기 재감사에서 배정 결정 6,238개, C1 현재 모형 증명·독립 열거 3,047개, H1 안전 기준 재계산 3,047개, 문의 입력 복원·선택 재현 57,506개, 이동 구간 7,368개와 원래 전원 준비 516건을 확인했다. 추가 자원 변화 보고·배정 제약 위반은 0건이다. 별도 감사 프로세스에 엔진·배정 솔버가 import되지 않았음을 확인했다.

신규 테스트는 **146개**, 관련 최종 소스의 고유 테스트는 **1,222개**를 확인했다. 넓은 회귀 1,219개와 최종 변경 모듈 99개 검사를 합친 수이며 중복을 제외했다. 이전부터 `WinError 10013`으로 사용할 수 없던 선택적 로컬 HTTP 바인딩 테스트 6개는 제외했고, 새 문의·결합 엔진·시나리오·감사·실행기 테스트는 모두 포함했다.

이전 소스·설정·결과·문서 **421개**의 SHA-256을 보존했고, 새 잠금 소스 **90개**가 일치했다. 첫 개발 중단 이후 문의 후보 파라미터·선택 기준을 바꾸지 않았으며, 검증 결과로 재튜닝하지 않았다. Python 3.12.14·OR-Tools 9.15.6755를 사용했다.

## 해석 범위와 남은 일

- 기존 48개 환경과 추가 8개 환경의 기여를 별도로 공개한다. 새 환경은 실패를 드러내기 위한 합성 스트레스 입력이며 현장 발생 분포가 아니다.
- 전체 대기는 탐색·병원 대기·전원 준비를 합산하고 이동을 제외한다. 요청→처치·선정·최종 도착은 미확보 환자를 같은 관찰 종료로 제한한다. 성공 환자만의 평균으로 실패를 숨기지 않는다.
- 이번 저장 결과의 병원 내부 대기 합은 0이었다. 병원 내부 대기열이나 실제 처치 지연 개선을 별도로 검증한 자료는 아니다.
- 진행 문의 보호는 개인별 비악화를 보장하지 않는다. 유효한 대안 수용이 이미 있는 환자도 전체가 잠시 유보될 수 있어 후보별 제약 방식의 추가 개선 여지가 있다.
- 지속 정보 누락과 실제 병상 부족은 남는다. 현재 모형 증명은 실제 전체 이송의 전역 최적성이나 임상 안전성 증명이 아니다.
- 운영 적용 전 실제 워크플로의 300초 종료·동시 작업 취소 규칙과 결합한 검증이 필요하다. 이번 결합 엔진은 제출된 병원 업무를 취소하지 않는 기존 전체 이송 환경을 따른다.
