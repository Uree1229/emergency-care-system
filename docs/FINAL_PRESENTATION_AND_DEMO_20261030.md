## 정상과 조건 변경과 실패 시연

저장소 루트에서 실행한다. 설치된 Python 3.12 환경을 사용한다.

```powershell
python -m simulation.viewer_server --port 18045 --reuse-data --no-browser
```

기존 서버와 포트가 겹치면 다른 포트를 사용한다. 이 뷰어는 저장된 재생 파일만 제공하며 병원·환자 DB를 열지 않는다. 이번 검증에 사용한 로컬 주소는 다음과 같다.

| 순서 | 주소와 이동 | 확인할 내용 |
|---|---|---|
| 정상 | [정상 수용과 도착](http://127.0.0.1:18045/?scenario=voice-road-normal_arrival), 처음→수용→확정→출발→끝 | 수용과 추천만으로 확정되지 않음. 마지막 목적지는 H1, 저장된 도착 사건 이후 ARRIVED |
| 조건 변경 | [대체 수용과 사람의 변경](http://127.0.0.1:18045/?scenario=voice-road-enroute_resource_reroute), #66→#72→끝 | #66은 H2 수용 확보 후에도 H1 유지·목적지 변경 0. #72의 명시적 변경 이후 H2. 마지막 저장된 도착 확인 |
| 실패 | [무응답과 미배정](http://127.0.0.1:18045/?scenario=voice-road-no_hospital_response), 끝 | 문의 마감 EXHAUSTED, 환자는 WAITING, 목적지 없음. 무응답을 수용·도착으로 만들어내지 않음 |

추가 사례는 [음성 치료조건 변경](http://127.0.0.1:18045/?scenario=voice-waiting_treatment_change), [필수 정보 누락](http://127.0.0.1:18045/?scenario=voice-missing_r1_rejected), [병원의 수용 유지](http://127.0.0.1:18045/?scenario=voice-road-enroute_resource_keep)다. 수용 유지 사례는 IN_TRANSIT에서 관찰이 끝나므로 도착 완료로 설명하지 않는다.

재생축 **#번호는 사건 탐색 순서**이고 실제 경과초는 사건에 따로 표시된다. 기본 9종은 같은 초의 독립 로그 간 정확한 교차 선후를 입증하지 않는다. 카카오 4종은 API 사이 통제시계를 진행하지만 이 간격도 사람의 입력·검토시간은 아니다.

도로 자료와 형상은 저장 JSON에서 재생한다. 인터넷 없이 발표할 때는 지도 배경을 **간략지도**로 바꾸고 저장 경로·사건·상태를 확인한다. 지도 배경 타일 실패와 길찾기 입력 실패를 구분한다. 이번 준비물은 재생 JSON과 화면 캡처이며 녹화 영상은 별도로 준비해야 한다.
