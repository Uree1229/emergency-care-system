# 전체 흐름 관제 화면

`/flow-console.html`에서 환자 앱, 구급대 기록, 병원 웹과 서버 대화·업무 기록을 같은 창에서 확인합니다. PC 시연용 합성 데이터에만 연결됩니다.

## 실행

저장소 루트에서 프로젝트의 Python 환경과 고정 의존성을 준비합니다. 새 가상 시연 DB 경로를 사용하면 초기 합성 병원 10곳이 생성됩니다. 기존 공통 DB를 지정하면 기록과 자원 관측시각을 보존하며 재사용합니다.

```powershell
python -m pip install -r requirements/requirements-server.txt
python -B -m server.flow_console_runtime --db data/flow-console-demo.db --mode full --port 18035 --run-dir .codex-build/flow-console/run-001
```

브라우저에서 <http://127.0.0.1:18035/flow-console.html>을 엽니다. `--run-dir`는 실행마다 새 경로를 지정합니다. 종료는 터미널의 Ctrl+C 또는 해당 실행 폴더에 `stop-requested.json` 파일을 만드는 방식입니다. 포트를 점유한 기존 서버를 강제로 종료하지 않습니다. `voice-only` 모드는 음성 화면만 점검할 때 사용하며 추천·문의 워커가 실행되지 않습니다.

## 시연 순서

1. 위쪽 이송 선택에서 새 이송을 선택하고 적용합니다. 환자 앱 또는 구급대 화면에서 가상 환자를 등록합니다.
2. 병원 문의를 시작한 뒤 오른쪽 병원에서 담당자를 입력하고 검토·응답합니다.
3. 환자 화면에서 수용 응답을 확인하고 목적지를 직접 확정합니다.
4. 두 화면에서 대화를 보내고 아래 대화·기록의 동기화를 확인합니다.
5. 출발·도착을 명시적으로 처리하면서 위쪽 진행 단계를 확인합니다.

각 패널의 확장 버튼으로 작업 화면을 크게 볼 수 있습니다. 좁은 화면은 역할 탭을 사용합니다. 환자나 병원을 바꾸려면 위쪽 선택 후 적용합니다. 미저장 입력·녹음·결과가 미확인인 요청이 있으면 먼저 해당 화면에서 처리해야 합니다. 이미 등록된 환자의 구급대 기록은 환자 기록 연결 버튼으로 명시적으로 불러옵니다.

## 연결 범위

새 `GET /api/flow-console`은 `pid` 또는 `sid` 하나로 선택한 기록만 읽습니다. 병원·환자·초안 목록은 제한된 메타데이터이며, 원본 음성 문장과 연락처는 포함하지 않습니다. 스냅샷은 별도 SQLite 읽기 전용 연결과 읽기 트랜잭션을 사용합니다. 실제 등록·문의·수용·확정·메시지 전송은 기존 역할 화면과 API를 그대로 사용합니다. 기존 역할 API의 조회 시점 만료 처리 등도 그대로 적용됩니다.

서버는 `127.0.0.1`에만 바인딩합니다. 실제 병원 연결이나 외부 메시지 발송은 없으며, 문의 수용만으로 목적지가 자동 확정되지 않습니다. 공개 병원 데이터 모드·외부 호스팅·운영용 인증은 이번 범위에 포함되지 않습니다.

## 검증

```powershell
python -B scripts/test_suites.py python test_flow_console
node --test tests/browser/test_paramedic_flow_console_state.mjs tests/browser/test_paramedic_flow_console_entry.mjs tests/browser/test_paramedic_draft_handoff.mjs
```

읽기 전용 DB 보존, 선택 범위, 잘못된 쿼리, 기존 처리기 위임·실행기 종료, 지연 응답 취소, 초안 소유자·버전과 미전송 문장 보존을 검사합니다. 별도 합성 DB에서 full 실행 시작·관제 API·세 역할 화면의 HTTP 응답·정상 종료를 확인했습니다. 같은 기능 소스의 별도 합성 실행본에서 Chromium UI로 가상 환자 등록 → 세 병원 문의 → 병원 수용 → 담당자 목적지 확정 → 양쪽 메시지 → 출발 → 병원 도착 흐름과 자동 갱신을 확인했습니다. 이는 실제 마이크·기기·소음·임상 사용성 평가를 대신하지 않습니다.
