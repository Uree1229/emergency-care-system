# 서버·자동 작업 상태 조회

기준: 2026-10-14. `GET /api/system/status`는 DB의 읽기 가능 여부, 현재 서버 프로세스의 워커 상태, 저장된 작업·추천·데이터 갱신 현황을 반환한다. 조회가 병원 문의나 배정 계산을 실행하지는 않는다.

현재 시연 주소: `http://127.0.0.1:18027/api/system/status`

## 무엇을 확인할 수 있는가

| 응답 영역 | 의미 |
|---|---|
| `server` | 상태 관측 시작 시각과 서버 가동 시간 |
| `database` | 제한 시간 안에 필요한 DB 정보를 읽을 수 있었는지 |
| `workers.planning` | 현재 프로세스의 배정 워커 실행·지연·오류·중단 상태 |
| `workers.inquiry` | 현재 프로세스의 초기 문의·조건 감시·대체 문의 워커 상태 |
| `planning` | 현재/완료 입력 버전, 처리 대기, 활성 lease, 유효/오래된 추천 건수와 마지막 결과 시각 |
| `workflows.initial` | 초기 자동 문의의 활성·처리 시각 도달·오류 건수와 상태별 집계 |
| `workflows.alternative` | 확정 이후 대체 문의의 같은 집계 |
| `workflows.transport_reviews` | 감시 활성·재확인 필요·오류 건수와 마지막 점검 시각 |
| `data` | 병원·운영 자원 수, 오래된 운영 자원 수, 공공 관측 수집·관측 시각과 NMC 기본 수집 이력 |
| `issues` | 현재 확인된 워커·작업·배정·NMC 기본 수집 오류의 코드와 해당 영역 |

추천이 대기 중인 것과 워커가 멈춘 것은 별개다. `planning.pending`는 입력 버전이 완료 버전과 다르거나 만료된 추천이 남아 있는지를 나타낸다. `lease_active`는 계산 소유권 또는 재시도 대기를 포함하므로 이것만으로 솔버가 실행 중이라고 해석하지 않는다. 추천의 `fresh`는 입력 버전이 현재와 같고 유효기간이 남아 있는 결과다.

워커의 성공은 **한 점검 주기가 예외 없이 끝났다**는 뜻이다. 처리할 일이 없어도 정상 주기로 기록한다. 개별 환자 작업이 내부에서 오류 상태로 끝날 수 있으므로 워커가 `RUNNING`이어도 `workflows.*.errors`가 존재할 수 있다.

## 상태와 HTTP 코드

| 전체 `status` | 의미 |
|---|---|
| `OK` | DB 조회 성공. 등록된 워커·저장된 작업에 현재 확인된 오류 없음 |
| `DEGRADED` | DB 조회는 성공했으나 워커 지연·오류·중단 또는 저장된 작업 오류 등이 있음 |
| `UNKNOWN` | DB 조회는 성공했으나 현재 프로세스의 일부 워커가 관측기에 등록되지 않음 |
| `UNAVAILABLE` | 제한 시간 내 DB 정보를 읽지 못함. 파일 없음·읽기 실패·잠금·필수 스키마 누락 등 |

DB를 읽을 수 있으면 진단 결과 조회 자체는 HTTP 200이다. 따라서 **200만 보고 정상이라고 표시하지 말고 본문의 `status`와 각 영역을 함께 읽는다.** DB를 읽지 못하면 HTTP 503이며 `database.error_code=DATABASE_UNAVAILABLE`, DB 집계 영역은 null이다. 이 API는 읽기 상태 진단이며 DB 쓰기 가능성·전체 무결성·의료적 수용 가능성을 보장하지 않는다.

| 워커 `state` | 의미 |
|---|---|
| `UNKNOWN` | 관측기에 등록하지 않음. 다른 프로세스가 실행 중일 가능성은 추정하지 않음 |
| `DISABLED` | 기동 옵션이나 시연 구성에서 명시적으로 꺼 둠 |
| `STARTING` | 구성되었으나 첫 처리 주기를 아직 확인하지 못함 |
| `RUNNING` | 스레드가 살아 있고 최근 주기를 정상적으로 관측함 |
| `ERROR` | 최근 주기가 실패했고 아직 정상 주기로 회복되지 않음 |
| `STALLED` | 스레드는 살아 있으나 시작/종료 기록 갱신이 설정 시간보다 오래 지연됨 |
| `STOPPING` | 중지 요청이 들어왔고 스레드가 아직 종료되지 않음 |
| `STOPPED` | 시작했던 스레드가 종료됨 |

`STALLED`는 지연 경고이며 교착이나 사망의 증명이 아니다. 기본 경고 기준은 배정 360초, 문의 180초다. 많은 후보의 외부 이동시간 조회 등으로 실제 처리 시간이 길어질 수 있다. 시간 간격은 시스템 시각 변경에 흔들리지 않도록 단조 시계로 측정한다. `phase`의 `BUSY`/`IDLE`은 관측 주기 안/밖을 뜻한다.

`last_error_code`는 이후 성공 주기가 오면 해제한다. 과거 실패 시각과 총 실패 횟수는 서버가 살아 있는 동안 유지하며, 프로세스를 다시 시작하면 메모리 카운터가 초기화된다. DB에 남은 개별 작업 오류는 별도 집계한다.

## 실행 구성

- `server.app`는 `--no-planner`, `--no-inquiry-worker`를 반영해 꺼 둔 워커를 `DISABLED`로 등록한다.
- `server.team_demo`와 `server.chat_demo`는 배정 워커를 사용하지 않으므로 배정은 `DISABLED`, 문의는 실제 실행 상태를 표시한다.
- 별도 실행기에서 `make_handler`만 호출하면 워커는 기본 `UNKNOWN`이다. 실행기가 `RuntimeStatus`에 워커를 등록하고 `make_handler(..., runtime=runtime)`에 전달해야 한다.
- 현재 18027 시연은 배정 워커를 명시적으로 끄고 문의 워커를 실행하는 구성이다. 배정이 `DISABLED`인 것은 고장이 아니다.

## 데이터와 공개 범위

공공 자료의 `latest_fetched_at`과 `latest_observed_at`을 구분한다. 최근에 내려받았어도 원천 관측 시각이 오래됐거나 없을 수 있다. `unknown_observed_at`은 오래됐다고 단정하지 않고 별도 집계한다. 신선도 기준은 기존 서버의 600초 설정을 사용하며 임상 기준이 아니다. 전체 `OK`는 모든 공공 관측이 최신이라는 뜻이 아니다.

현재 `data.public_sync`는 `public_sync_runs`에 저장된 **NMC 기본 수집 이력**이다. 심평원·별도 수용 메시지 수집 이력이나 외부 수집 프로세스의 생존 여부까지 표시하지 않는다. 저장된 최근 수집 상태가 `RUNNING`이어도 실제 수집 프로세스가 현재 살아 있다는 뜻은 아니다.

응답은 건수·설정된 상태 코드·시각만 포함한다. 환자 ID·인적사항·증상·대화·DB 경로·lease 소유자·인증키·예외 원문은 보내지 않는다. 오류 코드는 `PLANNING_FAILED`, `INQUIRY_FAILED`, `WORKER_FAILED`, `PUBLIC_SYNC_FAILED`, `DATABASE_UNAVAILABLE` 등 고정 값으로 제한한다. 시연 서버의 기존 접근 정책을 따르며 인증 기능을 새로 추가하지 않는다.

DB는 별도의 `mode=ro` 연결과 한 읽기 트랜잭션에서 조회한다. 기본 조회 제한은 0.25초다. 파일 생성·스키마 초기화·WAL 설정 변경·수용 응답 만료·문의 진행·외부 API 호출을 하지 않는다. 워커 생존 기록도 DB에 쓰지 않으므로 상태 관측 때문에 배정 입력 버전이 증가하지 않는다.

## 검증과 후속 작업

신규 `test_system_status.py` 26개가 통과했다. 워커 오류·복구·중지·동시 조회, 조회 전후 DB 보존, 없는·손상된·이전 스키마·잠긴 DB의 처리와 회복, 상태와 큐의 구분, 개인정보 비노출을 확인했다. 외부 유입 및 기존 서버·화면 연결·지도 재생을 포함한 전체 회귀 테스트는 600개 통과했다.

현재 기능은 조회 API다. 팀원 화면에 상태 표시를 추가하거나 오류를 외부로 통보하는 기능은 별도 작업이다. 다음 서버 과제는 팀원 화면의 공통 API 연결을 확인하고 추천 결과 표시·다중 기기 시연을 검증하는 것이다.
