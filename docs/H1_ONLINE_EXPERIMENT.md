# H1 전체 이송 실험

2026-10-15. 기존 H1 배정 알고리즘을 환자 발생·문의·수용 응답·목적지 확정·이송·재배정·도착·모의 치료까지 이어지는 별도 실험에 연결했다. 과거 잠금 실험의 소스와 결과, 운영 서버·DB, 환자용·병원용 앱은 수정하지 않았다.

## 첫 검증 결과

개발 27사례·81실행 후 소스·설정·런타임을 잠그고, 새 seed의 54사례·162실행을 검증했다. 각 규칙의 환자 실행 수는 216건이다.

| 규칙 | 미배정 | 미도착 | 문의 | 재배정 | 전원 |
|---|---:|---:|---:|---:|---:|
| R1 | 54 | 54 | 1,162 | 6 | 6 |
| H1 | 20 | 20 | 618 | 6 | 6 |
| C1 | 20 | 20 | 618 | 6 | 6 |

H1과 R1이 모두 최종 도착한 160건은 H1에서 평균 3.75분 늦었다. 60건 지연·100건 동일이며 최대 지연은 47분이다. H1에서만 도착한 건은 36건, R1에서만 도착한 건은 2건으로 순증 34건이다. 따라서 미배정 감소를 기존 모든 환자의 도착 단축으로 해석하지 않는다. 긴 우회 조건의 지연과 희소 후보 함정의 개선을 함께 읽어야 한다.

전체 자원이 없는 대조군은 세 규칙 모두 실패했고, 시간차 발생·이송 중 자원 변경·도착 후 전원에서는 이번 입력의 주요 결과가 같았다. H1과 C1의 전체 실패·문의 수가 같다는 사실만으로 같은 배정안이나 동등한 최적성을 주장하지 않는다.

관련 테스트 134개, 검증 330개 배정 결정의 원시 감사, H1 72배치 기준안 재계산이 통과했다. 후보·자원 제약 위반은 0건이다. 기존 소스·설정·결과 168개 파일의 SHA-256 보존도 확인했다. 검증 seed 16101–16106은 이후 개선의 독립 검증으로 재사용하지 않는다.

## 비교 조건

| 항목 | 설정 |
|---|---|
| 배정 규칙 | R1 / H1 / C1 |
| 문의 | 고정 3곳, 첫 유효 수용 이후 남은 응답을 최대 2분 추가 대기 |
| 조건 변경 | 같은 외부 사건과 알림·재문의·전원 규칙 |
| H1 | 기존 개발 선택 그대로: 추가 탐색 50ms, 최대 2,048개 수정 후보 평가 |
| C1 | 모델 작성과 두 단계 탐색의 합산 예산 50ms, 단일 검색 워커 |
| 입력 정보 | 현재 받은 유효 수용 응답·현재 위치의 이동시간 추정·현재 잔여 자원 |
| 개발 | seed 15101–15103, 9유형 × 3seed × 3규칙 = 81실행 |
| 검증 | seed 16101–16106, 9유형 × 6seed × 3규칙 = 162실행 |
| 실행 순서 | seed 순서와 유형 순서에 따라 R1/H1/C1 회전. 각 유형에서도 순서를 균형 있게 배치 |

같은 잠재 회신 환경을 복사하지만, 배정이 달라지면 이후 자원과 실제 수용 응답 목록도 달라진다. 따라서 이 비교는 수용 후보를 고정한 정적 배정 비교와 다르다. H1의 배치별 기준안 비악화는 전체 이송 과정의 도착시간 비악화를 뜻하지 않는다.

H1과 C1의 50ms는 숫자가 같아도 측정 범위가 다르다. H1은 스냅샷·기준안 이후의 추가 탐색이고 C1은 기준안과 최초 라이브러리 로딩 이후의 모델 작성·탐색이다. 전체 호출시간도 별도로 기록하며 강제 50ms 종료를 주장하지 않는다. 계산시간은 기존 분 단위 모의 시계에 더하지 않는다.

## 구조와 기록

- `simulation/h1_online_engine.py`: 기존 이송 엔진에 새로운 규칙 객체를 주입한다. H1/C1에 현재 정보만 복사한 뷰를 전달한다.
- `simulation/h1_online_experiment.py`: 독립 개발·검증 실행기, 회전 순서·소스/설정/런타임 잠금·결과표를 관리한다.
- `simulation/h1_online_audit.py`: 시뮬레이터나 솔버를 실행하지 않고 원시 이벤트·입력·배정 기록으로 결과를 재계산한다.

H1의 기록은 `heuristic_records`, C1의 증명 기록은 `solver_records`로 분리한다. H1은 `HEURISTIC`, 최적성 확인은 항상 false다. C1의 최적성도 현재 같은 분에 준비된 환자 묶음 안에서만 적용한다. 이송 중 단일 대체 병원 선택은 양쪽 모두 기존 근거리 규칙이다.

## 보는 지표

- 미배정·미도착·모의 치료 미시작 수와 우선순위별 분모
- 선정·최종 도착·모의 치료 시작의 조건부 평균과 관찰 종료를 포함한 제한 평균
- R1과 양쪽 모두 도착한 동일 환자의 시간 차이, 한쪽만 도착한 수, 더 늦어진 환자 수·최대 지연
- 도착 P95와 해당 분모, 환자당 문의, 재배정·전원·조건 변경 알림
- 배정 호출시간 P95·최댓값·호출 수, H1 수정 후보 수와 C1 최적성·대체 실행

전체 집계는 환자 실행 수를 명시한다. 여러 사례에 같은 환자 ID가 반복돼도 서로 다른 실행이다. 공통 환자 비교는 같은 사례 안의 같은 ID를 연결한다. 실패 환자를 빼고 도착 평균만 비교하지 않는다.

## 재현

OR-Tools가 설치된 Python이 필요하다. 프로젝트의 `.solver_deps`를 사용하는 PowerShell 예시는 다음과 같다.

```powershell
$env:PYTHONPATH = (Resolve-Path -LiteralPath .solver_deps).Path
python -B -m simulation.h1_online_experiment --phase development --lock
python -B -m simulation.h1_online_experiment --phase validation
python -B -m simulation.h1_online_audit simulation_results/h1_online_validation_20261015.json --lock config/h1_online_lock_20261015.json
```

실행기는 기존 JSON·Markdown·감사 결과·잠금 파일을 덮어쓰지 않는다. 이미 결과가 있으면 `--output`으로 새 파일 경로를 지정한다. 개발 잠금까지 다시 만들려면 `--lock-file`도 새 경로를 지정한다. 검증은 잠금과 소스·설정·런타임·seed가 달라지면 실행 전에 중단한다.

Windows 샌드박스에서 기본 임시 폴더 정리가 거부되는 경우, 테스트용 `TEMP`와 `TMP`를 작업 폴더 아래에 지정하고 테스트한다. 과거 테스트 소스를 수정해 우회하지 않는다.

## 해석 범위와 다음 작업

이 단계는 고정 문의 정책을 사용하는 H1 전체 이송 연결과 검증이다. V3 통합이나 정보 노후화 효과를 검증한 결과가 아니다. 환자·병원·회신·자원·치료시간·위치·경로는 합성이며, 실제 카카오 API 도로 시연과도 구분한다.

다음은 관측 누락·지연과 돌발 유입이 있는 조건에서 정책에 보이는 정보와 환경의 실제 상태를 분리하는 실험이다. 이후 V3와 배정 규칙을 함께 비교한다. 운영 서버의 시간축 추천 모델이나 팀원 화면에 H1을 자동 활성화하지 않는다.
