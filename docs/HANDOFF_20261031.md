# 인계: 남은 기간의 개선 방향 (2026-10-31)

**결론: 기능을 더 만들지 않는다. "실제로 일이 줄었는가"를 사람으로 증명하고, 단순하게 보여준다.**

|---|---|

| 실제 검증 | 거의 없음. 사람 대상 측정 0명, 실기기는 이 PC 한 대 |

## 근거

- 중간 피어리뷰 22건 중 13건이 입력·화면 복잡도, 8건이 전화와 채팅의 역할이었다. 요지는 "업무가 줄어드는지 설득되지 않았다"였고, 이에 대한 실측이 없다 ([피어리뷰 분석](reviews/피어리뷰_분석과_개선계획_20261028.md)).
- 알고리즘은 한계에 도달했다. 23~29차 후보는 효과가 수 초 이내로 7회 연속 미채택이었고, H1·W1도 미채택으로 연구를 닫았다.
- 같은 시뮬레이션에서 병원 쪽 업무 흐름이 더 큰 효과를 냈다. 검토시간 20% 단축 −28~−56초, 빠른 거절 50% −12~−29초. 합성 가정이므로 방향 근거로만 쓴다.

## 방향 3가지

**1. 증명: 사람으로 잰다 (최우선)**
- 11/2 팀 LAN에서 휴대폰+PC 실기기 전체 흐름을 먼저 통과시킨다. 측정의 전제다.
- 수동/음성 짝비교를 한다. 구급대 역할은 첫 문의까지 시간·수정·오입력, 병원 역할은 실제 검토시간. 학생 참여자도 "학생 대상"으로 밝히면 된다. 도구와 양식은 [사용성 평가](USABILITY_EVALUATION_20261030.md)에 있다.
- 측정 전 버전을 동결하고 성공 기준을 미리 고정한다.
- 구급대 쪽 계측(시작/종료·수정·터치)을 연결한다. 간편 음성 화면(`paramedic-ui`)은 Claude, 메인 화면은 같은 계약으로 화면 담당이 맡는다.

**2. 단순화: 보이는 것을 줄인다**
- 구급대 화면은 "지금 상태 + 다음 행동"만, 병원 화면은 한 화면 요약·한 번 누르는 결정·취소 즉시 표시. 위 시뮬레이션 수치를 화면 담당에게 근거로 전달한다.
- 시연 진입점을 하나로 합친다. 지금은 `index`·`demo`·`lab` 세 개다.
- 발표·문서는 주장 3개와 근거만 두고, 단서는 부록으로 보낸다.

**3. 정리: 같은 버전, 사라지지 않는 결과**
- 실행본은 커밋에서 묶는다. 10-30에 미완성 `index.html`이 작업 폴더에서 그대로 실행본에 들어간 사고가 있었다 ([경위](SIM_VIEWER_LAB_20261030.md)).
- 측정 기간에는 기능을 바꾸지 않는다.
- git 밖 결과 원자료(약 6GB)의 백업 여부를 확인한다.

## 하지 않을 것

새 알고리즘 실험, 수용 예측 모델, 블루투스 PTT·푸시 알림, 운영용 로그인·HTTPS(시연용 접속 암호만 유지), 문서 변형 추가.

## 발표 뼈대

1. 문제: "후보가 보인다"와 "이 환자를 받는다"는 다르다. 여기에 입력·전화 부담이 더해진다.
2. 입력 부담: 필수 5칸 최소 입력 + 음성 초안 → 사람 확인. **실측 결과**를 붙인다.
3. 전화는 유지하고 진행·기록만 공유한다.
4. 차별점: 명시적 수용, 사람의 확정, 확정 후 재확인. 새 화면(`lab.html`) 발표 탭으로 시연한다.
5. 알고리즘은 좋았던 곳과 나빴던 곳을 그대로, 병상·인력 부족은 소프트웨어로 못 푼다는 한계도 밝힌다.

## main 병합 (10-31 오전, 사용자 결정)

처음에는 Codex에 맡기기로 했으나 사용자 결정으로 Claude가 병합했다.

- **기준:** 공용 작업 폴더의 00:27 상태다. 그 뒤 10시간 넘게 변경이 없었고 11:13 복사 중에도 바뀐 파일이 없었다. 로컬 기준 커밋 `38d2144` 위에 스냅샷 커밋을 만들고 `origin/main`(`9a7215e`)을 합쳤다. 공용 작업 폴더의 파일·브랜치·인덱스는 건드리지 않았다.
- **포함:** 서버·음성·구급대원 화면(`paramedic-ui`)·팀 실행·시뮬레이션·연구·문서. 사용자 승인으로 `patient-ui`·`hospital-ui`의 화면 연결 15개를 내용 수정 없이 넣었다. `emergency-app`은 main 버전을 유지했다.
- **충돌 23개:** Codex 팀 실행본 v1.1과 같은 17개와 `VOICE_INPUT_API.md`는 로컬 쪽을 택했다. main 쪽에만 있던 문장은 '서버 전용 PR에는 화면이 없다'는 안내였다. 끝 빈 줄·줄바꿈만 다른 5개는 main 쪽이다. `README.md`는 로컬 첫 문단과 main의 '11월 2일 연결 시험용 서버'·'이전 팀원 연결본 실행' 절을 모두 남겼다. main이 더 최신이던 16개와 main에만 있던 6개는 main 쪽을 유지했다.
- **검증:** Node 화면 테스트 1,509개 통과(Python 하네스가 띄우는 `test_hospital_operations_http.mjs`는 단독 실행 제외). 서버 관련 Python 90개 모듈 1,325개 중 실패·오류 32개는 병합 전 스냅샷에서도 같은 환경에서 똑같이 났다. 원인은 새 체크아웃의 CRLF와 LF로 고정된 기준 소스 해시의 차이(`solver_improved.py` 등), 임시 폴더에 없는 git 밖 원자료, 원래 작업 폴더에서도 실행마다 결과가 바뀌는 `test_server_inquiry_experiment`다. 병합으로 새로 생긴 실패는 없다.
- **포함하지 않은 것:** Codex가 11:15부터 진행 중인 구급대원 메인 화면 복구(`paramedic-ui/app.js`·`index.html`·`main-recovery.mjs`와 테스트 2개). 작업을 마친 뒤 새 main 위에서 후속 PR로 올린다.
