# 문의 정책·배정 알고리즘

2026-11-05 기준으로 운영 설정과 연구 후보를 정리했다. 채택 결정은 [`final_algorithm_decision_20261030.json`](../config/final_algorithm_decision_20261030.json)에 보존돼 있다.

## 현재 설정

| 범위 | 설정 |
| --- | --- |
| 운영 기본 문의 | `fixed_3` |
| 전체 서버 배정 | CP-SAT `severity_first`, 계산 예산 3초 |
| 문의·화면 시연 `chat_demo` | 문의 워커 켬, 배정 워커 끔 |
| 공통 서버 `team_runtime full` | 문의·배정 워커 켬 |
| `team_runtime voice-only` | 두 워커 끔 |

문의는 어떤 병원에 언제 물을지를 정한다. 배정 추천은 유효한 수용 후보와 자원 제약에서 환자들의 배정안을 계산한다. 목적지 확정은 담당자가 유효한 병원 수용 응답을 확인한 뒤 별도 API로 수행한다.

`GET /api/inquiry-policies`가 실제 선택 가능한 이름과 설정을 반환한다. `fixed_1/3/5`와 관측형 `observed_v2`, `observed_v3`를 제공하며 기본은 `fixed_3`이다. 정책별 지연·한도·관측 사용 방법은 [문의 워커 계약](INQUIRY_WORKFLOW.md)에 있다. 실행 중 정책 변경에는 일시정지 등 해당 계약의 조건을 적용한다.

## 배정 목적과 입력

전체 서버는 우선순위군별 미배정 수와 시작 지연을 사전식으로 최소화하는 `severity_first`를 사용한다. 현재 후보·자원, 예상 이동시간과 치료 일정의 제약을 계산한다. `ed_bed`와 `special_team`을 모델링하고, 미지원 자원이나 확인되지 않은 조건은 별도 확인 대상으로 남긴다. 공개 가용 관측만으로 수용 응답을 만들지 않는다.

서버의 고정 기준은 [`server_allocation_baseline_20261030.json`](../config/server_allocation_baseline_20261030.json)과 [`team_runtime_profile_20261030.json`](../config/team_runtime_profile_20261030.json)에 있다. 이 파일의 소스 해시·환경·기준을 바꾸면 같은 고정 실험으로 집계할 수 없다. 실행기의 원본 일치 검사와 검증 지침은 [실행](RUNNING.md), [검증](TESTING.md)에 있다.

## 연구 후보와 채택 상태

| 후보 | 현재 판단 |
| --- | --- |
| H1 공동 배정 | 운영 기본으로 미채택. 미배정 개선과 개인 도착 지연의 상충을 보존 |
| W1 대기 보호 | 미채택. 기존 환자 개선이 다른 환자의 지연으로 옮겨간 결과를 보존 |
| G 계열·QI/QJ | 각각의 고정 연구 결과와 선택 여부를 유지 |
| EAT 문의·공동 평가 | 별도 문의 연구. 서버 기본 설정으로 자동 반영하지 않음 |

H1 연구는 가중 미배정 합과 가중 이동시간을 사용하며, 운영 서버와 목적·일정 표현·계산 예산이 다르다. 원 36환경의 H1 개인 최대 67분 추가 지연은 채택 결정에 남아 있다. 평균 시간, 미배정, 도착·치료 시작 기록과 우선군·개인 결과를 함께 읽는다. 제한 시간차가 0이어도 도착 기록을 잃은 경우는 별도 실패로 센다.

## 연구 기록을 찾을 때

최종 결정의 상세 근거는 [고정 정책과 사례 분석](FINAL_ALGORITHM_DECISION_20261030.md), 후속 대기는 [W1 기록](WAITING_PROTECTION_20261030.md)에 있다. 실험 당시 결과는 `simulation_results/`와 개별 연구 문서에 보존한다. 입력·소스·설정 해시를 사용한 프로토콜과 잠금 파일은 당시 바이트를 유지한다. 새 현재 안내가 과거 프로토콜의 결정이나 해시를 대체하지 않는다.

재현에는 해당 실험의 입력과 압축 사건 기록, 고정 설정·소스·환경이 필요하다. 대용량 원본 일부는 Git 밖 보관 대상이며 로컬 파일 유무를 먼저 확인한다. 관측한 검증 자료를 다시 개발 자료처럼 사용하거나 서로 다른 생성모형의 효과를 한 개선율로 합산하지 않는다.

일부 `inquiry_lab/cohort_*` 재현기는 당시 `docs/README.md`의 SHA-256도 검사한다. 현재 문서 색인을 새로 작성했으므로 이런 재현기는 현재 작업 트리에서 실행하면 고정 근거 변경으로 거절할 수 있다. 해당 연구의 고정 소스와 원래 문서 바이트를 별도 작업본에서 사용한다. `496d74f0c51e858d22b82f227810149932f3476c`의 문서 색인을 CRLF로 체크아웃하면 코드의 `INDEX_AFTER` 값 `d9e28990af5dadd6b9e8577904729cfbaeb4f53ade5faacecbfe94ed9ec093f2`와 일치한다. 연구별 소스·입력 잠금도 함께 일치해야 한다.
