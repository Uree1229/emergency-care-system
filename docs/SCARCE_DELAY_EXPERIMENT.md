# 희소 병상 보호 지연 개선 검증

2026-10-16 · 합성 이송 실험 · 개선 후보 채택 보류

원래 늦어졌던 6건에서는 초기 대안 문의를 병행해 유연한 환자의 처치 도달을 각각 15초 줄였다. 희소 환자의 도착시간과 문의 수는 유지했고, 두 환자의 전체 대기도 줄었다. 다만 새 검증에서는 문의 기한 경계에 걸린 다른 6건이 각각 1분 늦어졌다. **일부 상황의 대기를 늘리지 않는다는 채택 기준을 충족하지 못해, 보충 문의를 기본 정책으로 반영하지 않았다.**

실험 내 기준은 기존 보호가 켜진 V4이고, 실제 서버의 운영 기본값은 기존 고정3이다. 이번 후보는 별도 시뮬레이션 모듈에만 남겼다.

## 초기 보충 문의 방식

같은 시각에 실제 접수된 요청을 모두 등록한 뒤 원래 순서대로 첫 문의를 제출한다. 아직 자기 차례가 오지 않은 환자를 자원 보고에 따른 재평가가 먼저 문의하지 않도록 해 기존 FIFO 제출 순서를 유지했다. 미래 환자는 등록하지 않는다.

실제 V3/V4 선택기가 제안한 첫 문의는 그대로 제출한다. 이어서 다음 조건이 충족되면 다른 병원에 한 건만 보충한다.

- 현재 등록된 탐색 환자 중, 구조적으로 한 병원만 가능하고 우선순위가 같거나 더 높은 환자가 있다.
- 현재 받은 필수 자원 보고가 신선하고 충분하지만, 해당 병상의 가용 수량으로 두 환자의 수요를 함께 충족할 수 없다.
- 유연한 환자에게 구조적으로 가능한 대안이 있으며, 그 대안의 모든 필수 자원도 현재 보고로 신선하고 충분하다.
- 대안은 이미 문의했거나 진행 중이거나 유효 수용을 받은 병원이 아니다.
- 실제 첫 문의를 제출한 같은 시각이며, 동시 문의 3곳과 현재 에피소드 접촉 10건 한도 안이다.

보충은 환자당 최초에 최대 한 건이다. 등록 직후 아직 첫 문의를 보내지 않은 동시 환자도 현재 수요로 볼 수 있지만, 이후에는 실제 진행 중인 문의의 원래 기한과 1분 창 안에서만 희소 수요를 인정한다. 병원 수용 확률·회신 예정·복구 예정은 사용하지 않는다.

원래 문의, 대안 문의의 실제 병원 심사 작업, 문의 기한, 수용 만료, 이동시간과 처치시간을 유지한다. 보충 문의는 기존 순수 선택기 외부의 명시적인 추가 규칙이며, 서버 V4 자체를 수정하거나 새로운 서버 정책으로 등록한 변경은 아니다. 코드의 `scarce_routing` 플래그는 이 병행 보충 동작을 뜻하며, 원 선택기의 후보를 제거하지 않는다.

## 원래 지연 6건의 결과

과거 검증 시드 32101~32106의 원시 입력을 그대로 재실행했다. 아래 수치는 H1과 C1 각각 동일하며, 두 알고리즘의 결과를 합쳐 환자 수를 두 배로 세지 않는다.

| 방식 | 유연한 P01 처치 도달 | H01만 가능한 P02 처치 도달 | 6쌍 전체 대기 합 |
|---|---:|---:|---:|
| 희소 문의 보호 없음 | 각 3.25분 | 19.25~25.25분 | 113분 |
| 기존 희소 문의 보호 | 각 5.75분 | 각 3.5분 | 7.5분 |
| 초기 대안 문의 병행 후보 | 각 5.5분 | 각 3.5분 | 6분 |

기존 보호 대비 **P01 6명 각각 15초 단축, P02 지연 0, 전체 대기 1.5환자·분 감소**다. 각 쌍의 문의는 `[2, 1]`로 같았다. 요청부터 처치까지 합도 55.5→54분으로 줄었다. 문의 보호를 끈 결과에 대한 P01의 최대 추가 지연은 실험 후보에서 **2.5→2.25분**이 되었다.

이 비교의 무보호 기록은 이전 V3 분기다. 해당 6개 입력에서 기존 보호 V3와 V4의 환자 결과가 정확히 같음을 확인한 뒤 참고 비교에 사용했다. 과거 6건은 회귀 시험이며 아래의 새 검증 시드와 구분한다.

## 남은 2분 15초의 원인

해당 6개 입력에서는 P02가 H01만 가능하고 H01 응급 병상은 한 개다. P01을 원래처럼 H01에서 3.25분에 처치하면 최소 12분의 비선점 처치 동안 병상이 점유되므로, P02의 3.5분 처치와 동시에 만족할 수 없다.

P02에게 H01을 보존하면 P01은 대안 병원이 필요하다. 가장 가까운 H02는 이동 5분이고, 실제 심사 회신은 가장 빨라도 문의 후 0.5분이다. **수용 회신을 받은 뒤 현장에서 출발하는 현재 계약에서는 P01의 도달 하한이 5.5분**이다. 다른 대안은 더 멀다. 따라서 원래 무보호 3.25분보다 남는 2.25분을 없애면서 P02의 3.5분도 유지할 수 없다.

이는 해당 6개 합성 입력과 현재 계약에 한정된 물리적 설명이다. 수용 전 선이동·처치 선점·병상 추가를 허용하는 문제의 최적성을 뜻하지 않는다. 현재 후보는 원래 H01 문의 FIFO도 유지하므로 P02 회신 0.5분과 이동 3분을 합친 3.5분을 보존한다.

## 문의 기한 경계에서 발견한 악화

새 환경에서는 H02의 비공개 기존 심사 작업이 0~3분 동안 이어지고, 환자 문의 심사에는 0.25분이 걸린다. 이 병원 내부 일정은 환경이 실행하는 물리적 작업이며 정책 입력에 넣지 않는다.

기존 방식은 0.25분에 H02에 문의해 3.25분까지 기다린다. 회신이 3.25분에 완료되므로 유효하고, 이동 5분을 더해 P01은 8.25분에 처치에 도달한다.

보충 후보는 문의를 0분으로 앞당겼지만 원래 3분 문의 기한도 유지한다. 같은 3.25분 회신이 늦은 회신으로 폐기돼 재문의가 필요해지고, P01 도달은 9.25분이 된다. 각 사례에서 전체 대기와 문의 수가 각각 1분·1건 늘었다. 기한을 뒤로 늘리거나 이미 만료된 회신을 유효 수용으로 바꾸어 통과시키지 않았다.

별도 구조 시드 8에서는 심사 작업자 두 명인 상황도 확인했다. 기존 보호 분기는 같은 시각의 회신 처리 순서 때문에 `[P01 3.25, P02 19.25]`였고, 보충 후보는 병원 내부 작업 유무에 따라 `[5.25, 3.25]` 또는 `[9.25, 3.25]`가 되었다. 초기 정책 입력은 기록 연결용 순번을 제외하면 같았다. 이 추가 구조 시험은 아래 검증 집계에 포함하지 않으며, 한 환경의 평균 개선을 개인별 무악화나 보편적인 지연 상한으로 해석할 수 없음을 보여준다.

## 개발과 검증 비교

기존 56개 환경을 완전 보존하고 무응답·원 기한 뒤 회신·미확인·오래된 보고·먼 대안·늦게 발생한 환자·우선순위 역전·대안 없음·접촉 한도·짧은 수용 기한·현재 병상 부족의 11개 환경을 추가했다.

8분기는 V4의 기존 방식·동시 등록만·동시 등록과 보충 문의를 H1/C1 각각에 적용한 6개와, 고정3 H1/C1 참고 분기 2개다. 동일 환경에서 실행 순서를 회전했다. 모든 분기의 기존 회복·희소 기회 보호는 공통으로 켰다.

| 비교 범위 | 개발 | 별도 검증 |
|---|---:|---:|
| 시드 | 33101~33103 | 34101~34106 |
| 환경 수 | 201 | 402 |
| 전체 실행 수 | 1,608 | 3,216 |
| 분기당 환자 수 | 420 | 840 |

| 처치 상실 | 0 | 0 |

효과 행은 기존 보호 V4 대비 H1과 C1 각각의 결과다. 해당 모집단의 두 배정 알고리즘은 환자 결과가 같았으며, 이것이 일반적으로 같은 성능이라는 뜻은 아니다. 동시 등록만 적용하면 모든 환자 결과와 문의 수가 기존 방식과 같았다.

새 검증의 H1/C1 각각에서 기존 V4의 전체 대기 합은 8,624.5분, 보충 후보는 8,620분이다. 요청→처치 제한 합은 11,937→11,932.5분, 문의는 2,365→2,371건, 수량 재확인은 1,026→1,014건이었다. 평균 합은 줄지만 6개 환경의 대기를 늘려 채택 기준에서 탈락했다.

고정3 참고 분기는 미처치 54명, 전체 대기 8,035분, 요청→처치 제한 합 11,577.5분이었다. 보충 V4는 각각 60명·8,620분·11,932.5분이므로 이 검증으로 V4가 고정3보다 뛰어나다고 결론내릴 수도 없다. 고정3 대비 새 처치 12명과 처치 상실 18명을 모두 원시 비교에 남겼다.

채택 기준은 개발 전에 고정했다. 처치 상실과 개인 처치·최종 도착 악화가 없어야 하고, 환경별 전체 대기와 요청→처치 제한 합도 늘지 않아야 한다. 전체 문의는 기준의 1.10배 이내, 전체 대기는 엄격히 감소해야 한다. 동시 등록만은 개선이 없고 보충 후보는 악화가 있어, 두 배정 알고리즘 모두 실험 내 기존 보호 V4를 유지하도록 개발 잠금에 기록했다. 검증의 진단 결과로 다시 선택하지 않았다.

## 검증 근거와 범위

신규 141개를 포함한 총 1,363개 단위·회귀 테스트가 통과했다. 이전부터 로컬 소켓 바인딩이 불가능했던 선택적 HTTP 시험 6개는 기존 제외 목록을 그대로 사용했다. 이번 변경은 HTTP 동작을 수정하지 않는다.

저장된 개발 1,608회와 검증 3,216회, 과거 6건 48회의 원시 기록을 배정 엔진·솔버를 import하지 않는 별도 프로세스로 다시 감사했다. 실제 요청 등록·원문의와 보충 문의·기존 FIFO 작업·현재 수신 보고와 예약·우선순위·원 기한·수용 만료·실제 이동을 재구성했다. 압축 파일과 복원 원문, 원 입력과 소스의 SHA-256을 검증하고, 환자 결과와 집계 및 개발의 선택을 독립 재계산했다. 순수 문의 계산 재현과 현재 배정 모형의 최적성 검사는 전체 이송의 보편적 최적성 증명이 아니다.

추가 자원 변화 보고는 모든 실행에서 0건이다. 접촉 한도 환경에서는 실제 동시 문의 3개와 에피소드 10건까지 도달했다. 먼 대안의 수용도 실제로 발생했다. 짧은 수용 기한이라는 새 환경 자체에서는 만료 사건이 발생하지 않았으므로 이를 만료 도달 검증으로 세지 않는다. 실제 만료는 미확인·오래된 보고 환경에서 발생했고, 별도 단위 시험에서도 만료 수용의 부활을 거부한다.

시간 단위는 실제 분이고 문의 재평가는 15초다. 실제 이동의 기존 분 단위 반올림·2분 수용 대기 절차·3분 전원 준비를 유지했다. 전체 대기는 이동을 제외한 탐색·병원 대기·전원 준비 합이며, 요청→처치는 미처치를 동일 관찰 종료로 제한한다. 이번 모형의 병원 내 대기 합은 0이다. 실제 응급실 병원 내 대기 감소를 입증한 결과로 해석하지 않는다.

현재 공통 루프에 연결한 것은 서버의 순수 문의 선택 계산이다. 서버 전체 워크플로, 전역 300초 기한, 실제 임상 결과를 검증한 실험은 아니다. 접촉 10건은 현재 에피소드 단위다. 기존 감사기의 도착 후 요구 역량 추가 처리에는 초기 역량을 비교하는 한계가 있어, 그 별도 사례는 명시적으로 거부하는 시험으로 남겼다. 이 문서의 통과 범위는 명시된 67개 환경이다.
