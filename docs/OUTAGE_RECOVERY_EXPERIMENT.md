# 추가 자원 보고 없는 돌발 병상 중단 회복

2026-10-15 · 합성 시뮬레이션 실험 분기

**앞서 5분 늦어졌던 원본 6건을 모두 개선했다. 처치 도달은 18/19분에서 13/14분으로 돌아왔고, 조기 출발 전 비교군과 같아졌다.** 추가 자원 변화 보고 없이, 이미 제출한 백업 문의와 실제 수신한 유효 수용을 보존해 재사용한 결과다.

모두 처치 시작 시각이며 단위는 분이다. 원래 문의 기한, 수용 만료, 이동과 전원 준비시간을 유지했다. 각 사례에서 환자 문의는 3→2건, 자원 수량 조회는 0→0건이다. 수정된 재출발 시각인 7분까지 실제 수신한 자원 보고의 내용·시각·출처도 이전 분기와 동일하다.

## 원인과 변경

이전 구현은 가까운 병원으로 조기 확정하면 다른 병원의 문의를 환자 상태에서 지웠다. 병원 작업 자체는 계속됐지만 그 회신을 활용하지 못했다. 이후 실패 도착과 3분 전원 준비를 거친 뒤 먼 병원에 처음부터 다시 문의하면서 5분을 잃었다.

새 분기는 다음 과정을 적용한다.

1. **조기 확정 때 원래 백업 업무 보존:** 이미 제출한 다른 병원의 문의와 만료되지 않은 수용을 보존한다. 문의의 원 제출·시도·절대 시간 초과와 수용의 원 수신·만료 시각을 유지한다.
2. **정상 이송 중에는 회신만 수신:** 백업 병원이 수용했다고 자동으로 방향을 바꾸지 않는다. 기존 환자별 조건 변경 알림을 받은 뒤에는 기존 재판단과 최종 충돌 검사를 통해 방향을 바꿀 수 있다.
3. **실패 도착 후 기존 준비 유지:** 실제 도착·실패 평가와 3분 전원 준비를 그대로 둔다. 준비 중에 원래 문의의 회신이 오면 저장한다.
4. **준비 완료 분에 재검토:** 준비가 끝나는 분에 기존 자원 확인·기회 보호·C1 공동 배정·최종 실제 충돌 검사를 거쳐 재출발한다. 다음 반복 처리 시각까지 불필요하게 기다리지 않는다.
5. **유효한 백업이 없는 경우:** 이미 만료된 백업 응답은 기존 알림과 현재 신선·충분한 수량에 근거해 새 문의를 한다. 자원 부족으로 실패했던 병원은 실패 이후 관측한 기존 보고가 모든 필수 자원의 신선·충분한 수량을 확인할 때 새 수용 문의 대상으로 되돌린다. 역량 부족으로 실패한 병원에는 적용하지 않는다.

원본 사례의 타임라인은 다음과 같다.

| 시각 | 이전 조기 출발 | 새 회복 |
|---|---|---|
| 0 | NEAR·FAR 문의 | 동일 |
| 1 | NEAR 조기 확정, FAR 문의 상태 삭제 | NEAR 조기 확정, FAR 원 문의 보존 |
| 2 | 기존 병상 중단 알림 | 동일 |
| 4 | 실패 도착, 전원 준비 시작 | 동일 |
| 5 | FAR 원 회신 활용 못 함 | 원 FAR 문의의 수용 회신 수신 |
| 7 | 준비 완료 후 FAR 새 문의 | 준비 완료 후 기존 유효 FAR 수용으로 재출발 |
| 12 | FAR 새 회신·재출발 | 이미 이송 중 |
| 13/14 | 이송 중 | 최종 도착·처치 시작 |
| 18/19 | 최종 도착·처치 시작 | — |

도로 중간에서 멈추거나 이동·준비시간을 줄여 개선한 것이 아니다. 도착 직전에 병상이 복구되는 기존 사례는 처치 시작 4분을 유지한다.

## 새 검증 시드 결과

소스·설정·런타임을 잠근 뒤 미사용 시드 30101~30106을 사용했다. 기존 39개 환경을 그대로 보존하고 회신·만료·무응답·시간 초과·병상 경합·빠른 복구·수량 미확인·도착 경계 조건 9개를 추가했다. 총 **48환경 × 6시드 × 6분기 = 1,728회**, 분기당 환자 실행 612건이다.

| 지표 | 기존 보고 재검토 | 이전 조기 출발 | 새 전체 회복 |
|---|---:|---:|---:|
| 전체 대기 합, 환자·분 | 6,243 | 6,700 | 5,973 |
| 요청→처치 합, 미처치 관찰 종료 제한 | 8,830 | 9,303 | 8,536 |
| 관찰 종료까지 미처치 | 36 | 44 | 36 |
| 추가 자원 변화 보고 | 0 | 0 | 0 |

기존 보고 재검토 대비 전체 대기는 **270 환자·분, 4.32% 감소**, 요청→처치 합은 294분, 3.33% 감소했다. 처치 도달 지표는 **77건 단축·0건 악화·535건 동일**이다.

이전 조기 출발 대비 전체 대기는 727분, 10.85%, 요청→처치 합은 767분, 8.25% 감소했다. 처치 도달은 **54건 단축·0건 악화·558건 동일**이며 미처치가 8건 줄었다. 이 감소량 중 **697/727 환자·분은 신규 스트레스 환경 9개**에서 발생했다. 이를 일반적인 운영 개선율로 설명하면 안 된다.

기존 39개 환경만 따로 보면 이전 조기 출발의 전체 대기 합은 **5,445→5,415 환자·분**이다. 문제 유형 6건이 각각 5분 단축됐고 나머지 546건의 처치 도달 결과는 같다. 기존 조기 출발의 정상 상황 편익을 보존했다.

전체 대기는 모든 환자의 탐색·병원 내 대기·전원 대기 합이며 이동은 제외한다. 미처치는 관찰 종료까지 포함한다. 미확인 자원 유형의 6건은 여전히 미처치이며 요청→처치 제한값도 동일하다. 이 경우 이송에 쓴 3분 때문에 비이동 대기만 줄어든 것을 도착 개선으로 세지 않았다. 전체 대기와 요청→처치 지표를 함께 확인해야 한다.

## 정보와 비용

새 자원 보고나 미래 회신·병상 복구 일정은 정책에 제공하지 않는다. 기존 초기 보고·주기 피드·재확인과 실제 환자별 문의 회신만 사용한다. 병원 작업은 원래 일정대로 진행하며, 시간 초과 후 완료한 작업이 오래된 수용을 되살리지 않는다. 백업 수용은 자원 수량을 갱신하지 않으며 확정 전에 기존 수량 확인과 실제 충돌 검사가 필요하다.

| 검증 288사례 합산 | 기존 보고 재검토 | 이전 조기 출발 | 새 전체 회복 |
|---|---:|---:|---:|
| 환자 수용 문의 | 1,308 | 1,428 | 1,314 |
| 기존 자원 재확인 요청 | 948 | 840 | 834 |
| 기존 자원 보고 수신 | 17,670 | 17,562 | 17,550 |
| 추가 자원 변화 보고 | 0 | 0 | 0 |

기존 재검토보다 환자 문의는 6건 증가한다. 만료된 수용에 새 응답을 요구하는 등의 비용이다. 이전 조기 출발에 비해서는 재문의가 114건 감소했다. 기존 주기 보고의 점유량은 처치 시각 변화에 따라 달라질 수 있지만, 보고 채널·주기·지연·누락 계약은 같다.

`retained_backup_C1`은 보존만 켠 비교용 분기다. 준비 완료 시점 검토와 기존 보고 기반 후속 처리가 빠져 있으므로 전체 회복 분기와 같지 않다. 구현 효과를 설명할 때는 `outage_recovery_C1`을 사용한다.

## 검증·보존·한계

- 개발: 새 시드 29101~29103, 144사례 × 6분기.
- 검증: 미사용 시드 30101~30106, 288사례 × 6분기. 검증 결과로 소스·설정을 재튜닝하지 않았다.
- 과거 실패 6건: 실제 이전 입력과 이전 조기 분기를 재현한 별도 36분기 회귀 검증. 저장 결과를 다시 읽어 독립 감사 통과.
- 신규 테스트 138개 통과. 넓은 회귀 검사 967개와 최종 독립 감사 테스트 74개 재검사를 합쳐 고유 테스트 977개를 확인했다.
- 이전부터 환경의 `WinError 10013`으로 연결되지 않는 선택적 로컬 HTTP 테스트 6개는 이 수에서 제외했다. 새 시뮬레이션 테스트는 모두 포함한다.
- 저장된 검증 JSON을 엔진·솔버 없이 독립 검사: 배정 결정 2,688개, 보고된 C1 모형의 정확 재검사 2,669개, 이동 구간 3,696개, 기존 준비시간 246건 확인. 제약 위반 0건, 추가 자원 변화 보고 0건.
- 이전 소스·설정·결과·문서 299개 보존, 새 잠금 소스 77개 일치 확인.
- 운영 서버·API·DB·팀원 UI는 수정하지 않았다. 합성 실험의 관측 결과이며, 실제 임상 안전성이나 전체 이송 과정의 전역 최적성을 증명하지 않는다.
- 실제 병상 부족과 지속 정보 누락은 남는다. 복구 시점은 예측하지 않으며, 현재 받은 기존 보고가 충분하지 않으면 실패 병원 재문의 대상 재개를 하지 않는다.
- 현재 구현은 이번 분에 받은 유효 보고를 재개 계기로 삼는다. 더 이전에 받은 신선한 복구 보고만 남아 있는 상황의 추가 최적화는 포함하지 않는다.
