# 실제 회복 증거에 따른 정상 문의 순위 개선

개발에서 고정한 조합이 새 검증에서도 기존 frontier 대비 기본 개선 기준을 통과했다.

합성 시뮬레이션 연구 결과다. 운영 서버·화면·DB·기본 정책 `fixed_3`는 수정하지 않았으며 자동 채택하지 않았다.

기본 개선 기준의 비교 대상은 현재 frontier다. 별도로 유지한 safe·protected 등과의 도입 기준에서는 개발 normal에 처치 성공 상실과 환경별 총대기 증가가 남았다. 따라서 현재 기준 대비 개선을 운영 도입 가능이나 모든 기준 대비 우월성으로 해석하지 않는다.

## 구현과 비교 대상

이전 latched의 반례에서는 8분 회복 보고를 실제로 받았지만, H01의 실제 누적 문의가 2회이고 다른 병원은 1회여서 문의 순서에서 밀렸다. 기존 frontier 자체는 같은 환경에서 이미 8분에 H01을 선택하므로, 이 사례만으로 frontier보다 개선됐다고 주장하지 않는다.

- normal: 기존 frontier에 회복 보고 기반 순위 예외만 추가했다.
- latched: 앞서 실패한 대기 후 재문의 방식에 같은 순위 예외를 추가했다. 두 후보를 사전 고정해 기존 재문의와 순위 변경의 효과를 구분했다.
- 실제 최신 임상 거절이 최신 실제 문의와 같은 조건·시도여야 한다. 그 뒤 수신·적용된 신선한 수량 부족→충분 보고가 필요하다.
- 필요한 모든 자원은 같은 실제 보고에서 충분하고 출처 시각도 거절 이후여야 한다. 현재 정보도 신선·충분해야 하며 중간 자원 상실은 근거를 무효화한다.
- 초기 미수용 SEARCH, 진행 중인 자기 문의와 유효 수용 응답이 없는 경우만 대상이다. 기존 정상 문의 후보 밖의 병원은 추가하지 않는다.
- 아직 문의하지 않은 정상 후보가 있거나 이미 기존 최소 접촉 tier에 속하면 순위 예외를 쓰지 않는다.
- 실제 접촉 횟수는 차감·초기화하지 않는다. 실제 대상 문의가 전송될 때만 환자 조건당 한 번 소비하는 별도 근거를 기록한다.
- 기존 latched의 최초 재문의 허가와, 후속 최신 거절·새 회복에 대한 순위 허가는 별도 계보다. 동시 3곳·회차 10회, 원래 실제 접촉 시계·문의 간격 규칙·FIFO 업무·기한·수용 확정과 배정 규칙을 유지했다.

재문의 자격 허가와 순위 허가가 같은 실제 문의 하나에 함께 쓰일 수도 있다. 각 허가의 식별자와 한도는 별도로 확인하며, 실제 문의 횟수와 업무 비용은 원문의 문의 한 건으로 계산한다.

## 검증·보존과 해석 한계

- 코드 검사 2286개 통과. 기존과 같은 선택적 로컬 HTTP 바인딩 검사 6개만 제외했다.
- 작은 시드 7 통합 점검 129개 환경·516개 새 분기: 전체 원문 저장 후 감사했다.
- 신규 경계의 별도 작은 H1 원문 16개에서 실제 순위 우선권 소비, 소비 후 재사용 거부, 미방문 정상 후보 차단과 후발 환자의 FIFO를 확인했다. 부분정보·후착 출처·같은 부족 보고·busy 환경은 앞선 gate에 막힌 경우가 있어 해당 하위 의미 조건까지 원문으로 직접 도달했다고 주장하지 않는다. 순수 정책 단위검사와 실제 경계 도달은 구분한다.
- 과거 31개 입력에 새 124개 분기를 실행하고 엔진·솔버 없이 저장 원문을 별도 감사했다. 기본 회귀 기준 통과: True.
- 이전 자료 9,437개와 기존 과학 소스 156개를 변경하지 않았다. 새 10개 소스를 더한 166개와 평가 설정을 성과 실행 전에 고정했다.
- 개발 성과와 선택 lock 저장 후, 독립 감사 보조 도구에서 과거 보고서의 실행 순서 필드명을 잘못 읽는 KeyError가 발견됐다. 동결한 원본 도구를 보존하고 별도 v2에서 `execution_order`를 보고서의 실제 필드 `actual_execution_order`로 읽는 한 줄만 수정했다. 수정 시점에는 새 검증을 실행하지 않았으며, 소스 166개·개발 결과·선택 lock·원문은 변경하거나 재실행하지 않았다. 정정 기록과 두 도구의 해시를 남기고, 완전 독립 감사에는 v2를 사용했다.
- 이미 관측한 개발 자료와 새 검증을 구분했다. 새 검증 결과를 보고 정책·입력·선택 기준을 바꾸지 않았으며 실패 원문도 덮어쓰지 않았다.
- 새 시드가 실제 현장의 독립 표본을 뜻하지는 않는다. 고정 경계 입력은 시드별로 같은 조건을 반복할 수 있으므로 환경 실행 수와 서로 다른 환경 유형 수를 구분한다.
- 각 비교는 같은 전체 물리 환경을 받는다. 시도별 실제 응답 시간이 다른 합성 환경에서는 앞선 실제 문의가 이후 응답 경로도 바꾸므로, 개선을 미래 응답시간 예측의 효과로 표현하지 않는다.
- 순대기는 이동을 제외한 환자 탐색·병원·전원 준비 대기의 합이다. 병원 문의 큐 대기·문의 업무 시간과 구분한다.
- 미처치 환자는 같은 관찰 종료로 제한한다. 제한 지표 차이를 관측된 실제 처치 지연으로 혼동하지 않는다. 실제 지연과 성공 상실을 별도 표로 확인했다.
- 고정 3곳은 원래 회차 제한이 다른 전체 기반 참고 기준이다. 다른 시점에 실행한 저장 참조의 CPU 시간을 정책의 인과적 지연 증거로 쓰지 않는다.
- 50ms C1 제한의 fallback도 실제 결과로 보존하고 재실행·제외하지 않았다. 미래 환자·자원·실제 업무 완료시간은 정책 입력에 넣지 않았다.
- 원문에 번호가 없는 표시 사건은 원래 목록 위치로 구분하며, 실제 서버 사건 번호를 새로 만들어 붙이지 않는다. 원문은 그대로 감사한다.
