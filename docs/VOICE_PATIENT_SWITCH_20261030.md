# 환자별 음성 초안 보관과 전환

대상은 `/paramedic/quick-test.html`이다. 실제 환자 등록 전에 작성하는 음성 초안을 환자 번호별로 분리한다. 팀 환자용·병원용 화면과 임상 배정 규칙은 변경하지 않는다.

## 사용 흐름

상단의 현재 환자 번호를 확인하고 입력한다. 새 환자 시작은 현재 기록을 보관한 뒤 별도 번호·작성자의 빈 화면을 준비한다. 본문을 입력하기 전에는 빈 서버 초안을 생성하지 않는다. 목록에서 선택 환자 열기 또는 이전 환자로 버튼을 사용한다. 이전 환자는 직전에 열었던 기록이며 생성 순서의 바로 앞 번호를 뜻하지 않는다.

일반 말하기에서 새 환자 시작·다음 환자 시작·이전 환자로 돌아가를 명령으로 인식한다. 첫 명령 앞 본문은 원환자에게 저장하고 저장 응답을 확인한 뒤 전환한다. 명령 뒤 문장과 늦은 확정 인식은 원환자의 미반영 목록에 남긴다. 명령만 있으면 임상 본문이나 빈 서버 초안을 만들지 않는다. 인용·간접보고·부정·설명문은 명령에서 제외한다. 항목별 말로 확인 녹음은 전환 명령을 실행하지 않는다.

## 환자 격리

- 각 기록은 고유 NOTE ID·증가하는 환자 번호·작성자와 최대 한 개 서버 초안 ID를 갖는다. 서로 다른 기록이 작성자나 서버 초안을 공유하지 못한다.
- 기존 작성자는 고정하고, 서버 초안 ID는 생성 전 null에서 실제 ID로 한 번만 연결한다. 기존 ID 교체·버전 하향을 막는다.
- 현재 환자의 미반영 음성·직접 입력·저장 전 수정안을 먼저 보관한다. 대상 초안은 별도 클라이언트에서 GET으로 확인한 뒤 저장 목록의 활성 포인터를 확정한다. 조회·용량·저장 오류이면 기존 환자와 입력을 유지한다.
- 전환 후 원문·질문·보류·추천 준비·편집기·복창 확인 상태를 다른 환자에게 가져오지 않는다. 보관한 미반영 내용은 해당 환자로 돌아왔을 때 검토용으로 복원한다. 복창 확인은 다시 진행한다.
- 이전 화면의 항목 확인·수정·읽기·질문 보기 콜백에는 환자 세대 검사를 적용한다. 이전 인식기의 늦은 결과는 VoiceCapture의 세대 검사로 폐기한다.

## 불확실 요청과 복원

서버 응답이 불확실한 요청이 있으면 새 환자·선택·이전·삭제를 막는다. 원래 요청 ID·본문·버전으로 결과를 확인한 뒤에만 전환한다. 음성 명령이 붙은 저장 요청을 복원한 경우도 같은 요청 재시도 성공 뒤 한 번만 전환한다.

기존 DRAFT·환자 미연결 음성 초안만 편집한다. 대상의 ID·작성자·상태·최소 버전이 다르거나 12시간 자동 복원 유효기간이 지났으면 빈 새 초안으로 대체하지 않는다. 전환만으로 마이크·입력·환자 등록·병원 문의를 실행하지 않는다.

## 브라우저 보관과 이관

`paramedic.voice.patient-records.v1`의 단일 JSON envelope에 환자 목록·활성/직전 포인터·각 strict checkpoint를 함께 저장한다. 최대 20개, 개별 checkpoint 128KiB, 전체 UTF-8 1MiB다. 한도를 넘으면 기존 기록을 자동 삭제하거나 원문을 자르지 않는다. 새 기록을 더 보관하려면 완료한 환자의 로컬 복구본을 명시적으로 정리한다.

기존 `paramedic.voice.quick-recovery.v1` 단일 복구본은 첫 환자 기록으로 이관한다. 새 envelope가 저장·재조회된 뒤에만 같은 원본 legacy 값을 제거한다. 저장 실패·형식 오류·다른 탭 변경이면 이전 원본을 보존한다.

다른 탭에서 envelope가 바뀌면 오래된 탭의 쓰기·삭제를 막는다. 대상 GET 도중에도 다시 검사한다. localStorage 비교 후 저장은 원자적 CAS가 아니므로 완전히 동시인 여러 탭 편집까지 보장하지 않는다.

현재 환자 복구본 제거는 해당 브라우저 임시본과 미반영 내용만 지우며 다른 환자·서버 원기록은 보존한다. 현재 항목을 지우면 다른 환자를 자동 선택하지 않고 명시적인 선택을 기다린다. 손상된 목록의 전체 로컬 초기화는 별도 표시된 버튼으로만 수행한다. 12시간은 자동 복원 가능 기간이며 자동 삭제 시간이 아니다.

## 검증

독립 저장·명령 예시 시험과 실제 페이지를 실행하는 모의 DOM 시험을 수행한다. 여러 실제 서버 초안·고유 작성자를 사용하는 fresh SQLite HTTP 시험으로 A/B/C 격리, 음성 prefix/suffix 귀속, 응답 유실·재접속·재시도, 미반영 편집안, 오래된 콜백, 이관·용량·삭제 경계를 검증한다. 실제 마이크·STT·운영 DB·실제 환자 등록·병원 전송은 사용하지 않는다.
