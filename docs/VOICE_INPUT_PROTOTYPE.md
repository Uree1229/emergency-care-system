# 음성 입력 초안 시제품 (R12, v1)

작성일: 2026년 10월 30일 · 코드: [`voice_lab/`](../voice_lab/) · 입력 항목 기준: [R1 최소 입력 항목](R1_MINIMUM_INPUT.md)

구급대원이 말한 문장을 R1 입력 칸의 **초안**으로 바꾸는 시제품이다. 음성 인식 엔진과 앱 화면은 포함하지 않는다. 인식된 글을 받아 칸을 채우는 부분만 만들었다. 서버 파일은 수정하지 않았다.

## 1 설계 원칙

| 단계 | 음성으로 하는 것 | 화면 탭으로 하는 것 |
|---|---|---|
| 입력 | 말한 내용을 칸 초안으로 채움 | — |
| 수정 | "혈압 100에 70으로 수정", "의식 모름", "방금 거 취소" | 바뀌기 전·후 확인 |
| 확인 | 되읽어 주기, 빠진 칸 알려 주기 | 칸별 수정 |
| 저장·전송 | 요청만 알림(`send_requested`) | **확정과 전송** |

- 처음 입력과 수정을 하나로 처리한다: **지금 초안 + 새 문장 → 바꿀 칸 목록(이전 값 → 새 값)**.
- 등급·진단을 추론하지 않는다. 말한 사실만 칸에 옮긴다.
- 알아듣지 못한 칸은 비워 둔다. 애매하면 추측한 값을 고르되 `ambiguities`로 알려 화면에서 확인하게 한다.
- 입력 범위를 벗어난 숫자(예: 산소포화도 120)는 버리고 `rejected`로 알린다. 이 범위는 오인식을 거르는 값이며 임상 기준이 아니다.

## 2 구현한 것

| 함수 | 역할 |
|---|---|
| `normalize` | 말로 읽은 수를 숫자로 바꾼다: "구십에 육십", "삼십팔점오", 무전식 "일이공", "일곱 살", "한 시간 반 전". "혈압이 높음", "이대로"처럼 숫자가 아닌 말은 그대로 둔다 |
| `propose_changes` | 문장에서 칸 값·명령을 찾아 초안 대비 변경 목록을 만든다. 부정어 범위("흉통 없음"과 "흉통 있고 식은땀 없음" 구분)와 '주증상은 ~' 지정을 반영한다 |
| `apply_changes` | 사람이 확정한 변경만 반영한다 |
| `readback_text`, `missing_text` | 되읽어 주기와 빠진 필수 칸 안내 문장 |
| `profile_for` | 주증상·2차 고려사항·연령대로 서버 진료 프로필 선택(R1 4절) |
| `to_server_payload` | 확정 초안을 서버 환자 등록 본문으로 변환. 필수 칸이 비면 거부한다. 서버의 입력 검사(`_clean_patient`)를 통과하는지 테스트로 확인 |

용어 사전([`voice_lab/terms.py`](../voice_lab/terms.py))은 R1 칸에 필요한 표현만 담는다. 의식(AVPU), 호흡, 주증상 10묶음, 2차 고려사항, 연령대가 대상이다.

## 3 정확도 시험

같은 실험 규칙을 따랐다. 개발 문장으로 다듬은 뒤, 새로 쓴 검증 문장으로 한 번만 평가했다. 검증 전에 소스와 문장 파일의 해시를 잠금 파일로 남겼고, 결과를 본 뒤 추출기를 고치지 않았다.

| | 개발 문장 43개 | **검증 문장 40개** |
|---|---:|---:|
| 문장 완전 일치 | 43/43 | **26/40 (65.0%)** |
| 칸 재현율(말한 칸을 맞게 채움) | 100% | **85.4%** (117/137) |
| 칸 정밀도(채운 칸 중 맞은 칸) | 100% | **98.3%** (틀린 값 2, 남는 칸 0) |
| 명령 구분(수정·되돌리기·읽어 주기·전송) | 100% | **95.0%** |

검증 문장의 묶음별 결과:

| 묶음 | 재현율 | 정밀도 |
|---|---:|---:|
| 필수 5칸(의식·호흡·주증상·연령대·등급) | 76.9% | 96.8% |
| 활력징후 | 97.6% | 100% |
| 나이·발생 시각·2차 고려사항 | 94.1% | 100% |

- **개발 문장 100%는 그 문장으로 다듬은 결과라 의미가 없다.** 판단은 검증 문장으로 한다.
- **숫자는 잘 읽는다.** 활력징후, 나이, 등급처럼 형식이 정해진 값은 처음 보는 말투에서도 97.6%를 맞혔다.
- **말 표현이 약하다.** 필수 5칸의 재현율이 76.9%다. 사전에 없는 표현과 조사가 붙은 표현을 놓쳤다.
- **틀린 값을 채우는 일은 드물다(정밀도 98.3%).** 대부분 빈칸으로 남아 화면에서 탭으로 채우게 된다. 확인 단계를 두는 설계와 맞는다.

결과: `simulation_results/voice_lab_extract_validation_20261030.{json,md}`, `_lock.json`, 개발 기록 `voice_lab_extract_dev_20261030.{json,md}`

## 4 놓친 유형(검증 문장)

| 유형 | 예 | 개선 방향 |
|---|---|---|
| 조사·활용이 표현 중간에 붙음 | "의식은 명료하나", "의식 없고", "의식 깨어있고", "숨도 안 쉼" | 핵심어 사이의 조사(은·는·이·가·도)와 어미를 지운 형태로도 비교 |
| 사전에 없는 동의어 | "가슴 쥐어짜는 통증", "힘이 없고 말을 못 함", "숨을 헐떡임", "수면제 과다 복용", "복부 통증", "숨 참" | 구급 기록·Pre-KTAS 표현으로 사전 확장 |
| AVPU 글자 | "의식 V" | A·V·P·U 단독 글자 인식 |
| 고유어 수 | "아흔둘" | 살·시간 외 단위에도 고유어 수 변환 |
| 지속 시간 표현 | "40분째" | '~째', '~동안'을 발생 시각으로 해석 |
| 모름 표현 | "확인 못 함" | 모름 표현 확장 |
| 주증상 묶음 설계 | 임신 중 하혈 → 출혈로 고름(기대: 산과), 두통 → 구토로 복통을 고름(기대: 기타) | 임신 중 출혈은 산과 우선. 두통처럼 묶음에 없는 주증상 처리 규칙 |

## 4-1 서버 음성 추출기와 비교

같은 시각 Codex가 서버 음성 API를 따로 만들었다. 서버 추출기는 `server/voice_terms.py`다. 같은 검증 문장으로 공통 칸 100개를 비교했다.

| | 서버 추출기 | voice_lab |
|---|---:|---:|
| 재현율 | 50.0% | 78.0% |
| 정밀도 | 87.7% | 97.5% |
| R1 전용 칸 37개 | 미지원 | 37/37 |

문장을 voice_lab 작성자가 써서 voice_lab에 유리한 비교다. 서버 쪽 원인과 R1 맞춤 방안은 [서버 음성 입력 API의 R1 맞춤 목록](VOICE_R1_ALIGNMENT.md)에 정리했다.

## 5 한계

- 문장은 합성이다. 실제 구급대원 발화, 말버릇, 사투리, 끊김이 없다.
- 음성 인식 오류(소음, 동음이의, 띄어쓰기 오류)를 넣지 않았다. 실제 정확도는 더 낮을 수 있다.
- 개발 문장과 검증 문장을 같은 작성자가 썼다. 검증 문장은 다듬기를 마친 뒤 썼지만 완전한 맹검은 아니다.
- 입력 시간이 실제로 줄어드는지는 재지 않았다. 손 입력과의 비교는 사용성 평가에서 업무 계측(R8 `patient_input`)으로 한다.

## 6 다음 단계

1. **v2 개선:** 4절의 유형을 고친다. 이 검증 문장은 이제 개발용으로 넘기고, **새 검증 문장**으로 다시 평가한다.
2. **음성 인식 연결:** 서버 PC에서 Whisper를 돌려 음성이 밖으로 나가지 않게 한다. 용어 사전을 인식 힌트로 넣고, 녹음 파일은 글로 바꾼 뒤 지운다.
3. **화면 연결(구급대원 앱 담당):** 버튼을 누르는 동안 녹음, 변경 목록 확인, 되읽어 주기
4. **효과 측정:** 같은 가상 시나리오로 손 입력과 음성 입력의 '입력+수정 시간'과 오류를 비교한다.
