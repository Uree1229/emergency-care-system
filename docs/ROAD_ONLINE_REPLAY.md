# 실제 도로에서 5개 배정 정책 재생

`simulation/road_online_replay.py`는 실제 병원 좌표와 카카오모빌리티 또는 OSRM 도로 예상시간을 **계산 입력부터** 사용해 R0·R1·R2·R3·C1을 새로 실행한다. 2026-10-14 현재 생성물은 **카카오 자동차 길찾기**로 새로 계산한 `simulation/viewer/road_online_allocation_data.json`이다. 기존 `online_allocation_data.json`, 잠금 설정과 합성 검증 결과는 변경하지 않는다. 이전 OSRM 시연은 `.codex-build/kakao-simulation-20261014/road_online_allocation_data.osrm.json`에 보존했다.

## 화면에서 선택할 사례

| ID | 내용 | 재생에서 확인할 것 |
|---|---|---|
| `road-online-simultaneous` | 같은 지점에서 가상 환자 5명 동시 발생, 1명은 첫 병원만 가진 가상 희소 역량 필요 | 환자별 첫 확정, 병원 용량 경합, 미배정 여부와 도로 이동 |
| `road-online-change-enroute` | 북쪽의 별도 도로 지점에서 환자 2명 발생, 수용 후 첫 병원의 가상 전문팀 사용 불가 | 전문팀이 필요한 환자만 영향받는지, 현재 도로 위치에서 대체병원으로 이동하는지 |
| `road-online-transfer-after-arrival` | 도착 평가에서만 가상 추가 치료 필요 확인 | 처음 도착한 병원에서 새 수용 확인 후 전원하는 경로 |

각 사례의 조건을 먼저 고정했으며 알고리즘 결과를 보고 좋은 사례를 뽑지 않았다. 병원에는 실제 수용 문의를 보내지 않는다.

## 실제 자료와 가상 설정의 구분

| 자료 | 출처·처리 |
|---|---|
| 병원 이름·위도·경도 | 국립중앙의료원 공개 API를 저장한 `data/public.db`, 읽기 전용 조회 |
| 사용 병원 | 오산한국병원, 의료법인청파의료재단송탄중앙병원, 의료법인갈렌의료재단박병원 |
| 도로 형상·일반 자동차 예상시간 | `KakaoRouteProvider`의 카카오모빌리티 자동차 길찾기 `TIME` 옵션, 조회시점 스냅샷을 다섯 정책이 공유. OSRM도 명시적으로 선택 가능 |
| 환자 발생 지점 | 사전에 정한 경기남부 가상 발생 좌표를 선택한 제공자의 도로망에 스냅한 위치 |
| 119 출동 이동 | 도로 예상시간을 분 단위 올림해 모든 정책에서 같은 도착시각 적용 |
| 현장처치 | 모든 사례 3분이라는 합성 설정 |
| 진료 역량·병상·전문팀·환자 상태·응답·자원 변화·처치시간 | 전부 합성. 실제 기관의 진료 능력·수용 현황을 뜻하지 않음 |

지도 배경을 제공하는 OpenStreetMap 타일과 카카오·OSRM 경로는 서로 다른 자료다. 카카오 REST 키를 등록해도 배경 타일을 카카오 지도로 바꾼다는 뜻은 아니다. 지도 배경이 로딩되지 않아도 저장된 도로 경로와 알고리즘 재생은 독립적으로 사용할 수 있다.

기존 가상 출동점 `[37.09, 127.04]`는 카카오에서 도로 탐색 실패(code 102)로 판정돼, 인근 도로 연결이 가능한 `[37.09, 127.064]`를 새 고정 출동점으로 사용한다. 이송 중 조건 변경 대상은 해당 사례의 발생점에서 **도로 ETA가 가장 짧은 병원**으로 재생 전에 정한다. 다른 발생점의 병원 순위를 가져오지 않으며, 알고리즘 결과를 보고 사건 대상을 선택하지 않는다.

## 지도 배경과 화면 조작

`http://127.0.0.1:18005/?scenario=road-online-change-enroute`에서 실제 도로 시연을 바로 연다. 시나리오 선택창의 **실제 도로 · 5개 배정 정책 시연**에서 나머지 두 사례도 선택한다.

- 지도 상단의 **일반지도 / 간략지도**로 도로·지역명 배경을 켜고 끈다. 일반지도는 OpenStreetMap의 현재 화면 타일만 브라우저에서 불러오므로 인터넷이 필요하다.
- 확대·축소·드래그를 하면 지도와 경로·병원·구급차가 같은 Mercator 좌표계에서 이동한다. 전체 보기 버튼으로 처음 범위를 복구한다.
- 배경 연결 실패는 별도 안내하고, 저장된 경로와 재생·결과 표는 계속 사용할 수 있다. 시뮬레이션 재생 중 매 프레임 타일을 다시 요청하지 않는다.
- 가상 좌표를 쓰는 기존 합성 사례·서버 기록에는 실제 지도를 표시하지 않는다. 기존 합성 검증 자료는 그대로 남아 있다.
- 지도 아래 출처에 배경 OpenStreetMap, 도로 Kakao Mobility 또는 OSRM, 간략 경계 geoBoundaries를 구분한다. 지도 배경은 도로·지역·녹지·수계를 표시하며 고도·실시간 교통 자료는 아니다.

### 환자 위치 가시성 (2026-10-14)

- 지도 오른쪽 위 **크게 보기**는 지도·환자 선택·정책 필터·재생 도구를 브라우저 영역 가득 펼친다. **작게 보기** 또는 **Esc**로 돌아온다. 같은 DOM을 이동해 재생 시점·환자·정책·줌·이동 상태를 보존한다. 키보드 포커스는 큰 지도 안에 머물고 닫으면 원래 버튼과 스크롤 위치로 복구한다. 모바일·가로 화면도 지원한다.
- 지도 타일의 채도와 강도를 낮추고, **환자 발생지**는 흰색 테두리가 있는 주황색 핀과 라벨을 가장 위에 표시한다. 고정 발생지와 이동 중인 구급차 위치는 구분한다.
- 기본 화면은 문의선·병원별 응답 점·긴 차량 ID를 생략한다. **상세 표시**를 누르면 문의선과 응답 정보를 다시 볼 수 있다. 사건 기록과 문의 집계는 표시 모드와 무관하게 유지한다.
- 범례와 정책 선택을 지도 밖으로 옮겼다. **전체 / A1–A5**는 지도만 필터링하며 계산 결과나 환자 상태를 바꾸지 않는다.
- **환자 위치 보기**는 현재 선택한 환자의 발생지와 해당 시점까지 기록된 이동 위치를 함께 화면에 맞춘다. 미래에 발생할 환자는 포함하지 않는다. 전체 보기로 초기 지도 범위를 복구한다.
- 차량의 작은 점은 도로상의 모의 위치다. 아이콘은 겹침을 피하도록 점에서 조금 떨어뜨려 표시하며, 확대해도 표식 크기를 유지한다.

카카오 최종 자료로 관련 Python 75개, 지도 기하 6개, 가시성·정책 필터·환자 중심 보기·기존 시나리오·390px 화면의 브라우저 검사 10개를 확인했다. 기록은 `.codex-build/kakao-simulation-20261014/visibility-qa.json`, 최신 화면은 `outputs/시뮬레이션_카카오_가시성개선_20261014.png`다. 오프라인 재생성의 사건·궤적·배정 48항목이 같았고 네트워크 요청은 0회였다. 실제 인증키가 생성물·캐시 27파일에 포함되지 않은 것도 확인했다.

큰 지도 후속은 별도 브라우저 검사 7개와 기존 가시성 10개를 통과했다. 1440×1000 화면에서 지도 영역은 1008×420에서 1414×654로 커졌고, 390px 모바일에서는 높이 약205px에서471px로 커졌다. 반복 열기·닫기, Esc, 상태·포커스·스크롤 복구, 가로844×390에서 지도/조작부 표시를 검사했다. 기록은 `.codex-build/large-map-20261014/qa.json`이다.

타일은 기본 브라우저 캐시와 Referer를 사용하며 일괄 수집·사전 다운로드 기능은 없다. [OpenStreetMap 타일 이용 정책](https://operations.osmfoundation.org/policies/tiles/).

지도 좌표 계산 시험은 `node --test test_viewer_basemap.cjs`로 실행한다. 2026-10-14 확인에서 관련 Python 61개와 지도 계산 6개가 통과했고, 실제 지도 표시·배경 전환·시간 재생·합성/실제 사례 전환·새 3사례·연결 실패·390px 화면의 브라우저 검사 10개를 통과했다. 화면 검사는 `.codex-build/road-basemap-20261014/qa.json`에 있다.

카카오 자동차 길찾기는 **API 조회 시점의 일반 자동차 예상시간**을 사용한다. 시뮬레이션의 경과시간에 맞춰 실제 교통을 갱신하거나, 실제 미래 도착시간·구급차 우선주행 시간을 예측한 것이 아니다. OSRM도 실시간 교통·구급차 우선주행 자료로 사용하지 않는다. 병원 좌표와 스냅된 도로 사이 접속은 시속 10km로 추정하며 별도 점선 연결구간으로 남긴다. 구간 내 위치는 누적 이동거리 비례로 보간하고 이동시간은 분 단위로 올림한다. 실제 구간별 신호·속도를 재현하는 모델은 아니다.

## 동일하게 유지한 정책 조건

- 동시 문의 3곳, 첫 수용 후 남은 응답의 추가 대기 2분, 변경 알림 켜기.
- 같은 가상 환자·응답 환경·외부 자원 사건·고정 도로 캐시.
- 현재까지 도착한 유효 수용 응답, 현재 자원과 현재 위치만 배정 판단에 제공.
- 미래 응답·자원 복구 예정시각·도착 후 추가 진료 조건은 정책 입력에서 제외.
- R0는 첫 수용 순서, R1은 현재 수용 후보 중 예상 도착 우선, R2는 자원 경합 고려, R3는 같은 분의 환자를 제한 열거, C1은 같은 분의 환자를 CP-SAT으로 공동 배정.

R3/C1의 목적은 미배정 우선순위 합, 이후 우선순위 가중 이동시간 합의 순서다. C1의 최적성은 그 시각의 배정 묶음에만 해당하며 전체 이송의 최적성을 보장하지 않는다. 실제 의료적 판단이나 임상 예후 검증도 아니다.

동시 발생 사례의 150분 자원 점유는 관찰 중 반환을 막는 스트레스 설정이다. 지도에서 정책별 차이가 보여도 그 수치를 실제 응급의료체계 대비 성과로 해석하면 안 된다. 별도 검증군에 포함되지 않은 설명용 사례다.

## 재생성

OR-Tools가 설치된 Python 환경에서 실행한다. 프로젝트의 `.solver_deps`를 쓰는 환경은 해당 디렉터리를 `PYTHONPATH`에 추가한다.

```powershell
# 현재 프로세스에 KAKAO_REST_KEY가 있으면 카카오, 없으면 OSRM 선택
python -m simulation.road_online_replay --provider auto
# 카카오를 명시하면 키·경로 실패 시 OSRM/직선 이동으로 대체하지 않음
python -m simulation.road_online_replay --provider kakao
# 유효한 카카오 로컬 캐시만 사용. 만료·누락되면 기존 생성물 보존
python -m simulation.road_online_replay --provider kakao --offline
# 이전 OSRM 경로를 명시적으로 사용
python -m simulation.road_online_replay --provider osrm --offline
```

경로가 캐시에 없거나 호출·응답 검증에 실패하면 저장을 중단하고 기존 출력 파일을 유지한다. 직선 이동이나 다른 제공자로 조용히 대체하지 않는다. 카카오 응답의 `result_code=0`, `summary.duration/distance`, 모든 `sections[].roads[].vertexes`와 구간 연결을 검증한다. X/Y(경도/위도) 배열은 내부 위도/경도 배열로 변환한다. API 호출은 초당 1회 이하로 제한하며 브라우저 재생 중에는 경로 API를 호출하지 않는다.

키는 프로세스 환경변수에서 읽어 Authorization 헤더에만 사용한다. 환자 정보는 보내지 않고 출발·도착 좌표와 자동차 길찾기 옵션만 전송한다. 응답 원문·키·헤더는 JSON이나 로그에 저장하지 않는다. 실패 메시지에도 API 응답문이나 인증 헤더를 붙이지 않는다.

카카오 캐시는 앱의 지도 재생 속도와 중복 호출 방지를 위한 로컬 자료이며 `.codex-build/kakao-route-cache`에 둔다. 기본 만료는 30분이고, 새 생성 시 만료 자료는 다시 조회한다. `--offline` 생성도 만료·손상·누락 캐시를 거부한다. 저장된 시연 JSON을 브라우저에서 다시 보는 것은 새 길찾기 요청이 아니라 **기록된 조회시점 자료의 재생**이다. 각 구간의 `fetched_at`을 남기며 이를 현재 교통 안내로 쓰지 않는다. 카카오 운영정책의 캐시 목적·최신 유지 제한에 따라 무기한 경로 데이터베이스나 재배포용 데이터셋으로 사용하지 않는다. [카카오 운영정책](https://developers.kakao.com/terms/latest/ko/site-policies)

```powershell
python -m unittest test_kakao_routes test_road_online_replay -v
```

단위 시험은 꺾인 도로와 실제 직선거리 순서가 다른 예상시간을 주어 배정 결과 자체가 바뀌는지, 출동시각에 도로시간이 반영되는지, 재배정 전후 경로가 끊기지 않는지, 도착 평가 후 전원이 발생하는지, 미래 정보가 판단 입력에 없는지, 도로 실패 시 기존 결과를 보존하는지 확인한다. 단위 시험의 도로는 네트워크 없는 시험용 자료다.

## 출력 계약

기존 지도 재생의 `schema_version=2`와 `scenarios` 구조를 사용한다. 각 시나리오에는 `online_allocation_comparison=true`, `real_road_allocation=true`와 고유한 `road-online-*` ID가 있다. `routing_summary`와 각 `trajectories[].legs[]`는 기존 도로 재생 형식을 유지하고 제공자는 `provider=kakao` 또는 `osrm`으로 구분한다. 카카오는 `traffic_snapshot=true`, 수집시각 범위, `ambulance_priority=false`를 추가한다. `allocation_decisions`의 이동 비용도 이 도로 입력으로 계산된다.

루트·시나리오·분기의 출처는 `road_online_allocation_comparison`, `validation_dataset=false`로 표시한다. 시나리오 `source.input_sha256`은 재실행 전 입력 해시다. 실행시간 측정값과 생성 시각은 재생성 시 달라질 수 있다.
