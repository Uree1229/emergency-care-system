# 원본·RNNoise 소음 억제 짝 비교

> 아래 실험 수치와 당시 파일 동일성 설명은 2026-10-31 후보의 기록입니다. 2026-11-02 후속 통합에서는 Quick 업무 화면에 명령 보류를 연결하고 메인 복구·화면 복귀 회귀를 보완했습니다. 현재 구성은 [통합 안내](PARAMEDIC_PENDING_INTEGRATION_20261102.md)를 따르며, 과거 검사 횟수를 이번 실행 결과와 합산하지 않습니다.

음성 명령 연습 화면의 **원본·소음 억제 비교** 링크에서 같은 녹음 하나를 두 경로로 비교한다. 억제 모델은 RNNoise이며 모델·실행 코드를 로컬 정적 자산으로 제공한다. 음성을 외부 서비스에 업로드하지 않는다.

## 적용 범위

원본 파일 또는 연습 녹음 보관함의 녹음을 읽고, 같은 디코딩·모노 변환·48kHz 변환 결과를 원본 PCM과 RNNoise의 입력으로 사용한다. 원본 파일의 바이트는 별도로 보존한다. 변환된 원본 WAV와 처리 WAV를 비교해야 코덱·샘플 속도 차이를 억제 효과로 오인하지 않는다.

플레이어와 다운로드는 사용자가 직접 실행한다. ZIP은 원본 파일, 비교용 WAV 두 개, 파일 해시와 처리 설정 및 비교 기록을 포함한다. 원래 연습 기록과 음성 보관함은 변경하지 않는다. 새 파일을 선택하거나 화면을 닫으면 현재 메모리의 비교 결과가 없어지므로 필요한 결과는 내려받는다.

이 페이지는 기존 브라우저 음성 인식의 마이크 경로를 바꾸지 않는다. `SpeechRecognition.start()`가 내부적으로 취득하는 마이크에 별도 처리 결과를 주입했다고 표시하지 않는다. 원본·처리본의 인식 비교에는 같은 엔진·모델·파라미터로 두 파일을 각각 인식해야 한다.

## 검증을 나누는 이유

1. **모델 실행 검증:** 실제 WASM이 PCM을 처리하는지, 길이·샘플 값·취소·메모리 해제가 올바른지 확인한다. 모의 STT가 아니다.
2. **파형 비교:** 깨끗한 합성 음성에 같은 seed의 잡음을 섞어 파형 충실도와 원음 손상을 비교한다. SI-SDR·RMS·출력 음량 감소는 인식 정확도와 다르다.
3. **동일 엔진 ASR 비교:** 같은 합성 원본·처리 음원에 로컬 ASR을 실행하고, 수정하지 않은 인식문을 기존 명령 파서에 전달한다. 정답을 힌트나 복원용으로 제공하지 않는다. 명령 종류, 오탐, 누락, CER, 수치·부정 표현의 오류를 구분한다.
4. **기존 기능 회귀:** 기존 명령·보류·원문 보존·환자 전환·인계 기능이 이번 추가로 바뀌지 않았는지 검사한다. 이 검사는 소음 속 청취 성능의 증거가 아니다.

현재 시험은 개발 중 비교이며 실제 구급차·여러 사람·마이크에서의 성능을 대표하지 않는다. 더 작은 모델이나 합성 TTS 한 화자의 결과만으로 실서비스 기본값을 정하지 않는다. 처리로 더 나빠진 사례도 결과에서 제외하지 않는다.

## 이번 실제 파일 인식 결과

12개 한국어 합성 발화 × 4조건에 잡음만 있는 3개를 더해 **51쌍**을 고정했다. 한 쌍마다 원본과 처리본을 같은 로컬 faster-whisper base로 인식해 **102회** 실행했다. 최초 실행과 무결성 검사를 보강한 최종 재실행을 모두 보존했으며, 두 실행의 인식문·판정은 동일하다. 이것은 새 사람 102명이 말한 자료가 아니다.

조건별 발화 12개에는 진짜 명령 6개(5종류와 종료 1개 추가), 비명령 6개가 있다. 잡음은 생성 음원이고 잡음 조건의 입력 SNR은 0dB다. 원본·처리본에 같은 변환과 공통 음량 배율을 적용했고, 처리 후 음량을 따로 정규화하지 않았다.

| 조건 | 원본 명령 성공 | RNNoise 명령 성공 | 원본 CER | RNNoise CER |
|---|---:|---:|---:|---:|
| 조용함 | 6/6 | 6/6 | 9.24% | 10.16% |
| 엔진 소음 | 6/6 | 6/6 | 9.24% | 8.55% |
| 사이렌 | 5/6 | 4/6 | 14.55% | 20.09% |
| 혼합 소음 | 3/6 | 0/6 | 21.02% | 123.79% |

원본에서 성공했으나 처리 후 놓친 명령은 4쌍이고, 반대로 복구한 명령은 0쌍이다. 비명령·잡음뿐인 27쌍에서는 원본·처리본 모두 명령 오탐이 관측되지 않았다. 짧은 고정 음원에서의 결과이므로 연속 입력의 시간당 오탐률이나 전체 사용자 정확도를 뜻하지 않는다.

CER는 공백·문장부호를 정리한 문자 편집 거리이며 숫자 단어와 숫자 표기를 의미상 같다고 보정하지 않는다. 혼합 소음 처리본에서 반복·삽입된 인식문이 나와 CER가 100%를 넘었다. 무인식이나 긴 틀린 출력도 제외하지 않았다. 수치·부정 표현 대본도 포함했지만 별도의 임상 항목 정확도 점수로 집계한 결과는 아니다.

파형 SI-SDR은 엔진·사이렌·혼합에서 평균 개선됐지만 인식 결과는 위와 같았다. 따라서 **현재 RNNoise를 모든 녹음·STT의 기본 전처리로 채택하지 않고, 원본을 보존하는 선택형 A/B 도구로 제공한다.** 후속 실제 사람·소음 자료에서도 같은 엔진의 원본 대비 명령 손실을 확인해야 한다.

모델은 `Systran/faster-whisper-base` revision `ebe41f70d5b6dfa9166e2c581c45c9c0cfc57b66`, faster-whisper 1.2.1 / CTranslate2 4.8.4 / PyAV 16.0.1이다. CPU int8, 한국어 고정, beam 5, temperature 0, 이전 발화 조건화·VAD·정답 힌트·hotwords 없이 두 경로를 동일하게 실행했다. 외부 음성 전송·유료 API·실제 마이크 입력은 0회다. 브라우저 내장 STT의 결과라고 해석하지 않는다.

이 PC의 원본 계획·합성 WAV·모든 인식문·실패 사례·파일 SHA-256은 `.codex-build/voice-denoise-20261031/`에 보존한다. `asr-run-001`은 최초 결과, `asr-run-002`는 최종 소스의 동일 조건 재실행이다. 이 개발 증거와 큰 ASR 모델은 Git 배포 대상에 포함하지 않는다.

## 오프라인 ASR 재검증 도구

`speech_eval/noise_pair_asr.py`는 별도 설치한 로컬 모델과 정답·파일 해시를 가진 고정 manifest를 받는다. 현재 manifest 형식은 명시적으로 합성 자료라고 표시한 16kHz mono PCM16 WAV 쌍 전용이다. UI의 48kHz WAV를 그대로 넣는 형식은 아니다. 기존 인식문을 정답으로 덮거나 임의로 환자 정보를 수정하는 기능이 없다.

필요한 패키지는 선택 설치용 `requirements-audio-asr-eval.txt`에 고정했다. 서버 실행의 필수 의존성을 늘리지 않는다. 실행 예:

```powershell
python -m speech_eval.noise_pair_asr --manifest <고정_manifest.json> --local-model-dir <이미_받은_모델_폴더> --output <새_결과_폴더> --node <node.exe>
```

출력 폴더를 덮어쓰지 않고 인식문을 순서대로 JSONL에 남긴다. 명령 파서는 실제 앱의 `recording-control.mjs`를 사용하며 원본·처리본별 성공·오탐·CER와 전후 파일 무결성을 별도로 기록한다.

## 소프트웨어·증거 검증

- 배포 후보의 `test_paramedic_*.mjs` **2,013개 통과**. 기존 1,929개에 실제 RNNoise WASM 검사 64개와 새 화면 검사 20개를 더했다. 화면 자동 검사에서는 디코더·마이크·보관함만 모의로 제공하며 실제 WASM을 실행한다.
- 오프라인 비교 manifest·오류 지표 검사 **29개 통과**. 이 중 신규 runner 경계 검사는 10개다.
- 별도 결과 읽기 검사 **313개 통과**. 보존된 인식문·독립 CER 재계산·앱 파서 판정·원본/처리 음원 연결을 확인했다. 실제 ASR은 51쌍이며 재실행을 독립 표본으로 합산하지 않는다.
- 기존 `recording-control`, `command-commit`, `command-trace`, `quick-test`, `command-practice`, `speech`, `practice-audio`의 실행 코드는 직전 배포와 동일하다. 연습 HTML에 비교 화면 링크만 추가했다.
- RNNoise의 고정 모델 지연은 소스와 실제 임펄스 실행에서 **960샘플(20ms)**로 확인했다. 두 프레임을 비우고 지연을 보정해 원래 샘플 수를 유지한다. 이것은 파일 비교의 정렬이며 실시간 지연 0ms라는 주장이 아니다.
- 실제 브라우저에서 최종 페이지에 합성 엔진 소음 원본을 넣어 처리·ZIP 다운로드까지 수행했다. 별도 Python으로 ZIP CRC·6개 항목·manifest 5개 파일 해시·원본 바이트 일치·두 WAV의 48kHz mono/각 309,600샘플을 확인했다. 이 화면의 STT 실행은 0회이며 위 로컬 ASR 실험과 별도 검증이다.

위 숫자는 소프트웨어 및 해당 합성 자료의 검사 범위다. 실제 사람·구급 현장 검증, 브라우저 STT에 처리 트랙을 직접 연결한 검증, STT 향상률·임상 항목 정확도·시간당 오탐률 측정으로 바꾸어 해석하지 않는다.

## 직접 비교

1. 명령 연습에서 가상 대본을 읽고 원본 녹음을 보관한다. 주변 소음을 재생하더라도 실제 음량·거리·SNR을 모르면 미측정으로 기록한다.
2. 비교 화면에서 보관함을 읽거나 원본 파일 하나를 선택하고 RNNoise 비교를 실행한다.
3. 원본과 처리본을 같은 재생 음량으로 듣고 내려받는다. 별도 재생 음량 정규화는 하지 않는다.
4. 같은 STT 엔진에서 두 파일을 인식하고, 각 인식문과 공통 정답을 비교 기록에 넣는다. 텍스트를 직접 입력한 결과는 수동 입력으로 남긴다.
5. 숫자·부정·시간 설명·인용·명령 없는 발화와 진짜 명령을 함께 시험한다. 특히 ‘종료 시각’, ‘종료하지 마’, ‘병원 추천해줘’를 다른 발화로 나누어 확인한다.

## 근거

- [RNNoise 공식 구현](https://github.com/xiph/rnnoise): 신경망 기반 음성 소음 억제. 명령 의도 판별이나 의료정보 복원 모델이 아니다.
- [Jitsi RNNoise WASM](https://github.com/jitsi/rnnoise-wasm): 브라우저용 WASM 배포의 원 출처. vendored 파일과 라이선스·해시는 해당 vendor 폴더에서 확인한다.
- [Jitsi의 AudioWorklet/RNNoise 설명](https://jitsi.org/blog/enhanced-noise-suppression-in-jitsi-meet/amp/): 브라우저 프레임과 RNNoise 처리 프레임의 차이.
- [Web Speech API](https://webaudio.github.io/web-speech-api/): 기본 마이크 인식과 선택적 오디오 트랙 입력은 다른 경로다. API 명세에 오버로드가 있다고 현재 브라우저 지원을 가정하지 않는다.
- [faster-whisper 공식 구현](https://github.com/SYSTRAN/faster-whisper): 로컬 동일 엔진 파일 인식 비교 도구. 브라우저 STT와 동일한 엔진이라는 뜻은 아니다.
