# 확인 대기 환자의 병상 기회 보호

2026-10-15 · 합성 시뮬레이션의 배정 단계 개선 · 운영 서버에는 미적용

## 결과

기존 정보 누락 실험에서 발견한 문제를 대상으로, **확인 대기 환자를 제외한 채 유연한 환자부터 확정하는 시점을 잠시 늦추는 규칙**을 추가했다. H1·C1의 목적함수와 솔버는 그대로 두고 현재 배정 대상이 모이는 과정을 바꿨다.

개발 48사례 × 8분기 후 소스·설정·런타임을 잠그고, 사용하지 않은 시드의 **검증 96사례 × 8분기 = 768회**를 실행했다. 각 규칙의 환자 실행 수는 294명이다. 모든 병원·환자·자원·회신·이동시간은 합성이다.

| 전문팀 정보만 누락된 조건 | 보호 전 | 보호 후 | 해석 |
|---|---:|---:|---|
| 완전정보 대비 전체 환자 평균 도착 지연 | +8.500분 | +0.667분 | 동일한 새 검증 사례의 18명 기준 |
| 전문팀 필요 환자 P03 도착 변화 | 기준 | −30.333분 | 6명 모두 빨라짐 |
| 대안 병원으로 간 환자 P02 도착 변화 | 기준 | +6.833분 | 6명 모두 늦어짐 |
| P01 도착 변화 | 기준 | 0분 | 6명 동일 |

H1·C1 모두 위 집계가 같다. P03이 필수 자원을 확인하는 동안 P02의 확정을 잠시 유보하고, 정보가 도착하면 P03은 NEAR, P02는 FAR로 공동 배정한다. **P02의 비용에는 유보와 더 먼 병원까지의 이동이 함께 들어간다.** 3분 유보 예산을 실제 도착 지연의 상한으로 해석하지 않는다.

새 검증 시드의 보호 전 지연은 8.5분이다. 앞선 정보 누락 실험의 다른 시드에서 얻은 9.5분과 분모가 다르므로 두 값을 직접 전후 비교하지 않는다.

## 보호 규칙

다음 조건을 모두 만족하는 경우만 적용한다.

1. 이미 관측된 SEARCH 환자에게 현재 유효한 병원 수용 회신이 있다.
2. 진료 역량을 기준으로 구조적으로 가능한 병원이 **한 곳**이다.
3. 필요한 자원 중 일부가 unknown/stale이어서 별도 수량 재확인을 기다린다. fresh 부족인 후보는 보호 대상에서 제외한다.
4. 해당 병원의 `ed_bed`는 fresh이고, 현재 확정 예약·등록 대기를 뺀 관측 가용 병상이 확인된다.
5. 같은 병상을 사용할 수 있는 현재 배정 대상 중 구조적 대안 병원이 있고, 우선순위가 같거나 낮은 환자가 있다.

현재 배정 대상이 선택할 수 있는 병원별 병상 수요를 보수적으로 합산한다. 확인 대기 수요까지 합치면 알려진 병상을 넘는 경우, 낮은 우선순위 → 늦은 요청 → 큰 환자 ID 순으로 일부 경쟁 환자를 유보한다. 필요한 여유를 만들 수 없으면 해당 보호를 적용하지 않는다. 여러 대기 환자는 높은 우선순위 → 빠른 요청 → 환자 ID 순으로 검토한다.

이 규칙은 우선순위 순서로 여유를 만드는 방식이며, 서로 다른 병상 수요에서 유보 인원 수의 전역 최소화를 보장하지 않는다. 구조적 대안은 진료 역량의 일치일 뿐 해당 대안 병원의 현재 수용 보장이 아니다.

## 무한 대기·응답 만료 방지

- 첫 unknown/stale 확인 대기부터 최대 3분, 유보된 환자의 첫 실제 유보부터도 최대 3분이다. 더 이른 기한을 적용한다.
- 재문의·새 수용 응답·새 대기 환자가 생겨도 두 시계를 초기화하지 않는다.
- 대기 환자의 수용 회신이나 유보 환자의 마지막 현재 수용 회신이 다음 분에 만료된다면 유보하지 않는다.
- 확인이 끝나면 일반 H1·C1 현재 배정 모델에 다시 참여한다. 기한이 끝나거나 유효 회신이 없으면 보호를 해제한다.
- 더 높은 우선순위의 현재 배정 환자, 구조적 대안이 없는 경쟁 환자는 이 규칙으로 유보하지 않는다.

실제 병상을 예약하거나, 병원 응답을 자동 확정하거나, 자원 수량이 미확인인 환자를 솔버에 넣는 방식이 아니다. 병원 내부의 환자 우선순위를 바꾸지도 않는다.

## 전체 검증과 불리한 조건

H1·C1 각각의 보호 전/후를 같은 현재 정보 조건에서 비교했다.

| 항목 | 보호 전/후 비교 |
|---|---|
| 환자 실행 수 | 각 294명 |
| 공통 도착 | 270명 |
| 빨라짐 / 늦어짐 / 동일 | 25 / 41 / 204명 |
| 공통 도착 평균 변화 | −1.896분 |
| 공통 도착 최대 악화 | +8분 |
| 한쪽에서만 도착 | 양쪽 모두 0명 |
| 미배정·미도착 | 각각 24 → 24명 |
| 수용 문의 수 | 839 → 745회 |
| 보호가 적용된 고유 환자 | 36명 |

평균이 개선되어도 늦어지는 환자가 더 많다. 일부 대기 환자의 큰 지연을 줄이는 대신 다른 환자의 이동·대기 비용을 늘리는 결과다. 모든 환자의 비악화나 전역 최적성은 주장하지 않는다.

- **전문팀 정보가 끝내 오지 않음:** 확인 대기 환자는 자동 배정되지 않는다. 유보된 일반 환자는 3분 늦어진다. 공통 도착 12명의 평균은 +1.5분 악화됐다.
- **재확인 응답이 5분 걸림:** 3분 기한이 끝나면 병상을 계속 보호하지 않는다. 공통 도착 18명의 평균은 +1.444분 악화됐다. 이후 병상 해제와 재문의 시점이 맞물려 대기 환자도 6명 중 5명은 2분 늦어졌다.
- **높은 우선순위의 준비 환자 / 대안 병원 없음 / 짧은 수용 유효기간:** 보호를 적용하지 않았고 해당 검증 사례의 보호 전후 도착은 같다.
- **모든 자원 정보가 계속 없음:** fresh 병상도 없으므로 보호하지 않는다. unknown을 가용량으로 대신하지 않는다.

미배정 24명은 전체 자원 정보가 확인되지 않는 유형의 18명과 전문팀만 끝내 확인되지 않는 유형의 6명이다. 관측 수량을 요구하는 **자동 배정 미확보**이며 실제 병원의 임상적 수용 거절이나 기존 운영 서버의 수동 확정 불가를 뜻하지 않는다.

## 검증 방법

8분기는 `perfect_R1/H1/C1`, `observed_R1/H1/C1`, `protected_H1/C1`이다. 문의 3곳·첫 수용 후 추가 대기 2분·변경 알림은 같고, H1·C1의 50ms 탐색 설정도 같다. 실행 순서를 시드·유형에 따라 순환한다. 배정 계산시간과 보호 처리시간을 별도 측정하며 분 단위 시계에는 더하지 않는다.

기존 8개 정보 유형에 확인 실패·2분 확인·5분 확인·대기 환자의 높은/낮은 우선순위·복수 대기·대안 없음·수용 만료 8개를 더했다. 개발 시드는 19101–19103, 새 검증 시드는 20101–20106이다. 유형은 알고 있는 유형이며 새 시드는 실제 현장 일반화를 입증하지 않는다.

**관련 테스트 298개 통과.** 독립 감사기는 시뮬레이터·관측 저장소·보호 규칙·솔버를 실행하지 않고 저장된 원시 사건만으로 관측·수용·상태·두 시계·보호 결정·모델 대상을 다시 구성한다. 수량 변조, 미래 환자, 시계 초기화, 높은 우선순위 유보, 수용 만료, 모델 대상 변조를 거절하는 테스트를 포함한다.

저장한 검증 결과 재감사에서 1,602개 배정 결정, 450개 보호 평가, 132개 유보 검사, 522개 CP-SAT 모델 증명의 독립 완전탐색 재확인을 통과했다. 72명 유보 수는 H1과 C1의 각 36명을 합친 실행 수다. H1의 기준안·탐색 기록도 독립 확인한다.

현재 수용 모델의 증명은 보호 후 모델에만 해당한다. 최종 실제 확정 검사는 **환경의 실제 자원을 즉시 확인할 수 있다는 가정**을 유지한다. 운영 서버가 미보고 병원 상태를 자동 감지한다는 뜻이 아니며 최종 확인 자체의 지연·실패는 검증하지 않았다. 현재 서버의 등록 예약·대기 원장은 즉시 알려진다고 가정한다.
