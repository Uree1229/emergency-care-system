# 프로젝트 전체 잔여 업무와 개선 우선순위

> 이후 알고리즘·지도 시연·병원 운영·복구 후속이 완료됐다. 아래는 당시 업무 정의를 보존한 초기 목록이며, 현재 잔여 여부는 [최종발표를 제외한 현재 남은 작업](CURRENT_REMAINING_WORK_20261030.md)을 따른다. 알고리즘 추가 실험은 종료했고 최종발표 제작은 보류한다.

2026-10-30. 로컬 코드와 구현·검증·팀 인계 문서를 대조한 정리다. 원격의 모든 최신 브랜치를 다시 검토한 결과는 아니다. 오래된 문서의 ‘미구현’ 표기보다 현행 API·화면 코드를 우선했다. 이번 정리에서 UI·서버 동작·DB는 변경하지 않았다.

현재 단계는 **핵심 서버 구현과 합성 연결 검증 완료 → 최신 기능의 화면 통합·실제 기기 검증·최종 성과 평가**다. 알고리즘 후보를 계속 늘리기보다 실제 사용할 경로를 하나로 완성하는 것이 우선이다.

### T09에서 확인할 구체 사항

Claude 인계 문서에는 `claude/voice-v2-ui-20261030`에 서버·음성 UI 스냅숏을 올렸고 이후 Codex 변경은 로컬에 남을 수 있다고 기록돼 있다. 현재 로컬 브랜치는 `codex/peer-review-server-20261029`이며 미커밋·미추적 파일이 많이 섞여 있다. 따라서 ‘공유 브랜치를 받았다’와 ‘현재 559개 회귀를 통과한 전체 변경을 받았다’를 동일시하지 않는다.

현재 동결은 원본 바이트 SHA를 사용한다. Windows 체크아웃의 CRLF/LF 변환, Python·OR-Tools·SQLite 차이가 재현 검사에 영향을 줄 수 있다. 줄바꿈·의존성·실행 환경 정책을 정하고, 기존 v1 해시를 통과시키려고 조용히 바꾸지 않는다. 필요하면 새 기준 버전과 사유를 남긴다. 기존 동결 소스 사본은 보존한다.

| R05 | 최신 흐름과 도로 경로 통합 검증 | 카카오 경로 기능은 이미 있음. 최신 음성 검증은 합성 이동시간이므로 새 흐름의 현재 위치·대체 경로·캐시·추정 대체 표시까지 결합 |
| R06 | 좋은 사례·나쁜 사례·차이 없는 사례 보존 | 차이가 큰 사례만 골라 성과처럼 제시하지 않음. 왜 개선됐는지/왜 늦어졌는지 로그로 설명 |
| R07 | 발표·시연·질의응답 업데이트 | 실제 구현/합성 기능 검증/성능 평가/향후 계획 분리. 정상·조건 변경·실패 상황을 준비하고 네트워크 장애용 녹화·동결 경로도 준비 |

### 알고리즘 비교에서 특히 정리할 점

- 실제 서버 기준은 `fixed_3 + CP-SAT severity_first`다. 서버 자체가 CP-SAT을 쓰므로 전체 시스템을 막연히 ‘우리 알고리즘 vs CP-SAT’으로 나누지 않는다.
- 서버 목적은 가중치 4→2→1별 미배정 수의 사전식 최소화다. 일부 H1/C1 연구의 가중 미배정 합과 같지 않다. 동일 문제 비교인지 정책 목표 비교인지 먼저 정한다.
- G2/G5 배정 연구, QI/QJ 문의 개선, Claude EAT 문의 연구와 실제 서버 탑재 여부를 분리한다. EAT 연구의 성과가 그대로 서버의 성과가 되는 것은 아니다.
- G5 새 검증에서는 13,670명 중 1명만 3분 단축돼 뚜렷한 시간 우위가 없었다. QI/QJ 8개 후보도 기존 성과 보호조건 미달로 미채택됐다. 기본 정책을 조용히 바꾸거나 불리한 결과를 삭제하지 않는다.
- 미배정·고우선순위 성과를 유지하면서 평균을 줄이는 것이 목표라면 보호조건을 최종 평가 전에 고정한다. 실제 현행 운영 알고리즘 전체를 재현한 비교가 아니면 ‘현행 체계보다 빠르다’고 일반화하지 않는다.
- 알고리즘 실행 결과를 모았다는 사실만으로 학습을 했다고 부르지 않는다. 현재는 정책·최적화 해법의 비교 실험이다. 별도 학습 모델과 검증 자료가 없다면 예측 성과를 주장하지 않는다.

## 6. 외부 공개가 필요할 때: 배포·권한·자료 관리

| 업무 | 현재 상태와 남은 작업 |
|---|---|
| 로그인·역할 권한 | actor_id·병원 ID는 시연용이다. 외부 공유 시 로그인, 병원별 접근 제어, 작업자 식별자를 신뢰할 경로 구현 |
| 공유 환경 | 서버 주소·HTTPS·허용 Origin·환경변수·의존성·워커·DB 보존을 정리. 현재 로컬 합성 시연만 한다면 클라우드 실배포는 선행 필수가 아님 |
| 자료 보관·삭제 | 원본 오디오는 저장하지 않지만 인식문·초안·수정 이력은 DB에 남음. 테스트 DB·백업의 공유 제외와 보관·삭제 규칙 정리 |
| 실제 병원 연계 | 실제 기관 접속·업무 담당·입력/응답 책임·갱신 방식이 필요. 공개 조회 API만으로 실제 병원 통신이 완료되지는 않음 |

시연 데이터는 합성/익명 자료로 유지한다. 실제 임상 도입을 캡스톤의 필수 완료 조건과 혼동하지 않는다.

## 7. 당장 늘리지 않아도 되는 범위

- 새 AI/예측 모델: 현재 실제 수용·처치 종료 학습 자료가 부족하다. ‘곧 수용 가능’ 예측을 먼저 약속하지 않는다.
- G5 이후의 무제한 알고리즘 후보 확대: 지금은 기준을 유지하고 통합·평가를 마무리한다.
- 네이티브 앱 전면 재개발·별도 실시간 전송 체계 재구축: 기존 웹·폴링·API 흐름을 먼저 완성한다.
- 운영체제 푸시: 중요 사건 표시·실제 확인·복귀 복구를 먼저 완성한다. 백그라운드 알림을 필수 시연 요구로 정하면 그때 전달 방식과 검증을 별도 추가한다.
- 전국 실제 병원 상용 연계·임상 진단 자동화: 이번 시제품의 완료 범위를 넘는다.

## 8. 담당과 권장 실행 순서

| 담당 | 우선 맡을 내용 |
|---|---|
| 정진 | 최신 작업 정리·서버 통합 실행본, API 연결 지원, 실패·재접속 검증, 데이터 구분, 음성 사건→지도 재생, 평가 설계와 보고서 |
| Claude | `paramedic-ui/` 음성 기능의 메인 화면 통합, 치료조건 검토·미확정 표시, 새 실제 마이크 평가 |
| 김민석 | 공통 구급대 진행 화면, 추천·단계 요약·중요 알림·복구·통화 기록·업무 계측 |
| 김준성 | 병원 문의·추천·미확정 표시·취소 인지·재확인·알림·통화함·업무 계측·외부 유입 종료 |

권장 순서는 **① 최신 코드·실행 기준 정리 → ② 한 진입점에서 음성·문의·추천·변경 검토 연결 → ③ 두 기기로 정상/조건 변경/실패 시연 → ④ 최신 사건 지도 재생 → ⑤ 미사용 자료·사용성 평가 → ⑥ 발표·배포본 확정**이다. 팀원 화면은 각 담당자가 수정하고 정진은 서버 계약과 재현 가능한 검증으로 지원한다.
