# 과거 대기 보호 W1 후보와 별도 검증

2026-10-30. **W1을 구현해 기존 36환경과 새 60환경을 평가했으나 연구 추천 조건을 충족하지 못해 채택하지 않는다.** 기존의 한 67분 지연은 줄였지만 다른 환자를 H1보다 최대 83분 늦췄고, 새 검증 987명에서는 H1 대비 도착 개선이 없었다. 실제 서버의 고정3 문의·CP-SAT `severity_first`·3초 설정은 그대로 유지한다.

같은 우선군의 오래 기다린 환자를 짧은 이동시간 때문에 뒤로 미루는 선택을 개선하는 단일 연구 후보다. 실제 서버 설정은 이 실험의 비교 분기가 아니므로 연구 결과를 서버 CP-SAT의 우열로 해석하지 않는다.

## 실제 평가 결과

기존 36환경·603명은 개발·회귀 자료, 새 60환경·987명은 별도 합성 검증이다. 성능 실패에 따라 환경을 골라 제외하거나 후보를 수정하지 않고 총 96환경·384분기를 모두 완료했다. 아래 값은 방식당 같은 고정 환자 코호트의 기술통계다.

| 단계 | 환자 | W1−H1 제한값 감소 / 증가 / 동일 | W1−H1 최대 증가 | W1−R1 최대 증가 | 판단 |
|---|---:|---:|---:|---:|---|
| 기존 개발 36환경 | 603 | 3 / 5 / 595 | 83분 | 67분 | 지연 전가, R0 성공 기록 상실 등으로 실패 |
| 새 검증 60환경 | 987 | 0 / 0 / 987 | 0분 | 124분 | H1 대비 개선 없음, R0/R1 성공 기록 보호 실패 |

새 검증의 H1/W1 동일 987명에는 **양쪽 미도착 85명**이 포함된다. 나머지 902명은 양쪽 도착 기록과 도착 경과시간이 같다. ‘987명 모두 같은 성공’으로 표현하지 않는다. 새 검증의 R1 대비 최대 124분 악화는 H1에도 동일하게 존재했으며, 기존 36환경의 최대 67분을 새 검증의 최대값으로 재사용하지 않는다.

총 미도착 수가 같아도 성공한 환자 ID는 다르다. W1은 새 검증에서 R0의 선정 기록 8명·도착 및 치료 시작 기록 각각 12명을, R1의 선정 기록 9명·도착 및 치료 시작 기록 각각 13명을 보존하지 못했다. H1과 W1의 관측 끝점은 같으므로 이 손실을 W1의 대기 항목이 새로 만든 차이라고 설명하지 않는다. W1이 이 보호조건을 충족하는 새 개선책이 되지 못했다는 뜻이다.

## 67분 사례의 개선과 지연 전가

시각은 합성 시계의 절대 분이며 선정은 최초 확정 사건이다. 다음 사례는 전체 효과의 표본을 대신하지 않는 사후 설명이다.

| 기존 raw / 환자 | R1 선정→도착 | H1 선정→도착 | W1 선정→도착 | 해석 |
|---|---|---|---|---|
| 003 / P02 | 19→29 | 86→96 | 19→29 | 같은 우선군의 오래 기다린 환자 도착 67분 단축 |
| 003 / P05 | 69→77 | 19→27 | 45→53 | 위 환경의 다른 환자는 H1보다 26분 지연 |
| 016 / P05 | 8→15 | 75→82 | 75→82 | 다른 우선군과의 경쟁에 따른 기존 +67분은 유지 |
| 031 / P05 | 59→79 | 119→139 | 59→79 | H1보다 60분 단축 |
| 031 / P12 | 141→160 | 59→78 | 142→161 | 같은 환경의 다른 환자는 H1보다 83분 지연 |

따라서 ‘67분 문제 해결’로 발표하지 않는다. 현재 배치에서 대기를 보호해도 이후의 자원 점유·회신·다른 환자 선택이 함께 바뀌어 전체 도착 지연을 전가할 수 있다. 003에서는 P05 외에도 P07·P06·P08이 H1보다 각각 43·32·28분 늦었다. 우선군이 다른 동시 발생 사례는 첫 목적을 유지하는 W1의 변경 범위 밖에 남았다.

기존 `027 / P19`도 W1에서 도착·치료 시작 기록이 없다. R0는 관측 종료 t180에 두 사건이 있고 도착 제한값은 양쪽 모두 126분이다. 이 시간차 0의 성공 기록 상실도 보호조건 실패로 보존한다.

새 검증의 우선군4에서 W1−R1 개인 최대 증가는 112분, 우선군2는 124분, 우선군1은 87분이다. 세 값 모두 H1과 같다. 전체 미배정 수나 우선군 미배정 수 감소만으로 기존 성공 환자나 모든 개인의 보호를 주장하지 않는다.

새 검증의 W1 판단 833회 중 812회는 같은 우선군의 대기 차이가 없었다. 나머지 21회는 작은 현재 문제를 전수 열거했지만 더 나은 W1 목적값이 없어 H1 기준 계획을 유지했다. 실제 계획 변경은 0회, 최대 후보 평가도 108회여서 이번 효과 부재를 2,048회 예산 부족으로 설명하지 않는다. 기존 개발에서는 511회 중 대기 차이 14회, 실제 계획 변경은 003/t19와 031/t59 두 번이었다.

새 검증의 문의는 H1/W1 모두 8,900건이다. 저장된 판단 경과시간 833개의 평균/p95/p99는 H1 0.091/0.151/0.250ms, W1 0.220/0.340/0.491ms였다. 최대는 H1 0.349ms, W1 12.721ms다. 단일 실행의 실제 프로세스 측정이며 반복 벤치마크나 현장 지연 추정이 아니다. 계산시간은 합성 시계에 더하지 않았으며 추가 계산 비용과 도착 성과를 구분한다.

## 변경한 판단 기준

신규 `simulation/waiting_assignment_20261030.py`는 현재 배치에서 원 H1을 먼저 계산하고, 남은 탐색 예산으로 다음 목적을 사전식으로 줄인다.

1. 현재 미배정 환자의 우선순위 가중합.
2. 우선군 4→2→1 각각에서 오래 기다린 집단부터 세는 미배정 수.
3. 현재 배정의 우선순위 가중 이동시간 합.

대기는 기존 허용 입력의 `현재 t − request_t`다. `request_t`는 실제 문의 시작 시각인 `search_start_t`이며 새 미래 정보 필드를 추가하지 않는다. 각 우선군의 가장 짧은 대기 집단은 두 번째 목적에서 생략한다. 같은 우선군의 대기가 모두 같으면 새 대기 항목이 없고 원 H1 선택을 유지한다. 우선군 숫자는 이 실험의 가중치이며 임상 분류 검증을 뜻하지 않는다.

희소 병원 사례와 같은 현재 배치에서 같은 가중치의 오래 기다린 환자(이동 10분)와 새 환자(8분)가 한 자리를 경쟁하면, W1은 2분의 이동 절약보다 오래 기다린 환자를 보호한다. 첫 목적이 우선이므로 더 높은 가중치 환자와의 경쟁에서 오래 기다렸다는 이유만으로 가중 미배정 합을 늘리지는 않는다.

H1 기준 계산과 추가 W1 탐색을 합해 탐색 후보 계획 평가를 최대 2,048회 수행한다. 원 H1의 평가 횟수 정의를 따르며 초기 기준해·입력 검증·스냅샷 구성 비용은 이 횟수에 넣지 않고 실제 경과시간에 포함한다. H1이 전부 쓰면 W1 추가 탐색은 없다. 이 단위는 CPU 명령 수나 동일한 계산량 보장을 뜻하지 않으며 실제 시간을 별도로 보고한다. 전체 호출의 10초 기술 한도를 넘으면 성과로 반환하지 않고 기술 실패로 중단한다. 원본 H1 및 동결 서버 파일은 수정하지 않는다.

이 보호는 **동일한 현재 스냅샷의 H1 미배정 가중합**에 대한 것이다. 이후 자원 점유·문의 회신·환자 선택이 달라지는 전체 재생에서 개인 도착 비악화를 보장하지 않는다. 그 차이를 별도 검증한다.

## 결과 열람 전에 고정한 검증

규칙은 `config/waiting_protocol_20261030.json`과 독립 감사의 `GATE_CRITERIA`에 기록했다. 후보는 W1 한 개이며 성과를 본 뒤 파라미터나 통과선을 바꾸지 않는다.

- 기존 36환경·603명은 이미 관측한 개발·회귀 자료로만 사용한다.
- 같은 12조건에 조건당 새 seed 5개를 사용한 60환경을 별도 새 합성 검증으로 평가한다.
- 모든 입력 해시, seed, 소스 사본, 실제 4분기 실행 순서를 최초 실행 전에 잠근다. R0/R1/H1/W1의 문의는 모두 고정3·추가 대기2분·알림 사용이다.
- 개발 성능 실패여도 사전에 고정한 새 60환경을 모두 실행한다. 기술 예외·감사 오류·소스 변경은 실패 증거를 남기고 중단하며 seed를 골라 교체하지 않는다.
- 로컬에 저장된 비압축 JSON에서 새 seed 중복을 검사한다. 압축 raw·삭제 파일·다른 PC·접근 불가 과거 이력까지 미사용을 증명하지 않는다.

개발과 새 검증을 각각 다음 조건으로 판단한다. 통과는 연구 추천 자격이며 운영 자동 채택이 아니다.

| 보호 조건 | 사전 기준 |
|---|---|
| 기술 무결성 | 입력·과거 대기·현재 수용·자원·실제 확정·예산 위반 0 |
| 기존 성공 환자 | R0/R1/H1 각각의 선정·도착·치료 시작 기록을 가진 환자 ID 상실 0 |
| 다른 환자로의 지연 전가 | H1 대비 개인 도착 제한값 증가 최대 0분 |
| 우선군 분포 | 각 조건×우선군4/2/1의 도착 제한값 평균·p95·p99가 H1 대비 비악화 |
| R1 대비 최대 악화 | 전체 및 우선군별 W1−R1 개인 최대 양의 차이가 H1−R1보다 크지 않음 |
| 실제 개선 | H1보다 도착 제한값이 엄격히 감소하고 실제 도착한 환자 1명 이상 |

미도착자의 제한값은 환자 발생부터 관측 종료까지다. 양쪽 미도착이나 종료 시각 도착과 미도착은 같은 성공이 아니다. 제한값 차이가 0이어도 도착·치료 시작 기록 상실을 별도 실패로 센다.

## 구현 및 해석 범위

- `simulation/waiting_experiment_20261030.py`: 원본 3분기 실행을 그대로 사용하고 W1을 분리된 현재 관측 객체로 실행한다. 새 출력만 허용하며 raw·입력·소스·잠금·실패 증거를 보존한다.
- `simulation/waiting_audit_20261030.py`: 후보·시뮬레이터·실행기를 불러오지 않고 현재 목적값·과거 대기·배정·작은 문제의 독립 전수 계산·환자 사건과 보호 조건을 검사한다.
- 실제 병원 업무시간·임상 결과·관측 지연·실제 도로 효과와 전체 자원 이력의 독립 재생은 검증 범위 밖이다. 문의 수는 업무량의 대리 지표다.
- 새 자료도 60개의 합성 환경 안에 환자가 묶이고 조건당 환경은 5개뿐이다. 개인을 독립 표본으로 취급한 유의성·현장 대표성·임상 안전성·일반 우월성을 주장하지 않는다.
