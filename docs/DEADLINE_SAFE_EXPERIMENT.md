# 늦은 병원 회신과 진행 중인 문의 보호 검증

2026-10-16 · 합성 이송 실험 · 요청한 6건 회귀 해결 · 전체 후보 채택 보류

직전 보충 문의안에서 1분 늦어진 6건은 실제 도착한 늦은 회신을 별도로 재검증해 복원했다. 각 사례의 처치 시작은 **9.25→8.25분**, 다른 환자는 **3.5분 유지**, 전체 대기는 **각 1환자·분 감소**, 문의는 **각 1건 감소**했다. 기존에 15초 빨라졌던 6건의 효과도 보존했다.

새 검증에서도 직전 보충 문의안 대비 환자 도착·처치 악화와 환경별 대기 증가는 없었다. 그러나 다른 비교 기준에는 대기와 이동시간의 절충이 남아, 엄격한 전체 채택 조건은 실패했다. 실험 선택은 기존 보호 V4를 유지하며, 실제 서버 기본값인 고정3도 변경하지 않았다. 이번 코드는 별도 시뮬레이션 후보다.

## 수정한 회신 처리

직전 보충안은 H02 문의를 0.25분에서 0분으로 앞당겼다. 같은 실제 병원 심사 작업은 3.25분에 끝나는데, 원래 3분 문의 기한은 3.25분에서 3분으로 앞당겨졌다. 늦은 회신이 폐기돼 재문의가 필요했고 도달이 1분 늦어졌다.

원 문의는 예정대로 시간 초과 처리하고, 기존 무응답 이력과 피드백도 유지한다. 이후 실제 회신이 도착했을 때 다음 조건을 전부 확인해 새 제안으로 받을 수 있다.

- 최초 보충 문의에서 실제 수신한 회신이며, 원 기한을 지난 시간이 최대 15초다.
- 아직 탐색 중이고 이전 목적지 확정이 없으며, 같은 병원에 더 새 문의를 제출하지 않았다.
- 식별자·입력된 우선순위·필수 자원 수요·필요 역량의 조건 지문이 같다.
- 현재 수신한 자원 정보가 신선하고 충분하고, 실제 병원 평가도 수용 가능이다.
- 이미 쓸 수 있는 수용 제안이 없고, 현재 등록된 같은 우선순위 이상 환자에 대한 희소 기회 충돌 검사를 통과한다. 이 검사는 단일 구조 후보·신선하고 충분한 필수 자원·유효 수용 또는 원 문의의 1분 보호창을 가진 환자의 병상 수요에 한정된다.
- **현재 진행 중인 다른 원 문의가 하나라도 있으면 선택적인 늦은 제안을 거부한다.**

회신을 추가로 기다리지 않는다. 제출된 원 문의의 기한, 기존 FIFO 심사 작업, 기존 제안의 만료를 변경하지 않는다. 실제 수신 시점부터 새 제안의 만료를 계산하고 배정 시점에 기존 물리 자원 검사도 다시 적용한다. 새 제안을 이용하면 후속 재문의가 줄 수 있다. 미래 회신·복구 시각·병원 내부 작업 종료 예정은 정책 입력에 넣지 않는다. 추가 자원 변화 보고는 0건이다.

## 진행 중인 문의를 보호한 이유

첫 시제품 V1은 늦은 H02 제안을 3.25분에 받아 첫 수용 대기 시계를 당겼다. 이때 H04 원 문의 한 건이 진행 중이었다. H03 문의는 3.5분에 추가되고 3.75분에 회신했으며, 더 가까운 H04는 5.5분에 회신했다. V1은 5.25분에 H03으로 확정해 처치가 9.25분이 됐다.

V2는 현재 H04 문의를 확인해 선택적 늦은 제안을 거부한다. 원래 회신 절차를 유지해 H04로 5.5분에 확정하고 7.5분에 처치한다. 이는 직전 보충안의 7.5분과 같고, V1의 추가 도착 지연을 없앤다. 첫 시제품과 결과는 모두 보존했다.

다만 이동 4분인 H03 대신 이동 2분인 H04를 기다리므로, **V1 대비 처치는 1.75분 빠르지만 순수 대기는 15초 늘어난다.** 기존 보호 V4 대비 순수 대기 증가는 2.25분이며, 이는 직전 보충 문의안부터 있던 차이다. 도착 개선을 대기 감소로 표현하지 않는다.

## 동일 과거 입력 회귀

아래 결과는 H1과 C1 각각 동일하다. 같은 환자를 두 알고리즘에 적용한 결과를 합쳐 인원수를 두 배로 세지 않는다.

| 과거 입력 | 직전 보충안 P01 | V2 P01 | V2 P02 | 전체 대기 변화 |
|---|---:|---:|---:|---:|
| 요청한 기한 지연 6건, 34101~34106 | 각 9.25분 | 각 8.25분 | 각 3.5분 | 6건 합 −6환자·분 |
| 기존 개선 6건, 32101~32106 | 각 5.5분 | 각 5.5분 | 각 3.5분 | 0 |
| 진행 문의 경계, 구조 시드 7 | 7.5분 | 7.5분 | 3.5분 | 0 |

기존 32101~32106 사례에서 희소 보호가 없던 결과에 대한 P01의 남은 2.25분 차이는 이전 문서의 물리적 절충이다. 이번 늦은 회신 수정이 그것까지 없앤다는 주장은 하지 않는다.

## 새 입력에서의 비교

V1의 72개 환경은 완전 보존하고 진행 문의 경계 1개를 추가했다. DEV 37101~37103, VAL 38101~38106은 사용 이력이 없는 시드로 예약했으며 개발 후 소스·설정·선택을 잠갔다. 검증 결과를 보고 정책을 재선택하거나 소스를 조정하지 않았다.

10분기는 기존 보호 V4·직전 보충안·V1·V2를 H1/C1 각각에 적용한 8개와 고정3 H1/C1 참고 2개다. 환경별 실행 순서를 회전했다.

| 직전 보충안 → V2 | 개발 | 별도 검증 |
|---|---:|---:|
| 환경 | 219 | 438 |
| 전체 실행 | 2,190 | 4,380 |
| 분기당 환자 | 459 | 918 |
| 처치 단축 / 동일 / 악화 | 3 / 456 / 0 | 6 / 912 / 0 |
| 최종 도착 악화 / 처치 상실 | 0 / 0 | 0 / 0 |
| 전체 대기 합 변화(환자·분) | -3 | -6 |
| 대기가 증가한 환경 | 0 | 0 |
| 문의 수 변화 | -3 | -6 |

검증 전체 집계는 아래와 같다. H1/C1은 이 모집단에서 환자 결과가 같았으며, 일반적인 성능 동등성을 뜻하지 않는다.

| 방식 | 환자 | 미처치 | 전체 대기 합(환자·분) | 요청→처치 제한 합(분) | 문의 |
|---|---:|---:|---:|---:|---:|
| 기존 보호 V4 | 918 | 60 | 8915.25 | 12524.75 | 2553 |
| 직전 보충 문의안 | 918 | 60 | 8901.75 | 12481.25 | 2565 |
| 보호 없는 늦은 회신 V1 | 918 | 60 | 8894.25 | 12485.75 | 2559 |
| 진행 문의 보호 V2 | 918 | 60 | 8895.75 | 12475.25 | 2559 |

V1→V2에서는 개발 3명·검증 6명의 도착과 처치가 빨라졌지만, 위 진행 문의 환경의 대기 합은 개발 +0.75·검증 +1.5환자·분이다. 기존 보호 V4→V2에서는 검증 30명 단축, 6명 악화, 882명 동일이며 대기 증가 환경이 7개다. 이 차이는 직전 보충안 대비 새 악화와 구분한다.

기존에 추가한 `deadline_later_single_candidate`에서는 P03의 희소 기회를 보존하며 P01이 늦어지는 절충도 남았다. 새 검증의 P01 최대 차이는 기존 보호 V4 대비 17분이고, 해당 환경 중 대기 합 증가가 1개다. 이 환자별 차이를 평균 대기 감소로 숨기지 않는다.

고정3 참고 대비 V2에는 처치 상실 18명과 환자 처치 악화 248명이 있다. 따라서 V2 또는 V4가 고정3보다 우수하다는 결론도 내리지 않는다.

## 채택 판단과 해석 범위

직전 보충안과 V1 각각에 대해 개인 처치·최종 도착 악화 및 처치 상실 0, 환경별 전체 대기·요청→처치 제한 합 비증가, 문의 1.10배 이내, 전체 대기 엄격 감소를 요구했다. 기존 보호 V4에는 개인별 절충을 공개하면서 처치 상실과 환경별 전체 대기·요청→처치 제한 합 증가를 금지했다.

**직전 보충안 비교는 개발과 검증 모두 통과했다. V1 및 기존 보호 V4까지 포함한 전체 게이트는 실패했다.** 개발 잠금에는 두 배정 알고리즘 모두 기존 보호 V4 유지로 기록했고, 검증은 이 선택을 바꾸지 않았다. 6건 수정 완료와 전체 후보 채택 여부는 구분한다.

전체 대기는 이동을 제외한 탐색·병원 대기·전원 준비 합이다. 요청→처치는 미처치를 동일 관찰 종료로 제한한다. 병원 내 대기 합은 이번 모형에서 0이며 실제 응급실 대기 감소를 증명하지 않는다. 우선순위는 공급된 합성 값이고 자동 KTAS 판정이 아니다.

조건 지문은 모형의 필드만 확인하며 실제 임상 전체 상태 버전을 검증한 것이 아니다. 15초 회신 창은 이번 실험의 고정 규칙이며 운영 수신 기한을 정한 결과가 아니다. 병원 심사 종료와 회신 수신은 같은 환경 시각으로 모델링했고 별도 네트워크 지연은 추가하지 않았다. 같은 시각에 회신이 도착했지만 아직 처리하지 않은 원 문의도 보수적으로 pending으로 본다.

서버의 순수 문의 선택 계산을 공통 시뮬레이션에 연결한 실험이다. 운영 HTTP 전체 흐름, 전역 300초 기한, 실제 임상 결과나 미래 병상 예측은 검증하지 않는다. 초기 역량을 비교하는 기존 감사기의 도착 후 요구 역량 추가 한계도 유지한다. 합성 환경의 통과는 보편적 무악화·최적성 보장이 아니다.

## 검증 근거

V2 신규 94개를 포함한 총 **1,580개 테스트**가 통과했다. 기존 선택적 HTTP 바인딩 시험 6개 제외 목록은 그대로다. 저장된 개발 2,190회·검증 4,380회·과거 130회, 합계 **6,700회**를 엔진·솔버 import 없이 별도 프로세스에서 다시 감사했다. 원 문의·병원 FIFO·현재 정보·우선순위·기한·만료·실제 이동과 대기를 재구성하고, 환자별 차이·전체 집계·개발 선택을 독립 재계산했다.

압축·복원 원문·원 입력 SHA-256과 잠긴 114개 소스를 확인했다. 이전 2,400개 파일도 모두 동일했다. 첫 V1의 개발·검증 및 추가 반례도 덮어쓰지 않고 남겼다.
