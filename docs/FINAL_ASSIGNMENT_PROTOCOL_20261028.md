# 회신순·거리순·H1 최종 비교 사전 설계

2026-10-28. 성과를 확인하기 전에 비교 방식과 표본 수·지표·판정을 고정한다. 기존 소스와 실험 결과, 운영 서버·DB·팀원 화면은 변경하지 않는다.

## 비교 대상

- R0: 현재 유효 수용 응답 중 먼저 회신한 병원 우선.
- R1: 현재 유효 수용 응답 중 예상 이동시간이 짧은 병원 우선.
- H1: 현재 같은 분에 준비된 환자의 유효 응답과 잔여 자원으로 공동 배정. 미배정 우선순위 합을 먼저, 동률이면 우선순위 가중 이동시간 합을 줄인다.

모두 고정3 문의·첫 수용 이후 최대 2분 추가 대기·변경 알림을 동일하게 적용한다. 따라서 R0도 이 공통 대기 절차 안의 회신순 선택이다. 즉시 첫 응답 확정과 대기시간까지 바꾸는 묶음 비교가 아니다. 환자·기관·초기 자원·잠재 회신·외부 사건·합성 이동 조건이 같다. 배정 결과로 이후 점유와 실제 수용 응답이 달라지는 것은 결과의 일부다.

H1의 알고리즘은 기존 것을 사용하되 최대 2,048회 후보 평가를 주된 탐색 예산으로 사용한다. 10초 안전 상한에 걸린 사례는 유효한 성능 결과로 인정하지 않고 기술 실패로 남긴다. 과거 50ms 선택 버전과 구분한다. 계산시간은 따로 측정하고 분 단위 모의 도착시간에 가산하지 않는다.

## 입력과 표본

주 평가 분포는 결과를 보고 유리한 입력을 고르지 않는 새 생성기다. 실제 발생 빈도 추정은 아니다.

| 층 | 환자 수와 도착 | 개발 환경 | 검증 환경 |
|---|---|---:|---:|
| 단일 발생 | 1명 | 30 | 100 |
| 순차 발생 | 3~8명, 2~8분 간격 | 30 | 100 |
| 다수 발생 | 12~20명, 동시 또는 2~4차 유입 | 30 | 100 |

주 평가의 병원은 5~10곳, 병원별 병상 1~6개·전문팀 0~3개, 역량과 초기 점유·해제시각을 무작위로 생성한다. 회신은 환자·병원·시도별 미응답 20%와 지연 1~5분을 사전 고정한다. 수용은 기존 엔진의 역량·현재 잔여 자원 검사로 결정하며 문의당 수용률 40%를 가정하지 않는다. 현재 자원 관측은 완전하다. 주 평가의 병원 검토 대기열은 사용하지 않는다. 미래 정보는 환경에만 있고 배정 규칙에는 전달하지 않는다.

기존 9종 희소 후보·장거리 우회·자원 중단·여유/불가능 대조군은 개발 2seed씩 18환경, 검증 5seed씩 45환경의 별도 스트레스 시험으로 보고한다. 주 평가와 합쳐 대표 평균을 만들지 않는다.

seed는 개발·검증·단위검사 namespace를 나누고 SHA256 전체 값에 `2**256`을 더해 생성한다. 입력과 소스·설정·런타임을 실행 전에 기록한다. 개발 결과는 기술 계약 검사에만 쓰며 H1·분포·판정 기준을 조정하지 않는다. 검증은 개발의 수치/원문 감사가 통과하고 같은 소스 지문이 유지될 때 한 번 실행한다. 효과가 없거나 불리한 결과도 그대로 보고한다.

## 지표와 판정

주 지표는 **각 층 안에서 환경을 동등하게 가중한 미배정 우선순위 비율**이다. 실험 가중치 4·2·1은 임상 기준이 아니다. 전체 환자 수·미배정/미도착 수와 우선순위별 분모를 별도로 제시한다.

보조 지표는 전체 환자의 선정·도착 제한 경과시간, 도착 p95, 실제 도착한 환자의 평균·p95와 분모, 양쪽 모두 도착한 환자의 지연/단축·최대 지연, 한쪽만 성공한 환자 식별자, 문의 건수, 계산시간이다. 도착하지 않은 환자를 조용히 제외하지 않고 관측 종료 경과시간을 제한 평균에 포함한다. 문의 건수를 실제 병원 업무시간으로 해석하지 않는다.

같은 환경의 H1−R0, H1−R1 차이를 비교한다. 환자를 독립 표본으로 세지 않고 환경 단위로 짝지어 5,000회 부트스트랩한다. 일반 95% 구간과, 주 지표 6개 비교(3층×2기준)에 대해 Bonferroni 보정 구간을 함께 보고한다. 보정 구간 상한이 0 미만일 때 해당 층의 우선순위 수용 기회 개선 근거로 표시한다. 도착 지연의 교환이나 불확실성이 있으면 별도로 표시한다. 모든 환자 비악화나 전체 과정 최적성을 주장하지 않는다. 스트레스 시험은 기술·서술 통계로 분리한다.

원문은 세 분기를 모두 생성한 뒤 배타적으로 저장하고 독립 감사한다. 실패 원문을 삭제하거나 같은 사례를 선택적으로 재실행하지 않는다. 기술 검증 통과와 성능 개선 여부를 구분한다.

구체적인 범위·분포·검사 규칙은 `config/final_assignment_protocol_20261028.json`과 새 실험 manifest에 고정한다.
