# 후속 문의 대기열의 시간 진행 보정

상태: 별도 후보 `eat_cohort_advance_l15_f`의 훈련 360환경·1,242명 검증을 마쳤다. 직전 후보의 성공 환자를 모두 유지하며 추가 자료의 대기를 51초 줄였지만, 전체 목표에 미달하고 개인 지연이 생겨 채택하지 않는다. 새 개발·별도 검증은 실행하지 않는다. 이전 후보의 소스·증거는 보존했다.

기존 목표는 CS 대비 성공 순증 3명과 D의 대기 113,374초 대비 최소 78초 단축이다. 실패 환자의 선정 대기는 300초, 도착 비용은 1,800초로 계산한다. 도착과 선정 대기는 구분한다. 기존 성공 환자의 개별 교환과 개인 최대 지연은 별도로 보고하며, 개별 성공의 전부 보존은 추가 하드 조건으로 두지 않는다. 두 자료를 합쳐 목표를 완화하지 않는다.

## 바꾸는 계산 한 가지

직전 Contention의 가상 미래 문의는 앞선 작업량을 계속 누적했다. 15초와 195초에 나눠 문의해도 그 사이에 처리가 끝날 가능성을 반영하지 않았다. 이번 후보는 동일한 가상 문의 계획에 시간 진행을 적용한다.

문의안은 원래 Followplan의 최대 세 가지로 고정한다. 문의할 병원·시점·환자 목록, 초기 회신 분포, 잔여 환자의 점수, 문의 비용·우선순위·동률 처리 원칙은 그대로다. 가상 후속 문의만 송신 오프셋·환자 순서·후보 순서로 정렬한다.

1. 각 가상 후속 문의의 부모 예상 대기 `q0`와 송신 오프셋 `s`를 가져온다. 고정 기준 분포 F0의 대기는 `max(0, q0 − s)`로 한 번 계산한다.
2. 병원별 직전 가상 작업 완료 시점 `c`를 추적한다. 이번 문의의 보정 대기는 `q1 = max(0, q0 − s, c − s)`다. 같은 작업을 기본 대기와 이전 완료 시점에 두 번 더하지 않는다.
3. 예상 시작 시점 `min(s + q1, 환자 H)`까지 다른 병원에서 수용되지 않았을 확률 S를 고정 초기 분포와 고정 F0로 계산한다. 자기 병원은 제외한다.
4. 작업량 `w = 평균 검토시간 / 가정 작업자 수 × S`를 구하고, 병원 완료 시점을 `c = s + q1 + w`로 갱신한다. 보정된 F1은 작업량 계산에 되먹이지 않는다.
5. 초기 분포는 그대로 두고, 후속 문의의 F1·미래 문의 비용만 새 대기로 다시 계산한다. S를 수용 확률에 다시 곱하지 않는다.

이것은 평균 작업량의 결정적 시간 진행 근사다. 확률적 잔여 작업량의 정확한 기댓값이 아니다. 평균에서 경과시간을 빼는 계산은 잔여 작업을 과소 평가할 수 있다. 작업자 수로 나눈 단일 예상 대기열도 실제 다중 작업자 FIFO 분포와 같다고 주장하지 않는다. 결과와 별개로 이 가정을 명시한다.

모형의 예상 작업 완료는 실제 관측 회신이나 실제 자리 해제가 아니다. 실제 동시 문의 4건·총 문의 10곳·A/H·종료 장벽·원자적 공동 적용·FIFO·단독 및 후기 H 경로는 그대로다. 가상 미래 문의를 실제 예약하지 않으며 현재 두 환자의 행동만 적용한다. 미래 사건·아직 등록되지 않은 환자·결과·시나리오 ID를 정책에 넣지 않는다.

## 사전 고정과 검증

부모 Contention의 봉인 `ec2c7181f5e7c101d3e43a149e195635a6aaa943420e537ccf155abebc542244`, 소스 490개·원문 2,760개와 모든 참조를 보존한다. 새 소스 16개를 더한 506개를 검사·고정한다. 기존 문서 목록의 역사적 해시 변경은 봉인된 이력을 그대로 승계하고 새 재결속은 하지 않는다.

- 훈련 360환경: 새 후보만 한 번 실행한다. 비교군 16개·5,760분기는 봉인된 기록을 재사용한다. 모든 원문 저장 후 두 훈련 구간의 조건을 따로 판정한다.
- 새 개발 120환경: 훈련 조건을 모두 통과할 때만 17개 정책을 실행한다. CS·Hedge 각각의 실패 비증가와 선정 대기 엄격 감소를 모두 요구한다.
- 별도 검증 368환경: 새 개발도 통과할 때만 실행한다. 같은 점 조건에 더해 CS·Hedge 각각의 실패 차이 95% 상한이 0 이하, 대기 차이 95% 상한이 0 미만이어야 한다. 시나리오 단위 짝 부트스트랩 10,000회다. 지표별 주변 95% 구간으로 네 조건의 공동 95% 보장은 아니다.

새 입력은 소스 고정 후 생성한다. 과거에 생성만 하고 실행하지 않은 입력의 난수도 재사용하지 않는다. 입력 명세는 848개이며 최대 새 실행은 8,656분기다. 결과 제외·성능 재실행·사후 설정 변경은 하지 않는다. 실패 뒤 후속 단계는 차단한다. 운영 서버와 기본 `fixed_3`는 바꾸지 않는다.

초기 분포·고정 미래 계획·시간 진행·S와 F0·비용·선택·실제 전 환자 FIFO를 독립 감사한다. 모든 원문 저장 후 네 프로세스에서 의미 감사를 하고, 원문·전체 소스·원문 인덱스 해시에 결속한 사례별 증명을 남긴다. 유효한 증명은 재실행하지 않는다. 표준 라이브러리 회계기는 정책·시뮬레이터를 호출하지 않고 결과와 성공 교환·도착·조건을 별도로 재계산한다.

전체 검사는 현재 파일로 수행한다. 과거 `docs/README.md` 참조 검사 10개가 같은 오류로 실패하면 실패·추적 기록을 그대로 남긴다. 정확한 검사 ID·원래/현재 해시·문서 오류만 일치할 때 새 후보 고정 자격을 허용하며, 전체 검사 통과로 표시하지 않는다. 읽기·해시·단언을 바꾸거나 검사를 건너뛰지 않는다.

합성 성능 자료의 우선순위는 미확인·기본값 4다. 임상 응급도별 효과나 실제 현장의 성능 우월성을 주장하지 않는다. 전체 벽시계 시간은 감사·수집을 포함하므로 정책 계산시간이 아니다.

## 결과

사전 검사 66개 모듈·1,084건 중 1,074건이 성공했다. 나머지 10건은 부모에서 기록한 `docs/README.md`의 역사적 참조 해시 오류이며 실패·추적 기록을 보존했다. 실행 오류와 건너뛴 검사는 없다. 새 검사 119건은 모두 성공했다. 읽기·해시·단언을 대체하지 않았으며 전체 검사 통과로 표시하지 않는다.

고정 예제에서는 비교군 16개의 전체 실행 원문이 부모와 같고 새 후보 2개의 독립 의미 감사가 성공했다. 동시 발생 예제는 실제 공동 처리 4개와 새 미래 작업량 32개를 검사했다. 이는 연결·계산의 사전 검사이며 새 성능 표본이 아니다. 별도 표준 라이브러리 회계기의 수치 계산과 13개 증명 변조 거부 검사도 통과했다.

### 개인 지연과 도착 구분

전체 대기 51초 감소가 모든 환자의 개선을 뜻하지 않는다. 추가 혼합 자료의 네 환경에서 대기 변화가 각각 −97초·+33초·+39초·−26초였고, 한 환경은 문의 기록만 바뀌었다. 스트레스 자료의 초과 대기는 그대로 남았다.

직전 후보 대비 한 환자의 선정 대기가 84초에서 254초로 170초 늘고, 목적지가 H05에서 H07로 바뀌어 도착이 1,004초에서 1,281초로 **277초 늦어졌다**. 다른 환자는 선정 대기가 39초에서 197초로 158초, 도착은 772초에서 845초로 73초 늘었다. 원문과 식별자는 별도 집계에 기록했다. 이 결과로 개인 지연 문제가 해결됐다고 주장하지 않는다.

실패 도착 비용 1,800초를 포함한 J는 기존 840.874초, 추가 822.629초다. CS보다 기존은 3.989초 낮고 추가는 3.224초 높다. 직전 후보 대비 추가 J는 약 0.070초 낮지만 개인 최대 도착 지연 277초가 함께 발생했다. CS와 두 정책에서 모두 성공한 환자의 최대 도착 지연은 기존 135초·추가 607초다. 도착과 선정 대기, 평균과 개인 손해를 구분한다.

전체 실행·의미 감사·수집 벽시계 시간은 약 518.24초다. 정책 계산시간이나 현장 처리 지연으로 해석하지 않는다. 결과 제외·성능 재실행·사후 설정 변경은 없다.

### 판정과 다음 연구

기존 성공 목표만 충족했고, 기존 대기·추가 성공·추가 대기 목표는 실패했다. 이번 후보를 채택하지 않으며 운영 서버와 기본 `fixed_3`는 유지한다. 새 개발·별도 검증으로 넘어가지 않는다. 소스·검사·원문·사례별 의미 증명·독립 집계·문서를 해시에 결속해 보존한다.

다음 연구 방향으로 공개 로그정규 서비스 모형의 확률적 잔여 작업 분포를 검토했다. 기존 `residual_policy.head_expected_remaining`도 현재 증거에 조건화한 잔여 기댓값을 사용한다. 현재 무회신 증거의 추정 경과가 a이고 앞으로 u초를 예측한다면 양의 잔여 함수 J에 대해 `J(a+u)/(1−rF(a))`처럼 분모를 현재 증거에 고정해야 한다. 아직 관측하지 않은 미래 무회신에 재조건화하면 안 된다. 확정 처리 시작시각·실제 작업자 상태는 공개 입력에 없으므로, 아직 송신하지 않은 작업이나 시작하지 않은 후속 작업의 서비스 시간을 미리 차감하지 않는 구분도 필요하다.

완료시각 분포를 제한된 격자에서 전파하는 방법과 그 계산량·의존성·꼬리 절단 한계는 `diagnosis/math-residual-future-research.json`에 남겼다. 이 설계는 구현·성능 검증하지 않았고 이번 결과의 원인이나 개선 효과로 주장하지 않는다.
