## 모델 계약과 해석 범위

- `scenario.inquiry_queue`: `{enabled: true, workers: 정수, background_jobs: [{t, hospital, service_minutes}]}`.
- 기존 `response_environment`의 `delay`를 큐 모델이 켜졌을 때 합성 검토 소요시간으로 사용한다. 요청이 많으면 앞선 요청 뒤에서 기다린다.
- 무응답 요청도 검토 작업은 소모하지만 회신만 누락된다는 실험 가정이다. 현실의 원인 비중을 추정한 모델은 아니다.
- 다른 병원 확정 이후 남아 있는 문의의 작업은 자동 취소하지 않는 보수적 가정이다. 실제 취소 효과는 별도 모델이 필요하다.
- 후보 분산 정책은 현재까지 보낸 문의 수만 사용한다. 미래 응답, 실제 미래 작업 종료, 외생 사건 일정은 정책 입력으로 제공하지 않는다.
- 기존 알고리즘 결과와 비교하려고 개선이 보장되는 사례만 고르면 안 된다. 변화 없음·일시 변화·지속 변화·총자원 부족 및 악화 사례도 보존한다.
- 개발 seed와 검증 seed를 분리한다. 정책 가중치를 고르는 데 검증 결과를 사용하지 않는다.
- 병원 위치는 공개 DB, 임상 자원·환자·처리시간·중증도 가중치는 합성값이다. 신규 반복 실험의 기본 도로 모드는 합성 추정이며 기존 OSRM 지도 사례와 구분한다.
- R3는 같은 분에 준비된 소규모 묶음의 열거다. CP-SAT 연결/전체 이송 과정의 전역 최적화는 아직 하지 않았다.
- 알림 켬/끔 비교는 기능의 기여를 분리하는 실험이다. 현행 전국 시스템에 알림이 없다는 주장이 아니다.
- 실험에서는 수용 확인 후 목적지 조정 결정이 즉시 이루어진다고 단순화했다. 실제 사람의 판단·연락 시간은 포함하지 않았다.
- `resource_invalid_transit_minutes`는 모델이 영향 대상으로 식별한 환자가 자원 불충족 상태의 목적지로 이송 중이었던 환자·분이다. 임상 위해·생존 지표가 아니다.
