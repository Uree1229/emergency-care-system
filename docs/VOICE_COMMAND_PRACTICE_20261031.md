# 음성 명령 연습과 데이터 수집

`/paramedic/command-practice.html`은 실제 환자 기록에 적용하지 않고 명령 판정과 인식문 자료를 모으는 전용 화면이다. 음성 기록 화면의 설정에서도 연결한다. 앱 API·환자 등록·환자 전환·병원 문의를 호출하지 않으며 명령은 판별 결과만 보여준다. 마이크 권한은 사용자가 말하기 시작을 눌렀을 때 요청한다.

## 빠른 수집 순서

1. 발화 유형·명령 종류·문장 검색으로 대본을 고른다. 종료·추천·새 환자·이전 환자·인계 요약, 부정·인용·처치 표현·다중 명령·늦은 부정·긴 문장 등 11개 유형의 합성 대본 60개를 제공한다.
2. 익명 화자 ID·장비·소음·말하기 방식·마스크·거리·짝 비교 ID를 정한다. 같은 대본·화자·장비에서 조건 하나씩 바꾸고 같은 짝 비교 ID를 쓰면 비교하기 쉽다. 측정하지 않은 거리는 비워 둔다.
3. 말하기 시작 → 말하기 마치기로 한 시도를 수집한다. 기본은 버튼 종료이며 명령 자동 종료를 선택할 수 있다. 최대 180초다. 정상·무인식·오류·명시 중단을 모두 자동 보관한다.
4. 대본대로 말한 것과 의도한 명령을 확인한 뒤 `정답 확인 후 다음`으로 이어간다. 같은 문장 다시·순서 섞기·오류/불일치 문장만 보기로 반복할 수 있다. 원문과 다르게 말했으면 정답 확인을 하지 않고 메모를 남긴다.
5. 정기적으로 전체 JSON을 내려받는다. 다른 기기·브라우저에서 모은 JSON을 합칠 수 있다. CSV는 표 검토, TXT는 현재 원문 별도 보관용이다.

직접 만든 문장·자유 발화는 별도로 선택한다. 정답 문장을 비우고 수집할 수 있으며 이 경우 자동으로 정답을 만들어 채점하지 않는다. 수동 모의 입력에는 의도적으로 숫자·띄어쓰기·부정 표현을 바꾼 결과를 넣을 수 있다. 이 경로는 마이크 시도와 따로 보관·집계한다.

## 원문·정답·판정의 분리

시도에는 확정 인식문 조각·합친 원문·최종 명령 판정·명령 앞 본문·뒤 문장·최초 명령 후보·종료 사유·오류 코드·시각·환경을 남긴다. 여기서 원문은 브라우저가 전달한 확정 인식문이며 실제 음성 원본이나 전체 음성 서비스 이벤트가 아니다. 임시 인식은 화면에만 표시한다. 브라우저 음성 서비스는 네트워크를 사용할 수 있으며 이 화면은 원본 오디오를 저장하지 않는다. 별도 사전 힌트는 요청하지 않는다.

자동 종료에서는 먼저 나온 명령 후보를 보존하고 stop 완료까지 늦은 확정 문장을 받는다. 예를 들어 첫 조각이 `종료`, 뒤 조각이 `하지 마`이면 최초 후보와 최종 `명령 없음`을 구분한다. 연습 화면의 최종 판정은 전체 확정문 기준이며 기존 업무 화면의 실시간 실행 결과를 재현했다고 주장하지 않는다. 실제 업무 동작은 실행하지 않는다.

대본의 고정 기대값과 사용자가 확인한 정답은 판정 결과로부터 생성하지 않는다. 정답 검토는 기대 명령·확인 여부·메모만 바꾸며 원문·출처·당시 판정·원래 대본 snapshot은 보존한다. `명령 없음`과 `정답 미지정`을 구분한다. 정답 확인된 시도의 명령 일치 집계에는 오류·무인식·중단도 실패로 포함하고, 전체 시도의 실패 수도 항상 표시한다.

`human_voice`는 브라우저 마이크 경로, `manual_simulation`은 수동 모의 경로다. 가져온 파일은 원래 출처를 유지하고 imported 표시를 추가한다. 파일의 출처 표시는 수집자의 신고이며 실제 사람의 음성임을 인증하는 수단은 아니다. 합성 대본 또는 가짜 인식기로 얻은 시험 수치를 실제 STT 성능으로 바꾸지 않는다.

## 보관·병합·새 묶음

기존 환자 임시본과 다른 `paramedic.voice.command-practice.v1` 키에 보관한다. 완료 시도와 pagehide까지 알려진 확정 문장을 중단 상태로 보관한다. 브라우저 강제 종료·충돌·저장소 삭제까지 보장하지 않는다. 마이크는 복원만으로 다시 켜지지 않는다.

저장 결과를 다시 읽어 확인하며 실패하면 새 결과를 현재 메모리에 유지하고 새 시도를 막는다. JSON/TXT를 먼저 보관하고 저장을 재시도할 수 있다. 다른 탭의 변경과 손상된 저장본을 자동 덮어쓰지 않는다. localStorage의 비교 후 쓰기는 완전 동시 편집을 보장하는 원자적 CAS가 아니다.

한 묶음은 최대 500건·UTF-8 JSON 4MiB, 원문 16,000자·확정 조각 256개다. 기기의 저장 여유 공간에 따라 이보다 먼저 저장이 거부될 수 있다. 현재 목록은 최근 80건을 표시하며 내보내기에는 전체가 들어간다. 상한에 맞추려고 오래된 시도나 원문을 자동 삭제·자르지 않는다.

새 묶음은 현재 전체 JSON 내보내기를 요청한 뒤 실제 파일을 보관했다고 사용자가 확인해야 시작할 수 있다. 내보낸 뒤 정답·시도가 바뀌면 다시 내보내야 한다. 파일 확인 후 새 묶음을 누르면 브라우저 목록을 비우며, 이전 자료는 JSON으로 다시 합칠 수 있다. 내보내기 요청만으로 파일 저장 성공을 단정하지 않는다.

JSON 병합은 전체 형식·크기·ID를 검증한다. 동일 시도는 중복 추가하지 않고 같은 ID의 다른 내용은 충돌로 거절한다. 파손·상충·초과 파일로 기존 자료를 일부만 바꾸지 않는다. CSV에는 수식 시작 문자를 이스케이프하고 JSON에는 원문을 그대로 보존한다.

이 자료는 `schema:1`, `purpose:synthetic_command_practice`, `actualAudioSaved:false`, `attempts:[]`인 명령 연습 전용 형식이다. 기존 `evaluate.html`의 `speech_eval --recordings` 형식과는 다르다. 데이터 검토는 이 화면의 JSON 합치기와 source별 집계 또는 core의 `scorePracticeAttempts`를 사용한다.

## 실행과 검증

공통 앱 서버에서는 `http://127.0.0.1:8000/paramedic/command-practice.html`로 연다. 이 페이지 자체는 정적 파일만으로 동작하며 브라우저 인식 외 별도 API가 필요 없다. Windows 정적 서버를 직접 쓸 경우 `.js`·`.mjs`가 JavaScript MIME으로 전달돼야 한다. 현재 전용 미리보기는 `http://localhost:18044/command-practice.html`이며 앱 API와 DB는 실행하지 않는다. 전용 미리보기에서 기존 음성 기록 업무를 이어가려면 공통 앱 서버를 사용한다.

core·페이지 회귀와 실제 모듈/VoiceCapture를 가짜 브라우저 인식기에 연결한 통합 시험을 수행한다. 원문과 정답 분리·늦은 final·idle 뒤 오류·무인식·중단·pagehide·저장 실패·오래된 탭·JSON 병합·실제 Blob 내보내기 readback·CSV 수식 보호·새 묶음 확인을 검사한다. 가짜 인식기는 실제 STT 증거가 아니며 마이크·운영 DB·OS 클립보드는 사용하지 않는다. 실제 브라우저에서는 수동 모의 입력과 표시·보관을 별도로 확인한다.

최종 배포 후보의 전체 Node 회귀 **1,546/1,546**, 전용 통합 **17개 시나리오·95개 확인**을 통과했다. core 독립 시험은 119개, 실제 VoiceCapture와 가짜 인식기를 연결한 페이지 회귀는 12개다. 정적 파일 8개의 바이트·JavaScript MIME을 확인했고 페이지/호스트의 앱 API 요청은 0건이었다. 내려받기 Blob 12개를 다시 읽어 JSON·CSV·TXT 원문과 주석 보존을 확인했으며 별도 디스크 readback 24개와 독립 읽기 감사도 통과했다.

실제 브라우저에서는 수동 모의 1건의 보관·마이크 집계와 분리·명령 앞/뒤 문장·새로고침 복원을 확인했다. 실제 마이크 시도는 이 검증에서 실행하지 않았다. 브라우저에서 다운로드를 요청하고 사용자가 보관을 확인하는 절차와 실제 OS 파일 저장 성공은 구분한다.

반복 회귀 실행: `node --test test_paramedic_command_practice_data.mjs test_paramedic_command_practice_page.mjs`.
