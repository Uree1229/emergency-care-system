# EAT 문의 대기 추정 실험: 선행 업무의 잔여 시간 반영

개발 기준을 통과하지 못해 별도 검증 성능 실행을 진행하지 않았다. 이 후보는 채택하지 않는다. 기존 서비스 기본값은 `fixed_3`으로 유지했다.

## 한 가지 변경

기존 EAT의 신규 문의 대기 추정에서 선행 문의 수만큼 평균 업무 시간을 통째로 더하던 부분을 개선 후보로 삼았다. `eat_residual_l15_f`는 현재 관측된 선행 문의의 제출 시각과 회신 이력으로 선두 업무가 이미 진행됐을 시간을 추정해, 조건부 잔여 업무와 뒤에 남은 업무를 더한다. 실제 업무 시작 시각·실제 처리 인원·숨은 회신 일정은 정책 입력에 추가하지 않는다.

이 변경은 **새 문의의 대기 추정**에만 적용한다. 기존 자기 대기 문의의 수용 분포, 이동시간순 최대 여섯 병원 선별, EAT 계획 계산·15초 문의 비용 계수·동시 문의 4곳 상한·안전 규칙·최초 유효 수용 회신 즉시 확정은 유지했다. 앞서 기각한 기대 비용 후보 선별(shortlist)은 섞지 않았다. 기존 EAT·실행기·서비스 원본은 그대로 두고 별도 실험 소스만 추가했다.

## 고정한 비교와 지표

- 같은 새 합성 환경에서 `fixed_3 즉시`, `기존 EAT 즉시`, `잔여 업무 후보 즉시`, `V3 즉시`, `기존 EAT hold120` 다섯 분기를 실행했다. 캐시로 비교 분기를 대체하지 않았다.
- 개발은 혼합 96개 + 스트레스 8유형 × 3 seed = **120개 환경·600개 분기**다. 별도 검증 성능 실행은 0회다. 검증을 실행했다면 혼합 320개 + 스트레스 8유형 × 6 seed로 구성된다.
- **W는 환자 발생부터 병원 선정까지의 대기**이며 실패 환자는 300초를 부여한다. 선정된 환자만 집계하지 않는다. 이동시간이나 도착 후 처치 대기를 포함한 전체 치료 지연 지표가 아니다.
- **J는 성공 시 추정 도착시간, 실패 시 300 + 1,500 = 1,800초인 환자 평균**이다. 실패 비용은 설계값이며 600·3,000초 민감도도 원 보고서에 함께 남겼다.
- 개발 기준은 기존 EAT 대비 W 감소·실패 수와 J 비증가, `fixed_3` 이하 문의 수·병원 검토 업무다. 검증은 같은 조건과 **시나리오 단위 부트스트랩 W 변화 95% 구간 상한 < 0**을 함께 요구한다. 스트레스는 주 판정에서 제외하고 유형별로 보고한다.
- 후보·게이트·271개 소스를 고정한 뒤 개발·검증 입력 488개의 해시를 생성했다. namespace·역할·인덱스를 이용한 SHA256 128비트 seed 425개는 역할 간 분리했고 이전 shortlist namespace·보고된 EAT/확정 규칙 검증 seed와 겹치지 않게 확인했다. 전체 과거 대형 원문을 새로 검색했다는 주장은 하지 않는다.

개발 또는 검증의 해당 사전 기준 통과: **False**. 환자당 W 변화의 시나리오 단위 95% 부트스트랩 구간은 **-1.931~+2.958초**, J 변화 구간은 **-21.516~+0.119초**다. 스트레스 24개 환경은 이 표와 주 판정에서 제외했다.

환자별 대기는 개선 10명·악화 19명·동일 339명이다. 기존 성공 중 실패로 바뀐 환자 0명, 새로 성공한 환자 4명, 대기 합계가 늘어난 혼합 환경 11개다. 최대 개별 대기 악화 195초, 최대 개별 J 악화 303초도 포함했다.

별도 검증 성능 실행 없음. 개발 실패 후 후보나 기준을 바꿔 같은 검증 입력을 재사용하지 않았다.

최대 대기 악화 원문은 `010_193436270004239920733058239088871358543.json.gz`의 P05로, 58초에서 253초로 195초 늘었다. 실패 전환 여부는 기존 False·후보 False이며, 이 결과도 전체 합계에 포함했다. 개별 무악화나 모든 가능한 미래 입력에 대한 보장은 주장하지 않는다.

## 검사·감사·보존

고정 소스 기준 **86개 검사**가 통과했다. 기존 EAT·확정 규칙 검사 27개와 이번 후보 정책·기록 연결·감사·프로토콜 검사를 합친 것이며 과거 전체 프로젝트 검사를 다시 실행한 결과는 아니다.

동결 전 정상 검증 진입 경계를 확인하는 단위 검사에서 모의 입력의 manifest 누락으로 오류 1건이 발생했으며, **시험용 fixture만 수정하고 실패 산출물·수정 기록을 사전 증거에 연결한 뒤 86개 통과를 확인하고 정식 동결했다**; 이 과정에서 정식 성능 실행이나 결과 조정은 없었다.

개발 성능 실행 1회와 검증 성능 실행 0회, 비교 캐시 0개를 확인했다. 저장 원문 **120개 gzip·600개 완전 분기**를 압축·해제 SHA256, 동결 입력 해시, 환자 원문과 보고서 항목, 환자 전체 W/J/실패/문의 합계, 실제 `review_started` 업무 합계로 대조했다. 저장 원문 감사와 최종 집계 검사는 정책·시뮬레이션 성능을 다시 실행하지 않았다. 불리한 원문을 제외하거나 시도를 다시 고르지 않았다.

개발 및 실제 실행한 검증의 보고서·감사·원문 색인·잠금·소스 동결·검사 증거를 최종 봉인했다. 부모의 **260개 소스·48개 참조 경로**와 새 동결 **271개 소스 경로**를 확인했다. 부모 phase1의 원문과 그 이전 전체 증거는 이름·해시가 고정된 부모 봉인 증명을 재사용하며, 이번 단계에서 과거 대형 글로벌 증거 전부를 재해시했다고 주장하지 않는다. 기존 `docs/README.md`, 운영 서비스·UI·실제 DB는 변경하지 않았다.

결과는 합성 병원 문의 실험의 선정 대기 비교다. 실제 임상 예후·병상 확보·도착 후 처치 대기 또는 공동 배정 H1/C1의 성능을 직접 증명하지 않는다. 최적성이나 임의 상황의 무손해를 주장하지 않으며, 후보가 통과해도 운영 채택은 별도 결정이다.
