## 이번에 마무리한 것

1. `confirm`과 `change-destination`이 성공하는 동일 트랜잭션에서 `patients.transport_baseline`에 병원·시각·환자 요구·관련 자원·역량·제한을 저장한다. 감시를 켜기 전에도 기록하며 이 저장만으로 감시나 문의를 시작하지 않는다.
2. 감시를 나중에 켜면 저장된 확정 조건을 사용한다. 감시가 꺼진 상태의 목적지 변경도 새 조건으로 기록한다. 기존 DB에 당시 조건이 없으면 첫 설정 시 관측을 사용하며 과거 변화까지 소급 검출하지 않는다.
3. 이동시간 계산 도중 다른 후보 병원의 자원이 바뀌는 경합 테스트를 추가했다. 환자·위치·현재 병원 검토 버전이 그대로여도 전체 입력 버전 변화로 결과를 폐기하고, 새 계산에서 소진된 병원을 제외한다.
4. 전용 가상 DB의 이전 준비 A/B 두 건을 취소하고 그 시연에서 만든 전문팀 점유 1건만 원복한 뒤 새 사례를 준비했다. 실제 공공 DB나 팀원 데이터를 초기화하지 않았다.

## 유지할 업무 규칙

- 감시는 이송 건별로 명시적으로 켠다. 초기 문의와 확정 후 대체 문의는 별도 작업이다.
- 신규 수용 여유가 0인 것만으로 기존 환자를 조정 대상으로 정하지 않는다. 관련 자원을 요구하는 환자를 찾아 현재 병원의 재확인을 기다린다.
- 병원의 명시적 `adjust` 이후 최신 위치로 대체병원 자동 문의를 진행한다. 유효 응답을 확보해도 목적지 변경은 사람이 한다. 그전에는 기존 목적지·도착 예정 수요·대화 참여를 유지한다.
- `keep`·감시 일시정지·도착·취소는 해당 대체 문의 회차를 정리한다. 이동 중 위치는 개발 설정상 120초 이내 관측값이 필요하다.
- 실제 GPS 수집은 미구현이다. ‘시연 위치 갱신’ 버튼은 저장된 가상 좌표의 관측 시각을 갱신한다.
