# 전체 후보 평가에 환자별 예측 확률 보호 추가

상태: 별도 후보 `eat_cohort_pareto_l15_f`의 훈련 360환경 실행·공식 의미 감사·독립 집계 대조를 완료했다. 기존 성공은 보존했지만 선정 대기를 줄이지 못해 채택하지 않는다. 후보 확장판 Fullmenu의 소스·결과는 별도로 봉인해 보존했다.

## 배경과 목표

Fullmenu의 독립 집계에서는 기존 827명의 선정 대기가 Stoploss보다 1,604초, 추가 415명은 1,230초 감소했다. 성공 수는 각각 692명·363명으로 같았지만 기존 성공 2명을 잃고 다른 2명이 새로 성공했다. 전체 확률 합을 높이는 선택에서 일부 환자의 예측 확률이 낮아질 수 있다는 제한을 확인했다. 예측 확률 변화가 관측 실패를 일으켰다는 인과관계까지 증명한 것은 아니다.

이번 후보는 모든 기존 후보를 계산하는 Fullmenu를 유지하고, 현재 점수를 계산한 모든 환자의 예측 수용 확률을 보호하는 조건을 추가한다. 실제 성공 결과나 과거 성공 환자 목록을 정책에 입력하지 않는다.

검증의 성공 보존 기준은 Fullmenu가 아니라 원래 요청의 부모 Stoploss다. 이미 실패로 바뀐 두 환자를 보존 기준에서 제외하지 않는다.

| 기존 827명 | 692 / 113,429초 | 692 / 111,825초 | Stoploss 성공 손실 0명·대기 엄격 감소·성공 692 이상·대기 113,296초 이하 |

두 구간은 각각 이미 관측한 훈련 자료다. 구간·환자 사이에서 성공 손실이나 대기 증가를 합산으로 감추지 않는다. 실패 선정 대기는 300초, 실패 도착 비용은 1,800초로 계산한다. 선정 대기·도착·개별 성공 교환·개인 최대 지연을 따로 보고한다.

## 추가하는 보호 조건

Fullmenu의 원래 제안·모든 허용 행·점수·공개 투영·활성화 조건은 그대로 보존한다. 각 평가 그룹 안에서 내장된 Stoploss의 실제 선택 행을 기준으로, 행마다 H가 남은 현재 대기 상태의 점수 대상 환자 모두의 최종 예측 수용 확률을 비교한다.

1. 현재 첫 문의 환자와 이미 문의 중인 환자를 모두 포함해 환자 식별자와 점수 목록이 정확히 대응하는지 검사한다. 누락·중복·다른 환자로의 교체는 거부한다.
2. 어느 환자라도 후보 확률이 Stoploss 기준보다 기존 확률 허용 오차 `1e−12`를 넘어 낮으면 그 행을 선택 대상에서 제외한다. 우선순위와 관계없이 모든 점수 대상 환자에게 적용한다.
3. Stoploss 기준 행 자체는 항상 허용돼야 한다. 허용된 행에서만 기존 우선순위별 확률 합·선정 대기 순서로 선택한다. 동률은 원래 Stoploss 선택을 우선한다.
4. 전체 행·환자 비교, 제외 이유, 허용 행 목록과 최종 선택을 증거로 남긴다. 점수를 새로 계산하거나 새 가중치를 도입하지 않는다.

이는 공개 모형의 환자별 예측 확률 보호다. 모형의 확률이 실제로 보정돼 있다는 주장이나 실제 성공 보장은 별도 검증이 필요하다. 기존 성공 환자의 실제 보존 여부는 결과에서 별도로 판정한다.

Fullmenu가 유지한 기존 JOINT 허용 조건·문의 개수·후보 병원·평가 활성화 조건은 그대로다. 실제 문의 10곳·동시 문의 4건·A/H·종료 장벽·원자적 공동 적용·전 환자 FIFO를 유지하고 현재 두 환자의 문의만 적용한다. 미래 사건·성공 결과·미등록 환자·실제 작업자 상태는 정책에 넣지 않는다.

## 검증 절차

Fullmenu의 소스·전체 원문·감사·실패 결과를 봉인했다. 부모 봉인은 `e63a6fb8cd206e755ff3b0eae1706045cf14100da36a6b8cf7051c969638703e`다. 회계기 원본의 지역 변수 충돌은 원본을 보존한 별도 회계기 수정본과 독립 검토 기록까지 결속했다. 부모 소스 538개·참조 2,480개·압축 원문 3,840개를 보존하고 새 소스 16개를 더한 554개를 검사·고정한다. 문서 목록의 역사적 해시 변경은 기존 이력을 승계하고 새 재결속은 하지 않는다.

- 훈련 360환경: 새 후보를 각각 한 번 실행한다. 비교군 19개·6,840분기는 봉인된 기록을 재사용한다. 모든 원문 저장 후 두 훈련 구간의 9개 조건을 각각 확인한다.
- 새 개발 120환경: 훈련이 통과할 때만 20개 정책을 실행한다. Stoploss·CS·Hedge 각각의 실패 비증가와 선정 대기 엄격 감소, Stoploss 성공 환자 손실 0명을 요구한다.
- 별도 검증 368환경: 새 개발도 통과할 때만 실행한다. 동일한 점 조건에 더해 세 비교군 각각 실패 차이 95% 상한 0 이하·대기 차이 95% 상한 0 미만을 요구한다. 시나리오 단위 짝 부트스트랩 10,000회이며 지표별 주변 구간으로 전체 조건의 공동 95% 보장은 아니다.

새 입력은 소스 고정 뒤 생성하며 과거 미실행 입력의 난수도 재사용하지 않는다. 입력 명세 848개, 최대 새 실행은 10,120분기다. 성능 재실행·결과 제외·사후 설정 변경은 하지 않는다. 단계 실패 뒤 후속 단계는 차단한다. 운영 서버와 기본 `fixed_3`는 유지한다.

독립 감사는 부모 Fullmenu 전체 증명, 모든 환자·행의 확률 비교, 제외·허용 목록·기준 행의 허용·동률·실제 출력·전 환자 FIFO를 확인한다. 모든 원문 저장 뒤 네 프로세스에서 의미 감사를 하고 원문·전체 소스·인덱스에 결속한 사례별 증명을 남긴다. 별도 회계기는 정책·시뮬레이터 없이 성공 식별자·대기·도착·조건을 재계산한다.

과거 `docs/README.md` 참조 검사 10개의 동일한 역사적 오류는 실패와 추적을 보존한다. 정확한 검사 ID·오류·원래/현재 해시가 일치할 때 새 고정 자격을 허용하며 전체 검사 통과로 표시하지 않는다. 해시·읽기·단언을 바꾸거나 검사를 건너뛰지 않는다.

성능 자료는 합성 입력이며 우선순위 미확인·기본값 4다. 실제 임상 응급도별 효과나 현장 우월성을 주장하지 않는다. 전체 벽시계 시간은 감사·수집을 포함하므로 정책 계산시간으로 해석하지 않는다.

## 결과

사전 전체 검사는 84개 모듈·1,478건 중 1,468건이 성공했다. 나머지 10건은 부모에서 기록한 `docs/README.md`의 역사적 참조 해시 오류이며 실패·추적 기록을 보존했다. 실행 오류와 건너뛴 검사는 없고, 새 검사 133건은 모두 성공했다. 읽기·해시·단언을 바꾸지 않았으며 전체 검사 통과로 표시하지 않는다.

고정 예제에서는 비교군 19개의 전체 실행 원문이 부모와 같았고 새 후보 2개의 의미 감사가 성공했다. 자연 확장 예제는 225행을 모두 평가한 뒤 224행을 개별 확률 하락으로 제외하고 Stoploss 기준 행을 남겼다. 기준 행의 허용과 실제 보호 분기 활성화를 독립 감사했다. 이는 기능 검사이며 성능 효과를 미리 주장하지 않는다. 표준 라이브러리 회계기도 이름 충돌 검사와 실제 main의 합성 사전 해시 경로 검사를 통과했다.

### 도착과 해석

실패 도착 비용 1,800초를 포함한 J는 기존 840.874초, 추가 821.807초다. Stoploss 대비 기존은 같고 추가는 약 0.822초 낮았다. 추가 자료의 총 도착 비용은 341초 감소했으나 선정 대기 감소 목표를 대신하지 않는다. Stoploss 대비 개인 선정 대기의 최대 증가는 기존 0초·추가 42초였고, 두 정책에서 모두 성공한 환자의 최대 도착 지연은 기존 0초·추가 91초였다.

Fullmenu의 대기 감소 1,604초·1,230초는 기존 성공 손실과 함께 발생했다. 이번 보호판은 기존 성공을 복구했지만 그 대기 감소를 유지하지 못했다. 두 조건을 동시에 달성했다는 결과는 없다. 개별 예측 확률 보호가 일반적으로 실제 성공을 보장하거나 대기를 최적화한다는 주장도 하지 않는다.

최종 판정은 훈련 조건 미달이다. 기존 성공 보존 조건은 두 구간 모두 통과했지만 대기 감소 조건은 통과하지 못했고, 추가 자료의 CS 대비 성공 수 목표도 미달했다. 새 개발·별도 검증으로 넘어가지 않으며 운영 서버와 기본 `fixed_3`는 유지한다. 최종 원문·소스·검사·감사·실패 조건을 함께 보존한다.

별도 저장 결과 감사도 360사례에서 성공했으며 기존 의미 증명을 재사용해 감사·성능 실행을 추가하지 않았다. 실제 `execute('development')`를 호출한 차단 검사에서는 실패한 훈련의 `verify_prior` 조건에서 멈췄다. 작업 목록·실행 풀·시뮬레이터 호출은 모두 0회였고 새 개발·별도 검증 산출물도 생성되지 않았다. 모든 고정 소스 554개의 해시는 전후 동일했다.

증거는 `.codex-build/eat-cohort-pareto-20261024/`에 보존한다. 공식 `repair.json`, 결과 감사 `repair-audit.json`, 의미 증명 인덱스 `repair-semantic-audit.json`, 독립 집계·대조·증명 검토·단계 차단 기록은 `diagnosis/`에 있다. 최종 회계 검증 `verification.json`은 이 문서·고정 소스·실행 원문·각 검사 기록을 해시로 결속한다.
