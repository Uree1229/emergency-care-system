# 음성 V2 — 구급대원 화면(Claude) 작업 기록

2026-10-30 · 담당: Claude · 범위: `paramedic-ui/`, `test_paramedic*` · 짝 문서: [Codex 경계·연결 계약](VOICE_V2_CLAUDE_HANDOFF.md), [무전기 방식 설계](VOICE_PTT_DESIGN.md)

간편 음성 시험 화면(`paramedic-ui/quick-test.html`)에 다음을 붙였다.

- **입력:** 무전기 방식 버튼과 자동 판단(`mode: "auto"`)
- **결과 표시:** 변경 전후 표시
- **확인 질문:** 질문 카드와 읽어주기, 답변 전송
- **연결 상태:** 서버 버전 확인과 문맥 힌트

**시험 상태:**

- Claude가 한 것: 가짜 인식기 시험(단위 테스트, 인앱 브라우저)
- 사용자가 한 것: 18:47 실제 마이크 시험 1회(검증 서버)
- Claude의 재생 시험: 그 인식 결과를 같은 서버에 다시 넣음(새 녹음 아님)

**18:5x 사용자 결정:** 답은 널널하게 받고, 틀린 값은 구급대원이 검토·전송할 때 고친다. 이에 맞춰 앱의 답변 처리를 관대하게 바꿨다(2.1절).

서버 쪽 문제와 제안은 5절에 적었다. 서버 판정 완화(5.5)는 Codex 파일이고 Codex가 지금 수정 중이어서, 서버 파일은 고치지 않았다.

## 2 구현 완료

| 기능 | 동작 |
|---|---|
| 자동 판단 | 기본 모드다. `transcripts`에 `mode: "auto"`를 보낸다. `QuickSession.apply`가 `auto`를 받고, 초안이 없으면 먼저 만든다. `환자 상태만`(dictation)과 `수정·확인 명령`(command)도 그대로 고를 수 있다. 기록에 `자동 판단 → 명령/상태 설명`(`effective_mode`)을 남긴다. |
| 무전기 버튼 | 누르는 동안만 듣고, 손을 떼면 최종 조각을 합쳐 한 번 보낸다. |
| 방금 바뀐 내용 | `session.latest_changes`로 `이전 값 → 현재 값`을 표시한다(아래). |
| 재확인과 미측정 구분 | 값 없는 변화 보고와 미측정 답변을 서로 다르게 표시한다(아래). |
| 확인 질문 | `session.followup.next_question`을 카드로 보여 준다(아래). |
| 답변 전송 | 카드의 버튼은 `followup/answers`로 그 질문의 답만 보낸다(아래). |
| 서버 확인 | 시작할 때 `GET /api/voice/capabilities`를 읽는다. `voice_revision`이 `voice-v2-20261030`이 아니면 화면 아래에 경고한다. `transcript_modes`에 `auto`가 없으면 `환자 상태만`으로 바꾸고 자동 버튼을 끈다. |
| 문맥 힌트 | capabilities의 `speech_context_hints`와 terms의 `speech_recognition_hints`를 합친다(아래). |
| 금지 호출 없음 | 이 화면은 `capabilities`, `terms`, `sessions`, `transcripts`, `followup/answers`만 부른다. 음성 “전송”은 안내만 하고, 음성 “확인”은 서버가 `confirmation_requires_tap`으로 돌려준다. |

**무전기 버튼:**

- 0.4초보다 짧게 누르면 버리고 “짧게 눌렀습니다…”라고 안내한다.
- 30초가 지나면 누르고 있어도 자동으로 마치고 보낸다.
- Space·Enter를 누르고 있어도 같다. 키 반복은 무시한다.
- 손을 뗀 뒤 따라오는 클릭은 무시한다. 누름 없이 들어온 클릭(보조기기)은 시작·종료 토글로 동작한다.
- 시작 신호는 진동이며, 화면 사용 기록이 있을 때만 준다. 신호음은 마이크가 열리는 동안 다시 받아 적힐 수 있어 넣지 않았다.

**방금 바뀐 내용:**

- 수치는 ▲▼ 방향과 “수치 비교이며 임상 판정이 아님” 문구를 함께 보여 준다.
- 새로 기록한 칸과 비운 칸은 이름만 묶어 보여 준다. 자동 해석 제안은 개수만 보여 준다.
- `latest_changes`는 마지막 개정 기준이다. 그래서 **이번 요청으로 버전이 올랐을 때만** 표시한다. 읽기 명령처럼 버전이 그대로면 예전 변경을 다시 보여 주지 않는다.

**재확인과 미측정 구분:**

- 서버가 `needs_clarification`을 표시한 칸(값 없이 “혈압이 지금 떨어졌어”라고 말한 경우)은 이렇게 보여 준다.
  - 카드: `재확인 필요`, 값 옆 `(이전 관찰값)`
  - 변경 목록: `이전 관찰값 X · 현재 값 미확인`
- `미측정·모름`으로 답한 질문의 칸(`followup.items[].answer_status: "unavailable"`)은 `미측정·확인 불가`로 따로 보여 준다.
- 어느 쪽도 값을 채우지 않는다.

**확인 질문:**

- 카드에 이유(누락·재확인 필요·미확인)와 `남은 질문 n개`를 보여 준다.
- 처리 결과가 나오고 마이크가 닫힌 뒤 질문을 한국어 TTS로 한 번 읽는다.
  - 같은 질문 ID와 문장은 다시 읽지 않는다. `다시 듣기`로는 다시 읽는다.
  - `처리 뒤 확인 질문을 소리로 읽기`를 끄면 읽지 않는다.
- 카드 문구: 시연용 체크리스트이며 임상 필수·등록 가능 판정이 아님.

**답변 전송:**

- 보내는 값: `question_id`, `profile: voice_extended_v1`, 새 `utterance_id`, `text`, 질문을 보여 준 초안 버전(`expected_version`).
- `미측정 · 모름` 버튼: `text: "미측정"`, `unavailable: true`
- 응답 처리:

| 서버 응답 | 화면 동작 |
|---|---|
| `accepted:false` | 질문을 유지하고 다시 답하라고 안내한다. |
| `ignored_fields` 있음 | “질문 대상이 아닌 맥박 값은 반영하지 않았습니다. 큰 버튼으로 다시 말해 주세요.” |
| 409 | 최신 초안과 질문을 다시 읽고 다시 확인하게 한다. 예전 질문으로 재시도하지 않는다. |
| 응답 유실 | `같은 요청 재시도`가 같은 요청 ID·발화 ID·본문·버전으로 다시 보낸다. |

**문맥 힌트:**

- 항목 이름·증상 용어만 브라우저 `SpeechRecognitionPhrase`(boost 1.0, 표준 기본값)에 넘긴다. 지금 서버 목록에서는 13개를 넘기고 8개를 뺀다.
- 값이 든 표현(정상·저하·없음·있음·숫자)은 넘기지 않는다. 불분명한 음성을 정상 소견이나 특정 수치로 끌 수 있기 때문이다.
- 브라우저가 `phrases-not-supported`로 거부하면 한 번만 일반 인식으로 다시 시작한다. 그 뒤로는 힌트 없이 시작한다. 다른 인식 오류는 지금처럼 재시작하지 않는다.
- 다시 시작한 뒤에는 이전 인식기 콜백이 세션에 들어오지 못하게 막았다(시험 중 발견해 고침).
- 화면에는 `미지원`·`요청`·`전달`·`거부` 상태를 보여 준다. 전달했다고 정확도가 나아졌다고 표시하지 않는다.

표준 근거: [W3C Web Speech API](https://webaudio.github.io/web-speech-api/) 편집자 초안을 10-30에 확인했다.

- `phrases`: `ObservableArray<SpeechRecognitionPhrase>`, boost 범위 0~10, 기본값 1.0
- `phrases-not-supported`: 시작할 때 오류 이벤트로 온다.
- `SpeechGrammarList`: 동작하지 않는 하위 호환용이라 쓰지 않는다.

### 2.1 관대한 답변 처리(사용자 결정 뒤 추가)

새 파일 `paramedic-ui/answer-match.mjs`가 판단을 맡는다. 서버에 보내는 문장은 항상 인식기가 실제로 낸 결과다.

| 기능 | 동작 |
|---|---|
| 미측정 알아듣기 | ‘비 측정’, ‘및 측정’(실제 인식 결과), ‘미측’, ‘미측정이요’, ‘측정 안 했어요’, ‘아직 안 쟀어요’, ‘모르겠습니다’, ‘패스’ 같은 짧은 답을 미측정 뜻으로 본다. 들린 문장은 그대로 두고 `unavailable: true`를 붙인다. |
| 미측정 오인 방지 | 숫자가 있으면 미측정으로 보지 않는다. ‘비정상’, ‘호흡 없음’, ‘편안했어요’, ‘넘어졌어요’, ‘모르핀’도 미측정으로 보지 않는다(테스트로 고정). |
| 인식 후보 고르기 | 답변을 녹음할 때만 브라우저에 후보 5개를 요청한다(`maxAlternatives`). 1순위가 질문 형태에 맞지 않으면 맞는 후보를 고른다(예: 1순위 ‘분당 입회’ → ‘분당 20회’). 아라비아 숫자가 든 후보를 한글 수만 든 후보보다 먼저 고른다. 고른 순위와 1순위 문장은 기록에 표시한다. 긴 설명은 지금처럼 1순위만 쓴다. |
| 답변용 힌트 | 답하는 동안 그 질문의 보기를 한꺼번에 힌트로 준다(호흡: 정상·비정상·없음 / 의식: 명료·저하·반응 없음, 공통: 미측정·모름). 보기를 모두 넣으므로 정상 쪽으로만 치우치지 않는다. 특정 숫자는 넣지 않는다. |
| 같은 질문 반복 안 함 | 서버가 답을 받지 않으면(`accepted:false`) 그 질문을 **보류**하고 다음 질문으로 넘어간다. 서버는 목록(`items`)에 있는 질문이면 어느 것이든 받으므로 계약 안에서 동작한다. |
| 보류 목록 | “검토 때 확인할 질문: 호흡수(들린 말 ‘분당 이사’)”처럼 보여 준다. `보류한 질문 다시 묻기`로 다시 묻는다. 값이 다른 경로로 들어오면 목록에서 빠진다. |
| 보류 뒤 읽기 | 보류한 질문을 다시 읽지 않는다. 남은 질문이 없으면 “알아듣지 못한 답은 보류했습니다. 검토할 때 확인해 주세요.”만 읽는다. |

### 2.2 화면 구성 — 시안 B(대화형), 사용자 선택

Claude Design 캔버스에 시안 3개(A 모니터형, B 대화형, C 체크리스트형)를 만들었고, 사용자가 B를 골랐다. 서버 계약과 동작은 그대로 두고 화면만 바꿨다.

| 영역 | 내용 |
|---|---|
| 위: 환자 요약 | 확인 질문 12항목을 칩 10개로 표시한다(나이·성별, 증상·발생은 하나로 묶음). 변화 ▼▲, 질문 중, 보류, 미측정, 재확인, 빈칸(—)을 색과 문구로 구분한다. 표시 형식: “12개 중 N개”. `전체 보기`를 누르면 기존 상세 카드(값·근거·출처), 방금 바뀐 내용, 자동 해석 제안, 경고가 펼쳐진다. |
| 가운데: 대화 | 말한 문장은 오른쪽 말풍선이다. 아래에 처리 방식(자동 판단 → 상태 설명/상태 변화/명령)과 결과 태그가 붙는다(“상태 변화 관찰 · 혈압 120/80 → 100/70 ▼”, “알아듣지 못해 보류 · 검토 때 확인”, “미측정 · 값을 채우지 않음”). 답변은 앱 질문 말풍선 다음에 붙고, 명령 결과·안내는 앱 말풍선으로 붙는다. 녹음 중에는 점선 말풍선에 최종 조각이 쌓인다. |
| 아래: 입력 | 질문 카드(이유·남은 수·보류 수, 보기 버튼, `미측정 · 모름`), 보류 안내와 `다시 묻기`, 큰 원형 마이크가 있다. 질문이 있으면 큰 마이크는 답하기이고, 왼쪽 `다른 내용`이 일반 입력(둘 다 누르고 있는 동안만 녹음)이다. 오른쪽 버튼은 질문이 있으면 `다시 듣기`, 없으면 `읽어주기`, 녹음 중에는 `취소`다. |
| 설정 | 말하기 방식(자동·상태만·명령만), 질문 소리로 읽기, 새 기록, 예시 문장, 서버·힌트 상태, 개인정보 안내. 서버 버전은 위쪽 칩(`음성 V2`/`버전 다름`/`서버 연결 안 됨`)으로도 보인다. |

**보기 버튼(탭 답변):**

- 의식(명료·저하·반응 없음), 호흡(정상·비정상·없음), 성별, 단일 미확인 증상(있음·없음)은 탭으로 답할 수 있다.
- 음성 답변과 같은 `followup/answers`로 보낸다. 기록에는 `[버튼]`으로 표시한다.
- 5.4의 `input_method` 제안이 반영되면 서버 기록에서도 구분할 수 있다.

**확인:**

- 인앱 브라우저(390×844)에서 가짜 인식기로 시안과 같은 장면을 재현했다. 칩 10개, 대화, 질문 카드, “12개 중 9개”가 맞게 나왔다.
- 녹음 중 빨간 마이크, 점선 말풍선, 취소 버튼, 다크 모드도 확인했다.
- 콘솔 오류는 없었다.

## 3 화면이 쓰는 서버 계약(Codex 참고)

바뀌면 화면이 깨지는 부분이다.

- **`session` 객체**
  - `fields`, `field_metadata[k].{needs_clarification, clarification_evidence, evidence, source, contextual_answer}`
  - `latest_changes[].{field, previous, current, change_kind, direction}`
  - `followup.{next_question, items[].answer_status, items[].fields, complete, collection_complete, unanswered_count, unresolved_count}`
  - `version`, `speak_text`, `warnings`
- **`next_question`:** `id`, `fields`, `question`, `answer_hint`, `reason`(missing·needs_clarification·uncertain)
- **`transcripts` 응답:** `command.action`, `effective_mode`, `operational_effect`(`confirmation_requires_tap`, `explicit_submit_api_required`), `speak_text`
- **`followup/answers` 응답:** `answer.{accepted, unavailable, contextual_answer, applied_fields, ignored_fields}`, `speak_text`. 409는 `VOICE_QUESTION_CHANGED`·`VOICE_VERSION_CONFLICT`를 같은 방식으로 처리한다.
- **`change_kind` 표시 이름:**

| 값 | 표시 |
|---|---|
| `dictation` | 받아쓰기 |
| `observation` | 상태 변화 관찰 |

- **제안:**
  - 항목 이름 바로 뒤에 붙은 한 글자 한글 수는 단위나 다른 수가 뒤따를 때만 값으로 읽는다.
  - 위 문장들을 회귀 테스트에 넣어, 값 없음과 `needs_clarification`을 기대값으로 둔다.

### 5.2 [작은 문제] 미측정 답변에 엉뚱한 경고가 붙는다

- 수치 질문(산소포화도)에 `unavailable: true`로 답하면 경고 “질문에는 하나의 정확한 측정값을 답해 주세요…”가 붙는다.
- 원인: `answer_followup`의 수치 질문 분기가 `unavailable`보다 먼저 경고를 만든다.
- 제안: `unavailable`이면 이 경고를 넣지 않는다.

### 5.3 [제안] 인식 힌트 목록에서 값 표현을 분리

- `speech_recognition_hints`와 `speech_context_hints`에 값이 든 표현이 섞여 있다(‘의식 명료’, ‘호흡 정상’, ‘구토 없음’, ‘출혈 없음’, ‘혈압 백이십에 팔십’, ‘체온 삼십칠 점 이’ 등).
- 문맥 편향은 불분명한 음성을 그 값 쪽으로 끌 수 있다.
- 화면은 지금 걸러서 쓴다(거르는 규칙: 숫자·십·백·명료·정상·저하·없음·있음).
- 제안: 서버가 용어 힌트만 주거나, 용어와 값 표현을 따로 나눠 준다.

### 5.4 [제안] 답변 입력 방식을 기록

- 미측정 버튼은 `text: "미측정"`으로 보낸다. 지금 발화 기록에서는 음성 답변과 구분되지 않는다.
- 제안: `input_method`(`voice`·`button`·`ptt`)를 받으면, 음성 정확도 평가에서 버튼 답변을 뺄 수 있다. 이 필드는 무전기 설계 문서의 선택 과제와도 같다.

**알려진 저장소 특성:**

- 윈도에서 `core.autocrlf=true`로 새로 받으면 줄바꿈이 CRLF로 바뀐다. 그러면 일부 배정 실험의 고정 소스 해시 검사가 `frozen H1 source differs`로 멈춘다.
- 저장소 내용은 같다. 해당 파일을 LF로 받으면 통과한다. 잠금 해시는 고치지 않았다.

**원래 작업 폴더:**

- 브랜치는 `codex/peer-review-server-20261029`, 미커밋 상태 그대로다.
- 올린 파일이 미커밋 사본으로도 남아 있다. 그래서 이 폴더에서 새 브랜치로 바로 전환하면 “덮어쓸 미추적 파일” 오류가 날 수 있다.
- 정리 방법은 Codex 작업이 멈춘 뒤 사용자와 정한다.

