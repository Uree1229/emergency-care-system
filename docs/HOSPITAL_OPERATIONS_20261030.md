# 병원 통화 기록·업무 계측·외부 유입 연결

2026-10-30. `hospital-ui/index.html`에 **통화 기록 · 업무 계측** 탭을 추가하고, 기존 **병원 자원** 탭의 외부 유입 등록을 고정 요청 ID·목록·개별 퇴실 API에 연결했다. 구현은 새 `hospital-ui/operations.mjs`에 분리했다. 서버의 기존 자원·수용·배정 로직은 변경하지 않았다.

## 통화 기록

병원 전체 통화함 `GET /api/hospitals/{hid}/call-records`로 이송 ID를 미리 몰라도 자기 병원에 공유된 기록을 발견한다. 전체·미확인·확인됨·이의 필터와 이전 기록 페이지를 제공한다. 선택한 기록의 이송 건 또는 직접 입력한 기존 이송 ID로 기록·업무 계측을 연다.

- `통화 기록 내용 확인`과 `내용 이의`는 구급대원이 작성한 현재 기록에만 제공한다. 확인 상태를 `기록 내용 확인됨`으로 표시한다.
- **통화 내용 확인은 수용 응답이 아니다.** 통화 결과의 `수용 가능하다고 전달받음`을 수용 확정 배지로 바꾸지 않는다. 수용·불가·목적지 변경은 기존 업무 API와 버튼을 사용한다.
- 병원이 작성한 기록의 원 작업자는 `원문 보존·정정본 작성`으로 새 정정본을 추가한다. 원문·정정 관계·상대측 이의 사유를 보존해 표시한다.
- 통화 시작·종료 입력은 명시적으로 KST이며 브라우저 컴퓨터의 기본 시간대와 무관하게 epoch로 변환한다. 담당자가 보고한 통화 시각과 서버 저장 시각을 구분한다. 실제 전화 연결·녹음·통화시간의 독립 측정 기능은 아니다.
- 메모·상대 표시명·서버 출처는 HTML 이스케이프 후 일반 텍스트로 표시한다. 다른 병원의 내용이나 환자 본문을 합쳐 표시하지 않는다.

## 직접 업무 계측

이송 건을 선택한 뒤 실제 검토·응답·추가 질문·통화 등의 활동을 시작할 때 **내 업무 시작**, 끝났을 때 해당 행의 **내 업무 종료**를 누른다. 단순히 화면을 열거나 수용 문의를 자동으로 기다리는 동작은 업무를 시작하지 않는다.

시작·종료의 권위 시각은 서버가 기록한다. 화면의 진행 중 초 표시만 `performance.now()`의 단조 시계로 늘린다. 컴퓨터 벽시계 변경이나 API 응답 전송시각을 완료 활동시간으로 사용하지 않는다. 새로고침하면 같은 작업자 ID로 열린 업무를 서버에서 다시 조회하고, 작업자가 직접 종료한다. 창 닫기·탭 전환을 완료로 추정하지 않는다.

작업자 ID는 서버·병원·입력한 담당자 이름별로 생성해 로컬 저장소에 보존한다. 다른 담당자의 활동을 종료하지 않는다. 이미 미종료 업무가 있으면 먼저 해당 업무를 조회·종료하도록 새 시작을 제한한다. 이전 업무 더 보기로 오래된 열린 업무도 찾을 수 있다.

완료 활동시간은 서버 집계의 중첩 제거 값을 표시한다. 미종료 건수는 완료 시간과 분리한다. 등록 전 입력시간·서로 다른 환자 사이의 중복시간·병원 전체 업무량은 이 수치로 측정하지 않는다. 통화 메모에 입력한 보고 통화기간도 활동시간에 자동 합산하지 않는다.

## 외부 유입

기존 자원 탭의 합성 유입 등록 폼에서 새로운 등록을 처음 전송하기 전에 `request_id`를 한 번 생성한다. 요청은 서버·병원 범위의 브라우저 저장소에 먼저 보존한다. 응답이 사라지거나 새로고침해도 같은 요청 ID·자원 수량·메모·처리자로 재시도한다. 미확인 요청의 입력은 잠그고 `같은 유입 요청 재시도`를 표시한다. 담당자 이름을 바꿔도 같은 병원의 미확인 유입 요청을 복구한다.

자원 탭 아래 **외부 유입 목록·개별 퇴실**에서 활성·퇴실 이력·무차감 종결·과거 원장 없음·전체 필터를 제공한다. 더 보기로 페이지를 조회한다. 활성 기록의 `이 기록만 퇴실·반영 점유 해제`는 그 기록 ID와 조회한 `expected_version`을 `/external-arrivals/{id}/discharge`로 전송한다.

목록에서 `resource_demands`를 점유 합계로 간주하지 않고 실제 반영한 `applied_resource_demands`를 표시한다. 퇴실 성공 후 목록·자원·도착 예정 상태를 재조회한다. 기록을 삭제하거나 점유 합계를 임의로 차감하지 않는다. `LEGACY`·이미 종료한 기록에는 자동 퇴실 버튼을 제공하지 않는다. 집계·버전 충돌을 무차감 종결 API로 자동 우회하지 않는다.

## 오류·중복·범위 변경

통화 작성·내용 확인·업무 시작·업무 종료·외부 유입 등록·개별 퇴실은 각각 첫 전송의 경로·본문·요청 키를 로컬 저장소에 보존한다. 전송 중 중복 클릭은 같은 요청 하나만 보낸다. HTTP 500·연결 오류처럼 결과가 불명확하면 같은 경로·본문으로 재시도한다. 보존할 수 없는 저장소 오류는 요청 전송 전에 표시한다.

400·403·404·409처럼 서버가 명시적으로 거부한 요청은 자동으로 재적용하지 않는다. 오류를 표시하고 입력 수정 또는 최신 목록 확인 뒤 사용자가 다시 수행한다. 409는 재조회하며, 새 버전으로 조용히 바꿔 자동 승인하지 않는다. 열린 업무나 저장된 통화가 서버 조회로 확인되면 그 요청의 미확인 표시를 해소한다.

서버·병원·담당자 전환마다 화면 세대를 바꾼다. 이전 요청이 늦게 도착해도 새 범위의 목록을 덮어쓰지 않는다. 응답 레코드의 병원·환자·작업자 범위를 검사하고 불일치 응답을 표시하지 않는다. 같은 병원의 필터 요청이 경합해도 나중에 요청한 필터가 우선한다. 자동 조회 중 입력·선택·메모에 포커스가 있으면 폼 DOM 자체를 교체하지 않는다. 실제 날짜 선택창·입력 연결을 보존하고 새 자료는 다음 입력 종료 후 자동 조회에 반영한다. 자료가 변하지 않은 자동 조회도 화면을 재생성하지 않는다. 담당자가 누른 새로고침과 쓰기 처리는 즉시 반영한다.

## 자료 출처와 연결

통화·계측 탭 아래 출처 펼침에서 `GET /api/hospitals/{hid}/data-provenance`의 기관 원천, 공공 관측의 원천 기준시각·수집시각, 운영 자원의 원천·갱신 신선도·공공값 여부를 표시한다. 기준시각이 없으면 미상으로 남긴다. `hospital_input`이나 시연 입력을 실제 병원의 실측으로 소개하지 않는다. 공공 관측을 운영 총량 또는 환자별 수용 확답으로 대신하지 않는다.

별도의 **이송 중 조건 변경 검토 화면 열기** 링크는 현재 서버의 `/patient/transport-change.html?hid=...`로 연결한다. 해당 검토는 별도 화면의 권한·버전·명시적 승인 계약을 따른다.
