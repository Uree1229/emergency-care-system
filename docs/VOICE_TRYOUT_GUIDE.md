# 구급대원 음성 기록 — 팀원 체험 안내

2026-10-30 · 브랜치 `codex/voice-toggle-20261030`

**구급대원 음성 기록 화면**은 버튼을 한 번 눌러 환자 상태를 말하고, 다시 누르거나 음성 종료 명령으로 마치면 초안을 만드는 시연 화면이다. 설정에서 기존 누르는 동안 말하기도 고를 수 있다. 토글은 `quick-test.html`에서 사용하며, 메인 이송 노트(`/paramedic/`)에는 별도로 로컬 WAV·PCM 설정 비교 시험을 제공한다.

- 말한 내용은 서버가 칸으로 정리한다.
- 빠진 항목은 질문으로 다시 묻는다.
- 바뀐 값은 이전 값과 함께 보여 준다.

**전부 가상 시연이다.** 실제 환자정보를 말하지 말고, 실제 병원에 연락하지 않는다. 이 화면은 환자 등록·병원 문의·전송을 실행하지 않는다.

## 1 준비물

- Windows 또는 macOS 노트북, Python 3.12 이상
  - 이 체험에는 추가 패키지가 필요 없다. 배정 솔버는 끄고 실행한다.
- 마이크와 브라우저 음성 인식 기능
  - 화면은 `SpeechRecognition` 또는 `webkitSpeechRecognition`의 제공 여부를 감지한다. 브라우저 이름만으로 모든 환경의 지원을 보장하지 않는다.
  - 브라우저 음성 서비스·마이크 권한·네트워크에 따라 실제 인식 가능 여부가 달라진다. 음성 인식을 쓸 수 없으면 설정의 직접 입력 시험을 이용한다.

## 2 실행(5분)

저장소를 이미 받았다면 브랜치만 바꾼다.

```bash
git fetch origin
git switch codex/voice-toggle-20261030
```

처음 받는다면 다음과 같이 받는다.

```bash
git clone -b codex/voice-toggle-20261030 https://github.com/Uree1229/emergency-care-system.git
```

저장소 루트에서 서버를 켠다. **`--seed`는 지정한 DB를 새로 만들므로 처음 한 번만 쓴다.**

```powershell
python -m server.app --db data/voice-tryout.db --seed --port 8000 --no-planner --no-inquiry-worker
```

다음부터는 `--seed`를 빼고 같은 명령으로 켠다.

```powershell
python -m server.app --db data/voice-tryout.db --port 8000 --no-planner --no-inquiry-worker
```

브라우저에서 **http://127.0.0.1:8000/paramedic/quick-test.html** 을 열고 마이크를 허용한다. 오른쪽 위 칩이 **`음성 V2`** 인지 확인한다.

### 휴대폰으로 써 볼 때

마이크는 HTTPS나 `localhost`에서만 켜진다. 같은 와이파이의 `http://192.168.x.x:8000`으로 열면 마이크가 막힌다.

1. 안드로이드 폰을 USB로 연결한다.
2. 노트북 크롬에서 `chrome://inspect` → Port forwarding을 열고 `8000` → `localhost:8000`을 켠다.
3. 폰 크롬에서 http://localhost:8000/paramedic/quick-test.html 을 연다.

## 3 화면 보는 법

| 위치 | 내용 |
|---|---|
| 위 · 환자 요약 | 확인할 12항목을 칩으로 보여 준다(“12개 중 N개”). 아래 표 참고. `전체 보기`를 누르면 값과 근거(들린 문장)가 나온다. |
| 가운데 · 대화 | 앱 질문은 왼쪽, 내가 말한 문장은 오른쪽 말풍선이다. 말풍선 아래에 처리 결과가 붙는다. |
| 아래 · 입력 | 큰 원형 버튼을 **한 번 눌러 시작하고 다시 눌러 종료**한다. 질문이 떠 있으면 큰 버튼은 그 질문에 답하고, 왼쪽 `다른 내용`이 일반 입력이다. |

칩 표시:

| 표시 | 뜻 |
|---|---|
| 파랑 ▼▲ | 방금 바뀐 값 |
| 청록 테두리 | 지금 묻는 항목 |
| 노란 점선 | 알아듣지 못해 보류한 항목 |
| 회색 | 미측정 |
| — | 빈칸 |

입력 버튼 규칙:

- 기본 토글은 손을 떼어도 계속 듣는다. 버튼·Space·Enter를 한 번 더 누르면 종료한다.
- 토글은 최대 180초다. 브라우저가 인식을 먼저 종료할 수도 있으므로 3분 연속 녹음을 보장하는 것은 아니다.
- 확정 인식문 마지막에 “그만”·“종료”·“녹음 종료”가 나오면 종료한다. 임시 인식문은 실행하지 않는다.
- “혈압 120에 80, 그만”은 앞 본문을 보존하고 종료어를 제외한다. “처치 종료” 같은 임상 표현과 인용·부정 표현은 종료 명령으로 오인하지 않도록 구분한다. 종료어만 말하면 빈 초안을 만들지 않는다.
- 설정 → `누르는 동안 말하기`를 선택하면 기존 무전기 방식이다. 0.4초보다 짧게 누르면 취소하고 최대 30초다. 이 방식에서는 음성 종료어를 적용하지 않는다.
- 의식·호흡처럼 보기가 정해진 질문은 보기 버튼을 탭해도 된다.

음성 종료어 뒤 늦게 확정된 문장은 **`종료 후 추가 인식 (미반영)`** 에 남고 자동 적용되지 않는다. 필요한 내용이면 `직접 입력으로 가져오기`를 누르고 내용을 검토·수정한 다음 **`검토한 내용을 초안에 반영`** 을 누른다. 버튼이나 시간 상한으로 종료할 때는 종료 과정의 늦은 확정 문장까지 모은다.

설정의 **`직접 입력 시험`** 은 1~4000자 본문을 검토해 받아쓰기 방식으로 반영한다. 여기에 붙여 넣은 “그만”·“종료”에는 음성 종료 규칙을 적용하지 않는다. 녹음·요청 처리 중에는 수동 반영을 막고, 같은 본문을 성공 직후 중복 적용하지 않는다. 음성 본문이 4000자를 넘으면 원문을 화면에 남기고 전송하지 않는다.

## 4 써 볼 순서(그대로 따라 말하기)

각 행은 버튼을 한 번 눌러 녹음을 시작한 뒤 말하고, 같은 버튼을 다시 눌러 종료한다. 마지막에 “녹음 종료”를 덧붙여 음성 종료를 시험해도 된다. 한 입력의 처리가 끝난 뒤 다음 행으로 넘어간다.

| 순서 | 버튼 | 말할 문장 | 기대 결과 |
|---|---|---|---|
| 1 | 큰 버튼 | “47세 남성 환자입니다. 20분 전부터 가슴 통증이 있습니다. 혈압 120에 80, 맥박 92회, 산소포화도 97퍼센트, 체온 37.2도입니다.” | 요약 칩이 채워지고, 의식 질문이 나타나며 소리로 읽힌다. |
| 2 | 큰 버튼(답하기) | “명료” (또는 `명료` 탭) | 의식 칸 반영. 다음 질문으로 넘어간다. |
| 3 | 큰 버튼(답하기) | “정상” | 호흡 칸 반영 |
| 4 | 왼쪽 `다른 내용` | “혈압이 지금 100에 70까지 떨어졌어” | 혈압 칩 `100/70 ▼`, 말풍선 아래 `120/80 → 100/70 ▼` |
| 5 | 큰 버튼(답하기) | “분당 20회” | 호흡수 20 반영 |
| 6 | 큰 버튼(답하기) | “미측정” (또는 `미측정 · 모름`) | 혈당은 0이나 정상으로 채우지 않고 미측정으로 남는다. |
| 7 | 질문이 없을 때 큰 버튼 | “방금 거 취소” | 직전 변경을 되돌린다. |
| 8 | 일반 입력(`다른 내용` 또는 질문이 없을 때 큰 버튼) | “확인”, “환자 정보로 전송” | 실행하지 않고 안내만 한다. 이 시험 화면은 환자 확인·등록·병원 전송을 실행하지 않는다. |

그 밖에 자유롭게 말해 본다(상태 변화, 정정, 짧은 답). 답을 못 알아들으면 같은 질문을 반복하지 않고 **보류**한다. 보류한 질문은 들린 말과 함께 남으니, 검토할 때 고치면 된다.

네트워크 응답을 잃어 저장 결과가 불확실하면 새 입력을 막고 `재시도`를 표시한다. 같은 요청 ID·본문·버전으로 결과를 확인하므로 다시 녹음해 중복 저장하지 않는다. 409가 나면 최신 초안·질문을 다시 불러오며 이전 답을 자동 덮어쓰지 않는다.

## 5 의견 남기기

팀 채팅이나 GitHub 이슈에 아래 다섯 가지를 적어 주세요.

1. **말한 문장:** 실제로 말하려던 문장
2. **들린 말:** 화면 말풍선에 나온 문장
3. **결과:** 반영됐는지, 보류됐는지, 잘못 반영됐는지(어떤 칸이 어떤 값으로)
4. **환경:** 기기·브라우저, 조용한 곳인지 시끄러운 곳인지
5. **불편했던 점:** 버튼 위치, 글자 크기, 읽어 주는 소리 등

말한 문장과 들린 말이 다르면 인식 단계 문제이고, 같은데 칸이 틀리면 서버 해석 문제다. 둘을 나눠 적으면 바로 고칠 곳을 찾을 수 있다.

## 6 개인정보와 범위

- 마이크는 버튼으로 시작한 뒤 선택한 방식의 종료·취소·브라우저 종료까지 열린다. 브라우저 음성 인식은 제공사의 온라인 서비스로 음성을 보낼 수 있다.
- 말하기 기록의 `인식 원문 · API 전송 본문`에서 종료어를 포함한 확정 인식 원문과 실제 API 본문을 구분한다. 서버 로컬 DB(`data/voice-tryout.db`)에는 전송한 본문과 초안만 저장한다. 원본 음성이나 종료어를 포함한 전체 원문을 서버에 저장한다고 표시하지 않는다. DB 파일은 Git에 올리지 않는다.
- 화면의 인식 원문·종료 후 미반영 문장은 새로고침하면 사라진다. 이 시험 화면은 새로고침 후 이전 초안도 자동 복원하지 않는다.
- 12항목 질문은 시연용 입력 체크리스트다. 임상 필수 항목이나 환자 등록 가능 판정이 아니다.

## 7 문제 해결

저장 여부는 요약 항목 수와 별도로 표시한다. 원문만 저장된 경우에는 `원문 저장됨 · 항목 확인 필요`, 저장 응답을 잃은 경우에는 이번 입력이 확인 중임을 보여 준다. `저장된 기록 확인`을 펼쳐 서버 주소·기록 ID·버전을 확인한다. 개발자는 예전 실행 기록이 아닌 현재 서버를 기준으로 [저장 점검](VOICE_STORAGE_CHECK.md)을 실행한다.

| 증상 | 확인할 것 |
|---|---|
| `지원 브라우저 필요` | 해당 환경에서 브라우저 음성 인식 기능이 제공되는지 확인한다. 이용할 수 없으면 설정의 직접 입력 시험을 쓴다. |
| 마이크가 안 켜짐 | 주소창 왼쪽 아이콘 → 마이크 허용. `127.0.0.1`·`localhost` 주소인지 확인한다. |
| 위쪽 칩이 `버전 다름`·`서버 연결 안 됨` | 이 브랜치의 서버를 다시 켠다. 다른 오래된 서버가 같은 포트를 쓰는지 확인한다. |
| 누르자마자 취소됨 | 무전기 방식을 선택했다면 0.4초 이상 누르고 상태가 “듣고 있습니다”로 바뀐 뒤 말한다. 토글 방식은 한 번 누르면 된다. |
| 녹음은 끝났는데 서버 기록이 없음 | 확정 인식문·오류 메시지를 확인한다. 종료어만 말했거나, 본문이 없거나, 4000자를 넘으면 전송하지 않는다. 응답이 불확실하면 `재시도`를 이용한다. |
| 포트 사용 중 | `--port 8010`처럼 바꾸고 주소도 같이 바꾼다. |
| 인식이 자꾸 틀림 | 마이크를 입 가까이 대고 짧게 끊어 말한다. 숫자는 “백이십에 팔십”보다 “120에 80”처럼 또박또박 말하면 잘 들린다. |

## 8 알려진 한계

- **정확도 미측정:** 음성 인식 정확도는 브라우저·마이크·소음에 따라 다르다. 이 화면은 기능 시연이며 정확도를 재지 않는다.
- **깨진 단어:** 단어가 통째로 다르게 들리면(예: ‘호흡 정상’ → ‘고급 정장’) 복원하지 않고 보류한다.
- **메인 화면:** 토글·음성 종료·미반영 문장 검토는 `quick-test.html`에서 시험한다. 메인의 `오디오만 녹음 · 로컬 시험`에서는 STT 키 없이 WAV·요청/실제 설정 JSON을 내려받을 수 있다. [현장 소음 시험 방법과 검증 한계](VOICE_NOISE_TESTING_20261030.md)를 확인한다.
