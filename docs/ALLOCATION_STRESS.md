# 큰 배치의 배정 알고리즘 개선과 검증

2026-10-14. 새 H1은 **현재 확보한 수용 후보와 자원으로 공동 배정을 만드는 실험용 알고리즘**이다. 기존 서버·환자 앱·병원 앱·지도 재생의 선택 규칙은 변경하지 않았다.

## 바꾼 계산 규칙

기존 큰 문제의 순차 방식에서는 선택지가 많은 환자가 가까운 병원을 먼저 차지해, 그 병원밖에 갈 수 없는 환자가 미배정될 수 있었다. 기존 R2의 경쟁비용은 실제 수용 응답을 확보하지 않은 병원도 대안으로 계산한다.

H1은 다음 순서로 계산한다.

1. 우선순위·요청시각 순으로 가까운 병원을 선택한 실행 가능 기준해를 먼저 만든다.
2. 실제 수용 후보 수, 현재 잔여 자원의 경쟁 수요, 자원 수요 대비 우선순위를 사용해 여러 초기 배정을 만든다.
3. 미배정 환자를 넣기 위해 이미 배정한 환자를 다른 유효 후보로 옮기거나, 두 환자의 병원을 교환하고 이동비용을 줄인다.
4. 모든 자원 제약을 다시 검사하고 목적값이 더 좋아진 결과만 보존한다.

미배정 환자 삽입을 앞에서 검사해, 100명 문제에서 단순 이동 후보 수백 개 때문에 중요한 재배치를 검토하지 못하는 문제도 막았다. 한 명의 방해 환자를 옮기는 제한된 탐색이며 임의 길이의 재배치나 최적성을 보장하지 않는다.

목적은 C1과 동일하게 **미배정 우선순위 합 → 우선순위 가중 이동시간 합**을 순서대로 최소화한다. 우선순위4·2·1은 실험 가중치다. 전체 미배정 인원 수나 임상 중증도별 계층 목적과 혼용하지 않는다. 미래 환자·미래 회신·자원 반환 예정시각은 읽지 않고 기존 확정 수요를 바꾸지 않는다.

## 개발과 검증 분리

- 개발: seed12101–12102, 7유형 × 20·50·100명 × 2seed = 42사례.
- 개발에서 탐색 횟수256/2048을 비교했다. 결과 전에 고정한 선택 규칙은 50ms 탐색 예산에서 전체 미배정 우선순위 합, 동률이면 가중 이동분 합을 줄이는 것이다.
- 2048회는 개발42사례 중18개 개선·24개 동률·0개 악화였고, 미배정은578→575명으로 줄었다. 10ms에서는 악화1개도 보존했다. [개발 선택과 전체 결과](../simulation_results/allocation_stress_moves_comparison_20261014.md).
- 소스12개·설정·런타임·seed를 잠근 뒤 미사용 seed13101–13104에서84사례 × 8분기 = 672배정을 검증했다. 검증 후 계산 규칙·시나리오·설정을 변경하지 않았다.
- 비교는 R1 최근거리 순차, R2 기존 경합 비용, H1 개선안과 C1 CP-SAT다. H1/C1은 각각10·50·200ms 탐색 예산으로 실행한다. 매 분기에 동일한 현재 입력을 주고 실행 순서를 회전했다.

선택 설정은 `config/heuristic_assignment_selected_20261014.json`의 **50ms·2048회**다. 클래스의 기본256회와 구분해서 명시적으로 전달한다.

```python
from simulation.heuristic_assignment import HeuristicAssignmentRule

rule = HeuristicAssignmentRule(time_limit_seconds=0.05, max_moves=2048)
plan = rule.decide_batch(sim, ready, current_minute)
```

## 새 검증 결과

84사례의 환자 합계는4,760명이다. 아래 수치는 같은 환자 목록에서 규칙별로 한 번씩 집계했다. 자원 전무 대조군680명도 포함하며, 이 대조군에서는 모든 규칙이 전원 미배정이다.

| 규칙 | 미배정 합계 | 미배정 우선순위 합 | 전체 계산 중앙값 | 전체 계산 p95 |
|---|---:|---:|---:|---:|
| R1 최근거리 순차 | 1,574 | 3,083 | 0.13ms | 0.70ms |
| R2 기존 경합 비용 | 1,556 | 3,055 | 2.54ms | 96.28ms |
| H1 개선안·50ms | 1,172 | 2,308 | 4.71ms | 51.11ms |
| C1 CP-SAT·50ms | 1,168 | 2,309 | 11.23ms | 51.76ms |
| C1 CP-SAT·200ms | 1,159 | 2,299 | 11.60ms | 201.61ms |

H1 50ms는 R1보다402명 더 배정했지만, **그 감소의340명·84.6%는 의도적으로 만든 희소 후보 함정에서 발생했다.** 전체25.5% 감소를 실제 응급의료나 임의의 모든 조건에 대한 개선율로 제시하지 않는다. R2 대비 목적값은59사례 우수·24동률·1열세다. R1 기준해보다 나빠지지 않는 보장은 R2보다 항상 좋다는 보장이 아니다.

같은 예산의 C1과 비교하면 다음과 같다. 우수·동률·열세는 두 목적을 순서대로 비교한 결과다.

| 10ms | 30 | 49 | 5 |

짧은 제한의 큰 문제에서는 H1이 경쟁력을 보였다. 충분한 계산시간을 준 C1보다 전반적으로 좋다는 결론은 아니다. 복수 자원과 조밀한 후보 조건에서 C1이 더 나은 이동시간 목적을 얻는 경우가 많았다.

## 더 많이 배정하는 것과 더 빨리 도착하는 것은 다르다

R1과 H1 50ms에 모두 배정된3,069명의 이동시간은 H1에서 평균1.94분 길었다. H1만 배정된519명, R1만 배정된117명을 구분하면 순증402명이다. 따라서 미배정 감소를 모든 환자의 이동시간 단축으로 설명할 수 없다.

C1 50ms와 공통 배정된3,494명은 H1에서 평균0.50분 짧았다. 하지만 H1만 배정된94명, C1만 배정된98명이 있어 H1의 전체 미배정은4명 더 많았다. 집계한 가중 목적과 환자 인원 수의 차이를 함께 보여야 한다.

## 최적성·시간·자료의 범위

- 84사례 중61개는 C1이 두 목적의 최적성을 증명했고,12개는 후보가 없는 자명한 문제다. 이73개 중 H1 50ms가 같은 목적값을 얻은 것은51개다.
- 위51개에는 희소 후보 함정·여유 자원·자원 전무의36개 사례가 포함된다. 나머지 어려운 최적 기준37개에서는15개가 일치했다. 특정 복수 자원 사례에서는 1차 목적이 같아도 2차 목적 차이가74.68%였다. 모든 조건에서 최적값에 가깝다는 표현은 부적절하다.
- C1이 최적을 증명하지 못한11개 사례는 관측한 규칙 중 최선값과의 차이만 계산한다. H1은 항상 실행 가능 휴리스틱으로 표시하며 최적 증명을 주장하지 않는다.
- 시간 예산은 현재 입력과 기준해를 만든 뒤의 추가 탐색을 협력적으로 제한한다. 전처리·최종 검증·기록을 포함한 강제 실행시간 상한이 아니다. H1 50ms의 전체 실행은12/84회50ms를 넘었고 최장은52.69ms였다.
- 전체 중앙값에는 쉬운 대조군이 포함된다. 경합이 있는 네 유형만 보면 중앙값은 H1 31.69ms, C1 34.11ms였다. CP-SAT 최초 import 시간은 따로 기록하고 정책 측정 전에 로드를 완료했다.
- 현재 관측이 완전하다는 합성 배정 실험이다. 병원 문의시간·병원 응답 부담·전체 선정시간·실제 도착·치료성과·정보 누락의 효과는 이 결과로 검증하지 않는다.

## 검증과 재현

신규 H1 27개·실험21개·독립 감사31개를 포함한 관련 회귀186개가 통과했다. 원시 스냅샷의 수용 후보·자원·배정·목적·분모·공통 환자·증명·요약을 별도 코드가 다시 계산했다. 672분기의 자원·후보 제약 위반은0건이며, 모든 H1 분기는 R1 기준해보다 목적값이 나빠지지 않았다. 실행기와 분리된 두 차례 감사가 잠금·소스 일치까지 통과했다.

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) '.solver_deps'
python scripts/test_suites.py python test_heuristic_assignment test_allocation_stress test_allocation_stress_audit
python -m simulation.allocation_stress_audit simulation_results/allocation_stress_validation_20261014.json --lock-file config/allocation_stress_lock_20261014.json
```

같은 잠금·소스로 계산을 재현하려면 기존 결과를 덮어쓰지 않는 별도 출력 경로를 사용한다.

```powershell
python -m simulation.allocation_stress_experiment --phase validation --lock-file config/allocation_stress_lock_20261014.json --output simulation_results/allocation_stress_reproduction.json
```

이 명령은 같은 평가의 재현이며 새 독립 검증이 아니다. 이미 본13101–13104를 다음 개선의 미사용 검증으로 재사용하지 않는다. 새 개선에는 새로운 개발·검증 seed와 별도 잠금을 사용한다.

## 다음 개선 대상

복수 자원의 여러 방해 환자를 함께 옮기는 탐색과 이동시간 개선을 보강하고, 충분한 시간을 준 CP-SAT 기준과의 차이를 다시 측정한다. 이후 H1을 별도 전체 이송 실험에 연결해 미배정 감소와 공통 환자 지연·재배정 횟수·문의량을 함께 검증한다. 현재 지도·운영 서버에 H1을 켠 상태는 아니다. 정보 누락·갱신 지연과 온라인 자원 변화도 후속 검증 대상이다.
