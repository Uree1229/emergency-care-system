# Codex 알고리즘 개선 연쇄 실험 검토 (2026-10-20)

검토 범위: 2026-10-15~10-20의 실험 문서 22개(`docs/*_EXPERIMENT.md`), 잠금 파일과 결과 요약, 진행 중이던 `offer_reserve`의 잠금(`simulation/offer_reserve.lock.json`).
코드와 결과는 수정하지 않았다. 대안 실험은 [EAT 문의 정책 실험](EAT_INQUIRY_EXPERIMENT.md)에 따로 정리했다.

## 한 줄 결론

절차의 엄격함(사전 고정·미사용 seed·원문 보존·독립 감사)은 훌륭하다. 그러나 **10-16 이후 개선 대상과 비교 기준이 운영 기본 `fixed_3`에서 멀어졌다.** 직전 후보 대비 몇 건씩 고치는 방식이 한계에 도달했다. 10-20 하루에 세 후보가 연속으로 개발 기준을 통과하지 못했다.

## 흐름

| 날짜 | 실험 | 개선 대상(요약) | 결과 |
|---|---|---|---|
| 10-15 | H1 전체 이송 → 정보 누락 → 기회 보호 → 재확인 → C1 안정화 → 전체 대기 → 기존 정보 → 병상 중단 회복 | 배정(H1/C1)과 정보 지연 | 일부 개선. 비교 기준은 매번 직전 분기 |
| 10-16 | 문의+배정 결합(V4) → 희소 지연 → 기한 안전 | 문의 정책 V4 도입 | V4는 V3 대비 12건 × 15초 단축. **같은 문서에서 고정3이 V3·V4보다 유리** |
| 10-17 | 부족 재확인 → 협력형 재확인 → 처리 지원 재확인 | V4 위 재확인 규칙 | 부분 개선, 채택 보류 반복 |
| 10-18 | 재문의 순회(frontier) → 회복 기억 → 회복 순위(normal) | 재문의 순서 | frontier·normal은 직전 대비 통과 |
| 10-20 | probe_guard → public_offer → offer_reserve | normal 위 예외 규칙 | **세 후보 모두 개발 기준 미통과**(offer_reserve `validation_allowed: false`, `OFFER_RESERVE_EXPERIMENT.md`) |

OFFER_RESERVE는 연쇄의 전형적인 모습을 보여 준다.
- **원래 반례 회복:** 직전 public_offer의 22분 지연 반례를 "한 명분 여유" 규칙으로 고쳤다(세 시드 22·18·19분 회복).
- **같은 지연 재현:** 함께 추가한 새 경계(더 큰 수요의 후발 환자)에서 같은 22분 지연이 다시 나왔다.
- **배정기 시간 초과 잡음:** 새 규칙이 한 번도 작동하지 않은 `out_of_order` 환경에서 C1의 50ms 예산 대체(FALLBACK)로 +35환자·분이 생겼고, 이 차이가 전체 결과에 섞였다.

## 잘한 점

- 개발·잠금·미사용 seed 검증의 분리, seed 노출 검사, 결과 덮어쓰기 금지가 일관된다.
- 실패와 반례를 숨기지 않고 문서에 남긴다. "직전 대비 개선 ≠ 모든 기준 대비 우월"을 반복해 명시했다.
- 미래 정보를 정책 입력에 넣지 않았다. 원문 감사로 구현 오류를 여러 차례 찾아냈다.

## 문제점

### 1. 비교 기준이 표류했고, 고정3 대비 누적 성과가 불리하거나 불분명하다

- `JOINT_POLICY_EXPERIMENT.md`
  - 전체 이송 입력에서는 고정3이 V3·V4보다 유리했다. V3는 고정3 대비 43건 단축·240건 악화였다.
  - 유형 균등 제한 처치 평균은 고정3 12.45분, V3 12.64분, V4 12.63분이었다.
  - 그런데 이후 실험은 **V4 기반 위에서** 진행됐다(SCARCE_DELAY·SHORTAGE_PROBE의 기준 "기존 보호 V4").
- `RETRY_DISPATCH_EXPERIMENT.md`의 새 검증에서, 직전 대비 채택된 frontier를 고정3 참고 기준과 비교한 결과는 다음과 같다.
  - 처치 단축 224명, 악화 322명이었다.
  - 기존 처치 성공 상실 18명, 새 성공 25명이었다.
  - 순대기는 −37환자·분으로 거의 같았다.
  - 대기가 늘어난 환경은 219개였다.
- 정리하면 직전 후보보다는 계속 나아졌지만, **운영 기본보다 낫다는 근거는 아직 없다.** 발표에서 "개선"이라고 말하려면 비교 대상이 고정3이어야 한다.

### 2. 채택 기준이 불확실성 아래에서 원리적으로 달성하기 어렵다

- 주 기준은 "개인별 처치·도착 악화 0건, 환경별 대기 증가 0건"이다.
- 현재 정보로 판단을 바꾸는 정책은, 관측할 수 없는 미래(늦게 등록되는 환자, 병상 중단)가 있는 사례에서 **반드시 누군가는 손해를 본다.**
  - 예: `PUBLIC_OFFER`에서 조기 확정은 11건을 빠르게 했지만, 뒤늦게 온 단독 후보 환자가 22분 늦어졌다.
- 그래서 평균이 좋아져도 통과할 수 없다. 10-20의 세 후보 연속 미통과는 후보의 질보다 기준의 구조 탓이 크다.
- 의사결정 이론에서 쓰는 기준은 다음과 같다.
  - 평균 개선(신뢰구간 포함)
  - 실패 비증가
  - 꼬리 위험 상한(p90·하위 10% 평균, 개인 최대 악화 한도)

### 3. 평가 환경이 반례 수집형으로 커져 대표성이 없다

- 환경 유형이 95 → 109 → 121 → 129 → 135 → 141 → 149개로 늘었다.
  - 새 후보마다 그 후보를 깨뜨리는 "경계" 유형을 추가하는 방식이다.
  - 모든 유형이 같은 가중치를 갖는다.
- 결과는 "현실에서 얼마나 자주 생기는 상황인가"가 아니라 "얼마나 많은 함정 유형을 만들었나"에 좌우된다.
- seed를 바꿔도 같은 함정 구조가 반복되므로 독립 표본도 아니다(문서도 이를 인정한다).

### 4. 효과 크기가 모형의 해상도보다 작다

- 예: V4는 V3 대비 12건 × 15초, 기한 안전은 6건 × 1분, 회복 순위는 검증 12건이었다.
- 모든 처리시간·회신·이동이 합성 가정인 환경에서 15초~1분 차이는 가정 하나만 바꿔도 뒤집힐 수 있다.

### 5. 복잡도가 운영 반영과 설명을 막는다

- 10-15 이후 결과물 규모는 다음과 같다.
  - 새 시뮬레이션 코드 약 33,000줄, 그중 감사 코드 약 17,000줄
  - 테스트 파일 94개, 잠금 24개
  - 결과·빌드 산출물 약 8.4GB
- 엔진이 서로를 감싸는 연쇄(frontier → normal → probe_guard → public_offer → offer_reserve)라, 한 규칙의 효과를 설명하려면 앞선 규칙 전체를 알아야 한다.
- 운영 서버에 반영된 것은 없고, 팀원이 발표에서 설명하기도 어렵다.

### 6. 측정 잡음: C1의 50ms 벽시계 예산

- 같은 입력에서도 C1이 `OPTIMAL` 대신 `FALLBACK, budget_exhausted_before_stage_one`을 내는 경우가 있다(PROBE_GUARD, PUBLIC_OFFER, OFFER_RESERVE에 기록). OFFER_RESERVE에서는 이 경로 하나가 P03 처치를 10분 → 45분으로 바꿨고, C1과 H1 결과의 차이 전부(+35환자·분)를 만들었다.
- 정책 차이와 계산 시간 차이가 섞인다.
- OR-Tools의 결정적 제한(`max_deterministic_time`)이나 작업 수 제한으로 바꾸면 재현성이 생긴다.

### 7. 교수님이 보는 핵심(P1 후보 탐색·P2 병렬 문의)과 거리가 멀어졌다

- 최근 실험은 "부족 보고 뒤 선택적 재문의 억제", "공개 부족 후보 때문의 조기 확정 승격"처럼 매우 특수한 상호작용을 다룬다.
- 발표의 질문인 "몇 곳에, 어떤 순서로, 언제 더 물을까"에 대한 답은 오히려 흐려졌다.

## 권고

1. **연쇄를 동결한다.** 지금까지의 결과는 "반례 목록과 안전성 검사 자료"로 정리한다. 새 규칙을 덧붙이지 않는다.
2. **비교 기준을 고정3(운영 기본)과 V3로 고정한다.** 모든 새 후보는 이 둘과 같은 입력에서 비교한다.
3. **평가를 분포 기반으로 바꾼다.**
   - 공개 통계로 범위를 맞춘 무작위 환경에서 평균·신뢰구간·꼬리 위험을 보고한다.
   - 반례 유형은 별도 스트레스 시험으로만 쓴다.
4. **규칙 누적 대신 원리 기반 정책 하나와 소수의 파라미터를 쓴다.** 개발 seed에서 파라미터를 고르고, 미사용 seed에서 한 번 검증한다.
5. **완전정보 하한을 함께 제시해 "개선 여지"를 수치로 보인다.**
6. C1을 계속 쓸 경우 결정적 시간 제한으로 바꾼다.

이 권고대로 진행한 대안 실험이 [EAT 문의 정책 실험](EAT_INQUIRY_EXPERIMENT.md)이다.

- **설계:** 확률 모형 하나와 문의비용 λ 하나를 개발 seed에서 고르고, 처음 쓰는 seed 448개로 한 번 검증했다.
- **결과:** 기대 비용이 다음과 같이 낮았다(환자당 ΔJ, 95% 구간 상한 < 0).
  - 고정3 대비 −20.4초 [−32.0, −9.1]
  - V3 대비 −65.6초
  - V4 대비 −65.0초
- **문의 수:** 고정3보다 20% 적었다.
- **실패 수:** 고정3과 같았다. 실패 비용을 바꾼 민감도와 기존 8유형에서는 약점도 함께 보고했다.
- **2차 확정 대기 규칙:** 같은 절차로 진행했다.
  - 고정3에 붙이면 −12.5초/환자로 뚜렷했다.
  - EAT에는 −2.4초로 판정만 통과했고, 실무 의미는 작다고 기록했다.
- **3차 공개 병상 신호(EAT-P):** 개발의 −11.4초가 검증에서 +1.4초로 사라져 미채택했다. 완전 수용 정보의 상한도 유의하지 않았다. 같은 절차가 개선이 없는 후보를 걸러 낸 사례로 남겼다.
- **4차 '확인 중' 신호(EAT-C):** 정보 가치 상한부터 쟀다. 무응답 정보는 묻기 전에 알면 −28.8초였지만, 사후 정보인 확인 중은 완전해도 이득이 없어 미채택했다.
  - 서버 장부가 확인 중을 첫 회신으로 기록해 V3가 +11.6초 나빠지는 설계 위험을 찾았다.
- **5차 응대 가능 상태 표시(EAT-R):** 정확한 표시도 J 개선이 작았고(−2.6초), 30% 틀린 표시를 믿으면 +74.7초여서 미채택했다.
  - 3~5차를 통틀어, 병원 추가 정보는 J보다 문의 부담 감소에 쓸모가 있었다.
- **6차 같은 J에서 문의 줄이기:** EAT의 문의비용 λ를 15에서 45로 올리자 J는 비열등했고(−5.6초 [−15.5, +4.3]), 문의·검토 업무는 8% 줄었다. 판정을 통과해 권장 설정으로 기록했다.
  - J–문의 교환 곡선에서 고정3·V3는 EAT 분기에 지배됐다.
- **7차 여러 환자 동시 계획:** 병원당 동시 문의 상한은 J를 줄이지 못해 미채택했다.
  - 용량 진단에서 병원 처리 인원이 무한이면 −77.5초, 문의 담당 2명이면 −57.0초였다.
  - 동시 다발 손실은 정책보다 병원 처리 용량 문제로 확인됐다.
  - 같은 표본에서 λ45는 λ15보다 +11.9초로, 6차 판정이 경계 통과였음을 함께 기록했다.
- **8차 병원 문의 처리 용량 설계:** 서버가 병원의 미회신 문의 2건에서 보조 담당을 부르는 규칙을 검증했다.
  - 60초 안에 합류하면 −34.3초/환자 [−42.5, −26.4]로, 상시 2명 효과의 72.0%를 얻었다(사전 기준 75%는 미달).
  - 합류 속도가 핵심이었다(30초 약 85%, 2분 약 47%).
  - 용량이 늘수록 EAT의 고정3 대비 이점이 줄고, 무한 용량에서는 고정3이 13.9초 나았다. 정책과 용량은 서로 대체한다.
- **9차 취소 즉시 검토 중단:** 이미 다른 병원으로 확정된 환자의 문의를 병원이 30초 뒤 절반만 멈춰도 −4.5초/환자 [−8.2, −1.2]였다(사전 지정 보수적 가정, 판정 통과).
  - 즉시·전원 중단이면 −20.6초로, 상시 2명 효과의 36%를 인력 추가 없이 얻는다.
  - 회수한 시간의 절반 이상은 기다리는 문의가 없어 쓰이지 않았다.
- **10차 병원 문의함 정렬:** 서버가 다른 병원에서 이미 검토 중인 환자를 뒤로 미루는 순서를 정하면, 검토자가 절반만 따라도 −7.0초/환자 [−12.7, −1.5](고정3 −10.6초)였다.
  - 인력 추가 없는 순수 알고리즘 개선이며, 병원 화면의 열람 기록이 필요하다.
  - 순서를 바꾸면 늦어지는 환자도 생긴다(개선 184명, 악화 126명). 이득은 주로 실패 감소에서 나온다.
- **11차 통합 패키지:** 세부 순위(위험 환자 먼저)는 효과가 없었다(+0.2초).
  - EAT + 문의함 정렬 + 취소 중단 + 보조 호출을 모두 쓰면 현행 고정3보다 −70.0초/환자 [−84.3, −55.5]다(미사용 seed 검증).
  - 서버 알고리즘 몫이 약 31초, 병원 운영 몫이 약 39초다.
- **12차 다수 사상자(12~20명 동시):** EAT가 가까운 10곳까지 계획에 넣으면 −12.3초/환자 [−24.7, −0.1], 평소에는 비열등(−1.2초)이었다.
  - 다수 사상자에서 고정3은 EAT보다 +143.5초, 실패가 43% 많았다.
  - 병원 쪽 패키지와 함께 쓰면 범위 확대의 이득이 사라졌다(+9.4초, 비유의). EAT의 대기 모형이 처리 용량을 알아야 한다.
- **13차 처리 용량을 아는 EAT(EAT-K):** 대기 시간을 병원별 지금 처리 인원으로 나누자 패키지 운영의 다수 사상자에서도 −16.1초/환자 [−27.0, −5.2]가 유지됐다.
  - 현행 운영 다수 사상자 −26.1초, 평소에는 비열등이었다.
  - 12차 EAT-W를 대체한다.
- **14차 EAT-K 재조정:** λ0·30, 동시 6곳 모두 13차 설정(λ15·동시 4곳)보다 낫지 않아 미채택했다(검증 미실행).
- **15차 열람 기록으로 처리 인원 추정:** 처리 인원 = max(평소 인원, 검토 중 문의 수)로 바꿔도 13차와 비열등했다(다수·패키지 −0.1초 [−3.9, +3.7]).
  - 병원 화면에 필요한 정보가 평소 인원 등록과 열람 기록 두 가지로 줄었다.
- **16차 다수 사상자 선제 호출:** 120초 안에 10명 이상 등록되면 모든 병원의 보조 담당을 바로 부르자 다수 사상자에서 −15.0초/환자 [−21.3, −9.0]였다.
  - 평소에는 작동하지 않았다. 비용은 보조 근무 +55초/환자다.
- **17차 최종 통합 검증:** 처음 쓰는 seed로 권장 구성 전체를 한 번 실행했다.
  - 현행 고정3보다 보통 상황 −70.8초/환자 [−85.3, −57.2], 다수 사상자 −277.2초 [−304.4, −250.6]이다.
  - 다수 사상자의 선정 실패는 57% 줄었다.
  - 직전 후보가 아니라 운영 기본(고정3)을 기준으로, 분포 기반 미사용 seed에서 누적 효과를 확인했다. 이 검토의 권고 2·3을 따른 결과다.
- **18차 분산 정렬 공정성 보완:** 대기 상한 120초는 평균을 지켰지만 새 실패 감소(−8명)가 유의하지 않아 미채택했다.
  - 30초 상한은 새 실패를 절반으로 줄이지만 평균이 4~7초 나빠졌다. 공정성과 평균의 교환은 운영 정책의 선택으로 남겼다.
  - 이 검토가 지적한 '개인별 악화 0건' 기준 대신, 평균과 꼬리(새 실패)를 함께 보고했다.
- **19차 응답 없이 닫힌 문의 즉시 종료:** 다수 사상자 −9.8초 [−16.1, −3.8]로 유의했지만, 주 판정인 혼합이 −3.5초 [−7.4, +0.2]라 사전 기준대로 미채택했다.
  - 결과를 보고 기준을 바꾸지 않았다. 구현 후보로만 남겼다.
- **20차 회신 즉시 재판단:** 단독 효과는 유의하지 않아 미채택했다(혼합 −1.0초, 다수 −3.1초).
  - 19차와 함께 쓴 참고 항목이 검증 혼합 −7.8초로 유의했지만, 사후에 판정 대상을 바꾸지 않고 새 seed의 확인 실험(21차)으로 넘겼다.
- **21차 조합 확인 실험:** 처음 쓰는 seed에서 두 규칙 조합이 17차 구성 대비 혼합 −8.1초 [−13.3, −2.9], 다수 −12.8초 [−20.1, −5.7]로 채택 기준을 통과했다.
  - 새 최종 구성은 현행 고정3 대비 혼합 −77.3초, 다수 사상자 −294.1초다.
- **22차 확정 대기 재적용:** 2차에서 1차 EAT에는 작았던 확정 대기(최대 120초)가 21차 최종 구성 위에서는 혼합 −6.3초 [−9.8, −3.1], 다수 −10.2초 [−13.6, −6.9]로 채택 기준을 통과했다.
  - 개발의 혼합 효과(−1.2초)는 검증보다 작았다. 과대평가를 막으려고 개발+검증 합산 참고값(−4.4초)을 함께 적었다.
- **23차 보조 근무 줄이기:** 즉시 복귀는 보조 근무를 36% 줄였지만 다수 사상자 J가 +3.2초 [+0.8, +5.8]로 비열등 여유를 넘어 미채택했다.
  - 개발에서 허용선에 가까운 후보를 고른 선택 규칙 탓에 검증 손해가 커졌다(승자의 저주). 결과를 보고 다른 후보로 바꾸지 않았다.
- **24차 확정 대기 개선:** 처리 용량 반영 + 상한 180초가 혼합 −2.7초, 다수 +2.8초 [−1.0, +7.0]로 다수 사상자 비열등에 실패해 미채택했다.
  - 개발과 검증의 방향이 반대였다. 작은 효과를 좇는 반복 실험에서는 이런 뒤집힘이 흔하므로, 단일 검증 통과만으로 채택하는 기준을 유지했다.
- **25차 마감을 아는 EAT-K:** 기존 seed 일부로 한 탐색에서는 유망했지만(−2.5·−5.1초), 새 seed의 개발·검증에서는 효과가 없어 미채택했다(혼합 +0.7, 다수 −1.1초).
  - 탐색은 후보를 고르는 데만 쓰고, 판정은 사전 고정한 새 seed 개발·검증으로만 했다. 이 검토가 권고한 절차가 착시를 걸러 냈다.
- **26차 최종 구성 확인 실험:** 처음 쓰는 seed로 한 번 실행해 확정 대기의 몫(혼합 −10.1, 다수 −12.8초)을 다시 확인했다.
  - 최종 구성은 현행 고정3 대비 혼합 −79.3초, 다수 사상자 −306.0초다. 보조 복귀 전 60초는 J를 지키며 보조 근무를 19% 줄여 선택지로 확인했다.
- **27차 보조 호출 2명 병원까지 확대:** 혼합 이득(−2~−3초)은 진단·개발 두 표본에서 일관됐지만, 다수 사상자 효과가 표본마다 부호가 바뀌어 개발 단계에서 멈췄다(검증 미실행).
- **28차 선제 호출 기준 낮추기:** 검증 혼합 −2.1초 [−4.8, +0.3]로 상한이 0을 조금 넘어 미채택했다. 결과를 보고 판정 기준을 바꾸지 않았다.
  - 23~28차가 연속 미채택이다. 이 검토가 경고한 '작은 효과를 좇는 반복 탐색'의 단계에 들어섰으므로, 추가 개선 탐색보다 가정 민감도 점검을 권한다.
- **29차 여러 관점 진단 + 부하 적응 EAT-K:** 진단에서 가장 좋아 보인 후보(−9.2초)가 개발 −5.7, 검증 −2.2초로 줄어 미채택했다.
  - 진단 → 개발 → 검증마다 효과가 줄어드는 것은 '여러 후보 중 최고 고르기'의 우연 몫이다. 이후 탐색은 후보 수를 줄이고 표본을 키워야 한다.
- **30차 병원 운영 지렛대·강건성 확인:** 처음 쓰는 seed로, 검토 시간 20% 단축(−27.6·−55.9초)이 알고리즘 개선보다 훨씬 큰 지렛대임을 확인했다. 나쁜 환경 3종에서도 최종 구성은 현행보다 크게 나았다.
  - 이 검토가 권한 '가정 민감도 점검'을 수행한 결과다. 선택 단계 없이 한 번에 판정해 우연 몫이 끼어들 여지를 없앴다.
- **31차 빠른 거절 확인:** 거절의 절반이 15초 안에 끝나는 업무 흐름이면 혼합 −11.6초, 다수 −29.0초로 확인했다. 진단(−20.9초)보다 작아졌지만 유의했다.
  - 진단의 부수 관찰('EAT가 두 배 이득')은 확인 실험에서 재현되지 않아 문서에서 바로잡았다.
- **32차 중증도 관점:** 중증 환자 적극 문의는 다수 사상자 중증 환자를 −18.8초 앞당겼지만, 사전 기준(보통 상황 중증 상한·다수 전체 상한)을 넘지 못해 미채택했다.
  - 묶음별 판정은 표본이 작은 묶음(보통 상황 중증 273명)에서 구간이 넓어진다. 다음에는 묶음별 표본 크기를 미리 계산해 판정 기준을 정해야 한다.
- **33차 시스템 전체 권장안 확인:** 서버 최종 구성 + 병원 권장안(빠른 거절·취소 즉시·보조 30초 합류)이 현행 대비 혼합 −82.5초, 다수 −385.4초로 확인됐다.
  - 개별로 확인한 수단들을 합친 구성을 다시 새 seed로 확인해, 수단 사이의 상호작용까지 포함한 최종 숫자를 얻었다.
- **34차 중증 환자 적극 문의 확인:** 32차 후보를 다수 사상자 표본 2배로 다시 확인해 채택 기준을 통과했다(다수 중증 −36.6초, 전체 −4.4초).
  - 32차의 판정 미달이 효과 부재가 아니라 표본 부족이었음을, 판정 기준을 바꾸지 않고 새 seed·큰 표본으로 확인했다.
- **35차 문의함 중증도 정렬:** 엄격한 중증 우선(서버 현재 정렬)과 중증만 우선 모두 다수 사상자 전체 평균을 나쁘게 해 개발 단계에서 멈췄다. 중증만 우선이 경증 손해를 3분의 1로 줄이는 더 나은 균형이었다.
- **36차 28차 후보 재확인:** 표본을 두 배로 늘리자 효과가 −0.7초로 줄어 미채택했다. 34차처럼 '표본 부족' 때문인지, 이번처럼 '애초에 효과가 작은지'는 큰 표본으로만 가려진다.
  - 두 번째 기회를 준 시험은 우연한 통과 위험이 커지므로, 사전에 그 사실을 적고 판정 기준은 바꾸지 않았다.
- **37차 지역형 강건성:** 농어촌형(병원 4곳)·도시형 모두에서 최종 구성이 현행보다 확실히 나았다. 농어촌 평소에는 EAT가 고정3보다 약간 불리한 약점을 찾았다.
- **38차 병원이 적은 지역 적응 규칙:** 그 약점을 겨냥했지만 효과가 없어 미채택했다. 더 큰 표본에서 약점 자체가 +1.7초로 줄어, 37차의 관찰이 잡음에 가까웠음을 확인했다.
- **39차 최종 권장안 확인:** 서버 구성 + 중증 적극 문의 + 병원 권장안이 현행 대비 혼합 −107.2초, 다수 −382.3초로 확인됐다. 중증 적극 문의의 몫(중증 −15.0·−26.3초, 전체 그대로)도 다시 재현됐다.
- **40차 수용 예측 가능 환경:** 알고리즘 개선이 막힌 이유가 '수용 여부를 예측할 단서가 없는 시뮬레이터'였음을 확인했다. 질환 유형 × 병원 적합도로 수용이 예측 가능하면, 유형을 아는 EAT가 혼합 −8.8초, 다수 −33.4초를 더 줄였다.
  - 시뮬레이터의 가정이 개선 여지를 정한다. 실제 수용 기록으로 예측 가능성을 재는 것이 다음 단계다.
- **41차 스스로 학습:** 등록 정보 없이 지난 기록(병원당 회신 80건)으로 배워도 등록 정보만큼 효과가 났다(혼합 −13.4초, 다수 −42.4초).
  - 과거 기록의 참 확률은 생성기의 숨은 값을 같은 난수로 복원해 만들고, 복원이 정확함을 잠재 회신 단위로 검증했다.
