# 두 명 공동 평가의 관측 경계 병원 교체 보호

상태: 별도 후보 `eat_cohort_pairshield_l15_f`의 훈련 360환경·의미 감사·독립 집계 대조를 마쳤다. 원래 Stoploss의 성공 환자를 두 자료 모두 전부 보존하면서 선정 대기를 기존 24초·추가 58초 줄였다. 관측된 훈련 자료의 직접 목표는 충족했지만 더 강한 승격 조건은 미달했으므로 채택하지 않는다. 고정된 부모 결과와 이번 소스·판정 기준은 바꾸지 않는다.

## 동기와 단일 변경

첫 문의 대상 두 명인 구간을 확장한 Pairscope는 공식·독립 집계에서 추가 415명의 기존 성공을 유지하고 Stoploss 대비 선정 대기를 58초 줄였다. 그러나 기존 827명에서는 성공 1명을 잃고 대기가 63초 늘었다. 따라서 요청한 두 자료의 성공 보존·대기 감소를 모두 충족하지 못했다.

이미 관측한 훈련 자료의 네 사례만 제한적으로 조사했다. 성공 손실 사례에서는 기준 행이 문의하던 병원을 예상 대기 337초가 남은 H=300초를 넘는다는 이유로 초기 응답 질량 0으로 평가했고, 새 선택은 이를 다른 병원으로 교체했다. 원래 기준 실행에서는 그 병원에서 205초에 선정됐었다. 다른 지연 사례에서는 반대로 새로 추가한 병원의 예상 대기가 H를 넘고 초기 응답 질량이 0이었다. 이는 예측값과 관측 결과의 차이를 보여주는 기록이며 인과적 설명이나 수정안의 복구 효과를 증명하지 않는다.

평균 대기시각을 확정적 지연으로 쓰는 현재 모형에서 `예상 대기 ≥ H`로 인해 CDF가 0이 되는 것은 실제 수용 가능성이 0이라는 뜻이 아니다. 이번 후보는 이 경계에서의 **초기 병원 소속 변경**만 보수적으로 제한한다. 점수 모형·가중치·확률 허용 오차·판정 기준을 조정하지 않는다. 환자 ID·시드·관측 성공 여부에 따른 규칙을 넣지 않는다.

## 보호 규칙

부모가 새로 평가한 두 명 구간에만 적용한다. 원래 Stoploss가 현재 공개 입력에서 선택한 행을 기준으로 각 현재 환자의 초기 문의 병원 목록과 초기 CDF를 비교한다.

1. 기준 행에서 빠지는 병원이 `queued`이고 그 행의 예상 대기가 환자별 남은 H 이상이며 저장된 초기 확률 질량이 전부 정확히 0이면 해당 교체 행을 제외한다.
2. 새로 들어오는 병원이 후보 행에서 같은 조건이면 그 행을 제외한다.
3. 기준과 후보에 공통으로 남는 병원은 이 보호로 막지 않는다. 같은 병원이 대기 변화로 0/양의 질량 경계를 넘는 경우도 소속이 바뀌지 않았으므로 허용한다.

두 방향은 하나의 관측 경계 소속 보호 법칙이다. 새 확률 임계값을 맞추지 않고 기존의 환자별 H와 저장된 질량의 정확한 0만 사용한다. 기준 행은 소속 변화가 없어 항상 허용된다. 대기가 H 미만인데 수치적으로 작은 질량이 0이 된 경우는 이 구조적 경계로 분류하지 않는다.

모든 원래 행과 부모 제안을 그대로 보존한다. 기존 전체 환자 확률 보호를 통과한 행과 새 소속 보호를 통과한 행의 교집합만 선택 영역으로 사용한다. 이 명시적 부분 영역에서 기존 대기 우선 선택·우선순위 동률·Stoploss 기준 행·원래 행 순서를 유지한다. 원래 JOINT 타당성을 다시 분류하거나 후보 행을 증거에서 누락하지 않는다.

이미 활성화되던 부모 경로, 한 명의 tail이 있는 비활성 경로와 단독 후속 H 처리는 그대로다. 현재 두 명의 문의만 적용하고 모든 잔여 대기 환자의 확률 보호·원점·버전·시간·FIFO·원자적 적용·A/H·동시 문의 4건·총 문의 10곳 제한을 유지한다. 이 보호가 실제 성공을 보장한다고 주장하지 않는다.

## 실행 전에 유지할 조건

부모 Pairscope에서 이미 잃은 환자도 보존 대상에 포함한다. 성공 식별자 기준은 부모 Pairscope가 아니라 원래 Stoploss다. 성공 수만 같고 기존 성공을 다른 성공으로 바꾸면 통과하지 못한다. 기존·추가 자료의 손실이나 대기 증가를 합쳐 가리지 않는다.

| 이미 관측한 훈련 자료 | Stoploss 성공 / 선정 대기 | 통과 조건 |
|---|---:|---|
| 기존 827명 | 692 / 113,429초 | 성공 692 이상·대기 113,296초 이하·Stoploss 성공 손실 0명·Stoploss보다 대기 엄격 감소 |
| 추가 415명 | 363 / 54,627초 | 성공 364 이상·대기 53,498초 미만·Stoploss 성공 손실 0명·Stoploss보다 대기 엄격 감소 |

두 자료 존재를 포함한 훈련 조건 9개를 유지한다. 직접 요청한 기존 성공 보존·자료별 대기 감소와 더 강한 전체 승격 조건의 충족 여부를 구분해 보고한다. 실패 선정 대기는 300초, 실패 도착 비용은 1,800초다. 성공 식별자·선정 대기·도착·개인 최대 지연·혼합/스트레스·부모 및 Fullmenu 대비를 각각 남긴다.

훈련 통과 뒤에만 새 개발 120환경을 실행한다. Stoploss·CS·Hedge 각각 실패 비증가와 대기 엄격 감소, Stoploss 성공 손실 0명으로 7개 조건을 적용한다. 새 개발 통과 뒤에만 별도 검증 368환경을 실행한다. 같은 점 조건에 세 비교군 각각 실패 차이 95% 상한 0 이하·대기 차이 95% 상한 0 미만을 더해 13개 조건을 적용한다. 시나리오 단위 짝 부트스트랩 10,000회이며 지표별 주변 구간으로, 전체 조건의 공동 95% 보장은 아니다.

부모의 봉인·보존·새 소스 검사·고정과 입력 명세를 먼저 완료한다. 부모 602개에 새 16개를 더한 전체 소스는 618개, 비교군은 23개·8,280분기, 새 개발·검증은 24개 정책이며 최대 새 실행은 12,072분기다. 새 후보의 훈련 360분기는 각각 한 번 실행한다. 전체 원문 저장 뒤 각 새 원문의 의미 감사를 한 번 하고, 별도 집계·저장 증명 재사용·실패 단계 차단·최종 회계를 확인한다. 성능 재실행·결과 제외·사후 설정 변경을 하지 않는다.

부모 Pairscope 봉인은 `4ef0fb7d513dfbc41bec5a1b1af59ff39a2aa438ebee8e01149c499e9fc647fc`다. 보존 파일 해시는 `68d94ae99759dc113b04f1c0074f93fbff0350d0a69aff9f7cb64640d0bc5e58`이며 부모 소스 602개·엄격 참조 4,114개·압축 원문 5,280개를 보존했다. 부모의 성공 손실·대기 증가와 실패 판정을 그대로 승계한다.

새 집계·최종 검증기의 수치·판정 함수는 부모와 같은 법칙인지 독립 AST 비교와 합성 검사로 확인했다. 최종 검증기의 실제 `main` 사전 경로도 합성 메타데이터로 실행해 명칭 충돌과 23개 변조 거부를 검사했다. 실제 보존 파일과 618개 소스의 동일성은 읽어 확인했지만, 이 검사에서 동결·전체 검사·고정 예제 메타데이터와 일부 검증 함수는 명시적으로 대체했다. 따라서 실제 전체 소스 동결이나 아직 수행하지 않은 성능 실행의 증거로 표현하지 않는다. 원문 읽기·모형·성능 실행은 없었다.

별도 회계기도 실제 `run`의 초기 메타데이터 경로를 사전 확인했다. 실제 보존 파일·엄격 참조 4,114개·현재 소스 618개·준비된 비교군 23개/8,280분기와 봉인된 부모 보고서를 읽었다. 아직 만들지 않은 동결 기록·360개 인덱스·명세·파일 목록만 합성했고 시작 마커 생성 직전에 차단했다. 새 원문 읽기·해제·모형·성능 실행은 0회였으며 실제 원문 헤더나 아직 없는 동결 기록을 검증한 것으로 표현하지 않는다. `diagnosis/independent-accounting-metadata-prefreeze-review.json`에 증거를 보존한다.

현재 자료는 모두 이미 관측한 합성 훈련 자료이며 보호 규칙은 그 진단에 근거한 개발 가설이다. 새 데이터의 효과나 임상 우월성을 미리 주장하지 않는다. 이 보호는 공통 병원의 CDF 악화까지 막는 규칙도 아니다. 환자 우선순위는 미확인·기본값 4다. 이전 문서 참조 오류 10건과 빈 후보에 대한 기존 부모 감사기의 숫자 타입 경계는 원본·실패 이력과 함께 승계하며 단언을 완화하지 않는다. 운영 서버와 기본 `fixed_3`는 유지한다.

## 결과

전체 검사는 108모듈·2,000건 중 1,990건이 성공했다. 10건은 그대로 보존된 역사적 `docs/README.md` 참조 오류이며 실패 ID·추적·원래/현재 해시를 남겼다. 새 검사 131건은 모두 성공했고 실행 오류·건너뛰기는 0건이었다. 실제 소스 618개의 검사 전후 해시는 동일했다. 전체 검사를 모두 통과했다고 표현하지 않는다.

고정 예제에서 비교군 23개의 전체 원문 동등성과 새 후보 두 개의 독립 감사를 통과했다. 자연 예제는 새 보호 구간 1개·후보 행 1개·현재 환자 원점 2개·기준 행 1개를 검사했다. 원래 타당한 행이 기준 행 하나뿐이어서 제거·추가 거부와 실제 선택 변경은 0건이었다. 복수 행·거부·선택 변경은 별도 합성 검사로 확인했으며 이 자연 예제를 성능 개선의 증거로 삼지 않는다.

소스 618개와 입력 명세 848개를 고정했다. 훈련 360환경의 후보를 각각 한 번 실행해 모든 원문을 저장했다. 원문 의미 감사와 공식·독립 회계 대조를 마친 결과를 아래에 기록한다.
