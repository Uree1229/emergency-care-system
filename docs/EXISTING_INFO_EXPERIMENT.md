# 추가 자원 보고 없는 전체 대기 개선

2026-10-15 · 기존 정보 활용 실험 · 운영 서버에는 미적용

현재 수용 응답과 기존 자원 보고만으로 일부 불필요한 회신 대기를 줄이는 실험 분기를 구현했다. **이전의 기존 보고 재검토 분기보다 전체 대기 합이 60 환자·분, 1.10% 줄었다.** 다만 미래 병상 중단 대조 사례에서는 6건의 개별 악화가 남았다. 전체 단축을 모든 환자의 개선으로 해석하면 안 된다.

## 같은 검증 입력에서의 비교

검증 시드 28101~28106, 39개 환경, 4개 분기 총 936회 실행이다. 각 분기에 동일한 환자 실행 552건을 포함했다.

| 분기 | 기존 보고 수신 시 재검토 | 유효한 우월 수용 조기 검토 | 전체 대기 합, 환자·분 | 요청→처치 시작 합, 관찰 종료 제한 |
|---|---|---|---:|---:|
| `stable_responsive_C1` | 없음 | 없음 | 5,489 | 7,698 |
| `review_stable_C1` | 적용 | 없음 | 5,459 | 7,668 |
| `early_stable_C1` | 없음 | 적용 | 5,429 | 7,574 |
| `existing_info_C1` | 적용 | 적용 | 5,399 | 7,544 |

기존 안정화 C1 대비 전체 대기 합은 90 환자·분, 1.64% 감소했다. 이전에 이미 구현한 기존 보고 재검토 대비 새 규칙의 추가 효과는 60 환자·분, 1.10%다. 요청→처치 시작 합은 각각 154분과 124분 감소했다.

전체 대기는 탐색 대기, 병원 도착 후 처치 대기, 전원 대기의 합이며 이동은 제외한다. 미처치 환자는 관찰 종료까지 포함한다. 요청→처치 지표는 이동도 포함하고 미처치 환자를 관찰 종료로 제한한다. 미처치 인원은 모든 분기에서 30건으로 동일하다.

## 변경한 판단

기존에는 유효한 수용 응답이 있어도 다른 문의가 남아 있으면 첫 수용 후 최대 2분을 기다렸다. 새 규칙은 다음 조건이 모두 맞을 때 이 대기를 생략하고 기존 공동 배정 단계에 올린다.

1. 환자가 이미 등록됐고 탐색 중이며, 기존 배정 대기열에 들어 있지 않다.
2. 현재 유효한 환자별 수용 응답이 있고, 필요한 자원 수량이 기존 보고에서 신선하고 충분하다.
3. 해당 수용 병원은 정적으로 호환되는 모든 후보 중 현재 이동시간 기준 최단 후보다. 더 가까운 후보의 회신을 기다리는 경우에는 적용하지 않는다.
4. 그 병원의 보고된 여유 자원이 해당 병원을 이용할 수 있는 **현재 등록된 모든 탐색 환자**의 경합 수요를 감당한다. 아직 회신을 기다리는 환자도 포함한다.

조기 판단 뒤에도 기존 기회 보호, 동률 안정화 C1, 최종 실제 자원 충돌 검사를 그대로 거친다. 현재 유효한 응답은 만료 전에 사용할 수 있지만, 이미 만료한 응답은 사용할 수 없다. 미확인·노후 수량을 채워 넣거나 다른 환자의 병상을 예약하는 규칙은 추가하지 않았다.

새 판단의 입력은 분리된 현재 정보 스냅샷이다. 아직 오지 않은 회신의 도착 시각·무응답 여부, 미래 환자, 병상 해제 일정, 미래 병상 중단을 전달하지 않는다. C1의 현재 목적함수를 전체 이송 시간 최적화로 바꾼 것은 아니다.

## 추가 보고가 없다는 의미

모든 분기에서 새 자원 변화 보고를 끄며 독립 감사기가 해당 보고의 생성·수신 사건이 없는지 확인한다. 기존 초기 보고, 주기 피드, 기존 재확인 계약만 사용한다. 새 조기 판단은 자원 수량 재요청을 직접 수행하지 않는다.

| 검증 234사례 합산 | 기존 재검토 | 새 규칙 함께 적용 |
|---|---:|---:|
| 추가 자원 변화 보고 | 0 | 0 |
| 기존 주기 피드 생성 | 10,608 | 10,608 |
| 기존 주기 피드 수신 | 10,464 | 10,464 |
| 기존 초기 보고 수신 | 390 | 390 |
| 기존 자원 재확인 요청 | 751 | 739 |
| 전체 자원 보고 수신 | 11,509 | 11,497 |
| 환자별 수용 문의 | 1,142 | 1,148 |

조기 처치로 실제 점유 시각이 바뀌면 기존 주기 피드의 점유량 값도 달라질 수 있다. 동일한 보고 채널·주기·지연·누락·시각 계약을 비교한 것이며, 서로 다른 물리적 실행에 똑같은 미래 점유량을 제공한 것은 아니다. 환자 문의 6건 증가는 아래의 돌발 중단 반례에서 재이송이 발생한 비용이다.

## 환자별 이득과 악화

| 비교 기준 | 대기 단축 | 대기 증가 | 동일 | 최대 대기 증가 | 최대 처치 도달 증가 |
|---|---:|---:|---:|---:|---:|
| 기존 안정화 C1 | 36 | 6 | 510 | 4분 | 5분 |
| 기존 보고 재검토 | 30 | 6 | 516 | 4분 | 5분 |

악화 6건은 모두 `future_outage_after_early_offer` 유형이다. 예를 들어 시드 28101에서는 1분에 가까운 병원의 수용 응답을 받고 조기 출발하지만 2분에 예고되지 않은 병상 중단이 발생한다. 4분에 도착 후 수용이 불가능해 재이송하며 처치 시작은 기존 13분에서 18분으로 늦어진다. 나머지 5개 시드도 처치 도달이 5분 증가한다. 이 반례를 제외하거나 미래 중단을 미리 아는 예외 조건을 넣지 않았다.

현재 이동시간과 자원 수량의 우월성만으로 미래 조건 변화까지 보장할 수 없다. 이번 결과는 전체 합 단축과 개별 위험이 함께 존재한다는 결과다. 따라서 조기 판단을 운영 기본 동작으로 적용하거나 무악화 알고리즘으로 설명하지 않는다. 새 동작은 시뮬레이션 실험 분기에만 있다.

## 기존 유형에서 실제로 바뀐 범위

기존 31개 유형만 따로 보면 492건 환자 실행의 전체 대기 합은 **5,273→5,219 환자·분, 1.02% 감소**다. 기존 보고 재검토 대비 추가 감소는 **5,243→5,219, 24 환자·분**이다.

- `periodic_release_long_retry`: 같은 지연 피드를 받고 재검토하는 기존 개선이 30 환자·분 단축했다.
- `release_before_offer_expiry`: 새 조기 검토가 24 환자·분 단축했다.
- 나머지 29개 기존 유형은 결과가 같다. 대안 없는 병원은 224→224, 단일 병상 큐는 600→600, 재확인 8분 조건은 265→265다.

기존 31개 유형에서는 악화가 없지만 개선이 나타난 유형은 2개뿐이다. 새 유형 8개에서는 이득 60 환자·분에서 돌발 중단의 손해 24 환자·분을 뺀 순이득이 36 환자·분이다. 새 조기 규칙이 기존 재검토보다 줄인 전체 60분 중 24분은 기존 유형, 36분은 신규 유형에서 나왔다.

기존 정보만으로 병상이 다시 비었음을 확인할 수 없는 구간과 실제 병상 점유 대기는 남는다. 특히 앞선 P03 대안 없는 병원 사례의 대기는 이번 변경으로 더 줄지 않았다. 병상 부족이나 정보 지연을 전반적으로 해소했다고 주장할 수 없다.

## 검증과 보존

- 개발: 미사용 시드 27101~27103, 117사례 × 4분기.
- 소스·설정·Python·OR-Tools 69개 파일을 잠근 뒤 미사용 검증 시드 28101~28106 실행. 검증 결과로 재튜닝하지 않음.
- 새 엔진·시나리오·실행기·독립 감사 테스트 112개 통과. 기존 관련 회귀 테스트 727개도 통과했다. 확장 실행은 823개, 최종 새 모듈 재검사는 112개이며 고유 테스트는 총 839개다.
- 이전부터 환경의 `WinError 10013`으로 연결할 수 없던 선택적 로컬 HTTP 테스트 6개는 이 통과 수에서 제외했다. 새 시뮬레이션 테스트는 모두 포함한다.
- 저장된 검증 JSON을 엔진·솔버 실행 없이 독립 감사기로 재검사: 배정 결정 1,440개, 보고된 C1 모형의 정확 재검사 1,440개, 조기 판단 228개, 조기 준비 72개 확인. 조기 판단을 켠 두 분기의 합이다.
- 추가 자원 변화 보고 0건, 실제 자원 제약 위반 0건. 전체 이송 과정의 전역 최적성이나 임상적 안전성 검증은 아니다.
- 이전 소스·설정·결과·문서 283개를 해시로 보존하고 새 잠금 소스 69개도 일치 확인.
- 운영 서버·API·DB·팀원 UI는 수정하지 않았다. 실제 병원·카카오 경로의 성능 결과가 아닌 합성 시뮬레이션이다.
