# 잔여시간 계산 보정 검증 — 2026-10-21

연구 후보 `eat_horizon_l15_f`를 별도 구현하고, 기존 120개 환경·434명에서 다시 비교했다. **원래 R이 복구한 정확한 4건과 모든 R 성공을 보존했고, 1명의 선정이 15초 빨라졌다. 나머지 433명은 선정 대기가 같았다.**

혼합 96개 환경의 전체 선정 대기 합계는 R의 52,105초에서 **52,090초로 15초 감소**했다. 다만 기존 EAT의 51,908초보다 182초 길어, 사전에 고정한 전체 기준은 통과하지 못했다. 새 개발·별도 검증 실행과 운영 채택은 하지 않았다. 15초는 전체 합계의 감소이며 모든 환자가 15초씩 빨라졌다는 뜻이 아니다.

## 적용 범위

원래 R `eat_residual_l15_f`의 잔여 문의 업무 추정과 비용·후보·동시 문의 수·재평가 간격·병원 확정 규칙을 유지했다. 현재 남아 있는 문의의 시각으로 경과시간을 추정하던 계산을, 공개 환자 생성 시각과 동결된 실험 관측 종료시각 H를 사용하도록 바꿨다.

- **A:** 현재 작업의 새 자동문의 중단시각. 기존 문의의 회신 유효기한이 아니다.
- **H:** 환자 생성+300초인 이 실험의 취소·측정 종료시각. 임상 기한이나 일반 운영의 회신 만료를 뜻하지 않는다.
- 계산 지평은 H−현재시각이며, 신규 문의 계획은 `현재시각+offset < min(A,H)`로 제한한다.
- 마지막 확률 구간과 그 대표 시각을 실제 남은 초에 맞춘다. 지연해 보낼 문의도 이동한 CDF의 실제 마지막 구간으로 계산한다. H 정각 회신을 먼저 반영하는 기존 실행 순서는 유지한다.
- 기존 `_apply`와 버전 검사를 보존하고, 현재 적용 스냅샷·커밋된 작업 행·공개 사건 prefix를 연결한 명시적 시간 입력을 추가했다. 기존 일곱 입력만 사용하는 정책과 동일한 계약이라고 주장하지 않는다.

[탐색에서 확인한 근거와 경계](NEXT_INQUIRY_EXPLORATION_20261021.md)를 바탕으로 요소 하나만 고정했다. guard·공개 의도 보호·전체 FIFO 추정·목적함수 필터를 함께 넣지 않았다. 기존 운영 기본 정책은 `fixed_3`다.

### 15초가 줄어든 기록

이 환자의 기존·신규 원문 두 개를 압축·해제 해시에 대조해 추적했다. 90초 시점에 기존 일곱 정책 입력은 동일했다. 89초에 첫 문의가 불가로 끝난 뒤 원래 R은 남은 문의의 45초 전송시각을 기준으로 지평을 255초로 잡았고, 새 안은 H=300에 맞춰 210초로 잡았다. 이때 H07 문의가 105→90초로 앞당겨졌다.

이후 H10 문의도 180→165초로 앞당겨졌다. H10의 실제 합성 검토시간은 양쪽 모두 25초였고 문의 처리 대기가 없어, 수용·선정이 205→190초가 됐다. 병원 10곳에 문의한 순서·최종 목적지·이동시간·이 환경의 검토 업무 612초는 동일했다.

다만 이후 입력 경로는 달라졌다. H07 불가 회신은 새 안에서도 174초로 H10 신규 문의 165초보다 뒤이므로, 이 회신이 먼저 와서 H10 문의를 당겼다고 설명할 수 없다. 직접 지평 보정과 달라진 문의 나이의 후속 효과를 별도 반사실 실행으로 분해하지 않았다. [단일 개선 기록 분석](../.codex-build/eat-horizon-20261021/diagnosis/post-result/single-improvement.json)에 출처와 경계를 남겼다.
