# 정보 누락·갱신 지연 실험

2026-10-15. 병원의 실제 자원과 배정 알고리즘에 전달된 자원 정보를 분리한 별도 합성 실험이다. 기존 H1 전체 이송 실험의 잠금 소스·결과, 공통 서버·DB와 팀원 앱은 변경하지 않는다.

## 첫 검증 결과

개발 24사례·144실행 후 소스·설정·런타임을 잠그고, 새 seed의 48사례·288실행을 검증했다. 각 분기의 환자 실행 수는 144건이다.

| 정보 | 규칙 | 자동 미배정 | 미도착 | 수용 문의 | 자원 재확인 | 확정 검사 거절 |
|---|---|---:|---:|---:|---:|---:|
| 완전정보 | R1 | 0 | 0 | 252 | 0 | 0 |
| 완전정보 | H1 | 0 | 0 | 222 | 0 | 0 |
| 완전정보 | C1 | 0 | 0 | 222 | 0 | 0 |
| 관측정보 | R1 | 18 | 18 | 418 | 132 | 0 |
| 관측정보 | H1 | 18 | 18 | 372 | 126 | 6 |
| 관측정보 | C1 | 18 | 18 | 372 | 126 | 12 |

자동 미배정 18건은 모두 자원 보고와 별도 확인 응답이 끝까지 없는 대조 조건의 6사례×3환자에서 발생했다. 이를 정보 누락 환자의 실제 수용 실패율로 해석하지 않는다. 최종 검사가 현재 실제 수량을 확인할 수 있다는 실험 가정하에서 충돌 제안 18건을 차단했고 잘못된 실제 확정은 없었다.

주요 관측은 다음과 같다.

- 정보가 정확한 대조군은 같은 규칙의 완전정보·관측정보 결과가 일치했다.
- 누락 후 재확인이 가능한 조건은 모두 도착했지만 공통 18건의 평균 도착이 R1에서 1.222분, H1/C1에서 1분 늦었다.
- 과거 부족 보고가 늦게 갱신되는 조건은 세 규칙 모두 평균 2분 늦었다.
- **전문팀만 누락된 조건에서 H1/C1은 평균 9.5분 지연**됐다. 재확인 중인 P03이 초기 공동 배정에서 빠져 유연한 P01/P02가 NEAR를 먼저 예약한다. P03은 완전정보 대비 평균 34분 늦어지고 P02는 5.5분 빨라졌다. 관측정보의 세 규칙은 실제 목적지·확정·도착이 같으며, R1의 손실이 0.5분으로 작은 것은 완전정보 R1부터 P03을 기다리게 했기 때문이다. 이 표를 정보 누락에서 R1이 더 빠르다는 결론으로 읽지 않는다.
- 오래된 부족 보고를 재확인하는 조건에서는 H1/C1이 평균 2.222분 늦었지만 R1은 6.278분 빨랐다. 관측정보 R1은 유연한 두 환자를 FAR로 먼저 보내 평균 5.667분씩 늦어졌지만, P03의 NEAR 자리가 남아 30.167분 빨라졌다. 정보 손실이 배정 대상·선택지·확정 순서를 바꾼 결과이며 이를 정보 누락의 이점으로 일반화하지 않는다.
- 역순 보고는 최신 관측을 덮지 않았고, 해당 조건의 도착 결과 차이는 없었다.

관련 테스트 223개와 독립 원시 감사가 통과했다. 검증 552개 배정 결정, H1 138배치 기준안, C1 144개 관측 모델 증명을 확인했다. 기존 소스·설정·결과 178개와 새 잠금 소스 24개의 해시가 보존됐다. 검증 seed 18101–18106은 이후 개선의 독립 검증으로 재사용하지 않는다.

## 검증하는 질문

1. 병상이나 전문팀 수량이 없을 때, 이를 0 또는 가용량으로 임의 변환하지 않는가?
2. 마지막 관측이 정확히 10분 된 경우와 10분을 초과한 경우를 구분하는가?
3. 과거 부족 정보가 오래되면 구조적 진료 불가로 종료하지 않고 문의·재확인하는가?
4. 오래된 여유 정보로 만든 배정안이 현재 자원과 충돌하면 실제 확정을 차단하고 기록하는가?
5. 늦게 도착한 과거 보고가 더 최신 관측을 덮어쓰지 않는가?
6. 자원 갱신이 환자별 수용 응답의 유효기간을 연장하지 않는가?

## 정보와 처리 경계

```text
환경의 실제 병상·점유
    → 관측 발생 → 누락·전달 지연 → 자원 관측 저장소
    → 문의 후보와 관측 기반 배정안
    → 별도의 실제 자원 확정 검사 → 확정 또는 거절·재확인
```

병원 수용 응답과 자원 수량 보고는 별도 사건이다. 수용 응답만으로 관측 시각이나 수량을 갱신하지 않는다. 누락·오래된 수량은 문의 후보에 남길 수 있지만 자동 배정 계산에는 명시적 자원 재확인 응답이 필요하다. 재확인 요청·응답은 이번 실험의 합성 계약이며, 이를 운영 서버에 자동 추가한 것은 아니다.

현재 운영 서버에는 수량이 미확인인 경우에도 유효 수용 응답을 담당자가 확정하는 별도 경로가 있다. 그 수동 경로는 이번 실험 범위에서 제외한다. 실험의 미배정은 관측 수량 기반 자동 배정 미확보이며 실제 병원이 수용을 거절했다는 뜻이 아니다.

`capacity`와 `used`는 병원 보고를 통해서만 관측한다. 시스템이 직접 확정한 예약과 등록된 도착 대기 원장은 즉시 알려진 정보로 적용한다. 등록된 외부 유입 대기도 포함하며, 등록되지 않은 외부 대기열이나 대기 원장 자체의 누락은 다루지 않는다. 병원의 수용 판단과 이송 중 조건 변경 알림까지 모두 지연시키는 실험도 아니다.

신선도는 **현재 시각−관측 발생 시각**으로 판단한다. 전달 시각이 최근이어도 원래 관측이 오래됐으면 stale이다. 정확히 10분은 fresh, 10분 초과는 stale이다. 현재 서버의 600초 기준을 참고하되, 관측·수신 시각을 분리한 전달층은 새 실험 모델임을 구분한다.

## 비교 구성

R1·H1·C1마다 같은 실제 환경에서 완전정보 기준과 관측정보 분기를 실행한다. 총 6분기다. 문의 3곳·첫 수용 이후 남은 응답을 최대 2분 추가 대기·변경 알림 조건은 동일하다. V2/V3나 다른 문의 정책을 섞지 않는다.

| 유형 | 주된 확인 내용 |
|---|---|
| fresh_control | 누락·전달 지연이 없을 때 같은 규칙의 결과 일치 |
| missing_recheck | 수량이 없으면 별도 확인 응답을 기다린 뒤 배정 |
| missing_unresolved | 확인 응답까지 없으면 추정 확정하지 않고 보류 |
| stale_shortage_recovery | 과거 부족 정보가 오래되면 재확인 문의 허용 |
| delayed_optimistic_change | 수용 응답 이후 자원 소진과 관측 기반 제안·실제 검사 차이 |
| delayed_pessimistic_recovery | 자원이 회복됐어도 부족 보고가 늦게 갱신되는 지연 |
| partial_team_missing | 병상은 알려져도 필요한 전문팀이 없으면 별도 확인 |
| out_of_order | 역순 보고 수신 시 최신 관측 유지 |

개발은 seed 17101–17103의 24사례·144실행, 검증은 seed 18101–18106의 48사례·288실행이다. 소스·설정·런타임을 개발 이후 잠그며 검증 후 튜닝하지 않는다. 검증에서는 각 유형의 6분기 실행 순서도 균형 있게 회전한다.

## 증거와 지표

- 관측 원문·source/수신 시각·적용 또는 역순 무시 여부
- 문의 가능 여부와 자동 배정 가능 여부, 누락·오래된 정보로 보류한 검사 수
- 수용 문의와 별도로 집계하는 자원 수량 재확인 요청
- 관측 기반 `proposed_assignments`와 실제 `assignments`, 실제 검사 성공·거절
- 미배정·미도착·모의 치료 미시작, 문의·재배정·전원, 우선순위별 분모
- 같은 규칙의 완전정보/관측정보에서 공통 도착 환자의 시간 차이와 한쪽만 도착한 수

H1 기준안과 C1 최적성은 관측 모델의 **제안**에만 적용한다. 실제 검사에서 일부 제안이 거절되면 실제 결과에 같은 최적성이나 비악화 보장을 붙이지 않는다. 원시 감사기는 초기 점유·외부 사건·도착·치료·예약 사건으로 실제 자원을 다시 구성하고, 실제 확정이 해당 수요를 초과하지 않았는지 검사한다.

최종 확정 gate는 환경의 실제 수량을 즉시 확인할 수 있다고 가정한 비교 장치다. 실제 서버가 병원 내부의 미보고 상태를 자동 감지한다는 뜻이 아니다. 최종 확인도 지연되거나 실패하는 상황은 이번 비교 범위에서 제외하며, 잘못된 확정이 차단된 결과도 이 가정 안에서 해석한다.

정보 보류 횟수는 환자 수가 아니라 환자·병원별 재평가 검사 수다. 확정 거절도 잘못 확정한 환자 수가 아니라 실제 검사가 관측 기반 제안을 차단한 횟수다.

## 실행과 재현

```powershell
$env:PYTHONPATH = (Resolve-Path -LiteralPath .solver_deps).Path
python -B -m simulation.partial_information_experiment --phase development --lock
python -B -m simulation.partial_information_experiment --phase validation
python -B -m simulation.partial_information_audit simulation_results/partial_information_validation_20261015.json --lock config/partial_information_lock_20261015.json
```

기존 JSON·Markdown·감사 결과·잠금 파일은 덮어쓰지 않는다. 재실행은 새 `--output` JSON 경로를 지정하고 개발 잠금도 새로 만들 경우에는 `--lock-file`을 별도로 지정한다. 보고서·Markdown·감사·잠금의 경로는 서로 달라야 한다.

새 구현은 `simulation/information_observations.py`, `partial_information_engine.py`, `partial_information_scenarios.py`, `partial_information_experiment.py`, `partial_information_audit.py`다. 감사기는 시뮬레이터·솔버·관측 저장소를 실행하지 않고 원시 JSON만 검증한다.

모든 병원·환자·자원·위치·회신·확인 응답·처치시간은 합성이다. 카카오 도로시간이나 실제 의료기관 운영 성과 검증으로 해석하지 않는다. 계산시간은 별도 측정하며 분 단위 모의 시간에 가산하지 않는다.
