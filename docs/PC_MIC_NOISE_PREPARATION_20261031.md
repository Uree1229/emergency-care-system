# PC 마이크·소음 재시험 준비

**사용자 요청에 따라 지금은 준비만 완료했다. 새 녹음·발화·실제 ASR·오디오 재생은 0회이며, 정확도와 소음 개선 효과는 미측정이다.** 기존 사용자 마이크 기록 1회와 이전 TTS·합성 소음 결과는 보존하고 이번 새 시험으로 합치지 않았다. 잔여 5번의 실제 측정은 아직 남아 있다.

## 준비한 것

- 고정 실행본 `team-common-20261030-v1.1` / `team-20261030-9959804fc7d6d55a`의 429파일을 새 전용 사본으로 보존했다. 제품·원래 실행본·Git·기존 DB는 수정하지 않았다.
- `voice-only` 전용 실행기를 준비했다. 문의·배정 워커 `DISABLED`가 정상이며 환자 등록·문의 시험으로 쓰지 않는다. 기본 포트는 18061이다.
- 마이크 입력·출력의 등록/active flag는 읽기 전용으로 확인했다. 기본 장치, 실제 신호, 권한, 새 물리 마이크 연결은 검증하지 않았다. 개인 장치 ID·장치 이름을 결과에 넣지 않았다.
- 별도 사본에서 캡처·ASR을 모의하는 기존 회귀 **75개 통과**, 대본·빈 양식·버전·미측정 상태의 준비 정합 **10개 통과**. 이 수치를 실제 녹음·ASR 성공으로 세지 않는다.
- 실제 PC 앱내 브라우저에서 수집 화면을 열어 대본 선택·소음 조건을 확인했다. `읽기 시작`은 누르지 않았다. 인식문 빈 값, 수집 0건, 대본 준수 체크 false, 결과 기록·내려받기 비활성, SNR 미측정 상태를 보존했다. 인식 시작 버튼이 노출됐다는 사실만으로 권한·엔진·마이크 성공을 주장하지 않는다.

## 나중에 시작·종료하는 명령

프로젝트 루트의 PowerShell에서 다음 명령을 사용한다. 시작만으로 마이크를 켜거나 음성 인식을 시작하지 않는다. 기존 준비 DB가 있으면 보존해 재사용하고, 다른 서버가 18061을 사용하면 임의 종료하지 않는다.

```powershell
# 시작
& '.\.codex-build\pc-mic-20261031\runtime\PC_MIC.ps1' -Action start
# 상태
& '.\.codex-build\pc-mic-20261031\runtime\PC_MIC.ps1' -Action status
# 종료
& '.\.codex-build\pc-mic-20261031\runtime\PC_MIC.ps1' -Action stop
```

로컬 스크립트 실행 정책에 막히면 영구 정책 변경 대신 준비된 Python 도구를 직접 실행할 수 있다. 같은 PC에서 검증한 Python 경로다.

```powershell
$micPython = 'C:\Users\PC\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $micPython -B -X utf8 '.codex-build/pc-mic-20261031/runtime/control.py' start
# 끝난 뒤 같은 명령의 start를 stop으로 바꾼다.
```

준비 도구는 현재 작업 폴더에서 사용하는 **이 PC용**이다. 다른 PC 설치 패키지로 검증한 것은 아니다. 상태의 ready 파일은 기동 당시의 기록이므로 비정상 종료 후에도 살아 있는 프로세스라고 단정하지 않는다. 이번에는 실제 기동·상태·정상 종료를 따로 확인했다.

## 짧은 시험 카드 3개

먼저 `/paramedic/quick-test.html`에서 새 합성 초안을 만들고 일반 상태 입력 경로를 사용한다. 확인 질문에 답하는 마이크와 일반 입력 마이크를 구분한다. 카드 사이의 같은 초안을 유지하되 조용함/소음 조건은 서로 다른 초안으로 분리한다. 실제 읽는 시점에 사용자가 대본과 참조를 확인한다.

| 카드 | 읽을 내용과 순서 | 확인할 점 |
|---|---|---|
| M01 숫자·부정 | “65세 남성입니다. 혈압은 120에 80, 맥박은 90이고 흉통은 있지만 호흡곤란은 없습니다.” | 120/80·맥박90, 흉통 있음·호흡곤란 없음 분리. 미언급 정상 소견을 만들어 넣지 않음 |
| M02 정정·미측정 | 먼저 “혈압을 110에 70으로 수정해.”를 처리한 뒤, 별도 받아쓰기로 “산소포화도는 미측정이야.” | 혈압만110/70으로 정정, 이전 맥박90 유지, 산소포화도를0·정상 수치로 만들지 않음. 일반 받아쓰기에서 미측정 상태 마커까지 지원된다고 전제하지 않음 |
| M03 중간 종료 | “혈당은 140이야. 녹음 종료. 맥박은 105야.” | 명령 앞 혈당140 저장 확인 후 종료. 명령 뒤 맥박105는 자동 반영 금지. 실제로 수신한 뒤 문장은 미반영으로 보존; 캡처 종료로 수신하지 않은 말은 임의 복원하지 않음 |

3카드지만 M02가 두 발화라 조건당 기본 4발화다. M03는 **quick의 실제 음성 중간 명령 경로**이며, 메인의 일반 문장 입력이나 `evaluate.html`의 단일 문장 채점과 섞지 않는다. 환자 등록·병원 문의·목적지 확정은 하지 않는다.

조용한 환경부터 확인한 뒤 같은 대본·화자·장비로 배경 소음 조건을 이어간다. 계획은 6개 카드/조건 조합이며 아직 실행 0건이다. 소음 종류·음원 ID·거리·짝 비교 ID를 실제 관측대로 기록하고 **모르는 SNR·dBA·거리는 비우거나 null**로 둔다. 입력 프로필은 비교 중 임의로 바꾸지 않는다. 표본이 적은 개발 점검을 일반 발화 정확도나 현장 성능으로 해석하지 않는다.

## 원본 음원과 인식문을 나누어 보존

1. **원본 WAV:** `/paramedic/` → `음성 인식 방식`에서 `오디오만 녹음 · 로컬 시험`. 사람이 읽을 준비가 된 뒤에만 마이크를 시작한다. 종료 후 **시험 WAV·시험 설정 JSON 둘 다 다음 녹음 전에 내려받는다.** 로컬 WAV 모드는 오디오를 STT·서버로 보내지 않는다.
2. **상태형 기능 카드:** quick에서 위 M01→M02→M03를 수행하고 인식 원문·전송 본문·초안·변경 전후·종료 사유·미반영 뒤 문장·요청 ID를 구분한다. 실제 발화와 다르면 따로 실패/원인 기록을 남긴다.
3. **고정 문장의 정밀 평가:** `/paramedic/evaluate.html`은 화면에 표시한 기존 120개 대본 중 하나를 **그대로** 읽는 별도 경로다. 인식 원문을 고치지 말고 동일 발화를 확인한 뒤 결과 기록·JSON 내려받기 한다. custom M01/M02/M03를 읽고 다른 기존 case의 대본 준수 체크를 해서는 안 된다. 이 화면은 원본 WAV를 저장하지 않는다.

브라우저 STT의 마이크 처리는 엔진이 관리한다. 로컬 PCM의 소음 억제·반향 제거·자동 음량 요청이 브라우저 STT에도 적용됐다고 표시하지 않는다. WAV의 RMS·포화 비율은 신호 진단이고 SNR·CER/WER·인식률이 아니다. 새로고침·다음 녹음 전에 파일을 내려받으며, 권한 창이 뜨면 사용자가 직접 확인한다.
