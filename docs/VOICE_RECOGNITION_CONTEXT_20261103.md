# 보고 문맥과 복수 인식 후보의 검토

2026-11-03 · `codex/voice-context-review-20261103` · 기준 main `3d2e1ea`.

## 문제와 범위

기존 Quick 화면은 확인 질문의 짧은 답변에서만 최대 5개 후보를 요청했고, 긴 상태 보고는 첫 후보만 사용했습니다. 이번 변경은 긴 보고에서도 복수 후보를 요청하고, 의료 항목·단위의 문맥과 서버의 기존 추출기를 이용해 후보 간 차이를 찾습니다. 숫자·부정이 엇갈린 항목은 새 값으로 자동 확정하지 않고 기존 확인 질문과 직접 수정으로 연결합니다.

이 기능은 새 STT 모델, LLM, 모델 학습, 외부 음성 업로드를 추가하지 않습니다. 문맥 힌트는 인식기의 후보 형성을 돕는 요청이고, 후보 비교는 불확실성 검출입니다. 실제 인식 정확도 향상은 새 원본 음성으로 별도 측정해야 합니다.

## 동작

1. 긴 상태 보고와 질문 답변 모두 브라우저에 최대 5개 인식 후보를 요청합니다. 지원하지 않는 브라우저가 한 후보만 돌려줄 수 있습니다.
2. 의료 항목명·단위를 힌트로 제공하고, 질문 답변에서는 현재 질문의 항목 문맥을 추가합니다. 정상값·기존 측정값·특정 정답 숫자를 강하게 주입하지 않습니다.
3. 원래 첫 후보들을 이어 붙인 보고문은 그대로 보존합니다. 각 조각에서 다른 인식 후보 하나만 교체한 전체 문장을 비교용으로 만들며, 후보들의 모든 조합을 생성하거나 임의의 새 말을 만들어 선택하지 않습니다.
4. 서버는 같은 사전·추출 규칙과 같은 현재 초안에서 비교합니다. 숫자 표기만 다른 동일 값은 같은 값으로 다룹니다. 정상 범위나 기존값과 가깝다는 이유로 후보를 정답으로 고르지 않습니다.
5. 일치하는 첫 후보의 항목은 기존 초안 흐름으로 처리합니다. 다른 후보의 값·부정·누락과 충돌하는 항목은 재확인 대상으로 남깁니다. 이전 관찰값이 있는 경우 현재값으로 확인됐다고 표시하지 않습니다.
6. 사용자는 긴 문장을 다시 읽는 대신 표시된 항목에 답하거나 직접 수정합니다. 음성 후보가 또 충돌하면 자동으로 하나를 골라 처리하지 않습니다.

보고 끝에 “녹음 종료” 같은 화면 명령이 있으면 후보들의 명령 종류·표현·뒤쪽 미반영 부분이 같은지 확인하고, 같은 명령 앞 본문만 비교합니다. 후보에 따라 명령이 달라지면 자동 동작을 보류하고 원문 검토로 넘깁니다.

그 밖의 음성 제어 명령, 미완성 인식, 비교 한도, 구형 서버 등은 별도 경계로 처리합니다. 실제 본문 저장·환자 등록·병원 문의·목적지 확정은 각각 기존 명시 절차를 유지합니다.

## 예시 — 실제 환자 자료가 아닌 가상 인식문

| 첫 후보 | 다른 인식 후보 | 기대 처리 |
|---|---|---|
| `혈압 120에 80, 맥박 90` | `혈압 120에 80, 맥박 19` | 혈압은 처리하고 맥박만 재확인. 19가 낯설다는 이유로 90을 정답으로 만들지 않음 |
| `맥박 구십 회` | `맥박 90회` | 현재 추출 규칙에서 같은 값90으로 확인된다면 숫자 표기 차이만으로 충돌시키지 않음 |
| 항목을 추출하지 못한 문장 | `산소포화도 97퍼센트` | 다른 후보의97을 자동으로 새 측정값으로 넣지 않고 해당 항목을 확인 |
| `호흡곤란 없음` | `호흡곤란 있음` | 긍정·부정과 관련 파생 메뉴까지 재확인. 확정 양성이나 음성으로 임의 선택하지 않음 |
| 후보 전부 `맥박 90` | 실제 발화가 다른 숫자였음 | 후보 간 일치만으로는 발견할 수 없음. 원음·복창·사용자 확인이 여전히 필요 |

## API와 복구

기존 final transcript와 followup answer API에 선택형 `recognition_alternatives`를 추가합니다. 원래 text는 그대로이며 비교용 문자열 배열은 최대16개, 각1~4000자, 원문과 후보의 합계20,000자 이내입니다. 임의 confidence·정답 라벨을 넣지 않습니다.

```json
{
  "actor_id": "crew-demo",
  "client_request_id": "context-demo-001",
  "expected_version": 1,
  "utterance_id": "utterance-demo-001",
  "text": "혈압 120에 80, 맥박 90",
  "is_final": true,
  "mode": "dictation",
  "recognition_alternatives": ["혈압 120에 80, 맥박 19"]
}
```

상태 확인은 `GET /api/voice/capabilities`의 `recognition_context_revision: voice-recognition-context-20261103-v1`을 사용합니다. 응답의 `recognition_context`는 비교 범위·서로 다른 필드·후보 값을 설명하며, 임상 확신도나 음성 정답률이 아닙니다.

ASR 후보 충돌이 남은 초안은 확인·환자 반영 API에서도 `409 VOICE_RECOGNITION_REVIEW_REQUIRED`로 막습니다. 명시적인 새 측정값·수정·값 비우기로 해소합니다. “미측정” 선택만으로 이전 충돌 값이 정답으로 바뀌지는 않으며, 필요하면 메인 검토로 이어갑니다.

증상 두 개가 각각 충돌한 경우 한 증상에만 답했다고 다른 증상의 확인까지 끝내지 않습니다. 새 답변으로 파생 메뉴를 다시 뒷받침할 수 없으면 과거의 충돌한 제안값을 제거하고 재입력을 알립니다. 임상 상태를 새로 추론해 채우지 않습니다.

원래 요청·원문·비교 후보·요청 ID·기대 버전을 함께 보존하고 결과가 불확실하면 정확히 같은 요청을 재시도합니다. 재시도할 때 새 후보를 끼워 넣거나 최신 버전으로 본문을 바꾸지 않습니다. 초안·환자·작업자 전환으로 이전 후보를 다른 사람의 기록에 붙이지 않습니다.

## 검증 방향

자동 검사는 실제 앱의 파서·초안·HTTP·클라이언트 복구를 사용하되, 인식 후보 자체는 고정한 가상 문자열입니다. 같은 음성을 더 잘 들었다는 검증과 구분합니다.

실제 효과 확인에는 가상 환자 보고를 새로 녹음해 원음·정답·후보·처리 결과를 보존하고, 동일 입력 조건에서 다음 항목을 비교합니다.

- 항목별 수치 완전 일치율과 잘못된 값·누락·불필요한 값.
- 부정·불확실 표현의 의미 반전.
- 불확실 항목 발견률과 불필요한 재질문 수.
- 최종 수정 횟수·입력 완료시간·수동 수정 부담.
- 문맥 힌트 지원 여부와 실제 인식 후보 개수.

지금 규칙을 만드는 데 쓴 문장을 독립 평가 자료로 다시 세지 않습니다. 과거13건의 원문·정답·평가를 수정하지 않으며 새 음성 시험의 분모에 합치지 않습니다.

## 참고한 공식 기능

- [Web Speech API의 인식 후보·문맥 힌트](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition): 브라우저 호환성과 실제 지원 여부를 확인해야 합니다.
- [Azure의 문구 목록](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/improve-accuracy-phrase-list): 인식 전 문맥 제공의 다른 구현 예입니다. 이번에 Azure SDK나 새 유료 STT를 연결했다는 뜻은 아닙니다.

## 실행과 연결 위치

새 합성 DB로 개발 서버를 실행합니다.

```powershell
python -m server.chat_demo --db data/context-review-20261103.db --port 18020
```

Quick 입력: `http://127.0.0.1:18020/paramedic/quick-test.html`.
기존 DB·실제 환자·병원에 문의하지 않습니다. 별도 로컬 서버 v1.4 전용 API를 이번 기능이 제공하는 것은 아닙니다.

## 이번 구현 검증

- 고정 환경(CPython3.12.14 / SQLite3.53.1 / OR-Tools9.15.6755) 전체 core: Python1,297개 실행, 실패·오류0, 생략4. 같은 실행의 Node2,162개 통과 뒤 명령 모드 경계를 추가했고, 최종 전체 standalone Node2,165개를 다시 통과했습니다.
- 신규 서버 후보·초안 검토28개와 기존 음성 회귀를 합친103개 검사 통과. 복수 증상의 부분 답변, 혈압 쌍, 미측정·나이·이전값·수정명령 충돌과 정확 재시도 포함.
- 새 합성 DB의 실제 로컬 HTTP20회로 후보 충돌, 이전값 보존, 동일 요청 중복 방지, 확인 API 차단, 맥박 재답변, 두 증상 순차 해소, 다른 작업자의403, 정적 모듈 제공을 확인했습니다.
- 실제 앱내 브라우저에서 최종 Quick 모듈 로딩, 문맥 힌트24개 표시와 콘솔 오류 없음을 확인했습니다. 버튼으로 마이크를 켜거나 새 실제 음성을 인식한 시험은 아닙니다.

가상 인식문을 이용한 구현 검사이며 STT 정확도 개선률·임상 성능·구급 현장 효과가 검증됐다는 뜻은 아닙니다. 다음 단계는 같은 가상 보고를 실제로 새로 말해 원문과 수치의 일치·재질문을 확인하는 것입니다.
