# UI 핸드오프 5.1·5.5 서버 반영

2026-10-30. 사용자가 `VOICE_UI_CLAUDE_HANDOFF.md`의 5.1·5.5절 반영을 요청했다. Codex 담당 서버의 해석 규칙과 테스트·연결 문서를 수정했다. Claude 담당 `paramedic-ui/`, `test_paramedic*`, 원래 UI 핸드오프 문서와 `_auto_mode()` 함수는 보존했다. 별도 작업에서 같은 서버의 치료조건 검토 기능과 `server/app.py` 변경이 함께 진행됐으며 해당 변경도 보존했다.

## 5.1: 조사 ‘이’에서 숫자 2를 만들지 않음

- `맥박이 지금 떨어졌어`, `맥박이 떨어졌어`, `맥박이 빨라졌어`, `혈당이 올랐어`, `혈당이 지금 떨어졌어`에서 측정값을 생성하지 않는다.
- 기존 관찰값은 보존하고 값 없는 새 변화의 대상에 `needs_clarification`을 표시한다. “빨라졌어·느려졌어”도 새 변화 표현으로 인식한다.
- 항목명에 붙은 한 글자 한글 수는 명시 단위가 있는 경우에만 읽는다. `이십` 같은 여러 글자 수와 명시 숫자는 유지한다. 단위의 접두만 같은 `회복`·`번쩍` 등은 단위로 보지 않는다.
- 공백 혈압 쌍에서도 `혈압이 한 번 떨어졌어`를 2/1로 읽지 않는다. 조사와 구분하기 어려운 한 글자 한글 수의 느슨한 쌍은 보류한다.
- 읽기·질문·미측정 답변은 새 측정값이나 0이 되지 않는다.

## 5.5: 질문 문맥 안에서 자연스러운 답변 허용

| 입력 형태 | 처리 |
|---|---|
| 맥박·호흡수 질문의 `분당 20회`, `분당 20`, `1분에 20회`, `20번`, `스무 번` | 질문한 항목의 수치로 반영 |
| `20회요`, `92회요`, `97퍼센트요`, `105요`, `47세요`, `정상이요`, `정상임`, `명료함` | 끝말을 정리해 해석 |
| 산소포화도 질문의 `97프로`, 체온 질문의 `37.2도씨` | 질문별 지원 단위로 정리 |
| 체온 질문의 `37도 2` | 37.2도 초안, 의미 보완에 대한 검토 표시 |
| `110 70`, `110의 70`, `110하고 70`, `백십 칠십` | 수축기·이완기 한 쌍으로 해석 |
| 긴 설명의 명시적인 `혈압 120 80` | 혈압 한 쌍으로 추출 |
| `혈압 120 80 92회`, `120 80 92라고`, `100/80/60` 등 세 수 | 앞의 두 값만 선택하지 않고 보류 |
| 발생 시각 질문의 `30분 전쯤`, `한 시간 전`, `30분 전부터`, `아까 30분 전에` | 관찰 시각 기준 상대 시각 초안. ‘쯤’은 검토 표시 |
| `비 측정`, `및 측정`, `미측`, `미측정이요`, `측정 안 했어요`, `모르겠습니다`, `패스` | 미측정·확인 불가로 보존하고 반복 질문에서 제외 |

맥박·호흡수 질문의 `분당 20분`은 사용자가 요청한 관대한 답변 정책에 따라 20회 초안으로 해석하되 검토 표시를 붙인다. 다른 수치 질문에는 이 단위 치환을 적용하지 않는다. 미측정 답변에는 정확한 수치를 요구하는 경고를 새로 붙이지 않는다.

증상 질문의 기존 `네/아니요` 극성 답변, 부정·추정·과거 문맥, 잘못된 단위, 여러 수치, 질문 범위 밖 필드의 보류·무반영 계약을 유지한다. `고급 정장 → 호흡 정상`, `의식은 역류 → 명료`처럼 단어 전체를 추측 복원하는 선택 기능은 넣지 않았다.

## 원문·검토·API 계약

- 요청 본문은 그대로다. 실제 `text`를 발화 원문과 `field_metadata[field].evidence`에 남긴다. 해석용 문장을 STT 원문으로 바꾸지 않는다.
- 출처는 `source: followup_answer`, `question_id`, `contextual_answer`로 추적한다.
- 의미 보완이 있으면 응답의 `answer.review_required: true`, `answer.interpretation_notes`와 해당 필드 메타데이터의 동일 속성을 제공한다. 경고에도 검토 이유를 포함한다.
- 일반적인 말끝 제거에는 별도 추정 표시를 붙이지 않는다. 검토 표시는 임상 판단·인식 신뢰도 점수·미응답 상태가 아니다. 같은 질문을 다시 열지 않으며 구급대원이 초안을 검토할 때 확인한다.
- 범위·버전·소유자·멱등 재시도·발화 중복 검사를 유지한다. 답변은 초안만 바꾸고 명시적 확인·제출을 실행하지 않는다.
- 기존 `voice_revision: voice-v2-20261030`은 유지하고 `handoff_parser_revision: voice-ui-handoff-20261030-v1`을 추가했다.

## 검증·실행 서버

- 기존 음성·서버·환자 보완·문의 흐름과 신규 회귀를 합쳐 **323개 검사 통과**, 실패·오류·건너뜀 0. 실행 전후 관련 소스 해시와 `_auto_mode()` 보호 해시 일치.
- 신규 32개 검사에는 실제 세션의 이전 값 보존·재확인, 5.5 예시, 원문 근거, 질문 범위, 미측정·복수 수치·부정 오인 방지와 의미 보완 검토 표시가 포함된다.
- 최초 샌드박스 검사에서는 로컬 HTTP 연결이 WinError 10013으로 차단됐다. 로컬 검증 실행 권한을 받은 뒤 임시 DB·임시 포트에서 HTTP 포함 전체 검사를 수행했다. 실제 STT·마이크·외부 병원은 사용하지 않았다.
- 기존 실제 발화 원문이나 잠금 실험 보고서는 수정하지 않았다. 이 결과는 인식된 문자열의 서버 처리 검증이며 새 녹음의 STT 정확도 개선을 뜻하지 않는다.
- 문서에 지정된 **18041 검증 서버**를 식별하고 시험 DB를 백업한 뒤 같은 DB로 재시작했다. `--seed`를 사용하지 않았다. API에서 새 `handoff_parser_revision`을 확인했다.
- 재시작 전후 시험 기록은 세션8·발화47·개정44·환자0·문의0으로 같았다. 이번 재시작 검증에서 새 발화나 실제 환자·병원 요청은 만들지 않았다. 18032 서버는 변경하지 않았다.

실행 근거: `.codex-build/voice-ui-handoff-20261030/verification-001.json`, `verification-001.log`, `live-validation-server.json`, `validation-backup.json`. 실제 원문이 들어 있을 수 있는 백업 DB는 로컬 작업 폴더에만 보존한다.
