# API 추가 수집과 치료조건 판정 연결

기준 시각: 2026-10-11 18:10:47 KST

**병원 34곳 전부에 심평원 기본·상세 12종을 연결해 408개 관측을 저장했고, NMC 수용 관련 메시지 63건을 추가 수집했다.** 조회한 메시지 관측은 34곳이며, 실제 메시지가 있는 병원은 9곳이다. 두 수집 작업은 오류 없이 완료됐다.

등록 진료과·전문의·시설·장비, 공개 가용 관측, 운영 정보와 메시지를 치료조건 평가기에 연결했다. 서비스의 병원 조회·환자별 후보·배정 결과에서도 조건별 근거와 확인 항목을 제공한다. 현재 당직과 환자별 수용 확답은 여전히 병원 응답으로 확인한다.

이전의 심평원 6종에서 운영 세부정보·전문병원 지정 분야·간호등급·기타 인력·교통 안내·식대가산 6종을 추가했다. 수집 가능한 주변 정보도 원문을 보존하지만, 교통 안내·식대가산·간호등급을 환자 수용 가능의 근거로 임의 변환하지 않는다. 조회 성공과 실제 정보 제공을 구분하며 빈 결과는 시설·인력 부재를 뜻하지 않는다.

기존 NMC 병원 목록·상세는 34곳, 공개 가용병상·장비와 중증질환 응답은 각 28곳이다. 나머지 6곳의 미제공 관측을 병상 0이나 수용 불가로 바꾸지 않는다.

## 2 판정에 연결한 방식

| 입력 자료 | 판정에서 하는 일 | 자동 확정하지 않는 것 |
|---|---|---|
| NMC·심평원 등록 진료과 | 치료조건에 지정한 정확한 진료과 이름과 비교 | 해당 전문의의 현재 당직·환자 치료 가능 |
| 심평원 전문의·시설·장비 신고 수 | 관련 조건에 등록 근거·수량·출처를 함께 표시 | 현재 남은 자원, 수술팀·마취팀 가용수 |
| NMC 공개 가용수·장비 Y/N | 원본 시각·신선도·부족·미확인을 조건별 비교 | 환자별 수용 확답·자원 예약 |
| 심평원 운영 세부정보 | 진료시간·응급 연락처·응급실 운영 신고값을 참고 문맥으로 제공 | 지금 수술·중환자 치료 가능 여부 |
| NMC 수용 관련 메시지 | 사유·질환·표출 상태·적용 기간 원문을 확인 문맥으로 제공 | 자유문을 읽어 환자를 자동 제외하는 판단 |

기본 결과는 `MATCH`, `NEEDS_CONFIRMATION`, `EXCLUDED`다. `MATCH`는 공개 근거의 일치이고 환자별 수용 확정이 아니다. 누락·오래된 관측·시각 미상·서로 모순된 자료는 확인 대상으로 남긴다. 공개 가용수 0이나 장비 N도 기본 운영 정책에서는 재확인 대상이다. 특정 환자에 대한 병원의 유효한 수용 응답과 기존 운영 제한 검사가 확정 조건이다.

6개 실험용 프로필 × 34곳의 **204개 평가**를 고정 스냅샷에 저장했다. 모든 프로필에 현재 전문팀·시술·환자별 수용 등 사람의 확인이 필요하므로 전체 상태는 `NEEDS_CONFIRMATION`이다. 이는 등록 근거를 확보하지 못했다는 뜻이 아니라, 등록정보만으로 현재 환자 수용을 확정하지 않았다는 뜻이다.

## 3 서비스와 배정 결과 연결

- 병원 조회: `treatment_evaluations`에 6개 프로필별 판정과 근거 제공.
- 환자별 후보 조회: `treatment_evaluation`과 `checks`에 환자의 조건별 근거·미확인 항목 제공.
- 환자 입력: `extra.treatment_profile_id`로 시나리오·의료진이 조건을 명시. 증상에서 자동으로 진단하거나 프로필을 추론하지 않음.
- 환자 요구: 선택 프로필의 기본·확장 자원과 명시 요구를 합치고, 같은 자원은 큰 필요량을 유지. 수술실·NICU·분만실을 누락시키지 않음.
- 배정 결과: 판정 근거를 함께 반환. 공개 등록 병상 수를 솔버의 운영 `capacity`로 사용하지 않음.
- 자료 변경: `public_api_snapshots` 변경도 계획 버전을 올려 이전 계산 결과를 무효화.

현재 솔버의 자원 모델은 `ed_bed`, `special_team`이다. 수술실·ICU·NICU·분만실을 요구하는 환자는 지원되지 않는 조건을 표시하고 `NEEDS_REVIEW`로 처리한다. 기존 병원 응답과 운영 자원만으로 지원하는 기본 모델을 계산하며, 공개정보의 미확인 상태만을 근거로 유효한 수용 응답을 거부하지 않는다.

현재 실제 자료 DB에는 환자와 병원 운영 자원이 각각 0건이다. 실제 환자 수용·배정 성공률을 검증한 결과가 아니다. 병원 34곳 전체는 기존 솔버의 32곳 제한보다 많아 실제 실험 입력에서는 후보 선정 또는 모델 제한 조정이 필요하다. 웹 화면에서 새 판정 필드를 표시하는 작업은 별도다.

## 4 미연결 3곳의 기관 검토

일반 자동 연결 기준은 정규화 병원명·주소 일치와 좌표 300m 이내다. 아래 3곳은 공식 자료로 동일 기관을 확인해 별도 검토 목록에 추가했다. 원본 이름·주소·좌표를 덮어쓰거나 전체 병원에 느슨한 매칭을 적용하지 않았다.

| 기관 | 검토 내용 | 공식 근거 |
|---|---|---|
| 다보스병원 | 명칭·주소·대표전화 일치, 좌표 약 361m 차이 보존 | [병원 공식 위치·연락처](https://www.davoshospital.co.kr/intro/page07-01.html) |
| 순천향대학교 부속 천안병원 | 법인명 접두어·5동 표기 차이, 도로명 주소·대표전화 일치 | [병원 공식 안내](https://www.schmc.ac.kr/cheonan/contents.do?key=888) |
| 천안충무병원 | 건물명 표기 차이, 법인·도로명 주소·대표전화 일치 | [병원 공식 홈페이지](https://cmhos.co.kr/cmhos/main.asp), [심평원 기관정보](https://www.hira.or.kr/ra/hosp/hospInfoAjax.do?ykiho=34100253) |

[검토된 기관 연결 설정](../../config/hospital_identity_links.json)에 기관쌍·검토일·공식 출처·양쪽 식별정보 해시를 저장했다. 검토 예외도 전화 일치·유효 좌표·500m 상한·기관쌍 1:1을 검사한다. 식별정보가 바뀌면 검토 예외를 적용하지 않고 일반 자동 조건으로 다시 판단한다. 충돌·중복은 보류한다.

## 5 검증과 재실행

수집·정규화·기관 연결·치료조건·스냅샷·서비스·계획·솔버·시뮬레이션 관련 **352개 테스트 통과**. 합성 응답 테스트와 위 실제 API 수집을 구분했다. DB 무결성·외래키, 고정 파일 해시, API 반환, 인증키 미저장도 별도로 확인했다.

```powershell
$env:DATA_GO_KR_KEY = [Environment]::GetEnvironmentVariable('DATA_GO_KR_KEY', 'User')
python -m server.sync_hira --db data/public.db
python -m server.sync_messages --db data/public.db
python -m server.sync_region --db data/public.db --export-only
```

도로 이동시간은 카카오 키가 없어 추가 수집하지 않았다. 서버의 기존 거리 보정 추정값을 실제 도로 관측으로 표시하지 않는다. 현재 전문팀·응답시간·미래 자원 해제시간은 이 API들로 확보되지 않았으며 병원 입력 또는 명시한 실험 설정이 필요하다.

- 실제 수집 DB(`data/public.db`)
- 고정 스냅샷(`data/regional_snapshots/20261011T091047315716Z`)
- 병원별 치료조건 평가(`data/regional_snapshots/20261011T091047315716Z/hospital_profiles.json`)
- 수집 요약(`data/regional_snapshots/20261011T091047315716Z/summary.json`)
- 심평원 실제 수집 결과(`data/hira_sync/20261011T090219631937Z.json`)
- NMC 메시지 실제 수집 결과(`data/nmc_message_sync/20261011T090244391071Z.json`)
- [API 명세](../API.md), [서버 실행 안내](../../server/README.md)
