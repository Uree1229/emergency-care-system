# 경기 남부와 충남 북부 데이터 확보 결과

기준일: 2026-10-11. 최종 고정 스냅샷 생성 시각: 2026-10-11 18:10:47 KST.

환자 발생 지역을 안성·평택으로 정하고, 경기 6개 시와 충남 2개 시에서 **실제 병원 34곳의 목록·좌표·등록 진료과·시설 정보**를 확보했다. 이 중 28곳은 공개 가용병상·장비 관측과 중증질환 수용 원문 정보가 연결됐다. 6개 실험용 치료조건 묶음과 조건별 근거·미확인 항목을 만들었다.

이번 완료 범위는 **실험 권역·치료조건 데이터 준비와 서비스 판정 연결**이다. 추가 수집·판정 연결은 [상세 결과](API추가수집_치료조건판정연결_20261011.md)를 참조한다. 병원별 현재 전문팀, 실제 응답시간, 환자별 수용 확답은 공개정보로 확보한 값이 아니며, 실제 권역에서 배정 알고리즘의 성능을 검증한 단계는 아니다.

## 1 수집 권역

환자는 안성·평택에서 발생시키고, 병원 후보는 아래 8개 시에서 찾는다. 경기와 충남의 경계를 넘어 탐색 범위를 넓히는 상황을 구성하기 위한 실험 범위다.

| 지역 | API 목록에서 수집한 기관 수 |
|---|---:|
| 경기도 안성시 | 2 |
| 경기도 평택시 | 6 |
| 경기도 오산시 | 1 |
| 경기도 화성시 | 5 |
| 경기도 용인시 | 5 |
| 경기도 수원시 | 9 |
| 충청남도 천안시 | 4 |
| 충청남도 아산시 | 2 |
| 합계 | 34 |

8개 지역의 목록·상세·가용병상·중증질환 수집을 모두 완료했다. 기관 ID 중복 0건, 가용병상 기관 미매칭 0건, 권역 밖 주소 0건이다. 주소·전화·좌표는 34곳 모두 확보했고, DB의 외래키 검사와 무결성 검사가 정상이다.

## 2 실제 정보와 미확인 정보

| 구분 | 현재 확보 상태 | 사용 기준 |
|---|---|---|

| 등록 진료과 | 34곳 | 해당 진료과 등록의 근거. 현재 전문의·수술 가능을 뜻하지 않음 |
| 시설 수 | 병원별 제공 항목이 다름 | 등록 시설 수. 현재 가용수나 운영 총량으로 자동 변환하지 않음 |
| 가용병상·장비 | 28곳의 관측 | 원본 입력시각과 수집시각을 각각 보존 |
| 중증질환 수용 코드 | 28곳의 원문 | 오퍼레이션별 코드 차이와 관측시각 부재 때문에 자동 불가 판정에 미사용 |

공개 병상 관측이 없는 6곳도 미확인 상태로 유지한다. 미제공 자료를 수용 불가나 병상 0으로 바꾸지 않는다.

## 3 가용정보의 제공 범위

아래 분모는 가용병상 응답이 있는 28곳이다. 숫자 해석 가능은 0을 포함한 정수가 제공됐다는 뜻이며, 현재 환자를 받을 수 있다는 뜻이 아니다. 나머지 6곳은 해당 응답 자체가 없다.

| 항목 | 숫자 해석 가능 | 미확인 |
|---|---:|---:|
| 응급실 가용수 | 27 | 1 |
| 수술실 가용수 | 28 | 0 |
| 일반 중환자실 가용수 | 18 | 10 |
| 신생아 중환자실 가용수 | 5 | 23 |
| 분만실 가용수 | 0 | 28 |

분만실은 수량과 별도로 `hv42`의 Y 10곳·N 1곳·누락 17곳을 `service_availability`에 반영했다. Y/N을 슬롯 1/0으로 변환하지 않으며 고위험 분만 수용 가능의 확답으로 해석하지 않는다. 원래 입력시각·수집시각을 유지했고 새 API 호출로 갱신한 값은 아니다.

| 장비 | Y 또는 N 해석 가능 | 미확인 |
|---|---:|---:|
| CT | 28 | 0 |
| MRI | 28 | 0 |
| 혈관촬영기 | 17 | 11 |
| 인공호흡기 | 28 | 0 |
| 조산아 인공호흡기 | 9 | 19 |
| 인큐베이터 | 9 | 19 |

장비의 `N1` 같은 특수값은 단순 N으로 바꾸지 않는다. 오래됐거나 원본 시각을 알 수 없는 관측도 현재 수용 불가 근거로 사용하지 않는다. 분만실·NICU 정보의 누락은 고위험 분만 조건을 병원에 추가 확인해야 하는 이유다.

2026-10-11 실제 호출로 34곳 모두를 연결하고 기본정보·상세 11종, 총 408개 관측을 DB에 저장했다. 심평원 신고 현황과 NMC 가용 관측은 별도로 보존했다. 신청·명령·검증 범위는 [연계 상태 문서](분만실_YN_심평원_연계_20261011.md)에 정리했다.

## 4 치료조건 카탈로그

다음 6개는 알고리즘 실험용 조건 묶음이다. 증상에서 자동으로 진단하거나 임상적 표준 자원량을 정한 것이 아니다. 실제 적용에는 의료진의 조건 지정과 병원 확인이 필요하다.

| 프로필 ID | 조건 묶음 | 등록 진료과 이름의 근거가 맞는 기관 수 |
|---|---|---:|
| TR_GENERAL_ED | 일반 응급 평가 시나리오 | 28 |
| TR_ORTHOPEDIC | 정형외과 평가 시나리오 | 33 |
| TR_CARDIAC_INTERVENTION | 심장 중재시술 필요 시나리오 | 0 |
| TR_NEUROSURGICAL | 뇌신경 응급수술·중환자 치료 시나리오 | 31 |
| TR_PEDIATRIC | 소아 응급 평가 시나리오 | 25 |
| TR_HIGH_RISK_BIRTH_NEONATAL | 고위험 분만과 신생아 집중치료 동시 필요 시나리오 | 23 |

위 수치는 **NMC·심평원의 등록 진료과 근거만** 비교한 결과다. 예를 들어 산부인과와 소아청소년과 등록이 함께 확인된 23곳 모두에서 고위험 분만·신생아 집중치료가 가능하다는 뜻이 아니다. 심장내과·순환기내과의 정확한 이름은 이번 상세 목록에서 확인되지 않아 0으로 집계됐다. `내과`를 심장내과로 추정하지 않았으며, 실제 심장 중재 역량은 추가 자료와 병원 응답이 필요하다.

필수 장비는 조건에 명시된 경우만 비교한다. 심장 중재 프로필의 혈관촬영기와 뇌신경 수술 프로필의 CT는 가상 조건에 포함했다. 인큐베이터·조산아 인공호흡기는 환자별 요구가 있는 경우 별도 추가하는 선택 조건이다.

조건 비교기는 다음 세 상태와 근거를 반환한다.

- `MATCH`: 요청한 공개 근거가 일치함. 환자별 수용 확답을 의미하지 않는다.
- `NEEDS_CONFIRMATION`: 진료과·장비·자원·원본 시각이 미확인이거나 현재 전문팀·시술 확인이 필요하다.
- `EXCLUDED`: 실험에서 공개 가용수 부족의 잠정 제외를 명시적으로 켠 경우에만 현재 문의 차수에서 적용한다. 실제 운영 후보 제외와 목적지 확정은 기존 병원 응답 규칙을 따른다.

기본 정책은 공개 가용수 0과 장비 N도 재확인 대상으로 남긴다. 이번 실제 병원 데이터의 6개 프로필 판정은 모두 추가 확인이 필요하다. 병원별 근거와 확인 항목은 `hospital_profiles.json`에 보존했다.

## 5 저장 위치와 재실행

- 운영 수집 DB: `data/public.db`
- 권역 설정: [experiment_region.json](../../config/experiment_region.json)
- 치료조건 설정: [treatment_requirements.json](../../config/treatment_requirements.json)
- 치료조건 설명: [치료조건 카탈로그](치료조건_카탈로그_20261011.md)
- 고정 스냅샷: `data/regional_snapshots/20261011T091047315716Z`
- 기관별 조건·근거: `data/regional_snapshots/20261011T091047315716Z/hospital_profiles.json`
- 수집 결과: `data/regional_snapshots/20261011T091047315716Z/summary.json`
- 파일·정규화 코드 해시: `data/regional_snapshots/20261011T091047315716Z/manifest.json`

고정 스냅샷에는 수집 DB 복사본, 기관 목록, 원본·정규화 관측, 권역·치료조건 설정과 파일 해시가 들어 있다. 이후 공개 정보가 갱신돼도 같은 입력으로 비교할 수 있다. 인증키와 요청 URL은 저장하지 않는다.

```powershell
$env:DATA_GO_KR_KEY = [Environment]::GetEnvironmentVariable('DATA_GO_KR_KEY', 'User')
python -m server.sync_region --db data/public.db
```

통신 없이 현재 자료의 스냅샷만 만들려면 다음 명령을 사용한다.

```powershell
python -m server.sync_region --db data/public.db --export-only
```

## 6 검증 결과와 후속 연결

공공 적재·치료조건·심평원 명세 계약/기관 매칭/적재·권역 스냅샷·공통 서버·계획 워커·솔버·시뮬레이션 관련 **352개 테스트가 통과**했다. 상세 조회 실패 시 롤백, 운영 자원 보존, 누락·특수값 처리, 정확한 기관 연결·진료과 이름 대응, 스냅샷 재현성도 포함한다. 심평원 테스트는 가상 응답으로 수행했다.

현재 수집 DB의 환자와 운영 자원은 각각 0건이다. 실제 공개 가용수를 임의의 `capacity/occupied`로 넣지 않았다. 다음 단계는 가상 운영 상태를 별도 표시한 실험 입력을 만들고 모바일·병원 웹을 같은 DB에 연결하는 것이다.

수집 기관은 34곳으로 현재 공통 서버 솔버의 32곳 제한을 넘는다. 이후 실험은 후보 선정 기준을 기록한 32곳 이하 입력을 만들거나 제한을 조정해야 한다. 현 솔버가 지원하는 자원은 `ed_bed`와 `special_team`이며, 수술실·ICU·NICU·분만실 조건을 실제 최적화하려면 확장 모델이 필요하다.
