# 전체 첫 문의 보존과 우선 문의 공동 제출

상태: 별도 후보 `eat_cohort_batchwave_l15_f`의 360환경 실행과 별도 보조 감사·수치 대조를 완료했다. 총 대기는 줄었지만 기존 성공 식별자 손실과 개인 지연이 남아 채택하지 않는다. 원래 감사가 중단된 사실은 그대로 보존하며 보조 검증으로 원래 프로토콜을 통과했다고 표시하지 않는다. 운영 기본은 `fixed_3`이고 성과를 보존할 Tailwait 비교 기준도 수정하지 않는다.

## 요청과 실패한 첫 시도

목표는 Stoploss의 기존 성공 환자를 모두 보존하고, Tailwait의 총 선정 대기 24초·70초 단축을 유지하면서 Pairshield보다 3초·15초·50초 더 기다린 환자와 최대 257초 도착 지연도 개선하는 것이다. 전체 환자의 대기·도착을 양쪽 비교안보다 악화시키지 않는 강한 별도 판정도 유지한다.

첫 후보 STARTSLOTS는 공통 첫 문의의 공개 가정 슬롯에 맞춰 문의 수를 줄이고 실제로 현재 두 명에게만 제출했다. 훈련 360환경에서 기존 자료 성공 692→690, 추가 363→362로 감소했다. 각 자료에서 기존 성공 식별자 3명씩을 잃어 채택하지 않았다. 대상 P04의 도착은 좋아졌지만 P05가 실패해 요청을 해결하지 못했다. 실패 결과와 소스는 봉인 `c103908f8d77293bc7a59015ba6b3e8b41be448089f425ca8ff8cee58b9def04`로 보존한다.

## 이번에 바꾸는 요소

정책 계산의 부모는 기존 Tailwait이며, STARTSLOTS는 보존·캐시의 직전 부모다. STARTSLOTS의 결과를 계산 기준으로 채택하지 않는다. 같은 시각에 접수된 첫 문의 대상 4~16명이고 공개 공통 대기열이 비어 있을 때만 새 분기를 사용한다.

원래 Stoploss 실제 기준 행에서 고정 Dynamic/CS 계산을 한 번 수행해 현재 두 명과 뒤 환자 전체의 첫 문의 참고안을 얻는다. 이 참고안의 환자별 문의 병원 집합과 건수를 그대로 보존한다. 참고안은 현재 공개 입력으로 계산한 CS 투영이며, 실제 Tailwait의 미래 진행을 그대로 재생한다는 뜻이 아니다.

각 환자의 보존된 병원 집합 안에서 한 곳을 우선 문의로 매칭한다. 원래 H 모델의 공개 `assumed_workers`는 우선 문의 한 차례에만 적용하는 계산 예산이며 실제 검토 인원·병상 수가 아니다. 전원에게 우선 문의를 배분하지 못하면 Tailwait의 현재 두 명 동작을 복사한다. 매칭 비용은 원래 공개 H 비용을 사용하며 미래 수용 잠재값·실제 검토 인원·환자 결과는 사용하지 않는다.

배분에 성공하면 전체 첫 문의 환자를 하나의 원자적 처리로 실제 제출한다. 환자별 결정 기록은 원래 순서로 한 번 저장하고, 공개 우선순위·원래 순서에 따라 전원의 우선 문의를 먼저 보낸 뒤 나머지 보존된 문의를 보낸다. 병원별 FIFO는 실제 삽입된 문의 순서로 그대로 처리한다. 나머지 문의는 대기열에 쌓일 수 있다. 전원 실제 제출은 앞선 STARTSLOTS의 뒤 환자 가상 계획과 다르다.

전체 환자와 문의 소유자의 공통 스냅샷을 첫 쓰기 전에 확인하고, 각 환자의 작업 회차·버전은 한 번만 갱신한다. 결정 기록·우선 문의·나머지 문의·작업 갱신 도중 오류가 나면 전체를 취소한다. 기존 동시 문의 4건·총 10곳 한도와 시간·실패 비용·실제 병원 환경은 유지한다. 문의 제출 순서는 의도적으로 달라지며 이를 원래 순서 보존이라고 표시하지 않는다.

원래 JOINT·예측 확률·대기 보호는 내장 Tailwait 참고안과 복사 경로에만 적용된다. 새로운 전체 제출의 성공·대기·도착을 보장한다고 주장하지 않으며 관련 전역 보장 플래그는 False다. 잔여 그래프 수치 인증은 `1e−9` 허용 오차가 있는 절차 확인이고 정확한 전역 최소 비용 증명은 아니다.

## 사전에 고정하는 판정

원래 승격 9/7/13개, 이전 보존 9/5개, 환자별 보존 17/9개 조건을 수치·함수 그대로 유지한다. 세 조건이 모두 통과해야 다음 단계로 간다.

- Stoploss·Pairshield·Tailwait에서 성공한 환자의 식별자를 모두 보존한다. 신규 성공으로 기존 성공 손실을 상쇄하지 않는다.
- 기존 827명·추가 415명의 총 선정 대기는 각각 113,405초·54,557초 이하여야 한다. 알려진 두 자료를 합쳐 판정하지 않는다.
- 모든 일치 환자에서 Tailwait와 Pairshield 양쪽에 대해 선정 대기와 도착 비용 증가가 모두 0초여야 한다. 전체 벡터·악화 식별자·건수·양수 합계·최댓값을 보존한다.
- 실패 대기는 300초·실패 도착 비용은 1,800초다. 도착 비용은 선정 경과와 이동시간의 합이며 생성시각을 다시 빼지 않는다. 양쪽 모두 성공한 환자의 도착 변화도 별도 기록한다.

이 목표는 결과 판정에만 사용하며 정책에는 전달하지 않는다. STARTSLOTS는 추가 비교 보고에만 포함한다. 훈련 360환경을 각 한 번 실행하고, 세 판정을 모두 통과할 때만 새 개발 120환경과 별도 검증 368환경으로 진행한다. 시나리오 짝 부트스트랩 10,000회·시드 20261021·지표별 주변 95% 구간도 유지한다.

## 보존과 검증 계획

부모 소스 650개와 새 소스 16개를 합한 666개를 고정한다. 부모 원문 6,360개를 보존하고 비교군 26개·9,360개 분기는 캐시로 사용한다. 새 개발·검증 비교 정책은 27개이며 입력 명세 848개·최대 새 분기 13,536개다. 자료별 게이트는 서로 다른 자료의 성공·총대기 결과를 합쳐 상쇄하지 않으며, 환자별 악화는 별도 Pareto 판정으로 차단한다.

전체 소스 검사, 고정 기능 예제 3개, 독립 참고안·매칭·문의 순서 감사, 저장 원문 360개의 개별 의미 감사, 독립 환자별 회계·공식 집계 대조, 다음 단계 차단 확인, 최종 봉인 순서로 검증한다. 고정 예제와 합성 검사는 기능 증거이며 성능 개선 자료가 아니다. 부모 자료의 문서 참조 실패 10건은 ID·추적·해시와 함께 실패로 남기며 전체 검사를 모두 통과했다고 표시하지 않는다.

모든 성능 환자의 응급 우선순위는 미확인·기본값 4다. 임상 응급도별 효과나 실무 배정 성능을 주장하지 않는다. 부모의 빈 후보 엄격 정수/실수 감사 경계는 단언 완화·정규화·사례 제외 없이 승계하며, 이번 성능 생성 범위는 후보 병원이 비어 있지 않은 경우다.

## 결과

새 모형·정책·컨텍스트·실행기 합성 검사 53건, 실험·판정 92건, 독립 감사 13건이 통과했다. 감사 보조 코드가 축약 작업 스냅샷에 없는 `round_no`를 찾던 오류는 전체 소유자 스냅샷의 원래 작업 회차에 연결하도록 수정했고, 이전 실패와 수정 후 13건 통과를 구분한다. 부모 코드·단언이나 알고리즘 수치는 바꾸지 않았다.

실제 보존 부모 650개 소스·5,355개 엄격 참조·6,360개 원문 연결을 확인했다. 기존 수치·보존·Pareto 함수의 3자 합성 계산이 일치했고, 독립 최종 검증기의 기존 함수 16개는 직전 봉인과 같은 AST다. 변조 57종과 세 판정의 8개 AND 조합을 검사했다. 실제 초기 메타데이터 경로에서는 666개 현재 소스와 캐시를 확인했지만, 아직 없는 동결·테스트·명세·파일 목록의 일부는 합성했다. 원문 경로 전에 중단한 사전 검사이며 전체 동결이나 성능 검증 완료로 표시하지 않는다.

고정 예제에서 비교군 26개의 전체 원문 기록이 기존 실행과 일치했고 후보 예제 세 개의 독립 감사를 통과했다. 원래 8명 예제는 참고 문의 24건 중 우선 슬롯으로 6명만 덮어 부모 두 명 처리 경로를 복사했다. 명시적 4명 예제는 참고 문의 16건·간선 16개·증가 경로 4개·잔여 인증 1개를 확인했고, 실제로 네 명 전체의 우선 문의 4건과 나머지 12건을 제출하고 작업 4개를 한 번씩 갱신했다. 첫 두 명의 병원 목록이 같아도 전체 적용 범위와 제출 순서는 바뀐다. 이는 기능 증거이며 성능 개선의 증거가 아니다.

첫 고정 예제 호출은 기본 Windows 임시 경로 권한으로 첫 기준 데이터베이스를 열기 전에 실패했다. 정책 분기·원문 저장·정식 성능 실행은 없었다. 소스와 판정을 변경하지 않고 작업 폴더의 임시 경로를 사용해 같은 기능 검사를 실행했다. 정식 성능 재실행으로 세지 않는다.

전체 126모듈·2,459건의 첫 실행도 같은 기본 임시 경로 권한 오류 78건과 원래 문서 실패 10건을 기록해 동결 자격에 실패했다. 모든 오류 추적과 검사 전후 동일한 666개 소스 해시를 보존했다. 작업 폴더의 임시 경로를 명시한 같은 전체 재검사에서는 2,449건 성공·동일한 문서 참조 실패 10건·실행 오류/건너뛰기 0건이었다. 새 검사 158건은 모두 성공했다. 검사 전후 666개 소스 해시가 같고 부모 보존 검사도 통과했다. 첫 실행 실패를 통과로 바꾸지 않으며 전체 검사 통과로 표현하지 않는다.

소스 666개·명세 848개를 고정하고 알려진 훈련 360환경을 각 한 번 실행해 전체 원문을 저장했다. 성능 재실행이나 사례 제외는 없다.

원래 의미 감사는 증명 187개를 저장한 뒤 `expanded residual-owner immutable origins` 오류로 중단됐다. 새로운 첫 문의 참고안을 감사하면서 활성 Fullmenu 잔여 환자 점수 계산용 보조 함수를 사용한 것이 원인이다. 부모 Hedge가 비활성인 경우 원래 법칙은 잔여 원점 목록을 비워 두는데, 그 보조 함수는 새 첫 문의 계산에 필요하지 않은 원점 일치를 요구했다. 이것을 원래 정책 실패와 혼동하거나 단언을 느슨하게 처리하지 않는다.

고정된 666개 소스와 실패·기존 증명 187개는 수정하지 않는다. 원래 `repair.json`·승격 잠금·전체 의미 감사 인덱스가 없으며, 실제 다음 단계 함수가 누락된 원래 보고서에서 중단해 실행기·작업 생성·정책 실행 호출 0회인 것을 확인했다. 원래 프로토콜을 통과한 실험으로 표시하지 않는다.

별도 보조 감사기에서는 새 첫 문의 계산에 필요한 현재·뒤 환자의 공개 모형, 전체 JOINT 표, 같은 Stoploss 기준 행과 Dynamic/CS 참고안만 재구성한다. 원래 Tailwait/Hedge 감사, 잔여 환자 공개 출처 검사, 기존 활성·비활성 법칙, 매칭·실제 문의·FIFO 검사는 유지한다. 보조 감사는 원래 실패를 덮지 않으며 별도 코드 해시와 원문·원래 666개 소스 연결로 기록한다. 360건을 다시 감사하므로 원래 전체 감사가 한 번씩만 성공했다고 주장하지 않는다. 원래 예약 작업은 360개, 영구 완료 증명은 187개이고 그 외 실제로 시작한 감사 횟수는 측정하지 않았다.

별도 보조 감사기와 실행기·대조기를 각각 소스 해시로 고정한 뒤 저장 원문 360개를 각 한 번 추가 감사해 모두 통과했다. 원래 187개 완료 증명과 이 360개 보조 증명은 겹치는 사례를 포함하며, 전체 감사가 원문마다 한 번뿐이었다고 주장하지 않는다. 추가 감사는 독립 공개 모형 재구성을 포함하지만 실제 정책·시뮬레이션이나 성능 실행은 하지 않았다. 원래 666개 소스와 기존 증명의 해시는 그대로다.

보조 감사기의 기존 함수 27개 중 수정한 것은 첫 문의 참고안 재구성 함수 1개뿐이다. 원래 테스트 13개를 그대로 유지했다. 추가한 4개를 포함한 첫 17개 검사에서 16개가 성공했고, 한 검사는 예제의 활성 상태를 잘못 가정해 실패했다. 해당 검사만 올바른 기존 활성 예제로 수정해 1개 재검사에 성공했다. 현재의 17개 검사는 그 두 실행에 걸쳐 확인했으며, 마지막에 전체 17개를 한 번에 재실행해 모두 통과했다고 쓰지 않는다. 실제 테스트 전의 가져오기 경로·함수 이름 문제 두 번도 구분해 남겼다. 실행기·대조기의 최종 합성 검사 12개와 독립 보관 도구의 바인딩 검사 5개도 통과했다.
