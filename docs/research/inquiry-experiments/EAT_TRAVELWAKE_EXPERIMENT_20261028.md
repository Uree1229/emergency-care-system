# 공개 이동시간으로 조기 문의를 보호하는 후보

2026-10-28. 조기 재평가로 선정은 빨라졌지만 도착이 118초 늦어진 사례를 확인한 뒤 Travelwake를 구현했다. 같은 개발 환경 12개·42명에서 기존 성공 37건을 보존하고, Tailwait 대비 개인 선정·도착 지연 없이 총 선정 대기와 도착 비용을 각각 6초 줄였다. 작은 개발 표본의 유망 후보이며 전체 연구 기준안이나 운영 정책으로 채택하지 않는다.

## 변경

자기 문의의 새 공개 불가 회신으로 기존 검토 시각보다 일찍 평가할 때만 송신 필터를 적용한다. 현재 자기 미해결 문의 중 `0 <= 현재 시각 - 전송 시각 <= 180초`인 문의의 공개 이동시간 최솟값을 구하고, 그보다 먼 새 병원으로 보내는 조기 문의를 보류한다. 새 병원의 이동시간이나 fresh 문의의 이동시간이 미확인이거나 조인이 모호하면 해당 조기 추가 송신을 보류한다. 과거 문의 중 오래된 문의의 이동시간 누락 자체는 fresh 보호 기준에 포함하지 않는다.

전체 공개 pending과 자기 patient_pending을 타입까지 일치하는 환자·병원·전송 시각으로 연결한다. 워크플로가 이동시간 없는 자기 문의를 H 입력의 patient_pending에서 제외해도 전체 pending에 남은 fresh 문의를 통해 누락을 감지한다. 미래 회신, 실제 서비스 시간이나 미래 환자는 사용하지 않는다.

정기 판단과 첫 공동 문의는 원래 경로를 유지한다. 기존 다음 검토 시각은 `min(기존 예정, 부모 H 제안)`으로 보호하고 무송신 판단도 실제 기록 후 해당 불가 이벤트를 소비한다. 필터 적용 전 H 계획·기대비용과 필터 후 실제 송신을 구분해 기록한다. **필터 후 H 기대비용을 재계산하지 않는다.** 이동시간만의 보호 조건이 실제 도착·성공 비퇴행을 일반적으로 보장하지 않는다.

## 고정한 검증

이전 Declinewake 다중 환자 검증과 정확히 같은 12개 환경·42명을 사용했다. 두 자료 각각에서 정확히 3명인 환경 3개·4명인 환경 3개를 색인 순으로 고른 표본이다. 색인은 `[1,7,16,20,26,54,240,251,254,256,265,275]`다. 같은 환자·병원·입력과 기존 25개 비교군 환자 캐시를 사용했고 비교군 성능은 재실행하지 않았다.

이전 소스 716개에 새 생산·검사 12개와 실행기·검사 2개를 더한 730개를 고정했다. 생산·SQLite 관련 검사 78개와 새 실행기·독립 수치·공개 필터 관측 관련 검사 62개가 각각 실패·오류·생략 없이 통과했다. 보관 도구의 별도 합성 검사 25개도 통과했다. 생산 검사 첫 시도의 복사된 rollback fixture 실패 1건과 관측기 개발 중 키워드 오타로 발생한 합성 오류 기록은 보존하고 최종 고정 소스의 통과 기록과 구분한다.

후보 성능 12개를 한 작업자로 각각 한 번 실행하고 모두 저장했다. 실행·저장·출력 검사·집계의 벽시계 시간 약 55.2초는 정책 판단 지연이나 이전 후보 대비 계산 가속률이 아니다.

## 직전 후보와의 비용

Declinewake는 같은 표본에서 대기를 기존 8초·추가 17초 줄였지만 추가 자료의 도착 비용이 106초 늘고 한 환자가 118초 늦어졌다. Travelwake는 그 도착 손해를 제거하는 대신 직전 후보 대비 총 선정 대기가 기존 8초·추가 11초 늘었다. 즉 직전 25초 단축 중 19초를 포기하고 Tailwait 대비 6초 단축을 남겼다. 직전 후보의 모든 이득을 보존한 개선이라고 주장하지 않는다.

총 문의는 기존 109건·추가 104건으로 세 비교군과 같았다. 조기 판단 51회에서 제안된 추가 문의 34건 중 33건을 보류하고 1건만 허용했다. 이 표본에서 보호 규칙은 매우 보수적이다. 기록된 정책 호출은 385회로 직전 Declinewake 382회보다 3회 많았다. 문의 수를 유지한 것이 재평가 연산량까지 줄였다는 뜻은 아니다. 기존 비교군의 작업량·전체 호출 기록은 캐시에 없어 그와의 연산량 우열은 비교하지 않는다.

## 독립 검사의 범위

수치 검사기가 전체 원문 12개를 읽어 SHA·정확한 환자 벡터·여섯 비교표·27개와 14개 판정·기술 오류 분리를 확인했다. 별도 관측기는 원문 12개를 다시 읽어 공개 fresh 판단·타입별 조인·최소 이동시간·미확인 차단·허용과 보류 순서·실제 송신·기록된 부모 제안과 다음 검토 상한을 독립 재구성했다. 두 검사 모두 통과했고 기술 워크플로 오류는 0개다.

관측기의 `public_travel_filter_verified=true`는 이 필터와 기록의 연결을 검증한 뜻이다. 부모 H 수학, 전체 공개 입력의 과거 이력, 전체 FIFO, 공동 판단의 모든 수학, 호출되지 않은 조기 판단의 누락과 실패·롤백 캡처 경로까지 검증한 뜻이 아니다. 전체 `semantic_verification=false`를 유지한다. 도구별 원문 읽기 횟수는 따로 기록하며 전체 작업에서 한 번만 읽었다고 표현하지 않는다.

case240을 확인한 뒤 만든 규칙을 같은 이미 관측한 개발 자료로 검증했다. 새로운 독립 자료·임상 효과·전체 자료의 일반화·솔버보다 우수함을 입증하지 않는다. 운영 기본값 `fixed_3`과 기존 Tailwait의 전체 자료 24초·70초 단축 성과를 유지한다. 다음 검증은 전체 의미감사와 더 넓은 환자 경쟁·문의 지연 환경에서 성공과 도착을 함께 확인하는 것이다. 자동 확대와 운영 반영은 허용하지 않는다.
