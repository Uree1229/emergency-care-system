# 분만실 Y/N 처리와 심평원 연계 상태

기준일: 2026-10-11

분만실 Y/N 처리와 기존 DB 반영은 완료했다. **2026-10-11 실제 호출로 34곳 모두를 연결하고 기본정보·상세 11종, 총 408개 관측을 DB에 저장했다.**

## 1 분만실 Y/N 반영 결과

기존 `data/public.db`의 가용병상 관측 28곳을 원본 응답으로 다시 처리했다. 새로운 API 호출 없이 원래 입력시각·수집시각을 유지했다.

| hv42 원문 | 기관 수 | 저장 |
|---|---:|---|
| Y | 10 | `service_availability[].reported_available=true` |
| N | 1 | `service_availability[].reported_available=false` |
| 누락 | 17 | `service_availability[].reported_available=null` |

전체 목록 34곳 중 나머지 6곳은 가용병상 응답 자체가 없다. 숫자로 된 분만실 가용수는 여전히 확보되지 않았다.

Y/N은 공개 서비스 표시다. Y를 병상 1개로, N을 병상 0개로 변환하지 않는다. `resources`의 분만실 수량과 별도로 보존한다. Y가 고위험 분만·산과수술·신생아 집중치료의 가능 여부를 보장하지 않는다. 특수값·누락·오래된 관측·시각 미상은 확인 필요로 처리한다.

치료조건 평가에는 `service_availability_evidence`를 추가했다. 분만실 수량이 필요한 조건에서는 Y/N 근거를 함께 전달하되 수량 미확인을 해결한 것으로 처리하지 않는다. 정확히 `required_services=["delivery_room"]`을 지정한 경우에만 해당 서비스 표시를 직접 비교한다.

## 2 심평원과 수용 메시지 연계 결과

심평원 기본·상세 12종을 병원 34곳에 모두 연결했다. 진료과·전문의·장비·시설·특수진료 외에 운영 세부정보·전문병원 지정 분야·간호등급·기타 인력·교통 안내·식대가산을 수집했다. **408개 관측, 수집 오류 0건**이다. NMC 수용 관련 메시지도 34곳에서 조회해 63건(9곳의 비어 있지 않은 응답)을 확보했다.

신고 전문의 수와 현재 당직 인원, 신고 병상수와 현재 가용수는 구분한다. 빈 결과를 인력·시설 부재로 확정하지 않는다. 원천 갱신시각이 없는 정보에는 수집시각을 대신 넣지 않는다. 메시지 시작·종료 시각은 원천 갱신시각이 아니다.

일반 자동 연결은 이름·주소 완전 일치와 좌표 300m 이내를 모두 요구한다. 이전 미연결 3곳은 공식 병원 안내로 동일 기관을 검토하고, [검토 목록](../../config/hospital_identity_links.json)의 기관쌍·해시가 맞는 경우에만 별도 연결했다. 원본 식별정보를 바꾸지 않고 전화·좌표·500m 상한·1:1·충돌 검사를 유지한다.

기본정보와 상세 11종을 모두 받은 기관만 묶음으로 적재한다. 일부 실패 시 해당 기관의 이전 관측을 유지하고, 기존 운영 자원·환자·수용 응답·배정은 덮어쓰지 않는다.

## 3 판정 연결과 실행

진료과·전문의·장비·시설은 치료조건별 등록 근거로 연결했다. 운영 세부정보·수용 메시지는 확인 문맥으로 제공한다. 병원 조회의 `treatment_evaluations`, 환자 후보의 `treatment_evaluation`, 계획 결과에 근거·미확인 항목을 반환한다. 실제 수용은 병원의 유효한 환자별 응답이 필요하다.

```powershell
$env:DATA_GO_KR_KEY = [Environment]::GetEnvironmentVariable('DATA_GO_KR_KEY', 'User')
python -m server.sync_hira --db data/public.db
python -m server.sync_messages --db data/public.db
python -m server.sync_region --db data/public.db --export-only
```

수집 이력은 `hira_sync_runs`, `nmc_message_sync_runs`와 각 결과 폴더에 보존한다. 세부 항목·실제 수집 파일·검증 범위는 [API 추가 수집과 판정 연결 결과](API추가수집_치료조건판정연결_20261011.md)를 따른다. 관련 전체 테스트 **352개 통과**.
