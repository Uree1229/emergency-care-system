# CP-SAT을 포함한 전체 이송 정책 비교

2026-10-13. **환자 발생 → 119 출동·현장 평가 → 문의·회신 → 병원 확정 → 이동 → 조건 변경·목적지 변경 또는 도착 후 전원 → 합성 치료**까지 기존 지도 엔진으로 연결했다.

지도: `http://127.0.0.1:18005/?scenario=online-large_simultaneous-11101`.

선택창의 **CP-SAT 전체 이송 정책 비교**에서 9개 조건을 고를 수 있다. R0·R1·R2·R3·C1의 5개 차량 흐름을 함께 재생하고, 환자 선택으로 개별 이동을 확인한다. C1 카드에는 현재 재생 시각까지의 배정 묶음과 솔버 상태가 표시된다.

## 공정한 비교의 범위

모든 분기에 동시 문의3곳·첫 수용 후 추가 대기2분·조건 변경 알림을 동일하게 적용했다. 같은 seed는 같은 환자 발생, 잠재 회신 지연, 외부 자원 변화, 이동 조건을 제공한다.

그러나 **앞선 배정으로 병원 자원이 달라지면 뒤 환자가 받는 수용 회신도 달라진다.** R0/R1/R2는 환자별로 확정하고 R3/C1은 같은 분의 준비 환자를 함께 확정한다. 이번 실험은 동일한 외부 환경에서 전체 정책의 결과를 비교한 것이며, 동일한 수용 응답 목록을 고정한 [배정 스냅샷 비교](ALLOCATION_BENCHMARK.md)와 구분한다.

C1에는 복사된 현재 환자·유효 수용 후보·이동비용·현재 잔여 자원만 전달한다. 미래 환자, 아직 받지 않은 회신, 자원 반환 예정시각은 넘기지 않는다. CP-SAT과 R3의 목적은 동일하다: 미배정 우선순위 합 → 우선순위 가중 이동시간 합 최소화. 우선순위와 치료 점유시간은 실험 설정이다.

## 검증 결과

개발 seed10101–10106의 **54사례·270실행** 후 소스·설정·런타임을 잠갔다. 새 검증 seed11101–11112의 **108사례·540실행**을 독립 감사했다. 각 유형의 첫 검증 seed11101만 지도에 넣었으며 결과가 좋은 사례를 고르지 않았다.

| 조건 | 관찰된 결과 |
|---|---|
| 늦은 근거리 응답 | R0 모의 도착 평균24분, R1/R3/C1은12분. 첫 회신보다 이동시간을 고려하는 효과이며 CP-SAT만의 효과는 아님 |
| 희소 후보 경합 | 12사례의24명에서 R1은12명 미배정, R3/C1은 모두 배정 |
| 큰 동시 발생 | 12사례의181명에서 R1·R3는48명 미배정, C1은5명 미배정 |
| 긴 우회가 필요한 희소 후보 | 공동 배정으로 한 명을 더 배정하지만, 양쪽 모두 배정된 기존 환자는 C1에서47분 늦게 도착 |
| 이송 중 조건 변경 | 모든 규칙이 해당 자원이 필요한 환자만 목적지 변경. C1만의 개선으로 계산하지 않음 |
| 도착 후 추가 조건 확인·전원 | 모든 규칙이 같은 전원 절차를 수행. 최초 확정 환자를 중복 집계하지 않음 |
| 여유 자원·순차 발생 | 규칙 간 차이가 없는 대조군 유지 |
| 자원 전무 | 모든 규칙 미배정. 없는 자원을 계산으로 만들지 않음 |

큰 동시 발생에서 R3는 조합 한도를 넘어 기존 순차 대체안을 사용한다. C1의 이점은 이 대체안과 비교한 것이다. 14–16명이 동시에 발생하고 병원 전체 자원은15명분인 스트레스 설정이며, 16명 사례5건에는 C1도 한 명씩 배정하지 못했다.

큰 조건의 문의는 R3 **1,250건**, C1 **663건**이었다. 초기 공동 배정으로 미배정 환자의 반복 문의가 줄어든 모형 결과다. 실제 병원의 응답률이나 업무시간 감소를 측정한 값은 아니다.

독립 감사에서 **현재 배정 제약 위반0건**을 확인했다. C1의144개 현재 배정 묶음은 두 목적의 최적성을 증명했고 대체 실행은 없었다. 이는 전체 이송 과정의 최적성 증명이 아니다. 최초 확정1,740건과 재배정·전원을 포함한 전체 확정1,860건을 구분해 집계했다.

## 화면·지표를 읽는 방법

- 미배정·미도착·치료 미시작 수와 시간의 분모를 함께 본다.
- **제한 경과 평균**은 사건이 없으면 관찰 종료까지의 경과시간을 넣어 전체 환자로 계산한다. 실제 미도착 시각을 추정한 값이 아니다.
- 원시 JSON의 `paired_vs_r1`은 양쪽 모두 선정·도착·치료한 같은 환자의 차이와 한쪽만 완료한 인원을 보존한다.
- 알림→목적지 변경 시간은 실제로 변경된 건에 한해 계산한다. 변경 미발생에는 자원 복구나 기존 이송 유지도 포함되므로 실패로 이름 붙이지 않는다.
- 화면의 `OPTIMAL`은 현재 수용 응답을 확보한 배정 묶음에만 적용된다. 미래 상황까지 고려한 전체 최적 경로를 뜻하지 않는다.
- 출동·회신·이동·치료·전원은 합성 모형이다. 운영 서버의 병원 판단·새 수용 확인·사람 승인 흐름은 [서버 조건 변경 시연](TRANSPORT_REPLAY.md)에서 별도로 다룬다.

## 구현·재현

- `simulation/online_allocation_engine.py`: 기존 `ReplaySimulation`을 재사용하며 현재 배정 입력·실제 확정·CP-SAT 증명을 기록한다. 잠금 대상인 기존 엔진·고정 배정 실험 파일은 수정하지 않았다.
- `simulation/online_allocation_scenarios.py`: 전부 합성된9개 유형. 실제 병원 DB와 도로 API를 사용하지 않는다.
- `simulation/online_allocation_experiment.py`: 개발/검증 분리, 설정 잠금, 지표·공통 환자 비교, 유형별 첫 seed 지도 내보내기.
- `simulation/online_allocation_audit.py`: 실행기의 지표 함수를 사용하지 않고 원시 사건·자원 원장·수용 유효시간·실제 확정·배정 목적·최적 증명·분모·요약·누락 사례를 다시 검사한다.
- `simulation/viewer/online_allocation_data.json`: 9조건×5분기. 기존 지도·문의 정책·서버 조건 변경 재생 파일은 보존한다.

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) '.solver_deps'
python -m simulation.online_allocation_experiment --phase development --lock
python -m simulation.online_allocation_experiment --phase validation --lock-file config/online_allocation_lock.json
python -m simulation.online_allocation_audit simulation_results/online_allocation_validation_20261013.json --lock-file config/online_allocation_lock.json
python -m simulation.online_allocation_experiment --export-replay simulation_results/online_allocation_validation_20261013.json
python -m simulation.viewer_server --reuse-data --no-browser --port 18005
```

이미 생성된 지도 파일로 재생할 때는 마지막 명령만 필요하다. OR-Tools는 생성 작업에서 사용하고, 브라우저는 저장된 결과를 재생한다. 이전 실험의 `--reuse-data`용 기본 지도 파일이 없는 새 환경에서는 한 번 `--reuse-data` 없이 기본 자료를 생성한다.

결과는 `simulation_results/online_allocation_{development,validation}_20261013.json`, 같은 이름의 `.md` 및 `_audit.json`에 있다. 잠금은 `config/online_allocation_lock.json`, 소스 보관은 `outputs/source_snapshots/online_allocation_20261013/`이다. 검증 seed11101–11112를 다음 개선의 독립 검증으로 재사용하지 않는다.

관련 회귀 **209개**, Chrome **15개 검사**가 통과했다. 9개 사례의 수치·현재 시각까지만 표시·차량 이동·환자 필터·이송 중 변경·전원·재생/정지·기존3개 그룹·390px 화면을 확인했다. 증거는 `.codex-build/online-allocation-20261013/`에 있다.

2026-10-14 지도 후속: 기존 9개 합성 검증 사례와 별도로, 실제 병원 좌표와 OSRM 이동시간을 입력부터 사용한 [도로 시연 3사례](ROAD_ONLINE_REPLAY.md)를 추가했다. 뷰어는 `road_online_allocation_data.json`도 읽고 **실제 도로 · 5개 배정 정책 시연**으로 분리한다. 실제 좌표 사례에는 OpenStreetMap 일반지도 배경을 선택할 수 있다. 이 문서의 기존 검증 수치·입력·잠금은 변경하지 않았으며, 새 도로 시연의 수치를 기존 검증 성과에 합치지 않는다.

## 남은 과제

2026-10-14 후속: 20·50·100명의 **현재 배정 스냅샷**에서 새 H1과 짧은 예산의 C1을 비교했다. 개발 선택·잠금·미사용84사례 검증과 독립 감사를 완료했다. [새 알고리즘과 결과·한계](ALLOCATION_STRESS.md). 전체 이송 지도에는 아직 H1을 연결하지 않았으며 아래 온라인·불완전 정보 과제는 계속 남아 있다.

현재 이득은 의도적으로 희소 후보 경합을 만든 합성 조건에서의 결과다. 실제 상황의 발생 빈도나 현장 개선율을 제시하지 않는다. 같은 가상 입력에서 모든 환자가 더 빨라진다는 결론도 낼 수 없다.

다음은 **50·100명 규모와 짧은 계산 제한**에서 실행 가능한 해·최적 증명·대체율을 비교하고, 이후 **자원 정보 누락·갱신 지연**을 넣어 정보가 완전하지 않을 때도 배정을 유지할 수 있는지 확인하는 것이다. 현재 계산시간은 따로 측정하며 분 단위 모의 시계에 더하지 않았다.
