# 시간 설명을 종료 명령으로 처리하던 문제 수정

## 수정 내용

LONG-20의 `종료 시각과 증상 발생 시각은 서로 다를 수 있고…`에서 `종료`가 녹음 종료 명령으로 분류됐다. 기존 시간·상태 문맥 규칙은 `시각은`처럼 일부 조사는 처리했지만 `시각과`는 처리하지 못했다.

기존 판정 규칙은 유지하고, `시각·시간·일시·여부·예정·상태` 뒤에 붙은 완전한 조사와 보조사를 추가로 확인한다. 조사 뒤 문장 경계도 확인하므로 `시각에서버` 같은 더 긴 문자열의 앞부분만으로 새 제외 규칙을 적용하지 않는다. 이 규칙은 접두어 없는 `종료·중단·그만`에만 적용한다. `녹음 종료 후…`, `종료 혈압120`, `중단 맥박90`과 같은 기존 명시적 명령은 유지한다.

시간 설명을 건너뛴 뒤 실제 병원 추천·새 환자·이전 환자·인계 요약·종료 명령이 있으면 그 명령을 찾는다. 판정 전 원문을 바꾸지 않으며 prefix·suffix와 명령 위치는 원본 기준이다. 임시 인식은 여전히 명령으로 처리하지 않는다.

## 과거 시험 기록의 보존

이번 수정 전 저장한 LONG-20의 관측값은 `stop`이다. 이를 현재의 `null`과 다르다는 이유로 손상 기록으로 처리하거나 과거 관측값을 수정하지 않는다. 자료 검증 전용 `matchesRecordedVoiceTrigger`는 현재 문법 또는 수정 전 문법의 정확한 6필드 결과만 허용한다. 원문·명령 위치·앞뒤 본문이 다른 임의 결과는 거부한다. 새 시도는 수정된 현재 판정기로만 생성한다. 과거 문법 검증은 종료 명령을 반환하지 않는 boolean 함수이며 실시간 명령 실행에 사용하지 않는다.

따라서 기존 JSON·브라우저 보관본·정답 검토·음성 snapshot 연결을 유지하고 당시의 실패 사례를 그대로 비교할 수 있다. 선택한 과거 기록은 ‘보관 당시 판정’으로 표시하며 현재 재판정과 다르면 둘을 함께 보여준다. schema와 음성 파일은 바꾸지 않는다.

## 검증 범위

수정 전 LONG-20의 오탐 위치는 258~260이었으며 수정 후 전체 문장의 판정은 `null`이다. 배포 후보의 전체 Node 회귀 **1,781/1,781**, 새 문맥 회귀 **63/63**, 과거 관측 호환 회귀 **12/12**가 통과했다. 문맥 회귀는 시간·상태 표현, 기존 명령, 뒤의 실제 명령, 원문 위치, 부분 문자열, 확정 조각 결합 및 기존 종료 API를 검사한다.

고정된 96개 대본을 수정 전후 비교하면 LONG-20만 `stop → null`로 바뀌었다. 기존에 의도와 일치했던 90개는 명령 위치·앞뒤 본문까지 동일하며 새 회귀는 0개다. 이전부터 불일치하던 다른 5개는 이번 수정으로 해결됐다고 주장하지 않는다. 대본과 의도 정답은 바꾸지 않았다.

실제 VoiceCapture를 가짜 인식기에 연결해 연습 화면과 quick-test 화면의 **13개 시나리오·76개 확인**을 통과했다. LONG-20 확정 인식문에서는 자동 종료를 켜도 stop 호출이 0회이며, 뒤의 실제 종료·추천·인계·새 환자·이전 환자 명령은 stop 1회와 원문·늦은 확정 조각을 보존했다. 과거 JSON 복원·가져오기·내보내기와 과거/현재 판정 표시도 확인했다. 결과 JSON의 디스크 독립 재확인 **11개**가 통과했다. quick-test 통신은 실제 VoiceClient/QuickSession에 연결한 메모리 mock이며 실제 서버·네트워크·DB는 사용하지 않았다. 별도로 실제 브라우저의 수동 모의 입력으로 LONG-20의 ‘명령 없음’ 표시와 보관을 확인했다.

실제 STT 정확도·소음 억제·마이크 음질을 측정하는 수정은 아니다. 이번 문맥 판정은 전달된 확정 인식문을 대상으로 한다. 이미 `종료` 한 단어가 확정 전달돼 실행된 뒤 미래의 `시각과`가 도착하는 문제를 해결했다고 주장하지 않는다. 사용자가 긴 문장을 완독해 비교하려면 연습 화면의 자동 종료를 끌 수 있다.
