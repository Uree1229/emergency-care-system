## 이번에 완료한 것

1. 이송 건별 대화 API와 병원 참여 구간·대화 이력 분리. 기존 문의·회신·이송 사건을 자유메시지와 같은 타임라인에 표시한다. [대화 API](CHAT_API.md).
2. 초기 자동 문의 기본 흐름. 환자 생성의 `auto_inquiry: true`로 활성화하며, 독립 워커가 후보 선별→최대 3곳 문의→회신 감시→다음 후보 확인을 수행한다. 유효 수용 응답 후에는 사람이 확정한다. [전체 규칙과 API](INQUIRY_WORKFLOW.md).
3. `server/static/conversation-demo.html`에서 양쪽 화면을 나란히 시연한다. 자동 문의 진행·일시정지·재개·회신·확정·출발·대화·수동 재배정·도착까지 실제 로컬 API를 사용한다. 팀원 원본 UI와의 연결은 남아 있다.
4. 문의 정책 교체 단계 완료. `fixed_1`·`fixed_3`·`fixed_5`·`observed_v2`를 서버 API와 새 시연 선택창에 연결했다. 정책 이름·버전·전체 명세와 매 판단의 사유·병원·관측 근거를 저장한다. 실행 중 전환은 거부하고 일시정지 후 WAITING 상태에서 변경한다. 같은 이름을 명시해도 저장된 버전·설정 불일치이면 변경 전 409로 거부한다.
5. 서버 문의 정책의 동일 조건 비교 완료. `server/inquiry_experiment.py`, `server/inquiry_experiment_scenarios.py`로 64시나리오×4정책=256분기를 실행했다. 각 분기는 같은 초기 SQLite DB와 환자·병원별 잠재 회신 조건을 사용한다. 결과를 보고 정책 설정을 바꾸지 않았다. [설계·성과·실패·재현 방법](INQUIRY_EXPERIMENT.md), [결과 표](../simulation_results/server_inquiry_comparison_20261012.md), [상세 JSON](../simulation_results/server_inquiry_comparison_20261012.json).

서버 소스: `server/inquiry_workflow.py`, `server/inquiry_worker.py`, `server/conversations.py`, `server/db.py`, `server/service.py`, `server/app.py`, `server/chat_demo.py`.
