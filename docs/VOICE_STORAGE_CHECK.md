# 음성 기록의 저장 확인

`/paramedic/quick-test.html`은 서버 응답의 `session.utterances`로 저장 발화 수를 표시한다. `저장된 기록 확인`을 펼치면 서버 주소, 전체 기록 ID, 초안 버전과 확인된 발화 수를 볼 수 있다.

- **저장 발화가 있고 환자 항목이 비어 있음:** 인식 원문은 저장됐다. 숫자·주체·표현이 불분명해 구조화된 항목을 확인해야 하는 상태다. 요약 칸도 `원문 저장됨 · 항목 확인 필요`로 표시한다.
- **초안 준비됨 · 저장 발화 0건:** 초안 생성 응답만 확인됐다. 발화의 저장 완료를 뜻하지 않는다.
- **이번 입력의 저장 결과를 확인하고 있음:** 이전에 서버에서 확인한 건수와 이번 요청의 불확실한 결과를 구분한다. 재시도가 보이면 같은 요청으로 확인한다.
- **현재 말하는 내용:** 녹음을 종료하고 최종 문장을 전송하기 전에는 저장 완료로 표시하지 않는다.

서버 DB에는 전송한 인식 문장이 저장된다. 원본 음성 파일을 보관하는 기능이 아니다. 음성 종료어가 포함된 전체 원문과 종료 후 미반영 문장은 기존처럼 화면 세션에만 남는다. 새로고침하면 해당 화면 기록이 사라지므로 미반영 문장은 먼저 검토한다.

## 현재 실행 중인 서버의 기록 조회

Windows에서는 프로젝트 루트에서 다음을 실행한다.

```powershell
python -m server.voice_record_check --port 18042
```

점검기는 현재 해당 포트에서 수신하는 프로세스를 찾고 실행 인자의 `--db`를 확인한다. HTTP 서버 상태의 시작 시각과 병원 집계도 대조해, 로컬 프록시·포트 전달 등으로 관측한 프로세스와 응답 서버가 다르면 조회를 거부한다. 이 검사는 실행 환경의 일관성 확인이며 인증된 서버 신원 보장은 아니다. 확인 가능한 DB만 읽기 전용으로 열어 전체/음성 시험 세션의 건수와 최근 기록의 메타데이터를 조회한다. 기본 출력에는 발화 원문을 포함하지 않는다.

원문까지 읽어야 할 때만 명시한다.

```powershell
python -m server.voice_record_check --port 18042 --include-text
```

특정 DB 파일만 직접 확인할 수도 있다. 이때 출력은 실행 서버와 대조하지 않은 조회임을 명시한다.

```powershell
python -m server.voice_record_check --db "C:/my-project/data/voice-tryout.db"
```

포트와 DB를 함께 지정하면 실행 서버의 DB와 일치하는지 검증한다.

```powershell
python -m server.voice_record_check --port 18042 --db "C:/my-project/data/voice-tryout.db"
```

종료된 프로세스의 실행 기록이나 예전 `launch.json`만 보고 DB를 고르지 않는다. 포트가 다른 서버에 재사용되면 과거의 DB 경로는 현재 화면과 관계없는 파일일 수 있다. 점검기는 저장 파일을 만들거나 초기화하지 않으며, 실행 인자가 모호하거나 DB가 없으면 오류로 끝낸다. 실행 인자의 DB가 상대 경로라 작업 디렉터리를 확인할 수 없는 경우도 추정하지 않는다. 이때는 실제 DB 파일을 확인해 `--db` 단독 조회를 하거나 서버를 절대 DB 경로로 실행한다.

## 검증 범위

페이지 회귀시험은 원문 저장/구조화 0항목, 생성만 된 초안, 응답 손실과 동일 요청 재시도, 새 기록으로의 전환을 구분한다. 점검기 시험은 현재 프로세스 선택, 명령줄의 DB 경로, 읽기 전용 조회와 잘못된 DB 거부를 다룬다. 이 검증은 마이크/STT 정확도를 측정하지 않는다.
