# 음성 명령 후보 보류와 이벤트 시험 기록

확정 인식 조각의 `종료`를 바로 처리하면 뒤늦게 오는 `시각과…`, `하지 마`, `라고 말함`을 놓칠 수 있다. 공유 `CommandCommitGate`는 전체 확정문의 후보를 잠시 보류하고 후속 인식에 따라 취소·갱신한다. **기본 800ms는 실험값이며 검증된 최적값이나 오탐 방지 보장이 아니다.** 소음 억제나 STT 모델 자체를 바꾸는 기능도 아니다.

이 대기는 마지막 확정 내용 뒤에 후속 확정 내용이나 비어 있지 않은 임시 조각이 수신되는지를 기준으로 한다. 실제 발화 완료를 판단하거나 800ms의 음향적 무음을 검출하는 기능은 아니다.

후보 발견, gate의 결정, 녹음 종료 요청, 브라우저 종료 통지, 서버 저장과 화면 동작은 별개다. 로그에 `commit`이 있다고 실제 녹음이나 업무 동작까지 완료됐다고 판단하지 않는다.

## Quick 음성 기록 화면

`/paramedic/quick-test.html` 설정의 기본값은 `추가 말 확인 후 실행`이다. 후보 뒤 800ms 동안 후속 인식을 확인하고, 확정 후 명령 앞 본문을 저장한 뒤 기존 동작으로 이어간다. `버튼으로만 종료`는 관찰 모드로 음성 제어를 실행하지 않으며 명령 단어도 본문에 남긴다. 기존 말하기 방식에 따라 본문을 처리하므로 원문을 검토한다. 녹음 중에는 정책을 바꿀 수 없다.

일반적인 명령 없는 말하기와 전용 복창 확인의 `맞아요`/`아니요`는 기존 흐름을 유지한다. 추천·환자 전환·인계 요약은 기존 본문 저장 확인을 먼저 거치며 이 gate가 환자 등록·동의·병원 문의를 추가로 자동 실행하지 않는다.

이미 종료 요청을 했더라도 stop 과정에서 미확정 발화를 받으면 명령·서버 반영을 보류하고 전체 확정 원문을 미반영 검토칸에 남긴다. 앞서 내린 `commit` 결정은 시험 로그에 보존하고 내보내기의 `outcome.actionSuppressed`로 동작 보류를 구분한다. 이미 요청한 마이크 종료를 되돌렸다는 뜻은 아니다.

`이번 음성 명령 시험 기록 JSON`은 최근 말하기의 이벤트와 확정 원문을 직접 내려받는 버튼이다. **Quick의 이 로그는 화면 메모리에만 두며 DB·복구 체크포인트·클라우드에 자동 추가 저장하지 않는다.** 기존 확정 본문의 서버 초안 저장과 별개다. 새로고침이나 환자 전환 뒤 로그 보존을 보장하지 않는다. 원문·임시 인식이 들어갈 수 있으므로 실제 환자정보가 없는지 확인한 뒤 공유한다. 자동 생성한 작업자·환자·세션 ID나 서버 주소는 시험 기록에 넣지 않는다.

## 명령 연습 화면의 비교 설정

`/paramedic/command-practice.html`은 명령 판정·녹음 종료 시점을 시험하며 실제 환자 업무 동작은 실행하지 않는다.

| 선택 | 실제 적용 |
|---|---|
| 자동 종료 끔 + 후속 문맥 기다림 | 기본 상태. `observe`로 가상 결정만 기록하고 녹음은 계속한다. 기본 대기 800ms. |
| 자동 종료 끔 + 즉시 처리 | `observe`, 대기 0ms의 비교 기록이며 실제 자동 종료는 하지 않는다. |
| 자동 종료 켬 + 후속 문맥 기다림 | `deferred`로 보류한 뒤 녹음 종료를 요청한다. |
| 자동 종료 켬 + 즉시 처리 | `immediate` 비교 기준. 첫 확정 후보에 종료를 요청하므로 후속 문맥을 놓칠 수 있다. |
| 실행 없이 관찰 | 체크박스 상태와 관계없이 실제 자동 종료를 끈 `observe`이며 가상 결정만 기록한다. |

보류 시간 입력은 100~5000ms의 실험 설정이고 즉시 처리의 비교 대기는 0ms다. 같은 대본·화자·장비에서 조건을 통제한다. 실제 발화가 대본과 달랐다면 독립 정답을 확인하지 않는다. 제공 대본 96개는 합성 텍스트이며 파일이나 수동 모의 결과만으로 실제 사람 음성·현장 STT 성능을 입증할 수 없다.

## 보류·취소·마무리

1. 확정문을 원래 순서로 모아 첫 유효 명령을 찾는다. 임시 인식만으로는 확정하지 않는다.
2. 지연 정책에서는 새 확정문이 오면 전체 문맥을 재판정하고 대기를 새로 시작한다. 뒤의 시간 설명·부정·인용으로 후보가 무효가 되면 취소하고 계속 듣는다.
3. 비어 있지 않은 임시 인식은 타이머를 멈춘다. 임시 문장이 빈 문자열로 바뀌었다는 이유만으로 재확정하지 않으며 새 확정문이 필요하다.
4. 자연 종료에서도 후보의 기존 대기 시점을 지킨다. 버튼으로 명시 종료하면 먼저 stop 과정의 확정문을 받고, 미확정 임시 발화가 없을 때 최신 후보를 `flush`한다.
5. 오류·사용자 취소·페이지 이탈·환자 전환은 이전 타이머를 취소한다. 한 gate는 실제 또는 가상 결정을 한 번만 내린다. 이후 확정문은 보존하되 두 번째 명령을 실행하지 않는다.

Quick에서 후보가 후속 확정문으로 취소된 뒤 정상 종료하면 최종 명령 없는 전체 본문을 일반 받아쓰기로 저장할 수 있다. 미확정 임시 발화가 남은 채 종료하면 확정 원문을 미반영으로 보존하고 명령·서버 반영을 보류한다. 결정 후 종료 과정에서 명령이 부정·인용·시간 설명으로 무효가 된 경우도 기존 보호 절차로 실행하지 않는다.

800ms보다 늦게 들어오는 문맥은 여전히 놓칠 수 있다. 주변 사람과 구급대원의 목소리를 구분하는 기능도 아니다. 더 긴 대기는 반응을 늦출 수 있으므로 실제 발화로 오탐·누락·사용성을 함께 평가해야 한다.

## 로그와 저장 형식

`commandTrace` 형식은 `schema:1`, `policy`, `waitMs`, `events`, `dropped`, `limited`다. 연습 데이터셋은 음성이 없어도 이 선택 필드가 있으면 바깥 형식 `schema:2`를 사용한다.

| 이벤트 | 의미 |
|---|---|
| `final`·`interim` | 인식 조각 수신과 제한된 텍스트 |
| `candidate`·`rearm` | 후보 발견·대기 재설정 |
| `cancel` | 문맥 변화·미확정 발화·종료·취소 등으로 처리를 닫은 이유 |
| `commit`·`would_commit` | 실제 처리 콜백 결정·관찰 모드의 가상 결정 |
| `finish` | gate에 자연 종료·버튼 종료 등 마무리를 요청한 시점 |
| `capture` | `stop_requested`, `recognizer_end`, `stop_drained`의 요청·콜백 수신 표식 |

`atMs`는 해당 gate를 만든 시작 요청부터의 경과시간이며 권한 대기 등이 포함될 수 있다. 실제 발음·단어 끝·마이크 하드웨어 종료 시각이 아니다. `commit.atMs`만으로 단어 끝부터의 지연을 계산하거나 `finish`를 실제 녹음 종료로 해석하지 않는다.

이벤트는 최대 600개·직렬화 약 60,000바이트다. 이벤트의 확정문 조각은 최대 1000자, 임시문은 최대 240자로 남기고 `textTruncated`를 표시한다. 생략 수는 `dropped`, 입력 길이 제한은 `limited`로 구분한다. 이벤트 사본이 잘려도 시도의 확정 원문·조각을 이 규칙으로 덮어쓰지 않는다. 원문에는 기존 화면별 길이 한도가 따로 있다.

연습 화면은 완료 시도의 로그를 JSON에 저장한다. CSV에는 `commandPolicy`, `commandWaitMs`, `commandEventCount`, `commandDropped`, `commandTraceLimited` 요약 열을 추가하며 전체 이벤트는 JSON·ZIP의 데이터셋에 남긴다. 음성이 있으면 원래 시도 snapshot과 함께 IndexedDB에 보관하고, 이후 정답 주석 수정으로 당시 로그를 바꾸지 않는다. JSON 가져오기는 로그·메타데이터만 복원하며 음성 파일은 복원하지 않는다. 이전 형식에 없던 이벤트를 임의로 채우지 않는다.

## 설계 참고와 검증 범위

다음 자료는 설계 참고이며 **800ms의 효과를 입증한 논문은 아니다.**

- [Whisper-Streaming](https://arxiv.org/abs/2307.14743)은 새 오디오를 포함해 재인식한 결과들의 공통 접두부를 LocalAgreement로 확정한다. 후보와 확정을 나누는 설계 참고이며, 현재 타이머가 LocalAgreement를 구현했다는 뜻은 아니다.
- [LiveKit turn detector](https://docs.livekit.io/agents/logic/turns/turn-detector/)는 의미·음향 정보를 이용한 발화 종료 판단을 다룬다. 현재 앱에 이 모델이나 VAD를 넣은 것은 아니다. 현재 대기는 후속 인식 수신을 기다리는 시간이며 실제 무음이나 발화 완료를 측정하지 않는다.
- [Web Speech 명세](https://webaudio.github.io/web-speech-api/#speechreco-methods)는 이미 받은 음성으로 결과를 반환하려는 `stop`과 결과 없이 중단하는 `abort`를 구분한다. stop 직후 결과를 모두 받았다고 가정하지 않는 구조의 참고다.
- [Careless Whisper](https://arxiv.org/abs/2402.08021)는 특정 Whisper 실험의 비발화 구간·허위 문장을 보고했다. 한국어 명령 오류율 근거가 아니며 무음·주저 등을 따로 시험할 이유를 제공한다.
- [독일어 EMS 소음 벤치마크](https://pmc.ncbi.nlm.nih.gov/articles/PMC12628192/)는 TTS 합성 대화와 혼합 소음을 썼다. 실제 한국어 현장 검증과 구분하고 일반 오류와 중요한 도메인 오류를 함께 보는 설계를 참고한다.
- [When De-noising Hurts](https://arxiv.org/html/2512.17562v1)는 영어 모의 상담과 특정 정제기에서 ASR 악화를 보고했다. 소음 억제 도입과 인식·명령 정확도 향상을 구분할 근거이며 모든 정제기에 대한 결론은 아니다.

이 후보는 전체 Node 회귀 **1,929/1,929**, 실제 페이지·VoiceCapture를 가짜 인식기와 연결한 **25개 시나리오·126개 확인**을 통과했다. 연습 화면 14개/67개 확인, Quick 11개/59개 확인이다. 실제 브라우저에서는 빈 대기값이 마이크 요청 전에 거절되는지, 기존 무이벤트 기록 복원과 수동 모의 분리가 유지되는지 확인했다. 실제 마이크·STT·현장 소음 성능을 측정한 시험은 아니다.

내려받은 JSON·ZIP은 Python으로 독립 재확인 **103개**를 통과했다. ZIP 2개에서 결정 로그가 있는 시도와 관찰 시도의 이벤트·메타데이터·CSV 요약 및 합성 녹음 바이트의 CRC·크기·SHA-256을 확인했다. 가짜 MediaRecorder의 바이트는 연결·무결성 시험용이며 실제 코덱 재생·음질 증거는 아니다. 검사 대상 runtime 24개는 루트와 배포 후보의 바이트가 동일했다.

고정한 17개 합성 인식 이벤트 흐름을 즉시·보류·관찰에 각각 넣은 **51회·90개 확인**에서, 비명령 12개 흐름의 gate 결정 콜백은 즉시 12개, 800ms 보류 3개였다. 관찰 모드는 실제 콜백이 0개이고 가상 결정 3개를 남겼다. 유효 명령 5종은 즉시·보류에서 각각 한 번 결정됐다. 이는 gate 결정·녹음 요청·원문 보존의 제어 시험이며 후속 업무 동작 전체 완료나 실제 음성 정확도를 입증하지 않는다.

보류에서도 조기에 결정된 3개는 문맥이 처음 1200ms에 도착하는 흐름이다. 실제 페이지 시험에서도 약 800ms에 종료 요청 후 인식기가 끝나면 1200ms 후 전달하려는 문맥이 무시되는 노출을 남겼다. 나중에 가짜 final을 주입했다는 이유로 실제 녹음을 복구했다고 해석하지 않는다. 관찰 모드가 그 전체 문맥을 남기는 비교 기준이다. 작은 인위적 타이밍 사례의 수치를 현장 오류율·시간당 오탐률이나 최적 대기값으로 환산하지 않는다.

기존 문서의 숫자는 각 이전 기능 후보의 이력이다. 가짜 인식기·가상 시계와 실제 사람 발화·소음 검증을 구분하며, 사람 음성으로 최적 대기 시간이나 현장 성능을 확인했다고 주장하지 않는다. 원본/정제 음원의 동일 ASR 비교와 새로운 사람·문장의 독립 평가는 후속 과제다.
