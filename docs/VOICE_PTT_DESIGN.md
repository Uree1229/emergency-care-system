# 음성 입력: 무전기 방식(누르는 동안 녹음) 설계

작성일: 2026년 10월 30일 · 상태: **방식 결정(사용자). 서버 자동 모드 구현 완료(4절). 앱 버튼은 간편 음성 시험 화면에 구현(10-30, 가짜 인식기로만 검증)** · 관련: [R1 최소 입력](R1_MINIMUM_INPUT.md), [음성 입력 API](VOICE_INPUT_API.md), [R1 맞춤 결과](VOICE.md), [화면 작업 기록](VOICE.md)

구급대원 음성 입력은 **버튼을 누르는 동안만 녹음하는 무전기 방식**을 기본으로 한다. 항상 켜 두는 방식(시리처럼 호출어로 깨우는 방식)은 쓰지 않는다.

## 1 이 방식을 고른 이유

| 기준 | 무전기 방식 | 항상 켜 두기 |
|---|---|---|
| 개인정보 | 누르는 동안만 녹음 | 환자·보호자 대화와 무전까지 녹음·전송 |
| 잘못 입력 | 말할 때만 들어가므로 거의 없음 | 대화·무전 속 숫자와 단어가 초안에 섞임 |
| 소음(사이렌) | 마이크를 입 가까이 대고 말하면 된다 | 계속 인식하므로 소음 영향이 크다 |
| 브라우저 제약 | 화면이 켜져 있으면 동작한다 | 화면이 꺼지거나 탭이 뒤로 가면 끊긴다 |
| 구현 | 지금 API로 바로 된다 | 호출어 엔진, 자동 재시작, 배터리 대책이 필요하다 |
| 익숙함 | 구급대원이 쓰는 무전기와 같은 동작 | 새 동작을 익혀야 한다 |

## 2 동작 규칙

1. **화면 버튼:** 큰 버튼 하나를 누르고 있는 동안 녹음하고, 손을 떼면 끝낸다.
   - 시작할 때 짧은 신호음·진동과 '녹음 중' 표시를 준다.
   - 0.4초보다 짧게 누르면 무시하고 "길게 누르세요"라고 안내한다.
   - 30초가 지나면 자동으로 끝낸다(서버 녹음 한도는 60초).
2. **손을 떼면 바로 전송:** 최종 문장을 서버에 보낸다.
   - 바뀐 칸을 '이전 값 → 새 값' 버튼으로 보여 준다.
   - 원하면 짧게 되읽어 준다. 되읽기는 녹음 중이 아닐 때만 하므로 기기가 자기 목소리를 받아 적지 않는다.
3. **버튼 하나로 입력과 명령:** "방금 거 취소", "읽어 줘", "빠진 거 알려줘", "혈압 100에 70으로 수정"도 같은 버튼으로 말한다.
   - 서버가 명령인지 받아쓰기인지 자동으로 판단한다(4절의 자동 모드, 구현 완료). 앱은 `mode: "auto"`로 보내면 된다.
4. **확정과 전송은 화면 탭:** 음성으로는 초안만 바꾼다.
5. **통신 실패:** 문장을 앱에 남겨 두고 같은 `utterance_id`로 다시 보낸다. 서버는 같은 발화를 두 번 반영하지 않는다(`VOICE_UTTERANCE_FINALIZED`).
6. **개인정보:** 녹음은 누르는 동안만 한다. 서버는 원본 음성을 저장하지 않고 인식 문장만 남긴다. 화면에 이를 안내한다.

## 3 하드웨어 버튼(선택)

손이 바쁠 때를 위해 블루투스 버튼을 붙일 수 있다. 버튼 종류마다 브라우저에서 받을 수 있는 신호가 다르니 **사기 전에 시험한다.**

| 버튼 종류 | 웹에서 받는 방법 | 동작 |
|---|---|---|
| 키보드처럼 동작(특정 키 신호) | 키를 누를 때·뗄 때 이벤트(`keydown`·`keyup`) | 누르는 동안 녹음(무전기와 같음) |
| 이어폰·미디어 버튼(재생/정지) | 미디어 세션 API | 한 번 누르면 시작, 다시 누르면 끝(누르고 있는 동작은 구분 못 함) |
| 볼륨 키로 동작하는 리모컨 | 브라우저가 대개 못 받는다 | 쓰지 않는다 |

## 4 시스템 영향

- **서버:** 기본 동작에는 변경이 필요 없다.
  - 인식 문장은 `transcripts` API로, 짧은 녹음은 Azure 경로(`audio`, 60초 이하)로 처리된다.
  - 세션당 발화 100개 한도는 이송 한 건(대략 5~20번 말함)에 충분하다.
- **서버 자동 모드(10-30 구현 완료):** Codex가 기본 판단을 넣었고, Claude가 무전기 방식 규칙 두 가지를 보탰다.
  - **요청:** `transcripts`·`audio`에 `mode: "auto"`. 명령 문장이면 명령으로, 아니면 받아쓰기로 처리한다(`parse_command` 기준).
  - **응답:** `requested_mode: "auto"`와 실제 처리한 `effective_mode`(`dictation`·`command`)를 돌려준다.
  - **값을 말한 문장은 받아쓰기:** 숫자가 있거나 값이 읽히면, 항목 이름 + '확인해·알려' 형태라도 읽기 명령으로 보지 않는다('혈압 120에 80 확인해' → 받아쓰기, '혈압 얼마야' → 읽기).
  - **음성 '확인'은 실행하지 않음:** 자동 모드에서 '확인'이라고 하면 확인하지 않고 `operational_effect: "confirmation_requires_tap"`과 안내 문장만 돌려준다. 확인·전송은 화면에서 누른다. 앱이 명시적으로 `mode: "command"`를 보내면 기존 동작을 유지한다.
  - **테스트:** `test_voice_r1`의 자동 모드 2개를 포함해 음성·서버 테스트 896개가 통과했다.
  - **남은 한계:** '혈압 확인해 보니 120에 80'처럼 항목 이름과 숫자 사이에 다른 말이 끼면, 받아쓰기로는 가지만 추출기가 혈압 값을 아직 못 읽는다.
  - **선택 과제:** 발화 기록에 입력 방식(`ptt`)을 남겨 효과 측정에 쓴다.
- **앱(10-30 간편 음성 시험 화면에 구현):**
  - 누르는 동안 녹음, 0.4초 미만 무시, 30초 자동 종료, Space·Enter 누름, 손을 떼면 `auto`로 자동 전송, 재전송.
  - 바뀐 칸은 버튼 대신 `이전 값 → 새 값` 목록으로 보여 준다.
  - 시작 신호는 진동만 준다. 신호음은 마이크가 열리는 동안 다시 받아 적힐 수 있어 뺐다.
  - 메인 이송 노트 화면과 하드웨어 버튼은 아직이다. 상세·검증 범위: [화면 작업 기록](VOICE.md).

## 5 시험 계획

1. **소음 속 정확도:** v4 같은 문장을 사이렌·무전 소리를 깔고 2~3단계 음량으로 녹음해 인식시킨다. 같은 채점 스크립트(`voice_lab/evaluate_server_ab.py`)로 칸 재현율·정밀도를 잰다. 지금 수치는 인식 오류가 없는 문장 기준이라, 이 시험이 실제 성능에 더 가깝다.
2. **입력 시간:** 같은 가상 시나리오로 화면 탭 입력과 무전기 방식 음성 입력을 비교한다. 업무 계측(R8 `patient_input`)으로 입력+수정 시간과 오류를 잰다. 참가자 순서는 바꿔 가며 한다.
3. **하드웨어 버튼:** 후보 버튼이 크롬(안드로이드)에서 어떤 신호로 들어오는지 확인한다.
