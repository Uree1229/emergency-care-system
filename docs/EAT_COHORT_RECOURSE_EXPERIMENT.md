# 미착수 문의의 예상 취소를 반영한 공동 배분

상태: 후보는 훈련 조건을 통과하지 못했다. 검사 745개, 기존 13개 비교군의 원문 동등성 검사와 정식 실행 360개의 의미·저장 감사를 통과했지만, 기존 자료의 성공 유지 조건과 추가 자료의 CS 대비 대기 감소 조건에 미달했다. 새 개발·별도 검증은 실행하지 않았고 운영에 적용하지 않았다.

## 목표와 자료 구분

이번 요청은 기존 827명의 CS 대비 성공 순증 3명과 D 대비 선정 대기 78초 단축을 유지하고, 직전 새 자료 415명의 CS 대비 성공 1명 감소와 총 대기 1,261초 증가를 개선하는 것이다. 이미 결과를 확인한 두 자료는 모두 훈련 자료이며, 각각의 조건을 따로 검사한다.

| 관측한 훈련 자료 | CS 성공 / 총 대기 | 이전 Hedge 성공 / 총 대기 | 새 후보 통과 조건 |
|---|---:|---:|---|
| 기존 240개 환경·827명 | 689명 / 111,858초 | 692명 / 113,296초 | 성공 692명 이상, 대기 113,296초 이하 |
| 추가 120개 환경·415명 | 364명 / 53,498초 | 363명 / 54,759초 | 성공 364명 이상, 대기 53,498초 미만 |

실패한 환자의 선정 대기는 관측 한도 300초로 반영한다. 도착시간은 선정 대기와 별도로 보고한다. 두 훈련 자료를 합산해 한쪽의 실패를 다른 쪽 개선으로 상쇄하지 않는다. 이전에 선택한 ‘환자 우선순위·성공 수 우선, 그다음 대기시간’ 원칙을 유지하며 개인 성공 교환은 별도로 보고한다. 모든 과거 성공 환자의 개별 성공을 동시에 유지한다는 추가 조건은 두지 않는다.

## 관측 원인과 개선 선택

직전 415명 중 CS에서는 성공했지만 Hedge에서는 실패한 환자는 2명이고, 반대로 추가 성공한 환자가 1명이었다. 실패 사례와 스트레스 대기 증가에서는 첫 문의가 4곳으로 차 있는 동안 중요한 후속 문의의 진입이 늦어졌다. 실제 시뮬레이터에서는 다른 병원에서 먼저 수용되면 아직 검토를 시작하지 않은 문의가 취소될 수 있지만, 기존의 가상 대기열은 이 작업량을 끝까지 처리하는 것으로 계산했다.

개별 환자의 예측 성공확률이나 예측 대기를 CS보다 악화시키지 않는 단순 가드도 검토했다. 저장된 공개 점수 비교에서 이 가드는 새 손실 경로뿐 아니라 기존 추가 성공 경로도 함께 거부하여 적용하지 않았다. 특정 환경·환자 ID를 정책 조건으로 사용하지 않는다.

이번 후보 `eat_cohort_recourse_l15_f`는 첫 문의 묶음의 예상 작업량 계산 하나만 바꾼다. 후기 재문의 앞당김, CS 후속 정책 교체, 목적지 확정 규칙 변경은 포함하지 않는다.

## 변경한 계산

원래 Hedge의 최대 3개 문의안과 각 문의안의 CS 참조 후속 병원·건수·순서를 그대로 보존한다. 현재 두 환자, 후속 두 환자 묶음, 마지막 단독 환자 순서로 같은 시점에 가상으로 추가할 문의를 읽는다.

1. 취소를 반영하지 않은 기존 대기시간으로 각 문의의 수용 회신 분포 F0를 계산해 고정한다.
2. 순서대로 앞선 가상 문의의 예상 작업량을 반영해 이번 문의의 예상 시작 대기 q1을 계산한다.
3. q1 이전에 같은 환자의 다른 병원에서 수용 회신이 없을 확률 u를 고정 F0로 계산한다. 자기 병원의 회신은 이 곱에서 제외하고 환자의 관측 종료 시점까지만 평가한다.
4. 해당 가상 문의가 뒤 환자에게 더하는 예상 작업량을 ‘원래 평균 작업량 × u’로 계산한다.
5. 한 번의 순방향 계산으로 첫 문의 대상자들의 성공확률·선정 대기를 다시 구한다. 나머지 대기 환자의 원래 회신 분포는 고정하고, 후속 계획의 가상 대기 부담에만 같은 보정을 적용한다.

보정된 회신 분포 F1을 다시 취소확률 계산에 넣는 반복은 하지 않는다. 이미 실제로 보낸 문의의 작업량과 원래 회신 분포는 할인하지 않는다. 대기 없이 바로 검토를 시작한다고 보는 가상 선두 작업도 취소 가능성을 이유로 줄이지 않는다. 환자 자신이 다른 병원에서 이미 수용됐을 가능성을 반영한 것이므로 해당 문의의 수용확률에 u를 다시 곱하지 않는다.

우선순위별 예상 성공 수를 먼저, 총 선정 대기를 다음으로 비교하고 동률이면 원래 Hedge의 선택을 유지한다. 예상 작업량 할인은 실제 동시 문의 자리를 나누는 계산이 아니다. 실제 문의 한도 10곳, 신선한 동시 문의 4건, 자동 문의 마감 A, 관측 종료 H, 원자적 묶음 적용과 실제 FIFO 처리는 그대로 유지한다.

이는 공개 입력으로 만든 취소·회신의 근사 계산이다. 실제 취소를 미리 알고 실행하거나 실제 이후 정책의 행동을 보장하는 모형이 아니다. 실제 선택은 현재 묶음에만 적용하며 나머지 단독·후기 판단은 기존 H 경로를 따른다.

## 사전에 고정할 검증 절차

새 후보는 하나다. 가중치 λ=15와 기존 수용·대기 계산 설정을 유지한다. 기존 442개 소스와 767개 참조 파일, 부모 소유 원문 360개 및 조상 원문 1,320개를 변경하지 않고 보존했다. 새 소스 16개를 추가한 총 458개 소스가 동결 대상이다.

- 훈련: 기존 360개 환경에서 새 후보만 실행하고, 봉인된 13개 비교군·4,680개 분기를 재사용한다. 위의 두 구간별 성공·대기 조건을 모두 충족해야 다음 단계로 간다.
- 새 개발: 과거에 실행했거나 생성만 해 둔 모든 역할·네임스페이스와 겹치지 않는 새 120개 환경에서 14개 정책을 비교한다. CS와 Hedge 각각에 대해 실패 비증가와 총 선정 대기 감소를 모두 요구한다.
- 별도 검증: 새 개발 조건을 통과한 경우에만 새 368개 환경을 실행한다. 같은 점 조건과 더불어 CS·Hedge 각각에 대한 환자당 실패 차이의 상한이 0 이하, 환자당 대기 차이의 상한이 0 미만이어야 한다. 시나리오 단위 짝 부트스트랩 10,000회의 지표별 주변 95% 구간이며 네 조건의 공동 95% 보장은 아니다.

각 단계의 모든 원문을 저장한 뒤에 결과를 평가하며 결과 제외와 성능 재실행은 하지 않는다. 실패한 단계 이후의 성능 실행은 차단한다. 새 자료를 보고 같은 후보의 정책·통과 조건·난수 네임스페이스를 조정하지 않는다. 기존에 생성했지만 실행하지 않은 검증 자료는 이번 개선의 진단·튜닝에 열지 않는다.

실험의 환자 우선순위는 모두 기존 합성 입력의 미확인·기본값 4다. 다양한 실제 임상 응급도에서 우월하다는 주장은 하지 않는다. 운영 서버와 기본 정책 `fixed_3`는 변경하지 않는다.

## 독립 감사와 회계 범위

새 감사 코드는 원래 Hedge 증명과 새 선택을 구분해 검사한다. 공개 이력 환자·전체 현재 원본·고정 F0·순방향 q1·기대 작업량·기존 회신 분포·정수 동시 문의 제한·실제 송신과 모든 환자의 FIFO 결과를 확인한다. 이전에 보완한 역사 환자 출처 검사와 빈 생존확률 곱의 숫자 형식 보완도 기존 소스 그대로 사용한다.

부모의 정책·FIFO 감사를 매 단계 재실행하지 않는다. 봉인된 부모 환자 원장을 재사용하되 부모 원문 360개의 해시·헤더·환자 결과를 한 번 대조한다. 기존 827명의 나머지 비교군 12개는 부모의 봉인된 감사·회계 기록에 의존한다. 새 원문에는 정확한 원문 해시와 전체 소스 해시에 결속한 의미 감사를 한 번 수행하고, 이후 저장 감사는 그 증명과 원문·수치·단계 조건의 무결성을 확인한다.

최종 표준 라이브러리 회계기는 정책·시뮬레이터·정답용 오라클을 호출하지 않고 저장 원문의 성공·실패·선정 대기·개별 성공 교환·도착 진단·구간별 조건·신뢰구간을 다시 계산한다. 기록의 무결성 통과와 후보의 성능 통과는 서로 다른 판단이다.

정식 실행 전 고정된 어댑터 입력에서 감사 라벨의 분류 오류를 발견했다. 비용 계산의 1 ULP 차이 약 1.14×10⁻¹³을 확률용 기준으로 잘못 검사하고 있었다. 새 감사의 상위 라벨 두 곳만 바로잡아 기존 확률 10⁻¹³·비용 10⁻¹⁰ 기준이 각각 적용되도록 했다. 생산 계산·정책·전역 허용오차 함수와 기존 442개 소스는 바꾸지 않았다. 초기 검사 기록과 고정 입력 원문도 보존했으며, 수정 후 전체 검사와 어댑터 검사를 다시 통과했다. 이 수정은 소스 동결과 정식 성능 실행 이전이다.

## 결과

소스 458개를 동결한 뒤 훈련 환경 360개에서 새 후보 분기 360개를 한 번씩 실행했다. 모든 원문을 저장한 후 평가했고, 결과 제외·성능 재실행은 없었다. 두 자료는 모두 이미 관측한 훈련 자료다.

| 훈련 구간 | CS 성공 / 선정 대기 | 이전 Hedge 성공 / 선정 대기 | 이번 후보 성공 / 선정 대기 | 조건 |
|---|---:|---:|---:|---|
| 기존 827명 | 689명 / 111,858초 | 692명 / 113,296초 | **691명 / 111,495초** | 성공 692명 이상 미달, 대기 조건 통과 |
| 추가 415명 | 364명 / 53,498초 | 363명 / 54,759초 | **364명 / 53,666초** | 성공 조건 통과, CS보다 대기 168초 증가로 미달 |

기존 자료에서는 Hedge보다 대기 1,801초를 줄였지만 성공도 1명 줄었다. CS 대비 순증은 2명으로, 요청한 3명을 유지하지 못했다. D 대비로는 성공 수가 같고 대기는 1,879초 짧다. 이는 기존 78초 단축에 추가 1,801초를 줄인 결과다.

추가 자료에서는 Hedge보다 성공 1명 증가·대기 1,093초 감소를 보였다. CS 대비 성공 1명 부족은 총수 기준으로 해소했지만, 기존 CS 성공 환자 2명의 실패는 그대로이고 다른 환자 2명이 새로 성공한 결과다. CS 대비 대기 증가도 1,261초에서 168초로 줄었으나 감소 목표를 충족하지 못했다.

스트레스 구간의 총 대기는 기존 132명에서 10,621초, 추가 66명에서 5,436초로 각각 CS와 같아졌다. Hedge 대비 초과 대기 1,721초와 694초가 사라졌다. 추가 415명의 CS 대비 차이 168초는 혼합 환경 두 개의 +218초와 −50초로 구성되며 나머지 118개 환경은 CS와 총 대기가 같다. 전체 합산으로 실패 조건을 상쇄하지 않는다.

### 성공 교환과 도착 진단

- 기존 자료의 Hedge 대비 성공 손실은 환경 174의 P03(237초→실패), 환경 203의 P01(229초→실패) 두 명이다. 환경 174의 P01이 새로 230초에 성공하여 순손실은 1명이다. CS 대비로는 기존 성공 손실 없이 환경 177의 P03·P05 두 명을 추가 성공시켰다.
- 추가 자료에서는 CS 대비 환경 291의 P06·P07을 잃고 환경 297의 P03·P07을 추가 성공시켰다. Hedge 대비로는 환경 296의 P06(274초→실패)을 잃고 환경 297의 두 명을 추가 성공시켜 순증 1명이다. 환경 번호는 이번 훈련 원장의 0부터 시작하는 인덱스이며 환자 식별에는 환경 종류·난수·원래 자료 구간을 함께 사용한다.
- 기존 자료의 환자당 도착 비용은 842.299초로 CS보다 2.565초 짧지만 Hedge보다 2.252초 길다. 추가 자료에서는 823.386초로 CS보다 3.981초, Hedge보다 0.511초 길다. 실패 환자의 도착 비용은 1,800초로 계산한다.
- 두 정책 모두 선정에 성공한 환자 중 도착 지연의 최대 증가는 기존 자료에서 Hedge 대비 345초(환경 182/P03), 추가 자료에서 CS 대비 607초(환경 291/P08)다. 선정 대기 감소가 도착시간 개선을 자동으로 뜻하지 않는다.

새 원문 360개의 해시·환자·공개 입력 기반 선택·실제 FIFO를 감사했다. 저장 감사에서는 같은 원문·소스 해시에 결속한 의미 증명을 재사용했다. 별도 독립 집계도 원문을 대조하여 위 수치와 성공 교환을 확인했다. 기존 442개 소스, 참조 767개와 압축 원문 1,680개는 보존한다.

실제 `execute('development')`를 호출한 차단 검사에서 `verify_prior`의 훈련 성능 조건에 걸렸다. 작업 생성·실행기·시뮬레이터 호출은 모두 0회이고 새 개발·별도 검증 산출물도 없다. 무결성 감사 통과는 성능 통과를 의미하지 않는다. 이 후보의 정책·소스·단계 조건을 사후 수정하지 않으며 다음 개선은 별도 후보로 기록한다.
