# 문의 시점과 계산량 개선 실험

2026-10-27. 검토 시점 정렬, 공개 불가 회신 재평가, 동일 계산 재사용의 세 방향을 구현·검증했다. 전체 자료에서 기존 성공을 잃은 검토 시점 정렬안은 채택하지 않는다. 불가 회신 후보는 작은 환경 선별과 좁은 이벤트 관측까지 완료했고, 계산 재사용은 별도 합성 동등성 시제품 단계다. 기존 Tailwait 연구 기준안과 운영 기본값 `fixed_3`을 유지한다.

## 검토 시점 정렬의 확대 검증

Releasealign은 자기 미해결 문의가 정확히 4건이고 기존 H가 추가 문의를 보내지 않은 후속 판단에서, 공개된 전송 시각으로 계산할 수 있는 정책상 180초 경계의 다음 시각에 검토하도록 조정한다. 병원 병상의 실제 회복을 예측하는 방식이 아니다. 기존 정책의 문의 대상과 목적함수, 첫 공동 문의 계산은 바꾸지 않는다.

지난 12환경 선별은 기존 자료 26명과 추가 자료 30명에서 기존 성공을 유지했고, 추가 자료의 선정·도착을 각각 14초 단축했다. 당시 원래 27개 조건은 실패였고 별도 연구용 14개 조건만 통과했다. 수치 독립 대조는 완료했지만 정책 의미감사는 없었다.

이번에는 그 12개 성능 원문을 읽기 전용으로 재사용하고 12개 환경을 추가한다. 전체 24개 원문에 대한 정책·공개 입력·FIFO 의미감사는 모두 새로 수행한다. 과거 선별 결과의 의미감사 상태를 소급해서 바꾸지 않는다. 24개 감사와 독립 수치 증빙, 동일한 연구용 14개 조건을 통과한 경우에만 나머지 336환경을 이미 관측한 개발 자료의 특성 조사로 확대한다.

기존 698개 소스에 새 실행기와 그 검사 파일 2개를 더한 700개를 새 동결 대상으로 사용한다. 재사용한 12개 성능의 생성 소스는 과거 698개이며 새 동결에서 생성됐다고 표시하지 않는다. 각 원문 색인·사례·새 감사 증명에 성능 생성 동결 SHA와 소스 개수를 따로 남긴다. 24개 감사 관측자의 소스 맵은 현재 700개다.

기존 보관 SHA `f924a5db49e72f3c8d11294e89783500cb3ee8ca8be3b1c882b7e3cf9afa7fd4`의 소스 698개·보관 파일 406개·압축 원문 372개·별도 검증 부품 2개·최종 문서를 바이트 단위로 다시 확인했다. 이 자료는 수정하지 않는다. 새 결과는 `.codex-build/eat-queue-review-20261027/`에만 저장한다.

## 유지하는 판정과 한계

- 원래 27개 조건과 전체 360환경에서의 원래 목표 9개·보존 9개·환자별 보존 17개를 그대로 보고한다.
- 연구용 14개 조건은 두 자료에서 각 비교군의 기존 성공을 보존하고, Tailwait 대비 모든 환자의 선정 대기·도착 비용 및 총 대기를 늘리지 않으며, 적어도 한 자료의 총 대기를 엄격히 줄여야 한다.
- 두 자료의 성공 상실을 다른 자료의 새 성공으로 상쇄하지 않는다. 환자별 지연을 합계나 평균 개선으로 덮지 않는다.
- 선정 실패의 제한 대기는 300초, 도착 실패 비용은 1,800초로 유지한다. 실제 양쪽 선정 환자의 도착 지연과 실패 비용 증가는 구분한다.
- 기존 비교군 성능을 재실행하지 않는다. 원래 전체 검사에 남았던 10개 실패는 재분류하지 않는다.
- 합성 환경이며 이미 관측한 개발 자료다. 새 독립 자료의 일반화, 임상 효과, 솔버보다 우수하다는 결론이나 운영 반영을 허용하지 않는다.

원문 전체를 읽는 수치 검사기는 환자 벡터와 여섯 비교표 및 27·14개 조건을 독립 계산한다. 정책 의미감사와는 다른 절차다. 전체 9·9·17개 목표의 산술까지 그 수치 검사기가 독립 재실행했다고 주장하지 않는다. 계산·감사 전체 벽시계 시간을 한 번의 정책 판단 지연으로 표현하지 않는다.

## 별도로 조사하는 공개 불가 회신 재평가

기존 워크플로는 다른 미해결 문의가 남아 있으면 새 불가 회신이 도착해도 예정된 검토 시각까지 기다릴 수 있다. 이미 공개된 자기 문의의 불가 회신을 근거로 추가 재평가를 삽입하는 후보를 준비한다.

이 방향은 마지막 실제 판단에서 포착한 이벤트 접두부 이후의 회신만 사용하고, 같은 초의 회신도 이벤트 식별자로 구분한다. 새 회신의 문의·환자·응답 상태와 공개 시각을 확인하며, 조기 평가가 기존 다음 검토 시각을 오히려 늦추지 않도록 보호한다. 아래에 단위·SQLite 검증과 작은 환경 선별 결과를 기록한다. 전체 자료의 성능 개선이나 기존 성공 복구를 증명한 후보는 아니다.

## 공개 불가 회신 후보의 작은 환경 선별

Declinewake는 새 6개 모듈과 대응 검사 6개로 구현했다. 실제 공개 불가 회신의 이벤트 식별자와 직전 실제 판단의 접두부를 사용하고, 원래 예정된 다음 검토보다 늦춰지지 않게 한다. 읽기 도중 시간이 바뀌거나 이벤트 접두부가 바뀌면 해당 판단을 폐기하고 회신을 소비하지 않는다. 무송신 판단은 실제 기록 후 회신을 소비한다. 다른 정책의 활성 작업은 첫 쓰기 전에 거부하는 실험 전용 실행기이며 운영 서버에 연결하지 않았다. 새 서비스 모듈은 실험에서 지정한 등록·조회·확정·취소와 내부 함수 경로를 지원하는 범위이며 일반 웹 API 전체를 교체하는 용도가 아니다.

생산 모듈·SQLite 합성 검사 66개, 작은 선별 실행기 검사 21개, 독립 수치 검사기 검사 12개를 합친 99개 검사가 실패·오류·생략 없이 통과했다. 기존 700개 소스와 새 생산·검사 12개, 새 선별 실행기·검사 2개를 합친 714개를 고정했다. 동결 SHA는 `94c814b22424b9fdd88449b5c5d5e88bf27b657b2e6029c097f6e5d911f7afe5`다.

선별 규칙은 두 자료 각각에서 환자가 최대 2명인 환경 중 원래 색인이 가장 빠른 6개씩을 고르는 것이다. 성공 여부·대기·회신 결과로 선택하지 않았다. 선택된 색인은 `[2,3,5,6,14,17,245,248,249,250,253,259]`이고 실제로는 모두 환자 1명인 환경이다. 따라서 다중 환자 간 경쟁을 평가한 자료가 아니다.

case6의 P01이 179초에서 177초로, case17의 P01이 121초에서 120초로 선정됐다. 두 환자의 도착도 같은 만큼 빨라졌다. 세 비교군의 기존 성공을 모두 보존했고 Tailwait 대비 새 개인 대기·도착 증가는 없었다. 기존 6명의 총 문의는 32 → 33건으로 1건 늘었고 추가 6명은 22 → 22건으로 같았다. 3초 단축과 함께 문의 1건이 추가된 비용도 기록한다. 기술적인 워크플로 오류는 0개이고 원래 모듈의 바인딩 식별자·정책 레지스트리·설치 집합 전후 비교도 12개 모두 같았다. 임의의 내부 가변 객체까지 모두 재귀적으로 검증했다는 뜻은 아니다.

원문 12개를 각각 전부 읽은 독립 수치 검사는 회계와 출력 가드 모두 통과했다. 증빙 SHA는 `de6a4ab3f45cb640401f3e03faa0c01ed509b1bd5420d133e229be965229c082`다. 원래 27개 조건은 실패이고 연구용 14개 조건만 통과했다. **이 단계에는 완전한 정책·FIFO·공개 입력의 의미감사가 없으며 `semantic_verification=false`다.** 원래 목표 9·9·17개도 이 12환경에서 재산술하지 않았다. 기존 자료와 크기 조건으로 고른 선별 결과이므로 별도 확대·새 독립 자료 검증·채택을 자동 허용하지 않는다.

별도 표준 라이브러리 관측 도구가 새 원문 12개를 다시 읽어 기록된 조기 판단 15회의 공개 불가 회신, 직전 실제 판단의 이벤트 접두부, 중복 소비 방지, 기록된 부모 제안의 복사와 다음 검토 상한을 확인했다. 추가 도구의 합성 검사 12개도 통과했다. 관측 결과 SHA는 `29f4404e11b7f380966fa8feceee7913b654c9a4a79240bd56bdff5c619bf2b0`다.

예를 들어 case17의 119초 조기 판단에서는 기록된 부모 H의 다음 제안이 134초였지만, 기존 예정 시각인 120초를 유지했다. 이는 원래 검토 일정을 늦추지 않는 보호 조건이 실제 기록에서도 적용됐음을 보여준다.

이 관측은 나머지 비조기 판단 90회, 첫 공동 판단, 호출되지 않은 추가 판단의 누락, 실패한 캡처 경로, 전체 FIFO·수학·공개 입력의 의미를 검증하지 않는다. 부모 H 함수를 다시 실행한 것도 아니다. 따라서 원래 선별 보고서의 `semantic_verification=false`를 바꾸지 않는다. 도구별 원문 읽기 횟수는 따로 기록하며 전체 작업에서 한 번만 압축을 풀었다고 주장하지 않는다.

## 반복 확률 계산을 줄이는 시제품

별도 `cohort_recourse_memo_model.py`는 원래 Recourse `score_owner` 한 번의 호출 안에서 동일 병원·문의 시점에 대한 구간 확률 배열만 재사용한다. 원래 검색 순서·동률 처리·합산과 곱셈의 순서·반환 증빙은 유지한다. 캐시는 호출이 끝나면 사라지고 다른 환자나 다른 대안의 상태와 공유하지 않는다. 정수·실수·양수와 음수 영을 구분하며, 지원하지 않는 값은 원래 계산 경로로 보낸다. 실패한 계산은 저장하지 않고 캐시 배열은 불변 튜플로 보관해 매번 새 목록을 돌려준다.

합성 검사 19개가 통과했고 작은 입력 28개에서 전체 반환값과 입력 불변성이 원래 함수와 일치했다. 사전·목록의 순서, 정확한 타입과 `float.hex`까지 비교했다. 원 함수 본문을 바탕으로 캐시를 끈 비교 경로와 켠 경로를 단일 계측한 결과는 다음과 같다.

| 계측한 내부 계산 | 캐시 끔 | 질량 배열 캐시 켬 |
|---|---:|---:|
| 구간 확률 배열 계산 | 461회 | 131회 |
| 그 배열 계산 안의 CDF 평가 | 8,974회 | 2,655회 |

일부 동시 문의가 가득 찬 예에서는 6회 → 6회로 줄지 않았다. 실측 가속률·전체 정책 판단 지연·환자 대기 개선을 측정한 것은 아니다. 여러 번 반복한 성능 벤치마크도 아니며, 별도 scalar CDF 캐시는 적용하지 않았다. 예외·비유한 값의 우회와 실패 미저장 검사를 포함했으나 비유한 키와 실패 계산을 조합한 경우 자체는 따로 실행하지 않았다는 한계도 기록했다.

이 시제품은 두 문의 정책이나 이번 700개 소스의 감사에 연결하지 않았다. 생산 정책과 과거 증명을 바꾸지 않았으며 기존 부모 수학 증명의 캐시 재사용도 적용하지 않았다. 원 Recourse 소스 SHA는 `e776bd643611a9ce33cbfa3fdbd8f05042fae755c20be5e0a1f4bddfdcebc2de`, 최종 시제품 검증 기록 SHA는 `8accaaf803ce90b0ce7e7ba07ef95ae2e9937c672f48307fde6fc566e9fbb5e0`이다.

## 별도 선별과 시제품의 보관

두 보관 도구는 압축을 풀거나 정책·모델·의미감사를 다시 실행하지 않고 소스·문서 외 메타데이터·압축 파일의 바이트 SHA 연결만 확인했다. Declinewake 보관에는 소스 714개·보관 파일 22개·압축 원문 12개가 있고, Memo 보관에는 소스 2개·원래 수학 소스 4개·증빙 파일 2개가 있다. 공유 문서는 이 두 보관에 묶지 않고 최종 통합 기록에서 연결한다.

- Declinewake 선별 보관 SHA: `467bb320d97ae61388e2742d5ada1932bd8515757d2d62435b8e8c909f2caee9`
- Memo 시제품 보관 SHA: `4c3443a8b4455c41f5346ee158497ffd15b2e02ff46c09b622fde384d0efaf37`

각 보관의 검증 범위를 넘겨 해석하지 않는다. 모든 실험은 합성 자료이며 이번 선별·확대 자료는 이미 관측한 개발 자료다. 새로운 독립 자료의 성능이나 임상 효과를 입증한 결과가 아니다. 감사의 `audited_numeric_fields`는 정확한 접두부의 사례별 수치 합계이며 `mean_*` 필드의 합을 전체 환자의 평균으로 해석하지 않는다.

이번 추가 실험으로 기존 Tailwait 연구 기준안을 교체하지 않았다. 따라서 그 기준안의 Stoploss 대비 기존 자료 총 대기 24초 단축과 추가 자료 70초 단축을 유지한다. 운영 기본값 `fixed_3`도 유지한다. 후속 검증의 우선 대상은 불가 회신 후보의 다중 환자 경쟁과 문의 부담이며, 계산 시제품은 정책에 연결하기 전에 더 넓은 입력의 동등성과 실제 판단 시간을 검증해야 한다.
