# 수동·음성 입력과 병원 검토시간 평가

2026-10-30. 실제 참여자의 사용성 측정은 아직 없다. 아래 도구와 빈 양식은 실험 준비물이다. 합성 문장 추출 정확도, 과거 인식문 재생 성공, 서버 API 실행시간을 실제 입력시간이나 병원 업무시간으로 바꾸어 발표하지 않는다.

## 산출물과 실행

`usability_eval/`는 기존 서버·화면을 수정하지 않는 독립 평가기다. 실제 자료와 합성 시험자료를 분리하며, 빈 자료의 결과는 **미측정**이다.

```powershell
python -m usability_eval prepare --output outputs/usability_evaluation_20261030/new_preparation
python -m usability_eval evaluate --input outputs/usability_evaluation_20261030/new_preparation/measurement_template.csv --output outputs/usability_evaluation_20261030/new_results
python scripts/test_suites.py python test_usability_eval -v
```

출력 폴더가 이미 있으면 실행을 거부한다. `prepare`는 빈 CSV·JSON, 프로토콜과 미측정 보고서를 만든다. `evaluate`는 검증한 원자료, 입력 SHA-256, 평가 코드 스냅샷·해시, JSON·Markdown 보고서를 새 폴더에 저장한다. 기존 DB·외부 API에는 접근하지 않는다.

현재 준비본은 `outputs/usability_evaluation_20261030/preparation_v1/`이다. 평가 완료를 뜻하지 않는다.

## 실험 절차

1. 같은 가상 과업을 수동 입력과 음성 입력으로 수행한다. 정상 입력, 누락·수정, 조건 변경 과업을 미리 고정한다. 실제 환자자료는 쓰지 않는다.
2. 익명 참여자 ID를 정하고 모집 대상이 학생인지 현직자인지 별도 기록한다. `participant_role`은 과업의 역할이며 자격을 증명하지 않는다.
3. 과업·참여자별로 두 방식 순서를 교차 배치한다. 한 방식만 연습한 뒤 다른 방식과 비교하지 않는다. 두 방식에서 같은 안내·기기·성공 기준을 사용하고 화면·엔진 버전을 기록한다.
4. 과업 시작부터 최종 확인·전송 성공까지 같은 단조 시계로 잰다. 발화·STT 대기·수정·확인 시간을 모두 포함한다. 실패·중단은 중단 시각까지 잰 뒤 사유를 적는다. 서버 계산시간은 이 값의 대체물이 아니다.
5. 관찰자가 최종 오입력, 수정 행위, 터치를 같은 정의로 센다. 버튼 답변은 음성 인식 성공으로 세지 않는다. 실제 조작을 관찰하지 못한 값은 빈칸이다.
6. 병원 역할 과업은 문의 상세를 연 뒤 자원·근거를 실제로 검토하는 활동 구간을 따로 관찰한다. 동시에 겹친 구간은 한 번만 센다. 대기시간과 실제 검토시간을 구분한다.
7. 실패 시도를 지우고 성공 시도로 교체하지 않는다. 재시도는 두 방식의 같은 반복 번호 `attempt`를 늘려 보존한다. 한 방식만 남은 경우 짝누락으로 보고하며 비교 평균에서만 제외한다.
8. 관찰 기록·입력·버전을 동결한 다음 평가한다. 개선 후 같은 자료를 독립 검증으로 재사용하지 않는다.

전체 입력 화면의 계측 연결은 별도 작업이다. 지금은 관찰자 기록을 가져오는 방식이다. 서버의 `work-activities`는 활동 구간 근거로 쓸 수 있으나 현재 환자 한 명 범위의 합계라 같은 사람이 여러 환자를 처리한 겹침을 통합하지 않는다. UI가 시작·종료를 실제로 기록했는지 확인해야 한다. `speech_eval.metrics.timing_summary`의 실제 측정 구간과도 단위(ms)를 맞추되, STT 콜백만 있는 자료로 총입력시간을 추정하지 않는다.

## CSV·JSON 규칙

CSV 헤더는 생성된 양식을 그대로 쓴다. JSON은 `{"schema_version":1,"records":[]}` 형식이다. 알 수 없는 필드·중복 기록·동일 비교칸은 거부한다.

| 항목 | 값·정의 |
|---|---|
| `record_id` | 모든 행에서 유일한 시도 ID |
| `participant_id` | 가명. 실명·연락처를 넣지 않음 |
| `participant_role` | `paramedic` 또는 `hospital`; 실제 직업이 아니라 맡은 과업 |
| `task_id`, `attempt` | 두 방식이 같은 가상 과제·반복을 공유. 반복은 1 이상 정수 |
| `method` | `manual` 또는 `voice`. 병원 과업에서는 연결된 수동/음성 입력 조건을 뜻하며 병원이 음성 입력했다는 뜻이 아님 |
| `source` | 실제 사람이 수행한 `human`, 자동 실행·만든 자료 `synthetic` |
| `status` | `completed`, `failed`, `abandoned`. 실패·중단의 `failure_reason` 필수 |
| `order` | 해당 짝에서 수행 순서 1 또는 2. 두 방식의 순서가 같으면 거부 |
| `elapsed_ms` | 시작부터 성공 또는 중단까지 관찰한 총시간. 모든 시도에 필수 |
| `error_count` | 최종 제출값의 잘못된 항목 수. 미완료이면 관찰한 상태를 세거나 미측정으로 둠 |
| `correction_count` | 잘못 입력된 항목을 바로잡은 행위 수. 연속 키입력은 한 수정 행위 |
| `touch_count` | 관찰된 탭·클릭 수. 키보드 글자 수와 섞지 않음 |
| `hospital_review_ms` | 병원 역할 한 사람의 실제 검토 활동시간. 총시간을 넘으면 거부 |
| `inquiry_count` | 같은 과제의 문의 건수. 실제 검토시간을 대체하지 않음 |
| `interface_version`, `engine_version` | 사용한 화면·엔진 식별. 수동 입력 엔진은 `none` 등 명시 |

숫자는 유한한 0 이상 값, 횟수는 정수다. 선택 지표의 빈칸은 0이 아니라 미측정이다. `elapsed_ms`는 실패 시도에서도 필수라 실패 전에 들인 시간을 보존한다. 한 참여자가 동일 역할·과제·반복·방식을 여러 번 기록하면 오류가 나므로 재시도는 반복 번호를 바꾼다.

## 보고와 해석

실제/합성, 역할, 방식별 전체·완료·실패·중단 수와 완료율을 보고한다. 전체 시도의 관찰 지표와 완료된 시도의 지표를 따로 보존한다. 평균·중앙값·p95(최근접 순위)·최솟값·최댓값·지표별 유효 표본과 결측 수를 JSON에 저장한다.

같은 출처·참여자·역할·과제·반복에서 두 방식이 모두 완료됐을 때만 **음성 − 수동** 차이를 계산한다. 양수 최댓값은 관찰된 개별 최대 악화다. 짝이 있어도 실패·중단이 있으면 완료시간차를 만들지 않으며 그 수를 별도 보고한다. 참여자 수와 과업 수를 구분하고 한 사람이 여러 과업을 수행했다고 여러 참여자로 세지 않는다. 소표본 기술통계를 모집단 효과로 해석하지 않는다.

병원 부담 감소는 문의 수만으로 판정하지 않는다. 실제 검토시간·추가 질문·취소 후 불필요 검토를 관찰하고, 실제 검토시간이 비어 있으면 감소 여부도 미측정이다. 본 도구는 임상 효과, 실제 현장 사용성, STT 정확도를 대신 검증하지 않는다.
