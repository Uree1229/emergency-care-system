## 800ms 적용 범위

- `paramedic-ui/command-practice.js`는 `CommandCommitGate`를 사용합니다. 자동 종료를 켰을 때 후속 문맥 보류, 끄면 관찰 기록입니다.
- **main의 `quick-test.js`는 Gate를 import하지 않습니다.** 연습 화면에 800ms가 있다고 업무 음성 화면에도 적용됐다고 기록하지 않습니다.
- 공용 PC의 미커밋 quick 화면에는 더 최신 작업이 있을 수 있습니다. 팀원이 그 파일을 통째로 복사해 main 또는 자기 화면을 덮어쓰면 안 됩니다.
- 업무 화면 적용이 필요하면 서버 담당/통합 담당과 범위를 정하고, 명령 뒤 본문·부정·시각·인용·환자 전환·늦은 인식의 기존 회귀를 유지하는 별도 작업으로 다룹니다.

| 로컬 후속 기능 | main에서 연결하면 안 되는 경로 |

| 상태별 다음 처리 안내 | `GET /api/voice/sessions/{sid}/workflow` |
| 원문 대조 확인 | `GET …/record-review`, `POST …/record-review/acknowledge` |

## 서버 담당·통합 담당이 이어서 할 것

1. 로컬 미커밋 코드와 main의 차이를 검토하고, 사용할 서버/API 버전을 통합해 공지. dev1/dev2가 개별적으로 v1.4를 가져와 분기하지 않도록 조정.
2. 신규 개발 PC의 full 런타임·솔버 고정 환경과 공통 서버·LAN HTTPS 접속 준비. 독립 PC의 localhost DB는 서로 공유되지 않음.
3. 제한 해제 담당자 누락(`DELETE` handler가 UI의 `handled_by`를 읽지 않는 현재 경로)과 제한 연장/등록의 응답 유실 계약을 확인. dev2의 JSON 필드 변경만으로 해결되는 문제가 아님.
4. 보호된 배정 기준·DB 마이그레이션·수용 유효기간·자원 원장·공공 자료 수집과 API 키·백업/복구 관리. UI에서 직접 점유를 조작하거나 기한을 늘리지 않음.
5. 실제 참여자 시험의 설계·동의·자료 보관·결과 통합. 미실행·실패·중단·모의 시험을 성공률에서 임의 제외하지 않음.

## 공통 상태 구분

**후보 추천 → 병원 수용 응답 → 목적지 확정 → 출발 → 도착**은 각각 다른 상태입니다. 채팅으로 ‘받겠다’고 쓴 것이 수용 API 응답을 대신하지 않고, 수용 응답만으로 목적지가 바뀌지도 않습니다. 이송 중 조건 변화는 병원 재확인과 새 병원 수용, 사람의 명시 판단을 거쳐 처리합니다.

`ed_bed`·`special_team`의 현재 모델 범위, 공개 관측·운영 자원·환자별 수용의 구분, 실제 사용하지 않는 역할을 인증된 것으로 표시하지 않는 원칙을 유지합니다. 모든 새 개발·검사는 합성 환자와 전용 개발 DB에서 시작합니다.

역할별 자세한 API/완료 기준은 [dev1](dev1/README.md), [dev2](dev2/README.md)를, 실행과 검증의 한계는 [공통 실행 안내](COMMON_RUNTIME.md)를 참고합니다.
