# 전체 환자 대기시간 감소 실험

2026-10-15 · 합성 시뮬레이션 · 기존 안정화 C1 대비

## 결과

P03에게 대기를 넘기는 동률 선택을 넘어, 병상이 비어도 보고·재문의 시각을 기다리던 시간을 줄였다. 검증 시드 6개, 31개 환경, 20개 분기 총 3,720회 실행을 비교했다. 아래는 각 분기의 동일한 환자 실행 492건 전체를 합한 결과다.

|---|---:|---:|---:|
| 전체 대기 합, 환자·분 | 5,241 | 4,951 | −290, 5.53% 단축 |
| 우선순위 가중 전체 대기 합 | 20,910 | 19,750 | −1,160 |
| 요청→처치 시작 합, 환자·분, 미처치 관찰 종료 제한 | 7,164 | 6,840 | −324 |

전체 대기는 탐색 중 대기, 병원 도착 후 처치 대기, 전원 대기의 합이다. 이동과 처치 시간은 제외한다. 처치를 시작하지 못한 환자도 관찰 종료까지 포함한다. 따라서 완료 환자만 남기는 평균 비교가 아니다. 요청→처치 시작 지표는 이동도 포함하므로 전체 대기와 감소량이 다르다.

## 개선 구조와 효과 분리

1. **현재 자원 변화 보고:** 병원이 실제로 변경된 용량·사용량 필드만 전달하는 별도 합성 갱신 계약을 추가했다. 기존 보고와 재확인의 지속 누락 필드를 그대로 마스킹하고 병원 무응답도 유지한다. 설정된 통지 지연 이전에 사용할 수 없다. 미래 퇴실·복구·처치 종료 시각은 정책에 제공하지 않는다.
2. **수신 사건에 따른 재검토:** 이번 시각에 받은 유효한 보고로 필요한 자원이 충분해졌다면, 문의나 수용 응답이 남아 있지 않은 탐색 환자에게 해당 병원 재문의를 시작한다. 우선순위, 요청 시각, 환자 ID 순서를 유지하고 가까운 호환 병원을 선택한다. 새 환자별 수용 응답과 최종 충돌 검사를 반드시 거친다.
3. **기존 동률 안정화 유지:** 미배정 우선순위 합과 가중 이동시간이라는 기존 C1 목적값은 유지한다. C1 목적함수 자체를 전체 이송 시간 최적화로 바꾼 것은 아니다.

| 분기 | 현재 변화 보고 추가 | 즉시 재검토 | 전체 대기 합 |
|---|---|---|---:|
| `stable_responsive_C1` | 없음 | 없음 | 5,241 |
| `review_stable_C1` | 없음 | 적용 | 5,211 |
| `updates_stable_C1` | 적용 | 없음 | 5,059 |
| `total_wait_C1` | 적용 | 적용 | 4,951 |

같은 기존 보고에서 재검토만 적용한 효과는 30 환자·분이다. 추가 보고가 있는 상태에서 재검토를 더한 효과는 108 환자·분이다. 두 효과는 상호작용하므로 전체 290 환자·분을 단순히 더하거나 C1 배정 규칙만의 성과로 설명하면 안 된다. 현재 변화 보고가 제공되지 않는 운영 환경에는 해당 보고 효과를 그대로 적용할 수 없다.

## P03 사례

기존 대안 없는 병원 사례 6개에서 P01·P02는 모두 기존과 동일하게 4분에 도착하고 처치를 시작했다. P03의 도착·처치 시작은 다음과 같다.

| 검증 시드 | 기존 P03 | 개선 P03 | 단축 |
|---|---:|---:|---:|
| 26101 | 41 | 40 | 1분 |
| 26102 | 37 | 34 | 3분 |
| 26103 | 33 | 32 | 1분 |
| 26104 | 41 | 38 | 3분 |
| 26105 | 37 | 37 | 동일 |
| 26106 | 41 | 38 | 3분 |

세 환자의 전체 대기 합은 6개 사례 합산 **224→213 환자·분**이다. 26102 사례에서는 병상이 실제 비는 30분에 현재 사용량 보고를 받고 재문의를 시작한다. 31분에 새 수용 응답을 확보하고, 이동 3분 후 34분에 도착한다. 병상이 점유된 시간은 건너뛰지 않는다. 이 사례는 이번 응답·이동 조건에서 해제 후 응답 1분 + 이동 3분의 하한에 도달했다.

## 대표 조건과 남은 대기

| 조건, 사례당 | 기존 대기 | 개선 대기 | 해석 |
|---|---:|---:|---|
| 병상 해제 후 긴 재문의 간격 | 14분 | 7분 | 현재 변화 보고와 재검토가 함께 필요 |
| 같은 지연 피드, 재검토만 | 14분 | 9분 | 추가 정보 없이 재검토 절차 개선 |

지속 정보 누락으로 인한 미처치 30건도 남아 있다. 확인되지 않은 정보를 가능한 자원으로 바꿔 개선을 만들지 않는다. 이번 표본에서 환자별 대기·관찰 종료로 제한한 처치 도달 시간 증가와 처치 기회 상실은 없었지만, 다른 수요·자원·보고 조건에서도 무조건 악화가 없다는 보장은 아니다.

## 비용과 범위

검증 186개 사례에서 기존 대비 환자 수용 문의는 1,029→988건, 자원 재확인 요청은 709→690건이다. 대신 개선 분기에는 현재 변화 보고 **748건**이 추가된다. 통신량 전체가 감소했다고 주장하지 않는다. 자원 샘플링·전달과 재검토의 실제 실행시간을 별도 기록했으며 시뮬레이션 분 단위 시계에는 더하지 않았다.

병상 수, 환자 수, 처치시간과 물리적 변화는 분기 간 동일하다. 실제 병원 데이터나 카카오 경로 기반 성능 결과가 아니다. 운영 서버, API, DB, 환자·병원 UI에는 적용하지 않았다. 실제 적용에는 병원의 현재 자원 보고 인터페이스가 필요하다. 기존 최종 확정 단계의 즉시 권위 있는 자원 검사 가정도 유지된다.

## 검증과 보존

- 개발: 새 시드 25101~25103, 93사례 × 20분기. 소스·설정·런타임 61개 파일 잠금 후 검증 실시.
- 검증: 미사용 시드 26101~26106, 186사례 × 20분기. 검증 결과로 재튜닝하지 않음.
- 시드 7·8 구조 검증: 248개 요인 분기에서 독립 감사와 지표 일치.
- 관련 테스트 **727개 통과**. 확장 실행에 포함됐던 기존 로컬 HTTP 테스트 6개는 환경의 `WinError 10013`으로 연결되지 않아 이 통과 수에서 제외했다. 새 시뮬레이션 테스트는 모두 포함한다.
- 저장된 검증 JSON을 엔진·솔버를 실행하지 않는 감사기로 다시 검사: 배정 결정 6,738개, 보고된 CP-SAT 모형 증거·정확 재검사 3,851개, 자원 변화 보고 1,496개, 재검토 552개 확인. 두 보고 적용 분기의 보고 수를 합산한 값이다.
- 실제 자원 제약 위반 0건. 현재 보고된 모형의 검증이며, 전체 이송 과정의 전역 최적성을 주장하지 않는다.
- 이전 소스·설정·결과·문서 265개 해시 유지. 새 잠금 소스 61개도 일치.
