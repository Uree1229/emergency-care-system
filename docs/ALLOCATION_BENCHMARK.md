# 배정 규칙과 CP-SAT 비교

2026-10-13. 같은 시각에 확보한 환자·수용 응답·현재 자원·예상 이동시간을 복사해 **R0/R1/R2/R3/C1**을 비교했다. 문의가 완료된 시점의 배정 품질을 검사하는 실험이다.

## 비교 방식

| 규칙 | 선택 방식 |
|---|---|
| R0 | 현재 유효 응답 중 먼저 회신한 병원 우선 |
| R1 | 현재 유효 응답 중 예상 이동시간이 짧은 병원 우선 |
| R2 | 예상 이동시간에 자원 경쟁 비용을 더하는 기존 휴리스틱 |
| R3 | 동시 환자를 정확 열거. 조합 20,000개 초과 시 기존 순차 대체안 사용 |
| C1 | R3와 동일한 목적·제약을 CP-SAT으로 계산. 단계별 최적성·시간 제한·대체 실행 기록 |

R3/C1의 목적은 **미배정 우선순위 합을 먼저 최소화하고, 그 값이 같으면 우선순위 가중 예상 이동시간 합을 최소화**하는 것이다. 임상 기준이 아닌 실험 가중치 high=4, medium=2, low=1을 사용한다. 따라서 전체 배정 인원 최대화와 다른 결과를 낼 수 있다.

모든 규칙은 같은 최초 입력을 받고, 환자 처리 순서는 우선순위·요청 시각·ID로 고정한다. 기존 점유와 확정된 도착 예정 수요, 도착 후 대기 수요를 잔여 자원에서 뺀다. 현재 수용 응답이 없는 병원으로는 배정할 수 없다. 수용 응답 후 잔여 자원이 줄어든 후보도 확정 전에 다시 검사한다.

R2는 현재 구조적으로 수용 가능한 병원을 잠재적 대안으로 센다. 실제로 확보한 수용 응답만으로 희소성을 계산하는 방법은 이후의 개선 후보이며, 이번 기존 규칙을 유리하게 수정하지 않았다.

## 개발·검증 분리

- 개발: seed8101–8108 × 8개 유형 = **64사례·320실행**.
- 소스·설정·Python/OR-Tools 버전을 `config/allocation_benchmark_lock.json`에 잠갔다.
- 검증: 새 seed9101–9120 × 같은 8개 유형 = **160사례·800실행**. 검증 결과를 보고 설정을 바꾸지 않았다.
- 유형: 여유 자원, 첫 회신과 이동시간 충돌, 희소 후보 경합, 복수 자원, 우선순위와 인원 수 충돌, 기존 점유·확정·대기, 수용 후보 없음, 14–16명 동시 배정.
- 생성기·CP-SAT·실험 실행기·기존 규칙·독립 검증기의 잠금 소스는 `outputs/source_snapshots/allocation_benchmark_20261013/`에 보관했다.

## 검증 결과

| 조건 | 결과 |
|---|---|
| 작은 문제 140개 | C1과 R3의 목적값 모두 일치. 독립 전수 열거로 재확인 |
| 큰 동시 배정 20개 | C1 우수 8개 · 동률 12개 · 열세 0개 |
| 큰 문제의 우수 8개 세부 | 1개는 미배정 1명→0명, 7개는 동일한 미배정 우선순위 합에서 가중 이동시간 합 감소 |
| 희소 후보 경합 20개 | R0/R1/R2는 2명 중 1명 배정, R3/C1은 2명 배정 |
| 여유 자원·복수 자원 등 | 차이가 없는 조건도 그대로 보고 |
| 수용 후보 없음 20개 | 모든 규칙 미배정. 확보하지 않은 병원이나 자원을 만들어 내지 않음 |
| 자원·수용 응답 제약 위반 | 800실행 모두 0건 |

큰 문제에서는 R3가 20개 모두 열거 한도를 넘어 순차 대체안을 사용했다. 따라서 이 구간은 **CP-SAT과 R3의 대체안 비교**다. 정확 열거보다 CP-SAT이 더 좋은 최적값을 만들었다는 뜻이 아니다.

실제 솔버를 실행한 140개는 두 목적의 최적성을 증명했다. 후보가 전혀 없는 20개는 솔버를 실행하지 않은 자명한 미배정(`OPTIMAL_EMPTY`)으로 따로 집계했다. 이 최적성은 현재 스냅샷과 정의한 목적에만 적용된다.

검증 PC의 큰 문제 계산시간은 C1 중앙값 **7.33ms**, 최장 **84.09ms**였다. R3의 순차 대체안 중앙값은 **0.082ms**였다. C1은 더 많은 계산으로 일부 사례의 해를 개선했다. OR-Tools 초기 로딩은 실행 시간 비교 전에 완료했다. 이 측정은 해당 PC·입력 크기의 값이며 실서버 지연 보장이 아니다.

평균 가중 이동시간만 비교하면 더 많은 환자를 배정한 방식이 불리해질 수 있다. 원시 JSON에는 미배정 수·우선순위별 결과, 양쪽 모두 배정된 같은 환자의 이동시간 차이와 분모를 함께 저장했다.

## 실행과 결과 파일

OR-Tools는 `requirements-portable.txt`의 버전을 사용한다. 개발 환경의 `.solver_deps`를 쓸 경우 다음처럼 실행한다.

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) '.solver_deps'
python -m simulation.allocation_benchmark --phase development --lock
python -m simulation.allocation_benchmark --phase validation --lock-file config/allocation_benchmark_lock.json
python -m simulation.allocation_benchmark_audit simulation_results/allocation_validation_20261013.json --lock-file config/allocation_benchmark_lock.json
```

위 명령은 같은 실험을 재현하는 용도다. 이미 확인한 검증 seed를 새 개선안의 독립 검증으로 다시 사용하면 안 된다. 코드·설정을 바꾸면 잠금 검사가 실행을 거부한다. 새 개선은 보관한 소스와 기존 보고서를 유지하고 새로운 개발·검증 계획으로 분리한다.

- 결과 표: `simulation_results/allocation_validation_20261013.md`.
- 원시 입력·배정·솔버 기록: `simulation_results/allocation_validation_20261013.json`.
- 독립 감사: `simulation_results/allocation_validation_20261013_audit.json`.
- 개발 결과도 같은 경로의 `allocation_development_20261013.*`로 보관한다.

새 기능·기존 배정/재생 회귀 **118개**가 통과했다. 독립 검증기는 실험 실행기의 World·지표 함수를 가져오지 않고 원시 JSON에서 자원 사용, 목적값, 분모, 요약 통계, 누락 사례, 솔버 증명 상태를 다시 계산했다.

## 연결 범위와 다음 작업

`Policy(rule='C1', time_limit_seconds=1.0)`으로 기존 문의·회신 시뮬레이터의 공동 배정 단계에서도 실행할 수 있다. 실제 엔진에서 수용 회신 뒤 C1이 배정하고, 시간 제한이 0이면 검증된 대체안을 쓰는 통합 검사를 완료했다. 운영 서버의 자동 목적지 확정은 추가하지 않았다.

이번 결과로 **병원 선정시간·실제 도착시간·치료·전원·예후의 개선율**을 주장할 수는 없다. 문의 정책을 고정해 전체 흐름을 돌려도, 배정 결과가 달라지면 이후 병원의 응답과 자원 상태가 달라진다. 고정 배정 문제의 비교와 전체 흐름의 정책 비교를 별도로 보고해야 한다.

다음 우선순위는 다음과 같다.

1. 완료: C1을 전체 지도 재생 분기에 추가하고, 같은 문의 정책의 미배정·선정·모의 도착·재배정 지연을 비교했다. [전체 흐름 결과](ONLINE_ALLOCATION.md). 고정 입력 비교와 구분한다.
2. 50·100명 등 더 큰 동시 묶음과 빡빡한 시간 제한에서 최적 증명·실행 가능한 해·순차 대체율을 측정한다.
3. 현재 자원 정보가 누락되거나 오래된 조건을 추가하고, 병원 응답으로 확인된 정보만 사용할 때의 차이를 본다.

현재 데이터는 완전한 현재 자원을 가정한 합성 입력이다. 작은 문제에서 정확 열거가 이미 충분하고, CP-SAT의 추가 효과는 큰 묶음의 일부 사례에서 확인됐다는 결론으로 발표하는 것이 정확하다.
