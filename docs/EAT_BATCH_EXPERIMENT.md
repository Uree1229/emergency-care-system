# EAT 문의 계획 개선: 지금 실행 가능한 문의 묶음 비교

사전 단계 기준을 통과하지 못해 후속 새 성능 실행을 진행하지 않았으며, 이 후보는 채택하지 않는다. 최종 단계는 **기존 자료 회귀 확인**다. 기존 서비스 기본값 `fixed_3`은 유지했다.

## 바꾼 한 가지

잔여 업무 추정 R은 유지하면서, 가상의 미래 시점 문의 계획을 현재 실행 가능한 문의 묶음의 열거로 바꿨다. 현재 이동시간순 후보 최대 여섯 곳·동시 문의의 남은 슬롯 최대 네 곳에서 가능한 부분집합을 빈 집합부터 최대 **57개** 비교한다. 고정 추정 모델의 최소 비용과 1e-9 이내이면 문의 수가 적은 묶음, 원래 후보 조합 순으로 선택한다. 대기 문의가 없을 때 문의가 멈추지 않도록 한 곳에 문의하는 기존 안전 예외도 유지한다.

모델은 현재 공개된 관측·자기 대기 문의·잔여 선행 업무·이동시간과 15초 문의 비용을 사용한다. 새 회신 예측 모델·실제 처리 인원·숨은 상태·미래 정보를 추가하지 않았다. R의 잔여 업무 및 기존 자기 문의 수용 분포, 이동시간순 여섯 병원, 동시 문의 4곳, 최초 유효 수용 회신 즉시 확정은 그대로다. 기각한 shortlist 선별을 섞지 않았다. 이는 현재 고정 모델의 실행 가능한 묶음 비교이며 전체 환자의 대기나 실제 의료 결과의 전역 최적성을 뜻하지 않는다.

## 단계와 고정 기준

1. **기존 자료 회귀 확인(repair)**: R에서 네 환자를 복구했던 이미 확인된 120개 환경 전체를 사용했다. 새 후보만 환경당 한 분기씩 **120개 신규 실행**, 부모의 기존 다섯 분기 **600개는 캐시 참조로 명시**했다. 원래 네 환자를 각각 지키는지와 혼합·스트레스 전체에서 R 성공 환자를 잃지 않는지 검사한다. 이 자료는 설계에 사용한 학습 자료이며 독립 검증이 아니다.
2. repair 보고서·감사·잠금이 통과한 경우에만 새 개발 **120개 환경 × 6분기 = 720개**를 실행한다. 혼합 96개와 스트레스 8유형 × 3 seed다. 비교 정책도 모두 새로 실행한다.
3. 새 개발 통과 후에만 별도 검증 **368개 환경 × 6분기 = 2,208개**를 한 번 실행한다. 혼합 320개와 스트레스 8유형 × 6 seed다. 기존 성과를 보고 후보·설정·판정 기준을 바꾸거나 검증을 반복하지 않는다.

최대 신규 실행은 120 + 720 + 2,208 = **3,048분기**이며 부모 캐시 600개는 별도로 센다. 이번 실제 실행은 신규 **120개**, 캐시 **600개**다.

주 지표 **W는 환자 발생부터 병원 선정까지의 대기**이며 실패 환자에게 300초를 부여해 전체 환자를 집계한다. 이동·도착 후 처치 대기를 더한 지표가 아니다. **J는 선정 성공 시 추정 도착시간, 실패 시 300 + 1,500 = 1,800초인 환자 평균**이다. 실패 비용 600·3,000초 민감도도 원 보고서에 남겼다.

각 단계의 통과 조건은 **기존 EAT와 R 모두보다 W 합계가 작고**, R 성공 환자를 혼합·스트레스 전체에서 잃지 않으며, 실패 수·J가 두 기준보다 늘지 않고, 문의 수·병원 검토 업무가 `fixed_3` 이하인 것이다. repair에서는 정확한 네 복구 환자를 각각 지켜야 한다. 검증은 EAT·R 각각에 대해 시나리오 단위 부트스트랩 10,000회의 **환자당 W 변화 95% 구간 상한 < 0**도 요구한다. W/J 주 판정에서는 스트레스를 제외하되 성공 보존 게이트에는 포함한다.

고정 소스 281개와 후보·게이트를 먼저 동결하고 608개 단계 입력의 해시를 만들었다. 새 namespace의 역할별 128비트 seed 425개는 서로 분리하고 이전 shortlist·R namespace와 보고된 검증 seed와 겹치지 않게 확인했다. 전체 과거 글로벌 파일을 다시 검색했다는 주장은 하지 않는다.

원래 R에서 복구된 정확한 네 환자의 보존 결과: **2/4**. 식별자는 동결 protocol과 보고서 `recovery_check`에 전부 남겼다.



새 개발 실행 0회, 별도 검증 실행 0회다. 후속 단계가 실행되지 않았다면 앞 단계 게이트 실패에 따른 것으로, 미실행 단계의 성과를 주장하지 않는다. 개별 지연·실패 전환을 전체 개선으로 숨기지 않으며, 모든 미래 상황의 무손해는 주장하지 않는다.

## 검사·원문 감사·보존

선택한 기존 EAT·확정·잔여 업무와 새 묶음 정책·기록 연결·감사·단계 잠금 검사 **119개**가 통과했다. 과거 전체 프로젝트 검사 재실행은 아니다. 정상 잠금과 실패·변경 잠금의 단계 진입 경계도 검사했다.

신규 저장 gzip **120개·120개 완전 분기**와 명시한 기존 repair 캐시 gzip **120개·600분기**의 압축/해제 SHA256, 동결 입력 해시, 같은 초기 스냅샷·환경, 환자별 보고서, W/J/실패·문의 및 실제 `review_started` 업무 합계를 대조했다. 두 주 기준의 부트스트랩 구간과 전체 R 성공 보존, 네 복구 식별자, report/audit/lock의 단계별 해시 연결도 원문에서 재집계했다. 불리한 원문 제외·성능 재실행은 하지 않았다. 감사와 최종 집계는 저장 자료만 읽고 정책이나 시뮬레이션을 실행하지 않았다.

기존 **271개 소스·67개 참조 경로**와 새 동결 **281개 소스**를 확인했다. 이 실험의 명시된 부모 캐시 120개 외의 과거 원문 증거는 이름과 해시가 고정된 부모 봉인 증명을 재사용하며, 이전 대형 글로벌 원문 전체를 재해시했다고 주장하지 않는다. 기존 `docs/README.md`, 운영 서비스·UI·실제 DB는 그대로다. 운영 채택은 하지 않았다.

검증 범위는 합성 병원 문의의 선정 대기다. 임상 예후·실제 병상 확보·도착 후 치료 대기 또는 공동 배정 H1/C1 성능을 직접 증명하지 않는다.
