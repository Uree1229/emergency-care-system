## 아직 연결하거나 검증해야 할 것

1. 연결된 모바일·병원 화면의 입력·조작 사용성을 검증하고 필요한 임상 입력 항목과 실제 위치 관측 연계를 보강. 독립 환자 DB의 공통 API 전환·수용 확인·확정·이송·대화·조건 재확인 연결은 완료.
2. 병원 웹에서 `incoming.planning`의 예상 시작시각·재확인 사유를 표시.
3. 실제 점유 종료시각을 확보해 시간대별 점유 모델을 발전. 현재 점유는 계획 기간 전체에서 유지하며, 치료시간·최대 대기는 임상 기준이 아닌 실험값.
4. 구현된 환자별 조건 재확인과 기존 솔버의 전체 계획 재확인 결과를 화면에서 일관되게 구분. 목적지는 유지하고 병원의 수용 판단 뒤 사람의 변경을 기다리는 규칙을 지킴.
5. 실제 권역 데이터를 운영 배정 서버와 CP-SAT 실험 입력으로 연결. 지도 시뮬레이션에는 8기관 위치·도로시간을 연결했지만 실제 진료 자원은 가상입니다. 현재 34기관은 솔버 32기관 제한을 넘으므로 명시적 후보 선정 또는 제한 조정 필요. 수술실·ICU·NICU·분만실은 현 솔버 미지원이며 공개 가용수는 운영 총량과 분리. 중증질환 코드 자동 매핑·운영 배정 API의 도로시간 연계와 장기 갱신 검증은 남아 있음. 심평원 신고정보·NMC 메시지는 치료조건 평가와 후보·배정 결과 API에 연결 완료.
6. B2(같은 문의 방식 + 솔버 배정) 비교와 민감도 실험.
   병원별 관측 V2는 합성 입력에서 평균 시간을 줄였고, 후속 우선순위 처리는 높은 군의 미시작을 줄이는 대신 다른 군의 미시작을 늘렸습니다. 다음은 전체 처리 수와 낮은 군의 과도한 지연을 함께 고려하는 목적 설정, 위치·도로·자원 경쟁 일반화, 확정 후 잔여 문의 취소 유무 검토입니다. 검증1001~1020·2001~2020·3001~3020·5001~5020과 중단4001~4020은 재사용하지 않습니다. 정책 수정 후에는 별도의 미사용 검증 입력이 필요합니다. 관측 V2의 서버 연결과 합성 환경 정책 비교는 완료했습니다. seed6101~6108을 개발 자료로 추가하고, 무응답·과거 상태 반전의 실패를 개선한 뒤 미사용 입력에서 평가해야 합니다. 우선순위 정책은 아직 실험 엔진에만 있습니다.
7. 로그인·병원별 접근 통제, 임상 기준 검토, 실제 병원 연동은 시연 범위 밖. 실제 환자 정보 사용 금지.
