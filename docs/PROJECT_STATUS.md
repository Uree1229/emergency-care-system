# 현재 구현 상태와 남은 작업

2026-11-12 개발 소스 기준. 구급대 단계형 화면, 병원 임상변경 검토 대기 목록과 조회 전용 자원 탭, 별도 환자 입력 앱의 공통 이송 연결을 포함한다.

## 저장소에서 사용할 수 있는 기능

| 구간 | 현재 코드 |
|---|---|
| 환자 기록 | 음성 인식문·직접 입력 저장, 항목 추출, 불확실·충돌 표시, 중요 항목 확인, 환자별 초안·기록 전환 |
| 병원 연결 | 후보 조회, 명시적 문의 시작·중지·재개, 추가 질문·답변, 수용·불가 응답, 이송자의 목적지 확정 |
| 이송 진행 | 출발, 병원 메인의 임상변경 검토 대기 목록, 조건 재확인과 유지·조정 판단, 새 수용 확인 후 목적지 변경, 이송 대화 |
| 도착·퇴실 | 병원 도착·퇴실 확인, 조회 전용 자원 탭, 목적지 확정·도착·퇴실에 따른 서버 자원 반영, 가상 외부 유입·대사 |
| 운영 | 워커·오류 상태, 알림 수신과 확인, 통화 기록·업무 계측, 백업·새 경로 복원, 실행본 명세 |
| 시험 도구 | 명령 연습, 긴 대본·독립 정답, 원음과 메타데이터 내보내기, 재생 평가·선택형 소음 비교 |

구급대 기본 화면 `/paramedic/`은 상태 기록 → 내용 확인 → 환자 등록 → 병원 연결의 단계형 흐름을 제공한다. 기존 상세 입력은 `/paramedic/?view=full` 또는 `/paramedic/legacy.html`에서 사용할 수 있다. 병원은 A2 문의 화면을 유지하며, 음성 복수 후보·문맥 검토도 함께 포함한다. 소음 비교, 복구 보완, 혈압·부정 파서와 사용성 교차 배치의 고유 로컬 변경을 통합했다.

전체 흐름 관제는 `server.flow_console_runtime`으로 실행한다. [흐름 콘솔](FLOW_CONSOLE.md), [11월 5일 팀 지시](team-handoff/20261105/README.md), [실행](RUNNING.md), [API](API.md)를 따른다.

별도 프로필 앱 `emergency-app/`은 DEV1의 음성 문진·신체 부위·단계별 요약과 주변 병원 참고 조회를 유지한다. 마지막 화면에서 동의·관측 위치를 확인한 뒤 공통 이송 건을 만들고 `/patient/?pid=…`로 연결한다. 신체 부위와 명시 확인한 음성 정보는 보조 `extra`에 보존하며 우선순위·진료 조건을 자동 변경하지 않는다. 음성은 흐름·선택 환자로 구분해 탭 세션에 2시간 보관한다. [별도 앱 실행·연결·검증](../emergency-app/README.md)

이 별도 앱의 연결 복구는 `/patient/` 수동 입력의 D01이나 환자 측 채팅 D02를 대신하는 작업이 아니다. 해당 화면은 기존 팀 작업 범위를 유지한다.

## 최신 로컬 통합 시연

`.codex-build/hospital-full-demo-20261105`는 구급대 통합 화면 기준 커밋 `240b942`와 가상 병원 연동을 결합한 별도 실행본이다. 같은 가상 환자로 등록, H01 문의·수용, 목적지 확정, 출발, 도착, 오류 원인 대조, 재전송을 브라우저와 로컬 HTTP에서 확인했다. 도착 이벤트가 원본 그대로 재전송되고 가상 수신기에 병상 1개가 한 번 반영되는 기록을 남겼다.

이 실행본의 연동 기능은 `.codex-build`에 있으며 Git의 기본 `server/`·`hospital-ui/`에는 포함되지 않는다. 실행본에 읽기 전용 MCP 조회, JSON HTTP 이벤트 전달, 실패 재시도, 확인 필요 사유·송수신 이력 대조가 있다. 재전송 전에 선행 기록 복구를 별도 검증 도구로 수행한다. 시연 순서와 기록 위치는 [DEMO](DEMO.md)를 따른다.

## 실행 설정

`server.chat_demo`는 가상 병원과 문의 워커로 시작한다. `server.team_runtime --mode full`은 프로필 검사를 거쳐 문의·배정 워커를 구성한다. 현재 운영 기준은 `config/server_allocation_baseline_20261030.json` 등 실제 설정으로 확인한다. 과거 공통 배포 묶음의 버전명과 포트 번호를 현재 모든 실행의 상태로 사용하지 않는다. [실행 모드](RUNNING.md) · [알고리즘 선택](ALGORITHMS.md)

## 남은 확인

- 발표에 쓸 고정 실행본에서 실제 마이크·휴대폰으로 전체 흐름과 소요시간을 측정한다.
- 조용한 조건과 소음 조건에서 새 발화·원음을 짝으로 수집하고 수치·부정·명령 오류를 분석한다.
- 다른 물리 PC에서 설치, 같은 환자 연결, 연결 단절·복귀, 백업·복원을 재현한다.
- 같은 참여자의 수동·음성 과업을 교차 측정하고 완료시간·수정·터치·병원 검토시간을 기록한다.
- 실제 병원 연동을 추진할 때 기관별 인터페이스·인증·권한·보안 연결과 자원 정산을 협의한다.

현재 자동 검사와 합성 브라우저 결과는 [TESTING](TESTING.md)의 범위로 해석한다. 실험 결과는 [ALGORITHMS](ALGORITHMS.md)와 원래 결과·프로토콜에서 확인한다.
