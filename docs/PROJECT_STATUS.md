# 프로젝트 현재 상태

기준: 2026년 10월 2일, 저장소 코드·문서 검토. 아래의 ‘구현’은 시연용 코드의 존재를 뜻하며 실제 의료기관 검증을 뜻하지 않습니다.

## 구현된 시연 기능

- `server/`: 가상 환자·병원 데이터, 후보 조회, 병렬 문의, 병원 응답, 목적지 확정, 이동·도착, 병원 자원 변경과 미등록 환자 유입. SQLite 트랜잭션으로 확정 충돌을 검사합니다.
- `solver_improved.py`: 가상 입력에 대한 CP-SAT 배정, 자원 점유 제약, 우선순위 정책 2개, 초기해·대체안, 로컬 유효성 검사.
- `simulation/`: 같은 seed를 사용한 B0(순차 문의)와 B1(병렬 문의·변경 알림) 비교. 저장된 결과는 가상 시뮬레이션입니다.
- `prototype/`: 서버와 독립된 문의·응답 화면 프로토타입.

## 아직 연결하거나 검증해야 할 것

1. 환자용 모바일 웹과 병원용 웹을 `docs/API.md`의 서버 API에 연결.
2. 병원 수용 응답·자원 일정·이동시간을 솔버 입력으로 변환하고, 솔버 결과를 서버의 확정 절차와 연결.
3. 이동 중 환자는 목적지를 유지하되 치료 시작시각을 다시 계산하도록 A26 구현. 현재 솔버의 `fixed`는 병원과 시작시각을 함께 고정합니다.
4. 병원 영향 환자 판정을 수량 비교에서 시간대별 치료 가능성 평가로 발전.
5. 공공 의료 API 인증키로 실제 응답 필드와 결측·갱신 시각 확인. `server/probe_apis.py`의 미검증 엔드포인트·파라미터를 활용가이드와 대조한 뒤 사용.
6. B2(같은 문의 방식 + 솔버 배정) 비교와 민감도 실험.
7. 로그인·병원별 접근 통제, 임상 기준 검토, 실제 병원 연동은 시연 범위 밖. 실제 환자 정보 사용 금지.
