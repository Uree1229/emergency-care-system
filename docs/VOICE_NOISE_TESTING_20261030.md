# 음성 입력과 현장 소음 시험

직접 녹음은 마이크·음향 환경·발음·브라우저 STT·텍스트 해석·저장을 거친다. 가짜 인식 결과나 텍스트만 넣는 자동 시험은 뒤쪽의 해석·저장 검증이며 실제 녹음 정확도의 대체물이 아니다. 같은 원본 WAV와 정답을 보존하면 오디오부터 반복 비교할 수 있다. 이전 빠른 시험은 원본 음성 파일을 저장하지 않았으므로 당시 사이렌·바람의 영향은 재현할 수 없다.

## 적용한 변경

- 빠른 입력의 설정에서 브라우저가 오디오를 관리한다는 점과 소음 시험 링크를 표시한다. 별도의 PCM 설정을 브라우저 STT에 적용했다고 표시하지 않는다.
- 메인 이송 노트의 `음성 인식 방식`에 **오디오만 녹음 · 로컬 시험**을 추가했다. 마이크를 켜는 버튼을 누른 뒤 최대 60초 PCM을 수집하고 WAV와 설정 JSON을 사용자가 직접 내려받는다. 이 모드에서는 오디오 STT·오디오 서버 전송·환자 등록을 실행하지 않는다. 일반 페이지 연결 과정의 빈 초안 생성은 기존대로다.
- `소음 환경 입력 비교`에서 기존 설정, 처리 끄기 요청, 소음 억제/반향 제거 켜기·자동 음량 끄기 요청을 비교한다. 기본 설정은 유지했다. 하드웨어의 무처리 원음이나 특정 억제 성능을 보장하는 프로필이 아니다.
- 요청한 제약, 브라우저의 지원 여부, `track.getSettings()`가 보고한 실제 값을 구분한다. 값이 없으면 미확인이다. 장치·그룹 ID는 보존하지 않는다. PCM의 RMS·포화·저레벨 샘플 비율은 신호 진단이며 SNR·VAD 발화 시간·인식률이 아니다.
- 평가 화면에서 소음 종류·소음 음원 ID·짝 비교 ID·확인된 SNR과 출처·마이크 거리를 기록한다. 모르는 SNR은 `null`로 남기고 현장 음량(dBA)과 혼동하지 않는다. 대본을 그대로 읽었는지 확인하는 절차는 유지한다.
- 문장부호 없는 인계문에서 이미 끝난 보고 문장을 보수적으로 나눈다. 중간의 과거 행동 표현이 다른 현재 관찰까지 버리는 경우를 줄인다. 가족·과거 주제·질문·부정·불확실·인용은 기존 보수적 범위를 유지한다. 인식문에 없는 나이·혈압 등을 대본에서 복원하지 않는다.

## 실제 사용자가 만든 인식문 재생

보관된 세 발화를 새 격리 DB에 재생했다. 첫 발화의 종결된 현재 보고까지 중간의 과거 행동 표현 때문에 버려지고 있었다. 수정 후에는 원문에 명시된 흉통·발생 간격·혈당을 유지했다. 불확실한 나이·성별 답변은 계속 입력하지 않았다. 기존 사용자 기록은 변경하지 않았으며 실제 인식문은 공개 코드나 자료에 포함하지 않았다.

이 결과는 **같은 STT 출력의 해석 개선**이다. 실제 발화 정답과 원본 오디오가 없으므로 CER/WER 또는 STT 정확도 개선으로 집계하지 않는다. 기존 120개 개발 대본은 수정 전후 116개 전체 일치로 같았고 예측·실패 ID도 동일했다. 새 합성 긍정 8개 중 7개, 안전 경계 13개를 충족했다. 기존 사전에 없는 표현 하나는 예상 실패로 명시하고 정답을 바꾸지 않았다.

## 합성 음원 A/B 결과

로컬 Windows 한국어 TTS 한 목소리로 만든 6개 WAV에 생성 사이렌·엔진·바람·다중 유성음·충격음 잡음을 섞었다. 실제 현장 잡음이나 사람 녹음이 아니다. 20/10/5/0/−5dB SNR, 개발/검증 대본·seed를 분리한 375개 기본 혼합과 450개 교정 가정 스트레스를 실행했다. 원음·잡음·모든 처리본에 같은 음량 배율을 적용했으며 무음 출력이 높은 점수를 얻지 않도록 검사했다.

| 기본 검증 225개 혼합의 처리 | 평균 SI-SDR 변화 | 0.1dB 초과 감소 |
|---|---:|---:|
| HP80 | −3.005dB | 171/225 |
| 고정 900Hz 노치 | −3.205dB | 194/225 |
| 정적 스펙트럼 게이트 | +3.757dB | 0/225 |

**SI-SDR은 파형 충실도이며 말의 명료도·인식률이 아니다.** 위상 변화에도 영향을 받으므로 HP80의 감소를 곧바로 인식률 저하로 바꾸어 말할 수 없다. 이 표는 브라우저 내장 소음 억제의 효과를 측정한 표도 아니다.

게이트는 앞 0.4초가 잡음뿐이라는 유리한 교정 조건을 썼다. 사이렌의 평균 증가는 +0.777dB로 엔진의 +9.312dB보다 작았다. 녹음 직후 말하는 추가 조건에서는 90개 중 60개가 감소했고 최악은 −6.158dB였다. 교정 뒤 새로운 잡음이 나타나는 경우에는 효과가 없었다. 따라서 **실험 필터를 제품 기본값으로 채택하지 않았다.** 게이트는 중심 STFT와 다음 프레임을 참조하는 오프라인 후보이며 실시간 처리 지연도 측정하지 않았다.

실제 마이크 입력·STT 호출은 0회, CER/WER는 미측정이다. 실제 현장·마스크·여러 화자·여러 장비로 검증해야 한다.

## 직접 시험하는 방법

1. `/paramedic/`에서 `오디오만 녹음 · 로컬 시험`을 선택한다. `소음 환경 입력 비교`를 펼쳐 프로필을 고른다.
2. 같은 가상 대본을 읽고 종료한 뒤 WAV와 설정 JSON을 **다음 녹음 전에** 내려받는다. 녹음은 메모리에만 있고 새 녹음·새 기록·페이지 종료 때 이전 다운로드를 정리한다.
3. 조용한 환경과 소음 환경, 원래 입력과 억제 요청을 나누어 수집한다. 실제 적용 값이 미확인이면 켜졌다고 간주하지 않는다.
4. `/paramedic/evaluate.html`에서 대본·익명 화자·소음 조건을 지정해 실제 브라우저 STT 결과를 수집한다. 이 화면은 별도 브라우저 경로이며 PCM 파일을 브라우저 STT에 주입하는 기능은 없다.
5. 같은 음원을 같은 엔진에서 재생할 수 있을 때 CER/WER, 숫자·부정 오류, 누락·불필요 입력, 무음 환각과 지연을 함께 비교한다. 파형 지표만으로 인식 엔진의 개선을 채택하지 않는다.

가능하면 마이크를 말하는 사람 가까이에 두고 포화를 피한다. 여러 사람이 동시에 말하는 조건도 별도로 시험한다. 숫자나 부정을 인식 모델이 잘못 들었을 때 문맥으로 정상값을 만들어 넣지 않는다.

## 재현

```powershell
python -m pip install -r requirements-audio-eval.txt
python -m unittest test_audio_noise_benchmark test_voice_clause_scope_20261030
python -m speech_eval.audio_noise_benchmark --source-plan <TTS계획.json> --clean-directory <WAV폴더> --output <새결과폴더>
node --test test_paramedic_speech.mjs test_paramedic_audio_input_profile.mjs test_paramedic_speech_test_context.mjs test_paramedic_evaluation_page.mjs test_paramedic_local_audio_page.mjs
```

벤치마크는 명시적으로 합성 TTS라고 표시한 계획과 16kHz 모노 16비트 PCM WAV를 받는다. 결과 폴더가 있으면 덮어쓰지 않는다. 교정 가정 스트레스는 별도의 고정 계획으로 수행한 추가 연구 기록이다.

## 공식 근거

- [MDN: noiseSuppression](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/noiseSuppression): 설정 요청과 강제·실제 적용은 다르다.
- [MDN: getSettings](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/getSettings): 기기가 보고하는 현재 제약 값을 확인한다.
- [MDN: SpeechRecognition.start](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/start): 기본 마이크 입력과 선택적 오디오 트랙 입력을 구분한다. 처리 트랙 지원은 제한적이며 함수 인자 수만으로 실제 사용을 보장하지 않는다.
- [Google Cloud STT 권고](https://docs.cloud.google.com/speech-to-text/docs/best-practices): 마이크 근접 배치·포화 방지와 전처리 주의 사항. 이 권고를 다른 STT 엔진의 성능 증명으로 사용하지 않는다.
