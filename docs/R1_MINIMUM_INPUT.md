# R1 최소 입력 항목 (Pre-KTAS 흐름 기준)

작성일: 2026년 10월 30일 · 상태: **결정 반영(10-30, 사용자 위임, 13절)** · 전문가 검토 전 · 근거: [피어리뷰 개선 계획](reviews/피어리뷰_분석과_개선계획_20261028.md) R1, 서버 환자 입력 규칙(`server/service.py`의 `_clean_patient`)

첫 문의는 **"이 병원이 이 환자를 받을 수 있는가"를 판단하는 데 필요한 정보만** 받는다. 화면 순서는 Pre-KTAS의 판단 순서(첫인상 → 주증상 → 1차 고려사항 → 2차 고려사항 → 등급)를 따른다.

- **필수 입력:** 탭 5번(의식, 호흡, 주증상, 연령대, Pre-KTAS 등급). 위치와 시각은 자동이다.
- **선택 입력:** 활력징후와 주증상별 질문
- **문의 뒤 보완:** 나머지 정보

시스템은 등급이나 진단을 자동으로 판정하지 않는다.

## 1 원칙

1. **첫 문의 = 수용 판단에 필요한 최소 정보.** 나머지는 문의 뒤 보완한다.
2. **자유 서술 대신 탭 선택.** 숫자는 키패드, 위치는 GPS로 받는다.
3. **모든 항목에 '모름'을 둔다.** 모름을 정상이나 비정상으로 바꾸지 않는다(R6).
4. **등급은 구급대원이 고른다.** 시스템이 증상으로 등급·진단을 추론하지 않는다.
5. **서버 기존 필드에 맞춘다.** 새 DB 필드 없이 시작하고, 부족한 것은 `extra`의 정해진 키로 받는다.

## 2 입력 순서

| 단계 | Pre-KTAS 판단 | 입력 | 필수 여부 |
|---|---|---|---|
| 0 | — | 위치(GPS, 수정 가능), 요청 시각, 입력자=구급대 | 자동 |
| 1 | 첫인상 | 의식(AVPU), 호흡 | 필수 |
| 2 | 주증상 | 주증상 묶음 1개, 연령대 | 필수 |
| 3 | 1차 고려사항 | 활력징후, 통증, 출혈 경향, 손상 기전 | 선택(권장) |
| 4 | 2차 고려사항 | 주증상별 질문 1~2개 | 해당할 때만 표시 |
| 5 | 등급 | Pre-KTAS 1~5 또는 미분류 | 필수 |

의식이 U(무반응)이거나 호흡이 이상·없음이면 서버가 `call_119: true`를 내려준다. 구급대 화면에서는 이를 "119 전화"가 아니라 **"즉시 전화(상황실·병원)"**로 표시한다.

## 3 첫 문의 필수 항목

| 항목 | 선택지 | 서버 필드 | 모름 처리 |
|---|---|---|---|
| 의식 | A 명료 / V 목소리 반응 / P 통증 반응 / U 무반응 / 모름 | `consciousness`: A→`alert`, V·P→`impaired`, U→`unresponsive`. 원래 값은 `extra.avpu` | `unknown` |
| 호흡 | 정상 / 이상(곤란·빠름·느림) / 없음 / 모름 | `breathing`: `normal`·`abnormal`·`absent` | `unknown` |
| 주증상 | 4절의 10개 묶음 | `extra.chief_complaint`, `extra.treatment_profile_id` | '기타' |
| 연령대 | 성인 / 소아(15세 미만) / 신생아 / 임신 중 / 모름 | `extra.age_group`. 나이를 알면 `age` | 성인으로 가정하지 않음 |
| Pre-KTAS 등급 | 1 소생 / 2 긴급 / 3 응급 / 4 준응급 / 5 비응급 / 미분류 | `extra.pre_ktas_level`, `priority`(7절), `priority_source: "expert"` | 미분류 → `priority: null`. 서버가 높음(4)으로 다룸 |

입력자는 `reporter_role: "transporter"`로 자동 지정한다. `consent` 처리 방식은 12절을 본다.

## 4 주증상 묶음과 서버 진료 프로필

서버의 진료 프로필(`config/treatment_requirements.json`)은 가상 시나리오용 6종이다. 주증상과 2차 고려사항으로 다음과 같이 고른다.

| 주증상 묶음 | 예 | 기본 프로필 | 2차 고려사항에 따른 변경 | 41차 유형 |
|---|---|---|---|---|
| 흉통·심장 | 흉통, 두근거림, 실신 | `TR_GENERAL_ED` | 심전도 ST 상승 확인 → `TR_CARDIAC_INTERVENTION` | cardiac |
| 뇌졸중 의심 | 편마비, 언어장애, 안면마비 | `TR_NEUROSURGICAL`(현재 가장 가까움) | — | stroke |
| 의식저하·경련 | 경련, 혼수 | `TR_GENERAL_ED` | 두부 외상 동반 → `TR_NEUROSURGICAL` | general |
| 호흡곤란 | 천식 발작, 숨참 | `TR_GENERAL_ED` | — | general |
| 외상 | 교통사고, 추락, 관통상 | `TR_ORTHOPEDIC` | 머리 손상 → `TR_NEUROSURGICAL` | trauma |
| 출혈 | 토혈, 하혈, 대량 출혈 | `TR_GENERAL_ED` | — | general |
| 복통·소화기 | 복통, 구토 | `TR_GENERAL_ED` | — | general |
| 산과·분만 | 진통, 임신 중 질 출혈 | `TR_GENERAL_ED` | 고위험 분만(조산 등) → `TR_HIGH_RISK_BIRTH_NEONATAL` | general |
| 중독·환경 | 약물 중독, 열사병, 저체온 | `TR_GENERAL_ED` | — | general |
| 기타 | 정신과 응급 등 | `TR_GENERAL_ED` | — | general |

- 연령대가 소아·신생아이면 `TR_PEDIATRIC`을 쓴다. 고위험 분만은 `TR_HIGH_RISK_BIRTH_NEONATAL`이 우선이다.
- 흉통만으로 심장 중재시술 프로필을 고르지 않는다. 서버 프로필의 주석 규칙과 같다.
- **서버에 없는 프로필:** 뇌졸중 재관류 치료와 중증외상(권역외상센터)이다. 추가가 필요하다(14절).
- '41차 유형'은 시뮬레이션의 유형별 수용률 학습에 쓰는 분류다. 서버 적용은 향후 과제다.

## 5 1차 고려사항(선택, 권장)

측정한 값만 넣고, 측정하지 않은 값은 키를 넣지 않는다(모름). 기준값으로 등급을 계산하지 않는다.

| 항목 | 입력 | 키 |
|---|---|---|
| 혈압 | 수축기/이완기 키패드 | `extra.vitals.sbp`, `dbp` |
| 맥박 | 키패드 | `extra.vitals.hr` |
| 호흡수 | 키패드 | `extra.vitals.rr` |
| 산소포화도 | 키패드 | `extra.vitals.spo2` |
| 체온 | 키패드 | `extra.vitals.temp` |
| 통증 | 0~10 | `extra.vitals.nrs` |
| GCS | 3~15 | `extra.vitals.gcs` |
| 측정 시각 | 자동 | `extra.vitals.measured_at` |
| 출혈 경향(항응고제 등) | 예 / 아니오 / 모름 | `extra.bleeding_risk` |
| 고위험 손상 기전(외상일 때) | 예 / 아니오 / 모름 | `extra.high_risk_mechanism` |

## 6 2차 고려사항(주증상별, 해당할 때만)

| 주증상 | 질문 | 저장 |
|---|---|---|
| 흉통·심장 | 심전도에서 ST 상승을 확인했나? 예 / 아니오 / 미측정 | `extra.stemi_suspected` → 프로필 변경 |
| 뇌졸중 의심 | 마지막으로 정상이었던 시각(모름 가능) | `onset_at` |
| 외상 | 손상 부위: 머리 / 몸통 / 팔다리 / 여러 곳 | `extra.injury_region` → 프로필 변경 |
| 산과·분만 | 임신 주수, 진통·양막 파열 여부 | `extra.pregnancy_weeks`, `extra.labor` |
| 의식저하·경련 | 경련이 지금도 계속되나? 혈당(측정한 경우) | `extra.seizure_ongoing`, `extra.vitals.glucose` |

## 7 Pre-KTAS 등급과 서버 우선순위

| Pre-KTAS | 서버 `priority` | 뜻 |
|---|---|---|
| 1 소생, 2 긴급 | 4 | 높음 |
| 3 응급 | 2 | 중간 |
| 4 준응급, 5 비응급 | 1 | 낮음 |
| 미분류 | `null`(`priority_source: "unknown"`) | 서버가 높음(4)으로 다룸 |

서버의 우선순위는 3단계라서, 원래 1~5 값은 `extra.pre_ktas_level`에 보존한다. 이 등급이 들어와야 34차의 중증 환자 우선 문의 개선을 서버에서 쓸 수 있다.

## 8 문의 뒤 보완 항목

다음은 첫 문의에서 받지 않는다: 이름, 생년월일, 정확한 나이, 성별, 연락처, 보호자, 주소, 과거력, 복용약, 알레르기, 증상 상세 서술, 재측정한 활력징후. 문의 뒤 [환자정보 수정 API](PATIENT_AMENDMENTS_API.md)로 보완한다.

**서버 정책과 충돌한다.** 지금 수정 API는 어떤 필드가 바뀌어도 진행 중인 문의와 받은 수용 응답을 모두 취소한다. R1처럼 행정 정보를 나중에 보완하면, 이미 받은 수용이 이름 보완만으로 취소된다. 그래서 필드를 둘로 나누기로 했다(13절 3번). 구현은 Codex의 서버 작업이 끝난 뒤 진행한다.
- **행정 필드**(`name`, `relation`, `contact`, `address`, `guardian`, `guardian_phone`): 수용 응답을 유지하고 병원에는 알림만
- **임상 필드**(그 밖의 모든 필드. 나이를 바꾸는 `birth` 포함): 지금처럼 문의를 닫고 병원 재확인

## 9 화면 예시

```
[위치: 서울 동작구 흑석로 84 · GPS 확인됨]                     (자동)
의식    [A 명료] [V 목소리] [P 통증] [U 무반응] [모름]
호흡    [정상] [이상] [없음] [모름]
주증상  [흉통·심장] [뇌졸중] [의식·경련] [호흡곤란] [외상]
        [출혈] [복통] [산과] [중독·환경] [기타]
연령대  [성인] [소아] [신생아] [임신 중] [모름]
  └ 흉통 선택 시: 심전도 ST 상승? [예] [아니오] [미측정]
활력징후(선택) [혈압 __/__] [맥박 __] [SpO2 __] [체온 __] [통증 0~10]
Pre-KTAS [1] [2] [3] [4] [5] [미분류]
                                           [문의 보내기]
```

필수 탭은 5번과 보내기 1번이다. 지금 화면에는 입력 칸이 16개 있고, 자유 서술 2칸과 위도·경도 직접 입력이 포함된다.

## 10 음성 입력과의 연결

음성 초안은 이 화면과 같은 칸을 채우고, 확인도 이 화면에서 한다. 시제품과 정확도 시험은 [음성 입력 초안 시제품](VOICE_INPUT_PROTOTYPE.md)에 정리했다. 용어 사전은 아래와 같은 표현에서 시작한다.

| 말한 표현(예) | 채울 칸 |
|---|---|
| "의식 명료", "의식 있음" | 의식 A |
| "통증에만 반응" | 의식 P |
| "숨 안 쉼", "무호흡" | 호흡 없음 |
| "편마비", "한쪽 마비", "말이 어눌" | 주증상 뇌졸중 의심 |
| "ST 상승" | 흉통 2차 질문 예 |
| "케이타스 2", "프리케이타스 2" | 등급 2 |
| "혈압 90에 60" | `sbp` 90, `dbp` 60 |
| "산소포화도 88", "새츄 88" | `spo2` 88 |

## 11 검증(R1 완료 기준)

- **시나리오:** STEMI 의심, 뇌졸중, 다발 외상, 소아 경련, 분만 등 가상 시나리오 5개
- **비교 방법:** 현재 화면과 새 화면에 같은 시나리오를 넣고 교차 순서로 비교한다.
- **구급대 쪽 지표:**
  - 입력 활동시간: 업무 계측 R8의 `patient_input`
  - 탭·타이핑 수: 관찰자가 기록
  - 누락·오입력
- **충분성 지표:** 병원 역할 참가자가 판단에 필요한 정보가 없어 추가 질문을 보낸 횟수. 최소 항목이 충분한지 보여 준다.

## 12 확인이 필요한 것

- **Pre-KTAS 대조:** 이 문서는 Pre-KTAS의 판단 순서만 빌렸다. 주증상 묶음, 2차 질문, 등급 연결은 공식 Pre-KTAS 지침과 대조하고 구급대원·응급의학 전문가의 검토를 받아야 한다. R1에서 말한 '현장 검토 대상'이다.
- **동의 처리:** 구급 이송의 정보 전달 근거와 `consent` 화면 처리는 팀과 지도교수에게 확인한다.
- **활력징후 범위 검사:** 아직 서버에 없다. `extra.vitals` 값이 생리적으로 가능한 범위인지 검사하는 기능이다.

## 13 결정 사항

2026-10-30 사용자 위임으로 정했다. 팀에 공유하고, 전문가 검토(12절)에서 바뀌면 고친다.

| 번호 | 결정 | 이유 |
|---|---|---|
| 1 | **필수 5개 확정. 연령대도 필수**('모름' 허용) | 소아·신생아·임신 여부에 따라 받을 수 있는 병원이 크게 달라진다(소아·분만 프로필). 탭 한 번이면 된다 |
| 2 | **주증상 10개 묶음 확정**('기타' 포함) | 서버 진료 프로필 6종과 41차 유형 4종에 모두 연결된다. 전문가 검토 전까지 이 목록을 쓴다 |
| 3 | **행정 필드 보완은 수용 응답을 유지**하고, 임상 필드 변경만 병원 재확인 | 이름 보완만으로 받은 수용이 취소되면 R1(나중에 보완)이 오히려 지연을 만든다. 필드 목록은 8절 |
| 4 | **활력징후는 선택.** 등급 1~3이거나 미분류이면 입력란을 강조한다 | 첫 문의를 늦추지 않는다. 다만 문의 뒤에 넣으면 임상 수정이라 병원 재확인이 필요하므로, 화면에 "측정값이 있으면 지금 넣으세요"라고 안내한다 |

## 14 역할

- **화면:** 구급대원 앱 담당이 9절 화면을 구현한다.
- **서버(본인):**
  - `extra` 키 형식 검사
  - 주증상·2차 고려사항으로 진료 프로필을 고르는 함수
  - 수정 API의 임상·행정 필드 구분
  - 부족한 진료 프로필 추가
  - 병원 화면용 요약 필드

**진행 상황(10-30):**
- **음성 입력 경로:** R1 칸 추출, 첫 문의의 필수 5칸 검사, Pre-KTAS→우선순위와 진료 프로필 변환을 서버에 반영했다([반영 결과](VOICE_R1_ALIGNMENT.md)).
- **아직 남은 것:** 화면 직접 입력 경로의 `extra` 형식 검사, 수정 API의 행정 필드 구분, 부족한 진료 프로필
