# 첫 문의 검토 슬롯 공동 배분과 환자별 대기·도착 보존

상태: 별도 후보 `eat_cohort_startslots_l15_f`의 훈련 360환경을 한 번씩 실행하고 감사를 완료했다. 기존 성공 환자 손실과 개인 지연 증가로 세 채택 판정 모두 실패했다. 이 후보는 채택하지 않으며 부모 Tailwait와 운영 기본 `fixed_3`는 유지한다.

## 요청과 제한적 진단

Tailwait는 원래 Stoploss의 성공을 전부 보존하고 총 선정 대기를 기존 827명에서 24초·추가 415명에서 70초 줄였다. 그러나 직전 Pairshield보다 추가 자료의 다른 세 환자가 3초·15초·50초 더 기다렸고 개인 도착 비용도 최대 257초 늘었다. 이번 요청은 성공과 총 단축을 유지하면서 이 개인별 불이익도 개선하는 것이다.

현재 Tailwait와 Pairshield의 같은 혼합 환경 원문을 각각 한 번 읽고, 빠진 첫 문의의 원래 후보 표를 확인하기 위해 Tailwait 원문을 한 번 더 읽었다. 고유 원문은 2개·해제는 3회이며 압축/원문 해시와 봉인을 확인했다. 저장된 결과·문의·검토 시작/종료·회신을 진단에만 사용했다. 실제 처리 인원과 미래 수용 여부는 새 정책 입력으로 전달하지 않는다.

이 환경에서 앞선 두 환자의 H01 검토는 58초·92초 동안 두 검토자를 차지한다. 뒤 환자 P04가 대기 77초 이하이면서 도착 708초 이하를 만족하려면 해당 저장 환경에서는 H01의 27초 검토를 50초까지 시작해야 한다. H02는 거부하고 나머지 병원은 이동시간만 708초를 넘는다. 앞선 두 문의를 그대로 두면 P03를 없애도 H01의 가장 빠른 종료가 58+27=85초라 두 목표를 함께 만족하지 못한다. 이는 이 고정 과정의 제한적 결론이며 전체 알고리즘의 불가능성 증명이 아니다.

또한 첫 두 환자의 기존 JOINT 표는 400개 조합 중 원래 제약을 통과한 것이 기준 행 하나였다. 그 행은 두 환자 모두 H01·H02·H03에 문의한다. 기존 후보를 더 제외하거나 후속 문의만 바꾸는 방식은 필요한 앞단 결정을 새로 만들 수 없다. 접수시간·선정시간을 바꾸거나, 환경의 검토자를 늘리거나, 이미 진행 중인 검토를 중단하는 방식은 사용하지 않는다.

## 새 배분 규칙

등록된 첫 문의 대상이 4~16명이고 시작시각이 같으며 공통 공개 문의 대기열이 비어 있는 구간에만 새 규칙을 적용한다. 기존 두 환자 처리 순서와 병원 FIFO는 유지한다. 현재 공개 입력으로 전체 첫 문의 환자의 배분을 계산하되 **실제 문의는 현재 두 환자에게만** 제출한다. 뒤 환자의 계획은 예약·확정하지 않으며 다음 처리에서 다시 계산한다.

각 환자의 원래 H 모델이 보는 최대 6개 후보와 원래 `assumed_workers`를 사용한다. 이것은 정책이 가정한 검토 슬롯이며 실제 검토 인원이나 병상 수가 아니다. 환자마다 한 문의를 우선 배정하는 제한 용량 매칭을 계산하고, 남은 슬롯에만 기존 즉시 문의 수·개인 동시 4건·총 10곳 한도 안에서 기대 비용이 엄격히 줄어드는 추가 문의를 배분한다. 전원에게 첫 문의 한 건을 배분할 수 없으면 부모 Tailwait를 그대로 사용한다.

매칭은 잔여 그래프의 증가 경로와 역방향 간선을 기록하고 독립 감사가 비용·용량·절차·동률 처리를 다시 확인한다. 기존 `1e−9` 수치 허용 오차를 사용한다. 간선별 잔여 비용 검사는 수치 허용 오차가 있는 절차 검증이며 수학적으로 정확한 전역 최소 비용 증명으로 표현하지 않는다. 원래 H 비용·확률·CDF 법칙을 간선과 추가 문의 비용 계산에 사용한다.

새 분기에서는 문의 수와 후보 집합이 달라지므로 원래 JOINT 타당성이나 환자별 예측 확률·대기 보호가 새 선택을 보장한다고 주장하지 않는다. 부모 Tailwait 제안은 계산 참고안으로 온전히 보존하고 독립 감사한다. 그 보호는 복사된 경로와 내장 참고안에 적용되며 새 슬롯 배분의 전역 보장 플래그는 명시적으로 False다. 원래 H 미래 계획도 참고 정보로 표시하고 실제 새 문의는 새 배분 결과로 판정한다.

다른 구간·첫 문의 대상이 두 명뿐인 기존 개선 경로·단독 후속 문의는 부모 계산을 복사한다. 실제 검토 환경·수용 잠재값·시간 정의·실패 비용·총/동시 문의 제한·전체 대기 환자 상태 변경 감지·현재 두 환자만 적용하는 원자적 처리는 바꾸지 않는다. 새 규칙이 실제 성공·대기·도착시간을 보장하지는 않으며 아래 결과 판정이 모든 환자를 검사한다.

## 실행 전에 고정하는 판정

원래 승격 조건 9/7/13개와 Tailwait에서 추가한 보존 조건 9/5개는 함수와 수치를 그대로 유지한다. 여기에 별도의 환자별 대기·도착 보존 조건을 추가한다. 어떤 이전 조건도 완화하지 않고 다음 단계 진입은 세 판정이 모두 통과할 때만 허용한다.

- Stoploss·Pairshield·Tailwait에서 성공한 환자 식별자를 모두 보존한다. 성공 수만 같고 환자가 바뀌면 실패다.
- 기존 827명·추가 415명의 총 선정 대기가 각각 Tailwait의 113,405초·54,557초 이하여야 한다.
- 모든 일치 환자에서 Tailwait와 Pairshield **양쪽 모두**에 대해 선정 대기와 도착 비용 증가가 0초여야 한다. 일부 환자나 최대 지연 환자만 골라 검사하지 않는다.
- 실패 선정 대기는 300초, 실패 도착 비용은 1,800초로 유지한다. 도착 비용은 선정 경과+이동시간이며 생성시각을 다시 빼지 않는다. 양쪽 모두 성공한 환자의 도착 지연도 별도 기록한다.

알려진 두 훈련 자료에서는 존재 조건을 포함한 새 조건 17개, 새 개발·별도 검증에서는 9개다. 모든 환자의 대기·도착 벡터, 악화 식별자·건수·양수 합계·최댓값을 세 비교군별로 저장한다. 자료나 환자를 합쳐 다른 사람의 불이익을 가리지 않는다.

두 개선안의 환자별 더 좋은 값을 모두 지킨다면, 알려진 추가 자료의 총 대기는 54,489초 이하·도착 비용은 340,889초 이하여야 한다. 이는 저장 결과에서 계산한 **판정용 목표**이며 정책 입력이 아니다. 총 대기 70초 단축만 유지하는 것보다 강한 조건이다.

훈련의 세 판정을 모두 통과할 때만 새 개발 120환경, 그 뒤에도 모두 통과할 때만 별도 검증 368환경을 실행한다. 기존 시나리오 짝 부트스트랩 10,000회·시드 20261021·지표별 주변 95% 구간 조건도 그대로다. 어느 구간의 손실도 다른 구간 이득으로 상쇄하지 않는다.

## 보존과 사전 검증

부모 Tailwait 봉인은 `3158907de3612918a685a18dab25ddf4559f36710b0da906121fae9d765946e7`다. 부모 소스 634개·엄격 참조 4,937개·압축 원문 6,000개를 보존했다. 새 보존 파일 해시는 `f7b44419588d39dd87dc7d30bb5316872a6983a58cfc8163e0b9b973338970c8`이며 새 이름 공간은 `eat-cohort-startslots-v1-20261025-b4e5157a-4e93-4cd0-ae54-f84d54fe3143`다.

새 소스 16개를 더한 전체 650개를 고정할 계획이다. 비교군 25개·9,000분기를 재사용하고 새 개발·검증은 26개 정책으로 비교한다. 입력 명세 848개·최대 새 실행 13,048분기, 알려진 훈련은 새 후보 360분기 각각 한 번이다. 모든 원문 저장 뒤 각 새 원문의 의미 감사를 한 번 수행하고 독립 회계·공식 집계 대조·저장 증명 재사용·후속 단계 차단·최종 봉인으로 확인한다. 성능 재실행·결과 제외·사후 설정 변경은 하지 않는다.

고정 사전 예제는 이전 두 예제에 첫 4명의 환자만 남긴 명시적 합성 슬롯 배분 예제를 추가해 총 3개다. 원래 8명 예제에서는 가정한 슬롯으로 전원을 덮지 못할 수 있어, 새 예제는 배분 성공과 실제 제출을 검사하기 위한 기능 자료다. 병원 미래 수용 정보는 시뮬레이터만 사용하며 이 예제를 성능 개선의 증거로 쓰지 않는다.

추가로 저장된 첫 공개 입력을 사용하는 모형 시험을 한 번만 허용했다. 원래 H 계획 계산 6회·새 슬롯 배분 계산 1회, 새 실제 정책·시뮬레이션·감사 실행은 0회였다. 그 계산은 첫 두 환자를 H01 이외로 배분하고 P04에 H01을 계획했지만 뒤 환자 계획을 실제 예약한 것은 아니며 성공이나 지연 회복을 증명하지 않는다. 수치 모형은 이 계산 뒤 조정하지 않았고, 원래 H 계획을 참고로 표시하는 메타데이터만 보완했다.

과거 문서 참조 오류 10건은 정확한 실패 ID·추적·원래/현재 해시와 함께 유지하고 전체 검사 통과로 표시하지 않는다. 빈 문의 후보에서 봉인된 부모 감사기가 `0`과 `0.0`을 엄격히 구분하는 경계도 단언 완화·정규화·검사 건너뛰기 없이 승계한다. 이번 성능 입력은 후보 병원이 비어 있지 않은 범위다. 모든 성능 환자의 응급 우선순위는 미확인·기본값 4이므로 임상 응급도별 효과를 주장하지 않는다. 운영 서버와 기본 `fixed_3`는 유지한다.

## 결과

새 모형·정책 합성 검사 19건과 상태·원자적 제출 검사 32건, 독립 감사 합성 검사 16건, 실험·판정 검사 92건이 성공했다. 독립 감사의 성공 배분 4명/6병원·배분 불가 4명/3병원은 온전한 부모 증명을 포함한다. 일부 이전 조립용 합성 예제는 전체 H 시간 경계 감사를 통과하지 못하는 부분 자료로 명시하고, 그 거부도 검사했다. 단언 완화나 정식 사례 제외는 없다.

독립 최종 검증기의 기존 수치·증명·보존 함수 14개는 부모와 같은 AST이며 새 환자별 대기·도착 판정은 세 단계의 합성 자료에서 실제 실험과 일치했다. 기존·이전 보존·새 보존 세 판정의 8개 진릿값 조합을 검사하고 변조 57종을 거부했다. 실제 `main` 초기 경로도 합성 동결·검사·예제 메타데이터와 일부 함수 대체를 명시해 실행하고 원문 경로 전에 차단했다. 실제 보존 파일과 650개 소스 해시는 확인했지만, 이 검사를 실제 전체 동결이나 성능 검증으로 표현하지 않는다. 실제 원문·모형·성능 실행은 0회였다.

이전 보존 판정은 합성 14사례·누락/중복 거부 6종, 새 대기·도착 판정은 15사례·거부 6종에서 실제 실험 코드·독립 회계기·독립 최종 검증기의 세 계산이 일치했다. 새 회계기의 실제 `run` 초기 메타데이터 경로도 실제 보존 파일·650개 소스·비교군 25개/9,000분기·봉인된 부모 보고서로 사전 확인했다. 아직 없는 동결·인덱스·명세·파일 목록만 합성했고 시작 마커 전에 차단해 원문 읽기·해제는 0회였다. 실제 원문 헤더나 아직 없는 동결 기록을 검증한 것으로 표현하지 않는다.

전체 고정 소스 검사는 120모듈·2,301건 중 2,291건이 성공했다. 나머지 10건은 부모에서 보존한 정확히 동일한 문서 참조 실패로 ID·추적·원래/현재 해시를 남겼다. 새 검사 159건은 모두 성공했고 실행 오류·건너뛰기는 0건이었다. 실제 650개 소스의 검사 전후 해시도 동일했다. 전체 검사 통과로 표현하지 않는다.

고정 예제에서는 비교군 25개의 전체 원문 동등성과 후보 세 예제의 독립 감사를 통과했다. 8명 원래 예제는 슬롯으로 6명까지만 덮어 배분 불가로 부모 동작을 복사했다. 명시적 4명 합성 예제는 간선 비용 24개·증가 경로 4개·잔여 인증 1개·추가 문의 2개를 검사했고 현재 두 환자의 실제 문의 3건과 선택 변경을 확인했다. 이는 배분 성공/실패와 실제 제출에 대한 기능 증거이며 성능 개선의 증거가 아니다.
