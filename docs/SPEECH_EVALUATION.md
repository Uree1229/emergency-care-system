# 음성 입력 데이터셋과 자동 평가

2026-10-30. [실행·평가 규칙](../speech_eval/README.md) · [수동 정답 120개](../speech_eval/corpus_dev.json) · [정답 기준](../speech_eval/ANNOTATION.md)

## 긴 문장 간편 기능 시험

[긴 문장 음성 시험](http://127.0.0.1:18032/paramedic/quick-test.html)은 버튼을 눌러 긴 가상 환자 설명을 말하고 종료하면 자동으로 추출 결과를 보여준다. 여러 STT 최종 조각을 합쳐 한 번 처리하며, 별도 체크박스·결과 저장·JSON 전달은 필요 없다. 정상 처리한 원문과 결과는 공통 서버의 음성 초안에 저장된다. `QUICK-VOICE-` 작업자 접두사로 문장별 평가와 구분한다. 환자 등록·병원 문의는 수행하지 않는다.

이는 **자유 발화 기능 시험**이다. 예시와 다르게 말할 수 있으므로 120개 정답셋의 정확도 점수에 합산하지 않는다. 실제 마이크 발화와 연결 여부는 사람이 별도로 확인해야 한다. 아래 정밀 평가는 고정된 대본과 정답으로 오류를 재현할 때 사용한다.

## 구현한 것

- 15개 유형, 120개 합성 개발 발화와 관찰 정보 16개 항목의 정답. 받아쓰기/명령 모드를 문장마다 명시한다.
- 실제 서버의 R1 통합 추출 경로를 실행하되 채점 범위는 정답이 있는 16개 관찰 항목으로 고정한다. 추가 R1 결과는 미채점으로 보존한다.
- 원문을 넣었을 때와 STT 출력문을 넣었을 때를 같은 정답으로 비교한다. STT 전에도 틀린 경우와 STT 출력에서 악화된 경우를 구분한다.
- 수치 오답·누락, 증상 있음/없음/불확실, 불필요한 자동입력, 명령·조회 대상, CER/WER를 계산한다.
- 실제 발화·수동 문장·합성 오인식은 별도 집계한다. 인식 실패를 성공 결과의 분모에서 빼지 않는다.
- JSON·Markdown·HTML·CSV 보고서와 빈 수집 양식, 실행 전후 소스·입력 해시, 소스 스냅샷을 생성한다. 기존 결과를 덮어쓰지 않는다.
- [시험 수집 화면](http://127.0.0.1:18032/paramedic/evaluate.html): 가상 대본 선택 → 익명 화자·환경 선택 → 음성 인식 → 원문 확인 → JSON 내려받기. 실제 환자정보나 병원 문의는 처리하지 않는다.

## 지금 확인할 수 있는 것과 없는 것

현재 보관 기준선: [요약 보고서](../outputs/speech_evaluation_20261030/reference_v3/report.md) · [HTML 비교표](../outputs/speech_evaluation_20261030/reference_v3/report.html).

| 합성 개발 대본의 관찰 16개 항목 | 결과 |
|---|---:|
| 문장 전체 일치 | 114/120 (95.0%) |
| 항목 정밀도 / 재현율 | 96.0% / 97.5% |
| 값 오류 / 누락 / 불필요한 자동입력 | 1 / 2 / 4 |
| 실제 발화·녹음 수 | 0건 · 미측정 |

일치하지 않은 6문장은 `BG` 혈당 약어 누락, 복통 표현 누락, 이중 부정, 모호한 맥박 수치, 호흡 상태 보충에 관한 정책 차이 2건이다. 오류 항목 수는 문장 수와 다르다. 같은 문장에 누락과 불필요 입력이 함께 있을 수 있다. 개발 자료에서 확인한 값이며 일반 발화 정확도로 쓰지 않는다.

현재 기준선은 **합성 개발 대본의 구조화 결과**다. 실제 발화 정확도, 소음의 영향, 구급대원의 총 입력시간 감소는 아직 미측정이다. 수집 화면은 브라우저 STT를 사용하며 마이크 권한·지원 여부에 영향을 받는다. 실제 발화 종료 시각과 수정·확인·전송 시간을 임의로 만들어 넣지 않는다.

지원 29개 입력 항목 전체의 정확도나 임상적 판단의 정확도로 해석하지 않는다. '직접 언급한 관찰만 입력'이라는 정답 정책과 R1의 보충 규칙이 충돌하면 정책 차이도 오류 목록에 나온다. 이 기준선으로 문제를 찾고 개선한 뒤에는 새 문장·새 화자·새 녹음으로 별도 검증해야 한다.

## 실행

```powershell
# 대본 정답 → 현재 추출기 기준선
python -m speech_eval evaluate --output outputs/speech_eval/new_reference_run

# 내려받은 STT 결과와 정답 비교
python -m speech_eval evaluate --recordings "C:/path/speech-recordings.json" --output outputs/speech_eval/new_speech_run

# 손으로 만든 오인식 예시로 도구 동작만 확인
python -m speech_eval evaluate --recordings speech_eval/recordings_synthetic_example.json --output outputs/speech_eval/new_synthetic_run
```

2. 실제 원문 확인 후 수치·부정·미언급 오류와 명령 실패를 분석한다.
3. 개선 전후 엔진·사전·코드 버전을 고정해 같은 기록으로 회귀 비교한다.
4. 별도 과업에서 수동 입력과 음성 입력의 총시간·수정 횟수·오입력을 비교한다. 수집 화면의 인식 시간만으로 업무 절감률을 주장하지 않는다.
