> 2026-11-06 통합 안내: 현재 `codex/main-sync-20261106` 브랜치는 최신 main의 병원 A2·음성 문맥 검토에 구급대 통합 화면과 흐름 콘솔, 후속 로컬 변경을 결합한 소스다. 현재 구현·남은 확인은 [현재 상태](PROJECT_STATUS.md)를 따른다. 아래 본문은 11월 4일의 통합 전 기준을 보존한 기록이며, 당시의 브랜치 상태와 예정 작업을 설명한다.

2026-11-04 확인. 이 문서는 앞으로 만들 통합 후보의 기준이다. 아래 기능들이 이미 하나의 실행본에서 통합·검증됐다는 뜻은 아니다. 음성 담당이 기존 Git 기능과 로컬 시연 기능을 비교하고, 각 담당의 작업을 보존하면서 작은 단위로 이식한다.

구급대 후보 `240b942`에는 TTS 순차 확인·일괄 모름과 Git의 복수 후보 검토가 이미 함께 구현돼 있다. 따라서 해당 기능부터 다시 작성하지 않는다. 다만 같은 후보의 파서는 v1.12의 모든 보강을 포함하지 않으므로 별도 비교·이식이 필요하다. 관제의 초안 handoff는 해당 후보의 Quick 소비 경로를 확인하고, 등록 뒤 새 진행 링크 `fw-progress`와 기존 관제 선택 환자가 동기화되는지 실화면에서 확인한다.

멘토 시연본 전체를 Git 저장소에 복사하거나 서버·UI 파일을 통째로 덮지 않는다. 공통 실행본과 Git의 서버 API·schema·브라우저 화면 차이를 먼저 비교하고 필요한 기능과 테스트만 옮긴다. 시연본 ZIP·DB·현재 서버는 기존 그대로 둔다.

## 결합할 때 지킬 계약

- `voice_input.py` 전체를 시연본으로 교체하면 Git의 `recognition_alternatives` 충돌 검토가 사라진다. 파서·일괄 모름·후보 검토·원문 및 추출 출처를 합쳐서 검토한다.
- 최소 이식 후보는 `voice_terms.py`, `voice_r1.py`, `voice_input._answer_context`의 대시 혈압 처리다. 기능별 diff와 기존 테스트 의존성을 확인하며 이식하고, `240b942`에 이미 있는 후보 간 일괄 모름 일치 검사를 유지한다.
- 한 인식 후보는 `나머지는 모름`, 다른 후보는 혈압 등 실제 값을 말하는 경우 일괄 모름을 먼저 확정하지 않는다. 후보 간 불일치를 확인 대상으로 남긴다. 단일 후보 또는 후보가 같은 의미로 일치하는 경우도 기존 값·검토 상태 보존을 확인한다.
- 인계의 직접 관찰과 R1 파생 출처를 구분하고, 후보 충돌로 제거된 필드의 근거·출처를 현재 확정값처럼 남기지 않는다. 복구 시 원래 요청 ID·본문·소유 범위와 환자 ID를 유지한다.
- `app.py`도 통째로 교체하지 않고 필요한 route·handler·상태 응답을 선택적으로 결합한다. 기존 Git 자산의 MIME 설정 등 다른 변경을 보존한다. DB 변경이 필요한 경우 기존 마이그레이션·백업·복원과 구버전 호환을 따로 검증한다.
- 배정 알고리즘과 모델을 다시 선택하지 않는다. 추천, 병원 수용, 사람이 선택한 목적지, 출발·도착은 별개의 단계로 남긴다. 실제 공개 데이터와 가상 운영값도 구분한다.

## 검증 순서와 완료 기준

1. 최신 원격 main과 관련 브랜치의 SHA, 각 작업 트리 상태, v1.12 manifest·ZIP 무결성을 확인한다. 통합 전 변경 목록과 기능별 출처를 고정한다.
2. 합성 텍스트 검사에서 `혈압 120-80`, `경련 실신 없음`, `호흡곤란이 생기면 알려주세요`, `현재 혈압 120/80, 수축기 혈압 80으로 떨어지면 연락하세요`, 상충 맥박을 검증한다. 값·부정·원문 근거·경고를 함께 확인하고, 후보 간 값/모름/명령 충돌과 같은 요청 재시도를 추가로 확인한다.
3. TTS 모의 어댑터를 이용해 읽기 종료→답변→다음 항목, 불명확 답변·수정·중지·재개·환자/버전 변경과 명시적 다음 단계, 빈 항목 모름을 확인한다. 명령 게이트의 조기 종료·후속 부정·늦은 final도 각각 확인한다.
4. 새 합성 DB와 빈 포트의 full 실행기에서 단일 관제·최신 병원 A2·구급대 화면을 함께 열어 같은 환자의 등록→문의→수용→사람 확정→출발→양쪽 대화→도착을 검증한다. 기존 DB·공유 포트·진행 중 사용자 세션을 바꾸지 않는다.
5. 응답 유실·같은 요청 재시도·새로고침·환자 전환·서버 재기동과 백업/복구를 확인한다. 실패한 검사·생략 이유와 실제 검증에 사용한 소스 SHA·실행본 ID·DB 범위를 남긴다.
6. 실제 마이크·소음·TTS·다른 기기·수동/음성 사용성은 별도 측정으로 기록한다. 기존 13개 저장 인식문의 재처리 결과나 모의 브라우저 검사를 실제 STT 성능 향상으로 바꾸어 표현하지 않는다.

파서 범위의 기존 회귀는 통합 후보에 있는 `test_voice_unified_unknown_defaults.py`, `test_voice_recognition_context.py`, `test_voice_followup_edges_v2.py`, `test_voice_terms*`, `test_voice_r1.py`, `test_voice_clause_scope_20261030.py`를 우선 확인한다. 파일별 존재·호환성을 통합 후 확인하며 합성 HTTP와 화면 검사를 대체하지 않는다.

통합 후보는 위 검사와 관련 기존 회귀를 통과한 뒤에만 공통 실행본으로 채택한다. 성공한 항목과 미실행 항목을 분리하고, 팀원의 최신 변경이 생기면 다시 비교한다.
