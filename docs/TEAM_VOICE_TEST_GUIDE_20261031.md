# 팀원용 긴 문장 음성 테스트

이 문서와 대본을 팀원에게 전달하면 된다. **현재 GitHub `main`을 기준으로 각자 PC에서 실행**한다. 가상 대본을 길게 한 번에 읽고, 실제 음성·인식문·명령 판정 또는 저장 항목을 비교한다. 실제 환자정보·실명·연락처는 말하지 않는다.

## 먼저 할 것: 기본 시험과 확장 시험

| 시험 | 화면 | 무엇을 확인하나 | 대본 |
|---|---|---|---|
| A. 명령·긴 문장 수집 | `/paramedic/command-practice.html` | 긴 문장 인식, 명령 위치·부정·인용, 녹음 보관·ZIP | [긴 명령 대본40개](testing/TEAM_VOICE_COMMAND_LONG_SENTENCES_20261031.md), [낭독용 TXT](testing/TEAM_VOICE_COMMAND_LONG_SENTENCES_20261031.txt) |
| B. 환자정보 정리 | `/paramedic/quick-test.html` | 한 번에 말한 긴 보고를 숫자·증상·누락/미측정·변경 항목으로 정리하는지 | [긴 환자 보고12개](testing/TEAM_VOICE_REPORT_SENTENCES_20261031.md), [동일 대본 JSON](../datasets/voice/team_long_reports_20261031.json) |

**첫 회는 A의 LONG-01·LONG-20·LONG-39, B의 REP-01·REP-02·REP-03**을 한다. 준비 후 약15~25분을 잡되 실제 소요시간은 기록한다. 두 번째 회부터 남은 대본을 나누고, 같은 대본을 조용한 조건과 실제 주변 소음 조건에서 각각 반복한다. 전원이52개를 한 번에 읽을 필요는 없다.

A 화면은 녹음·판정 자료 수집 전용으로 환자·병원 API를 호출하지 않는다. B는 로컬 음성 초안을 저장하는 기능 시험이다. 두 결과를 같은 성능 지표로 합치지 않는다.

## 1. 준비와 실행

필요한 것은 Git, Python3.12 이상, 마이크, 브라우저 음성 인식 기능이 있는 환경이다. 앱이 지원 여부를 표시한다. 브라우저 이름만으로 모든 PC·휴대폰에서 인식된다고 보장하지 않는다. 이번 음성 전용 실행에는 공공데이터·카카오·Azure 키와 솔버 패키지가 필요 없다. 브라우저 음성 서비스는 인터넷을 사용할 수 있다.

현재 개발 폴더를 바꾸기 어려우면 **새 폴더에 clone**한다.

```powershell
git clone --branch main https://github.com/Uree1229/emergency-care-system.git emergency-care-voice-test
cd emergency-care-voice-test
python --version
git log -1 --oneline
```

이미 별도 시험용 폴더가 있고 변경사항이 없다면 그 폴더에서 `git switch main`, `git pull --ff-only`를 사용한다. 작업 중인 파일을 지우거나 강제로 checkout하지 않는다.

각자 화자 ID를 S01·S02처럼 정한다. 아래 S01을 자기 ID로 바꿔 **저장소 루트에서** 실행한다.

```powershell
python -m server.app --db data/voice-team-S01.db --port 8000 --no-planner --no-inquiry-worker
```

처음·다음 실행 모두 같은 명령이다. DB와 음성 사전은 보존 초기화된다. **`--seed`를 붙이지 않는다.** 이 시험은 가상 병원 생성·환자 등록·배정 없이 실행한다. 종료는 실행 터미널에서 Ctrl+C다. 포트가 사용 중이면 `--port 8010`으로 바꾸고 아래 주소도8010으로 바꾼다. 다른 사람의 서버를 종료하지 않는다.

브라우저에서 다음 중 필요한 화면을 연다.

- A: <http://127.0.0.1:8000/paramedic/command-practice.html>
- B: <http://127.0.0.1:8000/paramedic/quick-test.html>

이 주소는 **실행한 PC 본인용**이다. 휴대폰에 그대로 입력하면 PC로 연결되지 않는다. 첫 회는 PC 마이크로 한다. 휴대폰·같은 Wi-Fi·HTTPS 접속은 별도 연결 시험으로 진행하며 임의의 LAN HTTP 주소로 마이크 동작을 가정하지 않는다.

## 2. 시험 전에 기록할 조건

같은 사람·문장·장비에서 한 조건씩 바꾼다.

| 항목 | 예시·기록법 |
|---|---|
| 화자 ID | S01, S02. 실명 대신 사용 |
| 버전 | `git log -1 --oneline`의 커밋 |
| 기기·브라우저 | 실제 사용한 OS·브라우저 버전·내장/헤드셋 마이크 |
| 소음 | 조용함 / 실제 주변 말소리 / 실제 재생 소음. “시끄럽다”는 대본만 읽으면 소음 시험이 아님 |
| 말하기 | 평소 / 빠르게 / 머뭇거림. 처음에는 평소 속도 |
| 마스크·거리 | 실제 조건. 측정하지 않은 거리는 비워 둠 |
| 짝 비교 ID | 같은 화자·문장·기기의 조건 비교에 같은 값, 예: S01-LONG20 |
| 시도 | 실패·중단도 남기고 재시험은 시도 번호를 올림 |

다른 탭·다른 페이지의 녹음을 동시에 켜지 않는다. 앱의 TTS가 읽는 소리가 마이크로 다시 들어가지 않도록 안내 음성이 끝난 뒤 시작한다.

## 3. A — 긴 문장·명령 시험과 원본 녹음 수집

1. **발화 유형에서 긴 복합 문장**을 선택하거나 ID로 검색한다. 대본은 총96개이며 이 중 LONG-01~40이 긴 대본이다.
2. 시험 조건을 입력한다. `원본 녹음도 함께 보관`은 켜 둔다.
3. 첫 회에는 **`명령을 찾으면 녹음 자동 종료`를 끈다.** 한 문장 전체와 명령 뒤 내용을 끝까지 모으는 기준 시험이다.
4. `말하기 시작`을 눌러 듣기 상태가 된 뒤 **대본 본문만 한 번에 읽는다.** 제목·정답 라벨·해설은 읽지 않는다. 한 항목씩 끊어 녹음하지 않는다.
5. 다 읽으면 같은 버튼의 `말하기 마치기`를 누른다. 최대180초다. 시간 제한·인식기 종료로 잘렸다면 결과를 버리지 말고 중단 위치를 메모한다.
6. 실제로 말한 내용, 확정 인식문, 최종 명령 판정, 명령 앞/뒤 본문을 비교한다. 대본과 다르게 말했다면 `대본대로 말함`을 체크하지 않는다.
7. 대본대로 말했다면 의도 정답을 확인한 뒤 다음으로 간다. **판정 결과에 맞춰 정답을 바꾸지 않는다.** 다른 결과가 나와도 실패 자료로 남긴다.
8. 두 번째 회에서만 같은 대본으로 자동 종료를 켜 본다. 최초 명령 후보·최종 판정·잘린 위치를 따로 기록한다. 자동 종료 결과를 완독 조건과 섞지 않는다.

`새 환자`, `이전 환자`, `병원 추천`, `인계 요약`이 대본에 있어도 A에서는 실제 업무 동작을 실행하지 않고 명령만 판별한다. B나 실제 메인에서 이 긴 명령 대본을 무분별하게 읽지 않는다.

### 현재 알려진 어려운 대본

문서 작성 시 검토한 코드에서 LONG-12·14·16·34·39는 의도와 최종 판정이 달랐다. 상세 기대/관측은 [대본 묶음](testing/TEAM_VOICE_COMMAND_LONG_SENTENCES_20261031.md)에 있다. 이 대본들은 제거하거나 정답을 판정값으로 바꾸지 않았다. 팀원 시험에서 같은 문제가 있는지 확인하려는 항목이며, 대본96개가 모두 정상 판정된다는 뜻은 아니다.

## 4. B — 긴 환자 보고와 수정·조회 시험

1. 간편 음성 화면의 서버 연결 상태를 확인한다. `설정 → 새 환자 시작`으로 해당 케이스의 새 로컬 기록을 만든다. 이전 환자의 값을 다음 케이스 정답으로 쓰지 않는다.
2. `한 번 눌러 시작·종료`, `자동 판단`으로 시작한다. 질문에 답하는 모드라면 `다른 내용`을 사용해 긴 보고를 일반 입력으로 보낸다.
3. REP 대본의 본문 전체를 한 번에 읽고 버튼으로 끝낸다. 이 대본에는 실제 종료·새 환자·추천 명령을 섞지 않았다.
4. 인식 원문과 서버 전송 본문, 현재 저장된 칸을 비교한다. 원문 오류를 고치기 전에 원본을 먼저 기록한다.
5. 누락 질문이 나오면 대본에 있는 값으로 답한다. 대본에도 없으면 `미측정`/`모름`으로 남긴다. 맞아 보이도록 임의의 정상값을 말하지 않는다.
6. 대본의 **후속 발화**가 있으면 초기 보고를 저장한 뒤 별도 발화로 시험한다. 예를 들어 새 혈압을 보고하거나 저장값을 물었을 때 변화·조회가 구분되는지 본다.
7. 일반 “맥박이 떨어졌어”처럼 값이 없는 변화 보고가 새 숫자를 만들어내지 않는지, 부정·미확인·과거력이 현재 사실로 바뀌지 않는지 확인한다.
8. 기록 ID·버전과 어떤 칸이 어떻게 반영됐는지 결과 양식에 남긴다. 다음 케이스는 새 기록으로 시작한다.

B의 화면에서 알레르기·과거력 등 서술이 원문에 보존되는 것과 별도 구조화 칸에 반영되는 것은 다르다. 지원하지 않는 칸까지 자동 저장됐다고 가정하지 않는다. 이 화면의 시험만으로 실제 환자 등록·병원 추천·이송·인계 채팅이 검증됐다고 하지 않는다.

## 5. 끝나면 반드시 제출할 자료

### A 화면의 내보내기

- `음성 포함 전체 ZIP 내려받기`: 녹음·인식문·의도 정답·조건·파일 목록을 함께 보관한다.
- `메타데이터 JSON`: 텍스트·정답·조건의 추가 보관본이다. JSON만 보내면 녹음이 전달되지 않는다.
- `검토용 CSV`: 표로 볼 때 사용한다. ZIP을 대체하지 않는다.
- ZIP을 실제로 열어 녹음 파일과 manifest를 확인하고, 파일 하나를 재생해 본다. 내보내기 버튼을 눌렀다는 사실만으로 보관 성공이라고 판단하지 않는다.
- 저장 실패·용량 경고가 뜨면 현재 자료를 내보내고 실패 안내를 남긴다. 현재 자료를 지우거나 새 묶음으로 넘어가 문제를 숨기지 않는다.

파일명은 예를 들어 `S01_20261031_quiet_run1.zip`처럼 화자·날짜·조건·시도를 구분한다. 실제 원본 파일을 덮어쓰지 않는다. 자동 저장은 브라우저 보관이며 브라우저 데이터 삭제·강제 종료에 대한 외부 백업이 아니다.

### B 화면의 결과 기록

[빈 결과 양식](testing/TEAM_VOICE_TEST_RESULTS_TEMPLATE_20261031.csv)을 복사해서 케이스·시도별로 적는다. 확정 인식문·실제 전송 본문·저장값을 구분하고, 필요하면 해당 부분만 캡처한다. 녹음 내보내기를 제공하지 않는 경로에서 실제 녹음이 저장됐다고 적지 않는다.

최소한 아래를 남긴다.

| 항목 | 적을 내용 |
|---|---|
| 케이스·시도 | LONG-20 / REP-01, attempt1 |
| 읽은 대로인지 | 대본과 같은지, 다르게 말했다면 어떤 부분인지 |
| 인식 원문 | 고치기 전 브라우저의 실제 확정 인식문 |
| 관측 결과 | 명령 판정 또는 저장된 칸·값·이전→현재 |
| 문제 구간 | 혈압 숫자, 없음/미확인, 명령 오탐, 응답 유실 등 |
| 환경·증거 | 화자·기기·소음·커밋, ZIP 이름·시도 ID·초안 ID |

자료는 팀에서 정한 비공개 전달 경로로 공유한다. 담당자 PC의 최종 수집 위치는 `data/mic-tests/incoming/`이다. **음성·실제 인식문·작성한 결과 CSV·DB를 GitHub에 올리지 않는다.** GitHub에는 가상 대본·이 안내·빈 양식만 올린다.

A의 JSON은 명령 연습 형식이다. 기존 `evaluate.html`/`speech_eval`의 recordings JSON과 다른 형식이므로 이름만 바꿔 자동 평가기에 넣지 않는다. JSON 합치기는 텍스트·메타데이터만 합치며 다른 기기의 녹음 파일까지 복원하지 않는다.

## 6. 문제 원인을 나누는 기준

| 관측 | 우선 확인할 부분 |
|---|---|
| 말한 소리와 확정 인식문이 다름 | 마이크·브라우저 STT·소음·발음 |
| 인식문은 맞는데 의도 명령과 다름 | 명령 판별·부정/인용/시간 문맥 |
| 서버에 보낸 본문은 맞는데 칸이 틀림 | 서버의 용어·수치·문맥 해석 |
| 원문 일부가 전송 본문에서 빠짐 | 녹음 종료 시점·명령 분리·미반영 후속 문장 |
| 저장 응답이 없음 | 연결·서버 오류·결과 불확실 상태. 원래 요청 재시도로 확인 |
| 녹음은 없고 텍스트만 있음 | 음성 보관 선택·권한·용량·내보낸 파일 구성 |

수동으로 텍스트를 붙여 넣는 기능은 파서 점검이다. 마이크 성공이나 인식 정확도 개선으로 집계하지 않는다. 무인식·실패·중단도 분모에 남긴다. 같은 실패를 다시 읽어 성공했다고 첫 시도를 삭제하지 않는다.

## 7. 자주 막히는 부분

- **마이크가 안 켜짐:** `127.0.0.1` 주소·권한·기기 입력 선택·음성 인식 지원 표시를 확인한다. A/B 중 한 화면만 녹음한다.
- **서버 연결 실패:** 터미널이 살아 있는지, 포트와 주소가 같은지 확인한다. A는 정적 수집 기능이지만 B는 서버 연결이 필요하다.
- **이전 버전 화면:** 새 시험 폴더의 main 커밋을 확인하고 일반 새로고침한다. 자료가 든 브라우저 저장소를 먼저 지우지 않는다.
- **중간에 자동 종료:** A 기준 시험의 자동 종료를 껐는지 확인한다. B에서는 종료 명령을 포함한 LONG 대본 대신 REP 대본을 사용한다.
- **종료 후 저장이 불확실:** 같은 말을 새 요청으로 다시 저장하지 말고 화면의 원래 요청 재시도를 사용한다. 새 환자를 만들어 증거를 잃지 않는다.
